1 The story

Riya writes MapReduce without Java

The canteen committee wants revenue per menu category: drinks, snacks, breakfast, meals. Kabir knows Python well but has never written a line of Java. Riya has the Java version from Lesson 9.4 working, but Kabir asks: “Can't I just write two small Python scripts and let Hadoop run them on the cluster?” He can. Hadoop ships a tool for exactly this, and it works with any program that reads lines and prints lines.

K> So Hadoop runs my Python script instead of a Java Mapper? A> Alongside it. Each map task is still a Java process, but it starts your script as a child process, writes every input line to the script's standard input, and reads whatever the script prints. A line like meal⇥45 becomes the key meal and the value 45. That is Hadoop Streaming. R> And the reducer gets all values of a key in a list, like in Java? A> No, that's the one surprise. The reducer script gets plain lines, sorted by key, one after another. Your script has to notice when the key changes. Today we write both scripts, test them with an ordinary Linux pipe, run them on the cluster, and then break one on purpose to learn where Python errors hide.
2 Definition

Hadoop Streaming

Formal definition (write this in exams)

Hadoop Streaming is a utility shipped with Hadoop (hadoop-streaming-*.jar, run with mapred streaming or hadoop jar) that lets any executable or script that reads standard input and writes standard output act as the mapper, combiner or reducer of a MapReduce job. Each map task launches the mapper program as a subprocess and pipes its input records to it as lines of text; each output line is split at the first tab character into a key and a value (the whole line is the key if there is no tab). After the shuffle and sort, each reduce task pipes the key-value lines of its partition, sorted by key, to the reducer program, which must detect the boundaries between keys itself. The program and any files it needs are shipped to the worker nodes with the -files option; its interpreter must already be installed on every NodeManager.

In simple words

Write the map and the reduce as two small scripts that read lines and print key⇥value lines. Hadoop runs them on every node, sorts between them, and does everything else exactly as for a Java job.

LEVELS> Streaming at three levels L1> Two scripts and a pipe
  • The mapper reads order lines and prints one line per order: category⇥amount.
  • Hadoop collects those lines from all maps, sorts them by category and hands each reducer its share.
  • The reducer reads the sorted lines, keeps a running total, and prints the total whenever the category changes, and once more at the end.
  • On your laptop, head -1000 orders.csv | python3 mapper.py | sort | python3 reducer.py does the same thing; sort plays the shuffle.
L2> What Hadoop does with your script
  • Each task JVM (YarnChild) starts your command as a child process in the task's working folder, where -files placed your scripts and menu.csv.
  • Map input: with the default TextInputFormat, only the line (the value) is written to stdin, not the byte offset.
  • Your output lines are split at the first tab into key and value, partitioned with the HashPartitioner and sorted, just like Java map output (Lesson 8.4).
  • The reducer's stdin is key⇥value lines, grouped only in the sense that equal keys are next to each other. There is no Iterable of values.
  • If your process exits with a non-zero code, the attempt fails and is retried, up to 4 times, like any task (Lesson 8.6).
L3> Options, limits and alternatives
  • -numReduceTasks 0 gives a map-only job (filtering, format conversion); -combiner takes a script too.
  • -D stream.num.map.output.key.fields=2 makes the first two tab-separated fields the key, so you can sort on a composite key; with KeyFieldBasedPartitioner you can partition on part of it (a Streaming-style secondary sort, Lesson 9.7).
  • Everything travels as text and every record crosses two pipes, so Streaming usually uses more CPU than the same job in Java. For the heavy work, Java (or Spark) wins.
  • Libraries such as mrjob and Pydoop wrap Streaming for Python. Today most Python work on Hadoop data uses PySpark instead, but Streaming is still the quickest way to run an existing script, or a shell command like grep, across a cluster.
/LEVELS EXAM> For “What is Hadoop Streaming?”, say: a utility that lets any program reading stdin and writing stdout act as mapper or reducer; lines are split into key and value at the first tab; the reducer receives lines sorted by key and must detect key changes itself; files are shipped with -files. Then write the one-line command: mapred streaming -files m.py,r.py -input in -output out -mapper "python3 m.py" -reducer "python3 r.py".

4 Step by step

Revenue per category in Python, on the cluster

Run inside the namenode container of the Module 8 lab, with student_orders.csv (Lesson 9.1) in HDFS. The full script is streaming_lab.sh in “Run it on your PC”.

  1. The mapper: one order in, one line out

    menu = {}
with open("menu.csv") as f:                 # shipped with -files
    for line in f:
        item, category, price, counter = line.strip().split(",")
        menu[item] = category

for line in sys.stdin:
    order_id, student, time, item, amount = line.strip().split(",")
    print(f"{menu.get(item, 'unknown')}\t{amount}")
    The menu lookup makes this a map-side join (Lesson 9.6) for free: menu.csv lands in the task's working folder because of -files.

  2. The reducer: watch for the key to change

    current, orders, total = None, 0, 0
for line in sys.stdin:
    category, amount = line.rstrip("\n").split("\t")
    if category != current:
        if current is not None:
            print(f"{current}\t{orders}\t{total}")
        current, orders, total = category, 0, 0
    orders += 1
    total += int(amount)
if current is not None:
    print(f"{current}\t{orders}\t{total}")
    Two easy-to-miss lines: the final print after the loop (otherwise the last category is lost) and the if current is not None guard (an empty partition must print nothing).

  3. Test with a Linux pipe first

    head -1000 student_orders.csv | python3 revenue_mapper.py | sort | python3 revenue_reducer.py
    breakfast 179 4940 drink 377 6060 meal 162 9145 snack 282 5362
    179 + 377 + 162 + 282 = 1,000 orders. sort stands in for the shuffle. If this works, the cluster run almost always works too.

  4. Run it on the cluster

    mapred streaming -files revenue_mapper.py,revenue_reducer.py,menu.csv \
  -input /user/hadoop/data/student_orders.csv -output /out/stream \
  -mapper "python3 revenue_mapper.py" -reducer "python3 revenue_reducer.py"
    took 24512 ms number of splits:3 Job job_1792643020992_0045 completed successfully Launched map tasks=3 Map output records=500000 Reduce input groups=4 CPU time spent (ms)=5710
    Three map tasks each started a python3 process; the same counters as a Java job appear because the Java task around your script still does all the bookkeeping.

  5. Read the output and cross-check

    hdfs dfs -cat /out/stream/part-00000
    breakfast 90110 2476620 drink 190033 3052315 meal 80219 4670075 snack 139638 2652992
    Streaming output files are called part-00000 (the older API's naming). Every number equals the Java counters job of Lesson 9.4: BREAKFAST 90,110 and ₹24,76,620, and so on.

  6. Break the mapper and find the error

    # a typo: itme instead of item
mapred streaming -files broken_mapper.py,revenue_reducer.py,menu.csv … -mapper "python3 broken_mapper.py" …
yarn logs -applicationId <app id> -log_files stderr
    Error: java.lang.RuntimeException: PipeMapRed.waitOutputThreads(): subprocess failed with code 1 Job job_1792643020992_0046 failed with state FAILED due to: Task failed task_1792643020992_0046_m_000002 -- the Python error is in the task's stderr: NameError: name 'itme' is not defined Traceback (most recent call last):
    The job log only says that the subprocess exited with code 1. Python's traceback went to the task's stderr, which YARN keeps in the container logs. Retrying cannot fix a typo: the failed attempts are retried (up to 4 by default) and fail the same way, so the job gives up.
WARN> Python (and every library your script imports) must be installed on every NodeManager, in the same version. A script that works on the edge node can fail on a worker with ModuleNotFoundError. Ship pure-Python helpers with -files or -archives, or use a container image that has them.
5 See it happen

Lines through the pipes

Six steps of one Streaming job: ship the files, map through a Python process, sort, reduce through another Python process, and what a failure looks like.

Streaming job 6 steps
What you see
  1. The command ships two scripts and the menu, and the client finds 3 splits.
  2. Three map tasks start; each launches its own Python mapper.
  3. Maps are done: 5 lakh category lines were printed by the scripts.
  4. The reducer script saw 4 categories; the job succeeds.
  5. Four output lines, identical to the Java job's totals.
  6. With a typo, the job only reports a failed subprocess; the Python error is in the task log.
Behind the screen
  1. The NodeManager localizes the -files into each container's working folder.
  2. The Java map task writes every input line to Python's stdin and reads its stdout.
  3. Each output line is split at the first tab into key and value, then partitioned and sorted.
  4. The reduce task pipes sorted key⇥value lines to the reducer script, which prints one line per key.
  5. The reducer's printed lines become the job output in HDFS.
  6. If the script crashes, only its exit code reaches the job; its error text is in the container's stderr.
6 Real-world use

Streaming at work

1. Analysts who know Python, not Java

Data teams reuse existing Python parsing code to aggregate logs or clickstreams on Hadoop without learning the Java API.

Existing script→mapred streaming→Cluster-scale run

2. Shell tools across the whole cluster

A map-only Streaming job with -mapper "grep ERROR" and -numReduceTasks 0 searches terabytes of logs in parallel, one block per task.

Logs in HDFS→-mapper grep→Matching lines

3. Running a model on every record

Teams ship a trained scikit-learn model with -files or -archives and score millions of records in a map-only job, before Spark made this routine.

Records + model file→map: predict()→Scores

4. Migration to PySpark

Older Streaming pipelines are commonly rewritten in PySpark: the map logic becomes a DataFrame transformation and the key-change reducer becomes a groupBy().agg().

Streaming job→same logic→PySpark job
