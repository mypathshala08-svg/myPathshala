2 Definition

Practice exam: cloud concepts (MCQ)

Formal definition (write this in exams)

A cloud fundamentals exam (such as AWS CLF-C02, Microsoft AZ-900 or Google Cloud Digital Leader) assesses conceptual understanding of cloud computing, core services, security and compliance, pricing and governance through multiple-choice and multiple-response questions; effective preparation combines domain-weighted revision, recognition of question styles, a consistent answering method and timed practice with explanation review.

In simple words

The exam checks whether you understand cloud basics; practise with a timer, learn the question types, and read every explanation.

Say it in an interview

30-second answer you can speak:

  • “I prepared by mapping my study to the exam domains, practising timed sets, and reviewing explanations — especially look-alike services like CloudTrail vs CloudWatch.”
  • “For scenario questions I read the ask first, circle keywords like least effort or most cost-effective, eliminate, then choose the managed best fit.”

4 Types, one by one

Seven question styles, one by one

Seven question styles, each in the same pattern: definition, plain words, analogy, internal steps, animation, differences, real-world example, a sample question and an expert tip.

Type 1 · Definition questions

Definition (say it in an interview): Definition questions test whether you know the precise meaning of a concept — elasticity vs scalability, CapEx vs OpEx, Region vs Availability Zone, high availability vs fault tolerance — often with near-synonyms as distractors.

In plain words (no jargon): Questions asking you to identify a concept from its definition.

Analogy: Spelling bee words that sound alike: “affect” and “effect” are both real words, only one fits.

How it works internally, step by step

  1. Read. Underline the defining phrase.
  2. Recall. Your glossary definition.
  3. Compare. Near-synonyms side by side.
  4. Choose. Exact match.
  5. Review. Add misses to glossary.

Words used above, in simple terms: distractor = a wrong option designed to look right · near-synonym = a word with a close but different meaning · stem = the question text

Type 2 · “Which service?” questions

Definition (say it in an interview): Which-service questions describe a use case and ask for the most suitable service, often listing services from the same provider with overlapping features; the fastest route is need → service family → specific service.

In plain words (no jargon): Questions describing a need and asking which cloud service to use.

Analogy: A hardware shop: “I need to hang a picture” → fixings → wall plug and screw, not a drill press.

How it works internally, step by step

  1. Need. One-line job.
  2. Family. Compute, storage, DB, network, security, ops.
  3. Specific. Exact service.
  4. Check. Managed? Region? scope?
  5. Choose. —

Words used above, in simple terms: family = group of services for one kind of job · managed service = provider runs the infrastructure · scope = global, regional or zonal

Type 3 · Shared-responsibility questions

Definition (say it in an interview): Shared-responsibility questions ask who is responsible for a task — patching, physical security, data encryption choices, IAM, network rules — for a specific service; answer by identifying the layer and the service model (Lesson 9.1).

In plain words (no jargon): Questions asking whether the provider or the customer is responsible for something.

Analogy: A rented flat: the building owner fixes the lift; you lock your own door.

How it works internally, step by step

  1. Layer. Physical, network, hypervisor, OS, app, data, IAM.
  2. Service. EC2 / RDS / Lambda / S3…
  3. Model. IaaS/PaaS/SaaS.
  4. Owner. Apply the line.
  5. Shared?. Patching, config, training.

Words used above, in simple terms: inherited control = fully provider · shared control = split by layer · customer-specific control = only customer

Type 4 · Cost-optimised and pricing questions

Definition (say it in an interview): Cost questions ask for the most cost-effective option or the right pricing model for a usage pattern: steady workloads → commitments (Savings Plans, reservations, committed use); interruptible batch → Spot; short or unpredictable → on-demand or serverless; plus tools such as pricing calculators, budgets and cost explorers.

In plain words (no jargon): Questions asking for the cheapest option or right pricing model.

Analogy: Mobile plans: daily commuters buy a monthly pass, occasional riders pay per trip, flexible travellers wait for discounted off-peak seats.

How it works internally, step by step

  1. Pattern. Duration, steadiness, interruption tolerance.
  2. Model. On-demand, commit, spot, serverless.
  3. Tools. Calculator, budgets, Cost Explorer.
  4. Check. Requirements still met?
  5. Choose. —

Words used above, in simple terms: Savings Plan = AWS commitment discount · Spot = spare capacity at large discount, can be interrupted · TCO = total cost of ownership

Type 5 · Security best-practice questions

Definition (say it in an interview): Security questions ask for the most secure way to do something: grant access, store secrets, protect the root account, encrypt data, detect threats, or meet compliance; good answers use least privilege, roles instead of long-term keys, MFA, managed encryption and detection services.

In plain words (no jargon): Questions asking for the safest way to set something up.

Analogy: Lending your car: give the key for one trip (temporary role), not a copy of your house keys (root credentials).

How it works internally, step by step

  1. Risk. Identify.
  2. Identity. Roles, MFA, least privilege.
  3. Data. Encryption, KMS.
  4. Detect. GuardDuty, Defender, SCC.
  5. Comply. Artifact, reports.

Words used above, in simple terms: root user = all-powerful first account identity · instance profile = container for an IAM role on EC2 · least privilege = only required permissions

Type 6 · Architecture benefit questions

Definition (say it in an interview): Architecture questions ask how to achieve a quality — high availability, fault tolerance, elasticity, low latency for global users, faster delivery — or which Well-Architected pillar a practice belongs to; the answer links the benefit to a mechanism (multi-AZ, auto scaling, CDN/edge, decoupling with queues, IaC).

In plain words (no jargon): Questions about how to make a system reliable, scalable or fast.

Analogy: Building a bridge: “carry more trucks” → wider deck; “survive one pillar failing” → extra pillars; “faster crossing for distant towns” → more bridges.

How it works internally, step by step

  1. Benefit. What quality?
  2. Mechanism. AZs, scaling, CDN, queues.
  3. Scope. AZ vs Region vs global.
  4. Pillar. Which Well-Architected pillar?
  5. Choose. —

Words used above, in simple terms: multi-AZ = across several data centres in one Region · decoupling = separating parts with queues/events · pillar = Well-Architected category

Type 7 · Multiple-response (select TWO / THREE)

Definition (say it in an interview): Multiple-response questions require selecting a stated number of correct options; partial credit is usually not given, so each option must be judged independently and the final set must contain distinct, fully correct statements.

In plain words (no jargon): Questions where you must choose more than one answer.

Analogy: A team selection: each player must earn a place on their own merit — two players for the same position is a wasted pick.

How it works internally, step by step

  1. Count. Required number.
  2. Judge. True/false per option.
  3. Remove. Absolutes (“always”, “all”).
  4. Distinct. No duplicates.
  5. Check. Count again.

Words used above, in simple terms: partial credit = marks for some correct answers — usually not given · absolute wording = “always”, “never”, “all” — often false · multiple response = select more than one

7 Practice exam

60-question practice exam with explanations

Set a 60-minute timer, answer all 60 questions without notes, then open each to read the explanation. Score: 45+ ready to book; 36–44 revise weak parts; below 36 revisit the lessons named in the explanations.

10 Hands-on

Do it yourself, step by step

These labs run on your own cloud account — we cannot run them for you. Each step has three tabs (AWS, Azure, Google Cloud); pick the cloud you have and do both the UI way and the CLI way. Stay inside free tier / credit limits, use the India Region (AWS ap-south-1 Mumbai · Azure Central India · Google asia-south1 Mumbai), and always do the Clean up step at the end. Quick “see it yourself” checks for three facts that exams love: Regions and zones, default encryption and privacy of storage, and commitment discounts. Costs: nothing (delete the test buckets/accounts).

  1. 0 · Get ready: account, budget, CLI

    Pick your cloud.

    UI way — AWS Management Console

    1. Create an AWS account (aws.amazon.com → Create an AWS Account); choose the Free plan while learning.
    2. Never work as root: IAM Identity Center (or IAM) → create an admin user with MFA and sign in as that user.
    3. Billing and Cost Management → Budgets → Create budget → monthly cost budget, e.g. $5, alert by e-mail (Lesson 5.5).
    4. Top-right Region menu → Asia Pacific (Mumbai). Open CloudShell (terminal icon) — the AWS CLI is already signed in there.

    CLI way — the same thing with commands

    aws sts get-caller-identity          # who am I? (must NOT be the root user)
aws configure set region ap-south-1
aws configure list

    You should see: your account ID and an IAM user/role ARN — not “root”.

    UI way — Azure portal

    1. Create a free account at azure.microsoft.com/free (credit for the first 30 days).
    2. Search Cost Management → Budgets → Add → monthly budget, e.g. ₹400, alert at 80%.
    3. Open Cloud Shell (the >_ icon in the top bar) → choose Bash. The Azure CLI is already signed in.

    CLI way — the same thing with commands

    az account show --output table        # subscription in use
az account list-locations --query "[?name=='centralindia'].displayName" -o tsv

    You should see: your subscription name and state “Enabled”, then “Central India”.

    UI way — Google Cloud console

    1. Sign in at console.cloud.google.com and start the free trial (credit for 90 days).
    2. Create a project: project picker → New project → name tiffingo-lab.
    3. Billing → Budgets & alerts → Create budget → e.g. ₹400, alerts at 50/90/100%.
    4. Click Activate Cloud Shell (>_ icon). The gcloud CLI is already signed in.

    CLI way — the same thing with commands

    gcloud config set project tiffingo-lab      # use your real project ID
gcloud config set compute/region asia-south1
gcloud config list

    You should see: your account e-mail, the project and region asia-south1.

    Cloud Shell is the easiest CLI: free, in the browser, already logged in. On your laptop install the AWS CLI v2, Azure CLI or Google Cloud CLI and run aws configure / az login / gcloud init.

  2. 1 · Verify global-infrastructure facts (Regions and zones)

    Pick your cloud.

    UI way — AWS Management Console

    1. EC2 → EC2 Global View shows enabled Regions; the Region selector lists all Regions.

    CLI way — the same thing with commands

    aws ec2 describe-regions --all-regions --query 'length(Regions)'
aws ec2 describe-availability-zones --region ap-south-1 --query 'AvailabilityZones[?ZoneType==`availability-zone`].ZoneName' --output text

    You should see: the total number of Regions (enabled and opt-in) and Mumbai’s three AZ names — the “Region contains multiple AZs” fact, verified.

    UI way — Azure portal

    1. Any Create page → Region list; Subscriptions → Resource providers / Locations.

    CLI way — the same thing with commands

    az account list-locations --query "length([?metadata.regionType=='Physical'])"
az account list-locations --query "[?name=='centralindia'].availabilityZoneMappings[].logicalZone" -o tsv

    You should see: the number of physical Regions and Central India’s zones 1 2 3.

    UI way — Google Cloud console

    1. Compute Engine → Zones lists Regions and zones.

    CLI way — the same thing with commands

    gcloud compute regions list --format="value(name)" | wc -l
gcloud compute zones list --filter="region:asia-south1" --format="value(name)"

    You should see: the number of Regions and asia-south1-a/b/c.

    Facts you have seen yourself are much harder to forget in the exam.

  3. 2 · Verify security defaults (encryption and private storage)

    Pick your cloud.

    UI way — AWS Management Console

    1. Create a bucket → Properties → Default encryption shows SSE-S3; Permissions shows Block Public Access on.

    CLI way — the same thing with commands

    B=exam-facts-$RANDOM; aws s3 mb s3://$B --region ap-south-1 >/dev/null
aws s3api get-bucket-encryption --bucket $B --query 'ServerSideEncryptionConfiguration.Rules[0].ApplyServerSideEncryptionByDefault.SSEAlgorithm' --output text
aws s3api get-public-access-block --bucket $B --query 'PublicAccessBlockConfiguration' --output text

    You should see: AES256 (encrypted by default since 2023) and four True values — new buckets are private and encrypted by default.

    UI way — Azure portal

    1. Create a storage account → Encryption shows Microsoft-managed keys; Configuration shows anonymous blob access disabled.

    CLI way — the same thing with commands

    az group create -n rg-exam -l centralindia >/dev/null
SA=examfacts$RANDOM; az storage account create -n $SA -g rg-exam -l centralindia --sku Standard_LRS \
  --query "{encrypted:encryption.services.blob.enabled,keySource:encryption.keySource,anonymous:allowBlobPublicAccess,minTls:minimumTlsVersion}"

    You should see: encrypted: true, Microsoft.Storage key source, anonymous access false, minimum TLS 1.2.

    UI way — Google Cloud console

    1. Create a bucket → Configuration → encryption “Google-managed”; Permissions → not public.

    CLI way — the same thing with commands

    B=exam-facts-$RANDOM; gcloud storage buckets create gs://$B --location=asia-south1 --quiet
gcloud storage buckets describe gs://$B --format="value(default_kms_key,public_access_prevention,uniform_bucket_level_access)"

    You should see: an empty KMS key (meaning Google-managed default encryption), inherited or enforced, and True for uniform access.

    Exam answer pattern confirmed: storage is encrypted at rest by default on all three; access configuration remains your job.

  4. 3 · Verify a pricing fact (on-demand vs commitment)

    Pick your cloud.

    UI way — AWS Management Console

    1. Pricing Calculator → EC2 t3.micro Mumbai → compare On-Demand with a 1-year Savings Plan.

    CLI way — the same thing with commands

    aws pricing get-products --region us-east-1 --service-code AmazonEC2 --filters \
  Type=TERM_MATCH,Field=instanceType,Value=t3.micro Type=TERM_MATCH,Field=regionCode,Value=ap-south-1 \
  Type=TERM_MATCH,Field=operatingSystem,Value=Linux Type=TERM_MATCH,Field=tenancy,Value=Shared \
  Type=TERM_MATCH,Field=preInstalledSw,Value=NA Type=TERM_MATCH,Field=capacitystatus,Value=Used \
  --query 'PriceList[0]' --output text | python3 -c "import sys,json; d=json.loads(sys.stdin.read()); od=list(d['terms']['OnDemand'].values())[0]; print('on-demand', list(od['priceDimensions'].values())[0]['pricePerUnit']['USD']); [print(r['termAttributes'].get('LeaseContractLength'), r['termAttributes'].get('PurchaseOption'), [p['pricePerUnit']['USD'] for p in r['priceDimensions'].values() if p['unit']=='Hrs']) for r in d['terms'].get('Reserved',{}).values() if r['termAttributes'].get('OfferingClass')=='standard'][:3]"

    You should see: the on-demand hourly price and several reserved options with lower hourly rates — commitment = discount, verified.

    UI way — Azure portal

    1. Pricing calculator → Virtual Machines → compare Pay as you go with 1-year reserved for D2s_v5 in Central India.

    CLI way — the same thing with commands

    curl -s "https://prices.azure.com/api/retail/prices?\$filter=armRegionName%20eq%20'centralindia'%20and%20armSkuName%20eq%20'Standard_D2s_v5'%20and%20serviceName%20eq%20'Virtual%20Machines'" \
  | python3 -c "import sys,json; [print(i['type'], i.get('reservationTerm',''), i['retailPrice'], i['unitOfMeasure']) for i in json.load(sys.stdin)['Items'] if 'Windows' not in i['productName'] and 'Spot' not in i['skuName'] and 'Low Priority' not in i['skuName']]"

    You should see: Consumption 0.101 1 Hour and two Reservation rows (1 and 3 years, total price) at the time of writing — 1-year total ÷ 8,760 h is roughly 38% below the hourly rate.

    UI way — Google Cloud console

    1. Pricing Calculator → Compute Engine e2-standard-2 asia-south1 → compare on-demand with 1-year committed use discount.

    CLI way — the same thing with commands

    gcloud compute machine-types describe e2-standard-2 --zone=asia-south1-a --format="value(guestCpus,memoryMb)"

    You should see: the shape (2 vCPU, 8 GB); the calculator shows the committed-use discount percentage.

    Pricing questions become easy once you have seen on-demand and committed prices side by side.

Clean up and cost check

AWS: aws s3 rb s3://$B. Azure: az group delete -n rg-exam --yes --no-wait. Google Cloud: gcloud storage buckets delete gs://$B --quiet.
