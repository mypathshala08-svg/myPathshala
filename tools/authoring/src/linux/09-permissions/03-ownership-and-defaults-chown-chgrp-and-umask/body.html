The problem

Aman leaves; his manager needs his 40 GB of project files, but they all belong to aman. A cron job running as root writes a log the web app then cannot read. A team shares a folder, yet every new file comes out -rw-r--r-- so nobody else can edit it. These are not chmod problems: they are about who owns a file (chown, chgrp) and what mode new files get (umask).

2 Definition

chown, chgrp and umask

Formal definition (write this in exams)

chown changes the owner and/or group of files (USER, USER:GROUP, :GROUP, USER:); only root may change the owner. chgrp changes only the group; the owner may do it if they are a member of the new group. The umask is a per-process mask of permission bits that are removed from the default mode (666 for files, 777 for directories) when new files are created.

In simple words

Make sure the right person and team own each file, and that new files start with safe permissions.

Ownership and umask at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: deed, family and builder

A file is like a house.

Basic The commands you will type

  • sudo chown aman report.txt: aman owns it now.
  • sudo chown aman:finance report.txt: owner and group together.
  • chgrp finance report.txt: only the group.
  • sudo chown -R priya: /home/aman/project: a whole folder, owner priya, group priya.
  • umask: see the default (0022 or 0002).

Intermediate Who may change what; how umask works

  • Only root may change a file’s owner (otherwise users could give files away to dodge disk quotas or frame others).
  • The owner may change the group, but only to a group they belong to. Anyone else needs root.
  • New files start from 666 (rw for all: programs never ask for x on data), new folders from 777; the umask bits are removed: umask 022 → 644 / 755, 027 → 640 / 750, 077 → 600 / 700, 002 → 664 / 775.
  • umask is a property of each process, inherited by children. Set it in ~/.bashrc or ~/.profile, for services with systemd UMask=.

Advanced Behind the screen: chown(), umask() and inheritance

  • chown and chgrp use fchownat(). When a normal user changes the group of an SUID/SGID program, the kernel clears those bits (recorded below), so ownership tricks cannot create privileged programs.
  • umask removes bits; it is not arithmetic subtraction. 027 removes w for group and rwx for others: from 666 that gives 640 (no x appears, because 666 had none).
  • On Ubuntu, pam_umask with USERGROUPS_ENAB yes (login.defs) gives login sessions umask 0002 when the user’s group has the same name as the user; plain shells and services default to 0022.
  • New files get the creator’s effective UID and primary GID (or the folder’s group if the folder has SGID, Lesson 9.4). So sudo creates root-owned files, a classic source of “I cannot edit my own file”.
  • Default ACLs on a folder (9.5) override umask for files created inside it.

Did you know? Copying a file with cp makes you the owner of the copy, even with cp -p, unless you are root. That is how ownership “resets” when users copy files around.

EXAM> “Make the user tom and group web the owners of /var/www/site, recursively.” → chown -R tom:web /var/www/site.
Quick check Your umask is 027. What modes do a new file and a new folder get?
Answer: File 640 (rw-r-----), folder 750 (rwxr-x---).
Common mistake
✗“umask is subtracted from 777”, so umask 027 gives files 750
✓Files start from 666, folders from 777, and umask <b>removes</b> bits: 027 gives files 640 and folders 750.

Checked on our build machine: with umask 027, touch gives 640 and mkdir gives 750. Files never get x from umask alone.

🟡 Changes filessudo needed

Common mistake
✗chown -R aman / · sudo chown -R aman: /home/aman/../
✓sudo chown -R aman: /home/aman/project (an exact path, checked with ls first)

A recursive chown on / or a mistyped path changes system files (sudo, passwd, /etc) and can make the system unbootable. Check the path, never use .. in recursive commands.

🟢 Read-onlyno sudo

umask in security

  1. Situation: Create a secret that is private from the first moment.

    cd ~/own; (umask 077; echo 'token=abc' > api.token)
stat -c '%a %n' api.token; umask
    600 api.token 0022

    Why this way: With umask 022 the file would exist as 644 for a moment before a chmod 600; a subshell with 077 avoids that window.

umask in system info / admin

  1. Situation: Login sessions on Ubuntu get 0002 (user private groups); plain shells 0022.

    umask
sudo su - riya -c umask
grep -E '^(UMASK|USERGROUPS_ENAB)' /etc/login.defs
    0022 0002 UMASK 022 USERGROUPS_ENAB yes

    Why this way: pam_umask relaxes group bits when your group is your own private group. Services usually run with 0022.

umask in devops / cloud

  1. Situation: A service’s umask is set in its unit, not in .bashrc.

    printf '%s\n' '[Service]' 'User=reports' 'UMask=0027' 'ExecStart=/usr/local/bin/report'
    [Service] User=reports UMask=0027 ExecStart=/usr/local/bin/report

    Why this way: systemd starts services without your shell files (Lesson 17.3).

Common mistake
✗Run umask 077 and expect existing files to become private
✓umask only affects files created afterwards; fix existing ones with chmod (9.2).

umask is applied by the kernel at creation time (open with O_CREAT, mkdir). It never touches files that already exist.

Undo and safety net

Ownership changes are reversible if you know the old owner.

  • Before a recursive chown: record owners: find DIR -printf '%u:%g %p\n' > owners.txt.
  • Wrong owner on a tree: sudo chown -R RIGHT: DIR; for mixed trees replay owners.txt.
  • Ran chown -R on a system folder: compare with a working system, or reinstall the affected packages (14.2); restore from backup.
  • Wrong umask in .bashrc: fix the line, open a new shell; existing files need chmod.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. touch f; chown aman f
    chown: changing ownership of 'f': Operation not permitted exit status: 1

    What it means: Only root may change the owner (EPERM).

    Fix: sudo chown aman f.

  2. touch f; chgrp finance f
    chgrp: changing group of 'f': Operation not permitted exit status: 1

    What it means: riya is not a member of finance.

    Fix: Join the group (8.3) or use sudo.

  3. touch f; sudo chown nosuchuser f
    chown: invalid user: ‘nosuchuser’ exit status: 1

    What it means: No such user.

    Fix: Check with getent passwd.

  4. umask 999
    /home/riya/script.sh: line 1: umask: 999: octal number out of range exit status: 1

    What it means: Not an octal number.

    Fix: Digits 0–7, e.g. umask 027.

Quick check A file created by a root cron job must be readable by group www-data. Two fixes?
Answer: chown root:www-data + chmod 640 after creating it, or set the job’s umask (027) and run it as a user in that group.

6 Real-world use

Ownership and umask at work

1. Leavers and hand-overs

Files of departing staff are given to a manager or a project account.

Leaver→chown -R→continuity

2. “Cannot edit my file”

Files made with sudo or by root cron jobs are handed back with chown.

Ticket→chown→fixed

3. Service accounts

Data owned by the service; code owned by a deploy user; group for read access.

Deploy→chown u:g→least privilege

4. Team work

Shared folders combine a group, g+w and umask 002 (or default ACLs).

Team→chgrp→edit together

5. Hardening

Servers use umask 027 so new files are never readable by everyone.

Policy→umask→safe defaults

Hand a leaver’s project to a colleague: check both users, record old owners, change, and report.

from=${1:-aman}; to=${2:-riya}; dir=${3:-$HOME/own}
for u in "$from" "$to"; do id "$u" > /dev/null 2>&1 || { echo "no such user: $u" >&2; exit 1; }; done
[ -d "$dir" ] || { echo "no such folder: $dir" >&2; exit 1; }
sudo find "$dir" -printf '%u:%g %p\n' > /tmp/owners_before.txt
sudo chown -R "$to": "$dir"
echo "changed $(wc -l < /tmp/owners_before.txt) entries; now owned by: $(stat -c %U "$dir")"
changed 5 entries; now owned by: riya

umask arithmetic is right, the note is not: files start from 666 (folders from 777), so 027 gives a 640 file and a 750 folder; umask never adds x. And only root may change a file’s owner, even your own file: sudo chown aman report.txt.
