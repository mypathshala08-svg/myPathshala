The problem

A developer unzips a project and nothing runs: every script lost its x. A colleague “fixes” a website with chmod -R 777 /var/www and a week later the site is defaced. An SSH login fails with “UNPROTECTED PRIVATE KEY FILE”. All three are solved with one command, chmod, used precisely: the smallest change, on exactly the right files. You will learn both ways to write it, letters (u+x, go-r) and numbers (755, 644, 600), and the safe way to change a whole tree.

By the end of this page you will be able to:
  • change permissions with symbolic modes: who (u g o a), how (+ - =), what (r w x X)
  • convert between letters and octal in your head, and choose 644, 600, 755, 750 or 700 for the right job
  • change whole trees safely with -R, X and find … -exec chmod, without making every file executable
  • see what changed (-v -c), copy a mode (--reference), and know why chmod 777 is never the fix

2 Definition

chmod: change mode

Formal definition (write this in exams)

chmod changes the permission bits (the mode) of files and directories. A mode can be given symbolically (who, operator, permissions: u+x, go-w, a=r) to change some bits, or numerically in octal (644, 755) to set all of them. Only the owner of a file or root may change its mode.

In simple words

Give exactly the access each class needs: no more, no less.

chmod at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a board of nine switches

Each file has nine switches.

Basic The forms you will type every day

  • chmod +x deploy.sh: make a script runnable.
  • chmod 600 .env: only me, read and write.
  • chmod 644 page.html: everyone reads, only I write.
  • chmod 755 tools/: a normal folder.
  • chmod o-rwx report.xlsx: take everything away from others.

Intermediate Symbolic syntax and octal arithmetic

  • Symbolic: [ugoa][+-=][rwxXst], several joined by commas: u=rwx,g=rx,o=. + adds, - removes, = sets exactly (missing letters are removed).
  • Numeric: one digit per class, each the sum of r=4, w=2, x=1: rwx=7, rw-=6, r-x=5, r--=4, ---=0. Three digits always replace all nine bits.
  • X (capital) adds x only to directories and to files that already have some x. So on a tree that was 777, first remove x: chmod -R a-x,u=rwX,go=rX (clauses run left to right; a-x clears the files, X puts x back on folders only).
  • Only the file’s owner (or root) can chmod it, no matter what the mode says.

Advanced Behind the screen: chmod(), umask and digits

  • chmod calls the fchmodat() system call, which rewrites the mode in the inode and updates its ctime. The file’s contents and mtime do not change.
  • With no “who” letter (chmod +x f), the change is filtered by your umask (Lesson 9.3): with umask 022, chmod +w adds only u+w. Write a+x or u+x to be explicit.
  • Fewer than three digits are padded on the left: chmod 7 f means 007, chmod 64 f means 064. A fourth leading digit sets SUID/SGID/sticky (4/2/1, Lesson 9.4).
  • chmod on a symbolic link changes the target; with -R, links inside the tree are not followed.
  • Permission checks happen at open time: a process that already has a file open keeps its access after you chmod it.

Did you know? Octal is used because three bits make exactly one digit 0–7. That is why permissions are 3-digit numbers and why chmod 999 is an error: 9 is not an octal digit.

EXAM> “Set report.txt so the owner can read and write, the group can read, others nothing.” → chmod 640 report.txt or chmod u=rw,g=r,o= report.txt.
Quick check Convert rwxr-x--- to a number, and 644 to letters.
Answer: 750; rw-r--r--.
Common mistake
✗chmod -R 755 app/ (to make the scripts runnable)
✓chmod -R a-x,u=rwX,go=rX app/ then chmod u+x app/bin/*.sh and chmod 600 app/config/.env

-R 755 gives x to every file (data, configs, .py) and makes secrets readable by all. Capital X gives x only to folders; scripts and secrets get their own, precise command.

  • taking access away from others
✗ Don’t use it when

chmod (letters) in software development

chmod (letters) in security

  1. Situation: Take away everything from others on a sensitive folder, keep the rest.

    cd ~/app; chmod -R o-rwx config
ls -la config
    total 16 drwxr-x--- 2 riya riya 4096 Nov 11 13:36 . drwxr-xr-x 5 riya riya 4096 Nov 11 13:36 .. -rw-r----- 1 riya riya 15 Nov 11 13:36 .env -rw-r----- 1 riya riya 10 Nov 11 13:36 app.ini

    Why this way: Symbolic -R is safe here: it only removes, and it removes the same thing everywhere.

chmod (letters) in testing / qa

  1. Situation: Test how a program behaves when a config is unreadable.

    cd ~/app; chmod a-r config/app.ini

    Why this way: Remove r to simulate a broken deployment, then restore. Negative tests catch bad error messages.

chmod (numbers) set all nine bits

🟡 Changes filesno sudo

One octal digit per class, owner first: each digit is r(4) + w(2) + x(1). Three digits replace the whole mode; a fourth leading digit sets SUID, SGID, sticky.

✓ Use it when
  • setting a known final state
  • secrets, web files, scripts
  • scripts and documentation (short and exact)
✗ Don’t use it when
  • -R on trees that mix files and folders
  • fewer than 3 digits by accident

Syntax: chmod [-R] [-v|-c] NNN FILE…

chmod (numbers) in web servers

  1. Situation: Web content: files 644, folders 755.

    cd ~/site
find . -type d -exec chmod 755 {} +; find . -type f -exec chmod 644 {} +
find . -exec stat -c '%a %n' {} +
    755 . 644 ./index.html 755 ./css 644 ./css/app.css

    Why this way: Two finds, one for each type: the classic way to undo a chmod -R 777.

chmod (numbers) in data administration

  1. Situation: Database data folders must be private.

    chmod 700 ~/pgdata; ls -ld ~/pgdata
    drwx------ 3 riya riya 4096 Nov 11 13:36 /home/riya/pgdata

    Why this way: PostgreSQL refuses to start if its data directory is accessible by group or others (“has invalid permissions”).

Common mistake
✗chmod -R u=rwX,go=rX site/ (to repair a tree that was chmod -R 777)
✓chmod -R a-x,u=rwX,go=rX site/

X keeps x on files that already have it, so after 777 every file would stay 755. Clearing x first (a-x) makes X give x to folders only. Checked on our build machine.

Common mistake
✗chmod 7 file · chmod 64 file
✓chmod 700 file · chmod 640 file

Missing digits are added on the left: 7 becomes 007 (others rwx, owner nothing!) and 64 becomes 064. Always give three digits.

chmod -R · X · find -exec change a whole tree

🔴 Can destroy datano sudo

-R applies the mode to a folder and everything inside. With capital X, x goes only to folders (and files that already had x). For different modes per type, use find -type d and find -type f with -exec chmod.

✓ Use it when
  • fixing a whole project or website
  • giving x to folders but not files
✗ Don’t use it when
  • -R with numbers on mixed trees
  • chmod -R on / or /etc (breaks the system)

Syntax: chmod -R a-x,u=rwX,go=rX DIR · find DIR -type f -exec chmod 644 {} +

chmod -v · -c · --reference in security

  1. Situation: Only the owner or root may change a mode.

    chmod 666 /etc/passwd; echo "exit $?"
    chmod: changing permissions of '/etc/passwd': Operation not permitted exit 1

    Why this way: “Operation not permitted” (EPERM), not “Permission denied”: the mode bits of a file never give others the right to chmod it.

Undo and safety net

chmod is instant and has no undo command. Know the old mode before big changes.

  • Before a big change: save modes: find DIR -exec stat -c '%a %n' {} + > modes.txt; restore with while read m f; do chmod "$m" "$f"; done < modes.txt.
  • Ran chmod -R 777: reset with the two finds (folders 755, files 644), then re-apply secrets (600) and scripts (+x).
  • Broke system files (chmod -R on /etc or /usr): compare with a working server or reinstall packages (dpkg --verify, Lesson 14.2); often a reinstall is fastest.
  • Made your own file unreadable: you are still the owner: chmod u+rw FILE.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. chmod 644 /etc/passwd
    chmod: changing permissions of '/etc/passwd': Operation not permitted exit status: 1

    What it means: You are not the owner (EPERM).

    Fix: sudo chmod …, if you really should.

  2. chmod 999 notes.txt
    chmod: invalid mode: ‘999’ Try 'chmod --help' for more information. exit status: 1

    What it means: 9 is not an octal digit.

    Fix: Digits 0–7 only.

  3. chmod u+z notes.txt
    chmod: invalid mode: ‘u+z’ Try 'chmod --help' for more information. exit status: 1

    What it means: Unknown permission letter.

    Fix: r w x X s t only.

  4. chmod 644 missing.txt
    chmod: cannot access 'missing.txt': No such file or directory exit status: 1

    What it means: No such file.

    Fix: Check the name; quote names with spaces.

6 Real-world use

chmod at work

1. Scripts and CI

Pipelines fail with exit 126 until scripts get x (and Git records 755).

Fail→chmod +x→commit

2. Secrets

Keys, tokens and .env files are 600; ssh and many tools refuse anything looser.

Secret→chmod 600→safe

3. Websites

Web files 644, folders 755, uploads folder writable only by the app user.

Deploy→find -exec→serve

4. Databases

PostgreSQL and MySQL data directories must be private to the service account.

Init→chmod 700→start

5. Audits

Security teams search for world-writable files and fix them with chmod o-w.

Scan→chmod o-w→clean

Build it step by step: fixing a project after unzip

Scenario: Riya applies the four-step fix from the puzzle.

  1. 1. Start: everything 777.

    cd ~/app; find . -exec stat -c '%a %n' {} + | sort -k2 | head -4
    777 . 777 ./bin 777 ./bin/start.sh 777 ./config

  2. 2. Folders 755, files 644 (X).

    cd ~/app; chmod -R a-x,u=rwX,go=rX .

  3. 3. Scripts runnable, secret private.

    cd ~/app; chmod a+x bin/*.sh; chmod 600 config/.env

  4. 4. Check every file.

    cd ~/app; find . -type f -exec stat -c '%a %n' {} + | sort -k2
    755 ./bin/start.sh 600 ./config/.env 644 ./config/app.ini 644 ./src/lib/util.py 644 ./src/main.py

Script it: fix-perms.sh

A reusable fixer for a deployed app folder: safe defaults, executable scripts, private secrets, and a report.

d=${1:-$HOME/app}
[ -d "$d" ] || { echo "no such folder: $d" >&2; exit 1; }
chmod -R a-x,u=rwX,go=rX "$d"
find "$d" -name '*.sh' -exec chmod a+x {} +
find "$d" \( -name '.env' -o -name '*.key' -o -name '*.pem' \) -exec chmod 600 {} +
echo "world-writable left: $(find "$d" -perm -o+w | wc -l)"
find "$d" -type f -exec stat -c '%a %n' {} + | sort -k2
world-writable left: 0 755 /home/riya/app/bin/start.sh 600 /home/riya/app/config/.env 644 /home/riya/app/config/app.ini 644 /home/riya/app/src/lib/util.py 644 /home/riya/app/src/main.py

Run on the sample project (prepared with mixed modes).

Puzzle answer Remember the question from the story? Open to check your guess.

chmod -R 755 gave x to every file (data and configs became “executable”) and read access to everyone, including .env. Better: chmod -R a-x,u=rwX,go=rX app/ (capital X: folders only), then chmod a+x app/bin/*.sh and chmod 600 app/config/.env.

Quick check What does chmod o= do?
Answer: Removes all permissions for others (sets them to ---).
