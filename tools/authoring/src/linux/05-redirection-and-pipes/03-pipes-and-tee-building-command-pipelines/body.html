2 Definition

Pipes, pipelines and tee

Formal definition (write this in exams)

A pipe (|) connects the standard output of one command to the standard input of the next. A pipeline is a sequence of commands joined by pipes; all of them run at the same time and data flows through them as a stream. tee reads standard input and writes it both to standard output and to one or more files.

In simple words

Output of one command = input of the next. tee = a T-junction that also saves a copy.

Pipes at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: an assembly line

Think of a factory assembly line.

  • Each station does one small job: cut, sort, count, pack.
  • A conveyor belt carries the work from one station to the next: that belt is the pipe |.
  • Stations work at the same time: the cutter is already cutting the next piece while the sorter sorts.
  • tee is a T-junction in the belt that sends a copy into a storage box (a file) while the line keeps moving.

Basic The pipes you will type every day

  • ls -l | head -n 5: only the first lines of a long listing.
  • ls | wc -l: how many files; who | wc -l: how many users logged in.
  • cat data.txt | grep failed | sort | uniq: filter, sort, remove duplicates.
  • ps aux | less: scroll through long output (q quits).
  • command | tee out.txt: see the output and save it.

Intermediate Stages, filters and exit status

  • A command that reads stdin and writes stdout is a filter: grep, sort, uniq, cut, tr, head, tail, wc, sed, awk. Filters are the stations of a pipeline.
  • A pipe carries only stdout. Errors still reach the screen; use 2>&1 | (or |&) to send them too.
  • $? after a pipeline is the status of the last command. ${PIPESTATUS[@]} has all of them; set -o pipefail makes the pipeline fail if any stage fails.
  • uniq only merges adjacent equal lines, so always sort first.
  • Prefer the command’s own file argument over cat file |: grep x file, wc -l < file. Both work; the second saves a process.

Advanced Behind the screen: pipe(), buffers, SIGPIPE and subshells

  • The shell calls pipe(), which returns two descriptors (a read end and a write end), forks one process per stage, and connects stage 1’s fd 1 and stage 2’s fd 0 to the pipe with dup2(). All stages run at the same time.
  • The kernel pipe buffer holds 64 KB by default on Linux: a fast writer waits when it is full, a reader waits when it is empty. That is how a pipeline handles any amount of data with little memory.
  • When a reader exits early (head), the writer gets SIGPIPE and stops: seq 1 100000000 | head -2 finishes instantly. Its status is 141 (128 + 13).
  • Each stage runs in a subshell: echo x | read v sets v in a child that disappears. Use a here-string, process substitution or shopt -s lastpipe.
  • Named pipes (mkfifo) are pipes with a name in the file system, so unrelated processes can connect.

Did you know? The pipe was the idea of Doug McIlroy, head of the Bell Labs department where Unix was born. He pushed for it for years; when Ken Thompson finally added it in one night in 1973, the team rewrote many programs overnight to read stdin and write stdout. The “do one thing well” Unix philosophy comes directly from that night.

EXAM> “What is a pipe and how is it different from redirection?” → | connects one command’s stdout to another command’s stdin; > connects stdout to a file. Example: ls | wc -l vs ls > list.txt. Mention that only stdout passes (2>&1 for errors) and that $? is the last stage (PIPESTATUS / pipefail).
Quick check What is the difference between ls > wc and ls | wc?
Answer: ls > wc creates a file named wc containing the listing. ls | wc runs the command wc on the listing and prints the count.

Pipes and tee explained, then used in every field

| pipe

🟢 Read-onlyno sudo

Connects the stdout of the command on the left to the stdin of the command on the right. Both run at the same time. Chain as many as you like.

✓ Use it when
  • joining small tools into the exact command you need
  • filtering, counting, sorting and summarising any output
  • processing huge data without temporary files
✗ Don’t use it when

  • when you need the variable set inside the pipe afterwards (subshell trap)

| in system info / admin

  1. Situation: How many users are logged in, and how many accounts have bash as their shell?

    who | wc -l
grep -c '/bin/bash$' /etc/passwd
    0 5

    Why this way: who prints one line per session, so wc -l counts them (0 on our build machine, nobody is logged in). grep -c counts matches directly, no pipe needed.

  2. Situation: The 3 largest files in /etc (readable ones), biggest first.

    find /etc -maxdepth 1 -type f -readable -printf '%s %f\n' | sort -rn | head -n 3
    75113 mime.types 54703 ld.so.cache 12813 services

    Why this way: find prints “size name”; sort -rn sorts numerically, biggest first; head keeps 3. No “total” line to worry about.

| in web servers

  1. Situation: The top 5 IP addresses in an access log.

    cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head -n 5
    9 49.36.12.8 7 185.220.101.4 6 103.21.44.7 4 157.48.1.20 3 10.0.0.5

    Why this way: Column 1 is the IP. sort groups equal IPs, uniq -c counts each group, sort -rn puts the biggest counts first.

  2. Situation: How many requests failed with a 5xx server error?

    awk '{print $9}' access.log | grep -c '^5'
    3

    Why this way: Field 9 is the status code. Start with the whole pipeline in your head: extract, filter, count.

| in security

  1. Situation: Who is trying /admin and getting 401 Unauthorized? (brute force)

    grep '"GET /admin' access.log | grep ' 401 ' | cut -d' ' -f1 | sort | uniq -c | sort -rn
    7 185.220.101.4 3 103.21.44.7 2 49.36.12.8 2 117.99.3.3 1 157.48.1.20 1 10.0.0.5

    Why this way: Filter twice, then count per IP: one address with many 401s on /admin is worth blocking (Lesson 19.3).

| in data analysis / engineering

  1. Situation: Unique cities in a CSV, sorted, without the header.

    printf 'name,city\nAsha,Pune\nRavi,Agra\nMeena,Pune\nJoy,Goa\n' > people.csv
tail -n +2 people.csv | cut -d, -f2 | sort -u
    Agra Goa Pune

    Why this way: tail -n +2 skips the header; cut takes column 2; sort -u sorts and removes duplicates in one step.

  2. Situation: Word frequency in a text (the classic pipeline).

    echo 'the cat and the dog and the bird' | tr ' ' '\n' | sort | uniq -c | sort -rn | head -n 3
    3 the 2 and 1 dog

    Why this way: tr puts one word per line, then the frequency table. Search engines and NLP courses start with exactly this.

| in software development

  1. Situation: Which Python files have the most lines?

    mkdir -p src; seq 1 40 > src/app.py; seq 1 12 > src/util.py; seq 1 90 > src/models.py
wc -l src/*.py | sort -rn | head -n 3
    142 total 90 src/models.py 40 src/app.py

    Why this way: wc -l prints a total line, which sorts to the top; head -n 4 would show the top 3 files after it.

  2. Situation: Your most used shell commands (from your notes).

    printf 'ls\ncd src\nls -l\ngit status\nls\ngit status\nls\n' > hist.txt
awk '{print $1}' hist.txt | sort | uniq -c | sort -rn | head -n 3
    4 ls 2 git 1 cd

    Why this way: In your terminal: history | awk '{print $2}' | sort | uniq -c | sort -rn | head ($2 because history adds a number in column 1). Here a saved history file is used.

| in devops / cloud

  1. Situation: Is a process running? Count it correctly.

    sleep 123 &
ps aux | grep 'sleep 123' | wc -l
pgrep -fc 'sleep 123'
kill $!
    2 1

    Why this way: ps aux | grep counts the grep command itself (2 instead of 1). pgrep never matches itself. See the common mistake below.

Common mistake
✗ps aux | grep java | wc -l (counts one too many)
✓pgrep -c java · or ps aux | grep '[j]ava' | wc -l

The grep process itself has “java” in its command line, so it matches too (a real run counted 2 for 1 process). pgrep skips itself; the [j]ava trick works because the pattern text no longer matches itself.

Common mistake
✗ls -a ~ | grep ^\. (meant: only hidden files)
✓ls -a ~ | grep '^\.'

Without quotes bash removes the backslash, grep receives ^. (“any first character”) and prints every file (verified). Always quote grep patterns.

tee T-junction

🟡 Changes filesno sudo

Reads stdin, writes it to stdout and to every file you name. -a appends instead of overwriting. Because it is a separate program, sudo tee can write where your shell cannot.

✓ Use it when
  • seeing output on screen and saving it at the same time
  • saving an intermediate stage of a pipeline for later
  • writing root-owned files from a pipe (sudo tee)
✗ Don’t use it when
  • when you only need the file (use >)
  • huge binary streams to many files (it works, but doubles the I/O)

PIPESTATUS · pipefail exit status of a pipeline

🟢 Read-onlyno sudo

After a pipeline, $? is the status of the last command only. ${PIPESTATUS[@]} lists every stage. With set -o pipefail, the pipeline’s status is the last non-zero one.

✓ Use it when
  • scripts where a failed stage must not be ignored
  • debugging which stage of a pipeline failed
  • CI and backup pipelines (mysqldump | gzip > file)
✗ Don’t use it when
  • interactive quick checks (no need)
  • pipelines where an early stage normally “fails” on purpose (grep finding nothing, head closing the pipe)

PIPESTATUS · pipefail in software development

    1 2 stages: 141 0

Undo and safety net

Pipes do not change files, but the commands inside them can.

  • A pipeline ends with > file: the same rules as Lesson 5.2: the file is emptied first. Never redirect into a file that an earlier stage reads.
  • tee overwrote a file: tee without -a replaces the file, like >. Use tee -a for logs.
  • | xargs rm or | sh at the end: look at the list first by removing the last stage (Lesson 5.4).
  • A pipeline never finishes: a stage is waiting (a FIFO with no reader, or a command reading the keyboard). Ctrl+C stops all stages.
  • The variable set inside a pipe is empty afterwards: the subshell trap. Use done < <(cmd) or a here-string.

Error messages decoded

Pipeline errors students see most. Each was really produced on our build machine, with its exit status.

  1. ls | grepp txt
    /home/riya/script.sh: line 1: grepp: command not found exit status: 127

    What it means: A typo in a later stage: “command not found” (127). The first stage still ran.

    Fix: Check the spelling; use Tab completion.

  2. ls /nope | wc -l
    ls: cannot access '/nope': No such file or directory 0 exit status: 0

    What it means: The error went to the screen (not into the pipe) and wc counted 0 lines; the status is wc’s: 0.

    Fix: Use 2>&1 | to count errors; use pipefail in scripts.

  3. echo hello | tee /proc/version
    tee: /proc/version: Permission denied hello exit status: 1

    What it means: tee could not open the file for writing (here a read-only system file). The text still went to stdout.

    Fix: Check the path and permissions; use sudo tee for root files.

  4. set -o pipefail; printf 'a\nb\n' | grep zzz | wc -l
    0 exit status: 1

    What it means: grep found nothing (status 1); with pipefail the whole pipeline returns 1 even though wc printed 0.

    Fix: Expected for “nothing found”. Use grep … || true where no match is fine.

Quick check After mysqldump shop | gzip > shop.sql.gz, $? is 0. Does that prove the backup worked?
Answer: No. $? is gzip’s status. Use set -o pipefail or check ${PIPESTATUS[0]} for mysqldump.

Under the hood: one pipe, two programs

strace follows both processes (-f): the shell creates the pipe with pipe2(), each child moves its end to fd 0 or 1 with dup2(), then echo writes and wc reads.

strace -e trace=%file,%desc bash -c 'echo hello | wc -c'
pipe2([3, 4], 0) = 0 dup2(4, 1) = 1 write(1, "hello\n", 6) = 6 dup2(3, 0) = 0 read(0, "hello\n", 16384) = 6 read(0, "", 16384) = 0 write(1, "6\n", 2) = 2

Recorded with strace on our Ubuntu build machine; library loading lines are hidden. You can run the same on your PC after sudo apt install strace.

Quick check Why does seq 1 100000000 | head -n 2 finish instantly instead of generating 100 million numbers?
Answer: head exits after two lines; seq’s next write gets SIGPIPE and seq stops. Stages run at the same time, so seq never got far.

Script it: top-ips.sh

The manager’s report as a reusable script: strict pipefail, a parameter for N, and a saved copy with tee.

#!/bin/bash
set -o pipefail
python3 - << 'PY'
import random
random.seed(7)
ips = ['49.36.12.8']*9 + ['103.21.44.7']*6 + ['157.48.1.20']*4 + ['10.0.0.5']*3 + ['185.220.101.4']*7 + ['117.99.3.3']*2
pages = ['/', '/login', '/cart', '/api/orders', '/admin', '/products?id=7']
codes = [200]*7 + [404, 500, 302]
random.shuffle(ips)
with open('access.log', 'w') as f:
    for k, ip in enumerate(ips):
        p = '/admin' if ip == '185.220.101.4' else random.choice(pages)
        c = 401 if p == '/admin' else random.choice(codes)
        f.write(f'{ip} - - [06/Nov/2026:10:{k:02d}:00 +0530] "GET {p} HTTP/1.1" {c} {random.randint(200, 9000)}\n')
PY
log=access.log; n=${1:-3}
echo "Top $n IPs in $log:"
cut -d' ' -f1 "$log" | sort | uniq -c | sort -rn | head -n "$n" | tee top_ips.txt
echo "401 on /admin: $(grep '"GET /admin' "$log" | grep -c ' 401 ')"
Top 3 IPs in access.log: 9 49.36.12.8 7 185.220.101.4 6 103.21.44.7 401 on /admin: 16

The python block only creates the demo log; on a server you would point log= at /var/log/nginx/access.log.

She sees two file names. The first line of ls -l output is total 16K, so head -n 3 shows that line plus two files. Use ls -lhS | head -n 4, ls -lhS | tail -n +2 | head -n 3, or simply ls -S | head -n 3 for names only.

Quick check In echo "Asha" | read name; echo $name, why is name empty?
Answer: Each stage of a pipeline runs in a subshell; read set the variable there, and it vanished with the subshell. Use read name <<< "Asha".
