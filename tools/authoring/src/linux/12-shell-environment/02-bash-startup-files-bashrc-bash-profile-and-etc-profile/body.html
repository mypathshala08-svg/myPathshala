The problem

Riya adds export PATH="$HOME/bin:$PATH" and a handy alias in her terminal. Next morning: gone. She puts them in ~/.bashrc: they work in new terminals, but not when she logs in over SSH. Her colleague puts the same lines in ~/.bash_profile: SSH works, new terminal windows do not. Bash reads different startup files for different kinds of shells: login shells (SSH, console, su -) read /etc/profile and the first of ~/.bash_profile, ~/.bash_login, ~/.profile; interactive non-login shells (a new terminal tab) read ~/.bashrc; scripts read none; and ~/.bash_logout runs when a login shell exits.

By the end of this page you will be able to:
  • tell login, interactive non-login and non-interactive shells apart, and check which one you are in
  • know exactly which file each one reads, and in what order: /etc/profile, /etc/profile.d, ~/.bash_profile, ~/.bash_login, ~/.profile, /etc/bash.bashrc, ~/.bashrc, ~/.bash_logout
  • make settings permanent the right way, reload them with source, and use the standard “.profile sources .bashrc” pattern
  • set system-wide settings for all users, and debug startup files that break logins

2 Definition

Bash startup files

Formal definition (write this in exams)

Startup files are shell scripts that bash runs automatically. A login shell runs /etc/profile and the first readable file among ~/.bash_profile, ~/.bash_login and ~/.profile, and runs ~/.bash_logout when it exits. An interactive non-login shell runs /etc/bash.bashrc and ~/.bashrc. Non-interactive shells run none of them.

In simple words

Login = profile files once per session; every terminal = .bashrc; logout = .bash_logout.

Startup files at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: arrive, sit, leave

Three moments, three kinds of files.

Basic What you will do every day

  • Add aliases and your prompt to ~/.bashrc.
  • Add export lines (PATH, JAVA_HOME) to ~/.profile (or ~/.bash_profile).
  • After editing: source ~/.bashrc (or open a new terminal).
  • Never delete these files blindly; copy fresh ones from /etc/skel.

Intermediate The rules

  • Login shell: /etc/profile (which runs /etc/profile.d/*.sh), then the first one that exists of ~/.bash_profile, ~/.bash_login, ~/.profile. On exit: ~/.bash_logout.
  • Interactive non-login: /etc/bash.bashrc (Debian/Ubuntu; /etc/bashrc on RHEL), then ~/.bashrc.
  • Non-interactive (scripts, bash -c, cron): none, except the file named in $BASH_ENV.
  • Check: shopt -q login_shell && echo login; [[ $- == *i* ]] && echo interactive.

Advanced Behind the screen: how bash decides

  • bash is a login shell if argv[0] starts with - (that is how login, sshd and su - start it: ps shows -bash) or with --login/-l.
  • Interactive = stdin and stderr are terminals and no -c, or -i given. $- then contains i.
  • GUI terminals (GNOME Terminal) start non-login shells; your desktop session’s login read ~/.profile once.
  • SSH with a command (ssh host cmd) is non-login and non-interactive, yet bash still reads ~/.bashrc because it detects sshd. That is why the Ubuntu .bashrc starts with “If not running interactively, don’t do anything”.
  • sh/dash login shells read only /etc/profile and ~/.profile, not the bash files; that is why exports belong in ~/.profile.

Did you know? Only the first of ~/.bash_profile, ~/.bash_login and ~/.profile is read. Creating an empty ~/.bash_profile silently switches off your Ubuntu ~/.profile, and with it the line that loads ~/.bashrc in login shells.

EXAM> “Which file is executed when a user logs out?” → ~/.bash_logout (for login shells).
Quick check You open a new terminal tab in Ubuntu’s desktop. Which of your files runs?
Answer: ~/.bashrc (it is an interactive non-login shell), after /etc/bash.bashrc.
Common mistake
✗Put export PATH=… in ~/.bashrc only
✓Exports in ~/.profile; aliases/prompt/functions in ~/.bashrc; and ~/.profile sources ~/.bashrc

Programs started from your desktop or by a login (not from a terminal) never read .bashrc, so they miss the PATH. Exports are inherited, so setting them once at login is enough.

Undo and safety net

Startup files are plain text; a broken one can lock you out of comfortable logins, rarely more.

  • Broke ~/.bashrc: open a shell that skips it: bash --norc (or bash --noprofile --norc), fix the file, bash -n to check.
  • Lost the defaults: cp /etc/skel/.bashrc ~/ (and .profile).
  • A .bash_profile hides .profile: remove it or add . ~/.profile inside.
  • A command in .bashrc hangs logins: ssh host bash --norc or ssh -t host bash --noprofile, then fix.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. source ~/nofile
    /home/riya/script.sh: line 1: /home/riya/nofile: No such file or directory exit status: 1

    What it means: The file does not exist.

    Fix: Check the name: ~/.bashrc has a dot.

  2. bash -n broken.sh
    broken.sh: line 1: unexpected EOF while looking for matching `"' exit status: 2

    What it means: A missing quote in a startup file.

    Fix: Close the quote; check again with bash -n.

  3. logout
    /home/riya/script.sh: line 1: logout: not login shell: use `exit' exit status: 1

    What it means: logout works only in a login shell.

    Fix: Use exit.

  4. echo "export X=1" > /etc/profile.d/x.sh
    /home/riya/script.sh: line 1: /etc/profile.d/x.sh: Permission denied exit status: 1

    What it means: Only root may write there.

    Fix: echo … | sudo tee ….

Script it: whichfiles.sh

Report which of your startup files exist, which one a login shell will actually read, and whether it loads .bashrc.

cd "${1:-$HOME}"
for f in .bash_profile .bash_login .profile .bashrc .bash_logout; do
  [ -f "$f" ] && echo "exists: $f"
done
for f in .bash_profile .bash_login .profile; do
  if [ -f "$f" ]; then echo "login reads: $f"; grep -q bashrc "$f" && echo "  and it loads .bashrc" || echo "  WARNING: it does not load .bashrc"; break; fi
done
exists: .profile exists: .bashrc exists: .bash_logout login reads: .profile and it loads .bashrc

Run on the test home after adding an empty .bash_profile (the puzzle).

Puzzle answer Remember the question from the story? Open to check your guess.

Because ~/.bash_profile exists, a login shell (SSH) reads it and ignores ~/.profile, which is where Ubuntu loads ~/.bashrc. So aliases and the prompt are missing over SSH. Fix: add [ -f ~/.profile ] && . ~/.profile (or . ~/.bashrc) to ~/.bash_profile, or move its JAVA_HOME line into ~/.profile and delete it.

Quick check Does su riya (without the dash) read riya’s .profile?
Answer: No: it starts a non-login shell, which reads ~/.bashrc. su - riya starts a login shell.
