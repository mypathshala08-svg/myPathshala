The problem

Riya sets DB_HOST=10.0.0.5 in her terminal and runs her Python app. The app says DB_HOST is not set. She types echo $DB_HOST: it is right there! On another day she copies a tool to ~/bin, types its name, and gets “command not found”. Both problems are about variables: the shell keeps two kinds, shell variables that only the shell sees and environment variables that every program it starts receives. And one environment variable, PATH, decides where Linux looks for every command you type. Before that: which shell are you even talking to?

By the end of this page you will be able to:

  • explain shell vs environment variables, use export, env, printenv, set and declare -p, and pass a variable to one command only

2 Definition

Shells, shell variables and environment variables

Formal definition (write this in exams)

A shell is a command-line interpreter: it reads commands, expands them and starts programs. A shell variable is a named string stored inside the running shell. An environment variable is a variable that has been exported: it is part of the environment that the shell passes to every child process it starts. PATH is the environment variable that lists the directories searched for commands.

In simple words

Shell variable = only this shell. Environment variable = this shell and every program it starts.

Shells and variables at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: notes and a folder of copies

Your shell is a desk with notes; programs it starts get a folder of copies.

Basic What you will type every day

  • name=Riya makes a variable (no spaces around =); echo "$name" reads it.
  • export name (or export name=Riya) lets programs you start see it.
  • env or printenv lists the environment; echo $PATH shows where commands are searched.
  • unset name removes a variable. echo $0 shows which shell you are in.

Intermediate The rules

  • Names: letters, digits, _; not starting with a digit; case-sensitive (name ≠ NAME). Convention: UPPERCASE for environment variables, lowercase for your own.
  • All values are strings. ${name} marks where the name ends: "${file}_old".
  • VAR=value command puts VAR into the environment of that one command only.
  • A child can never change its parent’s variables: export copies downwards only. To change your current shell, use source (Lesson 11.1).
  • readonly variables cannot be changed or unset until the shell exits.

Advanced Behind the screen: the environment block

  • The environment is an array of NAME=value strings passed by execve() to every new program; read it for any process in /proc/PID/environ.
  • bash keeps attributes per variable: exported (-x), readonly (-r), integer (-i), array (-a, -A); declare -p shows them.
  • Command lookup order: alias → shell keyword → function → builtin → a hash table of remembered paths → search each PATH folder left to right. hash -r forgets remembered paths.
  • An empty entry in PATH (:: or a trailing :) means “the current folder”: a security risk.
  • /bin/sh on Ubuntu is dash (small, fast, POSIX only); on RHEL it is bash in POSIX mode. Scripts with #!/bin/sh must not use bash-only features.

Did you know? cd, export and read must be shell builtins for the same reason: they change the shell itself. If export were a separate program, it would only change its own copy and then exit.

EXAM> “Difference between a shell variable and an environment variable?” → A shell variable exists only in the current shell; an environment variable (exported) is also passed to every child process.
Quick check After x=5, which shows it: env, set or both?
Answer: Only set (and declare -p x). env shows exported variables only; after export x, both.
Common mistake
✗num= 20 · num = 20
✓num=20

No spaces around =. “num= 20” sets num to empty for one command and runs a command called 20 (exit 127). “num = 20” runs a command called num.

Common mistake
✗readonly MY_VAR=10; unset MY_VAR (to “come out of read-only mode”)
✓There is no way back: a readonly variable lasts until the shell exits. Use readonly only for real constants.

Checked on our build machine: unset prints “cannot unset: readonly variable” and exits 1; assigning prints “readonly variable”.

PATH · type -a · hash where commands are found

🟡 Changes filesno sudo

PATH is a colon-separated list of folders. The shell looks in each, left to right, and runs the first match. Add a folder in front ("$HOME/bin:$PATH") to prefer it, or at the end to use it last. type -a cmd shows every match; hash -r forgets remembered locations.

✓ Use it when
  • running your own scripts and tools by name
  • choosing between two versions of a tool
✗ Don’t use it when
  • adding . or an empty entry to PATH
  • PATH=newdir without :$PATH

Undo and safety net

Variables live in memory; a new terminal undoes almost everything.

  • Broke PATH: export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin, or open a new terminal; then fix the line in ~/.bashrc.
  • Exported something by mistake: export -n NAME or unset NAME.
  • readonly by mistake: start a new shell (exit and reopen).
  • chsh to a wrong shell: as root: usermod -s /bin/bash USER.

Numbers are strings too

echo "$a$b"        # joined as text
echo $((a + b))    # arithmetic needs $(( ))
510 15

Every value is a string; arithmetic is explicit (Lesson 12.7).

V2

Command output into a variable

today=$(date +%F)
files=$(ls /etc | wc -l)
echo "On $today, /etc has $([ "$files" -gt 50 ] && echo many || echo few) entries"
On 2026-11-11, /etc has many entries

$( ) stores the output of a command; the date changes each day.

V3

Append to a variable

list=apples
list+=",mangoes"
list="$list,grapes"
echo "$list"
apples,mangoes,grapes

+= appends; or rebuild it with the old value inside.

V4

Default, alternative and length

unset city
echo "${city:-Pune}"     # default when empty
city=Delhi
echo "${city:+set}"      # alternative when set
echo "${#city} letters"
Pune set 5 letters

${v:-x}, ${v:+x} and ${#v}: three of the most used expansions.

Shell vs environment variables

V5

export with and without a value

A=1; export A
export B=2
bash -c 'echo "child sees A=$A B=$B"'
child sees A=1 B=2

Both forms export; the second sets and exports in one step.

V6

Un-export but keep the value

export C=3
export -n C
bash -c 'echo "child: [$C]"'; echo "parent: $C"
child: [] parent: 3

export -n turns it back into a shell variable.

V7

Several variables for one command

LANG=C TZ=UTC bash -c 'echo "$LANG $TZ"'
echo "after: [$TZ]"
C UTC after: [Asia/Kolkata]

Any number of NAME=value before a command, for that command only.

V8

printenv vs echo

export SHOWN=yes; hidden=no
printenv SHOWN; printenv hidden || echo 'hidden is not in the environment'
yes hidden is not in the environment

printenv only knows the environment; echo knows all shell variables.

PATH variations

V9

Prepend vs append

PATH="$HOME/v1/a:$HOME/v1/b:$PATH" tool
PATH="$HOME/v1/b:$HOME/v1/a:$PATH" tool
from a from b

The first folder in PATH wins.

V10

Add only if missing

d=/opt/demo/bin
case ":$PATH:" in *":$d:"*) ;; *) PATH="$PATH:$d";; esac
case ":$PATH:" in *":$d:"*) ;; *) PATH="$PATH:$d";; esac
echo "$PATH" | tr : '\n' | grep -c demo
1

Running the same line twice adds it once: safe in .bashrc.

Script it: envcheck.sh

A start-up check for an application: required variables must be set and exported, and PATH must not contain an empty entry or a dot.

missing=0
for v in HOME USER APP_ENV DB_HOST; do
  if ! printenv "$v" > /dev/null; then echo "MISSING: $v"; missing=1; fi
done
case ":$PATH:" in *::*|*:.:*) echo "UNSAFE PATH: contains . or empty entry";; *) echo "PATH ok";; esac
exit $missing
MISSING: APP_ENV MISSING: DB_HOST PATH ok

Run with only APP_ENV exported, so DB_HOST is reported.

PATH=~/bin replaced the whole list, so the shell only looks in ~/bin: backup is found, ls is not. Fix the open terminal: export PATH=/usr/local/bin:/usr/bin:/bin (or open a new terminal). The right line: export PATH="$HOME/bin:$PATH", saved in ~/.bashrc to keep it (Lesson 12.2).
