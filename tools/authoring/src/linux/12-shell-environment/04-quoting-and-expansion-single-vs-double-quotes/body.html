The problem

Riya’s backup script works for months. Then a colleague saves a file called Q3 report.xlsx, with a space, and the script fails with “No such file: Q3” and “No such file: report.xlsx”. Another script prints a price as Price: 5 instead of Price: $5. A third one, meant to delete $dir/*, nearly deletes /* because $dir was empty. All three are quoting bugs. Before running any command, the shell rewrites your line: it expands $variables, $(commands), * wildcards and ~, then splits the result into words. Quotes decide which of those steps happen.

By the end of this page you will be able to:
  • explain exactly what single quotes, double quotes, backslash and $'…' protect, and what they do not
  • avoid word splitting and globbing bugs by quoting variables: "$var", "$@", "$(cmd)"
  • know the difference between $*, "$*", $@ and "$@", checked with real runs
  • combine quotes, print quotes inside quotes, and debug with printf '[%s]\n' and set -x

2 Definition

Quoting and expansion

Formal definition (write this in exams)

Quoting removes the special meaning of characters to the shell. Single quotes preserve every character literally. Double quotes preserve everything except $, ` and \ (so variable, command and arithmetic substitution still happen) and prevent word splitting and pathname expansion. A backslash quotes the single next character. Expansion is the rewriting the shell does to an unquoted line before running it.

In simple words

Single quotes: exactly as typed. Double quotes: fill in $, keep it one piece.

Quoting at four depths

Very basic No jargon: envelopes

How your text travels to the command.

Basic What you will type every day

  • echo "Hello $USER": double quotes, the variable is filled in.
  • echo 'Cost: $5': single quotes, printed exactly.
  • cp "$file" "$dest": quote every variable that holds a name.
  • echo "She said \"hi\"": backslash before a quote inside the same kind of quotes.

Intermediate The rules

  • Single quotes: everything literal; a single quote cannot appear inside, not even as \'.
  • Double quotes: $var, ${…}, $(…), `…`, $((…)) and \ before $ ` " \ still work; no word splitting, no wildcards, no ~.
  • Backslash outside quotes protects the next character (a space, *, $).
  • $'…' (ANSI-C) understands \n \t \e \'.
  • "$@" gives each argument as its own word; "$*" joins them into one; unquoted $@/$* are split again at spaces.

Advanced Behind the screen: the order of expansions

  • For each line bash does: brace expansion → tilde → parameter, arithmetic and command substitution (left to right) → word splitting → pathname expansion (globbing) → quote removal. Full order in Lesson 12.11.
  • Word splitting uses IFS (space, tab, newline by default) and happens only on the results of unquoted expansions, never on text you typed.
  • Quote removal is last: the program never sees your quotes. echo "a" and echo a pass the same argument.
  • History expansion (!) runs before all of this in interactive shells, even inside double quotes (Lesson 12.3).
  • [[ … ]] does no word splitting or globbing on variables; [ … ] is an ordinary command, so it does (Lesson 12.8).

Did you know? Quotes are for the shell, not for the program. When you type grep "error" log.txt, grep receives error without quotes. That is why grep "my error" works: the quotes only told the shell to keep the two words together.

EXAM> “Difference between single and double quotes in shell?” → Single quotes preserve the literal value of every character; double quotes allow $, ` and \ (variable, command and arithmetic substitution) but still prevent word splitting and globbing.
Quick check What does echo "Today is $(date +%A)" print, and what does the same with single quotes print?

✗“Without double quotes, $* expands to a single string”

Undo and safety net

Quoting mistakes are fixed by quoting; the damage is in what the command did.

  • A loop split a name with spaces: quote the variable; for lists of names use arrays or find -print0 | xargs -0.
  • An empty variable widened a command (rm, chmod): use ${var:?} and set -u; test with echo first.
  • The prompt shows > and waits: an unclosed quote; press Ctrl+C and retype.
  • Not sure what the shell made of a line: printf '[%s]\n' … or set -x (Lesson 12.6).

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. f="my report.txt"; cat $f
    cat: my: No such file or directory cat: report.txt: No such file or directory exit status: 1

    What it means: Unquoted: split into my and report.txt.

    Fix: cat "$f".

  2. echo 'it's'
    /home/riya/script.sh: line 1: unexpected EOF while looking for matching `''

    What it means: The quote in it's closed the string; the next one opens a new one that never ends.

    Fix: "it's" or 'it'\''s'.

  3. [ $name = Riya ]
    /home/riya/script.sh: line 1: [: =: unary operator expected exit status: 2

    What it means: Empty $name leaves [ = Riya ]: too few words.

    Fix: [ "$name" = Riya ].

  4. echo "${HOME"
    /home/riya/script.sh: line 2: unexpected EOF while looking for matching `"'

    What it means: Missing } in a ${ } expansion.

    Fix: "${HOME}".

Quick check Why does [ $name = Riya ] fail when name is empty, but [ "$name" = Riya ] works?
Answer: Unquoted, the empty value disappears and [ sees “= Riya”. Quoted, it sees an empty string "" as the first word.

6 Real-world use

Quoting at work

1. Backup and file scripts

Every path variable is quoted, because users create file names with spaces, brackets and dashes.

Name→"$f"→safe

2. Data pipelines

awk, sed and jq programs go in single quotes so $1 and $field reach the tool, not the shell.

Program→'...'→run

3. Wrappers and entrypoints

Docker entrypoints and tool wrappers end with exec "$@" to pass every argument unchanged.

Wrap→"$@"→exec

4. Safety in production

Famous outages were caused by rm -rf $DIR/ with an empty DIR. Quoting plus ${VAR:?} stops it.

Check→${v:?}→stop

5. Remote commands

Single quotes send the command to the server unexpanded; double quotes expand locally first.

Local→'...'→remote

Script it: safe-copy.sh

A copy tool that survives any file name: spaces, leading dashes, asterisks. It refuses an empty destination and passes all names with "$@".

dest=${DEST:?set DEST to a folder}
mkdir -p -- "$dest"
for f in "$@"; do
  if [ -f "$f" ]; then cp -- "$f" "$dest/" && echo "copied: $f"; else echo "skipped: $f" >&2; fi
done

With dir empty, rm -rf $dir/* becomes rm -rf /*: an attempt to delete everything the user can reach. Make it safe with "${dir:?}" (stop if empty or unset) and quotes: rm -rf -- "${dir:?}"/*, and add set -u at the top of the script (Lesson 12.6).
