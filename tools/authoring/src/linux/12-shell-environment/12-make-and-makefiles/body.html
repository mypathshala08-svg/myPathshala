The problem

Riya’s project has ten C files. After changing one, she runs gcc *.c -o app, waiting for all ten to compile again. Her data job is the same: she reruns every step of a report even when only the last input changed, and sometimes forgets a step. make fixes both. A Makefile lists targets (files to build), their prerequisites (files they depend on) and the recipe (commands). make compares file times and rebuilds only what is out of date, in the right order. It is used to build the Linux kernel, C programs, documentation sites, Docker images and data pipelines.

By the end of this page you will be able to:
  • write a Makefile with targets, prerequisites and tab-indented recipes
  • explain how make decides what to rebuild from timestamps, and read its messages
  • use variables, automatic variables ($@ $< $^), pattern rules and .PHONY targets
  • run make with -n, -B, -j, -C, -f and VAR=value, and fix “missing separator” and “No rule to make target”

2 Definition

make and the Makefile

Formal definition (write this in exams)

make is a build automation tool. It reads a Makefile made of rules: a target, its prerequisites and a recipe of shell commands. make rebuilds a target only when it is missing or older than one of its prerequisites, and builds prerequisites first.

In simple words

Write down what depends on what once; make works out what to redo.

Words you’ll meet in this lesson

PrerequisiteA file the target depends on.
RecipeTAB-indented commands that make the target.
Ruletarget: prerequisites + recipe.
Phony targetA name for an action, not a file (clean).
Pattern rule%.o: %.c, a rule for many files.

make at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a recipe card with a memory

Each card says what to make, from what, and how.

Basic What you will type

  • make: build the first target in ./Makefile.
  • make clean: run the clean target.
  • make -n: show the commands without running them.
  • A rule: target: prerequisites, then recipe lines that start with a TAB.

Intermediate Variables and patterns

  • CC = gcc, used as $(CC).
  • $@ the target, $< the first prerequisite, $^ all prerequisites.
  • Pattern rule %.o: %.c: how to make any .o from its .c.
  • .PHONY: clean: clean is a name, not a file.
  • Each recipe line runs in its own shell: cd dir on one line is forgotten on the next.

Advanced Behind the screen: the dependency graph

  • make reads the whole Makefile, builds a graph of targets and prerequisites, then walks it depth-first from the goal.
  • For each node it compares modification times (mtime, from stat). Missing target or newer prerequisite → rebuild. File systems store times to the nanosecond, but GNU make 4 compares them to the nanosecond, so “newer” means newer, not “different”: an older file restored with cp -p, tar or rsync does not trigger a rebuild.
  • Recipes run with /bin/sh -c (dash on Ubuntu) unless SHELL := /bin/bash; $ must be written $$ to reach the shell.
  • If a recipe line fails (non-zero exit), make stops and may delete a half-built target (.DELETE_ON_ERROR).
  • -j N runs independent branches of the graph at the same time; missing prerequisites then show up as random build failures.

Did you know? Stuart Feldman wrote make in 1976 after a colleague lost a morning debugging a program that was fine; he had just forgotten to recompile one file. Feldman later said that the TAB rule was a mistake he kept because a dozen people already used it.

EXAM> “What is the use of make?” → To automate building: it rebuilds only targets whose prerequisites changed, in dependency order, using rules in a Makefile.
Quick check Why does make say “up to date” on the second run?
Answer: Every target is newer than all its prerequisites, so no recipe needs to run.

target: prerequisites ⏎ <TAB>recipe a rule and how make decides

🟡 Changes filesno sudo

make starts at the first target (or the one you name), checks its prerequisites first, then runs the recipe if the target is missing or older than any prerequisite. It prints each command before running it (prefix a line with @ to hide it).

✓ Use it when

✗ Don’t use it when

CC = gcc · $(CC) · $@ $< $^ · %.o: %.c variables, automatic variables and pattern rules

✗ Don’t use it when

.PHONY: all clean test install phony targets

🟡 Changes filesno sudo

A phony target is a name for an action. Declaring it in .PHONY tells make never to look for a file with that name, so the recipe always runs. Without it, a file called clean makes the target “up to date” forever (the puzzle). A phony all listed first lets make build several things.

✓ Use it when
  • clean, test, install, all, help
  • targets that are actions, not files
✗ Don’t use it when
  • forgetting .PHONY (a file named clean breaks it)

Syntax: .PHONY: clean · all: prog docs · make clean

Undo and safety net

make only runs what you wrote; the risky parts are clean targets and install.

  • Not sure what make will do: run make -n first.
  • clean removed too much: restore from git; keep clean to built files only (no rm -rf *).
  • Build is stale or confused: make clean && make or make -B.
  • sudo make install put files everywhere: try sudo make uninstall; next time use a package or checkinstall (Lesson 14.4).

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. cd ~/mkx; make
    Makefile:2: *** missing separator. Stop. exit status: 2

    What it means: Recipe indented with spaces.

    Fix: Use a TAB.

  2. cd ~/mkx; make nope
    make: *** No rule to make target 'nope'. Stop. exit status: 2

    What it means: No such target.

    Fix: Check spelling; make help.

  3. cd ~/mkx; make
    make: *** No targets specified and no makefile found. Stop. exit status: 2

    What it means: No Makefile here.

    Fix: cd to the project, or make -C / -f.

  4. cd ~/mkx; make
    make: *** No rule to make target 'in.txt', needed by 'out'. Stop. exit status: 2

    What it means: A prerequisite file is missing and no rule makes it.

    Fix: Create it or add a rule.

  5. cd ~/mkx; make
    false make: *** [Makefile:2: all] Error 1 exit status: 2

    What it means: A recipe command failed, so make stopped.

    Fix: Fix the command; - prefix to ignore.

Create a starter Makefile for a C program (with variables, a pattern rule, all, clean and help), then build and run it.

dir=${1:-starter}
mkdir -p "$dir" && cd "$dir" || exit 1
printf '#include <stdio.h>\nint main(void){ puts("built by make"); return 0; }\n' > main.c
printf '%s\n' 'CC ?= gcc' 'CFLAGS ?= -Wall -O2' 'SRC := $(wildcard *.c)' 'OBJ := $(SRC:.c=.o)' '' \
  '.PHONY: all clean' 'all: app' 'app: $(OBJ)' '	$(CC) $(CFLAGS) -o $@ $^' '%.o: %.c' '	$(CC) $(CFLAGS) -c $<' 'clean:' '	rm -f app $(OBJ)' > Makefile
make -s && ./app
make
make -s clean && ls
built by make make: Nothing to be done for 'all'. Makefile main.c

Run without a name, so it uses the starter folder.

Puzzle answer Remember the question from the story? Open to check your guess.

1. Recipe lines must start with a TAB; spaces give “missing separator”. 2. make only asks “is a prerequisite newer than the target?”. cp -p kept the backup’s old timestamp, so sales.csv looked older than report.txt. Run touch sales.csv or make -B. 3. A file named clean appeared in the folder (for example from make clean > clean). With no prerequisites, that file is always “up to date”. Declare .PHONY: clean so make never treats it as a file.
