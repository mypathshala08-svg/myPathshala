The problem

Riya types ls -lh --color=auto forty times a day, and cd /var/www/html/projects/myphatshala/static twenty times. Yesterday she ran a perfect 120-character find … -exec command; today she cannot remember it. Bash has three tools for exactly this: aliases (short names for long commands), history (every command you typed, searchable and re-runnable) and keyboard shortcuts (Ctrl+R, Ctrl+A, Alt+.) that make editing a command line ten times faster. They are the difference between fighting the terminal and flying through it.

By the end of this page you will be able to:
  • create, list, use and remove aliases; make them permanent; know when an alias is the wrong tool
  • use history: list, search with Ctrl+R and grep, re-run with !!, !n, !string, fix typos with ^old^new, and reuse arguments with !$ and Alt+.
  • control history: HISTSIZE, HISTFILESIZE, HISTCONTROL, HISTTIMEFORMAT, HISTIGNORE, history -c, -d, -a
  • edit command lines fast with the readline shortcuts: Ctrl+A, Ctrl+E, Ctrl+U, Ctrl+K, Ctrl+W, Ctrl+L, Ctrl+C, Ctrl+D, Tab

2 Definition

Aliases, history and keyboard shortcuts

Formal definition (write this in exams)

An alias is a name that the shell replaces with a string of text when it appears as the first word of a simple command. The history is the list of commands the shell has read, kept in memory and saved to ~/.bash_history; history expansion (!!, !n, !string, ^old^new) re-uses entries. Keyboard shortcuts are readline key bindings for moving, editing, completing and searching the command line.

In simple words

Alias = short name. History = memory. Shortcuts = fast editing.

Aliases and history at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: speed dial and call log

Your phone already does this.

Basic What you will type every day

  • alias ll='ls -lh' then ll. alias alone lists them; unalias ll removes one.
  • history lists your commands; !! repeats the last; sudo !! repeats it as root.
  • Ctrl+R then type: search backwards; Enter runs, → edits, Ctrl+G cancels.
  • ↑/↓ walk through history; Tab completes names.

Intermediate The rules

  • Only the first word of a command is checked for an alias (and the word after an alias ending in a space: alias sudo='sudo ').
  • Define aliases with single quotes so $vars are expanded when used, not when defined.
  • Aliases are not expanded in scripts (shopt expand_aliases is off) and are expanded when a line is read, so an alias defined on a line is not usable on that same line.
  • History expansion (!) happens before everything else, even inside double quotes: echo "hi!" can surprise you. Use single quotes or set +H.
  • HISTSIZE = lines kept in memory; HISTFILESIZE = lines in ~/.bash_history; the file is written when the shell exits.

Advanced Behind the screen: readline and the history list

  • Line editing (Ctrl+A, Ctrl+R, Tab) is the GNU readline library, shared with python, mysql, psql and gdb. Its settings are in ~/.inputrc (e.g. set completion-ignore-case on).
  • Default key map is Emacs style; set -o vi switches to vi mode (Lesson 12.6).
  • Two terminals each keep their own in-memory list and overwrite each other’s file at exit unless shopt -s histappend (Ubuntu’s default .bashrc sets it). PROMPT_COMMAND='history -a' saves after every command.
  • Ctrl+S (forward search) is often swallowed by terminal flow control; stty -ixon frees it.
  • History is a convenience, not an audit log: users can edit or delete it. Real auditing uses auditd and system logs.

Did you know? sudo !! is probably the most-typed fix in Linux: you run a command, get “Permission denied”, and re-run exactly the same command as root without retyping it.

EXAM> “How do you make an alias permanent?” → Add the alias line to ~/.bashrc and run source ~/.bashrc.
Quick check Is ll a command on every Linux system?
Answer: No. It is an alias defined in many default .bashrc files (Ubuntu: ls -alF). type ll shows what it is on your machine.
Common mistake
✗alias rm='rm -i' (as your only protection)
✓Keep it if you like, but never rely on it: scripts, other users, sudo and root shells do not have it. Use rm -i explicitly and backups.

Aliases expand only in your interactive shell. The day you are on another server or in a script, rm deletes without asking.

Common mistake
✗alias today="echo $(date +%F)"

Undo and safety net

History and aliases are easy to reset.

  • Bad alias: unalias NAME; remove the line from ~/.bashrc.
  • All aliases broken: unalias -a, then source ~/.bashrc after fixing.
  • Secret in history: history -d N, edit ~/.bash_history, change the secret.
  • Pressed Ctrl+S and the terminal froze: press Ctrl+Q (flow control); stty -ixon disables it.
  • Stuck in Ctrl+R: Ctrl+G cancels the search.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. alias ll = 'ls -l'

    What it means: Spaces around = (alias sees three words).

    Fix: alias ll='ls -l'.

  2. unalias nothere
    /home/riya/script.sh: line 1: unalias: nothere: not found exit status: 1

    What it means: No such alias.

    Fix: alias to list them.

    What it means: No entry with that number.

    Fix: history first.

More examples and variations

Variations on aliases and history. Aliases are switched on with shopt -s expand_aliases because these run as scripts.

Alias variations

V1

Alias with a pipe

shopt -s expand_aliases
alias biggest='du -s ~/sz/* | sort -rn | head -3'
biggest | awk '{print $2}' | sed 's|.*/||'
data logs tmp

An alias can hold a whole pipeline.

V2

Alias that chains commands

shopt -s expand_aliases
alias mkcd_demo='mkdir -p demo && cd demo'
mkcd_demo; pwd | sed 's|.*/||'
demo

&& inside an alias; to pass the folder name as an argument, use a function (12.10).

V3

Overriding a command safely

shopt -s expand_aliases
alias df='df -h'
df / | head -1
command df / | head -1
Filesystem Size Used Avail Use% Mounted on Filesystem 1K-blocks Used Available Use% Mounted on

The alias adds -h; command df bypasses it.

V4

Why aliases cannot take middle arguments

shopt -s expand_aliases
alias greet='echo Hello, and welcome'
greet Riya
greetf(){ echo "Hello $1, and welcome"; }; greetf Riya
Hello, and welcome Riya Hello Riya, and welcome

Arguments always go at the end of an alias; a function puts them anywhere.

History variations

V5

Search a history file by date

printf '%s\n' '#1794370000' 'df -h' '#1794373600' 'systemctl restart app' > h.txt
HISTTIMEFORMAT='%F %H:%M ' ; history -r h.txt; history | grep restart | sed 's/^ *//'
2 2026-11-11 10:36 systemctl restart app

With timestamps you can answer “when did I restart it?”.

V6

Ignore some commands

HISTIGNORE='ls:pwd'
printf '%s\n' ls pwd 'df -h' > h.txt; history -r h.txt; history | sed 's/^ *//'
1 ls 2 pwd 3 df -h

HISTIGNORE applies to new entries you type; history -r loads all lines, so here all three appear. In your terminal ls and pwd would not be saved.

V7

Count commands per day of work

printf '%s\n' 'git pull' 'make' 'git push' 'make' 'make' > h.txt
awk '{print $1}' h.txt | sort | uniq -c | sort -rn
3 make 2 git

Your history is data: find what to alias.

V8

Clear and check

printf '%s\n' a b > h.txt; history -r h.txt; history -c; history | wc -l
0

history -c empties the list in memory (the file is untouched).

Script it: alias-report.sh

A small check for a .bashrc: list its aliases, warn about double-quoted ones that contain $ (evaluated too early) and about aliases that hide standard commands.

f=${1:-$HOME/.bashrc}
grep -E "^alias " "$f" | while read -r line; do
  name=${line#alias }; name=${name%%=*}
  echo "alias: $name"
  case $line in *'="'*'$'*) echo "  WARNING: double quotes with \$ (expanded once, when defined)";; esac
  [ -x "/usr/bin/$name" ] && echo "  NOTE: hides /usr/bin/$name (use \\$name for the real one)"
done
alias: ll alias: la alias: l alias: alert

Run on riya’s default Ubuntu .bashrc.

Puzzle answer Remember the question from the story? Open to check your guess.

Aliases are expanded only in interactive shells; a script runs with expand_aliases off, so rm *.tmp inside cleanup.sh is the real rm. Relying on the alias is dangerous because the same habit (typing rm and waiting for a question) deletes files without warning on any other machine, in scripts, under sudo or as root. Use rm -i explicitly when you want to be asked, and keep backups.
