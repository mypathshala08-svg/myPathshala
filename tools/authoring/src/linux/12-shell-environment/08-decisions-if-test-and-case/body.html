The problem

A script that never decides anything is just a list. Real scripts check: does the backup folder exist, is the disk more than 90% full, did the user type a number, which action did they ask for (start, stop, status)? Bash decides with if (one or two paths, elif for more), with case (many choices by pattern), and with tests written as [ … ], test …, [[ … ]] or (( … )). The trickiest part is not the syntax but the details: spaces inside brackets, quotes around variables, and using the right operator for numbers (-gt) versus strings (>).

By the end of this page you will be able to:
  • write if-then-fi, if-else, elif chains and nested ifs, and know that if tests an exit status
  • use the test command and its three families: file tests (-e -f -d -r -w -x -s -L -nt), string tests (= != -z -n) and number tests (-eq -ne -lt -le -gt -ge)
  • choose between [ ], [[ ]] and (( )); use &&, ||, ! and pattern / regex matching with =~
  • write case statements with several patterns, wildcards and a default, and avoid the classic bracket, quoting and case-sensitivity mistakes

2 Definition

if, test and case

Formal definition (write this in exams)

if runs a command list and executes the then part when its exit status is 0, otherwise the elif/else parts. test (also written [ … ]) evaluates file, string and integer expressions and returns 0 (true) or 1 (false); bash adds [[ … ]] with pattern and regex matching and (( … )) for arithmetic. case compares a word against patterns and runs the commands of the first matching pattern.

In simple words

if = do this if the command succeeded. test = a command that answers yes (0) or no (1). case = pick a branch by pattern.

Decisions at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: signals and junctions

The test is a signal; if and case choose the track.

Basic The shapes you will type

  • if [ -f report.txt ]; then echo found; fi
  • if [ "$n" -gt 10 ]; then …; else …; fi
  • if …; then …; elif …; then …; else …; fi
  • case "$1" in start) … ;; stop) … ;; *) echo usage ;; esac

Intermediate The rules

  • [ needs spaces: [ "$a" = "$b" ], never ["$a"="$b"]. The last argument must be ].
  • Strings: =, !=, -z, -n. Numbers: -eq -ne -lt -le -gt -ge. Inside [ ], > and < are redirections unless escaped (and then they compare text, not numbers).
  • Quote variables inside [ ]: an empty unquoted variable disappears and breaks the test.
  • [[ ]] (bash): no word splitting, == with patterns (*.log), =~ regex, && and || inside. (( )): arithmetic with > < ==.
  • case compares one value against glob patterns (* ? [ ] |), top to bottom, and runs only the first match; ;; ends a branch.

Advanced Behind the screen: commands and statuses

  • [ and test are shell builtins (there is also a /usr/bin/[ program); [[ is a keyword, parsed before expansion, which is why it can treat &&, < and unquoted variables safely.
  • if takes a whole list: if cd /x && ls; then uses the status of the last command.
  • -a / -o inside [ ] are obsolete and ambiguous; use [ … ] && [ … ] or [[ … && … ]].
  • =~ uses POSIX extended regex; quote nothing on the right (quoted parts become literal); captures go to BASH_REMATCH.
  • case terminators: ;; stop, ;& run the next branch too, ;;& test the next patterns too (bash 4).

Did you know? true and false are tiny commands that only return 0 and 1. That is why while true; do … done loops forever and if false; then never runs: the shell has no boolean type, only exit statuses.

EXAM> “Write a script to check whether a number is positive, negative or zero.” → if [ "$n" -gt 0 ]; then echo positive; elif [ "$n" -lt 0 ]; then echo negative; else echo zero; fi.
Quick check Why does [ "$a"="$b" ] always say true?
Answer: Without spaces it is ONE word, "x=y", and a single non-empty string is true. Write [ "$a" = "$b" ].
Common mistake
✗if [[ $num -gt 0]] ; then
✓if [[ $num -gt 0 ]]; then

]] must be a separate word: without the space bash reports “syntax error in conditional expression”. Checked (from the class notes’ positive/negative example).

Common mistake
✗Vowel check: [ "$char" == "a" ] || … || [ "$char" == "u" ] then [[ $char =~ [a-zA-Z] ]] → consonant
✓case $char in [aeiouAEIOU]) echo vowel;; [a-zA-Z]) echo consonant;; *) echo "not a letter";; esac

The notes’ version reports A, E, I, O, U as consonants (only lowercase vowels are listed), and [[ =~ [a-zA-Z] ]] also accepts “ab”. Real run: a → vowel, A → consonant.

Common mistake
✗Days example: prompt says “Monday”, patterns are monday) tuesday) …
✓case ${day,,} in monday) … (convert to lowercase first) or [Mm]onday)

Undo and safety net

Decisions do not change anything by themselves; check them before the commands they guard.

  • Not sure which branch will run: run with bash -x (12.6): you see each test and its values.
  • A stray file appeared (named 10, 5…): a > or < inside [ ] created it: delete it and use -gt/-lt.
  • Script works in bash, fails with sh: [[ ]] and (( )) are bash-only; use #!/bin/bash or [ ].
  • case never matches: check upper/lower case and spaces in the value: printf '[%s]\n' "$x".

6 Real-world use

Decisions at work

1. Service scripts

Init and helper scripts use case "$1" in start|stop|restart|status — the most common shell pattern in Linux.

Action→case→run

2. Backups and clean-ups

Check that the source exists, the target is writable and the disk has space before copying or deleting.

Check→[ -d ]→copy

3. Monitoring

Threshold checks (disk, load, queue length) with elif ladders send OK / WARNING / CRITICAL.

Measure→elif→alert

4. Input validation

Scripts check that arguments are numbers, dates or IDs before using them in SQL or commands.

Input→[[ =~ ]]→safe

5. CI quality gates

Pipelines fail a build if grep finds TODO in release code or a test report contains failures.

Scan→if grep→pass/fail

Examples are simplified and generic. They describe common patterns, not the internal systems of any particular company.

More examples and variations

Fifteen more decision scripts, each a variation of the examples above. All were really run on our build machine.

if variations

V1

Even or odd

for n in 4 7; do if (( n % 2 == 0 )); then echo "$n even"; else echo "$n odd"; fi; done
4 even 7 odd

% gives the remainder; (( )) tests it.

V2

Largest of three numbers

a=12; b=45; c=27
if (( a >= b && a >= c )); then max=$a
elif (( b >= c )); then max=$b
else max=$c; fi
echo "largest: $max"
largest: 45

&& inside (( )); elif narrows the choice.

V3

Leap year (nested logic)

for y in 2024 1900 2000 2026; do
  if (( y % 400 == 0 )) || { (( y % 4 == 0 )) && (( y % 100 != 0 )); }; then echo "$y leap"; else echo "$y not leap"; fi
done
2024 leap 1900 not leap 2000 leap 2026 not leap

A classic exam question; { } groups the && part.

V4

Grade from marks (elif ladder)

for m in 92 78 55 30; do
  if (( m >= 90 )); then g=A; elif (( m >= 75 )); then g=B; elif (( m >= 50 )); then g=C; else g=F; fi
  echo "$m -> $g"
done
92 -> A 78 -> B 55 -> C 30 -> F

Check the highest range first.

V5

One-line if with && and ||

f=/etc/hostname
[ -r "$f" ] && echo "can read $f" || echo "cannot read $f"
can read /etc/hostname

Short form; but if the && part fails, the || part also runs, so use a full if when the then-part can fail.

V6

Check several required files at once

cd ~/dc; missing=0
for f in app.conf run.sh secrets.env; do [ -f "$f" ] || { echo "missing: $f"; missing=1; }; done

Collect problems first, decide at the end.

V7

Is the script run as root?

if [ "$(id -u)" -eq 0 ]; then echo 'root'; else echo "normal user $(whoami)"; fi
normal user riya

UID 0 = root (Lesson 8.1).

V8

Empty or missing argument

check(){ if [ -z "${1:-}" ]; then echo 'no argument given'; else echo "argument: $1"; fi; }
check; check report.txt
no argument given argument: report.txt

${1:-} avoids a set -u error; -z tests empty.

V9

Compare two files

cd ~/dc; cp app.conf copy.conf
if cmp -s app.conf copy.conf; then echo 'identical'; fi
echo 'port=9090' > copy.conf
cmp -s app.conf copy.conf || echo 'they differ now'
identical they differ now

cmp -s is silent; its exit status is the answer.

V10

Does a user exist?

for u in riya ghost; do if id "$u" > /dev/null 2>&1; then echo "$u exists"; else echo "$u does not exist"; fi; done
riya exists ghost does not exist

Any command can be a test.

[[ ]] and case variations

V11

Email-like format check

for e in riya@cdac.in riya@ bad.mail; do [[ $e =~ ^[^@]+@[^@]+\.[a-z]+$ ]] && echo "$e looks valid" || echo "$e is invalid"; done
riya@cdac.in looks valid riya@ is invalid bad.mail is invalid

A simple regex; real email validation is much harder.

V12

Vowel or consonant, all cases

for c in a E k 7 ab; do
  case $c in [aeiouAEIOU]) echo "$c vowel";; [a-zA-Z]) echo "$c consonant";; *) echo "$c not a single letter";; esac
done
a vowel E vowel k consonant 7 not a single letter ab not a single letter

The corrected version of the class-notes example: upper-case vowels and “ab” are handled.

V13

Day of the week, any capitals

for day in Monday SATURDAY friday holiday; do
  case ${day,,} in
    saturday|sunday) echo "$day: weekend";;
    monday|tuesday|wednesday|thursday|friday) echo "$day: working day";;
    *) echo "$day: not a day";;
  esac
done
Monday: working day SATURDAY: weekend friday: working day holiday: not a day

${day,,} lowercases, so Monday and SATURDAY match.

V14

Car brand to country (notes example, fixed)

for car in Tesla bmw Toyota Tata; do
  case ${car,,} in
    tesla) c=USA;; bmw|mercedes|audi|porsche) c=Germany;; toyota|mazda|subaru) c=Japan;; *) c=unknown;;
  esac
  echo "$car: $c"
done
Tesla: USA bmw: Germany Toyota: Japan Tata: unknown

Same idea as the notes; lowercase first so bmw and BMW both match.

Menu with numbers and words

for x in 1 stop 7 x; do choose "$x"; done

Script it: check-env.sh

A start-up check that uses every kind of test from this lesson: arguments, files, permissions, numbers, regex and case.

env=${1:-dev}
case $env in dev|test|prod) ;; *) echo "unknown environment: $env" >&2; exit 2;; esac
conf=$HOME/dc/app.conf
[ -f "$conf" ] || { echo "missing $conf" >&2; exit 1; }
[ -r "$conf" ] || { echo "cannot read $conf" >&2; exit 1; }
port=$(grep -oP '(?<=port=)[0-9]+' "$conf")
if [[ ! $port =~ ^[0-9]+$ ]]; then echo "bad port"; exit 1
elif (( port < 1024 )) && [ "$(id -u)" -ne 0 ]; then echo "port $port needs root"; exit 1
fi
echo "env=$env port=$port: all checks passed"
env=dev port=8080: all checks passed

Run with the default environment on the lesson’s sample folder.

Puzzle answer Remember the question from the story? Open to check your guess.

Inside [ ], > 10 is a redirection: the shell ran [ 5 ] with its output sent to a new file called 10. [ 5 ] (one non-empty word) is always true, so “too many” is printed for any value. Correct: [ "$count" -gt 10 ] or (( count > 10 )), then delete the stray file 10.
