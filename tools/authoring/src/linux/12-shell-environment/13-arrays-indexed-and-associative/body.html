The problem

Riya keeps server names in server1, server2, server3 and loops over them with eval. When a fourth server arrives she edits five places. Bash has arrays: one variable holding a list (servers=(web01 web02 db01)), and associative arrays that map a name to a value (ip[web01]=10.0.0.11). Arrays are also the only safe way to keep a list of file names that contain spaces, and to build a command with arguments. This lesson covers both kinds, every ${…} form that works on them, mapfile to read files into arrays, and the mistakes that silently break scripts.

By the end of this page you will be able to:
  • create indexed arrays, read and change items, and loop over them safely with "${arr[@]}"
  • use the length, indices, slicing, appending and deleting forms, and know $@ vs $* for arrays
  • create associative arrays with declare -A and use them as lookup tables and counters
  • fill arrays from commands and files with mapfile/readarray and read -a, and pass them to functions

2 Definition

Indexed and associative arrays in bash

Formal definition (write this in exams)

An array is a variable that holds many values. An indexed array numbers its items from 0; an associative array (declare -A, bash 4+) uses string keys. Items are read with ${name[index]}, all items with "${name[@]}", and the count with ${#name[@]}.

In simple words

One name, many boxes: numbered or labelled.

Arrays at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: lockers and drawers

A row of numbered lockers, or a cabinet with labelled drawers.

Basic What you will type

  • fruits=(apple banana cherry): create.
  • echo "${fruits[0]}": first item.
  • echo "${#fruits[@]}": how many.
  • for f in "${fruits[@]}"; do …; done: every item.

Intermediate All the forms

  • "${a[@]}" each item as one word; "${a[*]}" all items joined into one word (first char of IFS).
  • ${!a[@]} the indices or keys; ${a[@]:1:2} a slice.
  • a+=(x y) append; unset 'a[1]' delete one (indices are not renumbered); unset a delete all.
  • declare -A m associative; ${m[key]}; [[ -v m[key] ]] exists?

Advanced Behind the screen: sparse arrays and references

  • Indexed arrays are sparse: after unset 'a[1]' the indices are 0 2; a[100]=x does not create 98 empty items. Loop over "${!a[@]}", not 0..length-1.
  • $a alone means ${a[0]}; ${#a} is the length of item 0 (the puzzle’s 14).
  • Without declare -A, ip[web01] is an indexed array and the key is evaluated as arithmetic: web01 is an unset variable = 0, so every key lands on index 0.
  • Arrays cannot be exported to child processes; functions get them by name with local -n ref=$1 (bash 4.3+) or as "$@".
  • Associative arrays need bash 4+ (macOS ships bash 3.2); key order is not guaranteed, so pipe through sort.
  • POSIX sh (dash) has no arrays at all; only "$@".

Did you know? Bash arrays start at 0, zsh arrays start at 1. The same script a=(x y); echo $a[1] prints different things in the two shells, one reason scripts start with #!/bin/bash.

EXAM> “How do you find the number of elements in an array?” → ${#arr[@]}. (${#arr} is the length of the first element.)
Quick check With a=(red green blue), what is ${a[2]}?
Answer: blue (counting from 0).
Common mistake
✗for f in ${files[@]}
✓for f in "${files[@]}"

Unquoted, every item is split at spaces and globbed; "report jan.csv" becomes two items (real run). Quoted "${a[@]}" keeps each item whole.

Common mistake
✗ip[web01]=1 without declare -A
✓declare -A ip; ip[web01]=1

Without -A the key is arithmetic: web01 → 0, db01 → 0, so both write index 0 (real run prints 2).

${a[@]:s:n} · unset · ${a[*]} · ${a[@]/x/y} slicing, deleting and joining

🟢 Read-onlyno sudo

A slice ${a[@]:start:count} returns part of the array. unset 'a[i]' removes one item but does not renumber (quote it so [i] is not a glob). "${a[*]}" joins with the first character of IFS. String operations like /old/new and #prefix apply to every item.

✓ Use it when
  • slices, deletes, search-and-replace on all items
  • joining with a separator
✗ Don’t use it when
  • assuming indices are 0..n-1 after unset

🟢 Read-onlyno sudo

mapfile -t · readarray · read -ra · a=($(cmd)) filling arrays from files and commands

🟢 Read-onlyno sudo

mapfile -t arr < file puts each line into one item (-t removes the newline). For commands use process substitution < <(cmd). read -ra arr <<< "$line" splits one line by IFS. a=($(cmd)) splits at any space and expands wildcards, so avoid it for names.

✓ Use it when
  • reading files and command output into arrays
  • splitting a line into fields
✗ Don’t use it when
  • cmd | mapfile (subshell loses the array)
  • a=($(cmd)) with spaces or * in output

    Why this way: The pipe version filled an array in a subshell (0 here); $(ls) split the two names with spaces into four.

Undo and safety net

Arrays live only in the current shell.

  • Deleted the wrong item: rebuild from the source (file, command) or re-run the assignment.
  • Array empty after a pipe: use < <(cmd) instead of cmd |.
  • Wrong type (indexed vs associative): unset name, then declare -A name.
  • Inspect any array: declare -p name prints it exactly.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. declare -A m; m[]=1
    /home/riya/script.sh: line 1: m[]: bad array subscript exit status: 1

    What it means: An empty key is not allowed.

    Fix: Use a non-empty key; quote variables: m["$k"].

  2. a=(1 2); echo ${a[5]:?missing}
    /home/riya/script.sh: line 1: a[5]: missing

    What it means: Item 5 is unset; :? turned it into an error.

    Fix: Check ${#a[@]} or [[ -v a[5] ]].

  3. a=(1 2); declare -A a
    /home/riya/script.sh: line 1: declare: a: cannot convert indexed to associative array exit status: 1

    What it means: Cannot change an indexed array into an associative one.

    Fix: unset a first.

  4. a=(1 2); echo ${a[-5]}
    /home/riya/script.sh: line 1: a: bad array subscript exit status: 0

    What it means: Negative index beyond the start.

    Fix: Use a valid index.

Script it: inventory.sh

Read servers.txt into associative arrays, then print a sorted table, the number of servers that are up, and the IP of a host given as an argument.

mkdir -p ~/ar && cd ~/ar || exit 1
[ -f servers.txt ] || printf 'web01 10.0.0.11 up\nweb02 10.0.0.12 down\ndb01 10.0.0.21 up\n' > servers.txt
declare -A ip status
while read -r name addr st; do ip[$name]=$addr; status[$name]=$st; done < servers.txt
printf '%-8s %-12s %s\n' HOST IP STATE
for h in $(printf '%s\n' "${!ip[@]}" | sort); do printf '%-8s %-12s %s\n' "$h" "${ip[$h]}" "${status[$h]}"; done
up=0; for h in "${!status[@]}"; do [ "${status[$h]}" = up ] && ((up++)); done
echo "up: $up of ${#ip[@]}"
want=${1:-db01}
[[ -v ip[$want] ]] && echo "$want -> ${ip[$want]}" || echo "$want not found"
HOST IP STATE db01 10.0.0.21 up web01 10.0.0.11 up web02 10.0.0.12 down up: 2 of 3 db01 -> 10.0.0.21

Run without an argument, so it looks up db01.

Puzzle answer Remember the question from the story? Open to check your guess.

1. ${files[@]} without quotes splits every item at spaces, so two names became four words. Use "${files[@]}". 2. ${#files} means the length of ${files[0]} (“report jan.csv” has 14 characters); the count is ${#files[@]}. 3. Without declare -A, ip is an indexed array and the keys are arithmetic: web01 and db01 are unset variables = 0, so both assignments wrote index 0 and the last one (2) won.
