2 Definition

Positional parameters, read and shell arithmetic

Formal definition (write this in exams)

Positional parameters ($1, $2, …) hold the arguments given to a script or function; $0 is its name, $# their number and $@ / $* all of them. The read builtin reads a line from standard input and assigns its words to variables. Arithmetic expansion $(( expression )) evaluates integer expressions; expr is an older external command for the same, and bc handles decimal numbers.

In simple words

Arguments = input before the start. read = input during the run. $(( )) = whole-number maths.

Very basic No jargon: a courier form

Information can arrive before the job starts, or be asked for during it.

Basic What you will type every day

  • ./greet.sh Riya → inside, $1 is Riya.
  • echo "You gave $# arguments: $@".
  • read -p "Your city: " city asks and stores the answer.
  • total=$(( price * qty )) multiplies.

Intermediate The rules

  • $0 = how the script was called; $1–$9; from 10 on use braces: ${10}. $# = count; "$@" = all, each kept whole (Lesson 12.4).
  • shift drops $1 and moves the rest down; shift 2 drops two.
  • read a b c splits the line at IFS: the last variable gets everything left. Always use -r (keep backslashes).
  • $(( )): + - * / % ** and ( ), integers only, variables without $. Division truncates: 7/2 = 3.
  • expr needs spaces between every part and \* for multiply; it prints the result and exits 1 when the result is 0.

Advanced Behind the screen: how the numbers really work

  • Positional parameters come from the argv array given to execve() (Lesson 11.1); set -- replaces them, functions get their own set (12.10).
  • bash arithmetic is 64-bit signed: up to 9223372036854775807, then it wraps without warning. Numbers with a leading 0 are octal: $((010)) is 8, so $((08)) is an error (beware dates like 08, 09).
  • expr is an external program (/usr/bin/expr), so each call costs a fork: in a loop of 10,000 it is much slower than $(( )).
  • read reads one byte at a time from a pipe to stop exactly at the newline; cmd | read x runs read in a subshell, so x is lost (use <<< or < file).
  • bc is an arbitrary-precision calculator language; scale sets digits after the point and every step is truncated, not rounded.

Did you know? $0 is not always the file name you think: run the same script as ./s.sh, bash s.sh or /home/riya/s.sh and $0 is exactly what you typed. Use basename "$0" in usage messages.

EXAM> “Write a script that takes two numbers as arguments and prints their sum.” → echo "$1 + $2 = $(( $1 + $2 ))", with a check [ $# -eq 2 ] || { echo "usage: $0 A B"; exit 1; }.
Quick check A script is run as ./s.sh a b c d e f g h i j k. What do $10 and ${10} print?
Answer: $10 is ${1} followed by 0: a0. ${10} is the tenth argument: j.
Common mistake
✗letters=( "A""B""C""D""E" ); echo "${letters:1:3}" (expecting B C D)
✓letters=( A B C D E ); echo "${letters[@]:1:3}"

Without spaces "A""B"… is ONE element, ABCDE; ${letters:1:3} cuts characters from it (BCD). An array slice needs [@]. Checked on our build machine (from the class notes’ slicing example).

Common mistake
✗“255: exit status out of range”
✓Exit statuses are 0–255 and wrap: exit 256 gives 0 (success!), exit 300 gives 44

There is no error for out-of-range values; bash keeps only the lowest 8 bits. Checked: bash -c "exit 256"; echo $? prints 0.

$(( )) · (( )) · let whole-number maths

bc · awk decimals

🟢 Read-onlyno sudo

bc is a calculator: send it an expression on stdin. scale=N sets digits after the point (truncated, not rounded); -l loads the maths library (scale 20, sqrt, s, c, l, e). awk 'BEGIN{printf …}' is a handy alternative with printf rounding.

✓ Use it when
  • money, averages, percentages with decimals
  • big numbers
✗ Don’t use it when
  • tight loops (it starts a new process each time)

Undo and safety net

Input and maths do not change files; the risk is wrong numbers.

  • Wrong argument used: print them first: printf '[%s]\n' "$@".
  • read waits forever in a script: add -t SECONDS, or give the answer through a pipe / here-string.
  • Integer result where decimals were needed: use bc or awk; or multiply first (cents, percent × 100).
  • expr error: check spaces and \*; better switch to $(( )).

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. echo $(( 5 / 0 ))
    /home/riya/script.sh: line 1: 5 / 0 : division by 0 (error token is "0 ") exit status: 1

    What it means: Division by zero.

    Fix: Check the divisor first: (( d != 0 )).

  2. expr 5 + x
    expr: non-integer argument exit status: 2

    What it means: expr needs integers.

    Fix: Validate input: [[ $x =~ ^[0-9]+$ ]] (12.8).

  3. echo $(( 09 + 1 ))
    /home/riya/script.sh: line 1: 09: value too great for base (error token is "09") exit status: 1

    What it means: A leading 0 means octal; 9 is not an octal digit.

    Fix: $(( 10#09 + 1 )).

  4. bash -c 'echo ${1:?need a file name}'
    bash: line 1: 1: need a file name exit status: 127

    What it means: Required argument missing.

    Fix: Pass it: bash -c '…' _ file.txt.

Build it step by step: a salary calculator

Scenario: Riya builds a script that takes a salary as an argument and asks for a bonus percentage.

  1. 1. Require the salary argument.

    cd ~/si; printf '#!/bin/bash\nsal=${1:?usage: pay.sh SALARY}\n' > pay.sh; bash pay.sh 2>&1 | sed 's/.*: //'
    pay.sh SALARY

  2. 2. Ask for the bonus and compute it.

    cd ~/si; printf 'read -r -p "Bonus %%: " b\n' >> pay.sh; printf 'bonus=$(( sal * b / 100 ))\n' >> pay.sh; tail -2 pay.sh
    read -r -p "Bonus %: " b bonus=$(( sal * b / 100 ))

  3. 3. Print the total (answer 12 given through <<<).

    cd ~/si; printf 'echo "salary $sal + bonus $bonus = $(( sal + bonus ))"\n' >> pay.sh; bash pay.sh 85000 <<< 12
    salary 85000 + bonus 10200 = 95200

More examples and variations

Twelve more scripts that each change one thing, so you see arguments, read and arithmetic from every side. All were really run on our build machine.

Arguments

V1

Print every argument with its number

cat > list.sh <<'EOF'
n=1
for a in "$@"; do echo "arg $n: $a"; n=$((n + 1)); done
echo "total: $#"
EOF
bash list.sh alpha 'beta gamma' 42
arg 1: alpha arg 2: beta gamma arg 3: 42 total: 3

"$@" in a loop; a counter with $(( )).

V2

Required and optional arguments together

cat > greet.sh <<'EOF'
name=${1:?usage: greet.sh NAME [GREETING]}
greeting=${2:-Namaste}
echo "$greeting, $name!"
EOF
bash greet.sh Riya; bash greet.sh Aman 'Good morning'
Namaste, Riya! Good morning, Aman!

${1:?} stops without a name; ${2:-} gives a default.

V3

Last argument and all but the first

set -- copy a.txt b.txt c.txt /backup
echo "action: $1"
echo "last: ${!#}"
echo "files: ${@:2:$#-2}"
action: copy last: /backup files: a.txt b.txt c.txt

${!#} is the last argument; ${@:2:N} slices the list.

V4

Simple option handling with shift

cat > opts.sh <<'EOF'
verbose=0
while [ $# -gt 0 ]; do
  case $1 in -v) verbose=1;; -o) out=$2; shift;; *) file=$1;; esac
  shift
done
echo "verbose=$verbose out=${out:-none} file=${file:-none}"
EOF
bash opts.sh -v -o report.txt data.csv
verbose=1 out=report.txt file=data.csv

The classic loop: look at $1, consume it with shift. getopts does this formally.

Yes/no confirmation with a default

ask(){ read -r -p 'Delete old logs? [y/N] ' a; [ "${a:-n}" = y ] && echo deleting || echo 'skipped'; }
ask <<< 'y'; ask <<< ''

V6

Timeout with a default answer

if read -r -t 1 -p 'Environment [dev]: ' env < <(sleep 2); then :; else env=dev; echo "(no answer in 1 s, using $env)"; fi
(no answer in 1 s, using dev)

-t returns a non-zero status on timeout; then use the default.

V11

Compound assignment

x=10; (( x += 5 )); (( x *= 2 )); (( x -= 6 )); echo "$x"
let 'y = x / 4'; echo "$y"
24 6

Script it: calc.sh

A tiny calculator from the syllabus topics: two numbers and an operator as arguments, input checked, integer and decimal results.

[ $# -eq 0 ] && set -- 7 / 2      # demo values when run without arguments
[ $# -eq 3 ] || { echo "usage: calc.sh A OP B   (OP: + - x /)" >&2; exit 2; }
a=$1; op=$2; b=$3
case $op in
  +) r=$(( a + b ));; -) r=$(( a - b ));; x) r=$(( a * b ));;
  /) [ "$b" -ne 0 ] || { echo "cannot divide by zero" >&2; exit 1; }; r=$(bc <<< "scale=2; $a / $b");;
  *) echo "unknown operator: $op" >&2; exit 2;;
esac
echo "$a $op $b = $r"
7 / 2 = 3.50

Run without arguments, so it uses the demo values 7 / 2 (x is used for multiply so the shell does not expand *). case is explained in Lesson 12.8.

Puzzle answer Remember the question from the story? Open to check your guess.

$(( )) does integer arithmetic, so (85+90+92)/3 = 267/3 = 89 exactly, and (70+71+71)/3 = 212/3 = 70 with the .67 dropped. The expr version fails because ( and ) are shell syntax: they must be escaped (\( … \)) and separated by spaces. For 70.67: bc <<< "scale=2; (70+71+71)/3" gives 70.66 (truncated); awk 'BEGIN{printf "%.2f\n", 212/3}' gives 70.67 (rounded).
