2 Definition

grep: searching inside files

Formal definition (write this in exams)

grep searches its input files (or standard input) for lines that match a pattern, a regular expression, and prints the matching lines. Options change what is matched (case, whole words, inverted), what is printed (line numbers, counts, file names, only the match, context lines) and which files are searched (recursive, include/exclude). It never modifies the files.

Show me the lines that contain this.

grep at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a highlighter

Think of reading a long printout with a highlighter.

  • You move down the page line by line and mark every line with the word you want.
  • Then you copy only the marked lines onto a short sheet: that is grep’s output.
  • The original page is never changed.

Basic The forms you will type every day

  • grep ERROR app.log: lines containing ERROR.
  • grep -i error app.log: any case. grep -n adds line numbers, grep -c counts lines.
  • grep -v INFO app.log: everything except INFO lines.
  • grep -rn TODO src/: search every file under a folder.
  • ps aux | grep nginx: search another command’s output.

Intermediate Patterns, files and exit codes

  • The pattern is a regular expression: ^ start of line, $ end, . any character, [0-9] a digit (Lesson 6.6). Quote it: grep '^ERROR' file.
  • Basic grep treats | + ? ( ) {} as normal characters; use grep -E (extended) for 'ERROR|FATAL', or \| in basic mode. -F means “fixed string”: no special characters at all.
  • With several files grep prefixes each line with the file name (-h hides it, -H forces it).
  • Exit code: 0 = found, 1 = not found, 2 = error. That is what makes grep -q useful in scripts.
  • -c counts matching lines; to count every occurrence use grep -o … | wc -l.

Advanced Behind the screen: fast search and encodings

  • GNU grep reads big blocks, not lines, and uses the Boyer-Moore algorithm to skip ahead: a fixed string search can check far fewer bytes than the file has. It only finds line boundaries around a match.
  • Regular expressions are compiled into an automaton (DFA) before reading, so a complex pattern costs little extra per line.
  • Files containing NUL bytes are treated as binary: grep prints “binary file matches” instead of the line. -a treats them as text.
  • -i and character classes depend on the locale (LANG); LC_ALL=C grep is byte-based and often faster.
  • -P uses Perl-compatible regex (\d, lookaheads). Faster modern alternatives: ripgrep (rg) respects .gitignore and searches in parallel.

Did you know? grep was written by Ken Thompson in one night in 1973 at Bell Labs, because Doug McIlroy wanted to search a text too large for the ed editor. The name is the ed command g/re/p: on every line (g), find the regular expression (re), print it (p). It is so common that “to grep” is now an English verb.

EXAM> “How do you search for a word in all files under a directory, ignoring case, showing line numbers?” → grep -rin word dir/ (add --include="*.conf" to limit the files, -l to list only file names, -w for whole words).
Quick check What is the difference between grep -c ERROR app.log and grep -o ERROR app.log | wc -l?
Answer: -c counts lines that contain ERROR. -o prints every occurrence on its own line, so wc -l counts occurrences. A line with ERROR twice counts 1 for -c and 2 for the second.
Common mistake
✗“grep stands for Global Expression Regular Print” · “grep -c: how many times a pattern appears” · “grep -v: displays the number of lines that didn’t match” · “grep -e: matches in a case-sensitive manner”
✓grep = global / regular expression / print · -c counts matching LINES · -v prints the non-matching LINES (-vc would count them) · -e marks a pattern (useful for several patterns or one starting with -); case is controlled by -i

grep in system info / admin

  1. Situation: Which users have bash as their login shell?

    grep '/bin/bash$' /etc/passwd | cut -d: -f1

    Why this way: $ anchors the pattern at the end of the line, so only the shell field matches.

  2. Situation: Show a config file without comments and blank lines.

    printf '# main config\nport=8080\n\n# log level\nlevel=info\n' > app.conf

    Why this way: -v with two patterns removes both comment lines and empty lines: the real settings remain.

grep in software development

  1. Situation: Is the function named exactly main used, not mainPage?

    printf 'main()\nmainPage()\nrun main now\n' > code.txt
grep -n main code.txt

grep -nw main code.txt

    Why this way: -w requires word boundaries on both sides, so mainPage is skipped.

grep in devops / cloud

  1. Situation: The first fatal error after a deploy, nothing more.

    grep -m 1 -n -E 'ERROR|FATAL' app.log

    Why this way: -m 1 stops reading at the first match: instant on multi-GB logs.

grep in data analysis / engineering

  1. Situation: All employees in Pune from a CSV (city is a whole field).

  1. Situation: Alert only if the log contains FATAL.

Common mistake
✗ps aux | grep java | wc -l
✓pgrep -c java · or ps aux | grep '[j]ava' | wc -l

grep’s own command line contains “java”, so it matches itself (Lesson 5.3).

Undo and safety net

grep never changes files, but a few habits save time.

  • Too much output: add -m 5, | head, -l or -c.
  • “binary file matches”: the file contains NUL bytes. Use -a to treat it as text or strings file | grep ….
  • Slow on a huge project: --exclude-dir=.git --exclude-dir=node_modules, LC_ALL=C, or ripgrep (rg).
  • Pattern starts with -: grep -e -v file or grep -- -v file.

Error messages decoded

grep errors students see most. Each was really produced on our build machine, with its exit status.

  1. grep root /nope/file
    grep: /nope/file: No such file or directory exit status: 2

    What it means: The file does not exist. Exit 2 = error (not “not found”).

    Fix: Check the path; add -s to hide such messages in scripts.

  2. grep 'a[' /etc/hostname
    grep: Invalid regular expression exit status: 2

    What it means: An unclosed bracket is an invalid regular expression.

    Fix: Close it, escape it (a\[) or use -F.

  3. grep -r root /etc/ssl/private
    grep: /etc/ssl/private: Permission denied exit status: 2

    What it means: Permission denied: a normal user cannot read that folder.

    Fix: -s to hide, or sudo if you really need it.

  4. printf 'a\0b' > bin.dat; grep a bin.dat
    grep: bin.dat: binary file matches exit status: 0

    What it means: Not an error: grep found a match in a binary file and only says so.

    Fix: grep -a, or strings bin.dat | grep ….

  5. grep -c PANIC /etc/hostname
    0 exit status: 1

    What it means: 0 matching lines; exit status 1 means “not found”, not a failure of grep.

    Fix: Nothing to fix; in scripts treat 1 differently from 2.

6 Real-world use

grep at work

1. Incident response

The first command in most incidents: grep the logs for errors with context and timestamps.

Alert→grep -C→cause

2. Code search and review

Developers find usages, TODOs and deprecated calls across a repository (git grep does the same inside git).

Repo→grep -r→files:lines

3. Security audits

Secret scanning, failed logins, suspicious IPs: grep with -i, -E and -f lists.

Logs/code→grep→findings

4. Monitoring and scripts

Health checks and cron jobs use grep -q exit codes to decide whether to alert.

Check→exit code→alert

5. Quick data filters

Data engineers filter rows of CSV and JSON lines before loading or before writing a real query.

File→grep→subset

Intermediate

Unique IPs that got 401

Scenario: Who is being refused?

grep '" 401 ' access.log | grep -oE '^[0-9.]+' | sort -u
185.220.101.4

-o extracts just the IP at the start of the line.

Intermediate

Every occurrence, not every line

Scenario: Count each ERROR, even two on one line (the puzzle).

echo 'ERROR ERROR twice' >> app.log; grep -c ERROR app.log; grep -o ERROR app.log | wc -l
3 4

3 lines, 4 occurrences.

Advanced

Errors per hour

Scenario: When did the problems happen?

grep -iE 'error|fatal' app.log | grep -oE ' [0-9]{2}:' | sort | uniq -c
4 09:

Extract the hour, then count (Lesson 6.2).

Script it: log-check.sh

A small monitoring script: count problems, show the first fatal line with context, and exit non-zero so cron or CI can alert.

cat > app.log << 'EOF'
2026-11-06 09:00:01 INFO  server started on port 8080
2026-11-06 09:00:05 INFO  GET /health 200
2026-11-06 09:01:10 WARN  disk usage 81% on /data
2026-11-06 09:02:30 ERROR db connection refused (host=db01)
2026-11-06 09:02:31 INFO  retrying db connection
2026-11-06 09:02:35 ERROR db connection refused (host=db01)
2026-11-06 09:03:00 INFO  GET /health 200
2026-11-06 09:04:12 error payment timeout for order 7781
2026-11-06 09:05:40 FATAL out of memory, shutting down
2026-11-06 09:06:00 INFO  server started on port 8080
EOF
log=app.log
errors=$(grep -ci 'error' "$log")
if grep -q FATAL "$log"; then
  echo "FATAL found ($errors error lines). First one:"
  grep -n -m 1 -B 1 FATAL "$log"
  exit 2
fi
echo "OK: $errors error lines, no FATAL"
FATAL found (3 error lines). First one: 8-2026-11-06 09:04:12 error payment timeout for order 7781 9:2026-11-06 09:05:40 FATAL out of memory, shutting down

The heredoc at the top only creates the demo log; on a server, point log= at your real file.

Puzzle answer Remember the question from the story? Open to check your guess.

grep -c ERROR prints 1: it counts matching lines. grep -o ERROR | wc -l prints 2: -o prints every occurrence on its own line. Many notes describe -c as “how many times the pattern appears”; real runs show it is the number of lines.

Quick check A script must check that /etc/hosts contains the exact line 10.0.0.5 db01. Which grep options?
Answer: grep -qxF '10.0.0.5 db01' /etc/hosts: quiet, whole line, fixed string (so the dots are literal).
