2 Definition

Regular expressions with grep, sed and awk

Formal definition (write this in exams)

A regular expression (regex) is a pattern that describes a set of strings, built from literal characters and metacharacters: anchors, the dot, bracket expressions, quantifiers, groups and alternation. POSIX defines basic (BRE) and extended (ERE) syntaxes; Perl-compatible regex (PCRE) adds shorthand classes, lazy quantifiers and lookarounds. grep and sed use BRE by default and ERE with -E; awk uses ERE.

Regular expressions at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a stencil

Think of the stencil used to paint vehicle number plates.

  • The stencil has slots: two letters, two digits, two letters, four digits.
  • A plate that fits every slot is valid; one with a missing digit or small letters is rejected.
  • A regex is such a stencil, written in symbols: [A-Z]{2}[0-9]{2}[A-Z]{2}[0-9]{4}.

Basic The symbols you will use every day

  • Letters and digits match themselves: error.
  • . any one character; ^ start of line; $ end of line.
  • [abc] one of a, b, c; [0-9] a digit; [^0-9] anything but a digit.
  • * zero or more of the previous item; with grep -E also + one or more, ? optional, {3} exactly three.
  • \. a real dot (escape special characters with a backslash).

Intermediate Dialects, groups and classes

  • BRE (basic: grep, sed): + ? | ( ) { } are ordinary characters; GNU lets you use \+ \? \| \( \) \{ \} for their special meaning.
  • ERE (extended: grep -E, sed -E, awk): + ? | ( ) { } are special without backslashes. Use ERE: it is easier to read.
  • PCRE (Perl: grep -P, rename, Python, Java): adds \d \w \s, lazy *?, lookarounds. In grep -E, sed and awk \d does not mean digit.
  • POSIX classes work everywhere: [[:digit:]] [[:alpha:]] [[:upper:]] [[:space:]] [[:alnum:]] [[:punct:]].
  • ( ) groups, | chooses, \1 repeats what group 1 matched (grep, sed; not awk).

Advanced Behind the screen: automata, greed and catastrophic backtracking

  • grep, sed and awk compile ERE/BRE into a finite automaton (DFA/NFA): matching takes time proportional to the text length, whatever the pattern. That is why grep -E is fast even with complex patterns.
  • Backreferences (\1) cannot be handled by a pure automaton, so those patterns use slower backtracking.
  • Quantifiers are greedy: .* takes as much as possible (Lesson 6.4’s IP trap). PCRE has lazy versions (.*?); ERE has none, so use negated classes like [^<]*.
  • PCRE engines can explode on nested quantifiers like (a+)+$ (“catastrophic backtracking”, ReDoS attacks). Keep patterns simple and anchored.
  • Ranges like [a-z] follow the locale’s collation; [[:lower:]] or LC_ALL=C is safer.

Did you know? Ken Thompson put regular expressions into his QED editor in 1968, compiling them into machine code on the fly: one of the first programs to generate code at runtime. From there they went into ed, grep, sed, awk, Perl, and every language you will use.

EXAM> “Write a regex for a 10-digit Indian mobile number and use it to find invalid entries in a file.” → grep -vxE '[6-9][0-9]{9}' mobiles.txt (explain [6-9], {9}, -x and -v; mention [0-9] instead of \d in grep -E).

^ $ . \b anchors and the dot

🟢 Read-onlyno sudo

^ and $ match the start and end of a line, \b a word boundary (GNU). The dot . matches any one character; \. a real dot.

✓ Use it when
  • searching for text at the start or end of a line
  • any single character, or a literal dot
  • whole words and whole lines
✗ Don’t use it when
  • matching everything with .* when a class would be safer

[ ] [^ ] [[:class:]] character classes

🟢 Read-onlyno sudo

A bracket expression matches one character from a set or range; [^…] matches one character NOT in the set. POSIX classes like [[:digit:]] go inside the brackets.

✓ Use it when

  • everything except a set: [^,] (stays inside a CSV column)
  • portable classes that work in every tool
✗ Don’t use it when
  • \d \w \s in POSIX tools (use [0-9], [[:alnum:]_], [[:space:]])

* + ? {n,m} quantifiers

🟢 Read-onlyno sudo

Apply to the item just before them: * 0 or more, + 1 or more, ? 0 or 1, {n} exactly n, {n,} at least n, {n,m} between n and m. In BRE write \+ \? \{n,m\}.

✓ Use it when
  • how many times: optional, at least one, exactly N, between N and M
  • lengths of codes, IDs, numbers
✗ Don’t use it when
  • .* in extraction (greedy): use classes or grep -o with exact pieces

Syntax: grep -E 'a+b' · 'colou?r' · '[0-9]{6}' · '[A-Z]{2,4}'

( ) | \1 groups, alternation, backreferences

🟢 Read-onlyno sudo

( ) groups items so a quantifier applies to all of them and remembers what matched. | means “or”. \1 refers to what group 1 matched: in a search it finds repeats, in sed’s replacement it reuses the text.

✓ Use it when

  • capturing parts to reuse in sed (\1) or to find repeats
✗ Don’t use it when
  • awk backreferences (not supported; use match() in gawk)

Undo and safety net

Regex mistakes rarely break files, but they can silently select the wrong data.

  • A pattern matches too much: anchor it (^ $ -x -w), replace .* with a negated class, escape dots.
  • A pattern matches nothing: check the dialect: + ? | ( ) { } need -E; \d needs -P.
  • sed -i with a wrong regex changed files: restore the .bak (Lesson 6.4); test with grep -o first.
  • Slow or hanging regex (PCRE): avoid nested quantifiers like (a+)+; anchor; prefer grep -E.

Error messages decoded

Regex errors students see most. Each was really produced on our build machine, with its exit status.

  1. echo x | grep -E '('
    grep: Unmatched ( or \( exit status: 2

    What it means: An unclosed group.

    Fix: Close it, or match a real bracket with \( (or [(]).

  2. echo x | grep '[a-'
    grep: Unmatched [, [^, [:, [., or [= exit status: 2

    What it means: An unclosed bracket expression.

    Fix: Close it: [a-z].

  3. echo x | grep -E '*abc'
    grep: warning: * at start of expression exit status: 1

    What it means: GNU grep warns and treats a * at the start as a literal *. No match, exit 1.

    Fix: Put * after the item it repeats.

  4. echo 'pin 1234' | sed 's/\d/X/g'
    pin 1234 exit status: 0

    What it means: No error and no change: \d is not a digit class in sed.

    Fix: sed 's/[0-9]/X/g'.

6 Real-world use

Regular expressions at work

1. Data validation

Banks, telecoms and e-commerce validate mobiles, PINs, PANs and emails before loading data.

Import→regex check→clean rows

2. Extraction

Pull order IDs, IPs, error codes and URLs out of logs and documents.

Text→grep -o→values

3. Transformation

Reformat dates, swap columns, mask secrets with groups and backreferences.

Data→sed -E→new format

WAF rules, log alerts and input filters are regexes; badly written ones can be attacked (ReDoS).

Input→regex→allow / block

IDEs, vim, git grep, linters and code reviews all use the same pattern language.

Script it: validate-signups.sh

The bank check as a script: count valid and invalid rows, write the bad ones to a file with their row numbers, and exit non-zero if any row is invalid.

printf '%s\n' 'Asha,9876543210,411001,ABCDE1234F,asha@cdac.in' 'Ravi,5876543210,40001,abcde1234f,ravi@cdac' 'Meena,98765 43210,560001,PQRSX5678Z,meena.k@gmail.com' 'Kabir,9123456780,110001,KLMNO9012P,kabir@@x.in' > signup.csv
re='^[^,]+,[6-9][0-9]{9},[1-9][0-9]{5},[A-Z]{5}[0-9]{4}[A-Z],[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$'
good=$(grep -cE "$re" signup.csv)
grep -nvE "$re" signup.csv > rejected.txt
echo "valid: $good  invalid: $(wc -l < rejected.txt)"
cut -d, -f1 rejected.txt
[ -s rejected.txt ] && exit 1 || exit 0
valid: 1 invalid: 3 2:Ravi 3:Meena 4:Kabir

The pattern is stored in a variable and used in double quotes, so the shell does not touch it. The first line only creates the sample file.

Puzzle answer Remember the question from the story? Open to check your guess.

grep -oE '\d+' prints d: in grep’s basic and extended syntax \d is just the letter d. sed 's/\d/X/g' changes nothing. Only Perl-style engines (grep -P, rename, Perl, Python) read \d as a digit. In grep, sed and awk use [0-9] or [[:digit:]].

Quick check Write a regex for a vehicle number like MH12AB1234 (two letters, two digits, one or two letters, four digits).
Answer: ^[A-Z]{2}[0-9]{2}[A-Z]{1,2}[0-9]{4}$ with grep -E.
