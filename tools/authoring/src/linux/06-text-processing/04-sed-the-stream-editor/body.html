The company is moving to HTTPS. Riya must change http:// to https:// in 300 config files, switch level=debug to level=info, and add a header line to each file. Opening 300 files in an editor would take a day and she would miss some. sed -i.bak 's|http://|https://|g' *.conf does the first part in one second, with a backup of every file. sed is an editor you control with commands instead of keys.

Which sed command? (decide in 5 seconds)

  • Replace the first match on each line→sed 's/old/new/' fprints the result; file unchanged
  • Replace every match→sed 's/old/new/g' fi = ignore case: s/x/y/gi
  • Text contains slashes (paths, URLs)→sed 's|/old/path|/new/path|g'any delimiter works
  • Change the file itself, keep a backup→sed -i.bak 's/a/b/g' ff.bak is the original
  • Print only lines 10–20→sed -n '10,20p' flike head + tail
  • Delete lines→sed '/^#/d; /^$/d' fcomments and blank lines
  • Only on lines that match→sed '/ERROR/s/db01/db02/' fan address before s
  • Insert / append / change a line→sed '1i\Header' f · '$a\Footer' · '3c\New'i before, a after, c replace
  • Reorder parts of a line→sed -E 's/(.*)-(.*)/\2-\1/'\1 \2 = captured groups

2 Definition

sed: the stream editor

Formal definition (write this in exams)

sed (stream editor) reads input line by line, applies a script of editing commands (substitute, delete, print, insert, append, change, and more) to each line that matches the command’s address, and writes the result to standard output, or back to the file with -i. It is non-interactive, so it is ideal for scripts and for editing many files the same way.

In simple words

Apply the same edit to every line, automatically.

sed at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a proofreader

Think of a proofreader with a red pen.

  • Pages (lines) come in one at a time.
  • The proofreader applies the same corrections to every page, without asking.
  • Corrected pages go out; with -i they replace the original pages.

Basic The forms you will type every day

  • sed 's/cat/dog/' f: first cat on each line → dog (printed, file unchanged).
  • sed 's/cat/dog/g' f: every cat. gi: any case.
  • sed -n '5,10p' f: print lines 5–10 only.
  • sed '/^#/d' f: delete comment lines.
  • sed -i.bak 's/a/b/g' f: change the file, keep f.bak.

Intermediate Addresses, groups and the -n trick

  • A command can have an address: 3, 2,5, $ (last line), /re/, /start/,/end/, 1~2 (every 2nd), and ! for “not”.
  • sed prints every line automatically; -n turns that off so only p prints.
  • In the replacement, & is the whole match and \1…\9 are groups. With -E write groups as ( ); without it \( \).
  • .* is greedy: it takes as much as possible, which is why the IP puzzle lost digits.
  • Use another delimiter when the text has slashes: s|/usr/local|/opt|, s#a#b#.

Advanced Behind the screen: pattern space, hold space, in-place

  • sed reads a line into the pattern space, runs the whole script on it, prints it (unless -n), and repeats. The hold space is a second buffer: h/H copy to it, g/G copy back, x swaps.
  • N appends the next line, so a script can work across lines; :a … ba are labels and branches: sed is a small programming language.
  • -i does not edit in place: it writes a new temporary file and renames it over the original. The file gets a new inode, so hard links break and the owner/permissions are copied from the original.
  • GNU sed extensions: -i, -E, \b, I flag, 0,/re/, 1~2. macOS (BSD) sed needs -i '' and lacks some of them.

Did you know? sed and vim share their roots: both come from the 1970s editor ed. That is why :%s/old/new/g in vim (Lesson 4.3) and sed 's/old/new/g' look the same, and why grep’s name comes from ed’s g/re/p.

EXAM> “How do you replace a word in a file in place, keeping a backup?” → sed -i.bak 's/old/new/g' file. Show -n 'Np' to print a line, '/re/d' to delete, and mention testing without -i first.
Quick check What does sed 's/cat/dog/' do with the line cat cat cat?
Answer: Only the first: dog cat cat. Add g for all, or a number for the Nth: s/cat/dog/2.

sed 's///' substitute

🟡 Changes filesno sudo

Replaces text matching a regular expression. Without -i the result is printed and the file is unchanged.

✓ Use it when
  • replacing words, values, URLs, paths
  • the same change in many files (-i)
  • cleaning data: spaces, quotes, separators
✗ Don’t use it when
  • changes that need column logic or arithmetic (use awk)
  • structured formats like JSON/YAML/XML (use jq, yq, xmlstarlet)
  • editing without testing first

sed 's///' in system info / admin

  1. Situation: HTTPS everywhere, in place, with a backup (the story).

    sed -i.bak 's|http://|https://|g' app.conf
grep -n 'https' app.conf
ls app.conf*
    2:server=https://api.cdac.in 7:backup_url=https://files.cdac.in app.conf app.conf.bak

    Why this way: | as the delimiter avoids escaping every slash. app.conf.bak holds the original.

  2. Situation: Change one setting value whatever it was before.

    sed -E 's/^level=.*/level=info/' app.conf | grep level
    level=info

    Why this way: ^ anchors at the line start, so only the real setting changes, not comments mentioning level.

sed 's///' in data analysis / engineering

  1. Situation: Convert a CSV to tab-separated and remove quotes (from your notes).

    printf '"id","city"\n"1","Pune"\n' > q.csv
sed -e 's/"//g' -e 's/,/\t/g' q.csv | cat -A
    id^Icity$ 1^IPune$

    Why this way: Two expressions with -e; cat -A shows ^I for each TAB. (Only safe when no field contains a comma.)

  2. Situation: Indian date 06/11/2026 → ISO 2026-11-06.

    echo 'paid on 06/11/2026' | sed -E 's|([0-9]{2})/([0-9]{2})/([0-9]{4})|\3-\2-\1|'
    paid on 2026-11-06

    Why this way: Three groups captured, written back in a new order.

sed 's///' in software development

  1. Situation: Rename a function everywhere in a project (whole word only).

    mkdir -p src; printf 'getUser()\ngetUserById()\nx = getUser()\n' > src/a.py
sed -i 's/\bgetUser\b/fetchUser/g' src/a.py; cat src/a.py
    fetchUser() getUserById() x = fetchUser()

    Why this way: \b is a word boundary (GNU), so getUserById is untouched. Check with grep -rnw first (Lesson 6.1).

sed 's///' in devops / cloud

  1. Situation: Set the image version in a deployment file.

    printf 'image: shop/api:1.4.2\nreplicas: 2\n' > deploy.yaml
v=1.5.0
sed -i "s|\(image: shop/api:\).*|\1$v|" deploy.yaml; cat deploy.yaml
    image: shop/api:1.5.0 replicas: 2

    Why this way: Double quotes let $v expand; the group keeps the image name and replaces only the tag. CI pipelines do this before every deploy.

sed 's///' in security

  1. Situation: Mask passwords before sharing a log or config.

    printf 'user=riya\npassword=Secret#42\ndb_password = x9\n' > s.conf
sed -E 's/(password *= *).*/\1*****/' s.conf
    user=riya password=***** db_password = *****

    Why this way: Keep the key, hide the value. Never paste real secrets into tickets or chat.

Common mistake
✗sed -n 's/.*\([0-9]\{1,3\}\.…\).*/\1/p' (extract IPs)
✓grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' file

The leading .* is greedy: it swallows as much as it can and leaves only the shortest possible match for the group, so 192.168.1.10 becomes 2.168.1.10 (real run). The same happens to the email example in many notes (riya.sharma@cdac.in → a@cdac.in). grep -o finds whole matches.

  1. Situation: Disable root SSH login (the real command; needs sudo).

Common mistake
✗sed -n 's/x/y/' -i file (meant: print and change)
✓sed -i.bak 's/x/y/' file

With -n nothing is printed unless you say p, and -i writes that nothing back: the file becomes empty. Never combine -n and -i without a p.

Undo and safety net

sed -i rewrites files. Protect yourself.

  • Wrong change with -i.bak: mv file.bak file restores it.
  • Wrong change without backup: git checkout -- file, your backups, or undo the edit with the reverse s command if it was a simple one-to-one change.
  • Before every -i: run the same command without -i and look (| diff file - shows the change).
  • Hard links broken by -i: expected: -i creates a new file. Use an editor or sed … file | tee file.new and copy back if links matter.

Error messages decoded

sed errors students see most. Each was really produced on our build machine, with its exit status.

  1. echo x | sed 's/x/y'
    sed: -e expression #1, char 5: unterminated `s' command exit status: 1

    What it means: The s command is missing its final delimiter.

    Fix: s/x/y/.

  2. echo /usr/bin | sed 's//usr/bin//opt/bin/'
    sed: -e expression #1, char 8: unknown option to `s' exit status: 1

    What it means: The slashes in the path end the s command too early.

    Fix: Use another delimiter: s|/usr/bin|/opt/bin|.

  3. echo abc | sed -E 's/(a/X/'
    sed: -e expression #1, char 7: Unmatched ( or \( exit status: 1

    What it means: An unclosed ( in an extended regex.

    Fix: Close it, or escape it as \( for a literal bracket.

  4. sed -i 's/a/b/' /etc/hostname
    sed: couldn't open temporary file /etc/sediQygP2: Permission denied exit status: 4

    What it means: -i needs to create a new file in /etc: permission denied for a normal user.

    Fix: sudo, and check first without -i.

  5. echo abc | sed 's/\(b\)/\2/'
    sed: -e expression #1, char 11: invalid reference \2 on `s' command's RHS exit status: 1

    What it means: There is only one group, so \2 does not exist.

    Fix: Count the groups; use \1.

Prefix every line

Intermediate

Commas in numbers

Scenario: 1234567 → 1,234,567 (from your notes).

echo 1234567 | sed ':a;s/\([0-9]\)\([0-9]\{3\}\)\($\|,\)/\1,\2\3/;ta'
1,234,567

A loop: label a, substitute, branch back while it changes. (Indian 12,34,567 grouping needs a different rule.)

Intermediate

Swap two columns

Scenario: name,city → city,name.

echo 'Asha,Pune' | sed -E 's/([^,]*),([^,]*)/\2,\1/'
Pune,Asha

[^,]* = “anything except a comma”: not greedy across columns.

Advanced

Join all lines

Scenario: Turn a list into one comma line (from your notes).

sed ':a;N;$!ba;s/\n/,/g' f.txt
one,two,three,four

N appends lines into one pattern space; paste -sd, is simpler.

Build it step by step: the HTTPS migration

Scenario: Riya moves a config to HTTPS safely, one step at a time.

  1. 1. See what will change.

    grep -n 'http://' app.conf
    2:server=http://api.cdac.in 7:backup_url=http://files.cdac.in

  2. 2. Preview the change without -i.

    sed 's|http://|https://|g' app.conf | grep -n 'https'
    2:server=https://api.cdac.in 7:backup_url=https://files.cdac.in

  3. 3. Apply with a backup and review the diff.

    sed -i.bak 's|http://|https://|g' app.conf && diff app.conf.bak app.conf

    sed -i.bak 's|http://|https://|g' app.conf; sed -i 's/^level=debug/level=info/' app.conf; sed -n '/^level/p;/url/p;/^server/p' app.conf

Script it: mask-and-clean.sh

A small data-cleaning script: remove comments and blank lines, trim spaces, mask passwords, convert dates, and save a cleaned copy.

printf '# export\n  user=riya  \n\npassword=Secret#42\njoined=06/11/2026\n' > raw.conf
sed -E -e '/^#/d' -e '/^\s*$/d' \
       -e 's/^\s+//; s/\s+$//' \
       -e 's/(password=).*/\1*****/' \
       -e 's|([0-9]{2})/([0-9]{2})/([0-9]{4})|\3-\2-\1|' raw.conf > clean.conf
cat clean.conf
user=riya password=***** joined=2026-11-06
Puzzle answer Remember the question from the story? Open to check your guess.

The leading .* is greedy: it takes as many characters as it can while the rest of the pattern can still match. The group needs only 1–3 digits for the first part, so .* keeps “from 19” and the group gets 2.168.1.10. Use grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}', or in sed make the left side unable to end in a digit: s/.*[^0-9]\(…\)…/.
