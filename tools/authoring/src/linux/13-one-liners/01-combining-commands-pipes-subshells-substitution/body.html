The problem

“How many different IP addresses got an error from our site today, and which one got the most?” Riya’s manager wants the answer in two minutes. There is no tool called count-error-ips. But Linux has dozens of small tools that each do one thing, and the shell has a handful of ways to combine them: | passes output along, && and || decide what runs next, ; runs things in order, ( ) and { } group commands, $( ) puts a command’s output inside another command, and <( ) lets a command read another command’s output as if it were a file. This lesson turns these into one habit: build a one-liner step by step and check each step.

By the end of this page you will be able to:
  • combine commands with ; && || | |& and know exactly when each next command runs
  • group commands with ( ) and { }, and know which one changes your shell
  • use $( ), <( ) and >( ) and tee to connect commands that need arguments or files
  • handle errors in pipelines with $?, PIPESTATUS and set -o pipefail, and build one-liners step by step

2 Definition

Pipes, lists, groups and substitutions

Formal definition (write this in exams)

A pipeline (A | B) connects the standard output of one command to the standard input of the next. A list joins commands with ;, &&, || or &, which decide when the next one runs based on the previous exit status. Grouping with ( ) (a subshell) or { ;} (the current shell) treats several commands as one. Command substitution $( ) inserts output as text; process substitution <( ) provides it as a file name.

In simple words

Pipes move data; operators decide what runs; groups bundle; substitutions plug outputs in.

Combining at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a factory line with traffic lights

Belts carry the product; lights decide if the next station starts.

Basic What you will type

  • ls | wc -l: count files (output of ls goes into wc).
  • mkdir backup && cp *.txt backup/: copy only if mkdir worked.
  • ping -c1 web01 || echo "web01 is down": message only on failure.
  • echo "Today is $(date +%A)": a command inside a command.

Intermediate Exit status decides

  • Every command returns an exit status: 0 = success, anything else = failure; $? holds the last one.
  • && and || look at it; ; ignores it.
  • A && B || C is not if/else: C also runs when B fails.
  • A pipeline’s status is the status of its last command, unless set -o pipefail; ${PIPESTATUS[@]} has all of them.
  • ( … ) runs in a subshell (cd and variables are forgotten), { …; } in the current shell.

Advanced Behind the screen: pipes, forks and file descriptors

  • For A | B the shell calls pipe(), forks twice, connects A’s stdout (fd 1) to the write end and B’s stdin (fd 0) to the read end. Both run at the same time; the kernel buffers 64 KiB.
  • Each part of a pipeline runs in its own subshell, so … | while read changes variables in a child (the third puzzle). shopt -s lastpipe or while … done < <(cmd) fixes it.
  • If B exits early (head), A gets SIGPIPE on its next write and dies with 141 (Lesson 11.3).
  • <(cmd) becomes a path like /dev/fd/63: a pipe the shell opened for you.
  • |& is 2>&1 |: stderr joins stdout into the pipe.

Did you know? Doug McIlroy wrote in a 1964 memo: “We should have some ways of coupling programs like garden hose: screw in another segment when it becomes necessary to massage data in another way.” It took until 1973 for pipes to appear in Unix, and the “do one thing well, and work together” philosophy grew from them.

EXAM> “What is the difference between ; and &&?” → With ; the next command always runs; with && it runs only if the previous one succeeded (exit status 0).
Quick check Is A && B || C the same as if A then B else C?
Answer: No. C runs if A fails or if B fails. Use a real if when B can fail.
Common mistake
✗cd /var/ww; rm -rf old/
✓cd /var/www && rm -rf old/ · or rm -rf /var/www/old/ (full path)

With ; the rm runs even after cd failed, in whatever folder you are in. With && it never runs after a failed cd.

Common mistake
✗grep ERROR app.log | wc -l && echo "report sent"
✓set -o pipefail; grep ERROR app.log | wc -l && echo "report sent"

The pipeline’s status is wc’s (0), even though grep failed (real run: grep 2, wc 0).

A ; B · A && B · A || B · $? running commands one after another

🟡 Changes filesno sudo

; runs the next command whatever happened. && runs it only after success (status 0), || only after failure. Chains are read left to right: A && B && C stops at the first failure; A || B || C stops at the first success.

✓ Use it when
  • deploy steps, backups, checks
  • anything where step 2 must not run after a failed step 1
✗ Don’t use it when
  • long chains with A && B || C as if/else
  • ; after cd

Syntax: A && B && C · A || B · A ; B

A | B · A |& B · tee · PIPESTATUS · pipefail pipelines

🟢 Read-onlyno sudo

A pipe sends one command’s standard output to the next command’s standard input; all parts run at the same time. |& also sends errors. tee file saves a copy in the middle. ${PIPESTATUS[@]} holds every part’s exit status, and set -o pipefail makes the pipeline fail if any part fails.

✓ Use it when
  • any “filter, transform, count” question
  • logs, CSVs, command output
✗ Don’t use it when
  • parsing ls output for scripts
  • trusting a pipeline’s status without pipefail

Syntax: A | B | C · A | tee f | B · set -o pipefail

( A; B ) · { A; B; } · bash -c subshells and groups

🟢 Read-onlyno sudo

( … ) runs the commands in a child shell: cd, variables, set options and exit stay inside it. { …; } runs them in your shell (note the spaces and the final ;) and is the way to redirect or pipe several commands at once.

✓ Use it when
  • trying something in another folder
  • one redirect for several commands
  • a temporary variable or option
✗ Don’t use it when
  • { } without the spaces and ;

"$(A)" · <(A) · >(A) command and process substitution

🟢 Read-onlyno sudo

$(A) runs A and puts its output into the command line as text (quote it). <(A) runs A and gives the command a file name to read from, so tools that only accept files (diff, comm, join, paste) can read command output. >(A) is the opposite: a file name that feeds A.

✓ Use it when
  • values inside commands (dates, counts, names)
  • comparing two outputs
  • sending one output to two places
✗ Don’t use it when
  • $(cat bigfile) for huge files
  • unquoted $( ) with spaces

Syntax: echo "$(cmd)" · diff <(cmd1) <(cmd2) · tee >(cmd) > file

Undo and safety net

Combining is safe; what you combine may not be.

  • A chain ran too far: use && instead of ;, and set -e in scripts.
  • Unsure what a pipeline does: run it stage by stage, or insert | tee /tmp/stepN.
  • Deleting from a pipeline: end with echo first (… | xargs echo rm), then remove echo.
  • Variables lost in a loop: done < <(cmd) instead of cmd | while.

Script it: errorreport.sh

Answer three questions about a web log with combined commands (error count, top error IP, top failing URL), stop with a clear message if the log is missing, and give the right exit status.

set -o pipefail
log=${1:-$HOME/cb/logs/access.log}
[ -r "$log" ] || { echo "cannot read $log" >&2; exit 1; }
err=$(grep -cE '" [45][0-9]{2} ' "$log") || err=0
top_ip=$(grep -E '" [45][0-9]{2} ' "$log" | cut -d' ' -f1 | sort | uniq -c | sort -rn | awk 'NR==1{print $2" ("$1")"}')
top_url=$(grep -E '" [45][0-9]{2} ' "$log" | cut -d'"' -f2 | awk '{print $2}' | sort | uniq -c | sort -rn | awk 'NR==1{print $2}')
{ echo "log:        ${log##*/}"; echo "errors:     $err"; echo "top IP:     ${top_ip:-none}"; echo "top URL:    ${top_url:-none}"; } | tee /tmp/errorreport.txt
[ "$err" -eq 0 ]
log: access.log errors: 4 top IP: 10.0.0.5 (2) top URL: /old-page

Run without arguments, so it reads the sample log; it exits with status 1 because there are errors.

Puzzle answer Remember the question from the story? Open to check your guess.

1. A pipeline’s exit status is that of its last command: grep failed (2), but wc succeeded (0), so && ran. Use set -o pipefail or check ${PIPESTATUS[0]}. 2. ; ignores the failed cd, so rm -rf old/ ran in the current folder. Always cd dir && … (or use full paths). 3. Each part of a pipeline runs in a subshell; the loop counted in a child, and the parent’s n stayed empty. Use while …; done < list.txt or < <(cmd).
