The problem

Riya’s manager forwards a CSV export with one line: “Totals per city and top products by Friday, please. Also join it with the product list, and the web team wants the same numbers from the orders API, which returns JSON.” Riya could open Excel, but the real file has 50,000 rows, arrives every night and needs the same steps every time. On Linux, data work is a pipeline of small tools: cut and awk pick columns, sort and uniq count, join and paste combine files, and jq does the same for JSON. This lesson runs each one on a real sales file, including the traps: headers, empty values, duplicates and commas inside quotes.

  • filter, total, average and group rows with awk, and count and rank with sort | uniq -c
  • combine files with join, paste and comm, handle headers, duplicates, empty and quoted fields
  • read, filter and reshape JSON with jq and convert between JSON and CSV

Which tool? (decide in 5 seconds)

  • One or two columns→cut -d, -f3,4cut
  • Rows where a column matches→awk -F, '$3=="Pune"'filter

2 Definition

CSV, JSON and data one-liners

Formal definition (write this in exams)

CSV (comma-separated values) stores a table as text: one row per line, columns separated by commas, usually with a header row. JSON stores nested objects ({"key": value}) and lists ([…]). Data one-liners use cut, awk, sort, uniq, join and paste for CSV and jq for JSON to select, filter, aggregate and combine data without a spreadsheet or a program.

In simple words

Tables with awk, trees with jq; check the data before trusting the numbers.

Data one-liners at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a table and a tree

CSV is a table; JSON is a tree of boxes.

Basic What you will type

  • head -3 sales.csv: see the columns.
  • cut -d, -f3 sales.csv | sort | uniq -c: orders per city.
  • awk -F, 'NR>1{s+=$5*$6} END{print s}' sales.csv: grand total.
  • jq '.orders[].city' orders.json: cities from JSON.

Intermediate The checks that make numbers right

  • Header: skip it with NR>1 or tail -n +2.
  • Duplicates: compare wc -l with sort -u | wc -l; remove with awk '!seen[$0]++' (keeps order).
  • Empty values: awk -F, '$5==""'; decide whether to skip or treat as 0.
  • Column count: awk -F, '{print NF}' | sort | uniq -c: every row should have the same NF.
  • join needs both inputs sorted on the key, with the same separator (-t,).

Advanced Behind the screen: quoting, locales and numbers

  • Real CSV (RFC 4180) allows commas and newlines inside double quotes. cut and plain awk -F, do not understand quotes; GNU awk has FPAT, and tools like csvkit, Miller (mlr) or Python’s csv module parse it properly.
  • Numbers: awk uses floating point; sums of money can drift (0.1+0.2). For exact currency, work in paise/cents (integers) or round with printf.
  • sort and join depend on the locale; use the same LC_ALL=C for both or join complains that input is not sorted.
  • Windows files end lines with \r\n: the last column then has an invisible \r (“Pune\r” ≠ “Pune”). tr -d '\r' or dos2unix fixes it.
  • jq processes a stream of JSON values; -r prints raw strings, -c compact lines, @csv and @tsv produce safe CSV/TSV output.

Did you know? The comma was chosen for CSV because early 1970s mainframe tools already used it for lists; but in many European countries the comma is the decimal separator, so their spreadsheets export with semicolons. Always check the delimiter in the first line.

EXAM> “How do you sum a column in a CSV file from the command line?” → awk -F, 'NR>1{s+=$N} END{print s}' file.csv (NR>1 skips the header).

join -t, · paste -d, · comm · awk two-file lookup combine files

🟢 Read-onlyno sudo

join matches rows of two files on a key column, like a database join; both inputs must be sorted on that key. paste glues files side by side by line number. comm compares two sorted lists. The awk idiom NR==FNR{…; next} loads a lookup table from the first file and uses it on the second, with no sorting.

✓ Use it when
  • adding names, categories or prices from another file
  • comparing two exports
✗ Don’t use it when
  • join on unsorted input
  • paste for files whose rows are in different orders

Syntax: join -t, -1 4 -2 1 <(sort -t, -k4 a.csv) <(sort -t, -k1 b.csv)

Undo and safety net

One-liners read data; writing results to the input file destroys it.

  • Overwrote the input (awk … f.csv > f.csv): the shell empties f.csv before awk reads it: restore from the source; write to a new file and mv.
  • Totals look wrong: inspect: header, duplicates, empty cells, NF per row, \r endings.
  • join prints nothing: sort both on the key with the same locale and separator; check the key column numbers.
  • jq error: validate with jq . file; fix the JSON (trailing commas are not allowed).

Script it: salesreport.sh

A small, safe sales report from a CSV: validate the file (column count, duplicates, empty quantities), then print totals per city and per product category using the product list, and the top product.

sales=${1:-$HOME/dt/sales.csv}; prods=${2:-$HOME/dt/products.csv}
[ -r "$sales" ] && [ -r "$prods" ] || { echo "missing input" >&2; exit 1; }
cols=$(head -1 "$sales" | awk -F, '{print NF}')
bad=$(awk -F, -v c="$cols" 'NF!=c' "$sales" | wc -l); dup=$(tail -n +2 "$sales" | sort | uniq -d | wc -l)
empty=$(awk -F, 'NR>1 && $5==""' "$sales" | wc -l)
echo "checks: $bad bad rows, $dup duplicate rows, $empty empty qty"
awk -F, 'NR>1 && $5!="" && !s[$0]++' "$sales" > /tmp/clean.$$
echo "-- revenue per city"; awk -F, '{t[$3]+=$5*$6} END{for(c in t) printf "%-9s %9.2f\n", c, t[c]}' /tmp/clean.$$ | sort -k2 -rn
echo "-- revenue per category"; awk -F, 'NR==FNR{if(FNR>1)cat[$1]=$2; next} {t[cat[$4]]+=$5*$6} END{for(c in t) printf "%-11s %9.2f\n", c, t[c]}' "$prods" /tmp/clean.$$ | sort -k2 -rn
echo "-- top product: $(awk -F, '{r[$4]+=$5*$6} END{for(p in r) print r[p], p}' /tmp/clean.$$ | sort -rn | head -1 | awk '{print $2}')"
rm -f /tmp/clean.$$
checks: 0 bad rows, 1 duplicate rows, 1 empty qty -- revenue per city Pune 1933.00 Delhi 1878.00 Mumbai 225.00 Chennai 90.00 -- revenue per category Luggage 3196.00 Stationery 930.00 -- top product: Bag

Run without arguments, so it reads the sample files.
