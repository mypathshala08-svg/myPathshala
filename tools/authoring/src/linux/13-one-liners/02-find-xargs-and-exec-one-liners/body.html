2 Definition

find actions, -exec and xargs

Formal definition (write this in exams)

find walks a directory tree and evaluates an expression of tests and actions for each file. The action -exec cmd {} ; runs a command for each match, -exec cmd {} + runs it with many matches at once, and -delete removes matches. xargs reads items from standard input and runs a command with them as arguments, in batches, optionally in parallel; with -0 it reads NUL-separated items produced by find -print0.

In simple words

find picks the files; -exec or xargs does the work.

Very basic No jargon: a warehouse

One person picks, another processes.

Basic What you will type

  • find logs -name "*.log" -mtime +30: look.
  • find logs -name "*.log" -mtime +30 -delete: delete those.
  • find . -name "*.conf" -exec grep -l old {} +: which configs mention old.
  • Always quote the pattern: "*.log".

Intermediate -exec forms and xargs

  • -exec cmd {} \; runs cmd once per file; {} is the file name, \; ends the command.
  • -exec cmd {} + runs cmd with as many file names as fit: far fewer processes.
  • xargs reads names from standard input and builds command lines; find -print0 | xargs -0 separates names with NUL bytes, so spaces and newlines are safe.
  • xargs -n 1 one name per command, -I{} put the name anywhere, -P 4 four at a time, -r do nothing if there is no input.
  • find evaluates its expression left to right: -delete before -name deletes everything (the second puzzle).

Advanced Behind the screen: argument limits and NUL

  • The kernel limits the size of one command line (getconf ARG_MAX, 2 MiB here); rm * on 500,000 files fails with “Argument list too long”. -exec + and xargs split the list into chunks under the limit.
  • NUL (byte 0) is the only character that cannot appear in a Linux file name, so it is the only fully safe separator.
  • -execdir runs the command inside the file’s folder with ./name, avoiding races with renamed parent folders.
  • -delete implies -depth (children before parents) and does not follow symlinks.
  • xargs without -0 also treats quotes and backslashes specially, another reason to use -0.
  • sed -i writes a new file and renames it over the old one: the inode changes and hard links break (Lesson 10.2).

Did you know? find / -name core -exec rm {} \; used to be a classic nightly cron job to remove crash dump files. On a system with a program called core it deleted that too: one reason modern advice adds -type f and a more exact test to every bulk delete.

EXAM> “What is the difference between -exec {} \; and -exec {} +?” → \; runs the command once per file; + passes many files to one command, like xargs, which is much faster.
Quick check Why put the pattern in quotes: find . -name "*.conf"?
Answer: Without quotes the shell expands *.conf in the current folder first; find then receives file names, or several of them, instead of the pattern.
Common mistake
✗find photos -name "*.JPG" | xargs rm
✓find photos -name "*.JPG" -print0 | xargs -0 rm · or find photos -name "*.JPG" -delete

xargs splits on spaces: “Beach Day.JPG” became “Beach” and “Day.JPG” (real run).

Common mistake
✗find logs -delete -name "*.log"

The expression is read left to right: -delete ran for every file before -name was checked.

-exec cmd {} \; · -exec cmd {} + · -execdir · -ok -exec

🟡 Changes filesno sudo

Everything after -exec up to \; or + is the command; {} is replaced by the path. With \; one command runs per file; with + the names are collected and passed together (the {} must be last). -ok asks before each one.

✓ Use it when
  • compress, checksum, change permissions, grep many files
✗ Don’t use it when
  • commands that need special per-file logic (use a loop)

Syntax: find … -exec gzip {} \; · find … -exec grep -l x {} +

xargs [-0] [-n N] [-I{}] [-P N] [-r] cmd xargs

🟡 Changes filesno sudo

xargs reads items from standard input and appends them to the command. -0 reads NUL-separated items (from -print0, grep -lZ, sort -z). -n 1 one item per command; -I{} one item per command, placed where {} is; -P N runs N commands at once; -r runs nothing on empty input; -t prints each command before running it.

✓ Use it when
  • any list of names: find, grep -l, a file
  • parallel work
✗ Don’t use it when
  • xargs without -0 on arbitrary names
  • commands that read stdin themselves

Syntax: find … -print0 | xargs -0 cmd · … | xargs -0 -P4 -n1 cmd

Undo and safety net

Bulk actions multiply mistakes; previews and backups are the undo.

  • Deleted the wrong files: restore from backup or snapshot; there is no undelete on ext4.
  • sed -i changed too much: restore the .bak files: for f in *.bak; do mv "$f" "${f%.bak}"; done, or git checkout.
  • Renames collided: use mv -n; keep the printed preview as a map back.
  • Habit: find … (look) → add echo before the action → remove echo.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. cd ~/fx/site/conf; find . -name *.conf
    find: paths must precede expression: `b.conf' find: possible unquoted pattern after predicate `-name'? exit status: 1

    What it means: The shell expanded *.conf to several names before find ran.

    Fix: Quote it: -name "*.conf".

  2. cd ~/fx; find . -name '*.conf' -exec ls {}

    What it means: -exec needs \; or + at the end.

    Fix: -exec ls {} \;

  3. cd ~/fx; find . -name '*.conf' -exec echo {} x +

    What it means: With +, {} must be the last argument.

    Fix: Use \; or xargs -I{}.

  4. cd ~/fx/photos; find . -name '*.JPG' | xargs ls

    What it means: xargs split “Beach Day.JPG” at the space.

    Fix: -print0 | xargs -0.

  5. find /root -name x

    What it means: No permission to read a folder.

Build it step by step: the old-logs clean-up

Scenario: Riya builds the nightly clean-up safely, one step at a time.

  1. 1. What is there?

    cd ~/fx; find logs -type f
    logs/app-35.log logs/big.dump logs/app-40.log logs/app-2.log logs/app-10.log

  2. 2. Narrow it down: only old .log files.

    cd ~/fx; find logs -type f -name '*.log' -mtime +30
    logs/app-35.log logs/app-40.log

  3. 3. Check the dates.

    cd ~/fx; find logs -type f -name '*.log' -mtime +30 -exec ls -l --time-style=+%F {} + | awk '{print $6, $7}'
    2026-10-08 logs/app-35.log 2026-10-03 logs/app-40.log

  4. 4. Delete and log what was deleted.

    cd ~/fx; find logs -type f -name '*.log' -mtime +30 -print -delete | sed 's/^/deleted: /'; ls logs

More examples and variations

Twenty more find/xargs one-liners. All were really run on our build machine on the sample tree.

Selecting

V1

Case-insensitive extension

find ~/fx/photos -iname '*.jpg' | wc -l
4

-iname matches .JPG and .jpg.

V2

Files changed in the last hour

find ~/fx -type f -mmin -60 | wc -l
11

-mmin in minutes.

V3

Bigger than 100 KB

find ~/fx -type f -size +100k -exec ls -lh {} + | awk '{print $5, $NF}' | sed 's|/home/riya|~|'
293K ~/fx/logs/big.dump

-size with k, M, G.

V4

Two patterns at once

find ~/fx \( -name '*.html' -o -name 'web.conf' \) | sed 's|/home/riya|~|' | sort
~/fx/site/conf/web.conf ~/fx/site/pages/index.html

\( … -o … \) groups an OR.

V5

Everything except .conf

find ~/fx/site -type f ! -name '*.conf' | sed 's|/home/riya|~|'
~/fx/site/pages/index.html

! negates a test.

V6

Newer than a reference file

cd ~/fx; touch -d '5 days ago' ref; find logs -newer ref -name '*.log'
logs/app-2.log

Since a deploy or a backup.

V7

Only this folder

find ~/fx -maxdepth 1 -type d | sed 's|/home/riya|~|' | sort
~/fx ~/fx/logs ~/fx/photos ~/fx/site

-maxdepth 1 stops recursion.

Acting

V8

Count lines in every .conf

cd ~/fx; find site -name '*.conf' -exec wc -l {} + | tail -1
4 total

One wc with all files gives a total.

V9

Copy matches into one folder

cd ~/fx; mkdir -p bk; find site -name '*.conf' -print0 | xargs -0 -I{} cp {} bk/; ls bk
a.conf b.conf c.conf web.conf

-I{} puts the name before the destination.

V10

cp -t avoids -I

cd ~/fx; mkdir -p bk2; find site -name '*.conf' -print0 | xargs -0 cp -t bk2/; ls bk2 | wc -l
4

cp -t DEST takes the files last: batched.

V11

Checksums of all photos

cd ~/fx; find photos -type f -print0 | sort -z | xargs -0 sha256sum | cut -c1-12,65- | head -3
e3b0c44298fc photos/Beach Day.JPG e3b0c44298fc photos/IMG_0001.JPG e3b0c44298fc photos/IMG_0002.JPG

Sorted for a stable list; identical hashes reveal identical files (here all are empty). Lesson 19.4.

V12

Compress old logs instead of deleting

cd ~/fx; find logs -name '*.log' -mtime +7 -exec gzip {} +; ls logs
app-10.log.gz app-2.log app-35.log.gz app-40.log.gz big.dump

gzip old logs, keep recent ones.

V13

Ask before each delete

cd ~/fx; yes n | find photos -name '*.txt' -ok rm {} \; 2>&1; ls photos/notes.txt
< rm ... photos/notes.txt > ? photos/notes.txt

-ok asked; we answered n (yes n), so nothing was removed.

V14

Print and run with -t

cd ~/fx; find site/conf -name 'a*' -print0 | xargs -0 -t wc -c 2>&1
wc -c site/conf/a.conf 23 site/conf/a.conf

-t echoes the exact command line.

Bulk edits and renames

V15

Change an extension for many files

cd ~/fx/photos; for f in *.JPG; do mv -n -- "$f" "${f%.JPG}.jpg"; done; ls
Beach Day.jpg IMG_0001.jpg IMG_0002.jpg IMG_0003.jpg notes.txt

A loop with ${f%.JPG} (Lesson 12.14).

V16

Spaces to underscores

cd ~/fx/photos; find . -maxdepth 1 -name '* *' -print0 | while IFS= read -r -d '' f; do mv -n -- "$f" "${f// /_}"; done; echo "names with spaces left: $(ls | grep -c ' ')"; ls | head -2
names with spaces left: 0 Beach_Day.JPG IMG_0001.JPG

The loop renamed every name that had a space.

V17

Lower-case all names

cd ~/fx/photos; for f in *; do l=${f,,}; [ "$f" = "$l" ] || mv -n -- "$f" "$l"; done; ls
beach day.jpg img_0001.jpg img_0002.jpg img_0003.jpg notes.txt

${f,,} lower-cases.

1c1 < <p>contact: old-db01.local</p> --- > <p>contact: db01.prod</p>

Undo with the .bak files

cd ~/fx; find site -name '*.conf' -exec sed -i.bak 's/old/new/' {} +; find site -name '*.bak' -print0 | while IFS= read -r -d '' b; do mv -- "$b" "${b%.bak}"; done; grep -c old site/conf/a.conf

Script it: cleanup.sh

Clean a folder safely: show what would be deleted (old .log and .tmp files, empty folders) with the space it would free, and delete only when called with --yes.

dir=${1:-$HOME/fx}; days=${DAYS:-30}; go=${2:-}
mapfile -d '' files < <(find "$dir" -type f \( -name '*.log' -o -name '*.tmp' \) -mtime +"$days" -print0)
echo "${#files[@]} file(s) older than $days days in ${dir/#$HOME/~}:"
for f in "${files[@]}"; do printf '  %s\n' "${f/#$HOME/~}"; done
[ ${#files[@]} -gt 0 ] && echo "space: $(du -ch "${files[@]}" | tail -1 | cut -f1)"
if [ "$go" = --yes ]; then
  [ ${#files[@]} -gt 0 ] && rm -f -- "${files[@]}"
  find "$dir" -mindepth 1 -type d -empty -delete
  echo "deleted."
else
  echo "dry run: add --yes to delete"
fi
2 file(s) older than 30 days in /home/riya/fx: /home/riya/fx/logs/app-35.log /home/riya/fx/logs/app-40.log space: 8.0K dry run: add --yes to delete

Run without --yes, so it only shows what it would do.

Puzzle answer Remember the question from the story? Open to check your guess.

1. xargs splits its input at spaces, so “photos/Beach Day.JPG” became two wrong names. Use find … -print0 | xargs -0 rm, or simply find … -delete. 2. find reads its expression left to right; -delete came before -name, so it ran for every file (and returned true) before the name was ever checked. Tests first, action last. 3. Unquoted, *.conf is expanded by the shell: in a folder with one .conf file find got that one name; with several, find got extra words and complained “paths must precede expression”. Quote patterns: -name "*.conf".

Quick check Where does -delete belong in a find command?
Answer: At the end, after all the tests.
