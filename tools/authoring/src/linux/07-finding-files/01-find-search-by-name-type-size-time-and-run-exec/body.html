The problem

Saturday morning, the server’s disk is 97% full and the website is about to stop. Somewhere under /var are log files that grew to gigabytes, backups older than anyone needs, and temporary files nobody cleaned. ls shows one folder at a time; grep looks inside files. To find the files themselves by name, size, age, owner or permission, anywhere in a folder tree, and act on them, Linux has find: find /var/log -name '*.log' -size +100M -mtime +30.

By the end of this page you will be able to:
  • search a folder tree by name (-name -iname -path -regex) and by type (-type f d l)
  • find files by size (-size +100M), age (-mtime -mmin -newer), permissions (-perm) and owner (-user -group -nouser)
  • combine tests with AND, OR, NOT and brackets, limit depth, and skip folders with -prune
  • act on what you found safely: -print, -ls, -printf, -exec … {} \; and +, -ok, -delete, -print0 | xargs -0

2 Definition

find: search by name, type, size, time and run -exec

Formal definition (write this in exams)

find walks a directory tree starting at one or more paths and evaluates an expression for every file and folder it meets. The expression is made of tests (name, type, size, times, permissions, owner…), operators (and, or, not, grouping) and actions (print, list, run a command, delete). The default action is -print.

In simple words

Walk the folders, test every file, act on the ones that match.

find at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a librarian with a checklist

Think of a librarian looking for books.

  • The librarian starts at one aisle (the folder you give) and walks every shelf below it.
  • Each book is checked against your rules: title, thickness, date, owner.
  • Matching books go on a trolley; then you decide what to do with them.

Basic The forms you will type every day

  • find . -name 'notes.txt': find a file by exact name under the current folder.
  • find ~ -name '*.pdf': all PDFs in your home folder (quote the *).
  • find . -type d: only folders; -type f only files.
  • find /var/log -size +100M: big files.
  • find . -mtime -1: changed in the last 24 hours.

Intermediate Tests, units and combining

  • Numbers take a sign: +N more than, -N less than, N exactly. -mtime +30 = more than 30 days ago.
  • Sizes: c bytes, k KiB, M MiB, G GiB. find rounds up to whole units, so -size -1k means “0 KiB”: only empty files.
  • Tests are joined by AND automatically; -o is OR, ! is NOT, \( … \) groups: find . \( -name '*.log' -o -name '*.tmp' \) -mtime +7.
  • -maxdepth N limits how deep find goes; -path ./node_modules -prune -o … -print skips a folder entirely.
  • Actions: -exec cmd {} \; runs once per file, -exec cmd {} + once for many files (faster), -ok asks first, -delete removes.

Advanced Behind the screen: walking the tree

  • find reads folders with getdents64 and checks each entry with newfstatat (size, times, owner, mode). It does not open or read the files, so it is fast even on millions of files, but it must visit every folder: no index (that is locate’s job, Lesson 7.2).
  • Tests run left to right and stop at the first false one: put cheap tests (-name, -type) before expensive ones (-exec).
  • Times: -mtime content modified, -ctime inode changed (permissions, owner, rename), -atime last read (often disabled by relatime mounts). Days are counted in whole 24-hour periods, so -mtime +1 means at least 48 hours ago.
  • -delete implies -depth (contents before their folder). -xdev stays on one file system (do not wander into /proc or network mounts).
  • Parsing find output is safe only with -print0 + xargs -0 or -exec … +: file names may contain spaces and even newlines.

Did you know? find never opens your files to search them: it only looks at their names and the information the file system keeps about them (the inode: size, owner, permissions, times, Lesson 10.1). That is why find / -size +1G can scan a whole server in seconds, while grep -r on the same server would read every byte.

EXAM> “Find all files larger than 100 MB under /var that have not been modified for 30 days, and list them with their sizes.” → find /var -type f -size +100M -mtime +30 -exec ls -lh {} + (explain + and - in -size and -mtime, and -exec … +).
Quick check What is the difference between find . -mtime -7 and find . -mtime +7?
Answer: -7: modified less than 7 days ago (recent). +7: modified more than 7 days ago (old).

Common mistake
✗find /home -type f -perm -777 (described as “files with 777 permissions”)

find explained, then used in every field

find -name · -type search by name and type

🟢 Read-onlyno sudo

Walks the tree below each starting point and prints paths whose name matches the glob. -iname ignores case; -type f/d/l restricts the kind.

✓ Use it when
  • you know (part of) the name but not the folder
  • all files of a kind: *.log, *.py, *.conf
  • folders only, files only, links only
✗ Don’t use it when
  • searching text inside files (grep -r, Lesson 6.1)
  • the whole disk when locate is enough (Lesson 7.2)

Syntax: find PATH... [-name 'GLOB' | -iname 'GLOB' | -path 'GLOB'] [-type f|d|l]

findcommandprojwhere to start-name '*.py'test: name (quoted glob)-type ftest: regular file-printaction (default)

find -name · -type in system info / admin

  1. Situation: Where is the nginx config? (the real command, with errors hidden)

    Typical output (cannot be recorded on our build machine)

    sudo find / -name 'nginx.conf' -type f 2>/dev/null
    /etc/nginx/nginx.conf

    Why this way: Search from / as root; 2>/dev/null hides “Permission denied” for /proc entries. On a normal Ubuntu, locate nginx.conf is faster (7.2).

  2. Situation: As a normal user, searching system folders gives permission errors.

    find /etc -name '*.conf' 2>&1 | grep -c 'Permission denied'
find /etc -name '*.conf' 2>/dev/null | wc -l
    5 132

    Why this way: Errors go to stderr (Lesson 5.1); the results still come through.

find -name · -type in software development

  1. Situation: All test files in a project, wherever they are.

    find proj -path '*/tests/*' -name '*.py'
    proj/src/tests/test_main.py

    Why this way: -path matches the whole path, so the folder name can be part of the pattern.

find -name · -type in devops / cloud

  1. Situation: Hidden files (like .env) that should not be in a deploy package.

    find proj -name '.*' -type f
    proj/src/app/.env

    Why this way: -name '.*' matches names starting with a dot. Secrets in .env files must never be shipped.

Common mistake
✗find .. -name *.py (no quotes)
✓find .. -name '*.py'

Without quotes the shell expands *.py in the current folder first. With one file app.py there, find receives -name app.py and finds only that name (real run). With two .py files here it fails with “paths must precede expression”. This is the first part of the puzzle.

find -size · -empty search by size

🟢 Read-onlyno sudo

-size +N bigger than, -N smaller than, N exactly, with units c (bytes), k, M, G. find rounds each file up to whole units before comparing. -empty matches empty files and folders.

✓ Use it when
  • disk full: what is big?
  • very small or empty files that should not exist
  • size limits for uploads, logs, backups
✗ Don’t use it when
  • totals per folder (use du, Lesson 15.4)

Syntax: find PATH -size [+|-]N[c|k|M|G] · find PATH -empty

find -mtime · -mmin · -newer search by time

🟢 Read-onlyno sudo

Compares file times with now: -mtime in days, -mmin in minutes (content changed), -ctime/-cmin (inode changed), -atime/-amin (last read). +N older than, -N newer than. -newer FILE compares with another file.

✗ Don’t use it when

find ! -o ( ) -prune combining tests

🟢 Read-onlyno sudo

Tests next to each other are joined by AND. -o means OR, ! means NOT, and \( \) groups (escaped for the shell). -prune stops find from going into a folder.

✓ Use it when
  • skipping folders like .git, node_modules, /proc
  • combining several names or conditions
  • limiting depth for speed
✗ Don’t use it when
  • very complex logic: pipe to grep/awk or write a small script

Syntax: find . \( -name '*.log' -o -name '*.tmp' \) ! -name 'keep*' · find . -path ./.git -prune -o -type f -print

find ! -o ( ) -prune in software development

  1. Situation: All files except Python and Java sources.

    find proj/src -type f ! -name '*.py' ! -name '*.java'

  1. Situation: Old .log or .tmp files, but never anything in backup/.

    find proj -path proj/backup -prune -o -type f \( -name '*.log' -o -name '*.tmp' \) -mtime +7 -print
    proj/tmp/b.tmp proj/logs/cron.log

    Why this way: Without the explicit -print the pruned folder name would be printed too; with it, only matches are shown.

Common mistake
✗find . -name '*.log' -o -name '*.tmp' -delete
✓find . \( -name '*.log' -o -name '*.tmp' \) -delete

AND binds tighter than OR, so without brackets -delete belongs only to the second test: the .log files are matched but not deleted (and nothing tells you). Always group OR tests in \( \).

find -exec · -ok · -delete · -print0 act on the results

🔴 Can destroy datano sudo

-exec cmd {} \; runs cmd for each file ({} = the path). -exec cmd {} + passes many files to one cmd (faster). -ok asks y/n first. -delete removes. -print0 + xargs -0 handles any file name.

✓ Use it when
  • doing something with each result: list, compress, move, change permissions, delete
  • bulk work on thousands of files
  • cleaning up by age or size
✗ Don’t use it when
  • deleting before you have looked at the list

Syntax: find … -exec CMD {} \; · find … -exec CMD {} + · find … -delete · find … -print0 | xargs -0 CMD

OptionWhat it doesWhen to use it
-exec ls -lh {} +list matches with sizesreview

Undo and safety net

find itself only reads; -delete and -exec can destroy data.

  • Before -delete or -exec rm: run the same command without it, read the list, count it with | wc -l.
  • -delete removed too much: there is no undo: restore from backup. Put -delete last; it acts on whatever matched before it.
  • Started at the wrong place (find / …): Ctrl+C stops it at once.
  • A command ran on the wrong files with -exec: use -ok the first time, or echo: -exec echo rm {} + as a dry run.

Error messages decoded

find errors students see most. Each was really produced on our build machine, with its exit status.

  1. find /root -name x
    find: ‘/root’: Permission denied exit status: 1

    What it means: A normal user cannot read /root. find reports it and exits 1.

    Fix: sudo, or 2>/dev/null if you only care about readable places.

  2. touch a.py b.py; find . -name *.py
    find: paths must precede expression: `b.py' find: possible unquoted pattern after predicate `-name'? exit status: 1

    What it means: The shell expanded *.py to a.py b.py; find got an extra word where it expected a test.

    Fix: Quote the pattern: -name '*.py'.

  3. find . -name x -exec echo {}
    find: missing argument to `-exec' exit status: 1

    What it means: -exec needs \; or + at the end.

    Fix: -exec echo {} \; or +.

  4. find -name x /tmp
    find: paths must precede expression: `/tmp' find: possible unquoted pattern after predicate `-name'? exit status: 1

    What it means: Paths must come before the tests.

    Fix: find /tmp -name x.

  5. find . -mtime 1.5x
    find: invalid argument `1.5x' to `-mtime' exit status: 1

    What it means: A number with letters is not valid.

    Fix: Whole numbers with + or -; use -mmin for minutes.

Script it: cleanup.sh

The clean-up as a cron-ready script: report, then delete old temp files and backups, and log how much space was freed.

mkdir -p proj/src/app proj/src/tests proj/logs proj/tmp/cache proj/empty_dir proj/backup
printf 'print(1)\n' > proj/src/app/main.py; printf 'x=1\n' > proj/src/app/Utils.PY; printf 'def test(): pass\n' > proj/src/tests/test_main.py
printf 'class Main {}\n' > proj/src/app/Main.java; : > proj/src/app/empty.txt; printf 'DB_PASSWORD=x\n' > proj/src/app/.env
head -c 3M /dev/zero > proj/logs/app.log; head -c 200K /dev/zero > proj/logs/access.log; printf 'ok\n' > proj/logs/cron.log
head -c 50K /dev/zero > proj/tmp/cache/a.tmp; head -c 20K /dev/zero > proj/tmp/b.tmp
head -c 1M /dev/zero > proj/backup/db_2026-10-01.sql.gz; head -c 1M /dev/zero > proj/backup/db_2026-11-05.sql.gz
touch -d '2026-10-01 02:00' proj/backup/db_2026-10-01.sql.gz proj/tmp/b.tmp; touch -d '2026-09-20' proj/logs/cron.log
touch -d '2026-11-05 02:00' proj/backup/db_2026-11-05.sql.gz
chmod 777 proj/src/app/main.py; chmod 600 proj/src/app/.env; chmod 755 proj/src/app/Utils.PY
dir=proj; days=30
list=$(find "$dir" -type f \( -name '*.tmp' -o -name '*.gz' \) -mtime +$days)
[ -z "$list" ] && { echo "nothing to delete"; exit 0; }
bytes=$(find "$dir" -type f \( -name '*.tmp' -o -name '*.gz' \) -mtime +$days -printf '%s\n' | paste -sd+ | bc)
echo "deleting $(echo "$list" | wc -l) files, $bytes bytes:"; echo "$list"
find "$dir" -type f \( -name '*.tmp' -o -name '*.gz' \) -mtime +$days -delete
echo "$(date -d 2026-11-06 +%F) freed $bytes bytes" >> cleanup.log; cat cleanup.log
deleting 2 files, 1069056 bytes: proj/tmp/b.tmp proj/backup/db_2026-10-01.sql.gz 2026-11-06 freed 1069056 bytes

The block at the top only creates the sample project. In cron: 0 3 * * * /opt/scripts/cleanup.sh >> /var/log/cleanup.log 2>&1 (Lesson 17.4).

Puzzle answer Remember the question from the story? Open to check your guess.

Without quotes the shell expands *.py in the current folder (src/) before find runs. There it matches only app.py, so find receives -name app.py and finds just that name. Quote it: find .. -name '*.py'. And -size -1k rounds every file up to whole kilobytes: a 2-byte file counts as 1k, which is not less than 1k, so only empty files match. Use -size -1024c.
