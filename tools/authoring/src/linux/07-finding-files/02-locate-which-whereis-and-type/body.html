2 Definition

locate, which, whereis and type

Formal definition (write this in exams)

locate searches a database of file names, built periodically by updatedb, for names matching a pattern. which prints the full path of the executable that would run for a command name, by searching the directories in $PATH. type (a shell builtin) tells how the shell would interpret a name: alias, keyword, function, builtin or file. whereis finds the binary, source and manual-page files of a command in standard locations.

In simple words

Find a file name instantly, and find out exactly what a command name refers to.

locate, which, whereis and type at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a detective, a phone book and a receptionist

Think of finding someone in a city.

  • find is a detective who walks every street: slow but always right.
  • locate is a phone book printed last night: instant, but people who moved in today are missing.
  • which, type and whereis are the receptionist who knows exactly which office a name refers to.

Basic The forms you will type every day

  • locate nginx.conf: every path containing that name.
  • locate -i report: any case; locate -c '*.pdf': just count.
  • which python3: the program that runs when you type python3.
  • type ll: “ll is aliased to ls -alF”.
  • whereis ls: the ls program and its manual page.

Intermediate Indexes, PATH and command types

  • The index is rebuilt by updatedb, normally once a day by a systemd timer or cron. Files created since are missing; deleted files are still listed (use locate -e to check they exist).
  • locate only shows files you are allowed to see, even though the index was built as root.
  • When you type a command, the shell checks in order: alias → keyword → function → builtin → a program in $PATH (searched left to right). type shows that order; which only searches $PATH.
  • which -a and type -a list every match: the answer to “wrong version” problems.
  • In scripts use command -v (POSIX, built in) to test whether a command exists.

Advanced Behind the screen: plocate, hashing and PATH order

  • Ubuntu 22.10+ and Debian 12 use plocate (database /var/lib/plocate/plocate.db, built by updatedb from /etc/updatedb.conf, which skips /tmp, /proc and network mounts). It is a compressed trigram index: a search reads a few kilobytes, not the disk. Older systems use mlocate.
  • -r/--regex forces a full scan of the database (still much faster than find).
  • bash remembers where it found each program (hash). If you install a new version in another folder, bash may keep running the old one until hash -r or a new shell.
  • which is an external program that knows nothing about aliases or functions; type and command -v are shell builtins and see everything the shell sees.
  • Security: a writable folder early in $PATH (like . or ~/bin before /usr/bin) lets someone plant a fake ls or sudo. Keep system folders first for root.

Did you know? On Ubuntu the locate index is refreshed by a systemd timer called plocate-updatedb.timer, normally once a day. You can see when it will run next with systemctl list-timers | grep updatedb (Lesson 17.3).

EXAM> “What is the difference between find and locate?” → locate searches a database built by updatedb (fast, may be stale, names only); find searches the file system live (slower, always current, can test size, time, owner and run actions).
Quick check Why can locate miss a file you created five minutes ago?
Answer: Its database was built earlier by updatedb. Run sudo updatedb first, or use find.
Common mistake
✗“Locate is able to find the files even after they are deleted” (listed as an advantage) · “locate -u username: files owned by a user” · “locate -n 10: limit results”
✓Listing deleted files is a drawback of the stale index: use locate -e to show only files that still exist · locate has no owner option (use find -user) · on plocate the limit option is -l 10 (-n belonged to older mlocate)

Checked against the plocate manual (Ubuntu’s locate since 22.10). The comparison table in the notes is otherwise right: locate is faster, find is current.

locate find file names in an index

🟢 Read-onlyno sudo

Prints every path in the database that contains the pattern (or matches it, if it has * ? [ ]). Shows only files you are allowed to see.

✓ Use it when
  • “where is that file?” when you know (part of) the name
  • searching the whole system in milliseconds
  • counting files of a kind across the disk
✗ Don’t use it when
  • files created or deleted since the last updatedb
  • searching by size, age or owner (use find)
  • servers where plocate is not installed (find works everywhere)

Syntax: locate [-i] [-b] [-c] [-l N] [-e] [-0] [-r REGEX | --regex ERE] PATTERN... · sudo updatedb

locatecommand-iignore case-bname only'report'text or glob to look for

A pattern without * ? [ ] matches anywhere in the path; with them it must match the whole path.

which · command -v in software development

  1. Situation: Two versions of a tool: which one wins depends on PATH order.

    PATH="$HOME/bin:$HOME/venv/bin:$PATH"; which -a mytool; mytool
PATH="$HOME/venv/bin:$HOME/bin:$PATH"; which mytool; mytool
    /home/riya/bin/mytool /home/riya/venv/bin/mytool python from ~/bin /home/riya/venv/bin/mytool python from venv

    Why this way: Activating a Python virtual environment puts its bin folder first: that is all “activate” really does.

  2. Situation: Follow a symlink to the real program.

    readlink -f "$(which python3)"
    /usr/local/bin/python3.13

    Why this way: /usr/bin/python3 is often a link to python3.12 (or similar): the real version.

which · command -v in devops / cloud

  1. Situation: A deploy script checks its tools first.

    for t in git curl docker; do if command -v "$t" > /dev/null; then echo "$t: $(command -v "$t")"; else echo "$t: MISSING"; fi; done
    git: /usr/bin/git curl: /usr/bin/curl docker: /usr/bin/docker

    Why this way: command -v exits 1 when the name is unknown; fail early with a clear message. (docker is not installed on our build machine.)

which · command -v in system info / admin

  1. Situation: Full paths for crontab entries (cron has a short PATH).

    echo "0 2 * * * $(which tar) czf /backup/etc.tgz /etc"
    0 2 * * * /usr/bin/tar czf /backup/etc.tgz /etc

    Why this way: cron runs with PATH=/usr/bin:/bin; full paths avoid “command not found” at 2 a.m. (Lesson 17.4).

Common mistake
✗which cd · which ll (expecting an answer)
✓type cd · type ll · command -v ll

which only searches $PATH for program files. Builtins, aliases and functions are invisible to it, so it prints nothing and exits 1.

type what kind of command?

🟢 Read-onlyno sudo

A shell builtin that says how a name would be interpreted: alias, keyword, function, builtin or file (with its path). -a lists every definition in the order the shell would try them; -t prints just the kind.

✓ Use it when

  • aliases that hide the real command
  • all definitions in order (type -a)
✗ Don’t use it when
  • shells without type (rare): use command -v

type in system info / admin

  1. Situation: Why does ls show colours, or rm ask before deleting? Check for aliases.

    shopt -s expand_aliases; alias ls='ls --color=auto'; alias rm='rm -i'
type ls rm
    ls is aliased to `ls --color=auto' rm is aliased to `rm -i'

    Why this way: Many distributions define aliases in ~/.bashrc. type reveals them; \rm or command rm skips an alias (Lesson 12.3).

type in software development

  1. Situation: Is my function overriding a real command?

    grep() { echo 'my grep function'; }
type -a grep
command grep -c root /etc/passwd
    grep is a function grep () { echo 'my grep function' } grep is /usr/bin/grep grep is /bin/grep 1

    Why this way: A function named like a program wins; type -a shows both; command runs the real program.

type in testing / qa

  1. Situation: A script behaves differently for two testers: same command, different kind.

    shopt -s expand_aliases; alias python3='echo using an alias'
type -t python3
unalias python3; type -t python3
    alias file

    Why this way: Aliases are not inherited by scripts, so a test that passes in your terminal can fail in CI. Check with type.

Undo and safety net

These tools only read, but they can mislead you.

  • locate shows a file that is gone: use locate -e, or run sudo updatedb.
  • locate misses a new file: sudo updatedb, or use find (Lesson 7.1).
  • which shows a program, but something else runs: an alias or function wins: use type -a.
  • Old version keeps running after an upgrade: hash -r or open a new terminal; check which -a and PATH order.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. locate nginx.conf
    /home/riya/script.sh: line 1: locate: command not found exit status: 127

    What it means: locate is not installed on this machine (minimal servers, containers).

    Fix: sudo apt install plocate (then sudo updatedb), or use find.

  2. which nosuchtool
    exit status: 1

    What it means: Not found in any $PATH folder: which prints nothing and exits 1.

    Fix: Install it, or add its folder to PATH (Lesson 12.1).

  3. type nosuchtool
    /home/riya/script.sh: line 1: type: nosuchtool: not found exit status: 1

    What it means: Not an alias, keyword, function, builtin or file.

    Fix: Check the spelling; install the package.

  4. nosuchtool --version
    /home/riya/script.sh: line 1: nosuchtool: command not found exit status: 127

    What it means: command not found (127): the shell searched every PATH folder.

    Fix: Ubuntu often suggests the package to install (command-not-found).

Build it step by step: the wrong-python investigation

Scenario: Riya finds out why her program cannot see its library.

  1. 1. Is mytool on PATH at all?

    type -a mytool 2>&1 || echo 'not on PATH yet'
    /home/riya/script.sh: line 4: type: mytool: not found not on PATH yet

  2. 2. After adding both folders: two copies.

    PATH="$HOME/bin:$HOME/venv/bin:$PATH"; type -a mytool
    mytool is /home/riya/bin/mytool mytool is /home/riya/venv/bin/mytool

  3. 3. The ~/bin one runs: the wrong one.

    PATH="$HOME/bin:$HOME/venv/bin:$PATH"; mytool
    python from ~/bin

  4. 4. Put the venv first (what “activate” does): fixed.

    PATH="$HOME/venv/bin:$HOME/bin:$PATH"; hash -r; mytool
    python from venv

Script it: need-tools.sh

The start of every serious script: check required tools, print where each one is, and stop with a clear message if one is missing.

need() {
  for t in "$@"; do
    if p=$(command -v "$t"); then printf '%-8s %s\n' "$t" "$p"
    else echo "error: $t is not installed" >&2; return 1; fi
  done
}
need bash grep sed awk && echo "all tools present"
need git jq || echo "stopping: install the missing tool first"
bash /usr/bin/bash grep /usr/bin/grep sed /usr/bin/sed awk /usr/bin/awk all tools present git /usr/bin/git jq /usr/bin/jq

jq is not installed on our build machine, so the second check fails as it should.

Puzzle answer Remember the question from the story? Open to check your guess.

locate is not broken: it searches a database built by updatedb, usually once a day. A file created after the last update is not in it (run sudo updatedb), and a deleted file is still in it until the next update. That is a limitation, not a feature: locate -e hides entries whose files no longer exist.
