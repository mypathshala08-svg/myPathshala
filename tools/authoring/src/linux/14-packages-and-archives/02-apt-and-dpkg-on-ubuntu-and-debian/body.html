2 Definition

apt and dpkg

Formal definition (write this in exams)

apt is the high-level package manager of Debian and Ubuntu: it downloads repository indexes (update), resolves dependencies and installs, upgrades and removes packages from repositories. dpkg is the low-level tool underneath: it installs, configures and removes individual .deb files and maintains the database of installed packages. apt calls dpkg to do the actual work.

In simple words

apt plans and fetches; dpkg unpacks and records.

Words you’ll meet in this lesson

updateRefresh repository lists.
upgradeInstall newer versions.
full-upgradeUpgrade that may add/remove packages.
remove / purgeUninstall / also delete configs.
autoremoveRemove unneeded dependencies.
holdKeep a package at its version.
simulate (-s)Show the plan, change nothing.
conffileA config file dpkg protects.

apt and dpkg at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a catalogue and a shop

Read the catalogue, then shop.

Basic What you will type

  • sudo apt update, then sudo apt upgrade.
  • sudo apt install htop, sudo apt remove htop.
  • apt search image editor, apt show gimp.
  • sudo apt autoremove after removing things.

Intermediate Choices that matter

  • upgrade never removes packages and does not add new ones; full-upgrade (dist-upgrade) may, which is needed for new kernels or changed dependencies (“kept back”).
  • remove keeps config files (status rc); purge deletes them.
  • autoremove removes packages that were installed only as dependencies and are no longer needed (marked “automatic”).
  • apt-mark hold PKG keeps a package at its version during upgrades; unhold releases it.
  • -s (simulate) shows what would happen without doing it, even as a normal user.
  • apt is for humans (progress bars, colours); apt-get/apt-cache have a stable output for scripts.

Advanced Behind the screen: locks, phases and logs

  • apt takes a lock (/var/lib/dpkg/lock-frontend); “Could not get lock” means another apt (often unattended-upgrades) is running.
  • An install has phases: download to /var/cache/apt/archives, unpack (dpkg), configure (postinst scripts, triggers like man-db and ldconfig).
  • If configuration is interrupted, packages stay half-configured; sudo dpkg --configure -a resumes, sudo apt -f install repairs dependencies.
  • Changed config files: on upgrade dpkg asks whether to keep yours or take the maintainer’s (--force-confold/--force-confnew in automation).
  • Logs: /var/log/apt/history.log (what was installed/removed and by which command), term.log (the full output), /var/log/dpkg.log (every status change).
  • unattended-upgrades installs security updates automatically on Ubuntu servers (Lesson 19.3).

Did you know? apt moo prints a cow. It is an old easter egg kept since apt-get’s early days: apt-get moo says “Have you mooed today?”

EXAM> “What is the difference between apt update and apt upgrade?” → update refreshes the package lists from the repositories; upgrade installs newer versions of installed packages using those lists.
Quick check Which command removes a package and its configuration files?
Answer: sudo apt purge PKG.
Common mistake
✗apt upgrade without apt update
✓sudo apt update && sudo apt upgrade

apt only knows the versions in its last downloaded lists; without update it sees nothing new.

Common mistake
✗apt remove when you want a clean reinstall
✓sudo apt purge PKG && sudo apt install PKG (back up /etc/PKG first)

remove keeps /etc files, so a reinstall brings back the old (broken) config: the puzzle.

Undo and safety net

Almost everything apt does can be undone with another apt command.

  • Removed the wrong package: sudo apt install PKG (configs were kept by remove).
  • Purged a config you needed: restore /etc from backup; reinstall gives the default config.
  • An upgrade broke something: find the old version in history.log; sudo apt install PKG=OLDVERSION and hold it.
  • Interrupted install: sudo dpkg --configure -a, then sudo apt -f install.

6 Real-world use

apt at work

1. Patch windows

Ops teams run update, list --upgradable, upgrade on staging first, then production, and record history.log.

Staging→apt upgrade→production

2. Protecting critical versions

PostgreSQL or a kernel is held during routine patching and upgraded in a planned window.

hold→routine upgrades→planned upgrade

3. Container images

Dockerfiles use apt-get update && apt-get install -y --no-install-recommends … && rm -rf /var/lib/apt/lists/* to keep images small.

Base→one RUN line→small image

4. Rebuilding a server

dpkg --get-selections on the old server, dpkg --set-selections and apt-get dselect-upgrade on the new one.

Old box→selections→same packages

5. Automatic security updates

unattended-upgrades applies security fixes nightly; history.log shows what it did (Lesson 19.3).

Night→unattended-upgrades→patched

    cd ~/ap; pdpkg --force-depends -i greet_1.0.deb > /dev/null 2>&1; pdpkg -l greet | tail -1 | awk '{print $1, $2, $3}'
    ii greet 1.0

  2. 2. Upgrade to 1.1.

    cd ~/ap; pdpkg --force-depends -i greet_1.1.deb > /dev/null 2>&1; pdpkg -l greet | tail -1 | awk '{print $1, $2, $3}'
    ii greet 1.1

  3. 3. Remove: rc, config still there.

    cd ~/ap; pdpkg -r greet > /dev/null 2>&1; pdpkg -l greet | tail -1 | awk '{print $1, $2}'; ls ~/ap/root/etc/greet
    rc greet greet.conf

  4. 4. Purge: config gone.

    cd ~/ap; pdpkg -P greet > /dev/null 2>&1; ls ~/ap/root/etc/greet 2>&1 | head -1
    ls: cannot access '/home/riya/ap/root/etc/greet': No such file or directory

Private dpkg root

V12

Status letters

cd ~/ap; pdpkg --force-depends -i greet_1.0.deb > /dev/null 2>&1; pdpkg -l | awk 'NR<=3 || /greet/' | cut -c1-60
Desired=Unknown/Install/Remove/Purge/Hold | Status=Not/Inst/Conf-files/Unpacked/halF-conf/Half-inst/tr |/ Err?=(none)/Reinst-required (Status,Err: uppercase=bad) ii greet 1.0 all greet demo

First letter: desired (i install, r remove, h hold); second: status (i installed, c config-files, U unpacked).

V13

Changed config file is kept on upgrade

cd ~/ap; pdpkg --force-depends -i greet_1.0.deb > /dev/null 2>&1; echo 'colour=red' > ~/ap/root/etc/greet/greet.conf; pdpkg --force-depends --force-confold -i greet_1.1.deb > /dev/null 2>&1; cat ~/ap/root/etc/greet/greet.conf
colour=red

1.1 ships a new default (colour=green), but you edited the file: --force-confold keeps yours (dpkg would ask interactively).

V14

Take the maintainer’s version instead

cd ~/ap; pdpkg --force-depends -i greet_1.0.deb > /dev/null 2>&1; echo 'colour=red' > ~/ap/root/etc/greet/greet.conf; pdpkg --force-depends --force-confnew -i greet_1.1.deb > /dev/null 2>&1; cat ~/ap/root/etc/greet/greet.conf; ls ~/ap/root/etc/greet/
colour=green greet.conf greet.conf.dpkg-old

--force-confnew installs the maintainer’s new default and saves yours as .dpkg-old.

V15

Finish interrupted configuration

cd ~/ap; pdpkg --force-depends --unpack greet_1.0.deb > /dev/null 2>&1; pdpkg -l greet | tail -1 | cut -c1-3; pdpkg --force-depends --configure -a > /dev/null 2>&1; pdpkg -l greet | tail -1 | cut -c1-3
iU ii

iU → ii: what dpkg --configure -a does after a crash.

Script it: patchreport.sh

A safe patch report: what is installed, what would be upgraded (simulated), held packages, leftover configs, cache size and the last three apt sessions from the log. Read-only: it changes nothing.

echo "== $(hostname) $(grep -m1 PRETTY /etc/os-release | cut -d'"' -f2)"
echo "installed packages: $(dpkg -l | grep -c '^ii')"
up=$(apt-get -s upgrade 2>/dev/null | grep -c '^Inst')
echo "would upgrade now:  $up (run 'sudo apt update' first for fresh lists)"
echo "held:               $(apt-mark showhold | wc -l)"
echo "leftover configs:   $(dpkg -l | grep -c '^rc')"
echo "download cache:     $(du -sh /var/cache/apt/archives 2>/dev/null | cut -f1)"
echo "last apt sessions:"
grep -E '^(Start-Date|Commandline)' /var/log/apt/history.log 2>/dev/null | tail -6 | paste - - | cut -c13-90 | sed 's/^/  /'
== web01 Ubuntu 24.04.5 LTS installed packages: 1044 would upgrade now: 0 (run 'sudo apt update' first for fresh lists) held: 0 leftover configs: 0 download cache: 8.0K last apt sessions: 2026-11-03 22:36:42 Commandline: apt-get install -y --no-install-recommends f 2026-11-03 22:37:54 Commandline: apt-get install -y --no-install-recommends t 2026-11-03 22:39:15 Commandline: apt-get install -y --no-install-recommends l

Read-only; safe to run anywhere.

Puzzle answer Remember the question from the story? Open to check your guess.

1. apt upgrade uses the package lists from the last apt update; without a fresh update apt did not know the new version existed. Always sudo apt update && sudo apt upgrade. 2. apt remove keeps configuration files (status rc), so the reinstall found the old config. Use sudo apt purge nginx (after saving what you need from /etc/nginx), then install again. 3. “Kept back”: the new linux-generic needs new packages (a new kernel), which plain upgrade never adds. Use sudo apt full-upgrade (or sudo apt install linux-generic) in a maintenance window, then reboot.

Answer: -s (simulate), e.g. apt-get -s upgrade.
