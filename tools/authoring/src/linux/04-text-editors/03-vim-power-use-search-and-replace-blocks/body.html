2 Definition

Substitution, global commands, visual mode, macros and registers

Formal definition (write this in exams)

:[range]s/pattern/replacement/[flags] substitutes text matching a regular expression in the given lines (% = all). :g/pattern/command runs an ex command on every line that matches (:v on those that do not). Visual mode (v, V, Ctrl+V) selects text for an operator. A macro is a recorded sequence of keys stored in a register and replayed with @; registers also hold yanked and deleted text.

In simple words

Describe a change once (:s, :g, a selection, a macro) and let vim apply it everywhere.

vim power features at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: do it once, repeat it

Three ideas from everyday life.

  • Find and replace, like Word, but you can ask for each change.
  • A stamp: select a column of lines and type once; it appears on all of them.
  • A tape recorder: record what you type once, replay it on the other lines.

Basic The commands you will use every day

  • :%s/old/new/g replaces in the whole file; add c to confirm each one.
  • . repeats your last change: change one line, move, press ..
  • v select characters, V whole lines, Ctrl+V a block; then d, y, >, or I to insert on every line.
  • :set number shows line numbers.
  • :e file opens another file; :sp/:vsp split the window.

Intermediate Ranges, :g, macros and registers

  • Ranges: :10,20s/…, :.,$s/… (here to end), :'<,'>s/… (the visual selection).
  • Flags: g all matches in a line, c confirm, i ignore case. Groups: \(…\) and \1.
  • :g/pattern/d deletes matching lines; :v/pattern/d deletes the others; :g can run any command (:g/ERROR/t$ copies them to the end).
  • Macro: qa record into a, do the edit, q stop, @a replay, 10@a ten times.
  • Registers: "ayy copy into a, "ap paste from a; :reg shows them all.

Advanced Behind the screen: ex, regex flavours and the shell

  • :s and :g are ex commands (the editor vi grew out of); sed uses the same s/// syntax because both come from ed.
  • vim regex is close to grep’s basic regex: \( \) \+ need backslashes; \v (“very magic”) at the start makes it like Perl/ERE: :%s/\v(\d+)-(\d+)/\2-\1/.
  • Text objects select by meaning: iw inner word, i" inside quotes, ap a paragraph: ci" changes a quoted string from anywhere inside it.
  • :r !cmd inserts command output, :%!cmd filters the whole buffer through a command (e.g. sort, jq .), :w !sudo tee % saves a root file you opened without sudo (prefer sudoedit).
  • ~/.vimrc is read at start; on Ubuntu, without one, vim loads defaults.vim (ruler, incremental search, last cursor position).

Did you know? The command g/re/p of the old Unix editor ed meant “globally, for every line matching the regular expression, print it”. Ken Thompson turned exactly that into a separate program in 1973: grep. vim still understands :g/re/p.

EXAM> “How do you replace a word in the whole file in vi, with confirmation?” → :%s/old/new/gc (% all lines, g all matches per line, c confirm; answer y/n/a/q); mention ranges like :10,20s and :g/pattern/d.
Quick check What do %, g and c mean in :%s/a/b/gc?
Answer: % = every line, g = every match in a line, c = confirm each change.

Undo and safety net

If a big edit went wrong…

  • Right after it: u undoes the whole :s or :g in one step.
  • Several steps back: u repeatedly, or :earlier 2m (the file as it was 2 minutes ago).
  • Before a risky :s: add c to confirm, or try on a range first; :w file.bak saves a copy first.
  • A macro ran wild: stop with Ctrl+C, then u.
  • Saved and closed: only backups, git or snapshots help (Lesson 3.2).

Your ~/.vimrc

Settings typed after : last until you quit. Put them in ~/.vimrc to have them every time. A good starting file:

set number            " line numbers
set relativenumber    " distance to other lines (great with 5j, 3dd)
set ignorecase smartcase
set incsearch hlsearch
set expandtab tabstop=4 shiftwidth=4   " spaces, 4 wide (Python, YAML)
set autoindent
syntax on
filetype plugin indent on

Check that vim really reads it (real run)

vim -u ~/.vimrc -e -c 'redir! > /tmp/o.txt | set number? shiftwidth? expandtab? | redir END' -c 'q'
cat /tmp/o.txt
number shiftwidth=4 expandtab

One-liner corner

The same power commands in batch mode (vim -es), really run on our build machine; handy in scripts.

Beginner

Replace everywhere from the shell

Scenario: Change localhost in a config without opening vim.

vim -u NONE -N -i NONE -es -c '%s/localhost/db.internal/g' -c 'wq' h.conf && cat h.conf

The exact :%s from this lesson, run by a script.

Intermediate

Delete comment lines

Scenario: Strip comments before comparing.

vim -u NONE -N -i NONE -es -c 'g/^#/d' -c 'wq' c.conf && cat c.conf
a=1 b=2

:g/^#/d in batch mode.

Advanced

Sort unique, in place

Scenario: A list with duplicates.

vim -u NONE -N -i NONE -es -c 'sort u' -c 'wq' l.txt && cat l.txt
a b c

:sort u removes duplicates while sorting.

Script it: migrate-host.sh

Apply the same vim substitution to several config files, with a backup and a count of changed lines per file.

#!/bin/bash
old=localhost new=db.internal
printf 'db=localhost\n' > a.conf; printf 'web=localhost\ncache=localhost\n' > b.conf   # demo
for f in *.conf; do
  cp "$f" "$f.bak"
  n=$(grep -c "$old" "$f")
  vim -u NONE -N -i NONE -es -c "%s/$old/$new/ge" -c 'wq' "$f"
  echo "$f: $n line(s) changed"
done
cat a.conf b.conf
a.conf: 1 line(s) changed b.conf: 2 line(s) changed db=db.internal web=db.internal cache=db.internal

The e flag stops vim from failing on files without a match. In larger scripts, sed -i is the more common tool (Lesson 6.4).

Puzzle answer Remember the question from the story? Open to check your guess.

One “localhost” remains: without g, :s replaces only the first match on each line, giving db=db.internal,backup=localhost. Adding the g flag (:%s/localhost/db.internal/g) replaces every match on every line.
