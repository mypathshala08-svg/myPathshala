2 Definition

What nano is

Formal definition (write this in exams)

GNU nano is a small, modeless text editor for the terminal. Text is typed directly; commands are given with Ctrl and Alt (Meta) key combinations, the most important of which are listed in two shortcut lines at the bottom of the screen. It edits a copy of the file in memory and writes it to disk when you save.

In simple words

nano = Notepad in the terminal. Type to edit, Ctrl+O save, Ctrl+X exit.

nano at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: Notepad inside the terminal

nano is like Notepad, but inside the black terminal window.

  • You open a file, move with the arrow keys and type, exactly like Notepad.
  • There is no mouse menu, so the menu is printed at the bottom: ^O means hold Ctrl and press O.
  • Two keys are enough to start: Ctrl+O to save, Ctrl+X to exit.

Basic The keys you will use every day

  • nano file opens (or creates, on save) a file. Arrows, Home, End, PgUp, PgDn move.
  • Ctrl+O then Enter saves (“Write Out”); Ctrl+X exits, asking Y/N if there are unsaved changes.
  • Ctrl+K cuts the whole line, Ctrl+U pastes it (“uncut”). Several Ctrl+K in a row cut several lines.
  • Ctrl+W searches (“Where is”), Alt+W finds the next match. Ctrl+\ replaces.
  • Alt+U undo, Alt+E redo. Ctrl+G shows the help page.

Intermediate Selecting, line numbers and options

  • Alt+A starts a selection (mark), move the cursor, then Ctrl+K cuts it or Alt+6 copies it.
  • Ctrl+_ (or Alt+G) goes to a line number: perfect when an error says “line 42”. nano +42 file opens there.
  • Alt+# toggles line numbers; nano -l starts with them. -B keeps a backup file~; -v opens read-only.
  • Ctrl+R inserts another file; Ctrl+T runs a command and can insert its output.
  • Ctrl+S also saves in modern nano (no question); Ctrl+O lets you change the name first.

Advanced Behind the screen: buffers, sudoedit and settings

  • nano loads the file into memory (a buffer); nothing on disk changes until you write it out. The * in the title bar means the buffer differs from the file.
  • On save, nano rewrites the file in place (same inode, permissions kept). With -B it first copies the old version to file~.
  • sudo nano /etc/x runs the whole editor as root (root’s settings, risky). sudoedit /etc/x copies the file to a temp file, runs your editor as you, and copies it back as root: safer, and the preferred way.
  • Settings live in ~/.nanorc (e.g. set linenumbers, set tabsize 4, set autoindent); syntax colours come from /usr/share/nano/*.nanorc.
  • Programs such as crontab, git, sudoedit and visudo open the editor named in $VISUAL / $EDITOR; export EDITOR=nano in ~/.bashrc picks nano.

Did you know? nano started in 1999 as “TIP” (This Isn’t Pico), a free clone of the Pico editor, whose licence was not fully free. It was renamed nano (a pun: nano is 1000 times bigger than pico) and became the default editor on Ubuntu and Debian.

EXAM> “How do you edit a file in the terminal and save it?” → nano file, edit, Ctrl+O + Enter to save, Ctrl+X to exit (answer Y/N when asked); mention vi/vim as the alternative available everywhere, and sudoedit for system files.
Quick check What does the * after the file name in nano’s title bar mean?
Answer: The buffer has unsaved changes. After Ctrl+O it disappears.

Common mistake
✗sudo nano /etc/ssh/sshd_config
✓sudoedit /etc/ssh/sshd_config

sudo nano runs the whole editor as root with root’s settings; a plugin or a typo in a file name can do damage as root. sudoedit edits a temporary copy as you and writes it back with root rights.

Undo and safety net

If an edit went wrong…

  • Before saving: Ctrl+X and answer N: nothing on disk changed. Or Alt+U to undo step by step.
  • After saving: Alt+U still works while nano is open; then save again.
  • After closing: only a backup helps: file~ (nano -B), your cp file file.bak (Lesson 3.2), or git.
  • nano says the file is locked / being edited: another nano has it open (a .file.swp lock). Close the other one, or answer the question carefully.
  • Pressed Ctrl+Z: nano was suspended, not closed: type fg to return (Lesson 11.3).

Error messages decoded

The problems students see with nano. Messages were really produced on our build machine.

  1. nano --version | head -1
ls -l /etc/hostname | cut -c1-10
touch /etc/hostname
    GNU nano, version 7.2 -rw-r--r-- touch: cannot touch '/etc/hostname': Permission denied exit status: 1

    What it means: /etc files belong to root. nano opens them read-only for you and shows “[ File ’/etc/hostname’ is unwritable ]”; saving fails with “Permission denied”.

    Fix: Use sudoedit /etc/hostname (if you are allowed).

  2. mkdir -p cfg && touch cfg/a.conf && chmod -w cfg/a.conf && echo x >> cfg/a.conf
    /home/riya/script.sh: line 1: cfg/a.conf: Permission denied exit status: 1

    What it means: The file itself is write-protected; nano will say “Permission denied” when you save.

    Fix: Save under another name with Ctrl+O, or fix permissions (Lesson 9.2) if it is your file.

5 See it happen

Buffer, star and Write Out

Left: real nano screens (small terminal). Right: memory vs disk.

Memory and disk 5 steps
What you see
  1. nano opens the file and lists shortcuts.
  2. After typing, the title bar shows *: changed, not saved.
  3. Ctrl+O asks which file name to write.
  4. Enter writes it: “[ Wrote 3 lines ]” and the star disappears.
  5. Ctrl+X with unsaved changes always asks first.
Behind the screen
  1. The file is copied into nano’s memory (the buffer).
  2. Every key changes only the buffer.
  3. The disk still has the old content until you save.
  4. Write Out copies the buffer to the file.
  5. Answering N on exit discards the buffer; the disk is unchanged.

Terminals send keys as bytes.

One-liner corner

nano is interactive, so these one-liners prepare or check files around an edit. All really run on our build machine.

Beginner

Back up, then edit

Scenario: Always keep a copy before editing.

cp -v app.conf app.conf.bak   # then: nano app.conf
'app.conf' -> 'app.conf.bak'

A copy is the simplest undo (Lesson 3.2).

Beginner

Which editor will tools open?

Scenario: Check EDITOR and VISUAL.

echo "EDITOR=${EDITOR:-not set} VISUAL=${VISUAL:-not set}"
EDITOR=not set VISUAL=not set

Not set → tools fall back to a default (often nano on Ubuntu, vi elsewhere).

Intermediate

What did my edit change?

Scenario: Compare after editing.

diff app.conf.bak app.conf
1c1 < port=80 --- > port=8080

diff shows the changed line (Lesson 6.3).

Advanced

No editor at all in a script

Scenario: Change the port without opening an editor.

sed -i 's/^port=.*/port=8080/' app.conf && cat app.conf
port=8080 host=localhost user=admin

For automation never open an interactive editor; use sed (Lesson 6.4).

Script it: safe-edit.sh

A wrapper professionals use around manual edits: backup first, open the editor, then show what changed. (Here the “edit” is simulated with sed so the script can run unattended.)

#!/bin/bash
f=${1:-app.conf}
printf 'port=80\nhost=localhost\n' > "$f"          # demo file
cp -p "$f" "$f.bak"                                # 1. backup
${EDITOR_DEMO:-sed -i s/80/8080/} "$f"             # 2. real use: ${EDITOR:-nano} "$f"
if cmp -s "$f" "$f.bak"; then echo "no changes"; else echo "changes:"; diff "$f.bak" "$f" || true; fi
changes: 1c1 < port=80 --- > port=8080

In real life line 2 is ${EDITOR:-nano} "$f": it opens your editor and waits until you exit.

Puzzle answer Remember the question from the story? Open to check your guess.

Yes, it saved. In nano 7, Ctrl+S saves the file without asking for a name (older nano versions used Ctrl+S for nothing or for flow control). After Ctrl+S the * disappears from the title bar, so Ctrl+X exits at once. If nano still asks “Save modified buffer?”, the save did not happen (for example in an old nano, or if the terminal swallowed Ctrl+S): answer Y. Ctrl+O is the safe key on every version.
