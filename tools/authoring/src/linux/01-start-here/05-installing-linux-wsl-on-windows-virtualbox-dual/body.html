2 Definition

WSL, virtual machines and where Linux can run

Formal definition (write this in exams)

A virtual machine (VM) is a software emulation of a complete computer, with virtual CPUs, memory, disks and network, created and managed by a hypervisor (such as VirtualBox, VMware, Hyper-V or KVM) on a physical host. The Windows Subsystem for Linux (WSL) is a Windows feature that runs Linux distributions directly on Windows; WSL 2 does this by running a genuine Linux kernel inside a lightweight, Windows-managed virtual machine.

In simple words

A VM is a pretend computer running inside your real one. WSL is Microsoft’s ready-made, very light VM that gives you a real Ubuntu inside Windows with one command.

Getting Linux at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: five ways to try a new dish

Getting Linux is like trying a new dish. There are five ways, from “just taste it” to “build a second kitchen”.

  • Browser runner: taste Linux right now on this page. Nothing to install.
  • WSL: Linux cooks in a corner of your Windows kitchen. Recommended for this course.
  • Virtual machine: a toy kitchen inside your kitchen; break anything, nothing real is harmed.
  • Dual boot: a second kitchen. Powerful, but building it can damage the first one.
  • Cloud VM: rent a professional kitchen by the hour. Remember to hand back the keys (stop it).

Basic Five kinds of homes for Linux

  • Browser runner: a room in a hotel. Walk in, use it, leave. Nothing installed (every “Run the code” box on this site).
  • WSL: a guest room inside your own house (Windows). Linux lives next to Windows and shares the furniture (files).
  • Virtual machine: a doll’s house inside your house. A complete pretend computer; break anything, nothing outside is affected.
  • Dual boot: divide your plot into two houses. Each start-up you choose Windows or Linux. Most power, most risk.
  • Cloud VM: rent a flat in another city. A real server reachable over the internet; you pay rent while it runs.

Intermediate What each option needs

  • WSL: Windows 10 version 2004 (build 19041) or later, or Windows 11; one command wsl --install in an administrator PowerShell; a restart. Installs Ubuntu with WSL 2 by default.
  • VirtualBox: an ISO file (the installer image) of a distro, hardware virtualisation enabled in BIOS/UEFI (Intel VT-x / AMD-V), 2 GB+ RAM and 25 GB disk for the VM.
  • Dual boot: a USB stick, a full backup, free unpartitioned space, and care with the partitioning screen. Turn off Windows Fast Startup.
  • Cloud VM: an account with a cloud provider, an SSH key pair, and a firewall rule (security group) allowing SSH only from your IP. Stop or delete the VM when done.
  • Always verify the ISO: compare its SHA-256 checksum with the one on the distro’s website (Lesson 19.4).

Advanced How WSL 2 really works, and its traps

  • WSL 2 runs a real Linux kernel (built by Microsoft) inside a lightweight utility virtual machine using Hyper-V technology. It starts in about a second and shares memory with Windows dynamically.
  • Each distro’s files live in a virtual disk (ext4.vhdx). Windows drives appear in Linux under /mnt/c, /mnt/d; Linux files appear in Windows Explorer under \\wsl.localhost\Ubuntu.
  • Performance trap: Linux tools working on files under /mnt/c cross the VM boundary and are much slower. Keep projects in your Linux home (~/projects).
  • WSL supports systemd (enable it in /etc/wsl.conf under [boot] if your distro has not), so services like Docker and databases work as on a server.
  • wsl --shutdown stops the VM; wsl -l -v lists distros and their WSL version; wsl --set-version Ubuntu 2 converts an old WSL 1 install.

Did you know? The Linux kernel used by WSL 2 is built and maintained by Microsoft, and its source code is published as open source, as the GPL requires (Lesson 1.4). A company famous for Windows now ships a Linux kernel with it.

4 Step by step

Install Ubuntu with WSL on Windows

About 15 minutes, most of it downloading. Follow along on your own laptop.

  1. 1. Open PowerShell as administrator

    Start menu → type PowerShell → right-click → Run as administrator.

    Behind the screen: enabling Windows features needs admin rights, just like sudo on Linux.

  2. 2. Run the install command

    wsl --install

    Behind the screen: Windows enables the “Virtual Machine Platform” and WSL features, downloads the WSL Linux kernel and the Ubuntu image. If you only see help text, WSL is already installed: run wsl --install -d Ubuntu.

  3. 3. Restart the computer

    Required once, so the new Windows features load.

    Behind the screen: the hypervisor component starts during boot.

  4. 4. Create your Linux user

    Ubuntu opens and asks for a new UNIX username and password. Use lower case and no spaces, for example riya.

    Behind the screen: this creates a normal Linux user (not root) and gives it sudo rights. While you type the password nothing appears, not even stars. That is normal on Linux.

  5. 5. Update the system

    sudo apt update && sudo apt upgrade -y

    Behind the screen: apt downloads the latest package lists and installs security updates (Module 14).

  6. 6. Check everything works

    whoami, pwd, cat /etc/os-release, and in PowerShell wsl -l -v should show VERSION 2.

    Behind the screen: VERSION 2 means a real Linux kernel. Version 1 is the older translation layer.

  7. 7. Work in your Linux home

    mkdir ~/projects; open the folder from Windows with explorer.exe . or in VS Code with code .

    Behind the screen: files under ~ are inside the Linux virtual disk: fast for Linux tools. /mnt/c is your C: drive, slower from Linux.

Choosing dual boot? Back up everything first, read the installer screens slowly, never choose “Erase disk” unless you mean it, and turn off Windows Fast Startup and BitLocker prompts as the distro’s guide explains.

Option B: Ubuntu in VirtualBox, step by step

Use this when you want a full Ubuntu desktop, snapshots you can roll back to, or you are on a computer where WSL is not allowed.

  1. 1. Download VirtualBox and an Ubuntu ISO

    VirtualBox from virtualbox.org for your OS; the Ubuntu Desktop LTS ISO from ubuntu.com. Verify the ISO with sha256sum (Windows: certutil -hashfile file.iso SHA256).

    Behind the screen: the checksum proves the ISO was not corrupted or tampered with (Lesson 19.4).

  2. 2. Make sure virtualisation is on

    If VirtualBox complains about VT-x/AMD-V, enable “Intel Virtualization Technology” or “SVM” in your BIOS/UEFI settings.

    Behind the screen: these CPU features let the guest run at near-native speed.

  3. 3. Create the VM

    New → name ubuntu-lab → choose the ISO → type Linux, Ubuntu (64-bit) → 4 GB RAM, 2 CPUs → a 25 GB dynamically allocated disk.

    Behind the screen: the VM’s disk is one file (.vdi) on your Windows drive; “dynamically allocated” means it grows only as Ubuntu uses space.

  4. 4. Install Ubuntu inside the VM

    Start the VM, choose Install Ubuntu, keyboard, then “Erase disk and install Ubuntu”, user name and password.

    Behind the screen: “Erase disk” here erases only the virtual disk file, never your real one. Inside a VM it is safe.

  5. 5. Add Guest Additions

    Devices → Insert Guest Additions CD image → run it → restart. Now the screen resizes, copy-paste works and shared folders are possible.

    Behind the screen: Guest Additions are drivers inside Ubuntu that talk to VirtualBox.

  6. 6. Take a snapshot

    Machine → Take Snapshot → “fresh install”. Before any risky experiment, take another.

    Behind the screen: a snapshot freezes the disk state; restoring it takes seconds.

5 See it happen

What wsl --install really builds

Left: what Riya sees in PowerShell and Ubuntu (messages are typical; wording varies by version). Right: the layers WSL creates.

From Windows to Ubuntu in one command 5 steps
What you see
  1. In an administrator PowerShell Riya types wsl --install.
  2. Windows installs the needed components and Ubuntu. (Messages shown are typical; exact wording varies by Windows version.)
  3. Windows asks for a restart to activate the new features.
  4. Ubuntu opens for the first time and asks for a new username and password. The password does not show while typing.
  5. Now whoami and /etc/os-release prove she is inside Ubuntu.
Behind the screen
  1. Changing Windows features needs administrator rights.
  2. WSL 2 adds a lightweight virtual machine, a Linux kernel built by Microsoft, and a distribution image (Ubuntu by default).
  3. The hypervisor layer starts with Windows after the reboot.
  4. Ubuntu’s whole file system lives in a virtual disk file. Your Linux user is created inside it and added to the sudo group.
  5. From now on, commands like ls run on a genuine Linux kernel. Windows files remain where they were, reachable at /mnt/c.

Real-time scenario 1

The invisible password

Almost every beginner thinks their keyboard stopped working the first time Linux asks for a password. Watch what really happens.

Typing a password on Linux 5 steps
Animated example
  1. Riya runs sudo apt update. sudo asks for her own password.
  2. She types, and nothing appears on the screen. She thinks something is broken.
  3. It is a security feature: the terminal does not echo the characters at all, so someone watching cannot see how long the password is.

Sharing files between Windows and WSL 5 steps
Animated example
  1. Windows has its folders; Ubuntu in WSL has its own Linux file system.
  2. Inside Ubuntu, the C: drive is mounted at /mnt/c, so cd /mnt/c/Users/Riya/Documents reaches Windows files.

Real-time scenario 3 · advanced

A cloud VM in ten minutes, and the bill that followed

Cloud servers are the best practice for SSH and administration, and a classic source of surprise bills and open doors. IP address and amounts are examples.

Using a cloud VM safely 5 steps
Animated example
  1. Riya creates a small Ubuntu VM and a firewall rule that allows SSH (port 22) only from her own IP address.
  2. She logs in with ssh -i key ubuntu@<ip>. Now she has a real internet-facing Linux server (Lesson 16.6 explains SSH keys).
  3. She forgets to stop it. Cloud VMs are billed by the hour (or second) while running, so a month of idling costs money.
  4. Habits: stop or delete VMs after practice, and set a budget alert on the account from day one.
  5. Security matters too: any server open to the internet receives automated login attempts within minutes. Keys and narrow firewall rules keep them out.

Layer by layer: dissect Ubuntu inside Windows (WSL 2)

What actually runs when you open “Ubuntu” from the Windows Start menu? Six layers, from the app you click down to the hardware. The commands shown ran on our Ubuntu build machine, which is not WSL; on WSL you will see the WSL values mentioned.

Top = what you touch · bottom = the hardware. Click a layer.

Windows Terminal the window you click

Why does it exist?

You need a window to type in. Windows provides it, as for any other app.

How does it work?

It starts wsl.exe and shows its text.

Where is it, really?

A normal Windows app; profiles for Ubuntu, PowerShell and cmd.

Where is it used?

Every WSL session; VS Code also opens WSL terminals.

wsl.exe the doorway

Why does it exist?

Something must connect Windows to the Linux side and start it if it is not running.

How does it work?

It asks the WSL service to start the utility VM and the Ubuntu distro, then attaches your window to a Linux shell.

Where is it, really?

C:\Windows\System32\wsl.exe; commands such as wsl -l -v and wsl --shutdown.

Where is it used?

Managing distros: install, list, stop, set defaults.

Utility VM lightweight virtual machine

Why does it exist?

The Linux kernel cannot run directly on the Windows kernel. A tiny VM gives it a computer of its own.

How does it work?

Built on Hyper-V technology; starts in about a second and borrows memory from Windows as needed.

Where is it, really?

Managed by Windows; you never configure it by hand (optional settings in .wslconfig).

Where is it used?

Also used by Docker Desktop on Windows.

WSL Linux kernel built by Microsoft

Why does it exist?

Ubuntu’s programs need a real Linux kernel for system calls.

How does it work?

A genuine Linux kernel, kept up to date through Windows Update; its version string contains “microsoft”.

Where is it, really?

Shipped with WSL; source published as open source.

Ubuntu’s files a virtual disk

Why does it exist?

Linux needs its own file system (ext4) with Linux permissions.

How does it work?

Ubuntu’s whole tree lives in one virtual disk file; Windows drives are mounted inside it at /mnt/c.

Where is it, really?

A file named ext4.vhdx in your Windows user’s AppData folder.

Where is it used?

Keep projects inside it (~/projects) for speed.

Why does it exist?

This is where you finally type commands.

How does it work?

bash runs as the user you created on first start, with sudo rights.

Where is it, really?

/usr/bin/bash inside Ubuntu; your home is /home/<you>.

6 Real-world use

How professionals get their Linux

1. Developers on Windows laptops

Many companies issue Windows laptops; developers install WSL, keep code in the Linux home and use VS Code’s WSL mode, so their tools match the Linux servers.

Windows laptop→WSL Ubuntu→Same tools as servers

2. Training and testing in VMs

Trainers and testers use VMs with snapshots: take a snapshot, try something risky, roll back in seconds. Perfect for learning administration.

Snapshot→experiment→Restore

3. Cloud servers for real projects

Production systems run on cloud VMs or on servers in data centres. Engineers reach them only over SSH; nobody installs them by clicking through an ISO.

Image→cloud VM→SSH

4. Containers for quick environments

With Docker, docker run -it ubuntu bash starts a throw-away Ubuntu environment in seconds. Common for testing scripts on several distros.

docker run→Linux container→Test script

5. Live USB for rescue

Admins carry a bootable Linux USB to rescue machines that will not start: copy files off, fix boot problems, test hardware.

Broken PC→Live USB Linux→Files rescued

Examples are simplified and generic. They describe common patterns, not the internal systems of any particular company.

One-liner corner

Checks to run right after installing Linux. All were really run on an Ubuntu 24.04 cloud VM; on WSL some answers will differ.

Beginner

Am I really inside Linux, and as whom?

Scenario: You opened Ubuntu for the first time and want to confirm the setup.

echo "$(whoami) on $(grep PRETTY_NAME /etc/os-release | cut -d'"' -f2)"
riya on Ubuntu 24.04.5 LTS

whoami prints your user; the grep and cut pick the distro name out of /etc/os-release.

Beginner

Is this WSL?

Scenario: A script should behave differently on WSL and on a real server.

grep -qi microsoft /proc/version && echo "running on WSL" || echo "not WSL"
not WSL

The WSL kernel’s version string contains “microsoft”. grep -q prints nothing and only sets the exit status, which && and || use.

Intermediate

Do I have enough room for the course?

Scenario: Before installing big tools (Docker, Hadoop) you want free disk and RAM in one line.

echo "disk free: $(df -h ~ | awk 'NR==2 {print $4}'), RAM: $(free -h | awk '/^Mem/ {print $2}')"
disk free: 30G, RAM: 7.8Gi

df -h ~ reports the disk holding your home; awk 'NR==2' takes its second line, column 4 (Avail). free -h line Mem, column 2 (total).

Advanced

What kind of machine is this?

Scenario: Support asks whether you are on a VM, a container, WSL or real hardware.

systemd-detect-virt
docker

Prints the virtualisation technology detected: none on real hardware, wsl, kvm, oracle (VirtualBox), docker… This answer came from the container used to build this lesson.

Intermediate

Build it step by step: a one-line “is this machine ready?” report

Scenario: Before installing Docker or Hadoop later in the course, check cores, RAM and free disk in one line.

  1. CPU cores.

    nproc
    2

  2. Total RAM in MB: the Mem line, column 2.

    free -m | awk '/^Mem/ {print $2}'
    8022

  3. Free disk space in GB on the disk holding your home.

    df -BG ~ | awk 'NR==2 {print $4}'
    30G

  4. Combine into a verdict. Both tests must pass for READY.

    c=$(nproc); r=$(free -m | awk '/^Mem/ {print $2}'); d=$(df -BG ~ | awk 'NR==2 {print $4}'); [ $c -ge 2 ] && [ $r -ge 4096 ] && s=READY || s='NOT READY'; echo "cores=$c ram=${r}MB disk_free=$d -> $s"
    cores=2 ram=8022MB disk_free=30G -> READY
