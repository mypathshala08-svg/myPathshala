1 The story

“Bombay, BANGALORE and navi mumbai are all wrong”

Before you start: built-in functions (4.1), explode and LATERAL VIEW (4.2), vectorisation (8.4). Basic Java helps.

TiffinGo has signed a new restaurant partner. Its feed spells cities any way it likes: old names, capitals, extra spaces. Kabir already has a 40-line CASE expression copied into six reports, and every copy is slightly different.

K> Sir, can Hive call my own code instead of this CASE monster? A> Yes. Hive lets you add user-defined functions written in Java. A UDF maps one row to one value, a UDAF aggregates many rows into one value like SUM, and a UDTF turns one row into many rows like explode. You compile them into a JAR and register them with CREATE FUNCTION. R> Do we need a Hadoop cluster to build them? A> Only a JDK and two JAR files from Hive. Today we write all three kinds for TiffinGo, register them temporarily and permanently, look at where Hive stores them, hit two real errors, and measure what a UDF costs compared with built-in functions. All outputs are real, from Hive 4.2.1; the Java sources are in the course lab folder.
2 Definition

User-defined functions in Hive

Formal definition (write this in exams)

A user-defined function extends HiveQL with logic implemented in Java (or another JVM language) and loaded from a JAR. Hive distinguishes three kinds by how many rows go in and come out: a UDF (scalar, one row to one value; modern ones extend GenericUDF), a UDAF (aggregate, many rows to one value per group; implemented as a resolver and a GenericUDAFEvaluator that supports partial aggregation), and a UDTF (table-generating, one row to zero or more rows; extends GenericUDTF). Functions are registered per session with CREATE TEMPORARY FUNCTION or permanently in the metastore with CREATE FUNCTION db.name AS 'class' USING JAR 'uri'.

In simple words

A UDF is your own function that Hive can call. You write it in Java, put it in a JAR file, and register it with a name. Then you use it in queries like any built-in function.

LEVELS> User-defined functions at three levels L1> Teaching Hive a new word
  • Hive has hundreds of built-in functions: upper, sum, explode. A UDF is one you add yourself.
  • You write the rule once in Java, package it as a JAR, and tell Hive its name.
  • After that, SELECT normalize_city(city) FROM … works like any built-in function.
L2> Three kinds and how they are registered
  • UDF (one row → one value): extend GenericUDF; implement initialize (check arguments, declare the return type), evaluate, getDisplayString.
  • UDAF (many rows → one value): a resolver plus a GenericUDAFEvaluator with iterate, terminatePartial, merge, terminate.
  • UDTF (one row → many rows): extend GenericUDTF; process calls forward for each output row.
  • CREATE TEMPORARY FUNCTION lasts for one session; CREATE FUNCTION … USING JAR is stored in the metastore for everyone.
L3> What the lab showed
  • The temporary function was gone in the next session (Error 10011: Invalid function); permanent functions appeared as rows in the metastore’s FUNCS and FUNC_RU tables, qualified by database.
  • Hive 4.2.1 called the older initialize(ObjectInspector[]) of our UDTF: “Should not be called directly” until we implemented it.
  • SHOW FUNCTIONS LIKE takes SQL wildcards (%) in Hive 4; the * pattern from older tutorials returned nothing. The UDF ran through VectorUDFAdaptor: about 3.2 s vs 2.8 s for built-ins.
/LEVELS EXAM> “Difference between UDF, UDAF and UDTF?” UDF: one row in, one value out (GenericUDF). UDAF: many rows in, one value out, with partial aggregation (iterate, terminatePartial, merge, terminate). UDTF: one row in, many rows out (GenericUDTF, forward), used with LATERAL VIEW. Register with ADD JAR + CREATE TEMPORARY FUNCTION, or CREATE FUNCTION … USING JAR for a permanent one.

4 Step by step

Three functions for TiffinGo, from Java to SQL

All outputs are real, from Hive 4.2.1. Java was compiled with JDK 21 (--release 17) against hive-exec-4.2.1.jar and hadoop-common-3.4.1.jar.

  1. Step 1 · A GenericUDF: normalize_city

    @Description(name = "normalize_city",
    value = "_FUNC_(str) - trims, title-cases and maps old city names (Bombay -> Mumbai)",
    extended = "Example: SELECT _FUNC_('  bombay ') returns 'Mumbai'")
public class NormalizeCity extends GenericUDF {
  private static final Map<String, String> OLD = Map.of(
      "bombay", "Mumbai", "bangalore", "Bengaluru", "madras", "Chennai",
      "calcutta", "Kolkata", "poona", "Pune", "gurgaon", "Gurugram");
  private PrimitiveObjectInspector in;

  @Override
  public ObjectInspector initialize(ObjectInspector[] args) throws UDFArgumentException {
    if (args.length != 1 || args[0].getCategory() != ObjectInspector.Category.PRIMITIVE)
      throw new UDFArgumentException("normalize_city takes exactly one string argument");
    in = (PrimitiveObjectInspector) args[0];
    return PrimitiveObjectInspectorFactory.javaStringObjectInspector;
  }

  @Override
  public Object evaluate(DeferredObject[] args) throws HiveException {
    Object v = args[0].get();
    if (v == null) return null;
    String s = PrimitiveObjectInspectorUtils.getString(v, in).trim().replaceAll("\\s+", " ");
    if (s.isEmpty()) return null;
    String mapped = OLD.get(s.toLowerCase());
    if (mapped != null) return mapped;
    StringBuilder b = new StringBuilder();
    for (String w : s.toLowerCase().split(" "))
      b.append(b.length() > 0 ? " " : "").append(Character.toUpperCase(w.charAt(0))).append(w.substring(1));
    return b.toString();
  }

  @Override
  public String getDisplayString(String[] children) {
    return "normalize_city(" + children[0] + ")";
  }
}
    initialize runs once, at compile time: it checks the arguments and returns the ObjectInspector of the result (a Java String). evaluate runs for every row: NULL in, NULL out; trim and squeeze spaces; map old names; otherwise title-case. @Description provides the help text for DESCRIBE FUNCTION.

  5. Step 5 · A UDAF: spread = max − min

      public static class Eval extends GenericUDAFEvaluator {
    private PrimitiveObjectInspector inputOI;          // PARTIAL1, COMPLETE
    private StructObjectInspector partialOI;           // PARTIAL2, FINAL
    private StructField minF, maxF;

    static class Buf extends AbstractAggregationBuffer { double min, max; boolean empty = true; }

    @Override
    public ObjectInspector init(Mode m, ObjectInspector[] p) throws HiveException {
      super.init(m, p);
      if (m == Mode.PARTIAL1 || m == Mode.COMPLETE) inputOI = (PrimitiveObjectInspector) p[0];
      else { partialOI = (StructObjectInspector) p[0]; minF = partialOI.getStructFieldRef("min"); maxF = partialOI.getStructFieldRef("max"); }
      if (m == Mode.PARTIAL1 || m == Mode.PARTIAL2)
        return ObjectInspectorFactory.getStandardStructObjectInspector(Arrays.asList("min", "max"),
            Arrays.asList((ObjectInspector) PrimitiveObjectInspectorFactory.writableDoubleObjectInspector,
                          PrimitiveObjectInspectorFactory.writableDoubleObjectInspector));
      return PrimitiveObjectInspectorFactory.writableDoubleObjectInspector;
    }

    @Override public AggregationBuffer getNewAggregationBuffer() { return new Buf(); }
    @Override public void reset(AggregationBuffer b) { ((Buf) b).empty = true; }

    private void add(Buf b, double lo, double hi) {
      if (b.empty) { b.min = lo; b.max = hi; b.empty = false; }
      else { b.min = Math.min(b.min, lo); b.max = Math.max(b.max, hi); }
    }

    @Override public void iterate(AggregationBuffer b, Object[] p) {
      if (p[0] == null) return;
      double v = PrimitiveObjectInspectorUtils.getDouble(p[0], inputOI);
      add((Buf) b, v, v);
    }

    @Override public Object terminatePartial(AggregationBuffer ab) {
      Buf b = (Buf) ab;
      if (b.empty) return null;
      return new Object[] { new DoubleWritable(b.min), new DoubleWritable(b.max) };
    }

    @Override public void merge(AggregationBuffer b, Object partial) {
      if (partial == null) return;
      double lo = ((DoubleWritable) partialOI.getStructFieldData(partial, minF)).get();
      double hi = ((DoubleWritable) partialOI.getStructFieldData(partial, maxF)).get();
      add((Buf) b, lo, hi);
    }

    @Override public Object terminate(AggregationBuffer ab) {
      Buf b = (Buf) ab;
      return b.empty ? null : new DoubleWritable(b.max - b.min);
    }
  }
    Aggregates run in two phases. On the map side (PARTIAL1) iterate sees raw values and terminatePartial emits a small struct (min, max). On the reducer (FINAL) merge combines the structs and terminate returns max − min. That is why init returns a struct inspector in partial modes and a double in final modes.

  7. Step 7 · A UDTF: split_items, and a real Hive 4 surprise

      @Override
  public StructObjectInspector initialize(StructObjectInspector argOIs) throws UDFArgumentException {
    List<? extends StructField> f = argOIs.getAllStructFieldRefs();
    ObjectInspector[] args = new ObjectInspector[f.size()];
    for (int i = 0; i < args.length; i++) args[i] = f.get(i).getFieldObjectInspector();
    return initialize(args);
  }

  @Override   // some Hive 4 code paths call this older entry point directly
  public StructObjectInspector initialize(ObjectInspector[] args) throws UDFArgumentException {
    if (args.length != 1) throw new UDFArgumentException("split_items takes exactly one argument");
    in = (PrimitiveObjectInspector) args[0];
    List<String> names = new ArrayList<>(List.of("item", "qty"));
    List<ObjectInspector> ois = new ArrayList<>(List.of(
        PrimitiveObjectInspectorFactory.javaStringObjectInspector,
        PrimitiveObjectInspectorFactory.javaIntObjectInspector));
    return ObjectInspectorFactory.getStandardStructObjectInspector(names, ois);
  }

  @Override
  public void process(Object[] args) throws HiveException {
    if (args[0] == null) return;
    String s = PrimitiveObjectInspectorUtils.getString(args[0], in);
    for (String part : s.split(",")) {
      String[] kv = part.trim().split(":");
      if (kv.length != 2 || kv[0].isEmpty()) continue;          // skip malformed entries
      out[0] = kv[0].trim();
      try { out[1] = Integer.parseInt(kv[1].trim()); } catch (NumberFormatException e) { out[1] = null; }
      forward(out);
    }
  }
    Our first version implemented only initialize(StructObjectInspector), as most tutorials show. Hive 4.2.1 failed at compile time with IllegalStateException Should not be called directly: some code paths call the older initialize(ObjectInspector[]). Implementing both (the new one delegating to the old one) fixed it. process calls forward once per output row; malformed entries are skipped and a bad quantity becomes NULL.

6 Real-world use

UDFs at work

1. Data standardisation

City, phone, and address normalisation rules live in one tested UDF instead of copies of CASE expressions in every job.

Raw feed→UDF→Clean column

2. Masking and tokenisation

Security teams provide UDFs that tokenise or mask personal data with a company key before analysts see it.

PII→mask UDF→Safe data

3. Parsing custom formats

UDTFs split proprietary strings (item lists, event payloads) into rows that SQL can aggregate.

Packed string→UDTF→Rows

4. Custom aggregates

Approximate distinct counts with sketches, weighted medians or domain scores are added as UDAFs.

Groups→UDAF→Metric

5. Reusing Java libraries

Geospatial, ML-scoring or encryption libraries are wrapped as UDFs so SQL users can call them directly.

Java library→wrapper→SQL function
