2 Definition

Production readiness review and interview preparation

Formal definition (write this in exams)

A production readiness review of a data pipeline checks, with measurements, that it is correct (tests and reconciliation), reliable (idempotent, observable, recoverable), efficient (file sizes, compaction, statistics, pruning) and maintainable (documented design, naming, ownership) before it is relied upon. Interview preparation for a data engineering role turns that knowledge into concise, evidence-based answers: definitions, trade-offs and examples from one’s own project.

In simple words

Measure the warehouse, fix what will hurt later, add automatic tests. Then practise explaining Hive using your own project’s numbers.

  4. Step 4 · Turn the reconciliation into automated tests

    -- TiffinGo data tests: run after every load. Any FAIL should alert the on-call engineer.
-- One small INSERT per test (a single six-way UNION ALL hits Tez's 120-counter limit, Lesson 12.2).
USE tiffingo_dw;
CREATE TABLE IF NOT EXISTS dq_results (test STRING, passed BOOLEAN, detail STRING, run_ts TIMESTAMP) STORED AS ORC;
TRUNCATE TABLE dq_results;
INSERT INTO dq_results SELECT 'fact key unique', COUNT(*) = COUNT(DISTINCT order_id),
  CONCAT(COUNT(*), ' rows / ', COUNT(DISTINCT order_id), ' ids'), CURRENT_TIMESTAMP FROM fact_orders;
INSERT INTO dq_results SELECT 'gold net = fact net', g.v = f.v, CONCAT(g.v, ' vs ', f.v), CURRENT_TIMESTAMP
  FROM (SELECT SUM(net_revenue) AS v FROM gold_city_daily) g
  CROSS JOIN (SELECT SUM(amount) AS v FROM fact_orders WHERE status = 'DELIVERED') f;

  CONCAT(SUM(IF(c <> 1, 1, 0)), ' violations'), CURRENT_TIMESTAMP
  FROM (SELECT customer_id, SUM(IF(is_current, 1, 0)) AS c FROM dim_customer GROUP BY customer_id) x;

  FROM dim_customer WHERE valid_to < valid_from;

  FROM fact_orders f LEFT JOIN dim_restaurant r ON r.restaurant_id = f.restaurant_id WHERE r.restaurant_id IS NULL;

  SUM(IF(step = 'rejected', row_count, 0)) / SUM(IF(step = 'raw_rows', row_count, 0)) < 0.01,
  CONCAT(ROUND(100 * SUM(IF(step = 'rejected', row_count, 0)) / SUM(IF(step = 'raw_rows', row_count, 0)), 2), '%'),
  CURRENT_TIMESTAMP FROM etl_audit;

  CONCAT(COUNT(DISTINCT order_date), ' of 31 days'), CURRENT_TIMESTAMP FROM gold_city_daily
  WHERE order_date BETWEEN DATE '2026-10-01' AND DATE '2026-10-31';

  5. Step 5 · A materialized view the optimiser uses

    CREATE MATERIALIZED VIEW mv_city_status AS
SELECT r.city, f.status, COUNT(*) AS n, SUM(f.amount) AS amt
FROM fact_orders f JOIN dim_restaurant r ON r.restaurant_id = f.restaurant_id
GROUP BY r.city, f.status;

CREATE MATERIALIZED VIEW mv_status_day AS
SELECT order_date, status, COUNT(*) AS n, SUM(amount) AS amt
FROM fact_orders GROUP BY order_date, status;

-- a normal query on the fact table
EXPLAIN CBO SELECT status, SUM(amount) AS amt FROM fact_orders
WHERE order_date >= DATE '2026-10-15' GROUP BY status;

    The first view was refused: automatic rewriting needs transactional source tables so Hive can tell whether the view is up to date, and dim_restaurant is plain ORC. The second view uses only the ACID fact. The query was written against fact_orders, yet the plan scans mv_status_day: 92 pre-aggregated rows (date × status) instead of 47,553 orders. Users do not need to know the view exists.

    After the load wrote to fact_orders, the view was stale and Hive correctly went back to scanning the fact: a materialized view never returns outdated results unless you allow it with a rewriting time window. After REBUILD the plan used the view again. So the nightly script needs one more step: rebuild the views after the MERGE.

Interview question bank: 50 questions with short answers

Grouped by topic, written from the questions most often listed on popular interview-preparation sites and from real interview rounds, and linked to the lesson that explains each one in depth. Answer aloud first, then open the answer.

Architecture and basics

1. What is Apache Hive and when would you use it?

A data warehouse system on Hadoop-compatible storage that lets you query and manage large datasets with SQL (HiveQL). Use it for batch ETL and analytics over large files; not for low-latency single-row lookups or OLTP. 1.2

2. Can Hive be used for OLTP?

No. Queries start distributed jobs with seconds of latency, and although Hive ACID supports INSERT, UPDATE, DELETE and MERGE, it is designed for batches of changes, not thousands of small transactions per second. 7.1

3. What does schema on read mean?

The table’s schema is applied when data is read, not checked when files are written. A file with a bad value loads fine and the value becomes NULL at query time, which is why our raw tables were all STRING. 2.4

4. What are the main components of Hive?

Clients (Beeline, JDBC/ODBC), HiveServer2, the Driver with compiler, optimiser and executor, the Metastore (service + relational database), and the execution engine (Tez by default) running on YARN over HDFS or object storage. 1.3

5. Describe how a query is executed.

Client sends the query; the driver asks the compiler for a plan; the compiler gets table metadata from the metastore; the optimiser (CBO) improves the plan; the executor submits a Tez DAG to YARN; results are fetched back through HiveServer2. 1.4

6. What is the metastore, and why is it not stored in HDFS?

It stores databases, tables, columns, partitions, locations and statistics. It needs fast random reads and updates and transactions, which a relational database (Derby, MySQL, PostgreSQL, Oracle) provides and HDFS files do not. 10.1

7. Embedded, local and remote metastore?

Embedded: Derby in the same JVM, one user, for testing. Local: the metastore code runs inside HiveServer2 but uses an external database. Remote: a separate metastore service on Thrift (port 9083) shared by Hive, Spark, Trino and others, the production choice.

8. What is HCatalog?

A table and storage management layer on top of the metastore that lets Pig, MapReduce and other tools read and write Hive tables without knowing file formats; WebHCat is its REST interface.

Tables, formats and loading

9. Managed versus external tables?

Hive owns managed table data: DROP deletes the files. External tables only point to a location: DROP removes metadata only. In Hive 4, non-ACID “managed” tables are translated to external tables with external.table.purge=true, as we saw in Lesson 12.2. 2.2

10. Can you change where a managed table is stored?

Yes: with LOCATION in CREATE TABLE, with ALTER TABLE … SET LOCATION, or globally with hive.metastore.warehouse.dir.

11. What is a SerDe? What is an ObjectInspector?

A SerDe (serializer/deserializer) converts between file bytes and Hive rows (LazySimpleSerDe, JsonSerDe, OrcSerde, RegexSerDe). An ObjectInspector describes the structure of a row object so Hive can read its fields without knowing its Java class.

12. Which classes read and write a text table?

org.apache.hadoop.mapred.TextInputFormat reads records; org.apache.hadoop.hive.ql.io.HiveIgnoreKeyTextOutputFormat writes them; the SerDe (LazySimpleSerDe) splits and joins fields.

13. ORC versus Parquet?

Both columnar, compressed, with min/max statistics for skipping. ORC is Hive’s native format and required for Hive ACID tables; Parquet is the most widely shared format across Spark, Trino and cloud warehouses. 6.2

14. What are Hive’s complex types?

ARRAY, MAP, STRUCT and UNIONTYPE; query them with index, key or dot syntax and flatten them with explode and LATERAL VIEW. 4.2

15. What does LOAD DATA do?

It moves (INPATH) or copies (LOCAL INPATH) files into the table’s folder without parsing them; Hive does not validate the content. 2.5

16. What is a .hiverc file?

A script of settings (SET …, ADD JAR …) that the old Hive CLI ran at start-up from the user’s home folder. With Beeline, pass an initialisation file with -i init.hql instead.

17. How do you skip a CSV header?

TBLPROPERTIES ('skip.header.line.count'='1'), as on our raw tables.

Querying

18. ORDER BY, SORT BY, DISTRIBUTE BY, CLUSTER BY?

ORDER BY: total order, one reducer. SORT BY: sorted within each reducer. DISTRIBUTE BY: chooses which reducer gets each row. CLUSTER BY x = DISTRIBUTE BY x SORT BY x. 3.4

19. Which joins does Hive support?

INNER, LEFT, RIGHT, FULL OUTER, CROSS and LEFT SEMI JOIN (rows of the left table with a match, like EXISTS), plus anti joins in newer versions. 3.3

20. What is a map join?

The small table is loaded into memory on every task and joined without a shuffle; Hive converts joins automatically when the small side is below hive.auto.convert.join.noconditionaltask.size. 8.3

21. How does Hive handle skewed joins?

With hive.optimize.skewjoin, keys above a row threshold are processed in a separate map join; you can also salt hot keys or declare skewed values on the table.

22. How do you remove duplicates but keep the newest row?

ROW_NUMBER() OVER (PARTITION BY key ORDER BY updated_at DESC) and keep rn = 1, as in our MERGE source. DISTINCT keeps both versions of a changed row. 3.6

23. How does Hive treat NULLs?

Comparisons with NULL are NULL (not true), so use IS NULL, COALESCE or NVL; a failed CAST returns NULL; in text files \N means NULL by default.

24. How do you list databases starting with c, or check a partition exists?

SHOW DATABASES LIKE 'c*'; and SHOW PARTITIONS t PARTITION (dt='2026-10-05');

25. How do you pass variables to a script?

beeline --hivevar load_date=2026-10-05 -f daily_load.hql and ${hivevar:load_date} in the script; --hiveconf sets configuration values. Hive CLI and Beeline also run single statements with -e.

Partitioning and bucketing

26. What is partitioning and why use it?

Splitting a table into folders by column values (dt=…). Queries that filter on the partition column read only matching folders (pruning), as EXPLAIN DEPENDENCY showed: 2 of 31 partitions. 5.1

27. Static versus dynamic partitions?

Static: you name the partition value in the INSERT. Dynamic: Hive takes it from the last SELECT column; needs hive.exec.dynamic.partition.mode=nonstrict when no static part is given. 5.2

28. How are rows assigned to buckets?

hash(bucketing column) mod number of buckets. Bucketing helps sampling, bucket map joins and sort-merge-bucket joins. 5.3

29. What is the small files problem and how do you fix it?

Many tiny files mean more metastore and NameNode load and more tasks. Fix: coarser partitions, hive.merge.* settings, CONCATENATE for ORC, compaction for ACID, or a table format such as Iceberg with compaction. 5.4

30. When do you need MSCK REPAIR TABLE?

When partition folders were created outside Hive; it adds missing partitions to the metastore (SYNC PARTITIONS also drops missing ones). Our raw tables used it once, then ALTER TABLE ADD IF NOT EXISTS PARTITION each night.

Performance and optimisation

31. How do you find out why a query is slow?

EXPLAIN (or EXPLAIN ANALYZE / FORMATTED / CBO), the Tez UI or HiveServer2 web UI, and the logs: look for missing partition filters, a shuffle of a big table, skew in one task, small files or missing statistics. 8.5

32. What does the cost-based optimiser need?

Table and column statistics (ANALYZE TABLE … COMPUTE STATISTICS FOR COLUMNS) to choose join order and join type. 8.2

33. What is vectorisation?

Processing a batch of rows (default 1,024) per operator call using column vectors, which cuts per-row overhead; works best with ORC. 8.4

34. MapReduce, Tez, Spark as engines?

Tez is the default and builds one DAG per query. MapReduce is deprecated in Hive 4. Hive on Spark was removed in Hive 4.0; Spark now reads Hive tables through the metastore instead (Lesson 11.1).

35. Common causes of OutOfMemory errors?

A map join whose “small” table is not small, huge GROUP BY key sets, skewed keys, too-small container memory, or wide rows with large collections. Fix the cause before raising memory.

36. What is a materialized view in Hive?

A stored query result that the optimiser can use automatically when it is up to date; requires transactional source tables for automatic rewriting. Step 5–6 below show it.

37. What happened to Hive indexes?

Removed in Hive 3.0. Use columnar formats with statistics and bloom filters, partitioning, and materialized views instead. 9.2

ACID, SCD and modern Hive

38. What does Hive ACID need, and what are its trade-offs?

ORC, transactional=true, managed table, and the DbTxnManager. Gains: UPDATE, DELETE, MERGE, consistent reads. Costs: delta folders, compaction, Hive-specific files other engines may misread. 7.1

39. Minor versus major compaction?

Minor merges delta files into one delta; major rewrites base + deltas into a new base. The cleaner then removes old folders. 7.3

40. How do you implement SCD type 2 in Hive?

MERGE with a source that contains every changed row twice: once with the key (to close the current version) and once with a NULL key (to insert the new one), plus a guard so only newer changes apply. 12.2

41. What is Apache Iceberg and why does it matter for Hive users?

An open table format with snapshots, hidden partitioning, partition evolution and engine-neutral row-level changes. Hive 4 creates and migrates Iceberg tables natively. 11.3

42. How is Hive used in the cloud?

Managed clusters such as Amazon EMR, Google Dataproc and Azure HDInsight run Hive on object storage; AWS Glue Data Catalog or a managed metastore replace the self-run metastore. 11.2

43. How is Hive secured?

Authentication (Kerberos, LDAP, SAML/JWT in Hive 4), authorization (SQL-standard based or Apache Ranger policies), and encryption in transit and at rest. 10.2

44. How do you monitor Hive?

HiveServer2 web UI (port 10002), Tez UI, metrics (JMX), operation logs, the metastore’s compaction and lock tables, and data tests like ours. 10.3

Comparisons and judgement

45. Hive versus HBase?

Hive: SQL analytics over files, batch, high latency. HBase: a NoSQL key-value store for random reads and writes in milliseconds. They are often used together.

46. Hive versus Pig?

Both turn scripts into jobs. Hive uses SQL and a metastore; Pig used a procedural data-flow language. Pig is rarely used for new work today.

47. Hive versus Spark SQL and Trino?

Hive excels at large SQL ETL and owns ACID tables; Spark SQL fits programmatic pipelines and ML; Trino is fastest for interactive queries. Many platforms share one metastore between all three. 11.1

48. When was Hive not the right tool?

For sub-second dashboards (use Trino or a serving store), per-event updates (use a streaming system or HBase) and very small data (a single database is simpler).

49. How do you ensure data quality in Hive?

Raw tables that keep everything, typed staging with reject reasons, quarantine, reconciliation between layers, automated PASS/FAIL tests and an audit table, as in this capstone.

50. Why is Hive still relevant in 2026?

Its metastore is the catalogue of many data lakes, large companies run huge Hive SQL estates, and Hive 4 adds Iceberg, so Hive skills transfer directly to lakehouse work.

6 Real-world use

Where review and interview skills are used

1. Production readiness reviews

Data platform teams review new pipelines against a checklist like ours before they feed executive dashboards.

New pipeline→review→Go-live

2. Data tests in schedulers

Airflow DAGs run data tests after each load and stop publishing when a test fails.

Load→tests→Publish or alert

3. Operating ACID tables

Teams monitor compaction backlog and delta counts the way they monitor disk space.

Deltas→compaction→Fast reads

4. Data engineering interviews

Service companies, product companies and startups ask Hive, SQL and project questions for data engineer, ETL developer and analytics engineer roles.

Concepts→project story→Offer

5. Faster dashboards without changing them

Materialized views let platform teams speed up common queries without asking analysts to rewrite reports.

Dashboard query→MV rewrite→Seconds
