1 The story

“The model works in my notebook”

Before you start: DataFrames and columns in 4.3, nulls in 4.4; basic ML ideas (features, labels, train/test) help.

A TiffinGo analyst built a churn model in pandas on a 50,000-row sample. In production, the scoring job had to repeat every preparation step by hand on 2 million customers: encode cities, fill missing values, scale numbers. One step was done in a different order, and the predictions were silently wrong for a month.

K> Sir, Spark has machine learning too? Like scikit-learn? A> MLlib trains models on data spread across the cluster, with the same DataFrames we already use. And like scikit-learn, it has pipelines: every preparation step and the model are fitted together and saved as one object. R> So the scoring job cannot get the steps wrong? A> Exactly. It loads the fitted pipeline and calls transform. Today we build a churn pipeline on 200,000 customers, look at what each stage does, and break it twice on purpose. All outputs are real (PySpark 4.3.0).
2 Definition

ML Pipelines

Formal definition (write this in exams)

MLlib is Spark’s machine-learning library; its DataFrame-based API (pyspark.ml) is organised around pipelines. A Transformer converts one DataFrame into another, typically by appending columns, through transform(). An Estimator learns parameters from a DataFrame through fit() and returns a Transformer (a model). A Pipeline is an Estimator made of an ordered list of stages; Pipeline.fit() runs the stages in order on the training data, fitting each Estimator and transforming the data for the next stage, and returns a PipelineModel containing only Transformers. Applying the same PipelineModel at training, evaluation and serving time guarantees identical feature preparation. Models expect features as a single vector column, usually built with VectorAssembler.

In simple words

A pipeline is a list of steps: preparation steps and a model. Steps that must learn something from data (like the list of cities) are estimators; fit learns it. The result is a fitted pipeline you apply to any new data with transform, so the same preparation is always used.

LEVELS> Pipelines at three levels L1> A recipe card
  • Wash, chop, marinate, cook: always in that order. Writing it on one card means any cook makes the same dish.
  • Some steps first need to measure the ingredients (how much salt for this batch): that is fit. Following the measured card is transform.
L2> The API
  • Transformer: transform(df) adds columns (VectorAssembler, a fitted model).
  • Estimator: fit(df) learns from data and returns a Transformer (StringIndexer → StringIndexerModel, LogisticRegression → LogisticRegressionModel).
  • Pipeline(stages=[…]).fit(train) → PipelineModel; .transform(test) adds rawPrediction, probability, prediction.
L3> What the lab showed
  • StringIndexer learned labels by frequency: Free 0, Silver 1, Gold 2.
  • 5 stages fitted in 6.2 s on 159,838 rows; test AUC 0.8105 on 40,162 rows.
  • An unseen city broke scoring unless handleInvalid="keep"; nulls broke VectorAssembler unless imputed.
/LEVELS EXAM> “Transformer vs Estimator in Spark ML?” A Transformer has transform() and maps a DataFrame to a new one (e.g. VectorAssembler, a fitted model). An Estimator has fit() and learns from data, returning a Transformer (e.g. StringIndexer → StringIndexerModel). A Pipeline is an Estimator of stages; its fitted form, PipelineModel, is a Transformer used to score new data with the same preprocessing.

WARN> Fit the pipeline on the training split only. If you fit an Imputer, scaler or indexer on all data before splitting, test-set information leaks into the model and your evaluation looks better than reality. And set handleInvalid deliberately: in production new categories (a new city) and nulls always appear; the default "error" stops the whole scoring job.
4 Step by step

A churn pipeline, stage by stage

All outputs are real: PySpark 4.3.0, local[4]. Data: 200,000 synthetic TiffinGo customers with city, plan, orders in the last 30 days, average amount, days since last order, complaints, late-delivery %, tenure and a churned label (37.2% churn); 3% of amounts and 2% of late % are missing.

  1. Step 1 · Data and the split

    df = spark.read.parquet("customers.parquet")
train, test = df.randomSplit([0.8, 0.2], seed=7)
    == 1) data rows 200000 | churn rate 0.372 +-----------+---------+------+----------+----------+---------------+----------+--------+-------------+-------+ |customer_id| city| plan|orders_30d|avg_amount|days_since_last|complaints|late_pct|tenure_months|churned| +-----------+---------+------+----------+----------+---------------+----------+--------+-------------+-------+ | 1|Bengaluru| Free| 9| 216.4| 18| 0| 42.0| 10| 0| | 2| Delhi| Free| 5| 133.2| 57| 0| 29.5| 43| 1| | 3| Chennai|Silver| 9| 152.4| 0| 1| 14.3| 29| 0| +-----------+---------+------+----------+----------+---------------+----------+--------+-------------+-------+ only showing top 3 rows train 159838 | test 40162
    A random 80/20 split with a fixed seed so results repeat. Everything that learns from data must see only train; test stays untouched until evaluation.

  2. Step 2 · An Estimator and a Transformer

    idx = StringIndexer(inputCol="plan", outputCol="plan_idx")
idx_model = idx.fit(train)                    # learns the labels
idx_model.transform(train)
va = VectorAssembler(inputCols=["orders_30d", "days_since_last"], outputCol="v")
va.transform(train)                           # nothing to learn
    == 2) a transformer vs an estimator StringIndexer is an Estimator: JavaEstimator fit() returned: StringIndexerModel | labels: ['Free', 'Silver', 'Gold'] +------+--------+ | plan|plan_idx| +------+--------+ | Free| 0.0| |Silver| 1.0| | Gold| 2.0| +------+--------+ VectorAssembler is a Transformer (no fit): False +----------+---------------+----------+ |orders_30d|days_since_last|v | +----------+---------------+----------+ |9 |18 |[9.0,18.0]| |5 |57 |[5.0,57.0]| +----------+---------------+----------+ only showing top 2 rows
    StringIndexer must first learn the categories, ordered by frequency: Free (most common) 0, Silver 1, Gold 2. fit returns a StringIndexerModel that does the mapping. VectorAssembler has no fit: it just packs columns into the single vector column that every MLlib model reads.

  3. Step 3 · The full pipeline

    pipe = Pipeline(stages=[
    Imputer(inputCols=["avg_amount", "late_pct"], outputCols=[…], strategy="median"),
    StringIndexer(inputCols=["city", "plan"], outputCols=["city_idx", "plan_idx"], handleInvalid="keep"),
    OneHotEncoder(inputCols=["city_idx", "plan_idx"], outputCols=["city_oh", "plan_oh"]),
    VectorAssembler(inputCols=num + ["city_oh", "plan_oh"], outputCol="features"),
    LogisticRegression(featuresCol="features", labelCol="churned", maxIter=50)])
model = pipe.fit(train); pred = model.transform(test)
    == 3) the full pipeline fit: 5.1 s -> PipelineModel stages after fit: ['ImputerModel', 'StringIndexerModel', 'OneHotEncoderModel', 'VectorAssembler', 'LogisticRegressionModel'] new columns: ['city_idx', 'plan_idx', 'city_oh', 'plan_oh', 'features', 'rawPrediction', 'probability', 'prediction'] +-----------+-------+----------------------------------------+---------------------------------------+----------+ |customer_id|churned|rawPrediction |probability |prediction| +-----------+-------+----------------------------------------+---------------------------------------+----------+ |6 |0 |[-0.6125765589052194,0.6125765589052194]|[0.3514716742765938,0.6485283257234062]|1.0 | |8 |0 |[1.35051361565342,-1.35051361565342] |[0.7942135853874407,0.2057864146125593]|0.0 | |10 |0 |[0.8145973123227467,-0.8145973123227467]|[0.693088297508758,0.306911702491242] |0.0 | +-----------+-------+----------------------------------------+---------------------------------------+----------+ only showing top 3 rows test AUC: 0.8105 features vector size: 15
    One fit fitted all four estimators in order (6.2 s on 160K rows across 4 cores) and returned a PipelineModel whose stages are now all models. transform added the intermediate columns and three outputs: rawPrediction (scores), probability ([P(stay), P(churn)]) and prediction (1 if P(churn) ≥ 0.5). 6 numbers + 6 city slots + 3 plan slots = 15 features. AUC on unseen customers: 0.81.

  4. Step 4 · A city the model has never seen

    new = spark.createDataFrame([(999001, "Surat", "Gold", 3, 250.0, 40, 2, 30.0, 5, 0)], df.schema)
model.transform(new)                                  # handleInvalid="keep"
Pipeline(stages=[StringIndexer(inputCol="city", outputCol="city_idx")]).fit(train).transform(new)
    == 4) unseen category at scoring time handleInvalid=keep: [Row(city='Surat', city_idx=6.0, prediction=1.0)] handleInvalid=error: Unseen label: Surat. To handle unseen labels, set Param handleInvalid to keep.
    TiffinGo launched in Surat after training. With handleInvalid="keep", unknown cities get an extra index (6) and the customer is still scored. With the default "error", the whole scoring job fails on the first unseen label. "skip" would silently drop the row.

  5. Step 5 · Missing values

    Pipeline(stages=stages[1:]).fit(train)     # same pipeline without the Imputer
    == 5) nulls without an Imputer ERROR: Encountered null while assembling a row with handleInvalid = "error". Consider removing nulls from dataset or using handleInvalid = "keep" or "skip".
    Without the Imputer, VectorAssembler hit the first null avg_amount and failed: models cannot take null features. Fill them (Imputer), drop them, or set handleInvalid on the assembler; deciding which is part of the model design, so it belongs inside the pipeline.
