2 Definition

Evaluation, tuning and saving models

Formal definition (write this in exams)

Evaluators compute metrics on a predictions DataFrame: for binary classification, the area under the ROC curve (threshold-independent ranking quality) and under the precision-recall curve; for class predictions, accuracy, F1, precision and recall. A confusion matrix counts true/false positives and negatives at a chosen decision threshold, which trades precision against recall. Hyperparameter tuning searches a ParamGridBuilder grid: TrainValidationSplit evaluates each combination once on a held-out part of the training data, while CrossValidator averages over k folds, costing about k times more; both refit the best combination on all training data as bestModel. Fitted pipelines are persisted with MLWriter (model.write().save(path)) as metadata and per-stage data, and restored with PipelineModel.load(path) for batch or streaming scoring.

In simple words

Measure a model with metrics that fit the problem, not just accuracy; pick the probability threshold that matches what you can act on. Try a few settings automatically and keep the best on validation data. Then save the whole fitted pipeline to storage so any job can load it and score new data exactly the same way.

Evaluation and tuning at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A security gate

  • A strict guard stops few innocent people but misses some intruders (high precision, low recall). A nervous guard stops everyone suspicious (high recall, more false alarms).
  • The threshold is how nervous the guard is. Tuning is trying a few guards on practice days and keeping the best.

Intermediate The API

  • BinaryClassificationEvaluator(metricName="areaUnderROC" | "areaUnderPR"), MulticlassClassificationEvaluator(metricName="accuracy" | "f1" | …).
  • ParamGridBuilder().addGrid(lr.regParam, […]).build(); TrainValidationSplit or CrossValidator(numFolds=3, parallelism=2); .bestModel.
  • model.write().overwrite().save(path), PipelineModel.load(path).

Advanced What the lab showed

  • AUC 0.8105, PR AUC 0.7174; accuracy 0.7517 vs 0.6284 for always predicting “stay”.
  • Threshold 0.7 flagged 5,643 customers with 81% precision; 0.3 caught 82% of churners.
  • CrossValidator took 2.1x as long as TrainValidationSplit and picked the same parameters; the reloaded model gave identical predictions.

Exam tip: “CrossValidator vs TrainValidationSplit?” Both search a parameter grid with an evaluator. TrainValidationSplit splits training data once (e.g. 80/20) and evaluates each combination once: fast but noisier. CrossValidator uses k folds and averages, more reliable but about k times the cost. Both refit the best parameters on the full training data. Use parallelism to fit several models at once, and keep a separate test set for the final estimate.

3 Types and ways to use it

Tuning options

ToolModels fittedOur timeWhen
Manual loopYou deciden/aQuick experiments
TrainValidationSplit(0.8)grid + 1 = 717.3 sLarge data, many combinations
CrossValidator(3 folds)3 × grid + 1 = 1936.9 sSmaller data, reliable estimates

Grids grow multiplicatively: 3 regParams × 2 elasticNets × 3 folds already meant 19 fits, and adding 3 values for another parameter triples that. Keep grids small and coarse, use parallelism, and cache the training data. Also, a saved model is tied to its Spark version: test loading in the version your scoring job runs, and store the training metrics and data date next to the files.

6 Real-world use

Model evaluation and deployment at work

1. Budgeted campaigns

Retention, credit and fraud teams choose thresholds from the cost of each error.

Scores→threshold→Campaign list

2. Scheduled retraining

Monthly jobs retrain with TrainValidationSplit and save a new version.

New data→tune + fit→models/v(n+1)

Customers→load + transform→Scores table

Run→log model→Registry

AUC on recent outcomes is tracked; a drop triggers retraining.

# Precision and recall from the lab confusion matrix, and a budget threshold
tn, fp, fn, tp = 21341, 3897, 6074, 8850
precision = tp / (tp + fp)
recall = tp / (tp + fn)
f1 = 2 * precision * recall / (precision + recall)
print(f"precision {precision:.3f} | recall {recall:.3f} | f1(churn) {f1:.3f}")

lab = {0.3: (21280, 0.571, 0.815), 0.5: (12747, 0.694, 0.593), 0.7: (5643, 0.807, 0.305)}
budget = 6000
ok = [th for th, (flagged, p, r) in lab.items() if flagged <= budget]
best = min(ok)                                   # lowest threshold that fits the budget
print("threshold for a budget of", budget, "->", best, lab[best])

Interview and viva questions

Should I tune on the test set?

No. Tuning uses validation splits inside the training data; the test set gives the final, untouched estimate.

How do I change the threshold of a saved model?

Set it on the model stage (lr_model.setThreshold(0.7)) or filter on the probability column in the scoring job.

Can I load the model in Scala or Java?

Yes, the saved format is shared across Spark’s language APIs.

Do saved models work across Spark versions?

Usually within a major version; test loading before upgrading and retrain if needed.

How do I track experiments?

Use MLflow’s Spark flavor to log parameters, metrics and the model with each run.

“Precision vs recall”

Explain with an example.

The interviewer is checking: trade-off?

Show a strong answer

Precision: of flagged customers, how many churn. Recall: of churners, how many we flagged. Raising the threshold raises precision and lowers recall; in my lab 0.5 → 0.7 moved precision 0.69 → 0.81 and recall 0.59 → 0.31.

Avoid: Using accuracy alone.
