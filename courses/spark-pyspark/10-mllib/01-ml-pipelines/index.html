ML Pipelines

MLlib trains models on distributed DataFrames, and pipelines keep preparation and model together. This lesson separates Transformers from Estimators, builds a five-stage churn pipeline on 200,000 customers, reads its predictions, and breaks it with an unseen city and missing values. All outputs are real (PySpark 4.3.0).

1 The story

“The model works in my notebook”

Before you start: DataFrames and columns in 4.3, nulls in 4.4; basic ML ideas (features, labels, train/test) help.

A TiffinGo analyst built a churn model in pandas on a 50,000-row sample. In production, the scoring job had to repeat every preparation step by hand on 2 million customers: encode cities, fill missing values, scale numbers. One step was done in a different order, and the predictions were silently wrong for a month.

Kabir

MLlib trains models on data spread across the cluster, with the same DataFrames we already use. And like scikit-learn, it has pipelines: every preparation step and the model are fitted together and saved as one object.

Arjun Sir

2 Definition

ML Pipelines

Formal definition (write this in exams)

MLlib is Spark’s machine-learning library; its DataFrame-based API (pyspark.ml) is organised around pipelines. A Transformer converts one DataFrame into another, typically by appending columns, through transform(). An Estimator learns parameters from a DataFrame through fit() and returns a Transformer (a model). A Pipeline is an Estimator made of an ordered list of stages; Pipeline.fit() runs the stages in order on the training data, fitting each Estimator and transforming the data for the next stage, and returns a PipelineModel containing only Transformers. Applying the same PipelineModel at training, evaluation and serving time guarantees identical feature preparation. Models expect features as a single vector column, usually built with VectorAssembler.

In simple words

A pipeline is a list of steps: preparation steps and a model. Steps that must learn something from data (like the list of cities) are estimators; fit learns it. The result is a fitted pipeline you apply to any new data with transform, so the same preparation is always used.

Pipelines at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A recipe card

  • Wash, chop, marinate, cook: always in that order. Writing it on one card means any cook makes the same dish.
  • Some steps first need to measure the ingredients (how much salt for this batch): that is fit. Following the measured card is transform.

Intermediate The API

  • Transformer: transform(df) adds columns (VectorAssembler, a fitted model).
  • Estimator: fit(df) learns from data and returns a Transformer (StringIndexer → StringIndexerModel, LogisticRegression → LogisticRegressionModel).
  • Pipeline(stages=[…]).fit(train) → PipelineModel; .transform(test) adds rawPrediction, probability, prediction.

Advanced What the lab showed

  • StringIndexer learned labels by frequency: Free 0, Silver 1, Gold 2.
  • 5 stages fitted in 6.2 s on 159,838 rows; test AUC 0.8105 on 40,162 rows.
  • An unseen city broke scoring unless handleInvalid="keep"; nulls broke VectorAssembler unless imputed.

Exam tip: “Transformer vs Estimator in Spark ML?” A Transformer has transform() and maps a DataFrame to a new one (e.g. VectorAssembler, a fitted model). An Estimator has fit() and learns from data, returning a Transformer (e.g. StringIndexer → StringIndexerModel). A Pipeline is an Estimator of stages; its fitted form, PipelineModel, is a Transformer used to score new data with the same preprocessing.

Fit the pipeline on the training split only. If you fit an Imputer, scaler or indexer on all data before splitting, test-set information leaks into the model and your evaluation looks better than reality. And set handleInvalid deliberately: in production new categories (a new city) and nulls always appear; the default "error" stops the whole scoring job.

  4. Step 4 · A city the model has never seen

    new = spark.createDataFrame([(999001, "Surat", "Gold", 3, 250.0, 40, 2, 30.0, 5, 0)], df.schema)
model.transform(new)                                  # handleInvalid="keep"
Pipeline(stages=[StringIndexer(inputCol="city", outputCol="city_idx")]).fit(train).transform(new)

    TiffinGo launched in Surat after training. With handleInvalid="keep", unknown cities get an extra index (6) and the customer is still scored. With the default "error", the whole scoring job fails on the first unseen label. "skip" would silently drop the row.

  5. Step 5 · Missing values

    Pipeline(stages=stages[1:]).fit(train)     # same pipeline without the Imputer
    == 5) nulls without an Imputer ERROR: Encountered null while assembling a row with handleInvalid = "error". Consider removing nulls from dataset or using handleInvalid = "keep" or "skip".
    Without the Imputer, VectorAssembler hit the first null avg_amount and failed: models cannot take null features. Fill them (Imputer), drop them, or set handleInvalid on the assembler; deciding which is part of the model design, so it belongs inside the pipeline.

7 Run the code

Run the code: fit and transform

What a StringIndexer does in fit and transform. Press Run, then try the challenges.

# fit() vs transform() for a StringIndexer, in plain Python
from collections import Counter
train_plans = ["Free", "Free", "Silver", "Free", "Gold", "Silver", "Free"]

# fit: learn labels ordered by frequency
labels = [p for p, _ in Counter(train_plans).most_common()]
print("learned labels:", labels)

# transform: map values with the learned labels
def transform(values, handle_invalid="keep"):
    out = []
    for v in values:
        if v in labels:
            out.append(float(labels.index(v)))
        elif handle_invalid == "keep":
            out.append(float(len(labels)))       # extra index for unknowns
        else:
            raise ValueError(f"Unseen label: {v}")
    return out

print(transform(["Gold", "Free", "Platinum"]))
learned labels: ['Free', 'Silver', 'Gold'] [2.0, 0.0, 3.0]
  • labels = [p for p, _ in Counter(train_plans).most_common()]fit: learn from training data only. Most frequent value gets index 0.
  • out.append(float(len(labels))) # extra index for unknownshandleInvalid="keep": unseen values get one extra index instead of failing.

  • Pipeline = ordered stages; fit → PipelineModel; transform scores new data.

Interview and viva questions

Is pyspark.mllib the same as pyspark.ml?

No. pyspark.mllib is the old RDD-based API in maintenance mode; use the DataFrame-based pyspark.ml.

Can I use scikit-learn models in Spark?

For scoring, yes via pandas UDFs; for training on huge data, use MLlib or distributed frameworks.

Do I always need OneHotEncoder?

Linear models need it; tree models can use StringIndexer output directly.

Can a stage be my own code?

Yes, SQLTransformer for SQL, or a custom Python Transformer class (harder to save).

How big can training data be?

As big as the cluster can process; most MLlib algorithms are iterative and benefit from caching.

Real-world scenario questions (asked in company interviews)

Pipeline basics are asked in every Spark ML interview.

Any company · SparkFresher

“Transformer vs Estimator”

Explain with examples.

The interviewer is checking: fit vs transform?

Show a strong answer

An Estimator learns from data with fit() and returns a Transformer (StringIndexer → StringIndexerModel, LogisticRegression → LogisticRegressionModel). A Transformer maps a DataFrame with transform() (VectorAssembler, any fitted model).

Avoid: Saying VectorAssembler must be fitted.

Why pipelines?

Your team scores models with hand-written prep code.

The interviewer is checking: risk and fix?

Show a strong answer

  • Pipeline with all prep stages + model, fitted once.
  • Save and load the PipelineModel for scoring.

Avoid: Copying notebook code into the job.
