2 Definition

The CSV and JSON data sources

Formal definition (write this in exams)

The CSV and JSON sources are built-in, text-based file data sources of Spark SQL, accessed with spark.read.csv() / .json() or format("csv"|"json"). Both are configured by options: for CSV, among others header, sep, quote, escape, multiLine, nullValue, dateFormat, timestampFormat, inferSchema, enforceSchema; for JSON, multiLine, primitivesAsString, dropFieldIfAllNull. Malformed input is handled by the parse mode: PERMISSIVE (default) sets unparsable fields to null and, if a string field named by columnNameOfCorruptRecord exists in the schema, stores the raw record there; DROPMALFORMED drops such records; FAILFAST raises an exception. JSON is read as JSON Lines (one object per line) unless multiLine is set, and its schema is inferred from all records unless one is supplied. Files compressed with a non-splittable codec such as gzip are processed by a single task per file.

In simple words

CSV and JSON are text, so Spark needs to be told how to read them: header, quotes, line breaks, dates, nulls, and what to do with bad lines. Give a schema, keep bad lines in a corrupt-record column, and remember that one gzip file is read by one core.

Reading text files at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A handwritten register

  • A CSV is a register where commas separate the columns. If someone writes a comma inside a name, you need quotes to know it is one name.
  • If a note continues on the next line, you must know it is still the same entry.
  • Some entries are unreadable: decide whether to keep them aside, skip them, or stop.

Intermediate The API

  • spark.read.csv(path, header=True, schema=…, multiLine=True, escape='"', mode=…, dateFormat=…, nullValue=…).
  • Modes: PERMISSIVE (default, bad fields → null, raw line in _corrupt_record if it is in the schema), DROPMALFORMED, FAILFAST.
  • spark.read.json(path) expects JSON Lines; use multiLine=True for a JSON array or pretty-printed file.

Advanced What the lab showed

  • Defaults turned 7 orders into 8 rows; multiLine and escape='"' gave 7 correct rows.
  • DROPMALFORMED kept 6 rows for count() but 4 when all columns were read: CSV parsing depends on the columns you select.
  • A gzip CSV was read as one partition: 3.4 s against 2.0 s for the plain file split into 7.

Exam tip: “How do you handle corrupt records in CSV?” Read with an explicit schema that includes a string column _corrupt_record in PERMISSIVE mode, cache the result, split good rows from rows where _corrupt_record is not null, and write the bad rows to a quarantine table with a count. Use FAILFAST when any bad row must stop the pipeline; avoid DROPMALFORMED because rows disappear without a trace.

_corrupt_record has two traps. Spark refuses queries that reference only that column on a raw file (UNSUPPORTED_FEATURE.QUERY_ONLY_CORRUPT_RECORD_COLUMN), so cache or save the parsed data first. And the CSV parser only converts the columns your query needs, so which rows count as “bad” depends on the columns you select (Step 4).

Run the code: why line breaks matter

A tiny parser shows what multiLine changes. Press Run, then try the challenges.

# Why one CSV line with a line break becomes two rows (simplified parser)
text = 'order_id,review\n9004,"Loved it.\nWill order again"\n9005,Cold\n'

def split_naive(t):                      # multiLine=false: a newline ends a record
    return [l for l in t.split("\n")[1:] if l]

def split_quoted(t):                     # multiLine=true: newlines inside quotes are data
    rows, cur, inq = [], "", False
    for ch in t.split("\n", 1)[1]:
        if ch == '"':
            inq = not inq
        if ch == "\n" and not inq:
            rows.append(cur); cur = ""
        else:
            cur += ch
    return rows

print("naive :", split_naive(text))
print("quoted:", split_quoted(text))
naive : ['9004,"Loved it.', 'Will order again"', '9005,Cold'] quoted: ['9004,"Loved it.\nWill order again"', '9005,Cold']
  • def split_naive(t): # multiLine=false: a newline ends a recordSpark’s default: 7 orders became 8 rows in the lab.
  • if ch == "\n" and not inq:Inside quotes a newline is part of the value.

  • Modes: PERMISSIVE (+ _corrupt_record), DROPMALFORMED (silent), FAILFAST (stop).

Interview and viva questions

Is bzip2 splittable?

Yes, bzip2 can be split, but it is slow to compress. In practice prefer many moderate files or convert to Parquet.

How do I read a pipe-separated file?

Use sep="|" (or delimiter). Spark also accepts multi-character separators.

What does enforceSchema=false do?

With a header, Spark checks that header names match your schema and warns or fails on mismatch, instead of silently applying the schema by position.

Can I read many files at once?

Yes: pass a folder, a glob (orders_2026-11-*.csv) or a list of paths. Use recursiveFileLookup for nested folders and input_file_name() or _metadata.file_path to know the source file.

Should I keep data in CSV?

Only at the edges. Read text once and store Parquet, ORC or a table format for analysis (Lesson 5.2).

  • Write bad rows to a quarantine table, alert, reconcile counts.
  • FAILFAST where any bad row must stop; avoid DROPMALFORMED.

Avoid: Silently dropping rows.

Data engineeringMid-level

Row counts differ from the source

Spark reports more rows than the source system sent.

The interviewer is checking: can you debug parsing?

Show a strong answer
  1. Look for line breaks inside quoted values: enable multiLine.
  2. Check escape (doubled quotes) and separators inside values.
  3. Compare counts with a control file every load.

Avoid: Deduplicating to hide the difference.

PlatformSenior

A 40 GB gzip file

One huge gzip file makes the job slow on a large cluster.

The interviewer is checking: do you know splittability?

Show a strong answer
  • gzip is read by one task: ask the producer for many files or a splittable format.
  • Otherwise convert once: read, repartition, write Parquet.
  • Measure partitions and task counts in the Spark UI.

Avoid: Adding executors.
