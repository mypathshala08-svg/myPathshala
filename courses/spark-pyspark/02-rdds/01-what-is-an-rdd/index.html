2 Definition

Resilient Distributed Dataset

Formal definition (write this in exams)

A Resilient Distributed Dataset (RDD) is Spark’s fundamental data abstraction: an immutable, partitioned collection of elements that can be operated on in parallel. An RDD is defined by a list of partitions, a function for computing each partition, a list of dependencies on parent RDDs (its lineage), and optionally a partitioner for key-value RDDs and preferred locations for each partition. RDDs are created by parallelising a driver collection or by reading external storage, and transformed with coarse-grained operations; because the lineage is recorded, lost partitions can be recomputed. In PySpark the elements are arbitrary Python objects processed by Python worker processes; the higher-level DataFrame API is built on RDDs and is usually preferred because Catalyst can optimise it.

In simple words

An RDD is a collection of data split into pieces (partitions) on many machines. You cannot change it; you make new RDDs from it. Spark remembers how every RDD was made, so lost pieces can be rebuilt.

RDDs at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A big box of order slips, split into trays

  • An RDD is like a pile of order slips split into trays (partitions), one tray per cook.
  • You never write on the slips: every step makes a new pile (immutability).
  • Each pile has a note saying how it was made, so a lost tray can be made again (lineage).

Intermediate What makes an RDD

  • Resilient: lost partitions are recomputed from lineage, not from replicas.
  • Distributed: partitions live on different executors and are processed in parallel.
  • Dataset: any Python objects (strings, tuples, dicts, Rows), no schema required.
  • Create from a collection (parallelize), from files (textFile, wholeTextFiles) or from a DataFrame (df.rdd).

Advanced Inside, and what the lab showed

  • Every RDD has five properties: its partitions, a function to compute each partition, dependencies on parent RDDs, and optionally a partitioner and preferred locations.
  • glom() showed the six amounts split 2-2-2 over 3 partitions; toDebugString() showed the lineage.
  • The same city revenue took 4.0 s as a DataFrame and 30.2 s as an RDD: Python lambdas, pickling and no Catalyst optimizer.

Exam tip: “What is an RDD and what are its properties?” An immutable, partitioned, fault-tolerant collection processed in parallel. Defined by partitions, a compute function, dependencies (lineage), and optionally a partitioner and preferred locations. Fault tolerance comes from recomputing lost partitions using lineage.

parallelize copies the list from the driver to the executors. It is fine for test data and small lookups, but never a way to load real data: the whole list must first fit in the driver’s memory. Read big data from storage with textFile or a DataFrame reader instead.

4 Step by step

Five RDDs, looked at from inside

All outputs are real: PySpark 4.3.0, local mode with 2 cores. Data: TiffinGo’s order_items.txt (5,000 lines), three months of review text (24,000 lines in 3 files), orders.csv and orders_big (5,000,000 orders) from Module 1.

  1. Step 1 · parallelize: a list becomes partitions

    sc = spark.sparkContext
amounts = sc.parallelize([530, 210, 480, 990, 120, 340], 3)
print(amounts, "| partitions:", amounts.getNumPartitions())
print("glom():", amounts.glom().collect())
    ParallelCollectionRDD[0] at readRDDFromFile at PythonRDD.scala:326 | partitions: 3 glom(): [[530, 210], [480, 990], [120, 340]]
    We asked for 3 partitions and Spark split the six amounts 2-2-2. glom() is a debugging tool: it turns each partition into a list so you can see the split. The printed name ParallelCollectionRDD[0] is the RDD’s class and id; every new RDD gets the next id.

  2. Step 2 · textFile: one element per line

    items = sc.textFile("order_items.txt")
print("partitions:", items.getNumPartitions(), "| lines:", items.count())
print("first():", items.first())

reviews = sc.textFile("reviews")          # a folder of 3 files
print("partitions:", reviews.getNumPartitions(), "| lines:", reviews.count())
    partitions: 2 | lines: 5000 first(): 100001|Chole Bhature,Aloo Paratha,Lassi,Rajma Chawal|spice:medium,cutlery:yes partitions: 3 | lines: 24000
    Each line is one string; Spark knows nothing about the | and , inside. A small file still gave 2 partitions (textFile’s default minimum is min(cores, 2)); a folder of 3 files gave 3, one per file. Paths can be local, hdfs://, s3a:// or wildcards like reviews/*.txt.

  3. Step 3 · wholeTextFiles: one element per file

    whole = sc.wholeTextFiles("reviews")
print(whole.count(), [(p.split("/")[-1], len(c)) for p, c in whole.collect()])
    elements: 3 | [('reviews_2026-09.txt', 302582), ('reviews_2026-08.txt', 264376), ('reviews_2026-10.txt', 339529)]
    Three elements, each a pair (path, entire content). Useful when a file must be parsed as a whole (a JSON or XML document per file) or when the file name carries information, such as the month here. Not for huge files: each file is one element in memory.

  4. Step 4 · From a DataFrame: Row objects

    df = spark.read.csv("orders.csv", header=True)
rows = df.rdd
print(type(rows.first()).__name__, rows.first()["city"], rows.first()["amount"])
    type of element: Row | Mumbai 530
    Every DataFrame has an RDD of Row objects underneath. A Row behaves like a named tuple: r["city"] or r.city. Going from DataFrame to RDD is easy; it is also the moment Spark stops optimising your code (Step 6).

  5. Step 5 · Immutable, with a recorded lineage

    big = amounts.filter(lambda a: a >= 300)
print("amounts:", amounts.collect())
print("big    :", big.collect(), "| same object?", big is amounts)
print(big.toDebugString().decode())
    amounts: [530, 210, 480, 990, 120, 340] big : [530, 480, 990, 340] | same object? False Lineage of big: (3) PythonRDD[30] at collect at /root/lab/spark/jobs/m2/l21_create.py:32 [] | ParallelCollectionRDD[0] at readRDDFromFile at PythonRDD.scala:326 []
    The filter did not change amounts; it returned a new RDD. toDebugString() shows the lineage: big (a PythonRDD, because a Python lambda computes it) depends on the original ParallelCollectionRDD; (3) is the number of partitions. If an executor holding a partition of big dies, Spark reruns the filter on that partition of amounts.

  6. Step 6 · The same question as RDD and DataFrame

    df = spark.read.parquet("orders_big")      # 5,000,000 orders
res_df = (df.where("status = 'DELIVERED'").groupBy("city").agg(F.sum("amount").alias("rev"))
            .orderBy(F.desc("rev")).collect())

res_rdd = (df.rdd.filter(lambda r: r.status == "DELIVERED")
                 .map(lambda r: (r.city, r.amount))
                 .reduceByKey(lambda a, b: a + b)
                 .sortBy(lambda kv: -kv[1]).collect())
    DataFrame: [('Mumbai', 484935971), ('Bengaluru', 483166030), ('Chennai', 242708114)] 4.0 s RDD : [('Mumbai', 484935971), ('Bengaluru', 483166030), ('Chennai', 242708114)] 30.2 s same answer: True | RDD/DataFrame time: 8x
    Identical answers; the RDD version took 8 times longer. Each of the 5,000,000 rows was converted to a Python Row, sent to a Python worker, filtered and mapped there, and pickled back. The DataFrame version stayed in the JVM, read only the three columns it needed and used code generation. Rule of thumb: DataFrames for structured data, RDDs for what DataFrames cannot express.

7 Run the code

Run the code: build a toy RDD

PySpark cannot run in the browser, so this toy class imitates an RDD: data split into partitions and a recorded parent. Press Run, then try the challenges.

# A toy RDD: partitions + a recipe (lineage), in plain Python
class ToyRDD:
    def __init__(self, partitions, parent=None, op=None):
        self.partitions, self.parent, self.op = partitions, parent, op
    @staticmethod
    def parallelize(data, n):
        size = -(-len(data) // n)
        return ToyRDD([data[i:i + size] for i in range(0, len(data), size)])
    def filter(self, f):
        return ToyRDD([[x for x in p if f(x)] for p in self.partitions], self, "filter")
    def glom(self):
        return self.partitions
    def lineage(self):
        r, chain = self, []
        while r:
            chain.append(r.op or "parallelize"); r = r.parent
        return " <- ".join(chain)

amounts = ToyRDD.parallelize([530, 210, 480, 990, 120, 340], 3)
big = amounts.filter(lambda a: a >= 300)
print("amounts:", amounts.glom())
print("big    :", big.glom())
print("lineage:", big.lineage())
amounts: [[530, 210], [480, 990], [120, 340]] big : [[530], [480, 990], [340]] lineage: filter <- parallelize
  • return ToyRDD([data[i:i + size] for i in range(0, len(data), size)])Like sc.parallelize(data, 3): the list is cut into 3 partitions of 2.
  • return ToyRDD([[x for x in p if f(x)] for p in self.partitions], self, "filter")A new RDD; the old one is untouched and becomes the parent (lineage).

9 Quiz and revision

Check yourself

Quick revision

Lesson 2.1 in one screen

  • RDD: immutable, partitioned collection processed in parallel; resilient through lineage.
  • Five properties: partitions, compute function, dependencies, optional partitioner, optional preferred locations.
  • Create: parallelize (small driver data), textFile (lines), wholeTextFiles (files), df.rdd (Rows).
  • glom() shows partitions; toDebugString() shows lineage.
  • Transformations return new RDDs; the parent is unchanged.
  • Lab: same answer, DataFrame 4.0 s vs RDD 30.2 s (8×): use DataFrames for structured data.
  • RDDs for unstructured text, custom per-partition logic, legacy jobs; then convert to DataFrames.

Interview and viva questions

Are RDDs deprecated?

No. They remain part of Spark Core and every DataFrame runs on them. The documentation recommends DataFrames for most work, and the RDD API is not available through Spark Connect clients.

What is the difference between SparkContext and SparkSession?

SparkSession is the entry point for DataFrames and SQL; it contains a SparkContext (spark.sparkContext), the entry point for RDDs. One application has one SparkContext.

How many partitions should an RDD have?

Enough to keep every core busy, typically 2–4 per core, with partitions of tens to a few hundred MB. Too few wastes cores; too many adds scheduling overhead (Lesson 8.1).

Does an RDD hold data?

Not necessarily. Until an action runs, an RDD is only a recipe. Data exists while tasks run, and stays in memory only if you cache it (Lesson 3.1).

Can I convert an RDD to a DataFrame?

Yes: spark.createDataFrame(rdd, schema) or rdd.toDF(["col1", "col2"]) for RDDs of tuples or Rows. Lesson 4.2 covers schemas.

Real-world scenario questions (asked in company interviews)

RDD fundamentals are asked in nearly every Spark interview.

Any company · SparkFresher

“What is an RDD?”

Explain RDDs and their main features.

The interviewer is checking: do you know the core idea?

Show a strong answer

An RDD is Spark’s basic data structure: an immutable collection split into partitions across the cluster and processed in parallel. It is lazily evaluated and fault tolerant: Spark keeps the lineage of operations and recomputes lost partitions. I can create one with parallelize, textFile or from a DataFrame.

Avoid: Saying RDDs are stored replicated in memory.

Data engineeringFresher

RDD vs DataFrame

When would you use an RDD instead of a DataFrame?

The interviewer is checking: do you know the trade-off?

Show a strong answer
  • DataFrame: structured data; Catalyst optimisation; much faster in Python (8× in our test).
  • RDD: unstructured data, custom low-level logic, per-partition resources, legacy code.
  • Often: parse with RDDs, then convert to a DataFrame.

Avoid: “RDDs are faster because they are lower level.”

Data engineeringMid-level

Slow PySpark RDD job

A job using df.rdd.map(...) is very slow.

The interviewer is checking: can you explain the cost?

Show a strong answer
  1. Each row is converted to a Python object and pickled to a Python worker.
  2. No optimisation: no column pruning, no code generation.
  3. Rewrite with DataFrame functions; verify identical results.

Avoid: Adding executors without changing the code.

PlatformSenior

Explain lineage-based fault tolerance

Why does Spark not replicate RDD data like HDFS?

The interviewer is checking: do you understand the design?

Show a strong answer
  • Lineage records coarse-grained transformations; recomputing a lost partition is cheaper than replicating every intermediate dataset.
  • Long lineages or expensive shuffles can be cut with checkpointing (Lesson 3.3).
  • Cached data can optionally be replicated (MEMORY_ONLY_2) when recomputation is too costly.

Avoid: Claiming RDDs are always replicated three times.
