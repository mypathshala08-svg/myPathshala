1 The story

Know your data before you use it

Before you start: 4.3 Working with columns.

🤔 Before any model or dashboard: what does the data actually look like? Averages, spread, medians, links between columns, and a fair sample to play with.

PySpark has a small statistics toolbox on every DataFrame. On 200,000 TiffinGo orders, describe() exposed a delivery of −4 minutes (bad data), corr showed distance explains delivery time (0.908), and approxQuantile with a loose error of 0.1 called the p95 order ₹1,414 while the true p95 is ₹419. Also: sample(0.01) gave 1,941, 1,938 and 2,009 rows, never exactly 2,000.

2 Definition

Statistics and sampling on DataFrames

Formal definition (write this in exams)

PySpark DataFrames expose descriptive statistics (describe, summary), approximate quantiles via the Greenwald–Khanna algorithm (approxQuantile with a relative error bound), pairwise statistics in DataFrame.stat (Pearson correlation, sample covariance, contingency tables, frequent items) and random sampling (Bernoulli sample, stratified sampleBy, weighted randomSplit).

In simple words

Quick numbers about your columns (average, spread, middle value, top 5%), whether two columns move together, and ways to take a fair random piece of the data.

Words you’ll meet in this lesson

describecount, mean, stddev, min, max.
summaryAdds percentiles.
QuantileValue below which p% fall.
relativeErrorAllowed rank error.
corrPearson −1..1.
crosstabPair counts.
sampleByFraction per key.
randomSplitWeighted splits.

Why, how, where

Why

Profiling first catches bad data (negative minutes), picks sensible thresholds (p95 order value) and prepares fair samples for experiments and ML.

the problem it solves

How

describe/summary run one aggregation job over the columns. approxQuantile uses the Greenwald–Khanna sketch: relativeError trades accuracy for memory. sample flips a coin per row (Bernoulli), so the size is only close to fraction × count; sampleBy uses a fraction per key.

the mechanism

Where

Data quality checks, EDA notebooks, KPI thresholds, A/B test groups, train/test splits, quick previews of huge tables.

in real systems

When not

Exact percentiles on billions of rows are expensive; sample sizes are random; corr is Pearson only (linear) in DataFrame.stat; freqItems may return false positives.

know the limits

Dissect approxQuantile

Statistics and sampling at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Tasting the dal

  • You do not drink the whole pot to check salt: you taste a spoon (sample). describe() is the label on the pot: count, average, spread, smallest, biggest.

Intermediate The API

  • df.describe(*cols): count, mean, stddev, min, max. df.summary("count", "25%", "50%", "75%", …) adds percentiles.
  • df.approxQuantile(col, [0.5, 0.95], relativeError); df.stat.corr(a, b), cov, crosstab, freqItems(cols, support).
  • df.sample(fraction, seed), withReplacement=True; df.sampleBy(col, {key: fraction}, seed); df.randomSplit([0.8, 0.2], seed).

Advanced Practical details

  • relativeError 0 is exact but can be expensive on huge data; 0.01 is a common compromise; SQL has percentile_approx and percentile.
  • summary() percentiles are approximate too. Use F.median, F.percentile inside groupBy for per-group values.
  • Cache before randomSplit: without it, each split re-reads and re-randomises the source; with the same seed and cached data, splits are reproducible.

Myth vs reality: things many websites still say

  • Myth: Approximate means slightly off.
    Reality (Spark 4.3): With err 0.1 the p95 can be wildly off.
    Proof: Step 2.
  • Myth: sample(0.01) gives exactly 1%.
    Reality (Spark 4.3): 1,941 / 1,938 / 2,009 rows.
    Proof: Step 5.
  • Myth: corr 0 means unrelated.
    Reality (Spark 4.3): Only no linear link.
    Proof: Step 3.

Exam tip: “How do you get a median in PySpark?” approxQuantile(col, [0.5], relativeError) or summary("50%"), F.median/percentile_approx in SQL; describe vs summary; corr is Pearson; sample is Bernoulli (approximate size); sampleBy = stratified; randomSplit with seed (cache first).

The statistics toolbox

approxQuantilemedian, p95…set by relativeErrorPython list

Do not trust approxQuantile with a large relativeError for tail percentiles: in our lab, 0.1 returned the maximum (₹1,414) as p95 instead of ₹419. And never expect sample(0.01) to return exactly 1% of rows: use limit() or take() after ordering if you need an exact count.

    At 200,000 rows all three are fast; the difference is accuracy. 0.01 is within ₹2 of exact; 0.1 is badly wrong in the tail.

  3. Step 3 · Correlation and covariance

    df.stat.corr("km", "mins"); df.stat.corr("km", "amount"); df.stat.cov("km", "mins")
    == 3) correlation and covariance corr(km, mins) = 0.908 corr(km, amount) = 0.0 cov(km, mins) = 28.63
    Distance and delivery time: 0.908 (strong). Distance and amount: 0.0 (no link). Lesson 10.5 turns this into a model.

  4. Step 4 · crosstab and freqItems

    df.stat.crosstab("city", "pay").show()
df.stat.freqItems(["pay"], 0.25)
    == 4) crosstab city x pay +--------+-----+-----+-----+ |city_pay| Card| Cash| UPI| +--------+-----+-----+-----+ | Delhi|18223| 6034|36072| | Mumbai|29795|10030|60069| | Pune|11700| 3956|24121| +--------+-----+-----+-----+ == 5) freqItems (approximate, may include false positives) ['Card', 'Cash', 'UPI']
    UPI dominates in every city. freqItems is approximate: it may list Cash even though Cash is only 10%.

  5. Step 5 · sample, sampleBy, randomSplit

    df.sample(fraction=0.01, seed=s).count()

    == 6) sample(fraction=0.01) is not exact seed 1: 1941 rows seed 2: 1938 rows seed 3: 2009 rows == 7) sampleBy: stratified by city +------+-----+ | city|count| +------+-----+ |Mumbai| 962| | Pune| 2069| +------+-----+ == 8) randomSplit([0.8, 0.2]) train 160000 test 40000
    Sizes are close to the fraction, not exact. sampleBy gives each city its own fraction (Delhi 0 → none).

7 Run the code

Run the code: statistics by hand

Percentiles and Pearson correlation in plain Python. Press Run, then try the challenges.

# Median, p95 and correlation by hand (what Spark computes for you)
amounts = [120, 180, 200, 210, 150, 400, 230, 190, 260, 900]
xs = sorted(amounts)
def q(p):
    return xs[min(len(xs) - 1, int(p * len(xs)))]
print("median:", q(0.5), " p95:", q(0.95))
km   = [1, 2, 3, 4, 5]
mins = [15, 17, 20, 22, 25]
mk, mm = sum(km) / 5, sum(mins) / 5
cov = sum((a - mk) * (b - mm) for a, b in zip(km, mins)) / 4
sd = lambda v, m: (sum((x - m) ** 2 for x in v) / 4) ** 0.5
print("corr:", round(cov / (sd(km, mk) * sd(mins, mm)), 3))
median: 210 p95: 900 corr: 0.998
  • return xs[min(len(xs) - 1, int(p * len(xs)))]Rank of the p-th value in sorted data.
  • print("corr:", round(cov / (sd(km, mk) * sd(mins, mm)), 3))Pearson = covariance ÷ (sd × sd).

Check yourself

Quick revision

Lesson 4.7 in one screen

  • describe: count, mean, stddev, min, max; summary adds percentiles.
  • approxQuantile(col, probs, err): 0 exact, 0.01 close, 0.1 wrong p95 (1414 vs 419).
  • stat.corr / cov / crosstab / freqItems (approx).
  • sample: approximate size; sampleBy: per-key fractions; randomSplit with seed, cache first.
  • Profiling found −4 minute deliveries.

Interview and viva questions

Is summary() exact?

count/mean/min/max yes; percentiles are approximate.

Spearman correlation?

DataFrame.stat.corr supports only Pearson; use pyspark.ml.stat.Correlation with method="spearman".

Exact N random rows?

orderBy(F.rand(seed)).limit(N): exact but needs a sort.

Why do split sizes change?

Without cache, the source is re-evaluated; cache and fix the seed.
