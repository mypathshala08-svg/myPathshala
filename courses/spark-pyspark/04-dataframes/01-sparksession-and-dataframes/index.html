SparkSession and DataFrames

2 Definition

SparkSession and the DataFrame

Formal definition (write this in exams)

A SparkSession is the unified entry point to Spark SQL and the DataFrame API (introduced in Spark 2.0). It wraps a SparkContext, holds the session’s SQL configuration, temporary views, functions and catalog, and is obtained with SparkSession.builder.getOrCreate(), which returns the active or default session if one exists. A DataFrame is an immutable, distributed collection of rows organised into named, typed columns, i.e. a table with a schema. It is lazily evaluated: transformations build a logical plan that the Catalyst optimizer turns into a physical plan when an action is called. DataFrames are executed by the same engine as Spark SQL, so equivalent DataFrame and SQL queries produce the same plan.

In simple words

The SparkSession is the object you start with: it reads data, runs SQL and makes DataFrames. A DataFrame is a big table spread over the cluster, with column names and types. Writing DataFrame code only plans the work; Spark runs it when you ask for a result.

SparkSession and DataFrames at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A restaurant kitchen

  • The SparkSession is the head chef’s order desk: every order (query) comes in through it.
  • A DataFrame is an order written down as steps; nothing is cooked until someone says “serve” (an action).
  • The cooks (executors) do the work; the head chef only plans and hands out tasks.

Intermediate The API

  • SparkSession.builder.appName(…).master(…).config(k, v).getOrCreate(); in the pyspark shell and notebooks it already exists as spark.
  • A DataFrame is a distributed table with a schema (named, typed columns). Transformations (select, where, groupBy) return new DataFrames; actions (show, count, collect, write) run jobs.
  • Rows come back as Row objects: r.city, r["city"], r.asDict().

Advanced What the lab showed

  • A second getOrCreate() returned the same object, kept the app name, but changed spark.sql.shuffle.partitions from 8 to 50.
  • newSession() shared the SparkContext but had its own temp views and SQL conf.
  • Building a query ran 0 jobs; show() ran 2. The DataFrame and the same SQL produced identical optimized plans.

Exam tip: “What is a SparkSession?” The unified entry point (since Spark 2.0) for DataFrames, SQL and the catalog; it wraps a SparkContext and holds SQL configuration and temporary views. getOrCreate() returns the existing session if there is one. Write one SparkSession per application; use newSession() only when you need isolated views or SQL settings.

4 Step by step

From a session to a first query

All outputs are real: PySpark 4.3.0 in local mode with two cores, reading TiffinGo’s orders.csv (50,002 rows).

  1. Step 1 · Build the session

    from pyspark.sql import SparkSession, functions as F
spark = (SparkSession.builder.appName("tiffingo-4.1").master("local[2]")
         .config("spark.sql.shuffle.partitions", "8").getOrCreate())
print(spark.version, spark.sparkContext.appName, spark.sparkContext.master)
print(spark.conf.get("spark.sql.shuffle.partitions"))
    == 1) builder.getOrCreate version : 4.3.0 app name : tiffingo-4.1 master : local[2] shuffle partitions : 8
    The builder collects settings and getOrCreate() starts the JVM, the SparkContext and the session. spark.conf reads and sets SQL settings at runtime; spark.sparkContext is the same SparkContext we used for RDDs in Module 2.

  2. Step 2 · A second getOrCreate() changes your settings

    s2 = (SparkSession.builder.appName("another-name")
      .config("spark.sql.shuffle.partitions", "50").getOrCreate())
print(s2 is spark, s2.sparkContext.appName, s2.conf.get("spark.sql.shuffle.partitions"))
    == 2) a second getOrCreate same object : True app name : tiffingo-4.1 shuffle partitions : 50
    The same object came back and the app name stayed (it belongs to the SparkContext, fixed at start-up). But the runtime SQL setting was applied to the existing session: from now on every shuffle in this application uses 50 partitions. You can see it later in the plan of Step 6 (hashpartitioning(city, 50)). Kabir’s mystery, solved.

  3. Step 3 · newSession(): isolated views and SQL conf

    s3 = spark.newSession()
spark.range(3).createOrReplaceTempView("nums")
print([t.name for t in spark.catalog.listTables()], [t.name for t in s3.catalog.listTables()])
s3.conf.set("spark.sql.shuffle.partitions", "4")
    == 3) newSession same SparkContext : True view in spark : ['nums'] view in newSession : [] conf spark / s3 : 50 / 4
    A new session shares the SparkContext (and its executors and cache) but has its own temporary views, SQL configuration and registered functions. Servers such as the Spark Thrift Server use this to keep users apart. In normal jobs one session is enough.

  5. Step 5 · Immutable and lazy

    o2 = orders.withColumn("amount_gst", F.round(F.col("amount") * 1.05, 2))
q = (orders.where(F.col("status") == "DELIVERED")
           .groupBy("city").agg(F.sum("amount").alias("revenue"))
           .orderBy(F.desc("revenue")))
# count jobs with the REST API before and after
q.show(5)

    withColumn returned a new DataFrame; orders still has 8 columns. Building q ran no job at all: it is only a plan. show() ran 2 jobs (with adaptive execution, the shuffle stages run as separate jobs). Bengaluru is second with ₹24.99 lakh of delivered orders.

    q.explain()
r = q.first(); print(r, r["city"], r.revenue, r.asDict())
orders.createOrReplaceTempView("orders")
sq = spark.sql("SELECT city, sum(amount) AS revenue FROM orders WHERE status='DELIVERED' GROUP BY city ORDER BY revenue DESC")

Results come back as Row objects. The SQL version produced exactly the same optimized plan: DataFrames and SQL are one engine.

7 Run the code

Run the code: how getOrCreate behaves

A plain-Python model of Step 2. Press Run, then try the challenges.

# A tiny model of getOrCreate(): one session, runtime settings applied
class Session:
    active = None
    def __init__(self, app, conf):
        self.app, self.conf = app, dict(conf)

def get_or_create(app, conf):
    if Session.active is None:
        Session.active = Session(app, conf)
    else:
        Session.active.conf.update(conf)      # runtime SQL settings are applied
    return Session.active

spark = get_or_create("tiffingo-4.1", {"spark.sql.shuffle.partitions": "8"})
s2 = get_or_create("another-name", {"spark.sql.shuffle.partitions": "50"})
print("same object:", s2 is spark)
print("app name   :", spark.app)
print("partitions :", spark.conf["spark.sql.shuffle.partitions"])
same object: True app name : tiffingo-4.1 partitions : 50
  • Session.active.conf.update(conf) # runtime SQL settings are appliedWhat we saw in the lab: 8 became 50 in the existing session.
  • print("app name :", spark.app)The app name belongs to the SparkContext and stays.

9 Quiz and revision

Check yourself

Quick revision

Lesson 4.1 in one screen

  • SparkSession: entry point for DataFrames and SQL; wraps the SparkContext (spark.sparkContext).
  • getOrCreate() returns the existing session but applies runtime SQL settings (8 → 50 in our lab).
  • newSession(): own temp views and SQL conf, shared SparkContext.
  • A DataFrame is an immutable distributed table with a schema; printSchema(), dtypes, columns.
  • Lazy: building a query ran 0 jobs; show() ran 2.
  • Read explain() bottom-up; look for pushed filters and pruned columns.
  • DataFrame and SQL share Catalyst: identical plans.

Interview and viva questions

Do I still need SparkContext?

Only for the RDD API, broadcast variables and accumulators. Get it from spark.sparkContext; never create a second one.

Should I call spark.stop()?

At the end of a script, yes, it releases executors. In notebooks and on Databricks, do not stop the platform’s session.

What about SQLContext and HiveContext?

Old entry points from Spark 1.x. SparkSession replaced them; use .enableHiveSupport() on the builder for a Hive metastore (Lesson 7.2).

Is a DataFrame the same as a pandas DataFrame?

No. A Spark DataFrame is distributed and lazy; pandas is in one machine’s memory and eager. Lesson 4.6 converts between them.

What is a Dataset?

A typed DataFrame in Scala and Java. In Python there is only the DataFrame, which is a Dataset of Row.

Real-world scenario questions (asked in company interviews)

Any company · PySparkFresher

“SparkSession vs SparkContext?”

Explain the difference between SparkSession and SparkContext.

The interviewer is checking: do you know the entry points?

Show a strong answer

SparkContext is the connection to the cluster used by the RDD API. SparkSession, since Spark 2.0, is the single entry point for DataFrames, SQL and the catalog; it wraps a SparkContext, available as spark.sparkContext. One application has one SparkContext and normally one session.

Avoid: “They are the same thing.”

Data engineeringFresher

What is lazy evaluation in DataFrames?

Why does nothing happen when I run a where and a groupBy?

The interviewer is checking: do you know transformations vs actions?

Show a strong answer
  • Transformations build a logical plan; actions run it.
  • Lazy plans let Catalyst optimise the whole query (pushdown, pruning).
  • In our lab: 0 jobs while building, 2 jobs at show().

Avoid: Saying each line runs immediately like pandas.

Data engineeringMid-level

Settings changed by themselves

Shuffle partitions changed mid-notebook. Why?

The interviewer is checking: do you know getOrCreate semantics?

Show a strong answer
  1. Another builder call with config reached the existing session.
  2. getOrCreate returns the same session and applies runtime SQL settings.
  3. Pass the session to helpers; set config once (spark-submit or job config).

Avoid: Restarting the cluster without finding the cause.

PlatformSenior

Multi-tenant Spark

Many analysts share one Spark server. How do you isolate them?

The interviewer is checking: do you know session isolation limits?

Show a strong answer

  • Shared: executors, cache, global temp views; use scheduler pools or separate apps for resource isolation.
  • Spark Connect gives each client a server-side session.
