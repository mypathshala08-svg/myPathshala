Working with columns

Most DataFrame code is column work: choosing columns, computing new ones, fixing types and filtering rows. This lesson covers the column API, Spark 4’s ANSI casts, the classic filter mistakes, and why a withColumn loop is slow. All outputs are real (PySpark 4.3.0).

2 Definition

Column expressions

Formal definition (write this in exams)

A Column in PySpark is an expression evaluated for every row of a DataFrame: a reference to an input column, a literal (F.lit), or a combination built with operators and functions from pyspark.sql.functions. Column expressions are used in projections (select, withColumn, withColumns), in predicates (where/filter) and in aggregations. Each such transformation returns a new DataFrame whose logical plan must be analysed by Catalyst; projections built in one call produce one plan node, while repeated withColumn calls add one node and one analysis each. Under ANSI mode (default since Spark 4.0), invalid casts and arithmetic overflow raise errors; try_cast and other try_* functions return null instead.

In simple words

A column in your code is a small formula, like amount * 0.05, that Spark applies to every row. You use these formulas to choose, add, change and filter columns. Add many columns in one step, and use try_cast when some values might be bad.

Columns at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A spreadsheet

  • Selecting is hiding the columns you do not need; adding is a new column with a formula; filtering is hiding rows.
  • A formula like =B2*0.05 describes every row at once; a Column expression does the same.
  • Typing a formula into each cell one by one is slow; writing it once for the whole column is fast.

Intermediate The API

  • Name a column: "city", df.city, df["city"], F.col("city"); build expressions with operators and pyspark.sql.functions.
  • select, selectExpr, withColumn, withColumns, withColumnRenamed, drop, cast/try_cast, F.when().otherwise(), where/filter.
  • Combine conditions with &, |, ~ and brackets, never Python and/or.

Advanced What the lab showed

  • With ANSI on, cast("int") failed on 'abc'; try_cast gave null and a sum over 50,001 values.
  • Missing brackets and Python and both raised CANNOT_CONVERT_COLUMN_INTO_BOOL; a typo got a “Did you mean” suggestion.
  • 300 columns: withColumn loop 6.87 s to build, withColumns 0.98 s, one select 0.83 s.

Exam tip: “withColumn in a loop: what is wrong?” Each call returns a new DataFrame and adds a projection to the plan, which Catalyst re-analyses every time; with hundreds of columns this costs seconds to minutes on the driver and can cause StackOverflowError. Use withColumns or a single select (300 columns: 6.87 s vs 0.98 s vs 0.83 s in our lab).

3 Types and ways to use it

Four ways to refer to a column

FormWorks whenWatch out
"city"Most methods accept namesNot for expressions like "amount" * 2
df.cityName is a valid Python identifierFails for order-id; clashes with DataFrame methods (df.count)
df["city"]Any nameBound to that DataFrame: useful to disambiguate joins
F.col("city")Anywhere, even before the DataFrame existsRecommended default

Python’s and, or and not do not work on Columns, and & binds tighter than ==. Always write (F.col("city") == "Pune") & (F.col("amount") > 500) with brackets around each comparison, or use a SQL string: df.where("city = 'Pune' AND amount > 500").

    c = (o.withColumn("amount", F.col("amount").try_cast("int"))
      .withColumn("order_ts", F.try_to_timestamp("order_ts"))

    Using an existing name in withColumn replaces the column; a new name adds one. withColumns added two at once. drop silently ignored a column that does not exist, which is convenient but can hide typos.

  4. Step 4 · when / otherwise

    c = c.withColumn("slot", F.when(F.col("hour") < 11, "breakfast")
                          .when(F.col("hour") < 16, "lunch")
                          .when(F.col("hour") < 22, "dinner")

c.groupBy("slot").count().orderBy("slot").show()
    == 5) when / otherwise +----------+-----+ | slot|count| +----------+-----+ | breakfast|22816| | dinner|12370| |late-night| 4154| | lunch|10662| +----------+-----+
    when conditions are checked in order, like CASE WHEN in SQL. Note that a row whose hour is null (the bad timestamp) matches no condition and lands in otherwise: one of these 4,154 “late-night” orders is really unknown. Handle nulls explicitly when it matters (Lesson 4.4).

    Column and SQL-string filters gave the same 860 Pune orders above ₹500. Without brackets, & was applied first and produced nonsense; with Python and, Python tried to turn a Column into True/False. Both failed with CANNOT_CONVERT_COLUMN_INTO_BOOL.   6. Step 6 · 300 columns: loop vs one call

    d = base
for i in range(300):
    d = d.withColumn(f"c{i}", F.col("id") + i)                      # 300 plans
d = base.withColumns({f"c{i}": F.col("id") + i for i in range(300)})   # one call

    The loop needed 6.87 s on the driver just to build the DataFrame, before any data was read; withColumns needed 0.98 s and one select 0.83 s. The data work (count) was tiny in all three. 6 Real-world use

Column work at companies

1. Type cleaning

Raw string feeds are converted with try_cast and try_to_timestamp; rows that become null go to a quarantine table.

Raw strings→try_cast→Typed table

2. Feature engineering

Config→withColumns→Features

9 Quiz and revision

Check yourself

Quick revision

Lesson 4.3 in one screen

  • Name columns with "c", df.c, df["c"] or F.col("c"); a Column is an expression.
  • select/selectExpr, withColumn/withColumns, withColumnRenamed, drop (ignores missing names).
  • Spark 4 ANSI: cast fails on bad input; try_cast/try_to_timestamp return null.
  • F.when(…).otherwise(…): nulls fall into otherwise.
  • Filters: (a) & (b), |, ~; never Python and/or.
  • Typos fail at analysis with “Did you mean”.
  • 300 columns: loop 6.87 s, withColumns 0.98 s, one select 0.83 s.

Interview and viva questions

Should I turn ANSI mode off after upgrading?

Only as a short-term bridge. ANSI errors reveal bad data that Spark 3 silently turned into nulls; fix them with try_cast and quarantine instead.

Is where() different from filter()?

No, they are aliases.

Is selectExpr slower than functions?

No. Both become the same Catalyst expressions; choose the one your team reads best.

How do I add a constant column?

df.withColumn("source", F.lit("app")). lit wraps a Python value as a Column.

Why does df.count give a method instead of a column?

Attribute access clashes with DataFrame methods. Use F.col("count") or df["count"] for such names.

Real-world scenario questions (asked in company interviews)

Column questions are where interviewers spot real PySpark experience.

Any company · PySparkFresher

“select vs withColumn?”

When do you use select and when withColumn?

The interviewer is checking: do you know projections?

Show a strong answer

select returns exactly the columns you list (and can compute new ones); withColumn keeps all columns and adds or replaces one. For many new columns use withColumns or one select, because each withColumn adds a projection to the plan.

Avoid: “They are the same.”

Data engineeringFresher

Multiple conditions

Filter Pune orders above ₹500.

The interviewer is checking: do you know operator rules?

Show a strong answer
  • df.where((F.col("city") == "Pune") & (F.col("amount") > 500))
  • Or df.where("city = 'Pune' AND amount > 500").
  • Python and/or raise CANNOT_CONVERT_COLUMN_INTO_BOOL.

Avoid: Forgetting brackets.

Data engineeringMid-level

Job fails after Spark 4 upgrade

CAST_INVALID_INPUT appears after upgrading. What do you do?

The interviewer is checking: do you know ANSI mode?

Show a strong answer
  1. Spark 4 enables ANSI: bad casts fail instead of returning null.
  2. Find the bad values; use try_cast where bad input is expected.
  3. Quarantine and monitor nulls; avoid disabling ANSI globally.

Avoid: Setting spark.sql.ansi.enabled=false everywhere.

Data engineeringSenior

Slow driver before jobs start

A job spends minutes before the first Spark job appears.

The interviewer is checking: can you diagnose plan-analysis cost?

Show a strong answer
  • Look for long chains: withColumn loops, many unions, deep plans.
  • Batch columns with withColumns/select; checkpoint very long chains (Lesson 3.3).
  • Measure build time separately from run time.

Avoid: Adding executors.
