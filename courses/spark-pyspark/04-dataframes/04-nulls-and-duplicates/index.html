Nulls and duplicates

Real data has gaps and repeats. This lesson shows how Spark treats null in filters and aggregates, how to drop and fill missing values without damaging your data, and how to remove duplicates so the same rows survive every run. All outputs are real (PySpark 4.3.0).

1 The story

“The numbers don’t add up”

Before you start: columns, when and filters in 4.3.

Marketing asked Kabir how many sign-ups came from outside Pune. He filtered city != 'Pune' and got 1,642. Pune had 404. The export had 2,200 rows. Where were the other 154? And when he removed duplicate users and re-ran the job, the “first sign-up date” changed every time.

Kabir

Arjun Sir

No. 154 rows have no city. For them, city != 'Pune' is neither true nor false, it is null, and a filter keeps only true. That is SQL’s three-valued logic.

Riya

Arjun Sir

dropDuplicates keeps some row per user, not a particular one. Today we find nulls, see how they behave in comparisons and aggregates, drop and fill them correctly, and remove duplicates in a way that gives the same answer every run. All outputs are real (PySpark 4.3.0).

2 Definition

Nulls and duplicates

Formal definition (write this in exams)

In Spark SQL, null represents a missing or unknown value of any type. Comparisons and arithmetic with null yield null (three-valued logic), filters keep only rows whose predicate is true, and aggregate functions such as count(col), sum and avg ignore nulls, while count(*) counts rows. NaN is a distinct floating-point value (“not a number”), not null. DataFrameNaFunctions (df.na) provide drop, fill and replace; fill applies a value only to columns of a compatible type. Duplicates are removed with distinct() (all columns) or dropDuplicates(subset), which keeps an arbitrary row per key and is therefore non-deterministic unless the choice is made explicit, typically with row_number() over a window ordered by a tiebreaker.

In simple words

A null means “we don’t know this value”. Spark skips nulls in sums and averages and treats “unknown = something” as unknown, so filters can quietly leave rows out. Find nulls first, then drop or fill them on purpose. To remove duplicates, decide which copy you want and tell Spark, otherwise it may pick a different one each run.

Nulls and duplicates at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A class register

  • A blank in the register means “we don’t know”, not “absent” and not zero. You cannot say whether that student is from Pune or not.
  • An average of marks counts only students with marks; blanks are left out.
  • If a student is written twice, you must decide which line to keep: the first admission, the latest address?

Intermediate The API

  • Find: isNull(), isNotNull(), F.isnan(), a null count per column. Compare safely: eqNullSafe (<=> in SQL).
  • Fix: df.na.drop(how, thresh, subset), df.na.fill(value or dict), df.na.replace(), F.coalesce(); at read time nullValue="NA".
  • Duplicates: distinct(), dropDuplicates(subset), or a window with row_number() to choose the copy.

Advanced What the lab showed

  • = 'Pune' (404) + != 'Pune' (1,642) missed the 154 null cities; avg(age) 38.9 ignored 118 nulls.
  • na.fill(0) filled only numeric columns, na.fill("unknown") only strings; na.drop() kept just 742 of 2,200 rows.
  • dropDuplicates(["user_id"]) kept 2,000 rows but different ones on each partitioning; row_number() gave the same rows every time.

Exam tip: “Why can count(*) and count(col) differ?” count(*) counts rows; count(col) counts non-null values of that column. In our sign-ups 2,200 rows had 2,082 known ages. The same rule makes avg the average of known values only.

Do not fill nulls just to make them disappear. Filling age with 0 drags the average down; filling city with “unknown” is fine for a report but wrong for a delivery address. Decide per column: drop the row, fill with a meaningful default, or keep the null and handle it downstream.

4 Step by step

Cleaning the sign-up export

All outputs are real: PySpark 4.3.0, local mode, a sign-up export of 2,200 rows (2,000 users) with blanks, NA strings, NaN ratings, 120 exact duplicates from app retries and 80 repeat sign-ups.

  1. Step 1 · Count nulls per column

    raw = spark.read.csv(path, header=True, inferSchema=True)
def nulls(df):
    return df.select([F.sum(F.col(c).isNull().cast("int")).alias(c) for c in df.columns])
nulls(raw).show()
raw.where("city = 'NA'").count(), raw.where(F.isnan("rating")).count()
    == 1) what CSV turns into null root |-- user_id: integer (nullable = true) |-- email: string (nullable = true) |-- phone: long (nullable = true) |-- city: string (nullable = true) |-- referral: string (nullable = true) |-- age: integer (nullable = true) |-- rating: double (nullable = true) |-- signed_up_at: timestamp (nullable = true) +-------+-----+-----+----+--------+---+------+------------+ |user_id|email|phone|city|referral|age|rating|signed_up_at| +-------+-----+-----+----+--------+---+------+------------+ | 0| 0| 77| 93| 850|118| 410| 0| +-------+-----+-----+----+--------+---+------+------------+ city = 'NA' rows: 61 | rating NaN rows: 366
    Empty fields became null, but 61 cities were the text NA and 366 ratings were NaN, neither of which counts as null. Note also that phone was inferred as long: phone numbers should be strings (Lesson 4.2). One select with a null count per column is the first thing to run on any new dataset.

  2. Step 2 · Make all “missing” values null

    s = spark.read.csv(path, header=True, inferSchema=True, nullValue="NA")
nulls(s).show()
s = s.withColumn("rating", F.when(F.isnan("rating"), None).otherwise(F.col("rating")))
    == 2) read again with nullValue="NA" +-------+-----+-----+----+--------+---+------+------------+ |user_id|email|phone|city|referral|age|rating|signed_up_at| +-------+-----+-----+----+--------+---+------+------------+ | 0| 0| 77| 154| 850|118| 410| 0| +-------+-----+-----+----+--------+---+------+------------+ rating NaN still: 366
    nullValue="NA" turned the 61 NA cities into nulls (93 + 61 = 154). NaN is a valid double, so it needed its own step: after the when, rating has 410 + 366 = 776 nulls. Now one rule handles all missing values.

  3. Step 3 · Comparisons with null

    spark.sql("SELECT NULL = NULL AS eq, NULL <=> NULL AS null_safe, NULL > 1 AS gt, NOT NULL AS not_null, NULL AND false AS and_false, NULL OR true AS or_true").show()
s.where(F.col("city") == "Pune").count(); s.where(F.col("city") != "Pune").count()
s.where(F.col("city").isNull()).count()
s.where(~F.col("city").eqNullSafe("Pune")).count()
    == 3) null comparisons +----+---------+----+--------+---------+-------+ | eq|null_safe| gt|not_null|and_false|or_true| +----+---------+----+--------+---------+-------+ |NULL| true|NULL| NULL| false| true| +----+---------+----+--------+---------+-------+ city = 'Pune' : 404 city != 'Pune' : 1642 city is null : 154 total : 2200 NOT eqNullSafe Pune : 1796
    Here is Kabir’s puzzle: 404 + 1,642 = 2,046, and the 154 null cities are in neither, because null != 'Pune' is null and filters keep only true. Use isNull() to find them, or eqNullSafe, which treats null as a normal value: “not Pune” then gives 1,796 = 1,642 + 154.

  4. Step 4 · Aggregates skip nulls

    s.select(F.count("*").alias("rows"), F.count("age").alias("count_age"), F.avg("age").alias("avg_age"),
         F.sum("age").alias("sum_age"), (F.sum("age") / F.count("*")).alias("sum_over_rows")).show()
    == 4) aggregates skip nulls +----+---------+-----------------+-------+------------------+ |rows|count_age| avg_age|sum_age| sum_over_rows| +----+---------+-----------------+-------+------------------+ |2200| 2082|38.85302593659942| 80892|36.769090909090906| +----+---------+-----------------+-------+------------------+
    count("age") counted 2,082 known ages, not 2,200 rows; avg divided by 2,082, giving 38.85. Dividing the sum by all rows gives 36.77, as if missing ages were 0. Both are “correct”; know which question you are answering.

  5. Step 5 · Drop and fill

    s.na.drop().count(); s.na.drop(how="all").count()
s.na.drop(thresh=6).count(); s.na.drop(subset=["city", "phone"]).count()
s.na.fill(0); s.na.fill("unknown")
s.na.fill({"city": "unknown", "referral": "none", "age": -1})
F.coalesce(F.col("phone").cast("string"), F.lit("no phone"))
s.na.replace({"INSTA": "Instagram"}, subset=["referral"])
    == 5) na.drop any : 742 all : 2200 thresh6: 2152 subset : 1971 == 6) na.fill is type-aware fill(0) nulls : {'user_id': 0, 'email': 0, 'phone': 0, 'city': 154, 'referral': 850, 'age': 0, 'rating': 0, 'signed_up_at' … fill('unknown') : {'user_id': 0, 'email': 0, 'phone': 77, 'city': 0, 'referral': 0, 'age': 118, 'rating': 776, 'signed_up_at … fill(dict) referral: ['FRIEND50', 'GOOGLE', 'INSTA', 'none'] coalesce : 77 na.replace : 475
    na.drop() with the default how="any" threw away two thirds of the data (742 left), because almost every row misses something. thresh and subset are what you usually want. na.fill is type-aware: fill(0) touched only numeric columns, fill("unknown") only strings. A dict sets a value per column.

  6. Step 6 · Duplicates, and which row survives

    s.distinct().count(); s.dropDuplicates(["user_id"]).count()
for parts in (1, 3, 7):
    k = s.repartition(parts).dropDuplicates(["user_id"])

6 Real-world use

Data cleaning at work

1. Data profiling

Ingestion jobs record null counts per column every day and alert when a column suddenly has many more.

New file→null counts→Alert

2. Latest version of a record

Change feeds keep the newest row per key with row_number ordered by update time.

Changes→row_number→Current table

3. Retried events

Apps resend events on bad networks; exact copies are removed by event id before counting.

Events→dropDuplicates(id)→True counts

4. Honest reports

Dashboards show an “unknown” category so totals match and data gaps stay visible.

Null city→coalesce("unknown")→Report

5. Model features

Missing values are filled per feature with medians and an is_missing flag, not with zeros.

Features→fill + flag→Training

# Three-valued logic: what a filter keeps
cities = ["Pune", "Delhi", None, "Pune", None, "Mumbai"]

def not_pune(c):
    if c is None:
        return None              # unknown, like SQL NULL
    return c != "Pune"

kept = [c for c in cities if not_pune(c) is True]   # a filter keeps only True
print("= Pune :", sum(c == "Pune" for c in cities))
print("!= Pune:", len(kept))
print("null   :", cities.count(None))
print("total  :", len(cities))

9 Quiz and revision

Check yourself

Quick revision

Lesson 4.4 in one screen

  • Null = unknown. Count nulls per column first; "NA" strings and NaN are not null.
  • Three-valued logic: null != 'Pune' is null, filters drop it (404 + 1,642 ≠ 2,200).
  • isNull(), eqNullSafe / <=>, coalesce().
  • Aggregates skip nulls: count(col) 2,082, avg 38.85.
  • na.drop (how, thresh, subset): default kept only 742 rows. na.fill is type-aware.
  • distinct() = all columns (2,080); dropDuplicates(subset) = keys (2,000).
  • dropDuplicates keeps an arbitrary row; use row_number() with an ordered window.

Interview and viva questions

What is the difference between distinct() and dropDuplicates()?

Without arguments they are the same. dropDuplicates(subset) compares only the listed columns and keeps one arbitrary row per key.

Does dropDuplicates work in streaming?

Yes, with a watermark to bound state; Spark 3.5+ also has dropDuplicatesWithinWatermark (Module 9).

How do nulls sort?

First in ascending order and last in descending by default; use asc_nulls_last etc. (Lesson 4.5).

How do nulls behave in joins?

A null key never matches with ==; use eqNullSafe if nulls should match (Lesson 6.2).

Is it faster to dedup with row_number?

It needs a sort within each key, so it can cost more than dropDuplicates; pay it when you need the same answer every run.

Real-world scenario questions (asked in company interviews)

Null and duplicate questions separate people who have cleaned real data.

Any company · PySparkFresher

“How do you handle nulls?”

How do you find and handle missing values in a DataFrame?

The interviewer is checking: do you know the toolkit?

Show a strong answer

Count nulls per column with one select. Normalise other forms of missing (NA strings, NaN). Then decide per column: na.drop(subset=…), na.fill({…}), coalesce, or keep the null and use null-safe logic. I remember that filters and aggregates silently skip nulls.
