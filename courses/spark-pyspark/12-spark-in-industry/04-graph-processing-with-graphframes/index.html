Graph processing with GraphFrames

How do you analyse relationships at scale? We load referrals as a graph, rank influence, find communities, query patterns and measure hops. All outputs are real.

1 The story

When the question is about relationships

Before you start: 6.2 Joins.

🤔 Asha referred Ravi and Meera; both referred Kabir; Kabir referred Zoya, who referred Asha back. Who is the most influential customer, and which referral groups never touch each other?

That is a graph question, and tables answer it badly. GraphFrames keeps vertices and edges as DataFrames and adds graph algorithms. In our lab PageRank ranked Zoya first (1.799), connected components split 9 customers into 3 communities, a motif query found every two-step referral chain, and shortest paths showed Zoya is 3 hops from Kabir while four customers cannot reach him at all.

  • Graphs as two DataFrames: vertices and edges.
  • Degrees, PageRank, connected components, shortest paths.
  • Motif finding: pattern queries on a graph.

2 Definition

Graph processing with GraphFrames

Formal definition (write this in exams)

GraphFrames is a Spark package that represents a property graph as two DataFrames, vertices (with an id) and edges (with src and dst), and provides graph queries (motif finding, BFS) and algorithms (degrees, PageRank, connected components, label propagation, shortest paths) implemented with DataFrame operations and GraphX. It is the Python-accessible successor to Spark’s Scala-only GraphX API.

In simple words

Put people in one table and their links in another, and GraphFrames can tell you who is most influential, which groups are connected, how many steps apart people are, and which link patterns exist.

Words you’ll meet in this lesson

VertexA node (id).
EdgeA link src → dst.
DegreeNumber of links.
PageRankInfluence score.
ComponentConnected group.
MotifLink pattern query.
LandmarkTarget for shortest paths.
GraphXScala graph API.

Why, how, where

Why

Relationships (who refers whom, which accounts share a device, how places connect) are hard with joins alone: “3 hops away” means 3 self-joins, and influence needs iterative algorithms.

the problem it solves

How

A GraphFrame wraps a vertices DataFrame (column id) and an edges DataFrame (src, dst). Algorithms run as iterative DataFrame jobs (or GraphX underneath): PageRank, connected components (needs a checkpoint directory), shortest paths, label propagation, and motif queries that compile to joins.

the mechanism

Where

Referral and influencer analysis, fraud rings (shared cards, devices, addresses), recommendation graphs, network and route analysis, knowledge graphs.

in real systems

When not

GraphFrames is a separate package (jar + Python), not part of Apache Spark; GraphX is Scala-only. Very large or real-time graph traversals may fit a graph database better.

Dissect a motif

Graphs at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A map of who knows whom

  • People are dots, referrals are arrows. Count arrows (degree), follow arrows (paths), find islands (components), and see who many important people point to (PageRank).

Intermediate The API

  • GraphFrame(vertices, edges) with id and src/dst columns; g.inDegrees, g.outDegrees, g.degrees.
  • g.pageRank(resetProbability=0.15, maxIter=10); g.connectedComponents() (set sc.setCheckpointDir); g.shortestPaths(landmarks=[…]); g.labelPropagation(maxIter); g.bfs(from, to).
  • Motifs: g.find("(a)-[e]->(b); (b)-[]->(c)") returns a DataFrame you can filter like any other.

Advanced Setup and scale

  • Spark 4 package: io.graphframes:graphframes-spark4_2.13 (we used 0.12.3) plus the graphframes-py Python package; add with --packages or spark.jars.
  • Iterative algorithms produce long lineages: checkpoints keep them manageable; cache vertices/edges.
  • GraphX (Scala) is the older RDD graph API; GraphFrames is the DataFrame one usable from Python.

Myth vs reality: things many websites still say

  • Myth: Most referrals = most influential.
    Reality (Spark 4.3): PageRank picked Zoya, not Asha.
    Proof: Step 3.
  • Myth: Spark has a Python graph API built in.
    Reality (Spark 4.3): GraphFrames is a separate package; GraphX is Scala.
    Proof: Level 3.
  • Myth: Shortest paths ignore direction.
    Reality (Spark 4.3): They follow edge direction here.
    Proof: Step 6.

Exam tip: “Graph processing in PySpark?” GraphFrames (vertices id, edges src/dst DataFrames): degrees, pageRank, connectedComponents (checkpoint dir), shortestPaths, labelPropagation, bfs, motif find; package graphframes-spark4; GraphX is Scala-only.

Ask the referral graph

All outputs are real: PySpark 4.3.0, GraphFrames 0.12.3 (graphframes-spark4_2.13), local[2].

  1. Step 1 · Build the graph

    v = spark.createDataFrame([("asha", "customer"), …], "id string, kind string")
e = spark.createDataFrame([("asha", "ravi", "referred"), …], "src string, dst string, relationship string")
g = GraphFrame(v, e)
    == 1) referral graph: 9 customers, 9 referrals
    Two ordinary DataFrames. Tara “referred” herself: a self-loop.

  2. Step 2 · Degrees

    g.inDegrees.join(g.outDegrees, "id", "full").fillna(0)
    == 2) degrees (who refers, who is referred) +-----+--------+---------+ | id|inDegree|outDegree| +-----+--------+---------+ |kabir| 2| 1| | asha| 1| 2| |meera| 1| 1| | neha| 1| 1| | om| 1| 0| +-----+--------+---------+ only showing top 5 rows
    Kabir is referred most (2); Asha refers most (2).

  3. Step 3 · PageRank

    g.pageRank(resetProbability=0.15, maxIter=10).vertices
    == 3) PageRank: most influential customers +-----+--------+ | id|pagerank| +-----+--------+ | zoya| 1.799| |kabir| 1.623| | asha| 1.506| | tara| 1.321| +-----+--------+ only showing top 4 rows
    Zoya ranks first: the cycle zoya → asha → … → kabir → zoya concentrates rank.

  4. Step 4 · Communities

    spark.sparkContext.setCheckpointDir("/tmp/gf-ckpt")
g.connectedComponents()
    == 4) connected components: separate referral communities +-------------+--------------------------------+ |component |members | +-------------+--------------------------------+ |249108103168 |[asha, kabir, meera, ravi, zoya]| |1151051235328|[arjun, neha, om] | |893353197568 |[tara] | +-------------+--------------------------------+
    Three separate communities; component ids are just labels.

  5. Step 5 · Motifs

    g.find("(a)-[]->(b); (b)-[]->(c)").filter("a.id != c.id")
    == 5) motif: chains a -> b -> c (two-step referrals) +-----+-----+-----+ | a| b| c| +-----+-----+-----+ |arjun| neha| om| | asha|meera|kabir| | asha| ravi|kabir| |kabir| zoya| asha| |meera|kabir| zoya| | ravi|kabir| zoya| +-----+-----+-----+ only showing top 6 rows
    Every two-step referral chain, e.g. asha → ravi → kabir.

  6. Step 6 · Shortest paths

    g.shortestPaths(landmarks=["kabir"])
    == 6) shortest paths to kabir (hops) +-----+-------------+ | id|hops_to_kabir| +-----+-------------+ |arjun| NULL| | neha| NULL| | om| NULL| | tara| NULL| |kabir| 0| |meera| 1| | ravi| 1| | asha| 2| | zoya| 3| +-----+-------------+
    Hops to Kabir follow edge direction; NULL means unreachable.

7 Run the code

Run the code: PageRank by hand

Rank flows along edges. Press Run, then try the challenges.

# PageRank by hand on a tiny referral graph
edges = [("asha", "ravi"), ("asha", "meera"), ("ravi", "kabir"), ("meera", "kabir"), ("kabir", "zoya"), ("zoya", "asha")]
nodes = sorted({n for e in edges for n in e})
out = {n: [d for s, d in edges if s == n] for n in nodes}
rank = {n: 1.0 for n in nodes}
for _ in range(20):
    new = {n: 0.15 for n in nodes}
    for s in nodes:
        for d in out[s]:
            new[d] += 0.85 * rank[s] / len(out[s])
    rank = new
for n, r in sorted(rank.items(), key=lambda x: -x[1]):
    print(f"{n:6s} {r:.3f}")
kabir 1.256 zoya 1.218 asha 1.185 meera 0.670 ravi 0.670
  • new[d] += 0.85 * rank[s] / len(out[s])Each node shares its rank among its out-links.
  • new = {n: 0.15 for n in nodes}resetProbability 0.15.

Interview and viva questions

Is GraphFrames part of Spark?

No, it is a separate open-source package; add it with --packages or spark.jars.

Can I use SQL on results?

Yes, every result is a DataFrame.

How large can graphs be?

Billions of edges on a cluster for batch analytics; use a graph database for low-latency traversals.

Undirected graphs?

Add edges both ways or use algorithms that ignore direction (components).
