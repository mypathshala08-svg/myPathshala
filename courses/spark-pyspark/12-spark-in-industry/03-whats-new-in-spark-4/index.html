What’s new in Spark 4

Spark 4 changed defaults and added a lot. This lesson tours Spark 4.0 to 4.3 on PySpark 4.3.0: ANSI mode and safe try_ functions, modern SQL (pipes, variables, collations, scripting), Python UDTFs and data sources, geospatial types and ASOF JOIN, with an upgrade checklist. 1 The story

“The upgrade broke our job, and we found 10 new features”

Before you start: Spark SQL in 7.1, VARIANT in 6.5, Spark Connect in 11.3, platforms in 12.1.

When TiffinGo moved from Spark 3.5 to Spark 4, one nightly job failed on the first run with CAST_INVALID_INPUT: a column of phone numbers contained “N/A”. In Spark 3 that row had silently become NULL for years. The same week, engineers discovered they could now write loops in SQL and their own data sources in pure Python.

Kabir

Sir, why would Spark break working code?

Arjun Sir

Spark 4 turned on ANSI SQL mode by default. Invalid casts and division by zero now raise errors instead of producing NULL, which hid bad data. The fix is explicit: try_cast, try_divide, or cleaning the data.

Riya

And the new features?

Arjun Sir

Spark 4.0 to 4.3 added a lot: VARIANT, Spark Connect as a first-class client, pipe syntax, SQL scripting, Python UDTFs and data sources, geospatial types, real-time streaming. Today we run a tour of them on PySpark 4.3.0. All outputs are real.

2 Definition

Spark 4: what changed

Formal definition (write this in exams)

Apache Spark 4.0 (2025) started a new major version that removed old platforms (Java 8/11, Scala 2.12, Mesos) and changed defaults, most visibly enabling ANSI SQL mode (spark.sql.ansi.enabled=true), so invalid operations such as overflow, division by zero and malformed casts raise errors rather than returning NULL. It added the VARIANT type for semi-structured data, string collations, SQL pipe syntax, session variables, SQL UDFs, Python user-defined table functions and a Python Data Source API, and made Spark Connect a central client architecture. Spark 4.1 made SQL scripting generally available, added recursive CTEs, Spark Declarative Pipelines and Real-Time Mode for Structured Streaming; 4.2 added geospatial types and change-data-capture APIs; 4.3 (October 2026, the first quarterly feature release) added ASOF joins, JSON_TABLE, UNNEST and stateful Real-Time Mode.

In simple words

Spark 4 is stricter by default (bad data raises errors instead of becoming NULL) and adds many features: semi-structured data, case-insensitive text comparison, SQL loops and variables, new ways to write Python functions and data sources, and a client-server mode. Each release since adds more SQL and streaming features.

Spark 4 at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A new car model

  • Stricter safety system: it refuses to start if a seatbelt is broken (ANSI errors) instead of driving anyway.
  • New dashboard and controls (SQL scripting, pipe syntax), a remote-control key (Spark Connect), and a faster engine options list each year.

Intermediate What to know

  • 4.0: ANSI default, Java 17+, Scala 2.13, VARIANT, collations, pipe syntax, session variables, SQL UDFs, Python UDTF and Data Source APIs, Spark Connect improvements.
  • 4.1: SQL scripting GA, recursive CTEs, Spark Declarative Pipelines, Real-Time Mode for streaming.
  • 4.2: GEOMETRY/GEOGRAPHY types, CDC APIs, Arrow-optimised Python UDFs by default. 4.3: ASOF JOIN, JSON_TABLE, UNNEST, stateful Real-Time Mode, quarterly releases.

Advanced What the lab showed

  • 1/0 and CAST('12a' AS INT) failed; try_divide/try_cast returned NULL; ANSI off brought back silent NULLs.
  • A SQL WHILE loop computed 1000; a recursive CTE summed 1..5 = 15.
  • ASOF JOIN worked only after enabling its flag.

Exam tip: “What changed in Spark 4?” Biggest behaviour change: ANSI SQL mode on by default, so bad casts, overflow and division by zero fail instead of returning NULL (use try_cast/try_divide). Platform: Java 17+, Scala 2.13. Features: VARIANT, collations, pipe syntax, session variables and SQL UDFs, Python UDTFs and data sources, Spark Connect; 4.1 added SQL scripting and Declarative Pipelines, 4.2 geospatial types and CDC, 4.3 ASOF joins and stateful real-time streaming.

Do not “fix” an ANSI upgrade by globally setting spark.sql.ansi.enabled=false. It brings back silent NULLs (our lab: 1/0 and CAST('12a') both became NULL) and hides the bad data that the error just found. Handle the specific expressions with try_cast/try_divide and route invalid rows to a quarantine table. Also note new opt-in features such as ASOF JOIN are disabled by default and may not exist on your platform yet (Lesson 12.1).

4 Step by step

A tour of Spark 4 on 4.3.0

All outputs are real: PySpark 4.3.0, local[2]. Each statement ran through spark.sql (or the Python APIs); errors show the error class.

  1. Step 1 · ANSI mode by default

    SELECT 1/0;
SELECT CAST('12a' AS INT);
SELECT try_cast('12a' AS INT);
SELECT try_divide(1, 0);
SET spark.sql.ansi.enabled = false;  SELECT 1/0, CAST('12a' AS INT);
    Spark 4.3.0 | ansi: true == 4.0 ANSI by default SELECT 1/0: ERROR [DIVIDE_BY_ZERO] CAST('12a' AS INT): ERROR [CAST_INVALID_INPUT] try_cast('12a' AS INT): [(None,)] try_divide(1, 0): [(None,)] ANSI off: 1/0, CAST('12a'): [(None, None)]
    The two classic silent failures of Spark 3 now stop the query with DIVIDE_BY_ZERO and CAST_INVALID_INPUT. When NULL is really what you want, say so with try_cast and try_divide. With ANSI turned off, both quietly returned NULL: the behaviour that hid the “N/A” phone numbers for years.

  2. Step 2 · Pipe syntax, variables, collations

    FROM o |> WHERE amount > 100 |> AGGREGATE sum(amount) AS total GROUP BY city |> ORDER BY city;
DECLARE VARIABLE min_amt INT DEFAULT 250;
SELECT city, amount FROM o WHERE amount >= min_amt;
SELECT city COLLATE UTF8_LCASE AS c, sum(amount) FROM o GROUP BY 1;
    == 4.0 SQL: pipe syntax, session variables, collation pipe syntax: [('MUMBAI', 200), ('Mumbai', 300), ('Pune', 450)] session variable: [] use variable: [('Mumbai', 300), ('Pune', 450)] collation UTF8_LCASE: [('Mumbai', 500), ('Pune', 450)] default collation: [('MUMBAI', 200), ('Mumbai', 300), ('Pune', 450)]
    Pipe syntax reads top to bottom like a DataFrame chain (Lesson 7.1). A session variable parameterises SQL without string formatting. With the default binary collation, “Mumbai” and “MUMBAI” are different cities; with UTF8_LCASE they group together: 500.

  3. Step 3 · SQL scripting and recursive CTEs (4.1)

    BEGIN
  DECLARE total INT DEFAULT 0;
  DECLARE i INT DEFAULT 1;
  WHILE i <= 4 DO SET total = total + i * 100; SET i = i + 1; END WHILE;
  SELECT total;
END;
WITH RECURSIVE r(n) AS (SELECT 1 UNION ALL SELECT n + 1 FROM r WHERE n < 5) SELECT sum(n) FROM r;
    == 4.1 SQL scripting (GA, on by default) script: [(1000,)] recursive CTE: [(15,)]
    Procedural logic, previously only possible in Python or Scala around Spark, now runs in SQL: variables, a WHILE loop, and a final result (100+200+300+400 = 1000). Recursive CTEs walk hierarchies such as category trees or referral chains (1+2+3+4+5 = 15).

  4. Step 4 · Python UDTFs and Python data sources

    @udtf(returnType="item string, qty int")
class SplitItems:
    def eval(self, order: str):
        for part in order.split(","):
            name, qty = part.split(":"); yield name.strip(), int(qty)

class Menu(DataSource):
    @classmethod
    def name(cls): return "menu"
    def schema(self): return "dish string, price int"
    def reader(self, schema): return MenuReader()
spark.dataSource.register(Menu); spark.read.format("menu").load()
    == 4.0 Python UDTF and Python data source UDTF: [('dosa', 2), ('idli', 3), ('vada', 1)] Python data source: [('Masala Dosa', 120), ('Pav Bhaji', 140)]
    A UDTF turns one input value into many rows: one order string became three item rows. A Python data source lets you add spark.read.format("menu") for any API or file type, in pure Python, with no Java connector. Both used to require Scala or awkward workarounds.

  5. Step 5 · Geospatial (4.2) and new SQL (4.3)

    SHOW FUNCTIONS LIKE 'st_*';
SELECT typeof(st_geomfromwkb(X'0101…')), st_srid(st_geomfromwkb(X'0101…'));
SELECT jaro_winkler_similarity('Biryani House', 'Biriyani House');
SELECT * FROM UNNEST(array(10, 20, 30)) AS t(x);
SET spark.sql.join.asofJoin.enabled = true;
SELECT o.t, s.surge FROM orders_t o ASOF JOIN surge_t s MATCH_CONDITION (o.t >= s.t) ON o.city = s.city;
    == 4.2 geospatial, 4.3 new SQL ST functions available: [('st_asbinary',), ('st_geogfromwkb',), ('st_geomfromwkb',), ('st_setsrid',), ('st_srid',)] GEOMETRY from WKB point: [('geometry(0)', 0)] jaro_winkler_similarity: [(0.947,)] to_base32: [('KREUMRSJJY======',)] UNNEST in FROM: [(10,), (20,), (30,)] ASOF JOIN (enabled): [(10, 1.0), (25, 1.5)] ASOF JOIN (off by default): ERROR [UNSUPPORTED_FEATURE.ASOF_JOIN]
    Spark now has a native GEOMETRY type; our 4.3 build exposed a first set of st_ functions working from WKB. jaro_winkler_similarity finds near-duplicate restaurant names (0.947). ASOF JOIN matches each order with the latest surge price at or before its time (10 → 1.0, 25 → 1.5), but only after enabling its flag; by default it fails with UNSUPPORTED_FEATURE.ASOF_JOIN.

7 Run the code

Run the code: ANSI mode

Why the upgrade broke the job, in plain Python. Press Run, then try the challenges.

# ANSI mode vs legacy behaviour, modelled in Python
def cast_int(s, ansi=True):
    try:
        return int(s)
    except ValueError:
        if ansi:
            raise ValueError(f"[CAST_INVALID_INPUT] '{s}' cannot be cast to INT")
        return None                      # Spark 3 default: silent NULL

def try_cast_int(s):
    try:
        return int(s)
    except ValueError:
        return None

phones = ["9820012345", "N/A", "9822254321"]
print("legacy :", [cast_int(p, ansi=False) for p in phones])
print("try_cast:", [try_cast_int(p) for p in phones])
try:
    print("ANSI   :", [cast_int(p) for p in phones])
except ValueError as e:
    print("ANSI   : ERROR", e)
legacy : [9820012345, None, 9822254321] try_cast: [9820012345, None, 9822254321] ANSI : ERROR [CAST_INVALID_INPUT] 'N/A' cannot be cast to INT
  • return None # Spark 3 default: silent NULLSpark 3 (ANSI off) turned bad values into NULL without telling anyone.
  • print("ANSI :", [cast_int(p) for p in phones])Spark 4 (ANSI on) raises CAST_INVALID_INPUT, exposing the bad row.

Interview and viva questions

Can I turn ANSI mode off?

Yes (spark.sql.ansi.enabled=false), but it restores silent NULLs; use it only as a short bridge while fixing queries.

Is Spark 5 coming?

The 4.x line continues with quarterly feature releases from 4.3; follow the Apache Spark news page for plans.

What are Spark Declarative Pipelines?

A 4.1+ framework where you declare datasets and flows in Python or SQL, and Spark handles ordering, checkpoints and retries.

Do these features exist on my platform?

Only if its runtime includes that Spark version; see Lesson 12.1 for November 2026 versions.

Where do I learn about each new release?

The release notes at spark.apache.org/releases and the Spark docs’ migration guides.
