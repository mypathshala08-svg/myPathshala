2 Definition

A PySpark installation and a standalone cluster

Formal definition (write this in exams)

A PySpark installation consists of the pyspark Python package (which, when installed from PyPI, bundles the Spark runtime JARs and launch scripts), a supported Java runtime and a supported Python interpreter. Spark can run in local mode inside one JVM, or connect to a cluster manager. A Spark standalone cluster is Spark’s own cluster manager: a master process accepts applications and allocates resources, and worker processes on each machine launch executors. A history server reconstructs the web UI of finished applications from event logs. For PySpark, the driver and all executors must use compatible Python environments with the same minor version and the same libraries.

In simple words

Install Java and pip install pyspark to run Spark on your computer. For a practice cluster, run Spark’s master, workers and history server as Docker containers from one image, so every part uses the same versions.

Installing Spark at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Two set-ups

  • Laptop: install Java 17 or 21, then pip install pyspark==4.3.0. Run Python scripts or the pyspark shell.
  • Docker cluster: install Docker, build one image, run docker compose up -d. You get a master, two workers and a history server.
  • Both run the same Spark code; the master URL decides where it runs.

Intermediate What is inside

  • The pip package contains the whole Spark distribution: 280 JAR files (462 MB), spark-submit, pyspark, spark-class, the start scripts.
  • The image adds Python 3.12 and a Java 21 runtime; containers differ only in the command they run (Master, Worker, HistoryServer).
  • Shared folders: ./data (datasets), ./jobs (your scripts), ./events (event logs for the history server).

Advanced What the lab showed

  • A first SparkSession took 6–15 s to start on the lab machine; the cluster’s first job took 20.6 s end to end, mostly executor start-up.
  • A driver on Python 3.13 with executors on 3.12 ran DataFrame code fine but failed on a Python lambda with [PYTHON_VERSION_MISMATCH].
  • pandas 3 triggered a PySpark warning, so the image pins pandas<3.

Exam tip: “How do you set up PySpark locally?” Install Java 17 or 21, pip install pyspark (which bundles Spark), and run with master local[*]. For a multi-node practice environment, run Spark standalone (master + workers) in Docker or use a managed service; keep Python versions identical on driver and executors.

  8. Step 8 · Break it on purpose: Python versions

    spark = (SparkSession.builder.master("spark://localhost:7077")
         .config("spark.driver.host", "172.19.0.1").getOrCreate())
print("DataFrame count on the cluster:", spark.range(1000).count())
print(spark.sparkContext.parallelize(range(10), 2).map(lambda x: x * 2).sum())
    DataFrame count on the cluster: 1000 ERROR TaskSetManager: Task 0 in stage 3.0 failed 4 times; aborting job [PYTHON_VERSION_MISMATCH] Python in worker has different version: 3.12 than that in driver: 3.13, PySpark cannot run with different minor versions. Please check environment variables PYSPARK_PYTHON and PYSPARK_DRIVER_PYTHON are correctly set.
    DataFrame operations run entirely in the executors’ JVMs, so the count worked. The lambda must run in a Python worker on each executor, which here was Python 3.12, while the driver was 3.13. Spark retried the task 4 times, then failed. Fix: use the same Python minor version everywhere (our image), or set PYSPARK_PYTHON to a matching interpreter on the executors.

Interview and viva questions

Do I need Docker for this course?

For most lessons, pip install pyspark is enough. Docker is needed for lessons that show cluster behaviour: executors, failures, the master UI and the history server.

Which Java should I install?

Java 17 or 21; the lab uses 21 (Eclipse Temurin). Java 8 and 11 do not work with Spark 4.

How much memory does the lab need?

About 6–8 GB free for the cluster (two workers with 2 GiB each plus the driver and the containers). Reduce worker memory in cluster.yml on smaller machines.

Can I use the official apache/spark image instead?

Yes, but check its Spark, Java and Python versions. The 3.5.6 image we had in the lab came with Java 11 and Python 3.8, too old for Spark 4; that is why we built our own.

Is Spark standalone used in production?

Sometimes, for small dedicated clusters. Most production Spark runs on YARN, Kubernetes or managed services (Lesson 11.2). The concepts you practise here are the same.

Install Java 17 or 21, create a virtual environment, pip install pyspark with a pinned version (plus pandas and pyarrow if needed), then create a SparkSession with master local[*] and run a smoke test. The UI is on port 4040 while the application runs.

Data engineeringMid-level

PYTHON_VERSION_MISMATCH

A job fails with PYTHON_VERSION_MISMATCH on the cluster.

The interviewer is checking: can you fix environments?

Show a strong answer
  1. Driver and executor Python minor versions differ.
  2. Use the same image or interpreter everywhere, or set spark.pyspark.python / PYSPARK_PYTHON.
  3. Ship dependencies as a packed environment if the cluster cannot be changed.

Avoid: Reinstalling pyspark on the laptop only.

PlatformMid-level

UI disappears after the job

The team cannot see the Spark UI of last night’s failed job.

The interviewer is checking: do you know the history server?

Show a strong answer
  • Enable spark.eventLog.enabled with a shared spark.eventLog.dir.
  • Run a history server reading that directory (port 18080).
  • Set retention and cleaning for the logs.

Avoid: Asking people to keep the driver running.

ArchitectureSenior

Standardise Spark environments

Ten teams run Spark on laptops, CI and Kubernetes with different versions.

The interviewer is checking: can you design for consistency?

Show a strong answer
  • One base image per Spark version with Java, Python and core libraries pinned; teams extend it.
  • Same image for notebooks, CI and cluster jobs; masters set by configuration, not code.
  • Upgrade by publishing a new image and testing jobs against it.

Avoid: Letting every team pick versions freely.
