What is Apache Spark? From MapReduce to Spark 4

Spark is the most widely used engine for big data processing. This lesson explains what Spark is, what it is made of, and why it replaced MapReduce for most work. Instead of only describing the components, we run five of them on the same 5,000,000 TiffinGo orders and measure what in-memory processing changes. All outputs are real.

2 Definition

What Apache Spark is

Formal definition (write this in exams)

Apache Spark is an open-source, distributed engine for large-scale data processing. A Spark application consists of a driver that plans the work and executors that run tasks in parallel on partitions of the data, on a single machine or on a cluster managed by Spark standalone, YARN or Kubernetes. Spark keeps intermediate data in memory where possible, recovers lost work from the recorded lineage of each dataset, and provides unified APIs in Python, Scala, Java, SQL and R for batch processing (Spark SQL and DataFrames), streaming (Structured Streaming), machine learning (MLlib) and remote clients (Spark Connect).

In simple words

Spark is a free engine that processes big data on many machines at once. It keeps data in memory when it can, so it is fast, and the same engine does SQL, Python data work, machine learning and streaming.

Words you’ll meet in this lesson

DriverThe process that runs your program and plans the work.
ExecutorA worker process that runs tasks and can cache data.
RDDResilient Distributed Dataset: Spark’s original low-level API.
DataFrameA distributed table; the main API since Spark 2.
CatalystSpark SQL’s query optimizer.
In-memoryKeeping data in RAM between steps instead of writing it to disk.
LineageThe recorded steps that built a dataset; used to recompute lost data.
Spark ConnectA client–server protocol so thin clients can use a remote Spark.

Spark at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A big, fast shared kitchen

  • One head chef (the driver) splits a huge order into small dishes (tasks).
  • Many cooks (executors) prepare them at the same time.
  • Ingredients already chopped stay on the counter (memory) instead of going back to the store-room (disk).

Intermediate What Spark is made of

  • Spark Core: scheduling, memory, fault tolerance, the RDD API.
  • Spark SQL / DataFrames: the main API today, optimised by the Catalyst optimizer; the pandas API on Spark sits on top.
  • Structured Streaming, MLlib, Spark Connect (remote clients) and, since 4.1, Declarative Pipelines. GraphX and the old DStreams API are legacy.

Advanced What the lab showed

  • SQL, DataFrame and pandas-API code gave the same city totals on 5,000,000 orders; KMeans and a streaming query ran in the same session.
  • Three questions on a 2,000,000-row CSV took 6.6 s uncached and 1.6 s after cache().
  • Spark 4 SQL pipe syntax and the VARIANT type worked out of the box in 4.3.0.

Exam tip: “What is Apache Spark and why is it faster than MapReduce?” A distributed, in-memory data processing engine with unified APIs for SQL, streaming, ML and graphs. It is faster mainly because it keeps intermediate data in memory and builds an optimised plan (DAG) for the whole job, instead of writing to disk after every map and reduce step.

“100× faster than Hadoop” comes from old benchmarks of iterative, in-memory workloads. For a single scan of data on disk, Spark and Hive on Tez can be close. In our lab, caching made repeated questions 4× faster, not 100×. Measure your own jobs.

4 Step by step

One engine, five components, one dataset

All outputs are real: PySpark 4.3.0 in local mode on the course lab machine, using orders_big: 5,000,000 generated TiffinGo orders in 8 Parquet files (Lesson 1.5 shows how it was made).

  1. Step 1 · Spark SQL

    orders = spark.read.parquet("orders_big").where("status = 'DELIVERED'")
orders.createOrReplaceTempView("orders")
spark.sql("SELECT city, COUNT(*) AS orders FROM orders GROUP BY city ORDER BY orders DESC LIMIT 3").show()
    +---------+------+ | city|orders| +---------+------+ | Mumbai|951430| |Bengaluru|949842| | Chennai|476038| +---------+------+
    Plain SQL on a temporary view. Anyone from the Hive course can use Spark from the first day. The SQL runs on the same engine as everything that follows.

  2. Step 2 · The DataFrame API

    from pyspark.sql import functions as F
orders.groupBy("city").agg(F.round(F.avg("amount"), 2).alias("avg_amount")).orderBy("city").show(3)
    +---------+------+ | city|orders| +---------+------+ | Mumbai|951430| |Bengaluru|949842| | Chennai|476038| +---------+------+ 2) DataFrame API +---------+----------+ | city|avg_amount| +---------+----------+ |Bengaluru| 508.68| | Chennai| 509.85| | Delhi| 509.35| +---------+----------+ only showing top 3 rows
    The same kind of question as Python method calls. DataFrame code and SQL compile to the same plan in Catalyst, so neither is faster; choose what reads better for the task.

  3. Step 3 · pandas API on Spark

    import pyspark.pandas as ps
pdf = orders.pandas_api()
print(pdf.groupby("city")["amount"].sum().sort_values(ascending=False).head(3))
    city Mumbai 484935971 Bengaluru 483166030 Chennai 242708114 Name: amount, dtype: int64
    pandas syntax, Spark execution: pdf is distributed, not in local memory. Mumbai’s total (484,935,971) matches the SQL view. Useful for porting pandas code; for new code most teams use DataFrames.

  4. Step 4 · MLlib

    from pyspark.ml.feature import VectorAssembler
from pyspark.ml.clustering import KMeans
sample = orders.sample(fraction=0.01, seed=1).select("amount")
vec = VectorAssembler(inputCols=["amount"], outputCol="features").transform(sample)
model = KMeans(k=3, seed=1).fit(vec)
print(sorted(round(float(c[0]), 1) for c in model.clusterCenters()))
    order-size clusters (centres): [210.4, 511.8, 810.5]
    K-means found three order sizes (about ₹210, ₹512 and ₹811) on a 1% sample. K-means repeats passes over the data until the centres stop moving: exactly the iterative workload where keeping data in memory matters most.

  5. Step 5 · Structured Streaming

    q = (spark.readStream.format("rate").option("rowsPerSecond", 5).load()
     .writeStream.format("memory").queryName("ticks").start())
time.sleep(6); q.stop()
print(spark.sql("SELECT COUNT(*) FROM ticks").first()[0])
    rows received in ~6 s: 25
    A test source generating 5 rows per second, written to an in-memory table: 25 rows arrived before we stopped it (the first micro-batch starts after a short delay). The same DataFrame operations work on streams; Module 9 uses Kafka.

  6. Step 6 · Why in-memory matters

    def three_questions(df):
    df.groupBy("city").count().collect()
    df.agg(F.avg("amount")).collect()
    df.where("amount > 900").count()

src = spark.read.csv("big_csv", header=True).withColumn("amount", F.col("amount").cast("int"))
three_questions(src)                      # timed
cached = src.cache(); cached.count()
three_questions(cached)                   # timed
    without cache: 6.6 s (CSV parsed 3 times) with cache : 1.6 s (rows kept in executor memory)
    Without caching, every question re-read and re-parsed the 2,000,000-row CSV. After cache(), the parsed rows stayed in executor memory and the same three questions took about a quarter of the time. MapReduce has no equivalent: each job starts from disk. Caching is covered properly in Lesson 3.1.

  7. Step 7 · Spark 4 features, live

    FROM orders
|> WHERE status = 'CANCELLED'
|> AGGREGATE COUNT(*) AS cancelled GROUP BY city
|> ORDER BY cancelled DESC
|> LIMIT 3;

SELECT v:restaurant::string AS restaurant, v:items[0].dish::string AS first_dish, v:rating::double AS rating
FROM (SELECT parse_json('{"restaurant":"Desai Mess","items":[{"dish":"Idli","qty":2}],"rating":4.8}') AS v);
    +---------+---------+ | city|cancelled| +---------+---------+ |Bengaluru| 50373| | Mumbai| 49775| | Delhi| 25047| +---------+---------+ +----------+----------+------+ |restaurant|first_dish|rating| +----------+----------+------+ |Desai Mess| Idli| 4.8| +----------+----------+------+
    Two Spark 4.0 additions that work in 4.3.0: SQL pipe syntax (|>), which reads top to bottom in the order the steps run, and the VARIANT type, which stores JSON efficiently and extracts fields with paths like v:items[0].dish. Lesson 12.3 covers what is new in Spark 4.x.

Run the code: memory versus disk

These programs model why Spark’s in-memory processing matters, using timings close to the lab’s. Press Run, then try the challenges.

# Why in-memory matters: model the cost of repeated passes (lab numbers)
read_and_parse = 2.0      # seconds to read + parse the CSV once (approx. from our lab)
answer = 0.2              # seconds to answer one question once data is ready
questions = 3

no_cache = questions * (read_and_parse + answer)
with_cache = read_and_parse + questions * answer
print(f"no cache  : {no_cache:.1f} s")
print(f"with cache: {with_cache:.1f} s   ({no_cache / with_cache:.1f}x faster)")
no cache : 6.6 s with cache: 2.6 s (2.5x faster)
  • no_cache = questions * (read_and_parse + answer)Every action re-reads the source, like MapReduce jobs or uncached Spark.
  • with_cache = read_and_parse + questions * answerRead once, then answer from executor memory.

9 Quiz and revision

Check yourself

Quick revision

Lesson 1.2 in one screen

  • Spark: open-source, distributed, in-memory engine; driver plans, executors run tasks.
  • Components: Spark SQL/DataFrames (main), pandas API, Structured Streaming, MLlib, Spark Connect, Declarative Pipelines (4.1); RDDs low-level; DStreams/GraphX legacy.
  • History: AMPLab 2009 → Apache TLP 2014 → 2.0 (2016) → 3.0 (2020) → 4.0 (May 2025) → 4.3.0 (30 Oct 2026).
  • Faster than MapReduce mainly through memory and whole-job DAG planning; biggest gains for iterative work.
  • Lab: same city totals via SQL, DataFrame and pandas API; cache: 6.6 s → 1.6 s.
  • Spark 4: ANSI default, pipe syntax |>, VARIANT, Java 17+.
  • Not always Spark: small data → pandas/Polars/DuckDB; interactive BI → Trino; ms latency → Flink.

Interview and viva questions

Is Spark a database?

No. Spark processes data stored elsewhere (files, object storage, databases, Kafka). With a catalogue such as the Hive metastore or Unity Catalog it can manage tables, but storage stays in files.

Does Spark replace Hadoop?

It replaced MapReduce for most processing. HDFS and YARN can still be Spark’s storage and cluster manager; many companies now use object storage and Kubernetes instead.

Is Spark only for Python?

No. Scala, Java, SQL and R are also supported (SparkR is deprecated in Spark 4). PySpark is the most popular way to use Spark today, which is why this course uses it.

What is Databricks?

A company founded by Spark’s creators that offers a managed Spark platform with extras (Delta Lake, Unity Catalog, Photon). Apache Spark itself is free and open source.

Why does a tiny job take seconds?

Starting the JVM, scheduling tasks and planning queries have fixed costs. Our first SparkSession took about 15 s to start on the lab machine. Spark is built for data where that overhead is small compared with the work.

Real-world scenario questions (asked in company interviews)

“What is Spark?” is the first question in nearly every data engineering interview.

Any company · SparkFresher

“What is Apache Spark?”

Explain Spark in one minute.

The interviewer is checking: can you be precise and brief?

Show a strong answer

Spark is an open-source distributed engine for large-scale data processing. A driver plans work as a DAG and executors run tasks in parallel on partitions, keeping data in memory where possible. One engine covers SQL and DataFrames, streaming and machine learning, on a laptop, YARN, Kubernetes or managed cloud services.

Avoid: “Spark is a faster Hadoop database.”

Data engineeringFresher

Spark vs MapReduce

Why did Spark replace MapReduce?

The interviewer is checking: do you know the real reasons?

Show a strong answer
  • In-memory processing between steps; MapReduce writes to disk after each map/reduce.
  • Whole-job DAG optimisation and a rich API (SQL, DataFrames, Python).
  • One engine for batch, streaming and ML.

Avoid: Only quoting “100× faster”.

Data engineeringMid-level

Caching decision

A notebook runs 10 queries on the same filtered DataFrame and is slow.

The interviewer is checking: do you know when to cache?

Show a strong answer
  1. Each action recomputes from the source.
  2. Cache the filtered DataFrame, trigger it once, check the Storage tab.
  3. Unpersist when done; do not cache everything.

Avoid: Caching every DataFrame by default.

ArchitectureSenior

Choose an engine

Teams ask for Spark for every new dataset.

The interviewer is checking: can you weigh alternatives?

Show a strong answer
  • Spark for large ETL, ML feature pipelines and streaming to tables.
  • Single-machine engines for small data; Trino/warehouses for interactive SQL; Flink for very low latency.
  • Standardise on shared table formats so engines can be mixed.

Avoid: “Spark for everything” without size or latency analysis.
