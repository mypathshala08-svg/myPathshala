2 Definition

What you need before PySpark

Formal definition (write this in exams)

PySpark is the Python API for Apache Spark. A PySpark program is ordinary Python that builds descriptions of computations (DataFrames, SQL queries, RDD operations); Spark’s engine, which runs on the Java Virtual Machine, turns them into tasks that run in parallel over partitions of the data. Working with PySpark therefore requires Python programming (functions, lambdas, collections), SQL (relational operations and data types, under Spark’s ANSI-compliant rules), a supported Java runtime (Java 17 or 21 for Spark 4.x), and the concepts of distributed data processing: data split into partitions or blocks, work spread over executors, and data moved between machines in a shuffle.

In simple words

PySpark lets you write Spark programs in Python. Python describes the work, Spark (running on Java) does it in parallel. So you need Python, SQL, Java installed, and the idea of splitting data over many machines.

Prerequisites at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner What you need to know

  • Python: variables, lists, dictionaries, functions, lambda, loops.
  • SQL: SELECT … WHERE … GROUP BY … ORDER BY, joins, data types.
  • Basic Linux: running a command, setting an environment variable, reading an error.
  • Spark needs Java installed even when you only write Python.

Intermediate Why each one matters in PySpark

  • Spark’s API is functional: filter, map, reduce and groupBy are the same ideas as in plain Python, applied to data on many machines.
  • DataFrames are SQL tables in disguise: every df.groupBy() becomes a SQL plan, and Spark 4 follows ANSI SQL rules for types and casts.
  • Your Python program only drives a Java process (through Py4J); without Java, nothing starts.
  • Spark reads files in partitions, the same idea as HDFS blocks: one task per partition.

Advanced What the lab showed

  • No Java: JAVA_HOME is not set, then [JAVA_GATEWAY_EXITED].
  • One row with amount = abc made the whole column a string in both pandas and Spark; an ANSI cast failed with CAST_INVALID_INPUT, try_cast returned NULL.
  • An 87 MiB file became 2 partitions on a 2-core laptop, not 1: Spark sizes splits from the cores too, not only from a block size.

Exam tip: “What are the prerequisites for PySpark?” Python (functions, lambdas, collections), SQL, a Java runtime (Java 17 or 21 for Spark 4), and distributed-computing basics such as partitions, parallel tasks and shuffles. Pandas experience helps, because the DataFrame API is similar, but Spark is lazy and distributed.

    Spark 4.x needs Java 17 or 21 and, since Spark 4.1, Python 3.10 or newer. pandas and PyArrow are optional, but many PySpark features (toPandas(), pandas UDFs, the pandas API on Spark) use them. Our pandas is 3.0.5, and PySpark warned on import: PySpark does not yet fully support pandas >= 3.0.0. Some features may not work correctly. It is recommended to use pandas < 3.0.0 for now.   2. Step 2 · What happens without Java

    from pyspark.sql import SparkSession
spark = SparkSession.builder.master("local[1]").getOrCreate()
    JAVA_HOME is not set PySparkRuntimeError: [JAVA_GATEWAY_EXITED] Java gateway process exited before sending its port number.
    We ran the same Python with Java removed from the PATH. The Python package was fine; the error came from the launcher script (JAVA_HOME is not set) and then from PySpark, because the Java process it starts in the background never came up. If you see JAVA_GATEWAY_EXITED, check Java first.

  3. Step 3 · The Python you need: filter, map, reduce, group

    from functools import reduce
orders = [("Mumbai", 530), ("Pune", 210), ("Mumbai", 480), ("Delhi", 990), ("Pune", 120)]
big = list(filter(lambda o: o[1] >= 300, orders))           # keep orders of 300 or more
gst = list(map(lambda o: (o[0], round(o[1] * 0.05, 2)), big)) # 5% GST on each
total = reduce(lambda a, b: a + b, [g for _, g in gst])       # add them up
by_city = {}
for city, amt in orders:                                      # group by city
    by_city[city] = by_city.get(city, 0) + amt
    filter : [('Mumbai', 530), ('Mumbai', 480), ('Delhi', 990)] map : [('Mumbai', 26.5), ('Mumbai', 24.0), ('Delhi', 49.5)] reduce : 100.0 groupBy: {'Mumbai': 1010, 'Delhi': 990, 'Pune': 330}
    These four patterns are the heart of Spark. filter and map work on each row independently, so Spark can run them on every partition at once. reduce and grouping need rows from different partitions to meet, which is what a shuffle does. If lambda o: o[1] >= 300 reads naturally to you, you are ready for RDDs in Module 2.

  4. Step 4 · The same question in pandas and PySpark

    import pandas as pd
pdf = pd.read_csv("orders.csv")
print("pandas dtypes:", dict(pdf.dtypes.astype(str)))
pdf["amount"] = pd.to_numeric(pdf["amount"], errors="coerce")
print(pdf.groupby("city")["amount"].sum().sort_values(ascending=False).head(3))

Another row has a date in 31/10/2026 21:20 format, so order_ts is a string too. Knowing your data types is a prerequisite, not an extra.

  5. Step 5 · SQL types under ANSI rules

    print("spark.sql.ansi.enabled =", spark.conf.get("spark.sql.ansi.enabled"))
df.select(F.sum(F.col("amount").cast("double"))).show()            # strict cast
df.select(F.sum(F.col("amount").try_cast("double")).alias("total"),
          F.count_if(F.col("amount").try_cast("double").isNull()).alias("bad_rows")).show()
    spark.sql.ansi.enabled = true org.apache.spark.SparkNumberFormatException: [CAST_INVALID_INPUT] The value 'abc' of the type "STRING" cannot be cast to "DOUBLE" because it is malformed. … +----------+--------+ | total|bad_rows| +----------+--------+ |1.472139E7| 1| +----------+--------+
    Since Spark 4.0, ANSI mode is on by default: a cast that cannot succeed stops the job, as in a standard SQL database. In Spark 3 the same cast silently returned NULL. try_cast gives NULL on purpose, and count_if tells you how many rows failed (1). Your SQL knowledge carries over directly; just expect strictness.

  6. Step 6 · Hadoop’s block idea, Spark’s partitions

    for mb in (128, 32, 8):
    spark.conf.set("spark.sql.files.maxPartitionBytes", f"{mb}m")
    n = spark.read.csv("big_csv", header=True).rdd.getNumPartitions()
    print(f"maxPartitionBytes={mb:>3} MiB -> {n:>2} partitions (= tasks in the first stage)")
    input: 87 MiB in 1 files maxPartitionBytes=128 MiB -> 2 partitions (= tasks in the first stage) maxPartitionBytes= 32 MiB -> 3 partitions (= tasks in the first stage) maxPartitionBytes= 8 MiB -> 11 partitions (= tasks in the first stage)
    On HDFS a file is cut into 128 MB blocks. Spark cuts input into partitions, and the first stage runs one task per partition. With the 128 MiB default our 87 MiB file still became 2 partitions, because Spark also divides the input by the number of cores (2 here) so that every core gets work. Partitions return in Lessons 1.4, 2.4 and 8.1.

  7. Step 7 · When does pandas stop being enough?

    df = pd.read_csv("orders.csv")
print(df.memory_usage(deep=True).sum() / 2**20, "MiB")
    file on disk : 2.9 MiB in pandas : 5.0 MiB (1.7x the file) rows: 50,002
    pandas loads everything into one process’s memory: here 1.7 times the file size (pandas 3 stores strings compactly; with older pandas it is often 3–5×). One laptop with 16 GB therefore handles a few GB comfortably. TiffinGo’s six months are tens of GB, and growing. Spark splits the data so no single machine needs to hold it all. For data that fits on one machine, pandas, Polars or DuckDB are often simpler (Lesson 12.2).

7 Run the code

Run the code: Spark’s ideas in plain Python

PySpark itself cannot run in the browser, but its core ideas can. These programs use plain Python with the same logic as the lesson’s Spark examples. Press Run, then try the challenges.

# Spark's core patterns in plain Python (this runs in your browser)
from functools import reduce
orders = [("Mumbai", 530), ("Pune", 210), ("Mumbai", 480), ("Delhi", 990), ("Pune", 120)]

big = list(filter(lambda o: o[1] >= 300, orders))
gst = list(map(lambda o: (o[0], round(o[1] * 0.05, 2)), big))
total = reduce(lambda a, b: a + b, [g for _, g in gst])

by_city = {}
for city, amt in orders:
    by_city[city] = by_city.get(city, 0) + amt

print("filter :", big)
print("map    :", gst)
print("reduce :", total)
print("groupBy:", by_city)
filter : [('Mumbai', 530), ('Mumbai', 480), ('Delhi', 990)] map : [('Mumbai', 26.5), ('Mumbai', 24.0), ('Delhi', 49.5)] reduce : 100.0 groupBy: {'Mumbai': 1010, 'Pune': 330, 'Delhi': 990}
  • big = list(filter(lambda o: o[1] >= 300, orders))Like df.where(F.col("amount") >= 300): each row is checked on its own.
  • total = reduce(lambda a, b: a + b, [g for _, g in gst])Like F.sum(): values from all rows are combined, which in Spark needs data from every partition.

9 Quiz and revision

Check yourself

Quick revision

Lesson 1.1 in one screen

  • PySpark = Python API; the engine runs on the JVM (Py4J bridge). No Java → JAVA_GATEWAY_EXITED.
  • Spark 4.x: Java 17 or 21; Spark 4.1+: Python 3.10+. pandas 3 triggered a warning in PySpark 4.3: pin pandas<3.
  • filter/map work per row (parallel); group/reduce need rows to meet (shuffle).
  • pandas and PySpark gave the same city totals; both read amount as string because of one bad row.
  • ANSI mode is on by default: bad casts fail (CAST_INVALID_INPUT); try_cast returns NULL.
  • Input is split into partitions; one task per partition. Split size depends on maxPartitionBytes and cores.
  • pandas holds data in one process (1.7× the CSV here); beyond one machine’s memory, use Spark.

Interview and viva questions

Do I need to know Scala or Java?

No. You need Java installed, not Java skills. Reading a Java stack trace helps, because Spark errors often contain one; the useful line is usually the first one with an error class such as CAST_INVALID_INPUT.

Do I need Hadoop installed?

No. PySpark from pip includes the Hadoop client libraries it needs and runs on your local file system. Knowing HDFS and YARN helps when you deploy on a Hadoop cluster (Lesson 11.2).

Is pandas knowledge required?

Helpful, not required. The DataFrame API has similar ideas, and Spark offers a pandas API (pyspark.pandas) for pandas-style code on a cluster.

Which Python version should I use?

A supported version that is the same on your laptop, the driver and all executors. Lesson 1.5 shows the error when the driver uses 3.13 and executors use 3.12.

Can I use Windows?

Yes, with Java and Python installed; writing files may additionally need Hadoop’s winutils on Windows. The course lab uses Docker, which works the same on Windows, macOS and Linux (Lesson 1.5).

Real-world scenario questions (asked in company interviews)

Prerequisite questions open most PySpark interviews.

Any company · PySparkFresher

“What is PySpark?”

Explain PySpark and what it needs.

The interviewer is checking: do you understand the Python/JVM split?

Show a strong answer

PySpark is Spark’s Python API. My Python code builds DataFrame or SQL operations; Spark’s engine on the JVM plans and runs them as parallel tasks over partitions. It needs Python, a Java 17/21 runtime and the pyspark package; on a cluster, the same Python version on every node.

Avoid: Saying PySpark is a Python re-implementation of Spark.

Data engineeringFresher

pandas vs PySpark

When would you use PySpark instead of pandas?

The interviewer is checking: can you reason about data size?

Show a strong answer
  • pandas: data fits comfortably in one machine’s memory; eager, simple.
  • PySpark: data larger than one machine, or the same job must scale; lazy and distributed.
  • For medium data on one machine, Polars or DuckDB are also good choices.

Avoid: “PySpark is always faster.”

Data engineeringMid-level

Job fails after upgrade with CAST_INVALID_INPUT

A Spark 3 job fails on Spark 4 with CAST_INVALID_INPUT.

The interviewer is checking: do you know ANSI mode?

Show a strong answer
  1. Spark 4 enables ANSI mode by default; invalid casts now fail instead of returning NULL.
  2. Use try_cast where bad values are expected, count and quarantine them.
  3. Avoid disabling ANSI globally; it hides data problems.

Avoid: Setting spark.sql.ansi.enabled=false everywhere.

PlatformMid-level

“Java gateway process exited”

A teammate gets JAVA_GATEWAY_EXITED when creating a SparkSession.

The interviewer is checking: can you debug the environment?

Show a strong answer
  • Check java -version and JAVA_HOME: Spark 4 needs Java 17 or 21.
  • Check that pyspark and the Java version match and that no old SPARK_HOME points elsewhere.
  • Run a smoke test: spark.range(5).count().

Avoid: Reinstalling Python first.
