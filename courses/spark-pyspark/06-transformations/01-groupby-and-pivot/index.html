groupBy and pivot

Module 6 covers the transformations used in almost every pipeline. First: aggregations. This lesson builds a city report with groupBy, explains partial aggregation, subtotals with rollup/cube, and reshapes data with pivot and unpivot. All outputs are real (PySpark 4.3.0).

1 The story

“One row per city, one column per status”

Before you start: reduceByKey vs groupByKey in 2.4, nulls in 4.4.

The operations head wants a daily sheet: one row per city with orders, revenue, average bill, customers and cancellations, and a second sheet with delivered, cancelled and refunded revenue side by side. Riya wrote it with groupBy and pivot. It worked, but the REFUNDED column was missing and the job ran more Spark jobs than she expected.

Riya

Sir, there are refunded orders in the app. Why no column?

Arjun Sir

Pivot without a value list first runs a query to find the distinct values, and in this data set there were none. Give the list yourself: the column is always there, and Spark skips that extra query.

Kabir

And groupBy on 5 million rows: is it one big shuffle?

Arjun Sir

A smaller one than you think: Spark adds up inside each partition first. Today: aggregates, partial aggregation, null keys, rollup and cube, pivot and its limits, unpivot and collecting lists. All outputs are real (PySpark 4.3.0).

2 Definition

Grouping, pivoting and unpivoting

Formal definition (write this in exams)

groupBy returns a GroupedData object whose agg computes aggregate functions over the rows of each group of equal key values; null keys form a group of their own. Spark executes most aggregations in two phases: a partial aggregation within each input partition, a shuffle by the grouping keys, and a final merge, so only partial results cross the network. rollup and cube compute additional grouping sets (hierarchical subtotals, or all combinations) with nulls marking the rolled-up columns. pivot(col, values) rotates distinct values of a column into output columns of an aggregation; if values are not given, Spark first computes them with a separate query and limits them to spark.sql.pivotMaxValues (10,000). unpivot (also melt) performs the reverse, turning columns into rows.

In simple words

groupBy puts rows with the same key together and computes totals, counts or averages per group. Spark adds things up inside each partition first, so the shuffle is small. pivot turns values into columns, unpivot turns columns back into rows. Give pivot its list of values.

Aggregation at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Counting votes

  • Each polling booth counts its own votes first, then sends only totals to the centre. That is partial aggregation.
  • A pivot is turning the result list (party, votes) into a table with one column per party.
  • Blank ballots still form a pile of their own: nulls are a group.

Intermediate The API

  • df.groupBy(cols).agg(F.count, F.sum, F.avg, F.countDistinct, F.collect_list…); rollup and cube add subtotals.
  • groupBy(k).pivot(col, [values]).agg(…); unpivot(ids, values, name, value) (alias melt, Spark 3.4+).
  • Conditional counts: F.sum(F.when(cond, 1).otherwise(0)) or F.count_if(cond).

Advanced What the lab showed

  • The plan aggregated twice: partial_sum per partition, shuffle, final sum.
  • Pivot without values ran 4 extra jobs and took 2.72 s; with values, 0 extra jobs and 1.30 s, and the empty REFUNDED column existed.
  • Pivot on order_id failed: more than 10,000 distinct values (spark.sql.pivotMaxValues).

Exam tip: “Why should you pass values to pivot?” Without them Spark runs an extra query over the data to find distinct values (4 extra jobs in our lab, 2.72 s vs 1.30 s), the output columns depend on the data (a missing status means a missing column), and more than 10,000 values fails. With a list, the schema is fixed and the extra pass disappears.

In rollup and cube results a NULL in a key column means “all values” (a subtotal), but a real null key also shows as NULL. Use F.grouping("city") or grouping_id() to tell them apart, or replace null keys with "unknown" before grouping.

6 Real-world use

Aggregations at work

1. Daily KPI tables

Orders, revenue, average bill and cancellations per city and day are one groupBy over the fact table.

Orders→groupBy + agg→KPI table

2. Spreadsheet-style reports

Status or month columns for finance sheets are pivots with a fixed value list.

Long table→pivot(values)→Wide sheet

3. Hierarchical totals

Region → city → restaurant totals for management reports come from rollup or GROUPING SETS.

Facts→rollup→Subtotals

4. Customer features

Per-customer counts, sums and favourite cities feed churn and recommendation models.

Orders→groupBy customer→Features

5. Tidying wide files

Wide spreadsheets from partners (one column per month) are unpivoted into long tables.

Wide CSV→unpivot→Long table

7 Run the code

Run the code: two-phase aggregation

A model of the plan in Step 2. Press Run, then try the challenges.

# Partial aggregation: what crosses the network?
partitions = [
    [("Pune", 450), ("Delhi", 300), ("Pune", 520)],
    [("Pune", 380), ("Delhi", 610)],
]
partials = []
for p in partitions:                      # step 1: inside each partition
    acc = {}
    for city, amount in p:
        acc[city] = acc.get(city, 0) + amount
    partials.append(acc)
print("sent over the shuffle:", partials)

final = {}
for acc in partials:                      # step 2: after the shuffle
    for city, s in acc.items():
        final[city] = final.get(city, 0) + s
print("final:", final)
sent over the shuffle: [{'Pune': 970, 'Delhi': 300}, {'Pune': 380, 'Delhi': 610}] final: {'Pune': 1350, 'Delhi': 910}

9 Quiz and revision

Check yourself

Quick revision

Lesson 6.1 in one screen

  • groupBy(...).agg(...): many aggregates in one job; null keys form a group.
  • Two-phase plan: partial_sum per partition → shuffle → final sum.
  • Conditional counts: sum(when(...)) or count_if.
  • rollup (hierarchy) and cube (all combinations); NULL = subtotal; use grouping_id.
  • Pivot with a value list: no extra jobs (2.72 → 1.30 s), stable columns.
  • Pivot limit 10,000 values; unpivot/melt reverses.
  • collect_list/collect_set for small groups only.

Interview and viva questions

Is groupBy().agg() the same as SQL GROUP BY?

Yes, they produce the same plan. Use whichever is clearer; spark.sql works on temp views.

How do I aggregate with several conditions?

Use several count_if/sum(when()) expressions in one agg, or FILTER clauses in SQL: count(*) FILTER (WHERE status = 'CANCELLED').

Why are my aggregate column names like sum(amount)?

Default names; use .alias() on each aggregate.

Can I pivot on two columns?

Pivot takes one column; combine two into one with concat_ws, or pivot then join.

Is countDistinct expensive?

Yes, it must shuffle distinct values. For dashboards consider approx_count_distinct (Lesson 4.5).
