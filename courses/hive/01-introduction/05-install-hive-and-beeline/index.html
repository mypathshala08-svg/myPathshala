2 Definition

A Hive deployment and its client

Formal definition (write this in exams)

A Hive deployment consists of HiveServer2 (the service that accepts, compiles and executes HiveQL from clients over Thrift/JDBC/ODBC), a Hive Metastore service (which stores table and partition metadata in a relational database such as PostgreSQL, MySQL or the embedded Derby), a storage layer for table data (HDFS, object storage or a local file system) and an execution engine (normally Apache Tez on YARN). Beeline is the command-line JDBC client used to connect to HiveServer2 with a URL of the form jdbc:hive2://host:port/database.

In simple words

To use Hive you need a server that runs your SQL (HiveServer2), a catalogue of tables (the metastore and its database), a place for the files, and a client to type into (Beeline). Docker lets you start all of them on one laptop with one command.

Words you’ll meet in this lesson

ContainerA running, isolated copy of an image: one program with everything it needs. Starts in seconds, removed without trace.
ImageThe packaged program a container is started from, for example apache/hive:4.2.1.
Docker ComposeA YAML file listing several containers, their settings and how they connect; started with docker compose up -d.
PortA numbered door on a machine. 10000 = HiveServer2, 10002 = its web UI, 9083 = metastore, 5432 = Postgres.
VolumeStorage that Docker keeps outside a container, so data survives when the container is recreated.
JDBC URLThe address a client uses to reach HiveServer2: jdbc:hive2://localhost:10000/default.
schematoolHive’s tool that creates or upgrades the metastore tables inside the database.
BeelineHive’s SQL shell. Interactive, or with -e "SQL" and -f file.hql for scripts.

Your Hive lab at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A café with a counter

  • Beeline is you at the counter, placing an order (a SQL statement).
  • HiveServer2 is the cashier and kitchen: it takes the order, plans it and cooks it.
  • The metastore is the menu book: what dishes (tables) exist and where the ingredients (files) are kept.
  • Postgres is the cupboard where the menu book is stored, so it survives the night.
  • Docker is the building: it lets the whole café open with one key and close without leaving a mess.

Intermediate What runs where

  • apache/hive:4.2.1 is the official image. One image, two roles, chosen with SERVICE_NAME=metastore or SERVICE_NAME=hiveserver2.
  • On first start the metastore container runs schematool, which creates the metastore schema in Postgres (84 tables in our run, schema version 4.2.0).
  • HiveServer2 listens on 10000 (Thrift/JDBC) and serves a web UI on 10002. The metastore listens on 9083.
  • Table data goes to a Docker volume mounted at /opt/hive/data/warehouse; our own files are mounted at /data.
  • Beeline connects with jdbc:hive2://localhost:10000/. In Hive 4 the old hive shell command also starts Beeline.

Advanced How the lab differs from production

  • Storage: the lab uses the local file system (file:///); production uses HDFS or object storage (S3, GCS, ADLS). Same SQL, different LOCATION scheme.
  • Engine: the image sets tez.local.mode=true, so Tez tasks run inside the HiveServer2 JVM. On a cluster the Tez AM and tasks run in YARN containers.
  • Security: no authentication (any user name works). Production uses LDAP or Kerberos, TLS and Ranger policies (Module 10).
  • High availability: one of each here; production runs several HiveServer2 and metastore instances registered in ZooKeeper, and the JDBC URL uses serviceDiscoveryMode=zooKeeper.
  • Metastore mode: our lab is a remote metastore (a separate service on 9083). The single-container quick start uses an embedded Derby database inside HiveServer2: fine for one learner, never for a team.

Exam tip: “Name the components needed to run Hive and the default ports.” HiveServer2 (10000, web UI 10002), Hive Metastore (9083) with its RDBMS (Derby embedded, or MySQL/PostgreSQL for production), storage (HDFS/object store) and an execution engine (Tez on YARN). Mention Beeline as the JDBC client and the URL jdbc:hive2://host:10000/db.

Tutorials written for Hive 1 and 2 use the old hive shell that talked to the metastore directly, skipping HiveServer2. In Hive 4 that shell is removed: hive starts Beeline, and hive -e "SQL" without a URL fails with Cannot run commands specified using -e. No current connection. Always use beeline -u ….

4 Step by step

Install the lab and run your first query

Every output below was recorded from a real run of Hive 4.2.1 on 26 October 2026. Your times and container ids will differ.

  1. Step 1 · Install Docker

    Windows or macOS: install Docker Desktop (on Windows it uses WSL 2). Linux: install Docker Engine and the compose plugin. Then check (your versions may be newer):

    docker --version
docker compose version
    Docker version 29.9.2, build a82e528 Docker Compose version v5.6.1
    Give Docker at least 4 GB of RAM (Settings → Resources). Our three containers used about 1.6 GB together when idle: HiveServer2 1.17 GB, metastore 348 MB, Postgres 102 MB.

  2. Step 2 · Get the files

    Make a folder hive-lab with three things: the compose file below, the Postgres JDBC driver postgresql-42.7.4.jar (from Maven Central) and a data folder for your CSV files.

    services:
  postgres:
    image: postgres:16
    container_name: hms-db
    environment:
      POSTGRES_DB: metastore_db
      POSTGRES_USER: hive
      POSTGRES_PASSWORD: hivepw
    volumes: [hms-db:/var/lib/postgresql/data]
  metastore:
    image: apache/hive:4.2.1
    container_name: metastore
    depends_on: [postgres]
    environment:
      SERVICE_NAME: metastore
      DB_DRIVER: postgres
      SERVICE_OPTS: >-
        -Xmx1G -Djavax.jdo.option.ConnectionDriverName=org.postgresql.Driver
        -Djavax.jdo.option.ConnectionURL=jdbc:postgresql://postgres:5432/metastore_db
        -Djavax.jdo.option.ConnectionUserName=hive -Djavax.jdo.option.ConnectionPassword=hivepw
    ports: ["9083:9083"]
    volumes:
      - warehouse:/opt/hive/data/warehouse
      - ./postgresql-42.7.4.jar:/opt/hive/lib/postgres.jar
      - ./data:/data
  hiveserver2:
    image: apache/hive:4.2.1
    container_name: hiveserver2
    depends_on: [metastore]
    environment:
      SERVICE_NAME: hiveserver2
      IS_RESUME: "true"
      SERVICE_OPTS: "-Xmx1G -Dhive.metastore.uris=thrift://metastore:9083"
    ports: ["10000:10000", "10002:10002"]
    volumes:
      - warehouse:/opt/hive/data/warehouse
      - ./data:/data
volumes:
  hms-db:
  warehouse:
    One image, apache/hive:4.2.1, is used twice: SERVICE_NAME decides whether the container becomes the metastore or HiveServer2. IS_RESUME: "true" tells HiveServer2 not to initialise a schema itself.

  3. Step 3 · Start the three containers

    docker compose -p hivelab up -d
docker compose -p hivelab ps
    NAME IMAGE STATUS PORTS hiveserver2 apache/hive:4.2.1 Up 7 minutes 0.0.0.0:10000->10000/tcp, 9083/tcp, 0.0.0.0:10002->10002/tcp hms-db postgres:16 Up 7 minutes 5432/tcp metastore apache/hive:4.2.1 Up 3 minutes 10000/tcp, 0.0.0.0:9083->9083/tcp, 10002/tcp
    On the first start the metastore container runs schematool -initOrUpgradeSchema against Postgres. HiveServer2 accepts connections after roughly 20–60 seconds; before that you get Connection refused.

  4. Step 4 · Connect with Beeline

    docker exec -it hiveserver2 beeline -u jdbc:hive2://localhost:10000/ -n hive
    Connecting to jdbc:hive2://localhost:10000/ Connected to: Apache Hive (version 4.2.1) Driver: Hive JDBC (version 4.2.1) Transaction isolation: TRANSACTION_REPEATABLE_READ Beeline version 4.2.1 by Apache Hive 0: jdbc:hive2://localhost:10000/>
    Beeline runs inside the hiveserver2 container here, so localhost is correct. The prompt 0: jdbc:hive2://…> shows the connection number and URL. -n hive is the user name; the lab has no password.

  5. Step 5 · Describe 50,002 orders as a table

    CREATE EXTERNAL TABLE orders_raw (
  order_id INT, customer_id INT, restaurant_id INT, city STRING,
  order_ts TIMESTAMP, amount INT, payment STRING, status STRING)
ROW FORMAT DELIMITED FIELDS TERMINATED BY ','
LOCATION 'file:///data/tiffingo/orders';
SHOW TABLES;
    +-------------+ | tab_name | +-------------+ | orders_raw | +-------------+
    Copy orders.csv into data/tiffingo/orders/ first. No data is copied by CREATE: Hive only records the columns, the delimiter and the folder in the metastore. file:/// means the container’s own disk; on a cluster you would write an HDFS or S3 path.

  6. Step 6 · Ask a real question

    SELECT city, COUNT(*) AS orders FROM orders_raw
WHERE city IN ('Pune','Thane') GROUP BY city ORDER BY city;
    +--------+---------+ | city | orders | +--------+---------+ | Pune | 7931 | | Thane | 4820 | +--------+---------+ 2 rows selected (1.573 seconds)
    This query runs a Tez DAG (Map 1 → Reducer 2 → Reducer 3) in local mode. The Tez counters printed in the log show RECORDS_IN_Map_1: 50002: every row was read, then filtered.

  7. Step 7 · Look behind the screen: the metastore row

    docker exec hms-db psql -U hive -d metastore_db \
  -c 'SELECT "TBL_ID","TBL_NAME","TBL_TYPE","OWNER" FROM "TBLS";'
    TBL_ID | TBL_NAME | TBL_TYPE | OWNER --------+------------+----------------+------- 1 | orders_raw | EXTERNAL_TABLE | hive (1 row)
    Your CREATE TABLE became one row in the Postgres table TBLS (plus rows in SDS for the location and COLUMNS_V2 for the columns). Only look here to learn: never edit metastore tables by hand.
5 See it happen

Lab start-up: seven frames from up -d to a result

Left: the real terminal output. Right: which container is doing the work, and what changes in the metastore database.

From docker compose up to your first answer 7 steps
What you see
  1. Riya starts the lab. Docker reports three containers started.
  2. The metastore container’s log shows schematool creating the metastore schema in Postgres.
  3. HiveServer2 logs that it has started and opened the web UI on 10002.
  4. Beeline connects. The prompt shows connection 0 and the JDBC URL.
  5. She creates an external table over the order folder. It returns at once.
  6. Her first query counts orders for Pune and Thane: 7,931 and 4,820, from 50,002 rows read.
  7. In Postgres she finds the row Hive wrote for her table.
Behind the screen
  1. Docker starts Postgres, then the metastore, then HiveServer2 (depends_on). Running is not the same as ready.
  2. schematool connects to Postgres and creates the metastore tables (84 in this run) and records schema version 4.2.0.
  3. HiveServer2 binds port 10000 for clients and 10002 for the web UI, and connects to the metastore on 9083.
  4. Beeline opens a JDBC session: protocol hive2, host localhost, port 10000, database default.
  5. CREATE EXTERNAL TABLE adds rows in TBLS, SDS and COLUMNS_V2 through the metastore. The CSV file is not touched.
  6. SELECT is compiled into a Tez DAG of three vertices that runs in local mode inside HiveServer2.
  7. The catalogue is ordinary rows in Postgres. This is why the metastore database must be backed up.

Three live scenarios follow: choosing a metastore mode, fixing connection errors, and using Beeline in scripts.

Real-time scenario 1

Embedded Derby or a remote metastore?

The quick-start container is tempting. See what happens when a second engine needs the tables, or when the container is removed.

Metastore modes 5 steps
Animated example
  1. The single-container quick start runs HiveServer2 with an embedded Derby database inside it.
  2. A Spark job cannot reach that catalogue: embedded Derby has no service port to connect to.
  3. Removing the container deletes the metastore with it. Data files in a mounted folder survive, but every table definition is lost.
  4. A remote metastore on port 9083 with Postgres behind it is shared by HiveServer2, Spark and other engines.
  5. Use the single container only for quick experiments; use a remote metastore for the course and for real work.
Real-time scenario 2

JDBC URLs and “Connection refused”

Most first-day problems are connection problems. Read the URL, then fix the most common error.

Connecting 5 steps
Animated example
  1. A JDBC URL names the driver (hive2), the host, the port, the database and optional settings after semicolons.
  2. A real error from our lab: port 10001 has no listener, so the connection is refused.
  3. Check the port, whether the container is running, whether HiveServer2 has finished starting, and which host name applies.
  4. On your PC, localhost reaches the published port. Containers reach each other by service name.
  5. With the right URL Beeline connects. Commands that start with ! (like !tables and !quit) are Beeline’s own, not SQL.
Real-time scenario 3 · advanced

Beeline in scripts: output formats and files

Analysts read the table format; programs need CSV or JSON. These outputs are from the lab.

Beeline switches 5 steps
Animated example
  1. The default table format is easy to read but awkward for programs.
  2. With --silent=true and --outputformat=csv2 the output is clean CSV that can be redirected to a file.
  3. tsv2, vertical and json are also available. vertical is handy for wide rows.
  4. beeline -f runs a whole .hql script; schedulers use the exit code to detect failures.
  5. Remember the six switches: -u, -n, -e, -f, --silent and --outputformat, plus --hivevar for variables.
6 Real-world use

Where a laptop lab and Beeline show up at work

1. A safe place to try things

Before running a risky ALTER TABLE or a new partition scheme on the shared cluster, engineers try it in a local Docker lab with a small copy of the data. Breaking a laptop lab costs nothing.

Idea→Local lab→Shared cluster

2. Testing SQL in CI

A team keeps its HiveQL in Git. On every pull request the CI pipeline starts the Hive containers, runs each script with beeline -f on sample data and compares the output with expected results.

Pull request→Hive in Docker→Merge

3. BI tools on Hive

A dashboard in a BI tool connects to HiveServer2 with the Hive ODBC/JDBC driver and the same host and port 10000. For interactive dashboards, teams often add a faster engine reading the same metastore.

Dashboard→JDBC/ODBC :10000→HiveServer2

4. Scheduled jobs

Airflow or cron runs beeline -u … --hivevar run_date=2026-10-31 -f daily.hql every night. If a statement fails, Beeline exits with a non-zero code and the scheduler marks the task failed and retries or alerts.

Scheduler→beeline -f→Alert on failure

5. Who is running what?

The HiveServer2 web UI on port 10002 lists open sessions, running and recent queries and their elapsed time. Support engineers use it to find the query that is slowing everyone down.

Slow cluster→Web UI :10002→Talk to the owner

Examples are simplified. Company setups differ.

7 Run the code

Run the code: JDBC URLs, ports and Beeline output

Beeline itself needs Java and a server, so the browser exercises practise the skills around it: reading a JDBC URL, checking which port is which, turning Beeline’s CSV output into numbers and planning memory for the lab. Press Run, then try the challenges.

# Read a Hive JDBC URL the way Beeline does
url = "jdbc:hive2://localhost:10000/tiffingo;ssl=false;transportMode=binary"

prefix, rest = url.split("://", 1)
hostport, _, path = rest.partition("/")
host, _, port = hostport.partition(":")
db, *opts = path.split(";")
options = dict(o.split("=", 1) for o in opts)

print("driver  :", prefix)
print("host    :", host)
print("port    :", int(port))
print("database:", db or "default")
print("options :", options)
driver : jdbc:hive2 host : localhost port : 10000 database: tiffingo options : {'ssl': 'false', 'transportMode': 'binary'}
  • prefix, rest = url.split("://", 1)jdbc:hive2 selects the Hive JDBC driver. hive2 means HiveServer2 (the old HiveServer1 is long gone).
  • host, _, port = hostport.partition(":")Host and port: where HiveServer2 is listening. 10000 is the default for binary (Thrift) mode.
  • db, *opts = path.split(";")Settings come after semicolons, for example ssl=true or transportMode=http;httpPath=cliservice.

Quick revision

Lesson 1.5 in one screen

  • A Hive deployment = HiveServer2 (10000, web UI 10002) + Metastore (9083) + its RDBMS + storage + engine (Tez).
  • Lab: docker compose up -d starts Postgres, metastore, hiveserver2 from image apache/hive:4.2.1; SERVICE_NAME picks the role.
  • Connect: beeline -u jdbc:hive2://localhost:10000/ -n hive. URL = driver · host · port · database · ;options.
  • Metastore modes: embedded (Derby, one process) · local · remote (service on 9083, shared by many engines).
  • CREATE EXTERNAL TABLE … LOCATION writes metadata only (rows in TBLS, SDS, COLUMNS_V2); data files are not copied.
  • Beeline: -e one statement, -f script, --silent=true, --outputformat=csv2|tsv2|vertical|json, --hivevar, !tables, !quit.
  • “Connection refused” → wrong port, container down, or not ready yet. Inside Docker use service names, from your PC use localhost.
  • In Hive 4 the old CLI is removed: hive starts Beeline.

Interview and viva questions

Do I need Hadoop installed to practise Hive?

Not for this course. The apache/hive image includes the Hadoop and Tez libraries it needs and runs Tez in local mode with the local file system as storage. You learn the same HiveQL, metastore and plans. On a real cluster the SQL is the same; only the storage paths (hdfs:// or s3a://) and the place where tasks run (YARN) differ.

Why Postgres for the metastore and not the built-in Derby?

Derby in embedded mode can be used by only the one process that embeds it and disappears with its container. A separate database such as PostgreSQL or MySQL can be shared by a metastore service that HiveServer2, Spark and Trino all use, and can be backed up. Production deployments always use an external database.

What is the difference between Beeline and the old Hive CLI?

Beeline is a JDBC client: it connects to HiveServer2, which applies security, sessions and resource management. The old CLI ran the compiler inside the user’s own process and talked to the metastore directly, bypassing HiveServer2 and its security. The old CLI is deprecated and removed in Hive 4; the hive command now starts Beeline.

My first query took longer than the next ones. Why?

The first query in a session opens a Tez session (“Tez session hasn’t been created yet. Opening session”), which starts the Tez application master. Later queries in the same session reuse it. Each new beeline -e command opens a new session, so scripts that run many statements should use -f with one file.

How do I stop and restart the lab without losing my tables?

Use docker compose -p hivelab stop and docker compose -p hivelab start (or up -d). The metastore lives in the Postgres volume hms-db and managed table data in the warehouse volume, so both survive. docker compose down -v deletes the volumes, and with them every table definition and managed table.

Options to a dictionary

Parse the options of jdbc:hive2://hs2:10001/sales;transportMode=http;httpPath=cliservice;ssl=true into a dictionary.

P7Business problem

Laptop or cloud for a training batch?

A batch of 40 students each needs about 2 GB RAM for the lab. Laptops have 8 GB. A cloud VM with 16 GB costs Rs 12 per hour and fits 6 students. For 30 hours of practice, what does the cloud cost if laptops are not used?

Input
40 students · 6 per VM · Rs 12/hour · 30 hours
Expected output
VMs: 7 | cost: Rs 2520
Show solution and explanation 
import math
students, per_vm, rate, hours = 40, 6, 12, 30
vms = math.ceil(students / per_vm)
print("VMs:", vms, "| cost: Rs", vms * rate * hours)
VMs: 7 | cost: Rs 2520

How it works: 7 VMs for 30 hours = Rs 2,520. With 8 GB laptops each student can run the lab locally, so the batch can avoid most of that cost.

P8Business problem

Backup check

The metastore database is 180 MB and grows 12 MB per month; table data is 3 TB. A backup job copies only the metastore. How big is it after 12 months, and why is backing it up so important compared with its size?

Input
180 MB + 12 MB/month · 12 months
Expected output
metastore after 12 months: 324 MB
share of total data: 0.0103%
Show solution and explanation 
size = 180 + 12 * 12
print("metastore after 12 months:", size, "MB")
print("share of total data:", f"{size / (3 * 1024 * 1024):.4%}")
metastore after 12 months: 324 MB share of total data: 0.0103%

How it works: 324 MB, about 0.01% of the data, yet without it nobody knows which files form which table, partition or column. Small, critical, back it up.

Real-world scenario questions (asked in company interviews)

Setting up and connecting are the first things a new data engineer does. Interviewers use them to check practical experience.

Any company · basicsFresher

“How would you set up Hive to practise?”

The interviewer asks how you practised Hive without a company cluster.

The interviewer is checking: have you actually run Hive, and do you know its parts?

Show a strong answer
  1. I used Docker Compose with the official apache/hive image: one container for PostgreSQL, one for the Hive Metastore on 9083 and one for HiveServer2 on 10000.
  2. I connected with Beeline using jdbc:hive2://localhost:10000/, created external tables over CSV files and ran queries on Tez in local mode.
  3. I checked the metastore tables in Postgres to see how a CREATE TABLE is stored.

Avoid: saying “I only watched videos”; describe the components and one thing you ran.

Support · connectivityFresher

Beeline says Connection refused

A new analyst cannot connect: “Could not open client transport … Connection refused”.

The interviewer is checking: can you troubleshoot from network to service?

Show a strong answer
  • Confirm the URL: host, port 10000 (not the web UI port 10002), correct transport mode.
  • Check the service is running and listening (container status, ss -ltn or the HiveServer2 log); it may still be starting.
  • Check firewalls or security groups between the analyst and the server; then retry with --verbose=true.

Avoid: blaming the SQL; Connection refused happens before any SQL is sent.

Platform · designMid-level

Why not use embedded Derby in our team setup?

A colleague proposes running HiveServer2 with the default embedded Derby metastore to save time.

The interviewer is checking: do you understand metastore modes and their limits?

Show a strong answer
  • Embedded Derby can be opened by only one process; a second HiveServer2, Spark or Trino cannot share the catalogue.
  • Metadata would live inside one machine or container: no backups, no high availability.
  • Use a remote metastore backed by PostgreSQL or MySQL, back up that database, and run more than one metastore instance for availability.

Avoid: “Derby is fine because it is the default”: defaults are for testing.

Data engineering · automationMid-level

Running Hive from a scheduler

You must run a nightly HiveQL report from Airflow and save the result as CSV.

The interviewer is checking: do you know Beeline’s scripting switches and failure handling?

Show a strong answer
  1. Put the SQL in a file and run beeline -u <url> --silent=true --outputformat=csv2 --hivevar run_date={{ ds }} -f report.hql > report.csv.
  2. Rely on Beeline’s exit code: a failed statement returns non-zero, so the task fails and retries or alerts.
  3. Keep credentials out of the command line (use the scheduler’s connection store), and write large results to a table or files instead of streaming them through Beeline.

Avoid: parsing the default table output with string tricks; use csv2.
