What is Hive? The story of SQL on Hadoop

Meera the analyst knows SQL, but the company’s data now lives as files on a Hadoop cluster. Hive is the layer that lets her ask questions in SQL while the cluster does the heavy lifting. This lesson tells the story behind Hive, defines it precisely, and compares it honestly with a normal database and with other SQL engines.

1 The story

The analyst who had to wait two days

Before you start: you should know basic SQL (SELECT, GROUP BY) and that HDFS stores files as blocks on many machines. Rusty? Read Lesson 1.1: Prerequisites first (25 minutes).

TiffinGo’s analyst Meera knows SQL very well. Her question is simple: “How many orders did each city give us last month?” But the orders are no longer in a small database. They are 2 TB of files spread over a Hadoop cluster, and the only way to read them is a Java MapReduce program. Meera cannot write one. She sends a request to the engineering team and waits.

Kabir

Sir, that sounds silly. Meera knows exactly what she wants. Why should she depend on an engineer for a simple count?

Arjun Sir

That was the exact problem a team at Facebook faced around 2007. Their data was growing fast on Hadoop, hundreds of analysts knew SQL, and only a few engineers could write MapReduce. So they built a layer that lets people write SQL-like queries, and the layer writes the MapReduce programs for them. They called it Hive, and in 2008 it was given to the Apache community as open source.

Riya

So Hive is a program that converts SQL into Java?

Arjun Sir

Close. Hive translates a SQL-like language called HiveQL into distributed jobs, runs them on the cluster, and returns the result. It also keeps a catalogue that says “the table orders is the folder /data/orders and has these columns”. That catalogue is the part many beginners miss, and Lesson 1.3 is entirely about it.

Kabir

So is Hive a database like MySQL?

Arjun Sir

That is the best question of the day, and the honest answer is “not really”. Let us find out why.

2 Definition

What is Apache Hive?

Formal definition (write this in exams)

Apache Hive is an open-source data-warehouse system built on top of Apache Hadoop that provides a SQL-like query language, HiveQL, for reading, writing and managing large datasets stored in distributed storage such as HDFS or cloud object stores. Hive keeps table definitions (schemas, partitions, locations) in a metastore, compiles each query into a plan of distributed tasks that run on an execution engine such as Apache Tez under YARN, and applies the schema when the data is read (schema on read). It is designed for batch analytical (OLAP) workloads, not for online transaction processing.

In simple words

Hive lets you ask questions of huge files using SQL. You describe the files as a table once; after that, you just write SELECT. Hive works out how to split the work across many machines. Think of it as SQL on top of Hadoop.

Words you’ll meet in this lesson

HiveQLHive’s SQL-like language. Mostly standard SQL, plus extras for partitions, file formats and Hadoop.
MetastoreThe catalogue (a small database) that stores table names, columns, types, partitions and file locations.
Schema on readThe data is stored as it is; the schema is applied only when you read it. Contrast: an RDBMS checks data when you write it.
OLAP / OLTPAnalytical queries over lots of data (OLAP) versus many small transactions (OLTP).
Execution engineThe component that runs a query’s tasks on the cluster: Tez (default), MapReduce (old) or Spark (optional).
HiveServer2The service that accepts SQL connections (JDBC/ODBC, Beeline) from users and tools.
BeelineThe command-line SQL client that connects to HiveServer2.
SerDeSerializer/Deserializer: the code that turns a file’s bytes into columns and back.

Hive at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A library

  • The books are your data files in HDFS. Hive does not move or copy them when you create a table.
  • The catalogue cards (the metastore) say which shelf holds which book and what each chapter (column) is called.
  • You, the reader, ask the librarian a question in plain language (HiveQL). The librarian (Hive) sends helpers (YARN containers) to the right shelves, collects the information and hands you the answer.
  • This is great for questions like “how many books about cooking were borrowed this year?” and not great for “find book number 42 right now”.

Intermediate What Hive is, and is not

  • Hive is: a data-warehouse layer on Hadoop; SQL-like language (HiveQL); a metastore of table definitions; a compiler that turns queries into distributed jobs; support for many file formats (text, ORC, Parquet, Avro).
  • Schema on read: the files exist first; the table definition describes how to read them. Bad values do not stop a load: a value that cannot be parsed simply reads as NULL.
  • Batch analytics (OLAP): built to scan huge data and summarise it. A query takes seconds to minutes because starting distributed work has a fixed cost.
  • Not OLTP: not for thousands of small reads and writes per second (orders being placed, balances being updated). Use MySQL, PostgreSQL or a NoSQL store for that.
  • Scales out: to query ten times more data, add more machines; you do not change the SQL.

Advanced Architecture position, engines and where Hive is going

  • Execution engine: in modern Hive queries run on Apache Tez by default; the original MapReduce engine is deprecated. Optional LLAP (long-lived daemons with caching) gives faster interactive queries.
  • ACID tables: since Hive 3, managed tables in ORC can be transactional (INSERT, UPDATE, DELETE, MERGE with snapshot isolation). Still batch-oriented, not OLTP.
  • The metastore outlived the engine: the Hive Metastore is the de-facto table catalogue for Spark, Trino/Presto, Impala, Flink and cloud services, even in platforms that no longer run HiveServer2.
  • Open table formats: Hive 4 can work with Apache Iceberg tables, and many clouds offer Hive-compatible catalogues (AWS Glue, for example).
  • Where Hive fits now: large nightly batch ETL, a shared SQL layer for analysts and BI tools, and the metastore. For interactive dashboards many teams add Trino, Impala, Spark SQL or a cloud warehouse next to it.

Exam tip: “Hive is not a database; it is a data-warehouse infrastructure on Hadoop.” For a 5-mark answer give: definition, origin (Facebook, 2007; Apache 2008), three features (HiveQL, schema on read, scalability), one limitation (high latency, not for OLTP) and the diagram “Client → Hive → Metastore + YARN + HDFS”.

4 Step by step

From files to an answer, the Hive way

  1. Start with plain files in HDFS

    The order files already sit in the folder /data/orders, one CSV per day. Nothing is loaded into a database.

    This is the big difference from MySQL: the data is not imported into Hive’s own storage. Other tools (Spark, Pig, MapReduce) can read the very same files.

  2. Describe the files as a table (HiveQL)

    CREATE EXTERNAL TABLE orders (
  id INT, city STRING, amount INT)
ROW FORMAT DELIMITED FIELDS TERMINATED BY ','
STORED AS TEXTFILE
LOCATION '/data/orders';
    This statement is fast even for 2 TB, because Hive does not touch the data. It only writes a few rows into the metastore: name, columns, delimiter and location.

  3. Schema is applied when data is read

    rows = "1,Pune,220\n2,Thane,abc\n3,Mumbai,310"
schema = [("id", int), ("city", str), ("amount", int)]
def read(line):
    out = []
    for (name, typ), raw in zip(schema, line.split(",")):
        try:
            out.append(typ(raw))
        except ValueError:
            out.append(None)          # Hive reads an unparseable value as NULL
    return out
for line in rows.split("\n"):
    print(read(line))
    [1, 'Pune', 220] [2, 'Thane', None] [3, 'Mumbai', 310]
    Row 2 has “abc” where a number should be. Hive does not refuse the file; the value reads as NULL. This is why Hive data-quality checks (counting NULLs) matter so much.

  4. Ask a question in SQL

    SELECT city, SUM(amount) AS total
FROM orders
GROUP BY city;
    Meera writes the same SELECT … GROUP BY she knows from MySQL. HiveServer2 receives it, checks the table in the metastore and compiles it into a plan of map and reduce stages (Lesson 1.4).

  5. The table is a window on the files

    files = {"/data/orders/part-0": "1,Pune,220\n2,Thane,150", "/data/orders/part-1": "3,Pune,180"}
metastore = {"orders": {"location": "/data/orders", "columns": ["id", "city", "amount"]}}
t = metastore["orders"]
data = [l.split(",") for p, c in files.items() if p.startswith(t["location"]) for l in c.split("\n")]
print("table orders reads", len(files), "files and", len(data), "rows")
    table orders reads 2 files and 3 rows
    The metastore stores only where the files are and how to read them. The query reads whatever files are in that folder at that moment: drop a new file in the folder and the next query includes it.

  6. Dropping an external table keeps the data

    files = {"/data/orders/part-0": "x", "/data/orders/part-1": "y"}
metastore = {"orders": "/data/orders"}
del metastore["orders"]            # DROP TABLE on an EXTERNAL table
print("tables:", list(metastore), "| files still there:", sorted(files))
    tables: [] | files still there: ['/data/orders/part-0', '/data/orders/part-1']
    DROP TABLE on an external table removes only the metastore entry. The files stay. (On a managed table Hive owns the files and deletes them too. Lesson 2.2 is about this difference.)
5 See it happen

Create a table, query it, drop it: what you see and what really happens

Left: the Beeline screen. Right: the metastore and the HDFS files. Watch how little happens when a table is created, and why the data survives a drop.

A Hive table is a window on files 6 steps
What you see
  1. Meera describes the order files as a table. She writes the columns and the folder.
  2. The statement returns in a fraction of a second, no matter how big the data is.
  3. She asks her question in ordinary SQL.
  4. Hive starts a Tez session and runs map and reduce stages on the cluster. 16 map tasks, 1 reducer.
  5. Three rows come back after about 21 seconds. (Time is illustrative.)
  6. She drops the table. The folder with the files is still there, so no data was lost.
Behind the screen
  1. Before anything: 16 files in HDFS, and an empty catalogue.
  2. CREATE EXTERNAL TABLE adds one entry to the metastore. Not a single byte of data is copied or moved.
  3. The query arrives. Hive looks up “orders” in the metastore to learn the folder, columns and file format.
  4. Hive plans the job. YARN gives containers and each reads some files from HDFS, applying the schema on the fly.
  5. The final rows are streamed back through HiveServer2 to Beeline. Intermediate data is thrown away.
  6. DROP TABLE on an external table removes only the metastore entry. Other tools can still read the files.

Choosing between Hive and an RDBMS 5 steps
Animated example
  1. Finding one order by its number: MySQL answers in milliseconds. Hive needs seconds because it starts distributed work first.
  2. Total sales per city over 2 TB: one MySQL server struggles or fails. Hive splits the work over many machines and finishes in minutes.
  3. Taking 5,000 orders a second: each Hive write would be a job. Use a transactional database.
  4. Real platforms use both: operational databases record the data, a data lake collects it, Hive analyses it.
  5. The rule of thumb: Hive for large analytical scans, an RDBMS or NoSQL for operational lookups and writes.
Real-time scenario 3 · advanced

One metastore, many engines

The metastore is Hive’s most reusable part. Watch the same table definition serve Hive, Spark, Trino and Impala, and survive a move to the cloud.

The metastore as shared catalogue 5 steps
Animated example
  1. Hive creates the table orders. The metastore records its location and columns. The data stays in files.
  2. Hive queries the table: it asks the metastore what the table is, then reads the files.
  3. Spark SQL, configured to use the same metastore, sees the table too. Nothing is copied or defined twice.
  4. Trino, Impala and other engines can do the same: one definition, many readers, one copy of the data.
  5. When the platform moves to cloud storage only the table’s location changes. Queries do not. That is why the Hive Metastore is used far beyond Hive itself.
6 Real-world use

Where companies use Hive

1. Nightly sales and revenue reports

A retailer’s stores upload the day’s billing files to HDFS. At 2 a.m. a scheduled Hive script joins sales with product and store tables and writes a summary table. By morning, managers open dashboards built on it.

Billing files→Hive batch job→Summary table→Dashboard

2. Web and app log analysis

Servers write terabytes of logs every day. A Hive table over the log folder lets support teams count error codes per hour, per app version, without writing code.

Log files→Hive table→Errors per hour

3. Telecom usage analytics

A telecom operator stores call and data records for billing and planning. Analysts use HiveQL to find busy cells, churn signals and plan usage over months of history.

Call records→HiveQL→Network planning

4. BI tools on a data lake

Business users connect Power BI, Tableau or Excel to HiveServer2 with an ODBC/JDBC driver and build charts over Hive tables, without knowing that files and clusters are behind them.

Dashboard→HiveServer2→Data lake

5. Metastore as the cloud data catalogue

On cloud platforms (for example Amazon EMR, Google Dataproc or Azure HDInsight) the Hive Metastore, or a compatible catalogue, tells Spark, Hive and Trino what tables exist over the object store.

Cloud storage→Metastore→Spark / Hive / Trino

Examples are simplified and generic. They describe common patterns, not any particular company’s internal systems.

7 Run the code

Schema on read: the idea behind every Hive table

A Hive table is a description of files. This program imitates that: a CSV text and a schema are kept apart, and the schema is applied only when a row is read. Notice what happens with a bad value, and compare with what Python normally does. Then try the challenges.

csv_text = """1,Pune,220
2,Thane,abc
3,Mumbai,310"""
schema = [("id", int), ("city", str), ("amount", int)]

def read_row(line):
    row = []
    for (name, typ), raw in zip(schema, line.split(",")):
        try:
            row.append(typ(raw))
        except ValueError:
            row.append(None)        # like Hive: unparseable value -> NULL
    return row

rows = [read_row(l) for l in csv_text.split("\n")]
for r in rows:
    print(r)
total = sum(r[2] for r in rows if r[2] is not None)
print("SUM(amount) ignores NULL:", total)
[1, 'Pune', 220] [2, 'Thane', None] [3, 'Mumbai', 310] SUM(amount) ignores NULL: 530
  • schema = [("id", int), ("city", str), ("amount", int)]The table definition, kept separate from the data, like a row in the metastore.
  • except ValueError: row.append(None)Hive does not reject a bad value; the column reads as NULL. This is the heart of schema on read.
  • sum(... if r[2] is not None)SQL aggregates such as SUM skip NULLs, so one bad value silently lowers the total. Always count NULLs when loading data.

Interview and viva questions

Is Hive a database?

Not in the usual sense. Hive keeps table definitions in a metastore (a small relational database) but stores the data as files in HDFS or cloud storage, and it has no query engine of its own beyond the compiler: queries run as distributed jobs. It is best described as a data-warehouse system on Hadoop that provides SQL access.

Who created Hive and why?

A team at Facebook built it around 2007 so that analysts who knew SQL could query very large datasets on Hadoop without writing Java MapReduce programs. It was contributed to the Apache Software Foundation in 2008 and became a top-level Apache project in 2010.

Why are Hive queries slow for small data?

Every query has fixed costs: compiling, requesting containers from YARN, starting tasks and writing results. For a few megabytes these costs dominate. For terabytes they are negligible compared with the parallel scan time.

What is the difference between Hive and HBase?

Hive provides SQL-style analytics over files and is batch-oriented. HBase is a NoSQL, column-family store with fast random reads and writes by key. They solve different problems, and Hive can even query HBase tables through a storage handler.

Does Hive still matter when Spark and cloud warehouses exist?

Yes, in two ways. Many large organisations still run Hive for batch ETL and as the shared SQL layer on Hadoop-style data lakes, and the Hive Metastore has become the common table catalogue for Spark, Trino, Impala and cloud services. Knowing Hive therefore helps with all of them.

['/data/orders/p0', '/data/orders/p1']

How it works: A table is just a folder. Anything in that folder is part of the table; files elsewhere are not.

P3Easy

External drop

After DROP TABLE on an external table, are the files still there? Simulate with a dict and a list.

Input
metastore {orders}, files [p0, p1]
Expected output
tables: 0 | files: 2
Show solution and explanation 
metastore = {"orders": "/data/orders"}
files = ["p0", "p1"]
del metastore["orders"]
print("tables:", len(metastore), "| files:", len(files))
tables: 0 | files: 2

How it works: The metastore entry is gone; the files are untouched. For a managed table the files would be deleted too.

P4Medium

NULL percentage

Given amounts as text, print the percentage that read as NULL.

Input
["220", "x", "150", "", "90", "60", "n/a", "75"]
Expected output
3 of 8 are NULL = 37.5%
Show solution and explanation 
vals = ["220", "x", "150", "", "90", "60", "n/a", "75"]
def ok(v):
    try:
        int(v); return True
    except ValueError:
        return False
bad = sum(1 for v in vals if not ok(v))
print(f"{bad} of {len(vals)} are NULL = {100 * bad / len(vals):.1f}%")
3 of 8 are NULL = 37.5%

How it works: 3 of 8, 37.5%. A data-quality rule might alert above 1%.

P5Medium

Pick a tool

Write a function that returns "Hive" for large scans, otherwise "RDBMS/NoSQL", and test three workloads.

Input
(10, "scan"), (10, "lookup"), (0.1, "scan")
Expected output
(10, 'scan') -> Hive
(10, 'lookup') -> RDBMS/NoSQL
(0.1, 'scan') -> RDBMS/NoSQL
Show solution and explanation 
def pick(tb, style):
    return "Hive" if tb >= 1 and style == "scan" else "RDBMS/NoSQL"
for w in [(10, "scan"), (10, "lookup"), (0.1, "scan")]:
    print(w, "->", pick(*w))
(10, 'scan') -> Hive (10, 'lookup') -> RDBMS/NoSQL (0.1, 'scan') -> RDBMS/NoSQL

How it works: Small data fits comfortably in a normal database even for scans. Lookups are an RDBMS/NoSQL job at any size.

P6Medium

Break-even size

Hive costs 15 s + size/2 GB/s; a database costs size/0.2 GB/s. Find the smallest whole number of GB where Hive is faster.

Input
15 + g/2 < g/0.2
Expected output
Hive wins from 4 GB
Show solution and explanation 
g = 1
while not (15 + g / 2.0 < g / 0.2):
    g += 1
print("Hive wins from", g, "GB")
Hive wins from 4 GB

How it works: From 4 GB (4 GB: Hive 17 s vs database 20 s). Below that the start-up cost is not worth it. (Illustrative model.)

P7Business problem

Month-end report: where to run it?

A 3 TB orders table must be summarised every night, and a web page needs single orders in under 100 ms. Decide where each workload runs and print the reason.

Input
3 TB nightly summary; 100 ms point lookups
Expected output
nightly summary -> Hive: large scan, batch, results ready by morning
order page lookup -> MySQL/NoSQL: needs milliseconds
Show solution and explanation 
jobs = [("nightly summary", "scan", "Hive: large scan, batch, results ready by morning"),
        ("order page lookup", "lookup", "MySQL/NoSQL: needs milliseconds")]
for name, style, why in jobs:
    print(name, "->", why)
nightly summary -> Hive: large scan, batch, results ready by morning order page lookup -> MySQL/NoSQL: needs milliseconds

How it works: This is how real platforms are built: an operational store serves the app, and a Hive (or similar) layer analyses the same orders in batch.

P8Business problem

Cost of a bad feed

A feed of 1,000,000 orders averaging Rs 250 has 2% of amounts unparseable (read as NULL). How much revenue does SUM miss?

Input
1,000,000 orders · Rs 250 · 2% NULL
Expected output
missing revenue: Rs 5000000
Show solution and explanation 
orders, avg, bad = 1_000_000, 250, 0.02
print("missing revenue: Rs", int(orders * bad * avg))
missing revenue: Rs 5000000

How it works: Rs 50,00,000 silently missing from the report. Schema on read is flexible, but it makes NULL checks a mandatory part of every pipeline.

Real-world scenario questions (asked in company interviews)

Typical “what is Hive and when would you use it?” questions, as company interviewers ask them.

Any company · conceptsFresher

“Is Hive a database?”

The interviewer asks: “Hive has tables and SQL, so it is a database, right?”

The interviewer is checking: do you separate metadata, storage and compute?

Show a strong answer
  • Hive stores table definitions in a metastore; the data stays as files in HDFS or cloud storage.
  • Queries are compiled into distributed jobs on Tez/YARN, so latency is seconds to minutes, not milliseconds.
  • So it is a data-warehouse layer providing SQL on Hadoop, not an OLTP database.

Avoid: a flat “yes” or “no” without explaining the difference.

Data platform · designMid-level

Dashboards are slow

A manager says: “Our Tableau dashboards on Hive take 40 seconds per click. Is Hive bad?”

The interviewer is checking: do you understand latency vs throughput and know the options?

Show a strong answer
  1. Hive on Tez has start-up overhead per query, so it is not ideal for interactive clicks.
  2. Options: build summary tables nightly so dashboards read small tables, enable LLAP or caching, use ORC/Parquet with partitioning, or add an interactive engine (Trino, Impala) on the same metastore.
  3. Keep Hive for the heavy batch transformations.

Avoid: rewriting everything in another tool without first measuring where the time goes.

Any company · conceptsFresher

A bad value in a Hive table

A file has “abc” in a numeric column. A colleague expects the load to fail.

The interviewer is checking: do you know schema on read?

Show a strong answer
  • Hive does not validate on write. The file is stored unchanged; at read time the value cannot be parsed and appears as NULL.
  • Aggregates like SUM ignore NULLs, so totals can be silently low.
  • Therefore: validate in the pipeline, count NULLs per column and compare with history.

Avoid: saying “Hive rejects the row”.

Operations · migrationMid-level

Moving to the cloud

The company will move HDFS data to S3 or another cloud store. Will analysts need to rewrite their Hive tables and queries?

The interviewer is checking: do you understand the role of the metastore and table locations?

Show a strong answer
  • Table definitions live in the metastore; the data location is one property of each table.
  • Copy the data to object storage, then change the table location (or recreate external tables) to point to it. Queries stay the same.
  • Check file-format, permission and consistency differences of the object store, and test performance.

Avoid: promising “no changes at all”; locations, security and performance still need work.
