TiffinGo’s data scientists use Spark, the BI team wants Trino for dashboards, and the warehouse is built in Hive. Everyone points their engine at the same Hive metastore. On Monday, a data scientist reports that the orders table is empty. In Hive it has five million rows.

2 Definition

One metastore, many engines

Formal definition (write this in exams)

The Hive Metastore (HMS) has become the shared catalogue of the open data stack: Spark SQL, Trino/Presto, Impala, Flink and many cloud services read and write table definitions through its Thrift API. Sharing the catalogue lets each engine see the same databases, tables, schemas, partitions and locations, but each engine reads and writes the data files with its own readers. Compatibility therefore depends on the metastore API version, the file formats and SerDes, Hive-specific features (ACID tables, views in HiveQL, storage handlers such as Iceberg’s) and SQL dialect differences.

In simple words

Hive, Spark and Trino can all use the same Hive metastore, so a table created in one is visible in the others. Whether they return the same answer depends on whether each engine understands the table’s format and Hive-specific features.

Many engines at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner One library catalogue, several readers

  • The metastore is a shared catalogue. Hive, Spark and Trino are different readers using it.
  • Each reader must understand the book’s language (file format) and any special rules (transactions, Iceberg).
  • Same catalogue, but a reader that does not know the rules may read the wrong pages.

Intermediate How each engine connects

  • Spark SQL: Hive support plus hive.metastore.uris; its built-in Hive client is 2.3.x, configurable with spark.sql.hive.metastore.version and .jars.
  • Trino: a catalog file with connector.name=hive and hive.metastore.uri; Iceberg tables through a separate iceberg catalog.
  • Hive: native; the only engine that writes Hive ACID tables with all features (MERGE, compaction, materialized views).

Advanced What the lab showed

  • Spark’s built-in 2.3.9 client failed on Hive 4’s metastore (Invalid method name: 'get_table'); a 3.1.3 client worked.
  • ORC, text and Parquet tables and the views gave identical answers in all engines. The ACID table: Hive 5,000,001 rows, Trino 5,000,004 (deleted and old versions included), Spark 0, with no error.
  • Trino’s native local file system silently returned 0 rows for file: locations; Spark could not open the Iceberg table through Hive’s storage handler or its own Hive catalog.

Exam tip: “Can Spark and Trino use Hive tables?” Yes, through the Hive metastore: Spark with Hive support and hive.metastore.uris, Trino with a hive catalog. Plain ORC/Parquet tables work well. Check Hive ACID tables, HiveQL views and Iceberg tables per engine and version; metastore client versions must also be compatible.

  -e "SHOW DATABASES; USE tiffingo; SELECT COUNT(*) FROM orders;"

-- Trino

-- Spark

    -- Hive +----------+ | n | +----------+ | 5000001 | +----------+ +------------+------------+ | order_id | status | +------------+------------+ | 999000010 | CANCELLED | +------------+------------+ -- Trino rows --------- 5000004 (1 row) order_id | status -----------+----------- 999000001 | DELIVERED 999000002 | DELIVERED 999000010 | CANCELLED 999000010 | NEW (4 rows) -- Spark 0
    orders_tx is the full-ACID table from Modules 9 and 10, with rows inserted, deleted and updated since. Hive: 5,000,001 rows, order 999000010 once, CANCELLED.     Error: Error while compiling statement: FAILED: ParseException line 1:19 cannot recognize input near 'AS' 'rows' 'FROM' in selection target Query 20261030_052433_00014_7jd7u failed: line 1:60: Cannot apply operator: date = varchar(10) LINE 1: SELECT COUNT(*) FROM hive.tiffingo.orders WHERE order_date = '2026-10-05' ^ engine run 1 run 2 run 3 measured as Trino 1.60 s 0.79 s 0.75 s server-side elapsed (system.runtime.queries) Hive 2.01 s 1.64 s 1.60 s HiveServer2 "Completed executing … Time taken" (results cache off) Spark 7.77 s 2.24 s 2.10 s spark-sql "Time taken" (same session; JVM start excluded)

Interview and viva questions

Is Hive still used if Spark and Trino exist?

Yes. Hive is still common for SQL-based ETL and as the metastore that every other engine depends on, and Cloudera’s data warehouse runs on Hive with LLAP and Iceberg. Many platforms use Hive for loads and Spark or Trino for analysis.

What is the Hive Warehouse Connector?

A Cloudera library that lets Spark read and write Hive managed (ACID) tables through HiveServer2/LLAP instead of reading the files directly, solving the “0 rows” problem of Step 5 on those platforms.

Should all shared tables be Iceberg?

For tables written or read by several engines, many teams now choose Iceberg, because Hive, Spark, Trino, Flink and cloud services implement the same specification. Hive ACID remains fine for Hive-only tables. Lesson 11.3 covers migration.

Why were Trino and Spark timings different from Hive’s?

Different architectures (Trino keeps long-running workers and pipelines data in memory; Spark and Hive on Tez schedule tasks), different measurement points, a single machine and small data. Benchmark on your own cluster and data.

Do Spark and Trino respect Hive grants?

No, SQL-standard grants are enforced inside HiveServer2 (Lesson 10.2). Use Ranger plugins for each engine or a shared permission layer, and restrict direct file access.

Real-world scenario questions (asked in company interviews)

Multi-engine questions are standard in data platform interviews.

Any company · HiveFresher

“Can Spark read Hive tables?”

Explain how Spark and Trino use Hive tables.

The interviewer is checking: do you know the metastore’s role?

Show a strong answer

Yes: both connect to the Hive metastore, so they see the same databases and tables, then read the ORC/Parquet files directly. Spark needs Hive support and the metastore URI; Trino needs a hive catalog. Hive-specific table types such as ACID tables are not fully supported by all engines, so results should be checked.

Avoid: Saying Spark queries HiveServer2.

Data engineeringMid-level

Different counts in two engines

A table shows different row counts in Hive and Trino.

The interviewer is checking: can you find the cause?

Show a strong answer
  1. Check the table type: transactional? Iceberg? Views?
  2. For ACID tables, deletes and updates live in delete deltas some readers ignore; compare a few known deleted keys.
  3. Fix: read through the correct engine, write plain snapshots, or migrate to Iceberg.

Avoid: “Trino is wrong, ignore it.”

PlatformMid-level

Spark fails after the metastore upgrade

After upgrading the metastore to Hive 4, Spark jobs fail with “Invalid method name: get_table”.

The interviewer is checking: do you know client compatibility?

Show a strong answer
  • Spark’s built-in Hive metastore client is too old for the new API.
  • Configure spark.sql.hive.metastore.version / jars for a compatible client, or upgrade Spark.
  • Test all engines against a restored metastore copy before future upgrades.

Avoid: Rolling back the metastore without analysis.

ArchitectureSenior

Design a multi-engine lakehouse

Hive, Spark and Trino must share tables safely; some tables are updated daily.

The interviewer is checking: can you choose formats and catalogs?

Show a strong answer
  • Shared, updated tables in Iceberg with one catalog (HMS, REST or Glue) that every engine uses.
  • Hive ACID only for Hive-only tables; plain Parquet/ORC for append-only data.
  • A compatibility matrix and automated cross-engine tests on every upgrade; Ranger for access in all engines.

Avoid: Letting each team pick its own format and catalog.
