2 Definition

SELECT, WHERE, operators and functions

Formal definition (write this in exams)

A HiveQL SELECT statement retrieves rows from tables, views, joins or subqueries: SELECT [ALL | DISTINCT] expr [AS alias], … FROM source [WHERE condition] [GROUP BY …] [HAVING …] [ORDER BY …] [LIMIT [offset,] n]. The WHERE clause keeps only rows for which a Boolean expression is true (rows where it is false or NULL are discarded). Expressions are built from built-in operators (relational, arithmetic, logical, string and complex-type operators) and built-in functions (mathematical, conditional, string, date and others).

In simple words

SELECT picks columns and computes new ones; WHERE keeps only the rows where your condition is definitely true. Operators compare and calculate; functions like ROUND, CASE and IF transform values. Unknown values (NULL) never pass a normal comparison.

Words you’ll meet in this lesson

SELECT and WHERE at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A filter and a form

  • WHERE is a sieve: only rows that pass every condition go through.
  • SELECT is the form you fill for each passing row: which columns, and any calculated ones (a rounded amount, a label).
  • LIMIT says how many forms you want back.
  • NULL means “unknown”. Comparing anything with unknown gives unknown, so such rows do not pass WHERE.

Intermediate The operator families

  • Relational: = == <> != < <= > >=, [NOT] BETWEEN a AND b, IS [NOT] NULL, [NOT] LIKE (% any text, _ one character), RLIKE / REGEXP (Java regular expressions), <=> (NULL-safe equal), IS [NOT] DISTINCT FROM.
  • Arithmetic: + - * /, % (remainder), DIV (whole-number division), bitwise & | ^ ~.
  • Logical: AND OR NOT !, [NOT] IN (…), [NOT] EXISTS (subquery).
  • String: || concatenates (same as concat()).
  • Complex types: a[n], m['key'], s.field (Lesson 2.3).
  • Conditional functions: CASE WHEN … THEN … END, IF(cond, a, b), COALESCE(a, b, …), NVL(a, b).
  • Maths: ROUND(x, d), FLOOR, CEIL, ABS, POW, SQRT.

Advanced Rules and Hive-specific features

  • Evaluation order: FROM → WHERE → (GROUP BY) → SELECT → ORDER BY → LIMIT. A SELECT alias cannot be used in WHERE (error 10004 in our lab).
  • Three-valued logic: NULL = NULL is NULL (not true); NULL <=> NULL is true. NOT IN with a NULL in the list returns no rows (Lesson 3.5).
  • ROUND is half-up: ROUND(2.5) = 3 in Hive; Python’s round(2.5) is 2 (banker’s rounding). ROUND(x, -2) rounds to hundreds.
  • LIMIT n OFFSET m (Hive 2.0+) skips m rows; use it only with ORDER BY, or the rows are arbitrary.
  • Virtual columns: INPUT__FILE__NAME and BLOCK__OFFSET__INSIDE__FILE show where a row was read from: great for debugging bad rows.
  • Identifiers: names are case-insensitive; backticks allow spaces and symbols (`order id`). With hive.support.quoted.identifiers=none a backticked name becomes a regex column list.
  • FROM is optional: SELECT 1 + 1 works, handy for testing functions.

Exam tip: “Explain the categories of built-in operators in Hive with examples.” Write four groups with two examples each: relational (=, BETWEEN, LIKE, RLIKE, IS NULL), arithmetic (+, %, DIV), logical (AND, OR, NOT, IN), and complex-type operators (a[n], m[k], s.x). Mention that comparisons with NULL return NULL.

Answer finance’s questions, one operator family at a time

All outputs are real, from the Hive 4.2.1 lab, on the curated orders table (50,000 clean orders in ORC).

  1. Step 1 · Combine relational and logical operators

    SELECT order_id, city, amount, payment FROM orders
WHERE city = 'Pune' AND amount BETWEEN 500 AND 520
  AND payment IN ('UPI','Card')
LIMIT 5;
    +-----------+-------+---------+----------+ | order_id | city | amount | payment | +-----------+-------+---------+----------+ | 100226 | Pune | 520.00 | Card | | 100365 | Pune | 510.00 | UPI | | 100386 | Pune | 510.00 | UPI | | 100416 | Pune | 510.00 | UPI | | 101410 | Pune | 520.00 | UPI | +-----------+-------+---------+----------+
    Three conditions joined with AND; BETWEEN includes both ends (520.00 appears). Without ORDER BY, which five rows you get is not guaranteed.

  2. Step 2 · Unique values

    SELECT COUNT(*) AS all_rows, COUNT(DISTINCT city) AS cities,
       COUNT(DISTINCT payment) AS payments FROM orders;
SELECT DISTINCT payment FROM orders;
    +-----------+---------+-----------+ | all_rows | cities | payments | +-----------+---------+-----------+ | 50000 | 8 | 4 | +-----------+---------+-----------+ +----------+ | payment | +----------+ | COD | | Card | | UPI | | Wallet | +----------+
    50,000 orders, 8 cities, 4 payment modes. DISTINCT needs a shuffle so equal values meet in one reducer.

  3. Step 3 · Patterns: LIKE and RLIKE

    SELECT name, city FROM customers WHERE name LIKE 'Riya%' LIMIT 3;
SELECT name FROM customers WHERE name RLIKE '^(Aarav|Diya) (Patil|Iyer)$' LIMIT 4;
    +-----------------+------------+ | name | city | +-----------------+------------+ | Riya Fernandes | Pune | | Riya Gupta | Bengaluru | | Riya Sharma | Bengaluru | +-----------------+------------+ +--------------+ | name | +--------------+ | Diya Iyer | | Aarav Patil | | Diya Iyer | | Diya Patil | +--------------+
    LIKE has two wildcards (%, _). RLIKE takes a full regular expression; ^ and $ force the whole name to match. Two customers are called Diya Iyer: names are not unique, ids are.

  4. Step 4 · NULL, arithmetic, bitwise and maths

    SELECT NULL = NULL AS eq, NULL <=> NULL AS nullsafe, 1 <=> NULL AS one_ns,
       17 % 5 AS modulo, 17 DIV 5 AS idiv, 6 & 3 AS band, 6 | 3 AS bor, 6 ^ 3 AS bxor,
       'Kharghar' || '-' || 'Navi Mumbai' AS concat_op,
       ROUND(1234.5678, 2) AS r2, ROUND(1234.5678, -2) AS rneg,
       FLOOR(-2.5) AS fl, CEIL(-2.5) AS ce, ROUND(2.5) AS r_half;
    | eq | nullsafe | one_ns | modulo | idiv | band | bor | bxor | concat_op | r2 | rneg | fl | ce | r_half | | NULL | true | false | 2 | 3 | 2 | 7 | 5 | Kharghar-Navi Mumbai | 1234.57 | 1200 | -3 | -2 | 3 | (borders removed to fit)
    No FROM is needed to test expressions. Note the two traps: NULL = NULL is NULL, and ROUND(2.5) is 3 (half-up), unlike Python.

  5. Step 5 · CASE, IF, COALESCE and NVL

    SELECT order_id, amount,
  CASE WHEN amount >= 600 THEN 'large' WHEN amount >= 300 THEN 'medium' ELSE 'small' END AS size_band,
  IF(payment = 'COD', 'cash', 'digital') AS pay_type,
  COALESCE(NULL, payment) AS c, NVL(NULL, 'x') AS n
FROM orders LIMIT 3;
    +-----------+---------+------------+-----------+------+----+ | order_id | amount | size_band | pay_type | c | n | +-----------+---------+------------+-----------+------+----+ | 100001 | 530.00 | medium | digital | UPI | x | | 100002 | 500.00 | medium | digital | UPI | x | | 100003 | 410.00 | medium | digital | UPI | x | +-----------+---------+------------+-----------+------+----+
    CASE checks branches in order and takes the first true one, so put the strictest condition first. IF is Hive shorthand for a two-branch CASE.

  6. Step 6 · Aliases, LIMIT … OFFSET and quoted names

    SELECT order_id, amount FROM orders ORDER BY order_id LIMIT 2 OFFSET 3;
SELECT order_id, amount * 1.18 AS with_gst FROM orders WHERE with_gst > 700 LIMIT 2;
SELECT order_id AS `order id`, city AS `delivery-city` FROM orders LIMIT 2;
    +-----------+---------+ | order_id | amount | +-----------+---------+ | 100004 | 180.00 | | 100005 | 480.00 | +-----------+---------+ Error: Error while compiling statement: FAILED: SemanticException [Error 10004]: Line 1:61 Invalid table alias or column reference 'with_gst' … +-----------+----------------+ | order id | delivery-city | +-----------+----------------+ | 100001 | Mumbai | | 100002 | Mumbai | +-----------+----------------+
    OFFSET 3 skipped orders 100001–100003. The alias with_gst does not exist yet when WHERE runs (WHERE is evaluated before SELECT); repeat the expression or wrap the query in a subquery. Backticks allow spaces and hyphens in names.

  7. Step 7 · Where did this row come from?

    SELECT order_id, INPUT__FILE__NAME AS file, BLOCK__OFFSET__INSIDE__FILE AS offset_
FROM orders_ext LIMIT 2;
    +-----------+--------------------------------------------+----------+ | order_id | file | offset_ | +-----------+--------------------------------------------+----------+ | 100001 | file:/data/tiffingo/orders_ext/orders.csv | 0 | | 100002 | file:/data/tiffingo/orders_ext/orders.csv | 61 | +-----------+--------------------------------------------+----------+
    Virtual columns give the file and the byte position of each row: the first line is 61 bytes long, so line 2 starts at byte 61. When a bad row appears among thousands of files, this tells you exactly which file to open.

Behind the screen
  1. Each row is tested against every condition.
  2. A row passes only if all ANDed conditions are true. One false condition drops it.
  3. Passing rows keep only the selected columns, and Hive stops once 5 rows are found.

# WHERE in Python: keep a row only when the condition is TRUE (None plays NULL)
orders = [(100226, "Pune", 520, "Card"), (100227, "Thane", 510, "UPI"),
          (100365, "Pune", 510, "UPI"), (100370, "Pune", 505, "COD"),
          (100380, "Pune", 700, "UPI"), (100999, None, 510, "UPI")]

def where(order_id, city, amount, payment):
    if city is None:
        return None                          # unknown: comparison with NULL
    return city == "Pune" and 500 <= amount <= 520 and payment in ("UPI", "Card")

for row in orders:
    result = where(*row)
    print(row[0], "->", {True: "kept", False: "dropped", None: "dropped (NULL)"}[result])

The two dirty rows (amount “abc” and a date in the wrong layout) are left out, so 50,002 raw orders become 50,000 clean ones, typed and stored as ORC.

2 · Select columns by regular expression

SET hive.support.quoted.identifiers=none;
SELECT `(order_ts|status|payment)?+.+` FROM orders LIMIT 2;
+------------------+---------------------+-----------------------+--------------+--------------------+----------------+ | orders.order_id | orders.customer_id | orders.restaurant_id | orders.city | orders.order_date | orders.amount | +------------------+---------------------+-----------------------+--------------+--------------------+----------------+ | 100001 | 1932 | 35 | Mumbai | 2026-10-29 | 530.00 | | 100002 | 1991 | 2 | Mumbai | 2026-10-17 | 500.00 | +------------------+---------------------+-----------------------+--------------+--------------------+----------------+

The pattern means “every column except order_ts, status and payment”. Handy for wide tables; set the property back to its default (column) afterwards, because backticks then stop meaning literal names.

3 · Standard NULL-safe comparison

SELECT 1 IS DISTINCT FROM NULL AS d, NULL IS NOT DISTINCT FROM NULL AS nd;
+-------+-------+ | d | nd | +-------+-------+ | true | true | +-------+-------+

IS [NOT] DISTINCT FROM is the SQL-standard spelling of the NULL-safe comparison; Hive 4 supports both it and <=>.

Interview and viva questions

Why did my simple SELECT … WHERE … LIMIT finish instantly without a Tez job?

For simple queries (projections, filters and LIMIT, no aggregation or join) Hive can skip the Tez job and read the files directly in a “fetch task” (hive.fetch.task.conversion). Our EXPLAIN showed only Stage-0 with a Fetch Operator, a Limit and a Filter. Larger or more complex queries run as Tez DAGs.

What is the difference between LIKE and RLIKE?

LIKE has two wildcards: % (any text) and _ (one character) and must match the whole value. RLIKE (also spelled REGEXP) takes a Java regular expression and matches if the pattern is found anywhere, so use ^ and $ to match the whole value. Prefer LIKE when it is enough: it is simpler and often faster.

Why does WHERE col <> 'x' not return rows where col is NULL?

Because NULL <> 'x' is NULL (unknown), and WHERE keeps only TRUE. Add OR col IS NULL, or write NOT (col <=> 'x'), when NULL rows should be included.

Is IF() standard SQL?

No, IF(condition, a, b) is a Hive (and MySQL) function. CASE WHEN is standard and portable to Spark SQL, Trino and others, so many teams prefer CASE in shared code.

Can I filter on a column alias from SELECT?

Not in the same query level, because WHERE is evaluated before SELECT. Repeat the expression in WHERE, or put the SELECT in a subquery or CTE and filter outside it. HAVING can use aggregates, and ORDER BY can use SELECT aliases because it is evaluated later.

import re
def like(text, pattern):
    regex = "^" + ".*".join(re.escape(p) for p in pattern.split("%")) + "$"
    return re.match(regex, text) is not None
for n in ["Riya Gupta", "Patil Mess", "Riyaz Khan"]:
    print(n, like(n, "Riya%"), like(n, "%Mess"))
Riya Gupta True False Patil Mess False True Riyaz Khan True False

How it works: 'Riya%' also matches Riyaz Khan. Use 'Riya %' (with a space) if you mean the first name exactly.

P5Medium

Half-up rounding to 2 decimals

Round 2.345, 2.355 and 1234.5678 to 2 decimals the Hive way.

Input
2.345, 2.355, 1234.5678
Expected output
2.345 2.35
2.355 2.36
1234.5678 1234.57
Show solution and explanation 
from decimal import Decimal, ROUND_HALF_UP
for x in ["2.345", "2.355", "1234.5678"]:
    print(x, Decimal(x).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
2.345 2.35 2.355 2.36 1234.5678 1234.57

How it works: 2.35, 2.36, 1234.57. Using Decimal from text avoids binary errors that would make 2.345 round down.

P6Medium

Bit flags

A restaurant flag uses bits: 1 = veg, 2 = jain, 4 = late-night. Flag 6 means which features? (Hive: flag & 2 > 0.)

Input
flag = 6
Expected output
veg False
jain True
late-night True
Show solution and explanation 
flag = 6
for name, bit in [("veg", 1), ("jain", 2), ("late-night", 4)]:
    print(name, bool(flag & bit))
veg False jain True late-night True

How it works: jain and late-night. Bitwise & tests one bit; Hive supports & | ^ ~ on integers.

P7Business problem

GST-inclusive filter

Find orders whose amount including 18% GST exceeds Rs 700. Write the Python filter, then the correct HiveQL (no alias in WHERE).

Input
530, 600, 610, 700
Expected output
[600, 610, 700]
HiveQL: SELECT order_id, amount * 1.18 AS with_gst FROM orders WHERE amount * 1.18 > 700;
Show solution and explanation 
amounts = [530, 600, 610, 700]
print([a for a in amounts if a * 1.18 > 700])
print("HiveQL: SELECT order_id, amount * 1.18 AS with_gst FROM orders WHERE amount * 1.18 > 700;")
[600, 610, 700] HiveQL: SELECT order_id, amount * 1.18 AS with_gst FROM orders WHERE amount * 1.18 > 700;

How it works: [600, 610, 700]. In Hive the expression is repeated in WHERE because the alias is not visible there.

P8Business problem

Unknown payment share

Out of 50,000 orders, 412 have NULL payment after a faulty release. What share is that, and should the release be rolled back if the limit is 0.5%?

Input
412 of 50,000
Expected output
0.82% -> roll back
Show solution and explanation 
share = 412 / 50_000
print(f"{share:.2%} -> {'roll back' if share > 0.005 else 'within limit'}")

Real-world scenario questions (asked in company interviews)

SELECT and WHERE questions look easy; interviewers use them to test NULL logic and evaluation order.

Any company · SQL basicsFresher

“Why does this query return no rows?”

The interviewer shows: SELECT * FROM customers WHERE referral_code = NULL;

The interviewer is checking: do you know three-valued logic?

Show a strong answer
  • Any comparison with NULL is NULL, and WHERE keeps only TRUE rows, so nothing is returned.
  • Use WHERE referral_code IS NULL; for equality that should treat NULLs as equal use <=> or IS NOT DISTINCT FROM.

Avoid: “Hive has a bug with NULL”.

AnalyticsFresher

Using an alias in WHERE

A candidate writes SELECT amount*1.18 AS gst_amt FROM orders WHERE gst_amt > 700 and gets error 10004.

The interviewer is checking: do you know the logical order of evaluation?

Show a strong answer
  1. WHERE runs before SELECT, so the alias does not exist yet.
  2. Repeat the expression in WHERE, or wrap: SELECT * FROM (SELECT amount*1.18 AS gst_amt FROM orders) t WHERE gst_amt > 700.
  3. ORDER BY may use the alias because it runs after SELECT.

Avoid: renaming the column in the table.

Finance · reconciliationMid-level

Totals differ from the finance system

Hive and the finance team’s spreadsheet differ by a few rupees on a rounded GST total.

The interviewer is checking: can you reason about rounding and types?

Show a strong answer
  • Check rounding rules: Hive ROUND is half-up; other tools may use half-even.
  • Check where rounding happens: per line or on the total.
  • Check types: DOUBLE amounts add binary errors; use DECIMAL.

Avoid: “it is just a small difference”: finance needs exact reconciliation.

Data engineering · debuggingMid-level

One bad row in thousands of files

A nightly job fails a quality check because one order has a NULL amount. The table has 3,000 files.

The interviewer is checking: do you know Hive’s virtual columns?

Show a strong answer
  1. Query INPUT__FILE__NAME and BLOCK__OFFSET__INSIDE__FILE for the bad row.
  2. Open the file at that offset to see the raw line.
  3. Report the file and line to the producer and add a check that quarantines such rows.

Avoid: downloading and grepping every file.
