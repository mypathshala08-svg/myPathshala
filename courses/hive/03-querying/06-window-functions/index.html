Window functions: ranking, running totals and LAG/LEAD

GROUP BY squeezes many rows into one. Window functions keep every row and add a calculation over related rows: a rank inside the city, a running total by date, the previous order of the same customer. This lesson answers three real requests from the TiffinGo growth team, compares the three ranking functions on real ties, and shows two traps that silently give wrong answers. All outputs are real, from Hive 4.2.1.

1 The story

“Top 3 customers in every city, a running total and the gap since the last order”

The growth team sends Kabir three requests on one morning: the top three customers per city for a loyalty campaign; Pune’s daily revenue with a running total and a 7-day average; and, for each order, how many hours since the same customer’s previous order. With GROUP BY he can get totals per city, but then the individual customers disappear.

Kabir

Sir, GROUP BY gives me one row per city. I need every customer row, plus its rank inside its city.

Arjun Sir

That is exactly what window functions do. You write a function, then OVER (PARTITION BY city ORDER BY …). Hive looks at all rows of the same city, in that order, computes the value, and writes it next to each row. Nothing collapses.

Riya

And “previous order” means looking at the row before?

Arjun Sir

LAG looks back, LEAD looks ahead, inside the window. A frame like ROWS BETWEEN 6 PRECEDING AND CURRENT ROW gives a moving 7-day average. Today all three requests, on real data, plus two traps: the default frame of LAST_VALUE, and a QUALIFY behaviour we found in Hive 4.2.1.

2 Definition

Window (analytic) functions

Formal definition (write this in exams)

A window function computes a value for each row from a set of related rows, its window, defined by the OVER clause: PARTITION BY divides rows into groups, ORDER BY orders rows within each partition, and an optional frame (ROWS or RANGE BETWEEN … AND …) limits the rows considered relative to the current row. Unlike GROUP BY, window functions do not reduce the number of rows. Hive provides ranking functions (ROW_NUMBER, RANK, DENSE_RANK, NTILE, PERCENT_RANK, CUME_DIST), offset functions (LAG, LEAD, FIRST_VALUE, LAST_VALUE) and aggregate functions used with OVER.

In simple words

A window function looks at a group of rows around each row (same city, earlier days…) and writes a result next to that row: a rank, a running total, the previous value. Every row stays in the result.

Words you’ll meet in this lesson

WindowThe set of rows a function sees for the current row.
PARTITION BYSplits rows into independent groups (each city on its own).
ORDER BY (in OVER)The order inside each partition, used for ranks, running totals and LAG/LEAD.
FrameWhich rows of the partition count, e.g. the 6 rows before and the current one.
Running totalSUM(x) OVER (ORDER BY day): total from the first row to this one.
Moving averageAVG(x) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW).
Top-N per groupROW_NUMBER in a subquery, then WHERE rn <= N.

Window functions at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A class register with extra columns

  • Imagine the class list sorted by marks inside each section. Next to each student you can write: their rank in the section, the section total, the marks of the student just above.
  • Each student keeps their own line; you only add information computed from their section. That is a window function.
  • The section is the PARTITION; the order of names is the ORDER BY; the rows you look at for each student (“the 7 above me”) are the FRAME.

Intermediate The families and the OVER clause

  • Ranking: ROW_NUMBER() (1, 2, 3, 4 … always unique), RANK() (ties share, then gaps: 6, 6, 6, 9), DENSE_RANK() (ties share, no gaps: 6, 6, 6, 7), NTILE(n), PERCENT_RANK(), CUME_DIST().
  • Offset: LAG(col, n, default), LEAD(col, n, default), FIRST_VALUE, LAST_VALUE.
  • Aggregates as windows: SUM/AVG/COUNT/MIN/MAX(…) OVER (…): running totals, moving averages, shares of a group total.
  • OVER (PARTITION BY … ORDER BY … [ROWS|RANGE BETWEEN … AND …]); reuse a definition with WINDOW w AS (…) and OVER w.

Advanced Frames, evaluation order and Hive specifics

  • Default frame: with ORDER BY it is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW (that is why SUM gives a running total and LAST_VALUE returns the current row); without ORDER BY it is the whole partition.
  • Ranking functions and LAG/LEAD take no frame.
  • Windows are computed after WHERE, GROUP BY and HAVING, so you cannot filter on them in WHERE (error 10002 in our lab); filter in an outer query, or with QUALIFY.
  • QUALIFY in Hive 4.2.1: it filtered correctly alone, but in our tests QUALIFY together with ORDER BY in the same query returned unfiltered rows (50,000 instead of 8). Until you have verified your version, prefer the subquery form SELECT … FROM (… ROW_NUMBER() … AS rn) x WHERE rn = 1.
  • Windows over aggregates are allowed: SUM(COUNT(*)) OVER (PARTITION BY city) gives shares in one query.
  • Execution: rows are shuffled by the partition key and sorted by the order key, then a PTF (partitioned table function) operator computes the values. Huge partitions (skew) are expensive.

Exam tip: “Difference between RANK, DENSE_RANK and ROW_NUMBER.” Show one tie: ROW_NUMBER 6, 7, 8 (unique); RANK 6, 6, 6 then 9 (gaps); DENSE_RANK 6, 6, 6 then 7 (no gaps). Then write a top-3-per-group query with ROW_NUMBER in a subquery.

3 Types and ways to use it

Common window patterns

PatternWriteBusiness use
Top-N per groupROW_NUMBER() OVER (PARTITION BY city ORDER BY spend DESC) then rn <= 3Loyalty campaigns, best sellers
De-duplicate (latest per key)ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY updated_at DESC) = 1Clean CDC / duplicate events
Running totalSUM(revenue) OVER (ORDER BY day)Month-to-date revenue
Moving averageAVG(revenue) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)Smooth daily noise
Change vs previousrevenue - LAG(revenue) OVER (ORDER BY day)Day-on-day growth
Time since last eventts - LAG(ts) OVER (PARTITION BY customer ORDER BY ts)Churn, sessions, fraud
Share of groupCOUNT(*) / SUM(COUNT(*)) OVER (PARTITION BY city)Payment mix per city
Buckets / percentilesNTILE(4), PERCENT_RANK(), CUME_DIST()Quartiles, customer tiers

LAST_VALUE(x) OVER (ORDER BY …) usually returns the current row’s value, not the last one, because the default frame ends at the current row. Write ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING when you mean the last row of the partition (shown in Step 5).

The growth team’s three requests, and two traps

  1. Step 1 · Rank customers inside each city

    WITH c AS (SELECT city, customer_id, COUNT(*) AS n_orders
           FROM orders GROUP BY city, customer_id)
SELECT * FROM (
  SELECT city, customer_id, n_orders,
    ROW_NUMBER() OVER (PARTITION BY city ORDER BY n_orders DESC, customer_id) AS rn,
    RANK()       OVER (PARTITION BY city ORDER BY n_orders DESC) AS rnk,
    DENSE_RANK() OVER (PARTITION BY city ORDER BY n_orders DESC) AS drnk
  FROM c WHERE city = 'Chennai') x
WHERE rn BETWEEN 6 AND 10 ORDER BY rn;
    +----------+----------------+-------------+-------+--------+---------+ | x.city | x.customer_id | x.n_orders | x.rn | x.rnk | x.drnk | +----------+----------------+-------------+-------+--------+---------+ | Chennai | 1208 | 33 | 6 | 6 | 6 | | Chennai | 1370 | 33 | 7 | 6 | 6 | | Chennai | 1936 | 33 | 8 | 6 | 6 | | Chennai | 682 | 32 | 9 | 9 | 7 | | Chennai | 697 | 32 | 10 | 9 | 7 | +----------+----------------+-------------+-------+--------+---------+
    Three customers tie at 33 orders. ROW_NUMBER breaks the tie (by customer_id, so it is repeatable); RANK gives 6, 6, 6 and jumps to 9; DENSE_RANK continues with 7. Window functions run on the grouped rows of the CTE.

  2. Step 2 · Top 1 per city: the subquery pattern

    SELECT * FROM (
  SELECT order_id, city, amount,
         ROW_NUMBER() OVER (PARTITION BY city ORDER BY amount DESC, order_id) AS rn
  FROM orders WHERE order_id < 100020) x
WHERE rn = 1 ORDER BY city;

    The biggest order per city among the first 19 orders. Change rn = 1 to rn <= 3 for the top three. This form works in every Hive version and every SQL engine.

  3. Step 3 · Running total, moving average, change vs previous day

    WITH d AS (SELECT order_date, SUM(amount) AS revenue FROM orders
           WHERE city = 'Pune' GROUP BY order_date)
SELECT order_date, revenue,
  SUM(revenue) OVER (ORDER BY order_date) AS running_total,
  ROUND(AVG(revenue) OVER (ORDER BY order_date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW), 2) AS avg_7d,
  revenue - LAG(revenue) OVER (ORDER BY order_date) AS change_vs_prev
FROM d ORDER BY order_date LIMIT 8;

  4. Step 4 · Gap since the customer’s previous order, and shares

    SELECT customer_id, order_ts,
  LAG(order_ts) OVER (PARTITION BY customer_id ORDER BY order_ts) AS prev_ts,
  ROUND((unix_timestamp(order_ts) - unix_timestamp(
     LAG(order_ts) OVER (PARTITION BY customer_id ORDER BY order_ts))) / 3600, 1) AS gap_hours
FROM orders WHERE customer_id = 1492 ORDER BY order_ts LIMIT 4;

SELECT city, payment, COUNT(*) AS n,
  ROUND(100 * COUNT(*) / SUM(COUNT(*)) OVER (PARTITION BY city), 1) AS pct
FROM orders WHERE city = 'Thane' GROUP BY city, payment ORDER BY n DESC;

  5. Step 5 · Trap: the default frame of LAST_VALUE

    SELECT order_id, amount,
  FIRST_VALUE(amount) OVER w AS first_amt,
  LAST_VALUE(amount)  OVER w AS last_default,
  LAST_VALUE(amount)  OVER (ORDER BY order_id
     ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS last_full
FROM orders WHERE order_id < 100005
WINDOW w AS (ORDER BY order_id) ORDER BY order_id;
    +-----------+---------+------------+---------------+------------+ | order_id | amount | first_amt | last_default | last_full | +-----------+---------+------------+---------------+------------+ | 100001 | 530.00 | 530.00 | 530.00 | 180.00 | | 100002 | 500.00 | 530.00 | 500.00 | 180.00 | | 100003 | 410.00 | 530.00 | 410.00 | 180.00 | | 100004 | 180.00 | 530.00 | 180.00 | 180.00 | +-----------+---------+------------+---------------+------------+
    With the default frame (up to the current row) LAST_VALUE simply echoes each row’s amount. Only the explicit full frame returns 180.00, the real last value. The named WINDOW w avoids repeating the same OVER definition.

  6. Step 6 · Trap: filtering on a window function

    SELECT order_id FROM orders WHERE ROW_NUMBER() OVER (ORDER BY amount) = 1;

-- QUALIFY alone filters correctly:
SELECT order_id, city, amount FROM orders WHERE order_id < 100020
QUALIFY ROW_NUMBER() OVER (PARTITION BY city ORDER BY amount DESC, order_id) = 1;

-- QUALIFY + ORDER BY in the same query (Hive 4.2.1, our lab):
SELECT … FROM orders QUALIFY ROW_NUMBER() OVER (…) = 1 ORDER BY city;
    Error: Error while compiling statement: FAILED: SemanticException [Error 10002]: Line 1:62 Invalid column reference 'amount' … 6 rows (one per city, same as Step 2) 50,000 rows returned: the QUALIFY filter was not applied
    Window results do not exist yet when WHERE runs. QUALIFY is meant for this, and it worked on its own, but combined with ORDER BY at the same level our Hive 4.2.1 returned every row. Use the subquery pattern from Step 2 in production code, and test QUALIFY on your exact version before relying on it.

# ROW_NUMBER, RANK and DENSE_RANK over the same ordered partition
rows = [("Chennai", 1208, 33), ("Chennai", 1370, 33), ("Chennai", 1936, 33),
        ("Chennai", 682, 32), ("Chennai", 697, 32)]          # real counts, ranks 6..10

rn, rank, dense = 5, 5, 5          # the five rows above these had ranks 1..5
prev = None
for i, (city, cust, n) in enumerate(rows):
    rn += 1                                  # ROW_NUMBER: always +1
    if n != prev:
        rank = rn                            # RANK: jump to the row number
        dense += 1                           # DENSE_RANK: next integer, no gaps
    prev = n
    print(f"{city} {cust:5} n={n}  rn={rn:2}  rank={rank}  dense={dense}")

  NTILE(4)       OVER (ORDER BY amount) AS quartile,

2 · QUALIFY inside a subquery

SELECT COUNT(*) AS n FROM (
  SELECT order_id, city FROM orders
  QUALIFY ROW_NUMBER() OVER (PARTITION BY city ORDER BY amount DESC, order_id) = 1
  ORDER BY city) t;
+----+ | n | +----+ | 8 | +----+

One row per city, as expected. The very same QUALIFY + ORDER BY run as the outer query returned all 50,000 rows in our lab. Count the rows of any QUALIFY query before trusting it on your Hive version.

SELECT city, payment, COUNT(*) AS n,

FROM orders WHERE city = 'Thane'
GROUP BY city, payment ORDER BY n DESC;

9 Quiz and revision

Check yourself

Quick revision

Lesson 3.6 in one screen

  • Syntax: func(…) OVER (PARTITION BY … ORDER BY … [ROWS|RANGE BETWEEN …]). Every input row stays.
  • ROW_NUMBER 1,2,3 always unique · RANK ties share, then gaps (6,6,6,9) · DENSE_RANK no gaps (6,6,6,7).
  • Top-N per group: rank in a subquery / CTE, filter rn <= N outside. Add a tie-breaker for ROW_NUMBER.
  • Running total: SUM(x) OVER (ORDER BY d). Moving average: ROWS BETWEEN 6 PRECEDING AND CURRENT ROW.
  • LAG / LEAD(col, offset, default): previous / next row; NULL at the edges without a default.
  • FIRST_VALUE is safe; LAST_VALUE needs a frame to UNBOUNDED FOLLOWING.
  • NTILE(n) buckets · PERCENT_RANK = (rank−1)/(rows−1) · CUME_DIST = rows ≤ current / rows.
  • Windows run after WHERE, GROUP BY and HAVING, so SUM(COUNT(*)) OVER (PARTITION BY city) works; you cannot use them in WHERE.
  • QUALIFY exists in Hive 4, but check it on your version; the subquery pattern is portable.

Interview and viva questions

ROWS or RANGE: what is the difference?

ROWS counts physical rows: 6 PRECEDING means six rows back. RANGE works on the ORDER BY value, so rows with the same value are treated together, and with no explicit frame and an ORDER BY the default is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW. With duplicate ORDER BY values a running total using the default frame jumps for all tied rows at once. Use ROWS when you want strictly one row at a time.

Are window functions slow in Hive?

Each distinct PARTITION BY / ORDER BY combination needs the data shuffled and sorted by those keys, much like a GROUP BY. Functions that share the same OVER clause are computed in one pass, so reuse one definition (a named WINDOW) where you can, and filter rows with WHERE before the window runs.

Can I use a window function without PARTITION BY?

Yes. The whole result becomes one window, as in the Pune running total. Be careful on big tables: one window means one reducer has to sort everything.

What does OVER () with nothing inside mean?

The window is all rows with no order, so SUM(x) OVER () puts the grand total on every row. That is handy for percentage-of-total columns.

Is QUALIFY safe to use?

QUALIFY is supported in Hive 4 and filtered correctly on its own and inside a subquery in our tests. Combined with ORDER BY in the same top-level query, Hive 4.2.1 returned every row. Until you have tested your exact version, prefer the subquery pattern, and always check the row count.

P8Business problem

Dedup before counting

A feed has 5 rows for 3 orders. How many delivered orders are there after keeping the latest version of each?

Input
(order, status, version)
Expected output
{1: 'delivered', 2: 'cancelled', 3: 'delivered'} delivered: 2
Show solution and explanation 
feed = [(1, "placed", 1), (1, "delivered", 2), (2, "placed", 1), (2, "cancelled", 2), (3, "delivered", 1)]
latest = {}
for o, s, v in sorted(feed, key=lambda r: r[2]):
    latest[o] = s
print(latest, "delivered:", sum(1 for s in latest.values() if s == "delivered"))
{1: 'delivered', 2: 'cancelled', 3: 'delivered'} delivered: 2

How it works: 3 orders with 2 delivered. Counting raw rows would report 5 orders and 2 still “placed”, although both of those orders moved on. Status counts must come from the latest version of each order.

Real-world scenario questions (asked in company interviews)

Window functions are among the most asked SQL interview topics. Expect top-N per group, the ranking differences and LAG questions.

Any company · SQLFresher

“Second highest order in each city”

Write a query that returns the second highest order amount in every city.

The interviewer is checking: do you know ranking functions and ties?

Show a strong answer
SELECT city, amount FROM (
  SELECT city, amount,
         DENSE_RANK() OVER (PARTITION BY city ORDER BY amount DESC) AS dr
  FROM orders) x
WHERE dr = 2;

Say why DENSE_RANK: if two orders tie for the highest, RANK would skip 2.

Avoid: Using LIMIT, which gives one global answer, not one per city.

Data engineeringMid-level

Duplicates from a change feed

The orders table receives every update of an order. Reports double count. Fix it.

The interviewer is checking: can you de-duplicate with ROW_NUMBER?

Show a strong answer
  1. Rank versions: ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY updated_at DESC, seq DESC).
  2. Keep rn = 1 in an outer query, and write the result to a clean table or view.
  3. Check: COUNT(*) equals COUNT(DISTINCT order_id).

Avoid: SELECT DISTINCT, which keeps every version because the statuses differ.

AnalyticsMid-level

QUALIFY returns too many rows

A colleague’s “latest row per key” query with QUALIFY and ORDER BY returns all rows on your cluster.

The interviewer is checking: do you verify results instead of trusting syntax?

Show a strong answer
  • Compare COUNT(*) of the result with the number of distinct keys.
  • Rewrite with the subquery pattern, or move ORDER BY to an outer query; both worked in our lab.
  • Report the behaviour with the exact Hive version, and add a row-count check to the job.

Avoid: “QUALIFY is standard, so it must be right”.

Product analyticsSenior

Sessions and retention

Define user sessions (gap ≥ 30 minutes starts a new session) and report sessions per user per day.

The interviewer is checking: can you combine LAG with a running sum?

Show a strong answer
  • Gap: unix_timestamp(ts) - unix_timestamp(LAG(ts) OVER (PARTITION BY user ORDER BY ts)).
  • Flag: 1 when the gap is NULL or ≥ 1800 seconds; session id = SUM(flag) OVER (PARTITION BY user ORDER BY ts ROWS UNBOUNDED PRECEDING).
  • Then GROUP BY user, date, session id.

Avoid: A self-join on “the previous event”, which is slow and hard to get right.
