Row formats and SerDes: CSV, JSON and logs

Every Hive table has a translator between the file and the columns: its SerDe. Pick the default one for a CSV with quoted commas and the columns shift. Pick OpenCSVSerde and the columns are right but every value is a string. JSON maps neatly to nested types, until one broken line stops the whole query. This lesson reads a menu CSV, restaurant JSON and a web server log with the right SerDe each, with real Hive 4.2.1 output.

1 The story

“Why did ‘Dal, Rice combo’ break my menu table?”

Before you start: know column types and delimiters from Lesson 2.3. A little regular-expression knowledge helps for Step 6 (each (…) captures one column).

The TiffinGo menu team exports a CSV. One dish is called "Dal, Rice combo", with a comma inside quotes. Kabir’s table shows "Dal as the name, NULL as the price and 120 as the category. The restaurant data arrives as JSON, and the operations team wants to query the web server’s access log, where nothing is separated by commas at all.

Kabir

Sir, a comma is a comma. How is Hive supposed to know which commas are inside quotes?

Arjun Sir

It isn’t, unless you choose a reader that understands quotes. Every Hive table has a SerDe, short for Serializer/Deserializer: the code that turns bytes into columns when reading and columns into bytes when writing. The default one splits on a character and knows nothing about quotes.

Riya

So there is a different SerDe for CSV, for JSON and for logs?

Arjun Sir

Exactly. OpenCSVSerde understands quotes, the JsonSerDe maps JSON keys to columns, and RegexSerDe cuts a line with a regular expression. Each has habits you must know: one returns every column as a string, one fails the whole query on a single broken line. We will hit each of them in the lab.

2 Definition

Row formats and SerDes

Formal definition (write this in exams)

A SerDe (Serializer/Deserializer) is the Hive component that converts between the bytes of a stored record and Hive’s row representation: the deserializer parses records into columns when data is read, and the serializer converts rows into records when data is written. A table’s row format names its SerDe and SerDe properties, either with the shorthand ROW FORMAT DELIMITED … (LazySimpleSerDe) or with ROW FORMAT SERDE 'class' WITH SERDEPROPERTIES (…); the file format (STORED AS) names the input and output formats that split files into records.

In simple words

The file format decides how a file is cut into records (usually lines). The SerDe decides how one record is cut into columns. Choose a SerDe that understands your file: delimited text, CSV with quotes, JSON, or a pattern for logs.

Words you’ll meet in this lesson

SerializeTurn a row into bytes for writing to a file.
DeserializeTurn bytes from a file into a row with columns.
InputFormatSplits a file into records (for text: one record per line).
SERDEPROPERTIESSettings for a SerDe, such as separator, quote character or regex.
LazySimpleSerDeThe default text SerDe. “Lazy” because it parses a column only when a query uses it.
Quote characterMarks text that may contain the separator: "Dal, Rice combo".
Capturing groupA part of a regular expression in brackets; RegexSerDe maps group 1 to column 1, and so on.
NULL markerText that means NULL in a file: \N by default for delimited text.

SerDes at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Translators at the door

  • Files speak different “languages”: CSV, JSON, log lines.
  • A SerDe is the translator Hive puts at the door of a table. Reading: file language → rows and columns. Writing: rows → file language.
  • Pick the wrong translator and Hive misunderstands: columns shift, values become NULL.

Intermediate The SerDes you will use

  • LazySimpleSerDe (the default for ROW FORMAT DELIMITED): splits on single characters; no quote handling; empty text stays an empty string; \N means NULL.
  • OpenCSVSerde: handles quotes and escaped quotes; but it returns every column as STRING, whatever you declare.
  • JsonSerDe (STORED AS JSONFILE): one JSON object per line; nested objects map to STRUCT and MAP, lists to ARRAY; extra keys ignored, missing keys NULL.
  • RegexSerDe: one capturing group per column; lines that do not match give a row of NULLs.
  • Binary formats (ORC, Parquet, Avro) have their own SerDes chosen by STORED AS (Module 6).

Advanced What the lab showed about edge cases (Hive 4.2.1)

  • OpenCSVSerde: typeof(price) was string although we declared INT; SUM(price) returned 395.0 (string → DOUBLE).
  • JsonSerDe: one line with a missing } made the whole query fail with JsonEOFException. A string where an INT was expected gave 0, not NULL. A key written CITY still matched column city.
  • RegexSerDe: in HiveQL string literals a backslash must be doubled: write \\S+ in the DDL to get the regex \S+.
  • LazySimpleSerDe: serialization.null.format changes the NULL marker (we set it to NA); an empty field is still '', not NULL.

Exam tip: “What is a SerDe in Hive?” Expand the name, say it converts records to rows (deserialize, on read) and rows to records (serialize, on write), name the default LazySimpleSerDe and two others (OpenCSVSerde, JsonSerDe, RegexSerDe, ORC/Parquet/Avro SerDes), and show ROW FORMAT SERDE … WITH SERDEPROPERTIES.

  3. Step 3 · The OpenCSVSerde surprise: everything is a string

    SELECT SUM(price) AS total FROM menu_csv;

    We declared price INT, yet the values arrive as strings, so arithmetic converts them to DOUBLE (395.0, 121.0). Cast explicitly (CAST(price AS INT)) or copy the data into a typed ORC table.

What you see
  1. The menu file has a dish name with a comma inside quotes.
  2. The default table splits that line wrongly: the name is cut and the price is NULL.
  3. With OpenCSVSerde the row is right, but typeof(price) says string.
  4. JSON keys become columns, including an array and a nested object.
  5. One unfinished JSON line makes the whole query fail.
  6. A log line that does not match the regex becomes a row of NULLs.
Behind the screen
  1. The text InputFormat has already split the file into lines. Now the SerDe must split one line into columns.
  2. LazySimpleSerDe splits on every comma: five pieces for four columns. Values land in the wrong columns.
  3. OpenCSVSerde respects quotes but returns all values as strings, so arithmetic converts them to DOUBLE.
  4. The JsonSerDe matches keys to column names, ignoring case; nested values map to complex types.
  5. The JSON parser reaches the end of the input inside an object and throws an exception for the whole read.
  6. RegexSerDe maps capturing group 1 to column 1, and so on. If the line does not match, nothing is captured.

6 Real-world use

SerDes in real pipelines

1. Partner and government CSV exports

Bank statements, GST reports and partner catalogues often quote fields with commas. A raw OpenCSVSerde table reads them correctly before a typed copy is made.

Export→OpenCSVSerde→Typed ORC

2. App and API events

Mobile apps and APIs emit JSON. Landing tables use STORED AS JSONFILE with ARRAY, MAP and STRUCT columns that mirror the payload.

App events→JsonSerDe→Event tables

3. Server and security logs

Web, firewall and application logs follow fixed patterns. RegexSerDe tables let operations and security teams query them with SQL during an incident.

Log files→RegexSerDe→Incident queries

4. Exports between systems

Data moved between databases is often exported as tab- or pipe-separated text with \N for NULL, which LazySimpleSerDe reads quickly with no extra settings.

DB export→Delimited text→Hive

5. Curated warehouse tables

Once data is clean it is stored as ORC or Parquet, whose SerDes keep types, compress well and let Hive skip data. Text SerDes stay at the edges of the pipeline.

Raw text→INSERT … SELECT→ORC tables

Interview and viva questions

What is the difference between a SerDe and a file format?

The file format (input and output format classes) decides how a file is split into records and how records are written into files; for text that means lines. The SerDe decides how one record is turned into columns and back. For text tables you can combine the text format with different SerDes (LazySimple, OpenCSV, JSON, Regex); binary formats such as ORC and Parquet come with matching SerDes.

Why does OpenCSVSerde return everything as a string?

Its parser produces text values and the SerDe exposes them as strings, regardless of the declared types; Hive then converts implicitly when you compute (string to DOUBLE), which is why SUM(price) gave 395.0. Cast explicitly in queries or, better, copy the data once into a typed ORC table.

Can Hive skip bad JSON lines instead of failing?

Some JSON SerDes and settings can ignore malformed records, depending on version and SerDe. In our Hive 4.2.1 test the built-in JsonSerDe failed the query. The robust approach is to validate and quarantine bad lines at ingestion so the table only ever sees valid JSON.

Is RegexSerDe fast enough for big logs?

Regular expressions cost CPU on every read, and logs are large text. RegexSerDe tables are excellent for exploring and incident work; for repeated analysis, convert the parsed logs daily into a partitioned ORC table, so the regex runs once per line instead of once per query.

Can I write data with RegexSerDe or OpenCSVSerde?

RegexSerDe is meant for reading; writing through it is not supported in general. OpenCSVSerde can write, quoting values as needed, but all values are strings. For tables you write to, prefer ORC or Parquet, or delimited text with a separator that never appears in the data.

obj = json.loads('{"name": "No Id", "city": "Thane"}')
print([obj.get(c) for c in ["restaurant_id", "name", "city"]])
[None, 'No Id', 'Thane']

How it works: [None, 'No Id', 'Thane']: a missing key becomes NULL, as in the lab.

P4Medium

Unmatched log lines

Count how many of these lines match a pattern that needs an IP at the start and a 3-digit status after the quoted request.

Input
3 lines, one health check
Expected output
matched 2 | would be all-NULL rows: 1
Show solution and explanation 
import re
pat = re.compile(r'^\d+\.\d+\.\d+\.\d+ .*" (\d{3}) ')
lines = ['10.0.0.1 - - [t] "GET / HTTP/1.1" 200 5', 'health-check ping', '10.0.0.2 - - [t] "GET /x HTTP/1.1" 500 9']
matched = sum(1 for l in lines if pat.match(l))
print("matched", matched, "| would be all-NULL rows:", len(lines) - matched)
matched 2 | would be all-NULL rows: 1

How it works: 2 matched, 1 all-NULL row. Track this number: a sudden jump means the log format changed.

P6Medium

Write CSV safely

Write the row [1, "Dal, Rice combo", 120] as one CSV line so that a CSV reader gets 3 fields back.

Input
[1, "Dal, Rice combo", 120]
Expected output
1,"Dal, Rice combo",120
Show solution and explanation 
import csv, io
buf = io.StringIO()
csv.writer(buf).writerow([1, "Dal, Rice combo", 120])
print(buf.getvalue().strip())
1,"Dal, Rice combo",120

How it works: 1,"Dal, Rice combo",120. Serialising is the other half of a SerDe: values with separators must be quoted.

P7Business problem

Cost of parsing every query

A 200 GB text log table is queried 40 times a day with a RegexSerDe at 2 minutes of cluster time per 10 GB. A daily ORC copy reads 25 GB per query at 0.5 minutes per 10 GB, plus 40 minutes once to build. Compare daily cluster minutes.

Input
200 GB · 40 queries · rates above
Expected output
regex on raw text: 1600.0 min/day
daily ORC copy   : 90.0 min/day
Show solution and explanation 
raw = 40 * (200 / 10) * 2
orc = 40 * (25 / 10) * 0.5 + 40
print("regex on raw text:", raw, "min/day")
print("daily ORC copy   :", orc, "min/day")
regex on raw text: 1600.0 min/day daily ORC copy : 90.0 min/day

How it works: 1,600 vs 90 minutes a day. Parse once, read many times. (Rates are illustrative.)

P8Business problem

Quarantine rate alert

A day had 1,20,000 JSON lines; 36 were quarantined. Alert if the rate is above 0.02%.

Input
120,000 lines · 36 quarantined
Expected output
rate 0.030% | alert: True
Show solution and explanation 
total, bad = 120_000, 36
rate = bad / total
print(f"rate {rate:.3%} | alert: {rate > 0.0002}")
rate 0.030% | alert: True

How it works: 0.030% is above the 0.02% threshold, so the app team is alerted with sample lines, before the problem grows.

Real-world scenario questions (asked in company interviews)

SerDe questions show whether you have loaded real-world files. Interviewers love the quoted-comma and JSON cases.

Retail / partner dataFresher

Columns are shifted in a CSV table

Some rows of a product table show the price in the category column.

The interviewer is checking: can you diagnose quoted separators?

Show a strong answer
  1. Look at the raw lines: the shifted rows contain a comma inside a quoted field.
  2. The default LazySimpleSerDe has no quote handling. Use OpenCSVSerde with quoteChar, or ask the producer for a different separator.
  3. Remember OpenCSVSerde returns strings; cast into a typed curated table.

Avoid: “clean the commas with a script first” without asking why they are there.

App analyticsMid-level

Nightly JSON job fails

The nightly job over app events fails with a SerDeException mentioning JsonEOFException.

The interviewer is checking: do you know JSON SerDe failure modes and fixes?

Show a strong answer
  • A malformed line (often a truncated upload) makes the JsonSerDe fail the whole read.
  • Find it: search the new files for lines that do not parse; move them to a quarantine folder and re-run.
  • Prevent: validate at ingestion, write atomically (temp file then rename), monitor quarantine counts.

Avoid: turning off all validation so bad data flows silently.

Operations / SREFresher

Query web logs during an incident

You have 30 minutes to find which endpoint returns most 500 errors from raw access logs on HDFS.

The interviewer is checking: can you use RegexSerDe pragmatically?

Show a strong answer
  1. Create an external RegexSerDe table on the log folder with groups for ip, time, method, path, status, bytes.
  2. SELECT path, COUNT(*) FROM access_log WHERE status >= 500 GROUP BY path ORDER BY 2 DESC.
  3. Check for all-NULL rows (unmatched lines) so you know the pattern covers the data.

Avoid: copying logs into a database first; an external table needs no copy.

Data platform · designMid-level

Raw vs curated tables

Analysts query a raw OpenCSVSerde table directly and complain it is slow and full of CASTs.

The interviewer is checking: do you know the raw-to-curated pattern?

Show a strong answer
  • Keep the raw table only for ingestion. A daily job casts and cleans into a partitioned ORC table.
  • Record rejected values in a quality table and alert on spikes.
  • Point analysts and BI at the curated table: typed, compressed and fast.

Avoid: “add more memory to the cluster”.
