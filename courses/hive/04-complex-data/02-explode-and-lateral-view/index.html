Arrays and maps: explode and LATERAL VIEW

Hive tables often store lists and key–value pairs inside one cell: the dishes of an order, the tags of a restaurant, the preferences of a customer. To count or group them you must turn the list into rows. This lesson finds TiffinGo’s top dishes with LATERAL VIEW explode, shows why empty carts disappear without OUTER, and works around two real errors. All outputs are real, from Hive 4.2.1.

2 Definition

explode and LATERAL VIEW

Formal definition (write this in exams)

A table-generating function (UDTF) maps one input row to zero or more output rows. explode(array) returns one row per element and explode(map) one row per key–value pair; posexplode adds a 0-based position. A LATERAL VIEW applies a UDTF to each row of a base table and joins the output rows with that input row, forming a virtual table with a table alias and column aliases: FROM base LATERAL VIEW [OUTER] udtf(expr) tableAlias AS colAlias, …. With OUTER, rows for which the UDTF produces no output are kept with NULL values.

In simple words

explode opens a list stored in one cell and puts each item on its own row. LATERAL VIEW keeps the rest of the original row next to each item, so you can still see which order each dish came from.

Words you’ll meet in this lesson

ARRAY<T>An ordered list of values of one type. Index from 0.
MAP<K,V>Key–value pairs. Read with m['key']; a missing key gives NULL.
STRUCTNamed fields in one value. Read with s.field.
UDTFFunction that returns rows: explode, posexplode, inline, stack, json_tuple.
LATERAL VIEWApplies a UDTF to each row and joins the output with that row.
OUTERKeeps rows whose array is empty or NULL.
collect_list / collect_setAggregate rows back into an array (set removes duplicates).

Complex types and explode at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A tiffin box with compartments

  • An array is a list in one cell: ["Poha","Chai"]. A map is labelled pairs: {"spice":"mild"}. A struct is a small record: {"phone":…, "email":…}.
  • You can read one item: dishes[0], prefs['spice'], contact.phone.
  • To count or group the items you must first unpack the list into rows. That is explode.

Intermediate UDTFs and LATERAL VIEW

  • UDTF (table-generating function): explode (array → one column; map → key, value), posexplode (adds the position), inline (array of structs → columns), stack (values → rows), json_tuple and parse_url_tuple (Lesson 4.3).
  • SELECT explode(col) works only if it is the only expression in SELECT.
  • FROM t LATERAL VIEW explode(t.col) alias AS c joins each generated row with its source row, so other columns stay available for WHERE, GROUP BY and JOIN (through a subquery).
  • LATERAL VIEW OUTER keeps source rows whose array is empty or NULL, with NULL in the generated column.

Advanced What Hive does, and the costs

  • The plan uses a Lateral View Forward, a UDTF operator and a Lateral View Join inside the same map task: no shuffle is needed to explode.
  • Row counts multiply: 5,000 orders became 12,671 dish rows. Two LATERAL VIEWs in one query multiply again (a cross product per row).
  • Rules found in our lab: UDTF next to other columns → Error 10081; JOIN directly after a LATERAL VIEW → Error 10085 (explode in a subquery, then join); stack needs identical types in each column.
  • collect_list / collect_set reverse explode by aggregating back into arrays; the element order of collect_list is not guaranteed after a shuffle.

Exam tip: “What is LATERAL VIEW and why is it needed?” Answer: a UDTF such as explode cannot be selected together with other columns; LATERAL VIEW applies it to every row and joins the generated rows back to the source row. Mention OUTER for empty arrays and posexplode for positions.

Plain LATERAL VIEW silently drops rows whose array is empty or NULL. In our lab, cart 2 ([]) and cart 3 (NULL) vanished until OUTER was added. If a count of orders falls after exploding, check for this first.

    SELECT array('Poha', 'Chai') AS a, map('spice', 'hot', 'cutlery', 'no') AS m,
  named_struct('city', 'Pune', 'pin', 411001) AS s;

    array(), map() and named_struct() create values in a query, for tests and for INSERT … SELECT into complex columns.

  3. Step 3 · explode alone, and the first error

    SELECT explode(dishes) AS dish FROM order_items WHERE order_id = 100001;

SELECT order_id, explode(dishes) AS dish FROM order_items WHERE order_id = 100001;
    +----------------+ | dish | +----------------+ | Chole Bhature | | Aloo Paratha | | Lassi | | Rajma Chawal | +----------------+ Error: Error while compiling statement: FAILED: SemanticException [Error 10081]: UDTF's are not supported outside the SELECT clause, nor nested in expressions
    Alone, explode returns the 4 dishes, but without the order id. Adding a normal column next to it fails with Error 10081.

  4. Step 4 · LATERAL VIEW keeps the other columns

    SELECT o.order_id, d.dish
FROM order_items o LATERAL VIEW explode(o.dishes) d AS dish
WHERE o.order_id <= 100002;
    +-------------+--------------------+ | o.order_id | d.dish | +-------------+--------------------+ | 100001 | Chole Bhature | | 100001 | Aloo Paratha | | 100001 | Lassi | | 100001 | Rajma Chawal | | 100002 | Veg Hakka Noodles | | 100002 | Manchurian | | 100002 | Fried Rice | +-------------+--------------------+
    d is the alias of the virtual table and dish its column. Two orders became 7 rows.

  5. Step 5 · posexplode and exploding a map

    SELECT order_id, pos, dish
FROM order_items LATERAL VIEW posexplode(dishes) p AS pos, dish
WHERE order_id = 100001;

SELECT order_id, k, v
FROM order_items LATERAL VIEW explode(prefs) m AS k, v
WHERE order_id <= 100002;

    posexplode adds the position, starting at 0. A map explodes into two columns, key and value.

  6. Step 6 · Answer the question: top dishes and restaurant tags

    SELECT dish, COUNT(*) AS times
FROM order_items LATERAL VIEW explode(dishes) d AS dish
GROUP BY dish ORDER BY times DESC, dish LIMIT 5;

FROM restaurants LATERAL VIEW explode(tags) t AS tag
GROUP BY tag ORDER BY restaurants DESC;

    Once the dishes are rows, normal GROUP BY works. Sambar Rice leads with 502 orders. The same pattern counts restaurants per tag.

  7. Step 7 · Trap: empty and NULL arrays disappear (use OUTER)

    SELECT cart_id, dishes, size(dishes) AS n FROM cart_demo ORDER BY cart_id;

SELECT c.cart_id, d.dish FROM cart_demo c
  LATERAL VIEW explode(c.dishes) d AS dish ORDER BY c.cart_id;

SELECT c.cart_id, d.dish FROM cart_demo c
  LATERAL VIEW OUTER explode(c.dishes) d AS dish ORDER BY c.cart_id;
    +----------+------------------+-----+ | cart_id | dishes | n | +----------+------------------+-----+ | 1 | ["Poha","Chai"] | 2 | | 2 | [] | 0 | | 3 | NULL | -1 | +----------+------------------+-----+ +------------+---------+ | c.cart_id | d.dish | +------------+---------+ | 1 | Poha | | 1 | Chai | +------------+---------+ +------------+---------+ | c.cart_id | d.dish | +------------+---------+ | 1 | Poha | | 1 | Chai | | 2 | NULL | | 3 | NULL | +------------+---------+
    size returns 0 for an empty array and -1 for NULL. Without OUTER, carts 2 and 3 vanish; with OUTER they stay, with NULL as the dish.

  8. Step 8 · Two LATERAL VIEWs multiply rows

    SELECT r.name, t.tag, c.word
FROM restaurants r
LATERAL VIEW explode(r.tags) t AS tag
LATERAL VIEW explode(split(r.cuisine, ' ')) c AS word
WHERE r.restaurant_id = 8;
    +-------------------+---------+---------+ | r.name | t.tag | c.word | +-------------------+---------+---------+ | Singh Bhojanalay | jain | North | | Singh Bhojanalay | jain | Indian | | Singh Bhojanalay | budget | North | | Singh Bhojanalay | budget | Indian | +-------------------+---------+---------+
    2 tags × 2 words = 4 rows for one restaurant. With long arrays this grows fast, so explode only what the question needs.

  9. Step 9 · Trap: JOIN after LATERAL VIEW, and collecting back

    -- fails:
SELECT o.city, d.dish FROM order_items i LATERAL VIEW explode(i.dishes) d AS dish
  JOIN orders o ON o.order_id = i.order_id;

-- works: explode in a subquery, then join
SELECT o.city, size(collect_list(e.dish)) AS n_rows, size(collect_set(e.dish)) AS n_distinct
FROM (SELECT i.order_id, d.dish FROM order_items i
      LATERAL VIEW explode(i.dishes) d AS dish) e
JOIN orders o ON o.order_id = e.order_id
GROUP BY o.city ORDER BY n_rows DESC LIMIT 4;
    Error: Error while compiling statement: FAILED: SemanticException [Error 10085]: Line 2:60 JOIN with a LATERAL VIEW is not supported 'order_id' +------------+---------+-------------+ | o.city | n_rows | n_distinct | +------------+---------+-------------+ | Mumbai | 2508 | 32 | | Bengaluru | 2450 | 32 | | Pune | 2012 | 28 | | Hyderabad | 1517 | 20 | +------------+---------+-------------+
    Hive does not allow a JOIN directly after a LATERAL VIEW (Error 10085). Wrap the explode in a subquery. collect_list keeps duplicates, collect_set removes them: Mumbai had 2,508 dish rows but only 32 different dishes.

  10. Step 10 · inline and stack

    SELECT inline(array(named_struct('dish', 'Poha', 'qty', 2),
                    named_struct('dish', 'Chai', 'qty', 3)));

SELECT stack(3, 'UPI', 60.5, 'Card', 20.2, 'COD', 8.9) AS (payment, pct);
SELECT stack(3, 'UPI', 60.5D, 'Card', 20.2D, 'COD', 8.9D) AS (payment, pct);
    +-------+------+ | dish | qty | +-------+------+ | Poha | 2 | | Chai | 3 | +-------+------+ Error: Error while compiling statement: FAILED: UDFArgumentException Argument 2's type (decimal(3,1)) should be equal to argument 6's type (decimal(2,1)) +----------+-------+ | payment | pct | +----------+-------+ | UPI | 60.5 | | Card | 20.2 | | COD | 8.9 | +----------+-------+
    inline turns structs into columns. stack unpivots values into rows, but each column must have one type: 60.5 is DECIMAL(3,1) and 8.9 is DECIMAL(2,1), so Hive refused. The D suffix makes them all DOUBLE.

  5. Plain LATERAL VIEW drops rows that generate nothing; OUTER keeps them with NULL.

6 Real-world use

explode and LATERAL VIEW at work

1. Basket analysis

E-commerce and food apps store cart items as arrays; exploding them gives best sellers, items bought together and average basket size.

Orders→explode items→Top items

2. Tags and categories

Products, articles and restaurants carry several tags; explode turns them into rows for counts and filters per tag.

Tag arrays→explode→Counts per tag

3. Flexible attributes

Device or app event properties are kept in MAP columns; explode(map) turns them into key–value rows for analysis without changing the schema.

Event props map→explode(map)→Key-value rows

4. Unpivoting wide tables

Monthly columns (jan, feb, mar…) from spreadsheets are turned into month–value rows with stack for loading into fact tables.

Wide table→stack→Long table

5. Building features

For recommendations, a customer’s ordered dishes are collected into an array with collect_set, the reverse of explode.

Order rows→collect_set→Dish list per customer

# LATERAL VIEW explode in Python: one output row per array element, keeping the order id
orders = [(100001, ["Chole Bhature", "Aloo Paratha", "Lassi", "Rajma Chawal"]),
          (100002, ["Veg Hakka Noodles", "Manchurian", "Fried Rice"])]

rows = []
for order_id, dishes in orders:          # FROM order_items o
    for dish in dishes:                  # LATERAL VIEW explode(o.dishes) d AS dish
        rows.append((order_id, dish))

for r in rows:
    print(r)
print(len(orders), "orders ->", len(rows), "rows")

Run on your PC: plan, a filter and rebuilding arrays

Three more queries for Beeline on the TiffinGo data. Outputs are real, from Hive 4.2.1.

1 · The plan of a LATERAL VIEW

EXPLAIN SELECT o.order_id, d.dish
FROM order_items o LATERAL VIEW explode(o.dishes) d AS dish;
| Lateral View Forward [LVF_1] | | UDTF Operator [UDTF_4] | | Lateral View Join Operator [LVJ_5] | (lines picked from the real plan)

The forward operator sends each row two ways: to the UDTF that generates dish rows, and straight to the join that glues the order columns back on. All of it runs in the map phase: exploding needs no shuffle.

2 · Filter on the exploded column, or not explode at all

SELECT COUNT(DISTINCT order_id) AS orders_with_lassi
FROM order_items LATERAL VIEW explode(dishes) d AS dish WHERE dish = 'Lassi';

SELECT COUNT(*) AS via_array_contains FROM order_items
WHERE array_contains(dishes, 'Lassi');
+--------------------+ | orders_with_lassi | +--------------------+ | 438 | +--------------------+ +---------------------+ | via_array_contains | +---------------------+ | 438 | +---------------------+

Both give 438. For a simple “contains” test, array_contains is cheaper because no extra rows are created.

3 · Collect rows back into an array

SELECT order_id, collect_list(dish) AS dishes_again
FROM (SELECT order_id, dish FROM order_items
      LATERAL VIEW explode(dishes) d AS dish WHERE order_id = 100001) x
GROUP BY order_id;
+-----------+----------------------------------------------------+ | order_id | dishes_again | +-----------+----------------------------------------------------+ | 100001 | ["Chole Bhature","Aloo Paratha","Lassi","Rajma Chawal"] | +-----------+----------------------------------------------------+

collect_list reverses explode. Here the order happened to be kept, but after a shuffle the element order is not guaranteed; use posexplode and sort_array or an ordered struct if order matters.

Quick revision

Lesson 4.2 in one screen

  • Build: array(), map(), named_struct(), struct().

  • collect_list (keeps duplicates) and collect_set (distinct) reverse explode; element order is not guaranteed.

Interview and viva questions

Is exploding expensive?

Exploding itself runs in the map phase without a shuffle, but it multiplies rows: everything after it (joins, GROUP BY, writes) handles more data. Filter source rows first, explode only the arrays you need, and use array_contains or size when you only need a yes/no or a count.

Can I use explode in a WHERE clause?

No. UDTFs are allowed only in SELECT (alone) or in LATERAL VIEW. Filter on the generated column after the LATERAL VIEW, as in WHERE dish = 'Lassi'.

Why store arrays at all, instead of a separate table?

Arrays keep related values with their parent row, avoid a join for common reads and match JSON sources. A separate table (order_id, dish) is better when items are queried on their own all the time. Many teams keep both: raw arrays plus an exploded table built by the pipeline.

Does Spark use the same syntax?

Spark SQL supports LATERAL VIEW explode and also allows explode directly in SELECT next to other columns. Queries written with LATERAL VIEW work in both engines.

What is the difference between inline and explode?

explode on an array of structs gives one column holding each struct; inline spreads the struct fields into separate columns. For line items with several fields, inline is simpler.

Real-world scenario questions (asked in company interviews)

Array questions appear in most Hive interviews: explode, LATERAL VIEW, OUTER and collect_set.

Any company · HiveQLFresher

“Count orders per dish”

order_items(order_id INT, dishes ARRAY<STRING>). Return each dish and how many orders contain it.

The interviewer is checking: can you use LATERAL VIEW?

Show a strong answer
SELECT dish, COUNT(DISTINCT order_id) AS orders
FROM order_items LATERAL VIEW explode(dishes) d AS dish
GROUP BY dish
ORDER BY orders DESC;

COUNT(DISTINCT order_id) handles an order that lists the same dish twice.

Avoid: SELECT order_id, explode(dishes), which fails with Error 10081.

Data engineeringMid-level

Row counts dropped after a new pipeline step

After adding an explode step, the number of customers in a report fell by 12%.

The interviewer is checking: do you know LATERAL VIEW drops empty arrays?

Show a strong answer
  1. Count source rows with size(arr) <= 0 (empty is 0, NULL is -1).
  2. Use LATERAL VIEW OUTER if every source row must stay.
  3. Count distinct keys, not exploded rows, in reports.

Avoid: “Some data was lost in HDFS.”

AnalyticsMid-level

Unpivot a wide spreadsheet

Finance uploads a table with one column per month. Analysts need month as a row.

The interviewer is checking: do you know stack (or UNION ALL)?

Show a strong answer
  • SELECT city, m.month, m.orders FROM wide LATERAL VIEW stack(3, 'jul', jul, 'aug', aug, 'sep', sep) m AS month, orders.
  • Make all values one type (CAST), or Hive rejects the call.
  • One scan of the table, instead of three with UNION ALL.

Avoid: Three separate queries glued together by hand.

Data modellingSenior

Design line items for analytics

Orders arrive as JSON with a list of items, each with dish, qty and price. How should the Hive tables look?

The interviewer is checking: can you balance nested and flat models?

Show a strong answer
  • Raw table: items ARRAY<STRUCT<dish:STRING, qty:INT, price:DECIMAL(8,2)>> (one row per order).
  • Curated table: LATERAL VIEW inline(items) into (order_id, dish, qty, price), partitioned by date.
  • Avoid parallel arrays (dishes, qty) that must be matched by position.

Avoid: Only a comma-separated string of dishes.
