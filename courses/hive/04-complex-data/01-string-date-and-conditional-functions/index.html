String, date and conditional functions

1 The story

“Why does my report say zero orders were delivered?”

Before you start: you need SELECT and WHERE (3.1) and data types (2.3).

Kabir’s first weekly report for TiffinGo shows 0 delivered orders, while the app clearly delivered thousands. The same report puts the first website visit of October at 6:30 pm on 30 September, and the vendor who receives the customer list complains that it contains full phone numbers.

Kabir

Sir, I wrote CASE status WHEN 'delivered' THEN 1 END. Hive returned zero.

Arjun Sir

Look at the data: the column says DELIVERED, in capitals. String comparison in Hive is case-sensitive. lower(status) fixes it. The 6:30 pm visit is a time-zone issue: the server runs in UTC, so the log time is converted to UTC. And phone numbers can be masked with mask_show_last_n.

Riya

How do we even know which functions exist?

Arjun Sir

SHOW FUNCTIONS lists them (493 in our Hive 4.2.1) and DESCRIBE FUNCTION EXTENDED explains one. Today we go through the families you use every day: text, dates, conditions, NULLs, maths and masking. Every output is real, and we will meet three traps, including one in Hive’s own help text.

2 Definition

Built-in scalar functions

Formal definition (write this in exams)

A built-in scalar function (a UDF in Hive terms) takes zero or more values from a single row and returns one value. Hive groups them into mathematical, string, date, conditional, type-conversion, collection, data-masking and miscellaneous functions. They can be used wherever an expression is allowed. The list available in a session is shown by SHOW FUNCTIONS, and DESCRIBE FUNCTION [EXTENDED] name documents one function.

In simple words

A function takes values from one row, like a name or a date, and gives back one new value, like the name in capitals or the number of days between two dates.

Words you’ll meet in this lesson

UDFUser-defined function: Hive’s name for a one-row-in, one-value-out function, built-in or your own.
UDAFAggregate function (many rows in, one value out), like SUM. Module 3.
UDTFTable-generating function (one row in, many rows out), like explode. Lesson 4.2.
Epoch / Unix timeSeconds since 1 January 1970 UTC. unix_timestamp returns it.
Format patternLetters like dd-MMM-yyyy that describe how a date is written.
MaskingHiding part of a value, e.g. showing only the last 4 digits of a phone.
HashA fixed-length fingerprint (md5, sha2). Same input → same hash; useful as a join key without exposing the value.

Built-in functions at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A toolbox for each kind of value

  • Text needs cleaning (spaces, capitals, symbols), dates need arithmetic (days between, month start), and many values need a rule (“if more than 500 then big”).
  • Hive has a ready function for each job. You call it inside SELECT, WHERE, GROUP BY or ORDER BY, like upper(name).
  • A function works on one row at a time and returns one value. (Aggregates like SUM, from Module 3, combine many rows.)

Intermediate The families you use most

  • String: upper/lower/initcap, trim, length, substr, concat/concat_ws, split, lpad/rpad, replace/translate, regexp_extract/regexp_replace, instr/locate, format_number.
  • Date: current_date, to_date, date_format, datediff, date_add/date_sub, add_months, last_day, next_day, trunc, months_between, year/month/dayofweek/weekofyear/extract, unix_timestamp/from_unixtime, from_utc_timestamp.
  • Conditional and NULL: IF, CASE, COALESCE, NVL, NULLIF, isnull/isnotnull, assert_true.
  • Maths, conversion, masking: round/bround/floor/ceil/pmod/power/greatest, CAST, mask*, md5/sha2/hash.

Advanced How Hive evaluates them, and where they bite

  • Built-ins are Java classes (GenericUDF). DESCRIBE FUNCTION EXTENDED shows the class and whether it is BUILTIN. Most run vectorised on ORC data.
  • Silent NULLs: a bad CAST, an invalid date, an unknown format or a concat with a NULL argument returns NULL without any error. Count NULLs after every transformation.
  • Time zones: unix_timestamp gives seconds since 1970 UTC; from_unixtime formats them in hive.local.time.zone (LOCAL = the server JVM’s zone). Set it per session or store UTC deliberately.
  • Functions on a partition column or in a join key can stop partition pruning or index use; filter on the raw column when you can (Modules 5 and 8).
  • Patterns in date_format and unix_timestamp follow Java’s DateTimeFormatter style: yyyy year, MM month, mm minutes, MMM “Oct”, EEEE weekday, Z zone offset.

Exam tip: “Name five string and five date functions in Hive.” Give them with one real result each, e.g. datediff('2026-10-31', '2026-10-04') = 27, then mention the two classic traps: string comparison is case-sensitive, and bad casts return NULL silently.

Hive’s own help can be wrong. DESCRIBE FUNCTION EXTENDED datediff prints the example datediff('2009-07-30', '2009-07-31') with the answer 1. Running it in our lab returns -1, which matches the description (“if date1 is earlier than date2, the result is negative”). Always run an example before you trust it.

  6. Step 6 · Trap: CASE that matches nothing

    SELECT status, COUNT(*) AS n,
  SUM(CASE status WHEN 'delivered' THEN 1 ELSE 0 END) AS exact_match,
  SUM(CASE lower(status) WHEN 'delivered' THEN 1 ELSE 0 END) AS lower_match
FROM orders GROUP BY status ORDER BY n DESC;
    +------------+--------+--------------+--------------+ | status | n | exact_match | lower_match | +------------+--------+--------------+--------------+ | DELIVERED | 46018 | 0 | 46018 | | CANCELLED | 3063 | 0 | 0 | | REFUNDED | 919 | 0 | 0 | +------------+--------+--------------+--------------+
    This was the zero in Kabir’s report. The data says DELIVERED, and 'ab' = 'AB' is false in Hive (also 'Pune' LIKE 'pu%'). Normalise with lower() or upper() on the column before comparing.

  2. Brackets in the pattern form capture group 1, which is returned.

  5. Many functions return NULL instead of failing, so check NULL counts.

6 Real-world use

Built-in functions at work

1. Standardising raw data

Curated tables are built with trim, lower/upper and regexp_replace so that city names, statuses and phone numbers match across sources.

Raw table→Clean functions→Curated table

2. Calendar reporting

Week, month and quarter keys (weekofyear, trunc, extract) drive weekly sales reviews and month-on-month comparisons.

Order date→Calendar parts→GROUP BY week

3. Parsing logs and codes

regexp_extract and unix_timestamp turn web and app logs into columns: time, page, response code, campaign id.

Log line→regexp + time→Columns

4. Business rules and bands

Order-size bands, customer tiers and SLA flags are written as CASE expressions in shared views so every report uses the same rule.

Measures→CASE / IF→Segments

5. Privacy-safe data sharing

Banks, telecoms and food apps mask phones and hash ids before sharing data with partners, as data-protection rules such as India’s DPDP Act expect.

Customer table→Mask + hash→Partner extract

# Cleaning raw values like Hive string functions do
raw = [("  aRJUN nAIR ", "+91 98765 43210", "DELIVERED"),
       ("ananya iyer", "098765-12345", "Delivered"),
       ("KABIR SHAH", "9876500011", "cancelled")]

for name, phone, status in raw:
    clean_name = name.strip().lower().title()          # initcap(lower(trim(name)))
    digits = "".join(ch for ch in phone if ch.isdigit())  # regexp_replace(phone, '[^0-9]', '')
    last10 = digits[-10:]                               # substr(digits, -10)
    masked = "n" * 6 + last10[-4:]                      # mask_show_last_n(last10, 4)
    delivered = 1 if status.lower() == "delivered" else 0   # CASE lower(status) WHEN 'delivered'
    print(f"{clean_name:12} {masked}  delivered={delivered}")

How old is each order?

Problem statement

Bucket orders by age on 31 October 2026: 0–7 days “this week”, 8–30 “this month”, older “old”, using CASE WHEN datediff('2026-10-31', order_date) <= 7 ….

Input
order dates 2026-10-30, 2026-10-20, 2026-09-15, 2026-10-24
Expected output
2026-10-30 1 this week
2026-10-20 11 this month
2026-09-15 46 old
2026-10-24 7 this week
{'this week': 2, 'this month': 1, 'old': 1}

Approach

  1. datediff(end, start) gives the age in days.
  2. CASE checks the smallest bucket first.

Check yourself

Quick revision

Lesson 4.1 in one screen

  • Discover: SHOW FUNCTIONS LIKE '%date%', DESCRIBE FUNCTION EXTENDED f (but run the example yourself).
  • Strings: trim, lower/upper/initcap, length, substr (1-based), split (0-based array), concat (NULL if any NULL), concat_ws (skips NULL), lpad/rpad, replace/translate, regexp_extract/regexp_replace, instr/locate (0 = not found), format_number.
  • Dates: datediff(end, start), date_add/date_sub, add_months (clamps), last_day, next_day, trunc(d, 'MM'), months_between, dayofweek (Sunday = 1), weekofyear, extract, date_format.
  • Times: unix_timestamp(s, fmt) → epoch; from_unixtime prints in hive.local.time.zone; from_utc_timestamp / to_utc_timestamp convert.
  • Rules: IF, CASE (simple and searched), COALESCE, NVL, NULLIF, isnull; string comparison and LIKE are case-sensitive.
  • Silent NULLs: bad CAST, invalid date, NULL in concat, NULL + 1.
  • Maths: round (half up) vs bround (half even), floor/ceil, % vs pmod, greatest/least.
  • Privacy: mask, mask_show_last_n, mask_first_n; md5/sha2 for stable ids (add a secret salt).

Interview and viva questions

Are function names case-sensitive?

No. UPPER(name), upper(name) and Upper(name) are the same function. The data values are case-sensitive, which is the trap in this lesson.

How do I make a comparison case-insensitive?

Normalise both sides: lower(city) = lower('Pune'), or for patterns lower(city) LIKE 'pu%'. RLIKE accepts Java regex flags, so city RLIKE '(?i)^pu' also works. Better still, standardise case once in the curated table.

Why do date functions accept strings?

Many date functions take a string in yyyy-MM-dd (or yyyy-MM-dd HH:mm:ss) form and convert it. An invalid string such as '2026-13-45' or '04/10/2026' becomes NULL, as our lab showed. Store dates as DATE or TIMESTAMP columns to catch bad values at load time.

What is assert_true for?

It stops a query when a condition fails: SELECT assert_true(COUNT(*) > 0) FROM staging. In our lab assert_true(1 > 2) failed with “ASSERT_TRUE(): assertion failed.” It is a simple data-quality gate in pipelines.

Can I add my own functions?

Yes. Write a Java UDF, add the JAR and CREATE FUNCTION; Module 9 shows how. First check SHOW FUNCTIONS: with about 490 built-ins, the function you need often already exists.

Real-world scenario questions (asked in company interviews)

Function questions in interviews usually come with data: clean this, compute that date, explain this NULL.

Any company · SQLFresher

“Count customers who joined in each month”

Customers have a joined_on DATE. Produce month and count, in calendar order.

The interviewer is checking: do you know date functions and grouping keys?

Show a strong answer
SELECT date_format(joined_on, 'yyyy-MM') AS ym, COUNT(*) AS customers
FROM customers
GROUP BY date_format(joined_on, 'yyyy-MM')
ORDER BY ym;

The yyyy-MM text sorts correctly; ‘MMM yyyy’ would sort alphabetically.

Avoid: Grouping by month() alone, which mixes the same month of different years.

Data qualityMid-level

A metric dropped to zero overnight

Delivered orders show 0 after a source system started sending upper-case statuses.

The interviewer is checking: do you check the data before blaming the engine?

Show a strong answer
  1. SELECT status, COUNT(*) … GROUP BY status to see the real values.
  2. Compare with lower(status); fix the view to normalise case.
  3. Add an alert when a core metric drops to zero or moves more than a threshold.

Avoid: “Hive lost the data”.

Data engineeringMid-level

Daily totals are off near midnight

Orders placed between 00:00 and 05:30 IST appear on the previous day in reports.

The interviewer is checking: do you understand epoch time and session time zones?

Show a strong answer
  • The data is correct as an instant; it is printed or truncated in UTC.
  • Set hive.local.time.zone=Asia/Kolkata in the job, or convert explicitly with from_utc_timestamp(ts, 'Asia/Kolkata') before to_date.
  • Document which zone each column is in.

Avoid: Adding 5.5 hours by hand everywhere.

PrivacySenior

Share data with a partner safely

A marketing partner needs customer segments for a campaign, but must not identify customers.

The interviewer is checking: can you minimise and pseudonymise data?

Show a strong answer
  • Send only needed columns; mask phones with mask_show_last_n if they must appear at all.
  • Replace ids with sha2(concat(id, secret_salt), 256) so files can be joined without revealing ids.
  • Prefer central masking policies (Ranger) over ad-hoc queries; log every export.

Avoid: Plain md5(id): small id ranges can be reversed by hashing every possible id.
