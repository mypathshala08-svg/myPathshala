1 The story

“Why are we on AWS?”

Before you start: Modules 5 and 6.

🤔 TiffinGo raises its first big investment. The new CTO asks: “Why are we on AWS? Should we be on Azure because our accountants use Microsoft 365, or Google because the data team loves BigQuery?” What would a good answer sound like?

Not “AWS is best”. All three leading clouds can run TiffinGo. The real differences are in strengths, ecosystem, organisation model, pricing details, Regions near your users and your team’s skills. This lesson compares six providers one by one — AWS, Microsoft Azure, Google Cloud, Oracle Cloud, IBM Cloud and Indian providers — animates how each one organises accounts, billing and policies, and on your own accounts you inspect the hierarchy, compare India Regions and zones, and price the same VM in all three.

  • Why the “resource hierarchy” matters more than the logo.
  • Same VM size, three prices — and why per-hour price is only the start.
  • How to answer “which cloud is best?” in an interview without picking a fight.

After a funding round, TiffinGo’s new CTO asked a simple question that started a long debate: should the company stay on AWS, move to Azure with its Microsoft 365 rollout, or use Google Cloud for its data team’s favourite tools?

Riya

Sir, the CTO wants a comparison by Friday. Should I list who has more services?

Arjun Sir

Counting services is the weakest argument. List what we need: managed Postgres, containers, BigQuery-style analytics, Indian Regions, and our team’s skills.

Kabir

Our team knows AWS. The data team uses BigQuery.

Arjun Sir

Then the honest answer might be “AWS for apps, Google for analytics” — that is the partitioned multi-cloud from Lesson 3.3.

Riya

And Azure?

Arjun Sir

If we adopt Microsoft 365 and Entra ID, Azure becomes attractive for identity and Windows workloads. Let’s compare properly.

2 Definition

AWS vs Azure vs Google Cloud

Formal definition (write this in exams)

Comparing cloud providers means evaluating platforms such as Amazon Web Services, Microsoft Azure and Google Cloud (and others including Oracle, IBM and regional providers) on service fit, global and local infrastructure, resource-hierarchy and governance model, identity integration, pricing and discount models, ecosystem, support and team skills, to choose the best platform — or combination — for specific workloads.

In simple words

AWS, Azure and Google Cloud can all run most apps; compare what you need, where your users are, what your team knows and what it really costs.

Say it in an interview

30-second answer you can speak:

  • “AWS has the broadest catalogue and largest ecosystem, Azure integrates with Microsoft 365, Entra ID and hybrid, Google Cloud leads in data analytics, AI and Kubernetes. I choose per workload on services, Regions, compliance, skills and TCO.”
  • “The organisation models differ: AWS accounts under Organizations, Azure subscriptions and resource groups under management groups, Google projects under folders and an organization.”

Type 1 · Amazon Web Services (AWS)

Definition (say it in an interview): AWS, Amazon’s cloud business, launched its first major infrastructure services (S3 and EC2) in 2006 and offers the broadest and deepest catalogue of cloud services — compute, storage, databases, analytics, AI/ML, IoT and more — across many Regions, with the largest market share and partner ecosystem.

In plain words (no jargon): Amazon’s cloud — the oldest and biggest, with the most services.

Analogy: The largest supermarket in town: if a product exists, it is probably on a shelf — but you need a map to find it.

How it works internally, step by step

  1. Account. Unit of isolation.
  2. Organizations. Group accounts, SCPs.
  3. Identity Center. SSO to accounts.
  4. Control Tower. Landing zone.
  5. Well-Architected. 6 pillars.

Words used above, in simple terms: Region / AZ = AWS geography (Lesson 5.1) · SCP = service control policy · Control Tower = AWS landing-zone service

TiffinGo started on AWS because its first engineers knew it, Mumbai was available early, and Lambda/DynamoDB fit the order API.

For the experienced — did you know? AWS often gives several services for one job (e.g. ECS, EKS, App Runner→ECS Express, Lambda, Beanstalk) — knowing when to pick which is the real AWS skill.

Use it when: you want the widest choice, the largest talent pool, or a specific AWS-only service.
Avoid / be careful when: your organisation is deeply standardised on Microsoft licensing and identity — compare Azure carefully.

Type 2 · Microsoft Azure

Definition (say it in an interview): Microsoft Azure, launched in 2010, is Microsoft’s cloud platform; it integrates closely with Windows Server, SQL Server, .NET, Microsoft 365 and Entra ID, offers strong hybrid capabilities (Azure Arc, Azure Local) and licensing benefits for existing Microsoft customers, and is the second-largest cloud infrastructure provider.

In plain words (no jargon): Microsoft’s cloud — strongest for companies already using Microsoft software.

Analogy: The company canteen run by the same firm that runs your office: your ID card already works there, and the menu matches what you are used to.

How it works internally, step by step

  1. Tenant. Entra ID directory.
  2. Management groups. Policy and RBAC at scale.
  3. Subscriptions. Billing + isolation.
  4. Resource groups. Lifecycle containers.
  5. Landing zones. Cloud Adoption Framework.

Words used above, in simple terms: tenant = an organisation’s Entra ID directory · resource group = container for related Azure resources · Hybrid Benefit = reuse existing Windows/SQL licences in Azure

Avoid / be careful when: you assume Azure is “only for Windows” — Linux runs a large share of Azure VMs.

Type 3 · Google Cloud

Definition (say it in an interview): Google Cloud provides infrastructure, platform, data and AI services built on Google’s global network and technologies; it is known for BigQuery (serverless data warehouse), Vertex AI and Gemini models, GKE (Kubernetes originated at Google), Cloud Run, and a project-based organisation model, and is the third-largest cloud infrastructure provider.

In plain words (no jargon): Google’s cloud — especially strong for data analysis, AI and containers.

Analogy: A specialist kitchen with the best ovens in the city: maybe a shorter menu than the supermarket, but certain dishes come out best there.

How it works internally, step by step

  1. Organization. Tied to Workspace/Cloud Identity domain.
  2. Folders. Group projects.
  3. Projects. Billing + isolation + APIs.
  4. Org policies. Guard-rails.
  5. Architecture Framework. 6 pillars.

Words used above, in simple terms: project = Google Cloud’s unit for resources, billing and APIs · BigQuery = serverless data warehouse · Vertex AI = Google’s ML platform

Type 4 · Oracle Cloud Infrastructure (OCI)

Definition (say it in an interview): Oracle Cloud Infrastructure offers IaaS and PaaS with particular strength in running Oracle Database (Exadata, Autonomous Database) and Oracle applications, competitive compute and networking prices, and multicloud database partnerships that place Oracle Database services inside Azure, AWS and Google Cloud data centres.

In plain words (no jargon): Oracle’s cloud — the natural home for companies running Oracle databases.

Analogy: The original manufacturer’s service centre: if your car is that brand, they know it best — and now they also open counters inside other garages.

How it works internally, step by step

  1. Tenancy. Top-level account.
  2. Compartments. Isolation and policy.
  3. DB services. Autonomous, Exadata.
  4. Interconnect. With Azure/Google.
  5. Licensing. BYOL options.

Words used above, in simple terms: Exadata = Oracle’s engineered database hardware · Autonomous Database = self-managing Oracle DB · compartment = OCI’s resource container

Type 5 · IBM Cloud

Definition (say it in an interview): IBM Cloud focuses on hybrid cloud for regulated industries, with offerings built around Red Hat OpenShift, mainframe and Power Systems integration, financial-services-ready controls and consulting-led modernisation, rather than competing on catalogue breadth.

In plain words (no jargon): IBM’s cloud — aimed at banks and large companies with old core systems.

Analogy: A specialist bank-security contractor: not the biggest builder, but the one many banks call for vault-grade work.

How it works internally, step by step

  1. Assess. Mainframe/Power estate.
  2. Platform. OpenShift for portability.
  3. Controls. FS-validated framework.
  4. Connect. To other clouds.
  5. Modernise. Gradually.

Words used above, in simple terms: mainframe = large central computer used by banks and governments · Power Systems = IBM servers for AIX/IBM i workloads · watsonx = IBM’s AI and data platform

Type 6 · Indian and regional providers

Definition (say it in an interview): Indian and regional cloud providers — such as Yotta, CtrlS, Sify, Tata Communications, ESDS, Jio and others — operate data centres and cloud services in India, offering rupee billing, local support, MeitY empanelment for government workloads, sovereign and GPU/AI cloud options, often alongside colocation for hyperscalers.

In plain words (no jargon): Indian cloud companies that keep data in India and serve local and government customers.

Analogy: A trusted neighbourhood caterer: smaller menu than a hotel chain, but local, flexible, speaks your language and knows the local rules.

How it works internally, step by step

  1. Check. MeitY empanelment and certifications.
  2. Compare. Services vs your needs.
  3. Contract. SLAs, exit terms.
  4. Integrate. Network to other clouds.
  5. Operate. Monitoring and support.

Words used above, in simple terms: empanelment = government approval to supply · colocation = renting data-centre space and power · GPU cloud = cloud focused on AI accelerators

6 Explained part by part

Six factors for choosing a provider

Service fit

What it is: Do they have what you need, managed?

Why it exists: Fewer services to build yourself.

Where it is used: Postgres, K8s, analytics, AI.

Regions + latency

What it is: Data centres near users and data.

Why it exists: Speed and residency.

Where it is used: India Regions, AZs.

Ecosystem

What it is: Partners, marketplace, community.

Why it exists: Hiring, tools, help.

Where it is used: Job market, training.

Pricing model

What it is: Compute, storage, egress, discounts.

Why it exists: Total cost, not list price.

Where it is used: Savings plans, CUDs, reservations.

Governance model

What it is: Hierarchy, policy, identity.

Why it exists: Security at scale.

Where it is used: Accounts / subscriptions / projects.

Skills + support

What it is: What your team knows; support plans.

Why it exists: Speed and safety.

Where it is used: Certifications, support tiers.

Myth vs reality: things many websites still say

  • Myth: One cloud is best for everything.
    Reality: Each has strengths; choose per workload.
    Proof: Types.
  • Myth: Azure is only for Windows.
    Reality: Linux is widely used on Azure.
    Proof: Type 2.
  • Myth: More services = better choice.
    Reality: Fit, skills and cost matter more.

How to write a fair comparison

  1. Start from requirements (services, Regions, compliance, skills), not from logos.
  2. Compare like for like: same vCPU/RAM generation, same storage class, same Region, same support level.
  3. Include egress, support plans and people costs (Lesson 5.5).
  4. Check roadmap risk: services being retired (App Runner new customers, Deployment Manager) matter.
  5. Run a small proof of concept on the top two.

Answering “which cloud is best?” in an interview

“It depends on the workload. AWS has the broadest catalogue and ecosystem, Azure fits Microsoft-centric enterprises and hybrid, Google Cloud is strong in data, AI and Kubernetes. I would decide on required services, Regions, compliance, team skills and total cost — and I’m comfortable translating between them.”

9 Hands-on

Do it yourself, step by step

These labs run on your own cloud account — we cannot run them for you. Each step has three tabs (AWS, Azure, Google Cloud); pick the cloud you have and do both the UI way and the CLI way. Stay inside free tier / credit limits, use the India Region (AWS ap-south-1 Mumbai · Azure Central India · Google asia-south1 Mumbai), and always do the Clean up step at the end. Read-only comparisons: your hierarchy, India Regions and zones, and the price of the same VM size on each cloud. Nothing costs money.

  1. 0 · Get ready: account, budget, CLI

    Pick your cloud.

    UI way — AWS Management Console

    1. Create an AWS account (aws.amazon.com → Create an AWS Account); choose the Free plan while learning.
    2. Never work as root: IAM Identity Center (or IAM) → create an admin user with MFA and sign in as that user.
    3. Billing and Cost Management → Budgets → Create budget → monthly cost budget, e.g. $5, alert by e-mail (Lesson 5.5).
    4. Top-right Region menu → Asia Pacific (Mumbai). Open CloudShell (terminal icon) — the AWS CLI is already signed in there.

    CLI way — the same thing with commands

    aws sts get-caller-identity          # who am I? (must NOT be the root user)
aws configure set region ap-south-1
aws configure list

    You should see: your account ID and an IAM user/role ARN — not “root”.

    UI way — Azure portal

    1. Create a free account at azure.microsoft.com/free (credit for the first 30 days).
    2. Search Cost Management → Budgets → Add → monthly budget, e.g. ₹400, alert at 80%.
    3. Open Cloud Shell (the >_ icon in the top bar) → choose Bash. The Azure CLI is already signed in.

    CLI way — the same thing with commands

    az account show --output table        # subscription in use
az account list-locations --query "[?name=='centralindia'].displayName" -o tsv

    You should see: your subscription name and state “Enabled”, then “Central India”.

    UI way — Google Cloud console

    1. Sign in at console.cloud.google.com and start the free trial (credit for 90 days).
    2. Create a project: project picker → New project → name tiffingo-lab.
    3. Billing → Budgets & alerts → Create budget → e.g. ₹400, alerts at 50/90/100%.
    4. Click Activate Cloud Shell (>_ icon). The gcloud CLI is already signed in.

    CLI way — the same thing with commands

    gcloud config set project tiffingo-lab      # use your real project ID
gcloud config set compute/region asia-south1
gcloud config list

    You should see: your account e-mail, the project and region asia-south1.

    Cloud Shell is the easiest CLI: free, in the browser, already logged in. On your laptop install the AWS CLI v2, Azure CLI or Google Cloud CLI and run aws configure / az login / gcloud init.

  2. 1 · Look at your own resource hierarchy

    Pick your cloud.

    UI way — AWS Management Console

    1. Search AWS Organizations — if you see “Create an organization”, your account is standalone (fine for learning). IAM shows your account ID top right.

    CLI way — the same thing with commands

    aws sts get-caller-identity --query '[Account,Arn]' --output text
aws organizations describe-organization --query 'Organization.[Id,MasterAccountId]' --output text 2>&1 | tail -1

    You should see: your 12-digit account ID; then either an organization ID or AWSOrganizationsNotInUseException — a standalone account is its own isolation and billing unit.

    UI way — Azure portal

    1. Management groups → you see the Tenant Root Group (create it if prompted); Subscriptions → your subscription; Resource groups inside it.

    CLI way — the same thing with commands

    az account show --query "{tenant:tenantId,subscription:name,id:id}" -o table
az account management-group list --query "[].{name:displayName,id:name}" -o table 2>&1 | tail -3
az group list --query "[].{rg:name,location:location}" -o table

    You should see: your tenant and subscription, any management groups you can see, and your resource groups — Azure’s three levels.

    UI way — Google Cloud console

    1. IAM & Admin → Manage resources — personal accounts show “No organization” with projects directly below; company accounts show the organization and folders.

    CLI way — the same thing with commands

    gcloud projects list --format="table(projectId,name,parent.type,parent.id)"
gcloud organizations list 2>&1 | tail -2

    You should see: your projects (parent empty for personal accounts) and the organization list (empty without Workspace/Cloud Identity).

    Same idea, three names: account, subscription (+ resource group), project.

  3. 2 · Compare India Regions and zones

    Pick your cloud.

    UI way — AWS Management Console

    1. Region selector: Mumbai and Hyderabad. EC2 → Settings → Zones shows Availability Zones and opt-in Local Zones (Delhi, Kolkata).

    CLI way — the same thing with commands

    for r in ap-south-1 ap-south-2; do echo "== $r"; aws ec2 describe-availability-zones --region $r --all-availability-zones \
  --query 'AvailabilityZones[].[ZoneName,ZoneType,OptInStatus]' --output text 2>&1 | head -6; done

    You should see: Mumbai’s three AZs plus Local Zones (e.g. ap-south-1-del-1a local-zone); Hyderabad needs opt-in to list zones.

    UI way — Azure portal

    1. Create pages list India Regions; zones appear under Availability options for VMs in Central India.

    CLI way — the same thing with commands

    az account list-locations --query "[?contains(displayName,'India')].{name:name,display:displayName,zones:length(availabilityZoneMappings || `[]`)}" -o table

    You should see: Central India with 3 zones; South India and West India listed (zone support varies by Region and subscription).

    UI way — Google Cloud console

    1. Compute Engine → Zones lists zones per Region.

    CLI way — the same thing with commands

    gcloud compute zones list --filter="region~asia-south" --format="table(name,region.basename(),status)"

    You should see: asia-south1-a/b/c and asia-south2-a/b/c, all UP.

    All three offer multiple India Regions with zones — residency and resilience are possible on each.

  4. 3 · Price the same VM size in all three

    Pick your cloud.

    UI way — AWS Management Console

    1. Pricing Calculator → EC2 → m7i.large (2 vCPU, 8 GiB), Mumbai, Linux, On-Demand → note the monthly cost.

    CLI way — the same thing with commands

    aws pricing get-products --region us-east-1 --service-code AmazonEC2 --filters \
  Type=TERM_MATCH,Field=instanceType,Value=m7i.large Type=TERM_MATCH,Field=regionCode,Value=ap-south-1 \
  Type=TERM_MATCH,Field=operatingSystem,Value=Linux Type=TERM_MATCH,Field=tenancy,Value=Shared \
  Type=TERM_MATCH,Field=preInstalledSw,Value=NA Type=TERM_MATCH,Field=capacitystatus,Value=Used \
  --query 'PriceList[0]' --output text | python3 -c "import sys,json; d=json.loads(sys.stdin.read()); t=list(d['terms']['OnDemand'].values())[0]; p=float(list(t['priceDimensions'].values())[0]['pricePerUnit']['USD']); print('m7i.large Mumbai', p, '/h  ~', round(p*730,1), '/month')"

    You should see: the hourly On-Demand USD price and an approximate monthly figure.

    UI way — Azure portal

    1. Pricing calculator → Virtual Machines → D2s v5 (2 vCPU, 8 GiB), Central India, Linux, Pay as you go.
    2. The CLI uses Azure’s public Retail Prices API — no login needed.

    CLI way — the same thing with commands

    curl -s "https://prices.azure.com/api/retail/prices?\$filter=serviceName%20eq%20'Virtual%20Machines'%20and%20armRegionName%20eq%20'centralindia'%20and%20armSkuName%20eq%20'Standard_D2s_v5'%20and%20priceType%20eq%20'Consumption'" \
  | python3 -c "import sys,json; [print(i['productName'], i['skuName'], i['retailPrice'], '/h') for i in json.load(sys.stdin)['Items'] if 'Windows' not in i['productName'] and 'Spot' not in i['skuName'] and 'Low' not in i['skuName']]"

    You should see: the Linux pay-as-you-go hourly price for D2s v5 in Central India.

    UI way — Google Cloud console

    1. Google Cloud Pricing Calculator → Compute Engine → n4-standard-2 (2 vCPU, 8 GB), asia-south1, on-demand.
    2. The Cloud Billing Catalog API needs an API key; the CLI confirms the machine shape.

    CLI way — the same thing with commands

    gcloud compute machine-types describe n4-standard-2 --zone=asia-south1-a --format="value(name,guestCpus,memoryMb)"

    You should see: n4-standard-2 2 8192 — then read the price in the calculator.

    List prices are close; real differences come from discounts, egress, support and how well you right-size (Lesson 5.5).

10 Mistakes to avoid

Common mistakes, why they happen, how to fix them

Mistake or symptomWhy it happensHow to fix or avoid
Choosing by number of services.Easy headline.Choose by required services, Regions, skills, cost.
Comparing different VM generations.Picking cheapest-looking names.Match vCPU/RAM/generation/Region.
Ignoring egress and support costs.Focus on compute.Full TCO (Lesson 5.5).
Treating resource groups as security boundaries.Azure naming confusion.Subscriptions/accounts/projects isolate; RGs organise.
Assuming skills transfer automatically.“Cloud is cloud”.Plan training and translation tables.
Religious debates.Personal preference.Requirements matrix + proof of concept.
