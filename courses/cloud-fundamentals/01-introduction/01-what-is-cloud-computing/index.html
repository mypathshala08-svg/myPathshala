What is cloud computing?

Cloud computing means renting computers, storage and software over the internet and paying only for what you use. We learn the NIST definition, see the layers, prove the cloud is real hardware with real data, compare AWS, Azure and Google Cloud, and finish with exam questions and a mini project.

1 The story

The Diwali crash that cloud would have prevented

Before you start: nothing! This is the first lesson. Basic computer knowledge is enough; the Linux course helps for the hands-on parts.

🤔 Where does your photo go when you “save it to the cloud”? Is the cloud just someone else’s computer?

Yes, and no. The cloud is real buildings full of servers, but you rent them by the minute over the internet, start them yourself in seconds and pay only for what you use. AWS even publishes every IP range it owns: on 9 Nov 2026 the file listed 10,744 IPv4 ranges across 42 regions, including Mumbai and Hyderabad. Google Cloud lists 48 regions, with Mumbai and Delhi in India.

2 Definition

What is cloud computing?

Formal definition (write this in exams)

Cloud computing (NIST SP 800-145) is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (networks, servers, storage, applications and services) that can be rapidly provisioned and released with minimal management effort or service-provider interaction.

In simple words

Renting computers, storage and software over the internet, starting them yourself in minutes and paying only for what you use.

Say it in an interview

30-second answer you can speak:

  • “Cloud computing is the on-demand delivery of IT resources such as servers, storage, databases and software over the internet, with pay-as-you-go pricing.”
  • “NIST defines it by five characteristics — on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service — three service models, IaaS, PaaS and SaaS, and four deployment models: public, private, hybrid and community.”
  • “For example, a food-delivery app adds servers automatically during Diwali and removes them after, paying only for that week.”

Exam tip: Learn the 5 NIST characteristics word for word. AWS phrases the benefits as: trade fixed expense for variable expense, benefit from massive economies of scale, stop guessing capacity, increase speed and agility, stop spending money running data centres, go global in minutes.

3 The big picture

Front end, back end and the NIST model

Every cloud, from AWS to Google Cloud, has the same two halves: a front end you touch and a back end the provider runs. Read the diagram left to right: your phone or browser sends a request over the internet; in the provider’s data centre it passes down through layers of software and hardware; management and security watch every layer.

NIST (the US standards body) defines cloud computing with a simple 5 + 3 + 4 model. Exams quote it word for word, so learn this picture.

Animated example
  1. Riya taps “Order”.

5 Explained part by part

The five characteristics, one by one

1. On-demand self-service

You create servers, storage or databases yourself from a console, CLI or API, any time.

Journey step 7: VM 3 started by itself

2. Broad network access

Resources are reached over the network from standard devices: phone, laptop, another server.

Journey step 3: request over the internet

3. Resource pooling

The provider’s big servers are shared by many customers; each gets an isolated slice (a VM).

Journey step 4: VM is a slice

4. Rapid elasticity

Capacity grows and shrinks quickly with demand and looks unlimited to you.

Diwali: 2 → 3 VMs and back

5. Measured service

Every hour, GB and request is metered; you pay only for what you used, like electricity.

Journey step 8: the meter

6 AWS · Azure · Google Cloud

The same idea in three clouds

Same idea in AWS, Azure and Google Cloud

Pick a cloud.

AWS (Amazon Web Services, 2006) is the largest public cloud. India regions: ap-south-1 Mumbai and ap-south-2 Hyderabad. You enter through the AWS Management Console, the AWS CLI or SDKs.

Exam: AWS Certified Cloud Practitioner (CLF-C02).

Microsoft Azure (2010) is strong with companies already on Windows, Office 365 and Active Directory. India regions include Central India (Pune), South India (Chennai) and West India (Mumbai). Entry: Azure portal, Azure CLI, PowerShell.

Exam: AZ-900 Azure Fundamentals.

Google Cloud (2008, App Engine) is known for data, analytics and AI (BigQuery, Vertex AI). India regions: asia-south1 Mumbai and asia-south2 Delhi. Entry: Google Cloud console, gcloud CLI.

Exam: Cloud Digital Leader.

7 Real proof

Proof that the cloud is real hardware

All outputs are real: the public IP-range files published by AWS and Google Cloud, downloaded on 10 Nov 2026 with a short Python script. Note: the AWS file lists 42 region codes because it includes special regions (GovCloud, China and others); the 34 normal commercial regions appear in Lesson 1.2.

  1. Step 1 · AWS publishes its whole network

    a = json.load(urlopen("https://ip-ranges.amazonaws.com/ip-ranges.json"))
len(a["prefixes"]), len(a["ipv6_prefixes"]), regions
    == 1) AWS publishes every public IP range it owns file created: 2026-11-09-20-47-05 IPv4 prefixes: 10744 IPv6 prefixes: 7072 regions in the file: 42 India regions: ['ap-south-1', 'ap-south-2'] (Mumbai, Hyderabad)
    Tens of thousands of address blocks and 42 region codes: physical places, not a fog.

  2. Step 2 · What runs in Mumbai

    Counter(x["service"] for x in prefixes if x["region"] == "ap-south-1")
    ap-south-1 IPv4 entries: 304 unique ranges: 221 services with ranges in ap-south-1 (Mumbai): {'AMAZON': 167, 'EC2': 56, 'ROUTE53_RESOLVER': 18, 'S3': 14, 'API_GATEWAY': 8, 'IVS_REALTIME': 6, 'CLOUDFRONT': 5, 'GLOBALACCELERATOR': 4}
    Virtual machines (EC2), storage (S3), DNS (Route 53), APIs: services you will use in the AWS course.

8 Hands-on

Do it yourself, step by step

No account and no card needed today. You will look at real cloud infrastructure from your own computer (Linux, macOS or Windows with WSL). On plain Windows PowerShell use Invoke-RestMethod https://ip-ranges.amazonaws.com/ip-ranges.json instead of curl + jq.

Caution: Do not create a cloud account with your card “just to look” yet. First learn budgets and alerts (AWS course, Lesson 1.3); most surprise bills come from forgotten resources.

  1. 1 · Download AWS’s address list

    curl -s https://ip-ranges.amazonaws.com/ip-ranges.json -o aws.json
ls -lh aws.json
    A few MB of JSON, updated by AWS several times a week.

  2. 2 · Count Mumbai ranges with jq

    sudo apt install -y jq          # once
jq '[.prefixes[] | select(.region=="ap-south-1")] | length' aws.json
jq -r '.prefixes[].region' aws.json | sort -u | wc -l
    Compare your numbers with Step 1–2 above; they change over time.

  3. 3 · Do the same for Google Cloud

    curl -s https://www.gstatic.com/ipranges/cloud.json -o gcp.json
jq -r '.prefixes[].scope' gcp.json | sort -u | grep asia-south
    You should see asia-south1 and asia-south2.

  4. 4 · Open the provider health pages

    Visit health.aws.amazon.com/health/status, azure.status.microsoft and status.cloud.google.com. Find Mumbai on each.

    Clouds publish outages per region: one more proof they are real places.

  5. 5 · Run the lesson script

    python3 l11_cloud_is_real.py
    Same output style as Step 1–4 above (numbers will be newer).

9 Mistakes to avoid

Common mistakes, why they happen, how to fix them

Mistake or symptomWhy it happensHow to fix or avoid
“Cloud is just online storage like Google Drive.”Drive is one SaaS product; people see only that face of the cloud.Remember the 3 service models: rent machines (IaaS), platforms (PaaS) or finished apps (SaaS).
“Cloud is always cheaper.”Pay-per-use is cheap for spiky or small loads; steady 24×7 loads can cost more than owned servers.Compare total cost (Lesson 1.5); use reserved/savings pricing for steady loads (Lesson 5.5).
Surprise bill after a free trial.A VM, disk, public IP or NAT gateway kept running; the meter never sleeps.Budget alert first, tag resources, delete after every lab, check the billing page weekly.
Slow app for Indian users.Resources created in the default US region (e.g. us-east-1).Pick ap-south-1 / Central India / asia-south1 before creating anything.
Logging in as root / owner for daily work.Sign-up account has full power; easy to keep using.Enable MFA, create an admin user/role, lock the root user away (AWS 2.1).

11 Quiz and revision

Check yourself

Quick revision

Lesson 1.1 in one screen

  • Cloud = on-demand IT resources over the internet, pay as you go.
  • NIST: 5 characteristics (self-service, network access, pooling, elasticity, measured), 3 service models (IaaS, PaaS, SaaS), 4 deployment models (public, private, hybrid, community).
  • Architecture: front end (app, browser, CLI) → internet → back end (application, service, runtime, storage, infrastructure) + management + security.
  • One order: phone → DNS → load balancer → VM → database → reply; auto scaling on Diwali; every second metered.
  • India regions: AWS ap-south-1/2, Azure Central/South/West India, Google asia-south1/2.
  • Always: budget alert first, right region, clean up after labs.

Interview and viva questions

Is the cloud safe?

The provider secures buildings, hardware and its services; you secure your accounts, data and settings (shared responsibility, Module 9).

Do I need a credit card to learn?

Not for this course’s concept lessons. For AWS labs you need an account; set budgets first.

Which cloud should I learn first?

Concepts are the same; AWS has the largest share and the most jobs, so our hands-on course starts there, with Azure and GCP names side by side.

Is Google Drive cloud computing?

Yes, it is SaaS: finished software delivered from the cloud.

Which certification after this course?

AWS Cloud Practitioner (CLF-C02), Azure AZ-900 or Google Cloud Digital Leader: each lesson has a Certification corner.

Real-world scenario questions (asked in company interviews)

Cloud interview questions.

Any company · fresherFresher

“What is cloud computing?”

The very first question in most cloud interviews.

The interviewer is checking: Can you give a precise definition and an example, not just “storing files online”?

Show a strong answer

“Cloud computing is the on-demand delivery of IT resources — servers, storage, databases, software — over the internet with pay-as-you-go pricing. NIST defines it by five characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service. For example, a food-delivery app adds servers for Diwali and removes them after, paying only for that week.”

Avoid: Saying “cloud means Google Drive” or “cloud means the internet”.

StartupFresher

Why should a startup use cloud?

The founder has ₹5 lakh and an idea.

The interviewer is checking: Do you know the business benefits, not just the technology?

Show a strong answer
  • No up-front hardware (CapEx → OpEx).
  • Start in minutes, experiment cheaply, delete what fails.
  • Scale automatically if the idea succeeds; go global later.

Avoid: “Because it is free.” It is not; set budgets.

BankMid-level

Where should Indian customer data live?

A bank wants to move an app to the cloud.

The interviewer is checking: Do you think about data residency and resilience?

Show a strong answer
  • Use Indian regions (e.g. AWS Mumbai + Hyderabad for DR).
  • Encrypt data, keep audit logs, follow RBI / DPDP rules.

Avoid: Picking the default US region.

OpsMid-level

The first cloud bill is much higher than expected.

Finance is upset after a month.

The interviewer is checking: Do you understand measured service and cost control?

Show a strong answer
  • Resources kept running (VMs, disks, IPs, NAT gateways) are billed even when idle.
  • Fix: budgets and alerts, tags, a cleanup checklist, stop dev servers at night.

Avoid: Blaming the provider.
