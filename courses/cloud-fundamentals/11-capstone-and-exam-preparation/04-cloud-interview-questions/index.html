1 The story

Correct answer, no offer

Before you start: the whole course, especially 10.4 and 11.1.

🤔 “What is the difference between scalability and elasticity?” Meena knew it — and still answered in a way that made the interviewer frown.

She recited a textbook line, gave no example, and stopped. The next candidate gave the same definition, added “for example, our canteen app scales out at lunch and back in at 2 pm — that is elasticity”, and got the offer. Interviews reward definition + example + trade-off. This lesson gives you the seven kinds of interview questions, an answer structure for each, 60 questions with model answers from fresher to mid-level, and a short drill on your own account so you can talk about real numbers.

2 Definition

Cloud interview questions

Formal definition (write this in exams)

A cloud technical interview evaluates a candidate’s understanding of cloud concepts, services, architecture, security, cost management and operations, together with problem-solving and communication, through concept, comparison, scenario, troubleshooting, security, cost and behavioural questions, often supported by hands-on or whiteboard exercises.

In simple words

Interviewers check whether you understand cloud and can use it — answer with a clear definition, a real example and a trade-off.

Say it in an interview

30-second answer you can speak:

  • “I structure answers as definition, example from my own project, then trade-off — for example, serverless for the spiky canteen workload but containers for steady load.”
  • “For incidents I reproduce, check layer by layer with logs and metrics, fix, then add an alarm or test so it does not recur.”

Type 1 · Concept questions

Definition (say it in an interview): Concept questions ask you to explain a term — cloud computing, IaaS/PaaS/SaaS, virtualisation, Region and AZ, serverless, containers — and are answered best in three parts: precise definition, an example from your own work, and a trade-off.

In plain words (no jargon): Questions asking you to explain a cloud term.

Analogy: Explaining a recipe: what the dish is, when you last made it, and when you would cook something else.

How it works internally, step by step

  1. Define. One sentence.
  2. Example. Lab/project.
  3. Benefit. Why it matters.
  4. Trade-off. Limits.
  5. Stop. Invite follow-up.

Words used above, in simple terms: elevator answer = 30–60 second explanation · trade-off = what you give up · follow-up = deeper question on the same topic

Type 2 · Comparison questions (X vs Y)

Definition (say it in an interview): Comparison questions ask the difference between two related things — VM vs container, SG vs NACL, CloudTrail vs CloudWatch, RDS vs DynamoDB, vertical vs horizontal scaling — and are answered by stating what they share, the key difference, and when to choose each.

In plain words (no jargon): Questions asking how two similar things differ.

Analogy: Bus vs taxi: both get you there; one is shared and scheduled, the other private and on demand; choose by budget and urgency.

How it works internally, step by step

  1. Common. Shared purpose.
  2. Axis. Scope, state, control, cost.
  3. Example. One each.
  4. Choose. When each.
  5. Stop. —

Words used above, in simple terms: stateful = remembers connections; return traffic allowed · stateless = each packet evaluated alone · axis = dimension of comparison

Type 3 · Scenario and design questions

Definition (say it in an interview): Scenario questions describe a business need — “design a photo-sharing app”, “move this on-premises app to cloud”, “handle a 10× traffic spike” — and test whether you clarify requirements, compare options and choose with reasons, as you did in the capstone.

In plain words (no jargon): Questions where you design a solution for a situation.

Analogy: An architect asking how many people will live in a house before drawing it.

How it works internally, step by step

  1. Clarify. Numbers.
  2. Options. Two.
  3. Choose. Reasoned.
  4. Security/cost. Mention both.
  5. Risks. And mitigations.

Words used above, in simple terms: NFR = non-functional requirement · RTO/RPO = recovery time / data-loss targets · 7 Rs = migration strategies

Type 4 · Troubleshooting questions

Definition (say it in an interview): Troubleshooting questions give a symptom — “the website is down”, “the VM is unreachable”, “the Lambda times out”, “S3 access denied” — and test a systematic approach: reproduce, check layer by layer, use logs and metrics, fix, then prevent recurrence.

In plain words (no jargon): Questions where you find and fix a problem.

Analogy: A doctor checking pulse, breathing and temperature in order before prescribing.

How it works internally, step by step

  1. Scope. Who/what/when.
  2. Recent change?. Deploys, config.
  3. Layers. Network → app.
  4. Evidence. Logs, metrics.
  5. Prevent. Alarm, test.

Words used above, in simple terms: status checks = EC2 system/instance health checks · curl -v = shows connection and HTTP details · runbook = documented fix procedure

Type 5 · Security questions

Definition (say it in an interview): Security questions ask how you would protect an account, application or data — “how do you secure S3?”, “what is least privilege?”, “someone leaked an access key — what do you do?” — and are answered in layers: identity, network, data, detection and response.

In plain words (no jargon): Questions about keeping systems and data safe.

Analogy: Securing a house: who has keys, locked doors and windows, a safe for valuables, and an alarm.

How it works internally, step by step

  1. Identity. IAM, MFA.
  2. Network. Private subnets, SGs.
  3. Data. Encryption, KMS.
  4. Detect. Trail, GuardDuty.
  5. Respond. Plan, rotate.

Words used above, in simple terms: least privilege = only what is needed · rotation = replacing credentials regularly · blast radius = how much damage one failure can do

Type 6 · Cost questions

Definition (say it in an interview): Cost questions ask how you would reduce or control a cloud bill — “our bill doubled”, “how do you choose a pricing model?”, “what is FinOps?” — and test whether you find the cost driver with data, apply quick wins, and add guard-rails.

In plain words (no jargon): Questions about spending less and controlling cloud costs.

Analogy: A household budget: look at the bank statement, cancel unused subscriptions, then set monthly limits.

How it works internally, step by step

  1. Data. Cost by dimension.
  2. Idle. Stop/delete.
  3. Right-size. Metrics.
  4. Pricing. Commit/Spot.
  5. Guard. Budgets, tags.

Words used above, in simple terms: right-sizing = matching size to actual use · FinOps = shared financial accountability for cloud · egress = data leaving the cloud, usually charged

Type 7 · Project and behavioural questions

Definition (say it in an interview): Project and behavioural questions — “walk me through your project”, “tell me about a failure”, “a time you disagreed with a teammate” — are answered with STAR: situation, task, action, result, ending with what you learned.

In plain words (no jargon): Questions about what you did and how you work with others.

Analogy: Telling a cricket story: the match situation, your role, the shots you played, the final score and what you would do differently.

How it works internally, step by step

  1. Situation. One line.
  2. Task. Your goal.
  3. Action. Specific steps.
  4. Result. Numbers.
  5. Learning. One line.

Words used above, in simple terms: STAR = situation, task, action, result · ownership = taking responsibility · blameless = focusing on the system, not the person

7 Question bank

60 interview questions with model answers

Sixty questions with model answers. Say each answer aloud, then compare. Replace the examples with your own labs and capstone wherever you can.

Fresher · Fundamentals (20)

1. What is cloud computing?

On-demand access to computing resources over a network, paid for as used. NIST lists five characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service. Example: I launch a VM in a minute and pay per second. Trade-off: less physical control, and costs need watching.

2. IaaS vs PaaS vs SaaS?

They differ in how much the provider manages. IaaS: VMs, I manage OS and up (EC2). PaaS: I deploy code, provider runs the platform (App Service, Elastic Beanstalk). SaaS: finished software (Gmail). Choose by how much control vs effort you want.

3. Public, private, hybrid and multi-cloud?

Public: shared provider infrastructure. Private: dedicated to one organisation. Hybrid: on-premises plus public cloud working together. Multi-cloud: more than one public provider. Banks often use hybrid for regulatory data.

4. What is a Region and an Availability Zone?

A Region is a geographic area; an AZ is one or more isolated data centres inside it with independent power and networking. Deploying across AZs gives high availability; across Regions gives disaster recovery.

5. Scalability vs elasticity?

Scalability is the ability to grow capacity; elasticity is adding and removing capacity automatically to match demand. Auto Scaling adding instances at lunch and removing them later is elasticity.

6. CapEx vs OpEx?

CapEx: upfront purchase of assets like servers. OpEx: ongoing pay-as-you-go spending. Cloud shifts IT from CapEx to OpEx, improving cash flow and agility.

7. What is virtualisation?

Running multiple virtual machines on one physical host using a hypervisor. Type 1 runs on hardware (KVM, Hyper-V, ESXi); Type 2 runs on an OS (VirtualBox). It is the foundation of IaaS.

8. VM vs container?

Both isolate workloads. A VM includes a full guest OS; a container shares the host kernel and packages only the app and libraries, so it starts faster and is smaller. Use VMs for full OS control, containers for portable microservices.

9. What is serverless?

Running code or services without managing servers; scaling and billing per use (Lambda, Azure Functions, Cloud Run functions). Great for event-driven and spiky work; less suited to long-running or steady heavy workloads.

10. What is object storage?

Storage of files as objects with metadata in buckets, accessed over HTTP (S3, Blob, Cloud Storage). Highly durable and cheap; not a file system for databases — that is block storage.

11. Block vs file vs object storage?

Block: raw disks for VMs and databases (EBS). File: shared folders over NFS/SMB (EFS, Azure Files). Object: HTTP-accessed objects for files, backups and data lakes (S3).

12. What is a VPC?

A logically isolated private network in the cloud where you define IP ranges, subnets, routes and firewalls. Public subnets route to an internet gateway; private subnets do not.

13. What is a load balancer?

A service that distributes incoming traffic across healthy targets, removing unhealthy ones using health checks. It enables high availability and horizontal scaling.

14. What is auto scaling?

Automatically adjusting the number of instances based on metrics or schedules, within minimum and maximum limits. It delivers elasticity and saves cost at quiet times.

15. What is the shared responsibility model?

The provider secures the cloud itself (facilities, hardware, hypervisor); the customer secures what they put in it (data, identities, configuration). The split moves with the service model: more customer responsibility in IaaS, less in SaaS.

16. What is IAM?

Identity and Access Management: who (users, groups, roles) can do what (actions) on which resources. Best practice: least privilege, MFA, roles instead of long-term keys.

17. What is a CDN?

A network of edge locations caching content close to users to reduce latency and origin load (CloudFront, Azure Front Door/CDN, Cloud CDN).

18. What is an SLA?

A provider’s commitment to availability, usually monthly, with service credits if missed. 99.9% allows about 43 minutes of downtime a month.

19. What is multitenancy?

Multiple customers sharing the same physical infrastructure with logical isolation. It drives cloud economies of scale.

20. Name the major cloud providers.

AWS, Microsoft Azure and Google Cloud lead the market; others include Oracle Cloud, IBM Cloud and Alibaba Cloud. Indian options include providers offering local data residency.

Junior · Services and hands-on (20)

21. How do you host a static website?

Upload files to object storage and enable website hosting (S3 website, Azure $web, GCS website config), ideally behind a CDN with HTTPS. Keep the bucket private and let the CDN read it where possible.

22. How does an EC2 instance access S3 securely?

Attach an IAM role through an instance profile; the SDK gets temporary credentials automatically. Never store access keys on the instance.

23. Security group vs NACL?

SGs are stateful, instance-level, allow-only. NACLs are stateless, subnet-level, ordered allow and deny rules. Most control uses SGs.

24. RDS vs DynamoDB?

RDS: managed relational databases with SQL and joins. DynamoDB: serverless key-value/document store with single-digit-millisecond latency at any scale. Choose by data model and access patterns.

25. What happens when you stop and start an EC2 instance?

EBS data persists; instance-store data is lost; the public IP usually changes unless you use an Elastic IP; billing for compute stops while stopped, but EBS storage is still billed.

26. What is an AMI / image?

A template with the OS and software used to launch instances. You can create your own golden images.

27. How do you make a database highly available?

Use the managed multi-AZ/zone-redundant option: a standby in another AZ with automatic failover; add read replicas for read scaling and backups for recovery.

28. What is CloudWatch vs CloudTrail?

CloudWatch: metrics, logs and alarms about performance. CloudTrail: audit log of API calls — who did what, when, from where.

29. What is infrastructure as code?

Defining infrastructure in files (CloudFormation, Bicep, Terraform) so it is versioned, reviewed and repeatable. My capstone stack deploys and tears down from one template.

30. What is CI/CD?

Continuous integration builds and tests every change; continuous delivery/deployment releases it automatically through stages. Tools: CodePipeline, Azure Pipelines, Cloud Build, GitHub Actions.

31. Blue/green vs canary deployment?

Blue/green switches all traffic to a new environment at once with instant rollback; canary sends a small percentage first and increases gradually. Canary limits blast radius.

32. What is a NAT gateway?

Lets instances in private subnets reach the internet for updates without being reachable from the internet. It has hourly and per-GB charges.

33. What is Route 53 / DNS?

DNS translates names to IP addresses. Route 53 also offers routing policies (latency, weighted, failover) and health checks.

34. What is a pre-signed URL?

A time-limited URL granting access to one private object without making it public; Azure uses SAS tokens, Google signed URLs.

35. What is a managed identity / service account?

An identity for applications managed by the cloud (Azure managed identity, Google service account) so code gets tokens without stored secrets.

36. What are tags/labels for?

Key-value metadata for cost allocation, automation, access control and cleanup — e.g. project=canteen, env=dev.

37. How do you connect on-premises to cloud?

Site-to-site VPN over the internet (quick, cheaper) or a dedicated private link (Direct Connect, ExpressRoute, Cloud Interconnect) for consistent bandwidth.

38. What is Kubernetes?

A container orchestration platform that schedules, scales and heals containers. Managed versions: EKS, AKS, GKE.

39. What is a snapshot?

A point-in-time copy of a disk stored durably; used for backups and creating new disks. AWS EBS snapshots are incremental.

40. What storage class would you use for 7-year archives?

An archive tier such as S3 Glacier Deep Archive, Azure Archive or Google Archive storage — cheapest per GB, with retrieval delays and costs.

Mid-level · Design, operations, security, cost (20)

41. Design a highly available web application.

Clarify SLA and traffic. Stateless app on instances or containers across at least two AZs behind a load balancer with health checks and auto scaling; managed DB multi-AZ; static content on CDN; sessions in a cache; IaC, monitoring, alarms; multi-Region only if the business needs it.

42. How would you migrate an on-premises application?

Assess (inventory, dependencies, licences), choose a strategy per app (7 Rs), build a landing zone (accounts, network, identity), pilot, migrate data with minimal downtime, cut over, optimise. Start with low-risk apps.

43. What is a landing zone?

A pre-configured multi-account/subscription environment with identity, network, logging, security baselines and guard-rails, e.g. AWS Control Tower, Azure landing zones.

44. RTO vs RPO?

RTO: how long until service is restored. RPO: how much data loss is acceptable. They decide the DR strategy — backup/restore, pilot light, warm standby or active-active.

45. How do you handle secrets?

Store in Secrets Manager/Key Vault/Secret Manager, access via roles, rotate automatically, never commit to Git, and scan repositories for leaks.

46. Someone pushed access keys to GitHub. What do you do?

Deactivate and delete the key immediately, review CloudTrail for misuse, remove any created resources, rotate related secrets, purge history, and move to roles/OIDC so no long-term keys exist.

47. How do you control costs across many teams?

Account/subscription per team, mandatory tags, budgets with alerts, cost dashboards, commitment discounts centrally, policies preventing expensive resources, monthly FinOps reviews.

48. The bill doubled this month. Investigate.

Cost Explorer by service, Region, usage type and tag; compare with last month; look for data transfer, NAT, idle or forgotten resources, logging volume; fix, then add budgets and anomaly detection.

49. How do you design for failure?

Assume components fail: redundancy across AZs, health checks, retries with backoff, timeouts, circuit breakers, queues to decouple, graceful degradation, chaos testing.

50. What is observability?

The ability to understand a system from its outputs — metrics, logs and traces — so you can ask new questions during incidents. Add SLOs and alerts on symptoms users feel.

51. SLI, SLO, SLA?

SLI: a measured indicator (p95 latency). SLO: internal target for it (p95 under 300 ms for 99% of minutes). SLA: external contract with penalties, usually looser than the SLO.

52. How do you secure a multi-account AWS organisation?

Organizations with SCPs, SSO/Identity Center, central CloudTrail and Config, GuardDuty and Security Hub delegated admin, guard-rails via Control Tower, separate log and security accounts.

53. Containers on ECS/EKS vs serverless functions?

Containers for long-running services, custom runtimes, steady load; functions for event-driven, spiky, short tasks. Consider team skills and cost at your load profile.

54. How do you choose a Region?

Latency to users, data-residency laws (e.g. DPDP), service availability, price, and DR pairing.

55. How do you do zero-downtime database migrations?

Backward-compatible schema changes (expand/contract), replication or DMS for data, dual writes or CDC, feature flags, and a rollback plan.

56. What is a VPC endpoint / private link?

Private connectivity from your network to a service without the internet; gateway endpoints for S3/DynamoDB are free and save NAT charges.

57. Multi-cloud: when and when not?

When for regulation, best-of-breed services, acquisitions or negotiating leverage; not by default — it multiplies skills, tooling and security effort.

58. What is policy as code?

Guard-rails written as code — SCPs, Azure Policy, Organization Policy, OPA — evaluated automatically, e.g. deny public buckets, require tags, restrict Regions.

59. How do you run an incident?

Declare, assign roles (commander, communications), mitigate first, communicate status, find root cause later, write a blameless postmortem with actions.

60. Where do you see cloud careers going?

More platform engineering, FinOps, security and AI/data workloads; strong fundamentals plus one deep specialty and automation skills stay valuable.

10 Hands-on

Do it yourself, step by step

These labs run on your own cloud account — we cannot run them for you. Each step has three tabs (AWS, Azure, Google Cloud); pick the cloud you have and do both the UI way and the CLI way. Stay inside free tier / credit limits, use the India Region (AWS ap-south-1 Mumbai · Azure Central India · Google asia-south1 Mumbai), and always do the Clean up step at the end. A 20-minute drill that turns your own account into interview material: security posture, cost, and an inventory you can explain. Read-only commands; no new resources except enabling one Google API.

  1. 0 · Get ready: account, budget, CLI

    Pick your cloud.

    UI way — AWS Management Console

    1. Create an AWS account (aws.amazon.com → Create an AWS Account); choose the Free plan while learning.
    2. Never work as root: IAM Identity Center (or IAM) → create an admin user with MFA and sign in as that user.
    3. Billing and Cost Management → Budgets → Create budget → monthly cost budget, e.g. $5, alert by e-mail (Lesson 5.5).
    4. Top-right Region menu → Asia Pacific (Mumbai). Open CloudShell (terminal icon) — the AWS CLI is already signed in there.

    CLI way — the same thing with commands

    aws sts get-caller-identity          # who am I? (must NOT be the root user)
aws configure set region ap-south-1
aws configure list

    You should see: your account ID and an IAM user/role ARN — not “root”.

    UI way — Azure portal

    1. Create a free account at azure.microsoft.com/free (credit for the first 30 days).
    2. Search Cost Management → Budgets → Add → monthly budget, e.g. ₹400, alert at 80%.
    3. Open Cloud Shell (the >_ icon in the top bar) → choose Bash. The Azure CLI is already signed in.

    CLI way — the same thing with commands

    az account show --output table        # subscription in use
az account list-locations --query "[?name=='centralindia'].displayName" -o tsv

    You should see: your subscription name and state “Enabled”, then “Central India”.

    UI way — Google Cloud console

    1. Sign in at console.cloud.google.com and start the free trial (credit for 90 days).
    2. Create a project: project picker → New project → name tiffingo-lab.
    3. Billing → Budgets & alerts → Create budget → e.g. ₹400, alerts at 50/90/100%.
    4. Click Activate Cloud Shell (>_ icon). The gcloud CLI is already signed in.

    CLI way — the same thing with commands

    gcloud config set project tiffingo-lab      # use your real project ID
gcloud config set compute/region asia-south1
gcloud config list

    You should see: your account e-mail, the project and region asia-south1.

    Cloud Shell is the easiest CLI: free, in the browser, already logged in. On your laptop install the AWS CLI v2, Azure CLI or Google Cloud CLI and run aws configure / az login / gcloud init.

  2. 1 · Account hygiene you can talk about (“how do you secure your account?”)

    Pick your cloud.

    UI way — AWS Management Console

    1. IAM → Dashboard → Security recommendations: root MFA on, no root access keys.
    2. Note the users and whether each has MFA.

    CLI way — the same thing with commands

    aws iam get-account-summary --query 'SummaryMap.[AccountMFAEnabled,AccountAccessKeysPresent]' --output text
aws iam generate-credential-report >/dev/null; sleep 5
aws iam get-credential-report --query Content --output text | base64 -d | cut -d, -f1,4,8,9 | head

    You should see: 1 0 (root MFA on, no root keys) and a CSV of users with password, MFA and key-1 status. Say: “root has MFA and no keys; I use SSO/role sessions day to day.”

    UI way — Azure portal

    1. Microsoft Entra ID → your user → Authentication methods; Subscriptions → Access control (IAM) → Role assignments.

    CLI way — the same thing with commands

    ME=$(az ad signed-in-user show --query id -o tsv)
az role assignment list --assignee $ME --all --query "[].{role:roleDefinitionName,scope:scope}" -o table

    You should see: your roles and scopes. Say: “I work as Contributor in a lab subscription, not Owner; Conditional Access enforces MFA.”

    UI way — Google Cloud console

    1. IAM & Admin → IAM → find your principal and roles; Google Account → Security → 2-Step Verification.

    CLI way — the same thing with commands

    P=$(gcloud config get-value project)
gcloud projects get-iam-policy $P --flatten='bindings[].members' \
  --filter="bindings.members:user:$(gcloud config get-value account)" --format='table(bindings.role)'

    You should see: your roles on the project (e.g. roles/owner). Say: “in a team I would use a group with narrower roles.”

    Interviewers ask “how do you secure your account?” — now you answer with your own facts.

  3. 2 · Last month’s cost by service (“what does your project cost?”)

    Pick your cloud.

    UI way — AWS Management Console

    1. Billing → Cost Explorer → last month, group by Service.

    CLI way — the same thing with commands

    S=$(date -d "$(date +%Y-%m-01) -1 month" +%Y-%m-%d); E=$(date +%Y-%m-01)
aws ce get-cost-and-usage --time-period Start=$S,End=$E --granularity MONTHLY --metrics UnblendedCost \
  --group-by Type=DIMENSION,Key=SERVICE --query 'ResultsByTime[0].Groups[].[Keys[0],Metrics.UnblendedCost.Amount]' --output text | sort -k2 -t$'\t' -nr | head

    You should see: services sorted by last month’s cost (USD). Cost Explorer API calls are charged per request — run it once.

    UI way — Azure portal

    1. Cost Management → Cost analysis → Last month → group by Service name.

    CLI way — the same thing with commands

    S=$(date -d "$(date +%Y-%m-01) -1 month" +%Y-%m-%d); E=$(date -d "$(date +%Y-%m-01) -1 day" +%Y-%m-%d)
az consumption usage list --start-date $S --end-date $E \
  --query "[].{svc:consumedService,cost:pretaxCost}" -o tsv | awk -F'\t' '{c[$1]+=$2} END {for (k in c) printf "%s\t%.2f\n", k, c[k]}' | sort -k2 -nr | head

    You should see: cost per service namespace (e.g. Microsoft.Compute). Some offer types (e.g. certain free or sponsored accounts) show no usage data here — use the portal view.

    UI way — Google Cloud console

    1. Billing → Reports → last month → group by Service.

    CLI way — the same thing with commands

    gcloud billing projects describe $(gcloud config get-value project) --format='value(billingAccountName,billingEnabled)'
gcloud billing budgets list --billing-account=$(gcloud billing projects describe $(gcloud config get-value project) --format='value(billingAccountName)' | cut -d/ -f2) --format='table(displayName,amount.specifiedAmount.units)'

    You should see: your billing account and budgets. Per-service cost is in the Reports page (or a BigQuery billing export for queries).

    Have one number ready: “my labs cost about ₹X last month; the biggest item was Y, and here is how I would cut it.”

  4. 3 · Inventory your account (“walk me through what you built”)

    Pick your cloud.

    UI way — AWS Management Console

    1. Resource Groups & Tag Editor → Tag Editor → all Regions, all types → Search.

    CLI way — the same thing with commands

    aws resourcegroupstaggingapi get-resources --query 'ResourceTagMappingList[].ResourceARN' --output text \
  | tr '\t' '\n' | cut -d: -f3 | sort | uniq -c | sort -nr

    You should see: a count per service (only for tagged or previously tagged resources in this Region). Use it as the outline of your project story — and delete what you no longer need.

    UI way — Azure portal

    1. All resources → group by type.

    CLI way — the same thing with commands

    az resource list --query "[].type" -o tsv | sort | uniq -c | sort -nr

    You should see: a count per resource type across the subscription, e.g. Microsoft.Storage/storageAccounts.

    UI way — Google Cloud console

    1. Asset Inventory → Resource tab → group by asset type.

    CLI way — the same thing with commands

    gcloud services enable cloudasset.googleapis.com
gcloud asset search-all-resources --scope=projects/$(gcloud config get-value project) --format='value(assetType)' | sort | uniq -c | sort -nr | head

    You should see: a count per asset type, e.g. compute.googleapis.com/Instance.

    Walk the list top to bottom in your answer: what each resource does, why it is there, and what it costs.

Clean up and cost check

Nothing to delete. Optional: AWS remove the downloaded credential report from your shell history/notes; Google Cloud gcloud services disable cloudasset.googleapis.com if you no longer need it. Delete any leftover lab resources the inventory revealed.
