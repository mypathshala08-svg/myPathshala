1 The story

The new menu website needs a server today

Before you start: Module 1, especially 1.5 who manages which layer. Linux basics help (SSH, nginx).

🤔 Can you get a brand-new server in Mumbai in under two minutes, without buying anything?

Yes — that is Infrastructure as a Service (IaaS). You rent the raw building blocks — a virtual machine, a disk, a network, a firewall — and you install and run everything on top. AWS Mumbai alone offers 849 instance types (sizes of VM), from a 2-vCPU t3.micro at $0.0112 per hour to huge memory and GPU machines. In this lesson you will launch, inspect, stop and delete one with the AWS CLI, step by step.

  • What IaaS gives you and what you still manage.
  • What happens inside AWS when you launch a VM, and how its lifecycle affects the bill.
  • A full CLI walkthrough (and the console screen) to launch a web server — and clean it up.

TiffinGo is launching a menu website for its Pune and Mumbai kitchens. It needs one Linux server with nginx, today. Kabir’s first instinct is to buy a server.

Kabir

Sir, the new TiffinGo menu website needs a Linux server with nginx. Should I ask finance to buy one?

Arjun Sir

No purchase order needed. With IaaS we rent a virtual machine in Mumbai, choose its size, open the web port in a firewall, and it boots in about a minute.

Riya

Arjun Sir

We do — that is the deal with IaaS: AWS runs the hardware and the virtualization; we run the operating system and the app. Let’s see exactly how a launch works, then do it with the CLI.

2 Definition

What is IaaS?

Formal definition (write this in exams)

Infrastructure as a Service (IaaS) is a cloud service model in which the provider delivers virtualized computing infrastructure — virtual machines, block and object storage, and networking — on demand over the internet, while the customer controls and manages the operating system, middleware, runtime, data and applications (NIST SP 800-145).

In simple words

You rent virtual servers, disks and networks by the second, and install and run everything on them yourself.

Say it in an interview

30-second answer you can speak:

  • “IaaS is the cloud service model where the provider gives virtualized infrastructure — virtual machines, storage and networks — on demand, and we manage the operating system and everything above it.”
  • “Examples are Amazon EC2, Azure Virtual Machines and Google Compute Engine. We choose an image, an instance type, a key pair and a security group, and pay per second while it runs.”
  • “For example, I launched a t3.micro in Mumbai with a user-data script that installed nginx, then terminated it to stop the bill.”

Type 1 · General purpose

Definition (say it in an interview): General-purpose instances provide a balance of compute, memory and networking (typically about 4 GiB of memory per vCPU) for workloads that use these resources in roughly equal proportion.

In plain words (no jargon): Normal all-rounder machines with a fair mix of processor and memory.

Analogy: A family car: not the fastest, not the biggest boot, but good at most trips.

How it works internally, step by step

  1. Ratio. About 1 vCPU : 4 GiB.
  2. Sizes. large, xlarge, 2xlarge … double each step.
  3. Network. Bandwidth grows with size.
  4. Choose CPU. Intel, AMD or ARM (Graviton/Cobalt/Axion).
  5. Right-size. Watch metrics, then move up or down.

Words used above, in simple terms: vCPU = virtual CPU — usually one hyper-thread of a physical core · GiB = gibibyte, 1,024 MiB · ARM = processor design used by Graviton, Cobalt and Axion chips; usually cheaper

Type 2 · Burstable (shared-core)

Definition (say it in an interview): Burstable instances provide a baseline level of CPU performance with the ability to burst above it using accumulated CPU credits, at a lower price than general-purpose instances; they suit workloads that are idle most of the time.

In plain words (no jargon): Very cheap small machines that are fine when mostly idle and can speed up for short bursts.

Analogy: A mobile prepaid data pack: light daily use is cheap, but streaming all day empties it fast.

How it works internally, step by step

  1. Baseline. e.g. t3.micro = 10% of each vCPU.
  2. Earn. Credits accrue below baseline.
  3. Spend. Above baseline uses credits.
  4. Empty. Standard mode throttles; unlimited mode bills extra.
  5. Watch. CPUCreditBalance metric.

Words used above, in simple terms: baseline = the CPU % you can use forever without credits · CPU credit = one vCPU at 100% for one minute (AWS) · throttle = force the CPU down to baseline

Type 3 · Compute optimised

Definition (say it in an interview): Compute-optimised instances offer a high ratio of CPU to memory (typically about 2 GiB per vCPU) and high-performance processors, for compute-bound workloads such as batch processing, media encoding, scientific modelling, gaming servers and high-traffic web front ends.

In plain words (no jargon): Machines with more and faster processor power for jobs that do heavy calculation.

Analogy: A sports bike: built for speed, not for carrying luggage.

How it works internally, step by step

  1. Profile. CPU near 100%, memory low.
  2. Ratio. About 1 vCPU : 2 GiB.
  3. Clock. Higher sustained frequencies.
  4. Scale out. Often many instances for batch.
  5. Combine. With Spot for cheap batch.

Words used above, in simple terms: compute-bound = limited by processor speed · HPC = high-performance computing — many tightly connected machines · encoding = converting audio/video formats

Type 4 · Memory optimised

Definition (say it in an interview): Memory-optimised instances provide a high ratio of memory to CPU (typically 8 GiB per vCPU, with extra-large sizes offering terabytes of RAM) for workloads that process large data sets in memory, such as relational and in-memory databases, caches, real-time analytics and SAP HANA.

In plain words (no jargon): Machines with a lot of memory, for programs that keep big data in RAM.

Analogy: A big dining table: more people can work on the same meal at once without running back to the kitchen.

How it works internally, step by step

  1. Measure. Working set and memory pressure.
  2. Ratio. 8 GiB+ per vCPU.
  3. NUMA. Large sizes span sockets — tune apps.
  4. Licence. Some DB licences are per core — fewer, bigger-RAM cores save money.
  5. Monitor. Memory needs an agent (not default metrics).

Words used above, in simple terms: working set = the data an app touches often · in-memory = kept in RAM rather than on disk · SAP HANA = an in-memory enterprise database

Type 5 · Storage optimised

Definition (say it in an interview): Storage-optimised instances provide high, low-latency local storage throughput and IOPS — usually large local NVMe SSDs attached directly to the host — for workloads such as NoSQL databases, data warehousing, search engines and log processing; the local storage is ephemeral.

In plain words (no jargon): Machines with very fast disks built in, for databases and tools that read and write data all the time.

Analogy: Keeping your tools on your own workbench instead of fetching them from the store room each time.

How it works internally, step by step

  1. Local NVMe. SSD physically in the host.
  2. Ephemeral. Lost on stop, host failure or terminate.
  3. Replicate. App keeps 3 copies across nodes/AZs.
  4. Format. Mount at boot (user data).
  5. Back up. To object storage.

Words used above, in simple terms: IOPS = input/output operations per second · NVMe = fast SSD interface · ephemeral = temporary; does not survive the VM moving

Type 6 · Accelerated computing (GPU / AI chips)

Definition (say it in an interview): Accelerated-computing instances add hardware accelerators — GPUs, FPGAs or custom AI chips — to perform massively parallel work such as machine-learning training and inference, graphics rendering, video processing and scientific simulation far faster than CPUs.

In plain words (no jargon): Machines with graphics cards or special AI chips for very heavy maths like training AI models.

Analogy: Hiring a team of 1,000 helpers to roll rotis at the same time instead of one expert cook.

How it works internally, step by step

  1. Quota. GPU quotas often start at 0 — request early.
  2. Image. Use deep-learning images with drivers.
  3. Data. Stage data close (object storage, fast disks).
  4. Run. Train / render.
  5. Stop. Highest hourly prices — never leave idle.

Words used above, in simple terms: GPU = graphics processor with thousands of small cores · inference = using a trained model to predict · TPU = Google’s custom AI accelerator

7 Deep dive

Under the hood: hardware, CPU credits, storage, network, identity, pricing

Everything above lets you use IaaS. This section explains what is happening underneath, so you can design, troubleshoot and answer deeper interview questions.

1. Inside the physical host

A vCPU in EC2 is one hardware thread of a real CPU core. AWS runs a very thin hypervisor and moves networking, storage and security onto separate cards — this is why your VM gets nearly bare-metal speed and why one customer cannot reach another’s memory.

Each piece of the Nitro System, explained:

Nitro Card for VPC

What it is: A PCIe card that does all VPC networking for the host: the virtual switch, security-group checks, route lookups, and wrapping each packet with your VPC’s ID before it crosses the physical network. Your instance sees it as an ENA network adapter.

Why it exists: In older clouds this ran as software in the hypervisor and used CPU you paid for, adding jitter. In hardware it is faster (up to 100–200 Gbps) and the rules sit outside your VM, so even a hacked OS cannot switch off its security group.

Where it is used: Every Nitro instance (all current families). Every packet you send passes through it — Lesson 4.3 follows one step by step.

Nitro Card for EBS

What it is: A card that turns remote EBS storage into an NVMe disk inside the instance and encrypts data on the way.

Why it exists: The disk lives on storage servers elsewhere in the AZ; the VM must still see a fast local-looking disk, and encryption must not cost VM CPU.

Where it is used: Every EBS volume on Nitro instances appears as /dev/nvme….

Nitro Card for instance storage

What it is: Controls the NVMe SSDs physically inside the host and encrypts them.

Why it exists: Very fast scratch disk for caches and temp data.

Where it is used: Instance types with “d” (m6id, c6gd…) and storage-optimized i4i; data is lost on stop/terminate.

Nitro Controller

What it is: The card that manages the whole host: it talks to the EC2 control plane, starts and stops VMs, and holds the root of trust.

Why it exists: Management must not run on the same CPUs as customers, and AWS staff must have no path into customer memory.

Where it is used: Every Nitro host; it is why there is no operator SSH access to the hypervisor.

Nitro Hypervisor

What it is: A thin KVM-based layer that only assigns CPU and memory to VMs; all I/O is done by the cards.

Why it exists: Less code means fewer bugs, less overhead and fewer reboots for updates.

Where it is used: All virtualized Nitro instances; bare-metal (.metal) instances skip it but still use the cards.

Nitro Security Chip

What it is: A chip on the motherboard that checks and protects the host’s firmware.

Why it exists: Stops tampering below the hypervisor (the hyperjacking risk in Lesson 4.6).

Where it is used: Every Nitro host.

  2. Get the role’s temporary credentials.
  3. The app calls S3.
  4. Least privilege in action.

Caution: Require IMDSv2 (token-based) on every instance. With the old IMDSv1, a bug in a web app (server-side request forgery) could read the role’s credentials. New AL2023 launches use IMDSv2 by default; check with describe-instances.

8. Placement groups and tenancy

Cluster placement group

Instances packed close together in one AZ for the lowest network latency.

a few critical servers

Groups of instances on separate racks.

Hadoop, Kafka, Cassandra

Tenancy: default (shared hardware), dedicated instance (hardware used only by your account), dedicated host (you see and control the physical server — needed for some per-core licences).

9. Limits and health

  • Quotas: each account has a vCPU limit per instance family per region (“Running On-Demand Standard instances”). A new account may hit it; request an increase in Service Quotas.
  • Status checks: system check (AWS hardware/network — fix by stop/start to move hosts) and instance check (your OS — fix inside the VM); newer instances also have an attached EBS check.
  • Monitoring: CloudWatch collects CPU, network and disk metrics every 5 minutes by default (1 minute with detailed monitoring). Memory and disk-space metrics need the CloudWatch agent.

10 Hands-on

Do it yourself, step by step

These labs run on your own cloud account — we cannot run them for you. Each step has three tabs (AWS, Azure, Google Cloud); pick the cloud you have and do both the UI way and the CLI way. Stay inside free tier / credit limits, use the India Region (AWS ap-south-1 Mumbai · Azure Central India · Google asia-south1 Mumbai), and always do the Clean up step at the end. Steps 1–5 work in all three clouds. The optional AWS extra steps after them (data disk, snapshot, Elastic IP, IAM role, IMDSv2) show outputs from a practice run on moto, an AWS-compatible emulator, with the real AWS CLI — IDs will differ on your account; start the instance again before them (aws ec2 start-instances --instance-ids $IID).

Caution: Never open SSH (port 22) to 0.0.0.0/0 on a server you keep, never use the root user’s keys in the CLI, and never commit the .pem file or access keys to GitHub. Bots scan for all three within minutes.

  3. 2 · Launch a VM that only you can log into

    Pick your cloud.

    UI way — AWS Management Console

    1. Launch instances → name tiffingo-iaas, Amazon Linux 2023, t3.micro.
    2. Key pair → Create new key pair tiffingo-key (.pem) — the browser downloads it once.
    3. Network settings → Allow SSH traffic from My IP (never Anywhere) → Launch instance.

    CLI way — the same thing with commands

    aws ec2 create-key-pair --key-name tiffingo-key --query KeyMaterial --output text > tiffingo-key.pem && chmod 400 tiffingo-key.pem

  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=tiffingo-iaas}]' --query 'Instances[0].InstanceId' --output text)

    You should see: an instance ID i-…, state running, and a public IP. In CloudShell, checkip returns CloudShell’s IP — run this step from your laptop terminal, or use EC2 Instance Connect in step 3.

    UI way — Azure portal

    1. Create a virtual machine: resource group rg-iaas, name tiffingo-iaas, Central India, Ubuntu Server 24.04 LTS, Standard_B1s.
    2. Authentication: SSH public key → Generate new key pair; inbound ports SSH (22).
    3. Review + create → Create → Download private key and create resource.

az vm create --resource-group rg-iaas --name tiffingo-iaas --image Ubuntu2404 --size Standard_B1s \
  --admin-username azureuser --generate-ssh-keys --public-ip-sku Standard

    You should see: JSON with "powerState": "VM running" and publicIpAddress; your SSH key is saved in ~/.ssh/. az vm create opens port 22 by default — restrict it to your IP in the NSG for anything beyond a lab.

  4. 3 · Log in and patch the OS yourself

    Pick your cloud.

    UI way — AWS Management Console

    1. Select the instance → Connect → EC2 Instance Connect → Connect (or SSH from your laptop).

    You should see: dnf prints the packages it updated (or “Nothing to do”), ends with Complete!, then active. Patching the guest OS is your job in IaaS — AWS patches only the hardware and hypervisor.

    UI way — Azure portal

    1. VM → Updates (Update Manager) → Check for updates → One-time update — or Connect → SSH.
    2. Inside: sudo apt-get update && sudo apt-get upgrade -y.

    CLI way — the same thing with commands

    ssh azureuser@$IP "sudo apt-get update && sudo DEBIAN_FRONTEND=noninteractive apt-get upgrade -y && sudo apt-get install -y nginx && systemctl is-active nginx"

    You should see: apt lists upgraded packages, then active. Azure Update Manager can schedule this, but deciding and testing patches is still yours.

    UI way — Google Cloud console

    1. VM instances → SSH next to the VM — a browser terminal opens.
    2. Run sudo apt-get update && sudo apt-get upgrade -y. (Optional: VM Manager → OS patch management for scheduled patching.)

    CLI way — the same thing with commands

    gcloud compute ssh tiffingo-iaas --zone=asia-south1-a \
  --command="sudo apt-get update && sudo DEBIAN_FRONTEND=noninteractive apt-get upgrade -y && sudo apt-get install -y nginx && systemctl is-active nginx"

    You should see: the first run creates an SSH key for you; apt output; then active.

    This is the line that separates IaaS from PaaS: on PaaS the provider would have patched the OS for you (Lesson 2.2).

  6. 5 · Back up the disk with a snapshot

    Pick your cloud.

    UI way — AWS Management Console

    1. Volumes → select the root volume → Actions → Create snapshot → description before-upgrade.

    CLI way — the same thing with commands

    VOL=$(aws ec2 describe-volumes --filters Name=attachment.instance-id,Values=$IID --query 'Volumes[0].VolumeId' --output text)

aws ec2 wait snapshot-completed --snapshot-ids $SNAP
aws ec2 describe-snapshots --snapshot-ids $SNAP --query 'Snapshots[0].[SnapshotId,State,VolumeSize]' --output text

    You should see: snap-… completed 8. Snapshots are incremental and stored regionally (across AZs).

    UI way — Azure portal

    1. Snapshots → Create → source disk = the VM’s OS disk, type Incremental → Review + create.

    CLI way — the same thing with commands

    DISK=$(az vm show -g rg-iaas -n tiffingo-iaas --query storageProfile.osDisk.managedDisk.id -o tsv)

    You should see: a snapshot row with Succeeded.

    UI way — Google Cloud console

    1. Disks → the boot disk → Create snapshot → name tiffingo-iaas-snap → Create.

    CLI way — the same thing with commands

    gcloud compute snapshots create tiffingo-iaas-snap --source-disk=tiffingo-iaas --source-disk-zone=asia-south1-a

    You should see: tiffingo-iaas-snap 10 READY.

    Backups of a VM are your responsibility in IaaS — the provider keeps the disk durable, not your history of changes.

11 Mistakes to avoid

Common mistakes, why they happen, how to fix them

Mistake or symptomWhy it happensHow to fix or avoid
“I launched an instance but cannot see it.”The console or CLI is pointed at another region (often us-east-1).Check the region selector / aws configure get region; use ap-south-1 everywhere.
SSH: “Connection timed out”.Port 22 not allowed from your IP, no public IP, or wrong IP after a restart.Fix the security group rule (your current IP /32), check the public IP in describe-instances.
SSH: “UNPROTECTED PRIVATE KEY FILE” or “Permission denied (publickey)”.Key file permissions too open, wrong key, or wrong user name.chmod 400 key.pem; user is ec2-user on Amazon Linux, ubuntu on Ubuntu.
Web page does not load.Port 80 closed, nginx not installed, or user data failed.Check the SG rule; SSH in and read /var/log/cloud-init-output.log; systemctl status nginx.
Bill keeps coming after “stopping” the server.Stopped instances still pay for EBS disks and Elastic IPs.Terminate when finished; release Elastic IPs; delete old snapshots.
Data lost after terminate.Root volume has DeleteOnTermination = true by default.Create an AMI or snapshot first, or keep data on a separate volume / S3.
“Cannot attach volume: different Availability Zone”.EBS volumes are AZ-bound.Create the volume in the instance’s AZ, or snapshot → new volume in the right AZ.
A t3 server becomes slow every afternoon.CPU credits run out in standard mode (or unlimited charges pile up).Watch CPUCreditBalance; move steady high-CPU work to m/c families.

Exam-style questions with explanations

1. A company runs its app on EC2. Who is responsible for installing security patches on the guest operating system?
  1. AWS
  2. ✔ The customer
  3. Both equally
  4. The internet provider

Why: With IaaS the customer manages the OS and above. AWS patches the hypervisor, hardware and facilities. This shared-responsibility question appears in almost every CLF-C02 paper.

2. Which is an example of IaaS?
  1. ✔ Amazon EC2
  2. AWS Elastic Beanstalk
  3. Gmail
  4. Amazon Rekognition

Why: EC2 gives raw virtual machines. Beanstalk is PaaS (it manages the platform), Gmail is SaaS, Rekognition is an AI service.

3. A web server is stopped (not terminated) for the weekend. What is still charged?
  1. Nothing
  2. Compute hours
  3. ✔ The attached EBS volume (and any Elastic IP)
  4. Data transfer in

Why: Stopped instances do not pay for compute, but storage on EBS and unattached/idle public IPs are still billed.

4. Which EC2 feature acts as a virtual firewall controlling inbound and outbound traffic for an instance?
  1. IAM role
  2. ✔ Security group
  3. AMI
  4. Key pair

Why: Security groups are stateful firewalls attached to instances (network interfaces). IAM controls who can call APIs; a key pair is for login; an AMI is the image.

5. Which pricing model suits a steady web server that will run 24×7 for 3 years at the lowest cost?
  1. On-Demand
  2. ✔ Savings Plans / Reserved Instances
  3. Spot Instances
  4. Dedicated Hosts

Why: Commitment-based pricing gives the biggest discount for steady use. Spot is cheap but can be interrupted; Dedicated Hosts are for licensing/compliance.

6. Which purchasing option gives the biggest discount but can be interrupted with a 2-minute warning?
  1. Reserved Instances
  2. ✔ Spot Instances
  3. Savings Plans
  4. Dedicated Hosts

Why: Spot uses spare capacity at up to 90% off; AWS can reclaim it. Good for fault-tolerant batch work, not for a single critical web server.

7. Data on which storage is lost when an instance is stopped?
  1. EBS gp3 volume
  2. ✔ Instance store
  3. S3
  4. EBS snapshot

Why: Instance store is physically on the host; stopping moves the VM to another host, so the data is gone. EBS survives stop/start.

8. What is the most secure way for an application on EC2 to read from S3?
  1. Store access keys in the code
  2. ✔ Attach an IAM role through an instance profile
  3. Make the bucket public
  4. Use the root user

Why: Roles give temporary, auto-rotated credentials via the metadata service; nothing secret is stored on the server.

9. A security group allows inbound port 443. What about the response traffic?
  1. It must be allowed by an outbound rule
  2. ✔ It is allowed automatically because security groups are stateful
  3. It is blocked
  4. Only for IPv6

Why: Security groups track connections (stateful). Network ACLs are stateless and need explicit rules both ways.

10. What is the purpose of EC2 user data?
  1. To store user passwords
  2. ✔ To run a script automatically at first boot
  3. To list IAM users
  4. To encrypt EBS

Why: User data scripts run as root through cloud-init at launch; they install and configure software without logging in.

13 Mini project

Build something with what you learned

Mini project: TiffinGo menu website on EC2 with a backup image

Goal: Launch a web server that shows TiffinGo’s menu, update the page over SSH, save a reusable image (AMI), then launch a second copy from that image — and clean up.

Combines: EC2 + security groups + key pairs + user data + AMIs/EBS snapshots + SSH (Linux course).

  1. Set up: aws configure (IAM user, region ap-south-1); create a budget alert of $1.
  2. Launch: as in practical step 2, but also allow port 80 in the security group and pass a user-data script that installs nginx (--user-data file://userdata.sh, as in Lesson 6.1).
  3. Test: aws ec2 wait instance-status-ok --instance-ids $IID, then PUB=$(aws ec2 describe-instances --instance-ids $IID --query "Reservations[0].Instances[0].PublicIpAddress" --output text) and curl http://$PUB → expect the “TiffinGo menu” heading.
  4. Update the menu: ssh -i tiffingo-key.pem ec2-user@$PUB, then echo "<p>Today: Paneer thali ₹150</p>" | sudo tee -a /usr/share/nginx/html/index.html; refresh the browser.
  5. Save an image: IMG=$(aws ec2 create-image --instance-id $IID --name tiffingo-web-v1 --query ImageId --output text); aws ec2 wait image-available --image-ids $IMG.
  6. Launch a copy: aws ec2 run-instances --image-id $IMG --instance-type t3.micro --security-group-ids $SG --key-name tiffingo-key — the new server already has nginx and the updated menu (no user data needed).
  7. Clean up: terminate both instances, aws ec2 deregister-image --image-id $IMG, delete the AMI’s snapshot (aws ec2 describe-snapshots --owner-ids self → delete-snapshot), delete the security group and key pair; then aws ec2 describe-instances --filters Name=instance-state-name,Values=pending,running,stopping,stopped --query "length(Reservations)" should print 0.

You should see: Two identical web servers showing the updated TiffinGo menu, then nothing left running and no snapshot left behind.

15 Quiz and revision

Check yourself

Quick revision

Lesson 2.1 in one screen

  • IaaS = rent VMs, disks, networks; you manage OS and above (EC2, Azure VMs, Compute Engine).
  • Parts: AMI, instance type, key pair, security group, EBS, user data, VPC/subnet, public/private IP.
  • Launch = API call → IAM check → host in AZ → VM + EBS from AMI → network + SG → boot + user data → running.
  • Lifecycle: running bills compute + disk + IP; stopped bills disk (+ IP); terminated deletes root disk.
  • CLI: ssm get-parameter (AMI) → create-key-pair → create-security-group → run-instances → describe → stop/start → terminate → verify 0.
  • 849 instance types in Mumbai; letter = purpose (t, m, c, r, i, g/p).

Interview and viva questions

Is EC2 included in the AWS free plan?

New accounts get credits that cover small instances like t3.micro for practice; always set a budget alert and terminate after labs.

What is the difference between stop and terminate?

Stop = shut down, keep the disk (you pay for the disk). Terminate = delete the instance and, by default, its root disk.

Do I need SSH for this lesson?

Not for the CLI steps; SSH is used in the mini project to edit the page. On Windows use the built-in OpenSSH client or EC2 Instance Connect.

Why Amazon Linux 2023?

It is AWS’s own Linux, free, tuned for EC2 and uses dnf. Ubuntu works too; the user name changes to ubuntu.

Was the lab run on a real AWS account?

The outputs come from an AWS-compatible emulator (moto) with the real AWS CLI, so commands and formats match; IDs and IPs will differ on your account.
