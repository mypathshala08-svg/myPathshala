1 The story

What changed since your tutorial

Before you start: 5.4 KRaft.

🤔 If you learned Kafka from a 2022 tutorial, how much of it is now wrong?

More than you think. Kafka 4.0 (March 2025) removed ZooKeeper, made the new consumer rebalance protocol (KIP-848) GA, and shipped queues (share groups) in early access. Through 4.1, 4.2, 4.3 and 4.4 (October 2026) queues became production-ready, Kafka Streams got broker-side rebalancing, and 4.4 added dead letter queues for share groups. Our lab cluster reports exactly these features through its feature levels.

  • The big changes in 4.0 and what they replaced.
  • What 4.1–4.4 added, release by release.
  • How to check your own cluster and upgrade safely.

2 Definition

What’s new in Kafka 4

Formal definition (write this in exams)

Apache Kafka 4.x is the major line that began with 4.0 (March 2025), the first release without ZooKeeper (KRaft-only), with the next-generation consumer group protocol (KIP-848) generally available and queues for Kafka (KIP-932) in early access. Subsequent minor releases (4.1–4.4) added production-ready share groups, a broker-side Kafka Streams rebalance protocol (KIP-1071), share-group dead letter queues (KIP-1191) and many operational improvements, enabled through feature levels managed with kafka-features.

In simple words

Kafka 4 dropped ZooKeeper, made rebalances smooth, and learned to act as a job queue. Each later version adds more; your cluster’s feature levels show what is switched on.

Why, how, where

Why

Kafka changes several times a year. Old tutorials, blog posts and even interview questions still assume ZooKeeper, eager rebalances and “Kafka is not a queue”. Knowing what changed avoids wrong designs and failed upgrades.

the problem it solves

How

Each release adds KIPs (Kafka Improvement Proposals). New on-disk or protocol behaviour is switched on with feature levels (metadata.version, group.version, share.version …) after all nodes run the new binaries, so upgrades are two steps: roll binaries, then upgrade features.

the mechanism

Where

Every new cluster (4.x), every upgrade plan, every architecture review, and interviews that ask “what is new in Kafka?”.

in real systems

When not

You cannot jump from a ZooKeeper cluster straight to 4.x (migrate to KRaft on 3.9 first). Kafka 4.x clients and brokers need newer Java (Java 11+ for clients, 17+ for brokers and tools).

Your cluster tells you

Kafka 4 at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A new phone OS

  • The phone is the same shape, but some old apps (ZooKeeper, old rebalance) were removed and new ones arrived (queues). Some features only switch on after every part of the system is updated (feature levels).

Intermediate 4.0 (March 2025): the big break

  • KRaft only (KIP-500/833): ZooKeeper mode removed; migrate on 3.x first. Old message formats v0/v1 and MirrorMaker 1 removed; many deprecated APIs and configs gone.
  • KIP-848 consumer protocol GA: broker-driven, incremental rebalances (group.protocol=consumer), Lesson 3.2.
  • Queues (KIP-932) early access, transaction protocol improvements (KIP-890), ELR (KIP-966), default linger.ms 5 ms, Java 17 for brokers.

Advanced 4.1 to 4.4

  • 4.1 (Sep 2025): queues preview; Streams rebalance protocol (KIP-1071) early access; plugin metrics (KIP-877); OAuth jwt-bearer (KIP-1139).
  • 4.2 (Feb 2026): share groups production-ready, RENEW acknowledgement (KIP-1222), share lag metrics (KIP-1226); Streams rebalance protocol GA with a limited feature set; DLQ support in Streams exception handlers (KIP-1034); standardised CLI arguments (KIP-1147).
  • 4.3 (May 2026): assignment epochs to reduce fencing (KIP-1251), headers in state stores (KIP-1271/1285), cordoned log dirs (KIP-1066), MM2 multi-group offset translation (KIP-1239).
  • 4.4 (Oct 2026): dead letter queues for share groups (KIP-1191, share.version 2), transactional state stores in Streams (KIP-892), unregistering controllers (KIP-1312), new Linux I/O metrics (KIP-1291); broker.id and kafka-broker-api-versions.sh deprecated.

Myth vs reality: things many websites still say

  • Myth: Kafka needs ZooKeeper.
    Reality (Kafka 4.4): Not since 4.0.
    Proof: Lesson 5.4.
  • Myth: Kafka cannot be a queue.
    Reality (Kafka 4.4): Share groups GA since 4.2.
    Proof: Step 2: 7 share groups.
  • Myth: Upgrading binaries enables everything.
    Reality (Kafka 4.4): Feature levels must be raised too.
    Proof: Peel.

Exam tip: “What is new in Kafka 4?” 4.0: KRaft only, KIP-848 GA, queues EA, old formats/MM1 removed, Java 17; 4.1: queues preview, Streams protocol EA; 4.2: share groups production-ready, Streams protocol GA (limited); 4.3: assignment epochs, header-aware stores; 4.4: share DLQ (KIP-1191), transactional state stores (KIP-892). Feature levels; upgrade via 3.9.

7 Run the code

Run the code: read feature levels

What our lab cluster supports. Press Run, then try the challenges.

# Which features does a cluster support? (from kafka-features describe)
levels = {"metadata.version": "4.4-IV2", "group.version": 1, "share.version": 2,
          "streams.version": 1, "transaction.version": 2, "eligible.leader.replicas.version": 1}
checks = {
    "KIP-848 consumer groups": levels["group.version"] >= 1,
    "share groups (queues)":   levels["share.version"] >= 1,
    "share-group DLQ (4.4)":   levels["share.version"] >= 2,
    "Streams broker protocol": levels["streams.version"] >= 1,
    "KIP-890 transactions":    levels["transaction.version"] >= 2,
}
for name, ok in checks.items():
    print(f"{name:26s} {'yes' if ok else 'no'}")

Interview and viva questions

Do my 3.x clients work with 4.x brokers?

Modern clients (2.1+ protocol) yes; very old clients no. Upgrade clients to use new features.

Is KIP-848 automatic?

No, clients opt in with group.protocol=consumer; classic remains supported.

Where do I read release details?

kafka.apache.org/blog release announcements and the upgrade notes in the docs.

What about Kafka 5?

Not released as of late 2026; deprecations in 4.x (e.g. broker.id) point to removals there.
