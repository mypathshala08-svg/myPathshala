1 The story

A stream processor without a cluster

Before you start: 3.1 Consumer groups.

🤔 Read a topic, clean each order, split big and small orders into two topics, and scale it across machines. How many servers do you need besides Kafka?

Zero. Kafka Streams is a Java library, not a cluster: your app is a normal program that reads, transforms and writes topics. Scaling works like a consumer group: one task per input partition, spread over threads and instances. In our lab a 20-line app drew its own topology, dropped a qty-0 order, routed 2 thalis to big-orders and 3 others to small-orders, using 2 threads and 3 tasks.

2 Definition

Kafka Streams

Formal definition (write this in exams)

Kafka Streams is a client library for building applications that process records from Kafka topics and write results to Kafka. A program defines a topology of processors using the high-level DSL (KStream, KTable) or the Processor API. At runtime instances sharing an application.id form a consumer group; the topology is split into tasks (one per input partition per sub-topology) executed by stream threads, with fault tolerance, state management and optional exactly-once processing.

In simple words

Kafka Streams is a Java library: you write a small program that says “read this topic, change records like this, write them there”, and the library handles splitting the work, restarts and offsets.

Why, how, where

Why

Hand-written consume-process-produce loops must solve partition assignment, offsets, retries, state, scaling and exactly-once. Kafka Streams gives all of that as a library inside your app.

the problem it solves

How

You describe a topology with the DSL (stream → filter → mapValues → split → to). At start the library joins a consumer group named application.id, gets partitions, creates one task per partition, runs tasks on stream threads, and commits offsets (and output) together.

the mechanism

Where

Microservices that enrich, route, aggregate or join events: fraud checks, order routing, real-time counters, alerting. Runs anywhere Java runs: containers, Kubernetes, a laptop.

in real systems

When not

Java/Scala (JVM) only; input and output must be Kafka. For SQL, Python or multi-source pipelines look at Flink, Spark (Lesson 9.4) or ksqlDB.

Dissect the topology

Kafka Streams at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A sorting conveyor

  • Parcels arrive on a belt (topic). Workers check each parcel (filter), relabel it (map), and push it onto the right outgoing belt (split/to). Add more workers and the belts are shared out among them.

Intermediate The DSL

  • KStream: an unbounded stream of key–value records. Stateless operations: filter, map/mapValues, flatMap, peek, split().branch(), merge, selectKey, to.
  • Serdes turn bytes into objects (String, Long, JSON, Avro with the registry).
  • topology.describe() prints sources, processors and sinks: read it to see what your code really does.

Advanced Runtime

  • application.id = consumer group id and prefix for internal topics. Each input partition → one task (0_0, 0_1, 0_2 = sub-topology 0, partition n). Tasks are spread over num.stream.threads and instances; max parallelism = number of input partitions.
  • Lifecycle states: CREATED → REBALANCING → RUNNING → PENDING_SHUTDOWN → NOT_RUNNING (also ERROR).
  • processing.guarantee=exactly_once_v2 uses transactions (Lesson 3.5) to commit input offsets and outputs atomically. The lower-level Processor API gives full control (custom state, punctuations).

Myth vs reality: things many websites still say

  • Myth: Kafka Streams needs its own cluster.
    Reality (Kafka 4.4): It is a library inside your app.
    Proof: Step 2: java -cp.
  • Myth: More threads always help.
    Reality (Kafka 4.4): Max parallelism = input partitions.
    Proof: 3 tasks.
  • Myth: Streams runs on the brokers.
    Reality (Kafka 4.4): It runs in your app, brokers only store.
    Proof: Peel.

Exam tip: “What is Kafka Streams?” Java library; DSL KStream/KTable; topology of processors; application.id = consumer group; tasks per partition over threads/instances; stateless ops filter/map/split; state stores with changelogs; exactly_once_v2.

7 Run the code

Run the code: a stateless topology

The lab app’s logic in Python. Press Run, then try the challenges.

# Kafka Streams-style pipeline in plain Python (stateless)
orders = [("Mumbai", "idli,2,40"), ("Pune", "thali,1,150"), ("Delhi", "dosa,0,90"),
          ("Mumbai", "thali,2,300"), ("Pune", "vada,3,60"), ("Delhi", "lassi,1,45")]

def topology(records):
    out = {"big-orders": [], "small-orders": []}
    for key, value in records:
        if int(value.split(",")[1]) <= 0:          # filter
            continue
        value = value.upper()                      # mapValues
        topic = "big-orders" if value.startswith("THALI") else "small-orders"   # split
        out[topic].append((key, value))            # to
    return out

for topic, recs in topology(orders).items():
    print(topic, recs)
big-orders [('Pune', 'THALI,1,150'), ('Mumbai', 'THALI,2,300')] small-orders [('Mumbai', 'IDLI,2,40'), ('Pune', 'VADA,3,60'), ('Delhi', 'LASSI,1,45')]
  • if int(value.split(",")[1]) <= 0: # filterDelhi dosa qty 0 is dropped.
  • topic = "big-orders" if value.startswith("THALI") else "small-orders" # splitBranch by predicate.

Interview and viva questions

Can I use Python?

Not with Kafka Streams; use Faust-style libraries, Flink or Spark (Lesson 9.4).

Where does it run?

Anywhere your Java app runs: containers, Kubernetes, VMs.

How do I test it?

With TopologyTestDriver from kafka-streams-test-utils, no broker needed (Lesson 9.3 uses it).

What is the new streams rebalance protocol?

KIP-1071 moves Streams task assignment to the broker (like KIP-848 for consumers); check your Kafka version.
