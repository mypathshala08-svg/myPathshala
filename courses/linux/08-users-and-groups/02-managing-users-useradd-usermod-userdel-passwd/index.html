Managing users: useradd, usermod, userdel, passwd and chage

Every new joiner and every leaver means user management. This lesson explains useradd, passwd, chage, usermod and userdel, their defaults and traps, and how admins, DevOps, security and testers onboard and offboard safely.

Module 8 · Users, groups and sudo⏱ 42 minBeginner → AdvancedOnboard and offboard safelyLock vs expire vs deleteErrors decodedPractice lab with checkerReal outputs8 practice problems
The problem

Monday: Neha joins the data team and needs an account by 10 a.m., with a home folder, bash, and a password she must change at first login. Friday: Mohan leaves; his account must stop working today, but his project files must be kept for his manager. Three months later an auditor asks why passwords never expire. All of this is user management, and a single wrong option (a missing -m, a -G without -a) causes real tickets.

By the end of this page you will be able to:
  • create accounts properly with useradd (-m -s -c -u -g -G -d -e) and the friendlier adduser
  • set, lock, unlock and expire passwords with passwd, and set ageing rules with chage
  • change existing accounts with usermod (shell, comment, home, name, lock), without losing groups
  • remove or disable leavers safely with userdel and userdel -r, and know what is left behind

2 Definition

useradd, usermod, userdel, passwd and chage

Formal definition (write this in exams)

useradd creates a user account (and optionally its home folder) from defaults plus the options you give. usermod changes an existing account. userdel removes an account. passwd sets, locks, unlocks or expires a password. chage changes password-ageing and account-expiry information. All of them edit /etc/passwd, /etc/shadow and /etc/group safely and need root.

In simple words

Create, change, disable and remove accounts without editing the account files by hand.

User management at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: hiring and leaving a company

An account is like an employee record.

Basic The commands you will type

  • sudo useradd -m -s /bin/bash -c "Neha Rao" neha: create.
  • sudo passwd neha: set her password (type it twice, nothing is shown).
  • sudo usermod -s /bin/zsh neha: change something later.
  • sudo userdel -r neha: remove the account and her home.

Intermediate Defaults, skeleton and ageing

  • useradd’s defaults come from /etc/default/useradd (useradd -D) and /etc/login.defs (UID range, home creation, password ageing defaults).
  • -m copies the files from /etc/skel (.bashrc, .profile) into the new home.
  • chage sets password ageing in /etc/shadow: -M max days, -m min, -W warning, -I inactive, -E account expiry, -d 0 force change.
  • Locking: passwd -l/usermod -L put ! before the hash, so the password stops working. SSH keys still work: also expire the account (-e 1 or chage -E 0) or set shell nologin.

Advanced Behind the screen: what useradd changes

  • useradd locks the account database (/etc/passwd.lock etc.), writes one line each to /etc/passwd, /etc/shadow, /etc/group and /etc/gshadow (the user private group), adds ranges to /etc/subuid//etc/subgid for containers, then creates the home and copies /etc/skel.
  • userdel removes those lines; -r also removes the home and mail spool. Files elsewhere (/srv, /tmp, crontabs in /var/spool/cron) keep the old UID: find them with find / -uid N. A new user can later get the same UID and inherit them.
  • adduser (Debian/Ubuntu) is a Perl front-end that calls useradd with friendly defaults (bash, home, prompts) and enforces lowercase names (NAME_REGEX). On RHEL, adduser is just a link to useradd.
  • Never pass a password with useradd -p or on the command line: it must be a hash and it appears in process lists and history. Use passwd or chpasswd from a file/stdin.

Did you know? On Ubuntu, useradd without -s gives new users /bin/sh (dash): no arrow-key history, no tab completion. That is the most common “my new user’s terminal is broken” ticket.

Exam tip: “Create user tom with UID 2000, home, bash, member of wheel, password expiring in 60 days.” → useradd -m -u 2000 -s /bin/bash -G wheel tom; passwd tom; chage -M 60 tom.

Quick check What do you lose if you forget -m?
Answer: No home folder is created (and nothing from /etc/skel), so login lands in / and many programs fail to save settings.
Common mistake
✗“useradd -m cdac creates a home directory at /home/john” · “useradd -m -G developers Mohan”
✓It creates <code>/home/cdac</code> (the account name). Use lowercase names (<code>mohan</code>): useradd on Ubuntu 24.04 accepts “Mohan”, but adduser refuses it and many tools assume lowercase. <code>-G developers</code> fails if the group does not exist yet: create it first (Lesson 8.3).

Checked on Ubuntu 24.04: useradd -m Mohan succeeds; adduser Mohan is refused (NAME_REGEX); useradd -G developers x gives “group ‘developers’ does not exist” (exit 6).

🟡 Changes filessudo needed

Creates the account from the defaults (useradd -D, /etc/login.defs) plus your options. The account has no usable password until you run passwd.

useradd · adduser in system info / admin

  1. Situation: The defaults: why a bare useradd surprises people.

    sudo useradd -D | grep -E "SHELL|HOME|SKEL"
sudo useradd cdac
getent passwd cdac
ls -d /home/cdac 2>&1
    HOME=/home SHELL=/bin/sh SKEL=/etc/skel cdac:x:1002:1002::/home/cdac:/bin/sh ls: cannot access '/home/cdac': No such file or directory

    Why this way: No -m: no home. No -s: /bin/sh. Both are the puzzle’s answer.

  2. Situation: Fixed UID, custom home and comment (consistent across servers).

    sudo mkdir -p /data/home
sudo useradd -m -u 1090 -d /data/home/karan -s /bin/bash -c "Karan (DBA)" karan

    uid=1090(karan) gid=1090(karan) groups=1090(karan) karan:x:1090:1090:Karan (DBA):/data/home/karan:/bin/bash

    Why this way: A fixed UID keeps file ownership correct on NFS and in backups (Lesson 8.1).

useradd · adduser in devops / cloud

  1. Situation: A service account for an app: no login, no home, system UID.

    sudo useradd -r -s /usr/sbin/nologin -c "MyApp service" myapp
getent passwd myapp
sudo -u myapp id; sudo userdel myapp
    myapp:x:996:995:MyApp service:/home/myapp:/usr/sbin/nologin uid=996(myapp) gid=995(myapp) groups=995(myapp)

    Why this way: The service runs as myapp (systemd User=myapp, Lesson 17.3). If it is hacked, the attacker is not root.

useradd · adduser in security

  1. Situation: Contractor account that stops working on its own.

    sudo useradd -m -s /bin/bash -e 2026-12-31 mohan
sudo chage -l mohan | grep "Account expires"
    Account expires : Dec 31, 2026

    Why this way: No one has to remember to remove it in January.

useradd · adduser in software development

  1. Situation: The friendly way on Ubuntu (asks questions; here non-interactive).

    sudo adduser --disabled-password --gecos "Neha Rao" neha | tail -3
getent passwd neha
    info: Copying files from `/etc/skel' ... info: Adding new user `neha' to supplemental / extra groups `users' ... info: Adding user `neha' to group `users' ... neha:x:1002:1002:Neha Rao,,,:/home/neha:/bin/bash

    Why this way: adduser picks bash and creates the home. It also adds the user to the users group.

Common mistake
✗sudo useradd neha (and nothing else)
✓sudo useradd -m -s /bin/bash -c "Neha Rao" neha && sudo passwd neha

Without -m there is no home; without -s Ubuntu uses /bin/sh; without passwd the account is locked.

passwd · chpasswd set, lock and expire passwords

🟡 Changes filessudo needed

passwd changes your own password, or (as root) anyone’s. It also locks (-l), unlocks (-u), expires (-e) and shows status (-S). chpasswd sets many passwords from name:password lines on stdin.

✓ Use it when
  • setting a first password or resetting a forgotten one
  • locking an account quickly
  • forcing a change at next login
✗ Don’t use it when
  • passwords on the command line or in scripts in plain text

Syntax: passwd · sudo passwd [-l|-u|-e|-S|-d] NAME · … | sudo chpasswd

OptionWhat it doesWhen to use it

-Sstatus: P, L, NP + ageingcheck
-l / -ulock / unlock the passwordincidents
-eexpire: must change at next logintemporary passwords
-ddelete password (passwordless: dangerous)almost never
echo 'neha:Temp#2026' | sudo chpasswdnon-interactivebulk onboarding

passwd · chpasswd in system info / admin

  1. Situation: Lock and unlock (see the ! in shadow).

    sudo passwd -l neha
sudo grep '^neha:' /etc/shadow | cut -c1-12
sudo passwd -u neha
sudo grep '^neha:' /etc/shadow | cut -c1-12
    passwd: password changed. neha:!$y$j9T passwd: password changed. neha:$y$j9T$

    Why this way: Locking just puts ! in front of the hash; unlocking removes it. Nothing is lost.

  2. Situation: Unlocking an account that never had a password is refused.

    sudo passwd -l mohan; sudo passwd -u mohan; echo "exit $?"
    passwd: password changed. passwd: unlocking the password would result in a passwordless account. You should set a password with usermod -p to unlock the password of this account. exit 3

    Why this way: passwd protects you from creating a passwordless account. Set a password first.

passwd · chpasswd in devops / cloud

  1. Situation: Onboard several people from a file (passwords never typed on the command line).

    printf 'neha:N3ha#Tmp\nmohan:M0han#Tmp\n' > new.txt
sudo chpasswd < new.txt && shred -u new.txt
for u in neha mohan; do sudo passwd -e $u > /dev/null; sudo passwd -S $u; done

    Why this way: chpasswd reads stdin; shred removes the file afterwards. Each person must change the temporary password.

🟡 Changes filessudo needed

usermod in system info / admin

  1. Situation: Rename a login after a name change (home renamed too).

    sudo usermod -l karan -d /home/karan -m mohan
id karan; ls -d /home/karan
    uid=1002(karan) gid=1002(mohan) groups=1002(mohan) /home/karan

    Why this way: -l renames the login; -d -m moves the home. The UID stays the same, so all files still belong to them. The private group is still called mohan (rename with groupmod -n).

usermod in security

  1. Situation: Leaver: block password, keys and shell in one go, keep files.

    sudo usermod -L -e 1 -s /usr/sbin/nologin mohan
sudo passwd -S mohan
sudo chage -l mohan | grep "Account expires"
getent passwd mohan | cut -d: -f7
    mohan L 2026-11-11 0 99999 7 -1 Account expires : Jan 02, 1970 /usr/sbin/nologin

    Why this way: -e 1 = expired on 2 January 1970, so even SSH keys are refused. Reversible: usermod -U -e "" -s /bin/bash.

Common mistake
✗sudo usermod -G docker riya
✓sudo usermod -aG docker riya

Without -a, -G replaces every supplementary group: riya silently loses sudo and every other group. More in Lesson 8.3.

    794998 0 -rw-r--r-- 1 1095 1095 0 Nov 11 17:22 /srv/shared/ghost.log

    Why this way: On a real server search everything: sudo find / -xdev -nouser. A future user that gets UID 1095 would inherit these files. Delete or reassign them.

Undo and safety net

Account changes are reversible, except deleting data.

  • Locked the wrong user: sudo usermod -U -e "" NAME (and set the shell back).
  • Removed a user but not -r: recreate with the same UID (useradd -u N) and the old home works again.
  • Ran userdel -r by mistake: only a backup brings the home back. Take one first: tar czf.
  • Lost all groups with usermod -G: add them back with usermod -aG; check old memberships in /etc/group- (backup copy).

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. /usr/sbin/useradd neha
    useradd: Permission denied. useradd: cannot lock /etc/passwd; try again later. exit status: 1

    What it means: Only root may create accounts: it cannot lock /etc/passwd.

    Fix: sudo useradd …

  2. sudo useradd riya
    useradd: user 'riya' already exists exit status: 9

    What it means: The account already exists (exit 9).

    Fix: Choose another name, or change it with usermod.

  3. sudo useradd -G developers neha
    useradd: group 'developers' does not exist exit status: 6

    What it means: -G names a group that does not exist (exit 6).

    Fix: sudo groupadd developers first (Lesson 8.3).

  4. useradd -D
    /home/riya/script.sh: line 1: useradd: command not found exit status: 127

    What it means: As a normal user, /usr/sbin (where admin tools live) is not in PATH.

    Fix: Use sudo useradd …; sudo’s secure_path includes /usr/sbin (Lesson 8.4).

  5. sudo userdel nosuchuser
    userdel: user 'nosuchuser' does not exist exit status: 6

    What it means: No such account (exit 6).

    Fix: Check with getent passwd NAME.

Quick check Order the offboarding steps: userdel -r, lock + expire, back up the home, hand files over.
Answer: Lock + expire → back up → hand files over → userdel -r (only when the manager agrees).

User management at work

Script it: offboard.sh

A safe offboarding script: lock and expire, stop processes, archive the home, and only print the delete command for later.

u=${1:-karan}
sudo useradd -m -s /bin/bash "$u" 2>/dev/null   # a test account, for this demo only
id "$u" > /dev/null 2>&1 || { echo "no such user: $u" >&2; exit 1; }
sudo usermod -L -e 1 -s /usr/sbin/nologin "$u"
sudo pkill -u "$u" 2>/dev/null || true
sudo tar czf "/tmp/${u}_home_$(date +%F).tgz" -C /home "$u"
echo "locked: $(sudo passwd -S "$u" | cut -d' ' -f2)  archive: $(ls /tmp/${u}_home_*.tgz)"
echo "when approved: sudo userdel -r $u"
locked: L archive: /tmp/karan_home_2026-11-11.tgz when approved: sudo userdel -r karan

Run with a test account; it never deletes anything by itself.

Puzzle answer Remember the question from the story? Open to check your guess.

The home is /home/cdac (the account name), not /home/john. And on Ubuntu useradd’s default shell is /bin/sh, which is why arrow keys printed ^[[A: create with -s /bin/bash, or fix it with sudo usermod -s /bin/bash cdac.

Quick revision

Lesson 8.2 in one screen

  • sudo useradd -m -s /bin/bash -c "Name" NAME; then sudo passwd NAME. Defaults: useradd -D, /etc/login.defs, /etc/skel.
  • Other options: -u UID, -g primary, -G a,b extra (must exist), -d home, -e DATE, -r system.
  • adduser: interactive, bash + home by default (Debian/Ubuntu).
  • passwd -S -l -u -e; chpasswd for many; never passwords on the command line.
  • chage -l -d 0 -M -m -W -I -E.
  • usermod -s -c -l -d -m -L -U -e -aG. -G without -a removes other groups.
  • Leavers: lock + expire + nologin, back up, hand over, then userdel -r. Check find -nouser.

Interview and viva questions

How do I create a user with a home directory?

sudo useradd -m -s /bin/bash NAME (or sudo adduser NAME on Ubuntu), then sudo passwd NAME.

What is the difference between useradd and adduser?

useradd is the low-level tool (needs options); adduser on Debian/Ubuntu is an interactive wrapper with friendly defaults.

How do I lock a user account?

sudo usermod -L NAME (password only); add -e 1 to block SSH keys too.

How do I force a user to change password at next login?

sudo chage -d 0 NAME (or sudo passwd -e NAME).

How do I delete a user and their home?

sudo userdel -r NAME, after backing up anything needed.

How do I change a user’s shell?

sudo usermod -s /bin/bash NAME (or chsh for your own).

How do I rename a user?

sudo usermod -l NEW -d /home/NEW -m OLD (and groupmod -n NEW OLD for the group).

Interview and certification corner

What does useradd -r do?
Creates a system account (UID below 1000, no home by default).
How do you lock and unlock an account?
usermod -L / -U, or passwd -l / -u.
What does chage -M 90 do?
Password must be changed every 90 days.
Where are useradd defaults?
/etc/default/useradd (useradd -D) and /etc/login.defs.
What does userdel leave behind?
Files outside the home owned by the old UID; cron jobs and mail unless removed.
How do you add a user to a group without removing others?
usermod -aG GROUP USER.
How do you set a password non-interactively?
echo "user:pass" | chpasswd (from a protected source).
