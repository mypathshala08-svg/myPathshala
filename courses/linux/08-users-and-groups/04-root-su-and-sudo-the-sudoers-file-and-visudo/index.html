root, su and sudo: the sudoers file and visudo

Servers avoid root logins: named people run single, logged commands with sudo instead. This lesson explains root, su and sudo, how to read and write sudoers rules, how visudo prevents lock-outs, and how admins, DBAs, DevOps and security teams use them.

Module 8 · Users, groups and sudo⏱ 42 minBeginner → Advancedsu vs sudoLeast-privilege rulesHow sudo decides (animated)Practice lab with checkerReal outputs8 practice problems
The problem

3 a.m., production is down. Someone logged in as root, ran a command, and nobody knows who it was or what they typed. That is why modern servers almost never let people log in as root. Instead, named people run single commands with sudo: every use is logged with their name, they need their own password, and the rules can give a DBA exactly “restart PostgreSQL” and nothing more. One typo in the rules file can lock every admin out, so it has its own safe editor, visudo.

By the end of this page you will be able to:
  • explain what root is, why direct root logins are avoided, and how su and sudo differ
  • use sudo, sudo -i, sudo -u USER, sudo -l and sudo -k correctly, and read sudo’s messages
  • read and write sudoers rules (who where=(as-whom) what), with groups, NOPASSWD and command limits, in /etc/sudoers.d
  • edit rules safely with visudo, check them with visudo -c, and find who ran what in the logs

2 Definition

root, su, sudo, sudoers and visudo

Formal definition (write this in exams)

root is the superuser, UID 0, which bypasses normal permission checks. su (substitute user) starts a shell as another user after you type that user’s password. sudo runs a single command as root (or another user) after you type your own password, if the rules in /etc/sudoers allow it, and logs it. visudo is the safe editor for those rules: it locks the file and refuses to save a rule with a syntax error.

In simple words

Let named people do administrator work, one controlled and logged command at a time.

root, su and sudo at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a bank’s master key

root is the master key of the building.

Basic The commands you will type

  • sudo apt update: run one command as root, typing your password.
  • sudo -i: a root shell for several commands; exit when done.
  • sudo -u postgres psql: run as another user.
  • sudo -l: what you are allowed to run.
  • su - aman: become aman (needs aman’s password).

Intermediate Rules, groups and the password cache

  • Rules live in /etc/sudoers and files in /etc/sudoers.d/. Ubuntu’s key rule: %sudo ALL=(ALL:ALL) ALL: members of group sudo may run anything as anyone. RHEL: %wheel.
  • Rule format: WHO HOST=(RUNAS_USER:RUNAS_GROUP) [NOPASSWD:] COMMANDS, with full paths to commands.
  • After a correct password, sudo remembers you for 15 minutes per terminal (timestamp_timeout); sudo -k forgets.
  • secure_path replaces your PATH for sudo, and env_reset drops most environment variables (keep some with -E or env_keep).
  • Ubuntu locks the root password (passwd -S root shows L), so su - fails; use sudo -i.

Advanced Behind the screen: SUID, PAM and logging

  • /usr/bin/sudo and /usr/bin/su are SUID root programs (-rwsr-xr-x, Lesson 9.4): they always start with UID 0, check who called them, and only then run your command.
  • Password checks go through PAM (/etc/pam.d/sudo, /etc/pam.d/su), the same stack used by login and SSH (2FA modules plug in here).
  • sudo logs every attempt to syslog/journal (journalctl -t sudo, /var/log/auth.log on Ubuntu, /var/log/secure on RHEL), including denied ones. log_output can even record whole sessions (sudoreplay).
  • Rules are matched top to bottom and the last match wins, so specific rules go after general ones. Files in sudoers.d are read in name order; names with a dot or ending in ~ are ignored.
  • Command limits can be escaped: allowing vim, less, find, tar or any shell-escaping program as root effectively allows everything. Prefer sudoedit for editing files.

Did you know? sudo asks for your password, not root’s. On Ubuntu the root account has no usable password at all: the first user is simply placed in the sudo group by the installer.

Exam tip: “Allow members of group dba to run /usr/bin/systemctl restart postgresql as root without a password.” → file /etc/sudoers.d/dba (via visudo -f): %dba ALL=(root) NOPASSWD: /usr/bin/systemctl restart postgresql.

Quick check Why is sudo safer than sharing the root password?
Answer: Each person uses their own password, every command is logged with their name, rules can limit commands, and removing one person does not require changing a shared secret.
Common mistake
✗if [ "$(whoami)" != "root" ]; then echo "must be root"; fi (a root check from common notes)
✓if [ "$(id -u)" -ne 0 ]; then … (compare the UID, not the name)

The notes’ version works on most systems, but root could be renamed or another UID 0 account used. The kernel only cares about UID 0 (Lesson 8.1).

sudo in system info / admin

  1. Situation: What may I run? (riya, in the sudo group)

    Typical output on Ubuntu for a member of the sudo group

    sudo -l | tail -2
    User riya may run the following commands on web01: (ALL : ALL) ALL

    Why this way: (ALL : ALL) ALL = any command, as any user and group. Our build machine adds a NOPASSWD line so recordings work without typing.

  2. Situation: Write to a protected file: sudo applies to the command, not to the redirect.

    sudo echo '10.0.0.5 db01' >> /etc/hosts; echo "exit $?"
echo '10.0.0.5 db01' | sudo tee -a /etc/hosts > /dev/null; tail -1 /etc/hosts
sudo sed -i '/db01/d' /etc/hosts
    /home/riya/script.sh: line 1: /etc/hosts: Permission denied exit 1 10.0.0.5 db01

    Why this way: Your own shell opens /etc/hosts for >> before sudo starts. tee runs as root and opens it (Lesson 5.2). That is half the puzzle.

sudo in data administration

  1. Situation: Work as the database account without knowing its password.

    sudo -u postgres whoami
sudo -u postgres bash -c "cd; pwd"
    postgres /var/lib/postgresql

    Why this way: DBAs run psql, pg_dump and backups as postgres: sudo -u postgres psql. postgres has no password at all.

sudo in devops / cloud

  1. Situation: Scripts and cron must never hang waiting for a password.

    sudo -u aman sudo -n true; echo "exit $?"
    sudo: a password is required exit 1

    Why this way: -n fails immediately (exit 1) instead of prompting. Give automation a NOPASSWD rule for exactly the commands it needs.

sudo in security

  1. Situation: A normal user tries sudo (aman types his own password).

    echo 'Welcome@1' | sudo -u aman sudo -S cat /etc/shadow; echo "exit $?"
    [sudo] password for aman: aman is not in the sudoers file. exit 1

    Why this way: Denied and reported: “is not in the sudoers file. This incident will be reported.” Every attempt is logged.

Common mistake
✗sudo echo "text" >> /etc/hosts · sudo cd /root
✓echo "text" | sudo tee -a /etc/hosts · sudo -i, then cd /root

Redirections and cd are done by your own shell, which is not root. sudo cd fails because cd is a shell builtin, not a program.

/etc/sudoers · /etc/sudoers.d the rules

🔴 Can destroy datasudo needed

Each rule says who (user, %group) may run what (full paths), on which host, as whom. Put your own rules in small files in /etc/sudoers.d/ (mode 440) instead of changing the main file.

✓ Use it when
  • giving a person or group admin rights
  • giving exactly one command to a team
  • automation that needs root for one task
✗ Don’t use it when
  • editing with a normal editor
  • allowing editors, pagers or shells as root (they escape)

/etc/sudoers · /etc/sudoers.d in system info / admin

  1. Situation: Give the finance group one read-only log command.

    printf '%s\n' '%finance ALL=(root) /usr/bin/tail /var/log/dpkg.log' > /tmp/rule && sudo visudo -cqf /tmp/rule && sudo install -m 440 /tmp/rule /etc/sudoers.d/finance
sudo cat /etc/sudoers.d/finance
sudo -l -U aman | tail -2
    %finance ALL=(root) /usr/bin/tail /var/log/dpkg.log User aman may run the following commands on web01: (root) /usr/bin/tail /var/log/dpkg.log

    Why this way: Written to a temp file, checked with visudo -c, then installed with mode 440. A broken rule never reaches /etc/sudoers.d.

  2. Situation: Aman uses his one allowed command, and is denied anything else.

    echo 'Welcome@1' | sudo -u aman sudo -S /usr/bin/tail /var/log/dpkg.log | tail -1 | cut -c1-50
echo 'Welcome@1' | sudo -u aman sudo -S /usr/bin/tail -n 1 /var/log/dpkg.log; echo "exit $?"
echo 'Welcome@1' | sudo -u aman sudo -S /usr/bin/tail /etc/shadow; echo "exit $?"
    [sudo] password for aman: 2026-11-03 22:39:18 status installed libc-bin:amd6 [sudo] password for aman: Sorry, user aman is not allowed to execute '/usr/bin/tail -n 1 /var/log/dpkg.log' as root on web01. exit 1 [sudo] password for aman: Sorry, user aman is not allowed to execute '/usr/bin/tail /etc/shadow' as root on web01. exit 1

    Why this way: Arguments are part of the rule: the exact command works, but adding -n 1 or naming another file is refused. To allow any arguments, end the rule with the command alone (/usr/bin/tail), which here would expose /etc/shadow.

/etc/sudoers · /etc/sudoers.d in data administration

  1. Situation: DBAs may do anything, but only as the postgres account.

/etc/sudoers · /etc/sudoers.d in security

  1. Situation: Why allowing an editor or pager as root is dangerous.

    sudo -l -U aman 2>/dev/null | tail -1; echo 'rule like: aman ALL=(root) /usr/bin/less /var/log/syslog'
echo 'inside less, typing !bash gives a root shell: use sudoedit or a read-only command instead'
    User aman is not allowed to run sudo on web01. rule like: aman ALL=(root) /usr/bin/less /var/log/syslog inside less, typing !bash gives a root shell: use sudoedit or a read-only command instead

    Why this way: Programs that can start other programs (vim, less, find -exec, tar, awk) break command limits. GTFOBins lists them.

visudo · visudo -c edit rules safely

🟡 Changes filessudo needed

Opens the sudoers file (or -f FILE) in your editor, locks it, and checks the syntax before saving; on an error it asks “What now?” (e = edit again, x = discard). -c only checks.

✓ Use it when
  • every change to sudo rules
  • checking all rule files before you log out
✗ Don’t use it when
  • nano /etc/sudoers (no syntax check: one typo and nobody can use sudo)

Syntax: sudo visudo · sudo visudo -f /etc/sudoers.d/NAME · sudo visudo -c [-f FILE]

Common mistake
✗sudo nano /etc/sudoers
✓sudo visudo (or sudo visudo -f /etc/sudoers.d/NAME)

If you save a syntax error with nano, sudo refuses to run for everyone (“parse error in /etc/sudoers”), and you need recovery mode or pkexec to fix it.

Undo and safety net

Mistakes with sudo rules can lock you out. Prepare before you change them.

  • Before editing: keep a second terminal open with sudo -i: it stays root even if you break the rules.
  • Broke sudoers anyway: pkexec visudo (desktops), or boot into recovery mode (Lesson 17.1) and fix the file.
  • Removed yourself from the sudo group: another admin runs usermod -aG sudo YOU, or use recovery mode.
  • Left a root shell open: exit; for cached passwords, sudo -k.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. echo 'Welcome@1' | sudo -u aman sudo -S whoami
    [sudo] password for aman: aman is not in the sudoers file. exit status: 1

    What it means: The user has no sudo rule at all. The attempt is logged.

    Fix: Ask an admin to add you to sudo, or for a specific rule.

  2. sudo -u aman sudo -n true
    sudo: a password is required exit status: 1

    What it means: sudo needs a password but -n forbids asking (scripts).

    Fix: Run interactively, or add a NOPASSWD rule for that exact command.

  3. sudo cd /root
    sudo: cd: command not found sudo: "cd" is a shell built-in command, it cannot be run directly. sudo: the -s option may be used to run a privileged shell. sudo: the -D option may be used to run a command in a specific directory. exit status: 1

    What it means: cd is a shell builtin; sudo can only run programs.

    Fix: sudo -i, then cd; or sudo ls /root.

  4. sudo visudo -cf /tmp/bad
    /tmp/bad:1:37: syntax error aman ALL=(root) NOPASSWD /usr/bin/ls ^ exit status: 1

    What it means: A syntax error in a rules file (position shown).

    Fix: Fix it before installing; never install a file that fails -c.

Quick check You want aman to restart nginx and nothing else. Write the rule.
Answer: aman ALL=(root) /usr/bin/systemctl restart nginx in a file under /etc/sudoers.d, created with visudo -f.

Script it: need-root.sh

The standard start of an admin script: re-run itself with sudo if needed, then do the root work.

if [ "$(id -u)" -ne 0 ]; then
  echo "not root ($(id -un)): re-running with sudo" >&2
  exec sudo bash "$0" "$@"
fi
echo "running as $(id -un) (UID $(id -u))"
not root (riya): re-running with sudo running as root (UID 0)

exec sudo bash "$0" replaces the script with a root copy of itself. Here the script is saved as a file and run by riya.

Puzzle answer Remember the question from the story? Open to check your guess.

In sudo echo … >> /etc/hosts only echo runs as root; the >> is opened by riya’s own shell, which may not write /etc/hosts. Use echo … | sudo tee -a /etc/hosts. And su - wants root’s password, which Ubuntu locks: use sudo -i with your own password.

Quick check Which file would you create to give the group support permission to run /usr/bin/journalctl, and with which command?
Answer: sudo visudo -f /etc/sudoers.d/support containing %support ALL=(root) /usr/bin/journalctl.

Quick revision

Lesson 8.4 in one screen

  • root = UID 0. Log in as yourself; use sudo for admin work (own password, logged).
  • sudo CMD, -i root shell, -u USER, -l, -k, -n, sudoedit.
  • Redirection is not covered by sudo: … | sudo tee [-a] FILE. sudo cd fails (builtin).
  • su - USER needs USER’s password; Ubuntu’s root is locked, so use sudo -i.
  • Rules: WHO HOST=(AS_USER:AS_GROUP) [NOPASSWD:] /full/path args; groups with %; last match wins.
  • Put rules in /etc/sudoers.d/NAME (440) with visudo -f; check with visudo -c; keep a root shell open.
  • sudo/su are SUID root; passwords via PAM; logs: journalctl -t sudo, /var/log/auth.log.

Interview and viva questions

What is the difference between su and sudo?

su starts a shell as another user using that user’s password; sudo runs a command as root (or another user) with your own password, according to the sudoers rules, and logs it.

How do I give a user sudo rights?

sudo usermod -aG sudo USER on Ubuntu (wheel on RHEL), then they log in again.

How do I edit the sudoers file?

sudo visudo, or sudo visudo -f /etc/sudoers.d/NAME for your own rules.

How do I allow a command without a password?

A rule like USER ALL=(root) NOPASSWD: /full/path/command (only for specific commands).

Why does sudo say “is not in the sudoers file”?

The user has no rule; an admin must add them to the sudo group or write a rule. The attempt is logged.

How do I get a root shell?

sudo -i (exit to leave).

Where are sudo logs?

journalctl -t sudo, or /var/log/auth.log (Ubuntu) and /var/log/secure (RHEL).

Real-world scenario questions (asked in company interviews)

Interview questions about root and sudo, from fresher to senior rounds.

Any company · basicsFresher

“su vs sudo?”

Asked in almost every Linux interview.

The interviewer is checking: do you know the password difference?

Show a strong answer
  • su: target’s password, whole shell, little logging.
  • sudo: own password, rules, every command logged.
  • Ubuntu: root locked, use sudo -i.

Avoid: “they are the same”.

Help deskJunior

“sudo: unable to … parse error in /etc/sudoers”

Someone edited sudoers with nano and saved a typo.

The interviewer is checking: can you recover without reinstalling?

Show a strong answer
  1. Use an open root shell, pkexec visudo, or recovery mode.
  2. Fix with visudo; check with visudo -c.
  3. Only ever edit with visudo.

Avoid: reinstalling the OS.

Database teamMid-level

Give DBAs what they need, no more

DBAs ask for root to restart PostgreSQL and read its logs.

The interviewer is checking: can you write least-privilege rules?

Show a strong answer
  • %dba ALL=(postgres) ALL for database work.
  • %dba ALL=(root) /usr/bin/systemctl restart postgresql, /usr/bin/journalctl -u postgresql.
  • No editors or shells as root; review logs.

Avoid: adding DBAs to the sudo group.

Security teamSenior

A rule lets support run “sudo find”

An audit flags it.

The interviewer is checking: do you know shell escapes?

Show a strong answer
  • sudo find . -exec /bin/sh \; gives a root shell: the rule is equivalent to ALL.
  • Replace with a fixed wrapper script owned by root (not writable), or sudoedit for files.
  • Alert on sudo use outside the allowed set.

Avoid: “find only reads files”.

/etc/sudoers and /etc/sudoers.d/*.
What does NOPASSWD do?
