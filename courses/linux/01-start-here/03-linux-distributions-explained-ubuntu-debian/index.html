2 Definition

What is a Linux distribution?

Formal definition (write this in exams)

A Linux distribution (distro) is a complete operating system built on the Linux kernel, combined with a collection of system software and libraries (usually the GNU tools), a package management system and software repositories, an installer and default configuration, and released and maintained by a community or a company on a defined release and support cycle.

In simple words

A distro is Linux “ready to use”: the kernel plus all the programs around it, a way to install more software, and a team that keeps it updated. Ubuntu, Debian, Fedora and RHEL are distros.

Distributions at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: one Android, many phones

You already understand distributions from your phone. Many companies make Android phones. All of them run Android underneath, but each brand adds its own look, its own apps and its own update schedule.

  • A distribution (“distro”) is a ready-to-use Linux made by one team: Ubuntu, Fedora, Debian, Red Hat.
  • Like phone brands, they share the same core and differ in looks, included software and how long they give updates.
  • What you learn on one works on almost all others, just as you can use any Android phone once you know one.

Basic Same atta, different rotis

  • The Linux kernel is the atta (flour): every distribution uses it.
  • Each distribution is a different recipe: phulka, paratha, naan. Same base, different extra ingredients, different cooking style.
  • The extras are the tools (shell, commands), the package manager (the way you add new software), and the default settings.
  • Most daily commands are the same everywhere. Start with Ubuntu: it is the most common for beginners, laptops (WSL) and cloud servers.

Intermediate The families and what differs between them

  • Debian family: Debian, Ubuntu, Linux Mint, Kali, Raspberry Pi OS. Packages .deb, tools apt/dpkg.
  • Red Hat family: RHEL, Fedora, CentOS Stream, Rocky Linux, AlmaLinux, Oracle Linux, Amazon Linux. Packages .rpm, tools dnf (older yum)/rpm.
  • SUSE: SUSE Linux Enterprise, openSUSE (zypper). Arch: Arch Linux, Manjaro (pacman). Alpine: tiny, for containers (apk).
  • Release model: fixed releases with long support (Ubuntu LTS, Debian, RHEL) vs rolling (Arch, openSUSE Tumbleweed) where you always get the newest versions.
  • Who supports it: community (Debian, Fedora, Rocky, Alma) or a company with paid support (Canonical for Ubuntu, Red Hat for RHEL, SUSE).

Advanced The real differences an engineer meets

  • Package names and paths: the Apache web server is apache2 on Ubuntu and httpd on RHEL; SSH login records go to /var/log/auth.log on Ubuntu and /var/log/secure on RHEL.
  • Security layer: RHEL family enables SELinux by default, Ubuntu uses AppArmor (Lesson 19.2).
  • C library: almost all use glibc; Alpine uses musl, so some pre-built programs behave differently in Alpine containers.
  • Lifecycle: an Ubuntu LTS gets 5 years of standard support (extendable with Ubuntu Pro); a RHEL major version is supported for 10 years. Banks and telecoms value long, predictable support and certified software.
  • Identity: every modern distro describes itself in /etc/os-release; ID and ID_LIKE tell scripts which family they are on.

Did you know? Ubuntu code names are an adjective and an animal starting with the same letter, moving through the alphabet: 24.04 is “Noble Numbat”, 26.04 is “Resolute Raccoon”. Debian names its releases after Toy Story characters: Debian 13 is “trixie”.

Exam tip: “Explain Linux distributions with examples” → definition, the components (kernel, GNU tools, package manager, repositories, installer, support), two families with examples and package tools (Debian: .deb/apt; Red Hat: .rpm/dnf), and one line on LTS vs rolling release.

Answer: Both use the Linux kernel (each distro ships its own build and version). What differs is everything around it: package manager, default tools and settings, support lifecycle.

4 Step by step

Sit at any Linux server and find out where you are

A routine every engineer follows on an unfamiliar machine. Each step takes seconds.

  1. 1. Which distribution and version?

    cat /etc/os-release (or lsb_release -a on Ubuntu).

    Behind the screen: a plain text file written by the distribution. The kernel knows nothing about it.

  2. 2. Which family?

    Look at ID and ID_LIKE: ID_LIKE=debian → apt; ID_LIKE="rhel centos fedora" → dnf.

    Behind the screen: scripts and tools such as Ansible read the same fields to decide which commands to use.

  3. 3. Which package manager?

    command -v apt dnf yum zypper prints the ones that exist.

    Behind the screen: command -v searches PATH, the same way the shell finds any command.

  4. 4. Which kernel?

    uname -r. Distros ship their own patched kernel builds, so the version tells you about patches too.

    Behind the screen: the kernel answers directly through the uname system call.

  5. 5. Is it still supported?

    Check the version against the vendor’s lifecycle page. An EOL version (for example CentOS 7) gets no security fixes.

    Behind the screen: an unsupported server is a security risk; auditors ask about this.

5 See it happen

Same task on two distributions

Left: what Riya types on an Ubuntu server and on a Rocky Linux server. Right: which layers actually differ.

Same program, two distributions 5 steps
What you see
  1. Riya must install the nginx web server on an Ubuntu server and on a Rocky Linux server.
  2. On Ubuntu she uses apt; on Rocky Linux, dnf. This is the biggest daily difference between families.
  3. The progress messages look different, but both download and install packages.
  4. Starting and testing the server uses exactly the same commands on both.
  5. One detail differs: Ubuntu’s nginx package adds sites-available and sites-enabled folders; Rocky’s package puts site configs in conf.d only. Small differences like this are why you read the distro’s docs.
Behind the screen
  1. Underneath, both are Linux kernels. Process, memory and file handling work the same.
  2. The package format and tool differ: .deb with apt on the Debian family, .rpm with dnf on the Red Hat family.
  3. Each package manager downloads from its own signed repository, maintained by the distribution.
  4. Once installed it is the same open-source nginx, started by the same systemd, using the same kernel features.
  5. Distributions choose defaults: folder layout, file names, service names. Learn the family’s conventions and you can work on all its members.

Three real-time scenarios: choosing a distro for a job, LTS vs rolling over three years, and a real end-of-life migration.

Real-time scenario 1

Choosing a distribution for four real jobs

There is no single “best Linux”. Watch four common situations and the usual choice for each. These are typical industry patterns, not strict rules.

Right distro, right job 5 steps
Animated example
  1. For learning, Ubuntu LTS is the usual choice: default in WSL, huge community, most tutorials use it.
  2. A startup’s cloud servers commonly run Ubuntu LTS or a free RHEL-compatible distro such as Rocky Linux or AlmaLinux.
  3. Banks and telecoms often choose RHEL or SUSE because software vendors certify their products on them and support contracts are available.
  4. For Docker images, smaller is better: Alpine (a few MB) or Debian “slim”. Alpine uses the musl C library, so test your app on it.
  5. The decision is driven by support, team skills and vendor requirements, not by which is “better”. Your skills transfer.
Real-time scenario 2

Three years of updates: LTS vs rolling

Each orange box is the same Ubuntu 24.04 LTS release receiving fixes; each violet bar is a batch of new versions on a rolling distro. Illustrative, not exact counts.

Fixed release vs rolling release 5 steps
Animated example
  1. Both machines are installed in 2024.
  2. The LTS keeps the same versions of every program and only gets security and bug fixes. The rolling distro updates programs to their newest versions all the time.
  3. For a server running a payment app, “nothing changes unexpectedly” is worth a lot. For a developer laptop, new features may matter more.

Real-time scenario 3 · advanced

When a distribution ends: the CentOS 7 migration

A real industry event: CentOS Linux reached end of life. Thousands of companies had to choose a new distribution. Simplified, but the decision steps are typical.

Planning a distribution migration 5 steps
Animated example
  1. Many companies ran CentOS Linux 7, a free rebuild of RHEL 7.
  2. CentOS Linux 7 reached end of life on 30 June 2024 (CentOS 8 had ended in December 2021). Unsupported servers get no security fixes.
  3. Options: a free RHEL-compatible rebuild (Rocky Linux, AlmaLinux), paid RHEL, moving to Ubuntu, or CentOS Stream, which now sits just ahead of RHEL.
  4. Staying in the Red Hat family keeps dnf, rpm, SELinux and most scripts the same. They test, then migrate in small waves.
  5. Knowing your distribution’s lifecycle and family is everyday knowledge for Linux admins and DevOps engineers.

Layer by layer: dissect sudo apt install nginx

Installing software is where distributions differ most. Open each layer to see what really happens on an Ubuntu machine, where each part lives on disk, and run the real commands that show it (on the machine used to build this lesson).

Top = what you touch · bottom = the hardware. Click a layer.

You + sudo ask, with admin rights

Why does it exist?

Installing software changes system folders, so only an administrator may do it.

How does it work?

sudo checks you are allowed, asks your password and runs apt as root.

Where is it, really?

/usr/bin/sudo and the rules in /etc/sudoers (Lesson 8.4).

Where is it used?

Every software installation on a server, usually in scripts or automation tools.

apt the planner

Why does it exist?

Programs need other programs (dependencies). Working them out by hand is painful.

How does it work?

apt reads the package lists, finds nginx and everything it depends on, and makes a plan: what to download, in which order.

Where is it, really?

/usr/bin/apt; its sources are listed in /etc/apt/sources.list.d/.

Where is it used?

All Debian-family systems. The Red Hat family uses dnf in the same role.

See this layer yourself (real output)

apt-cache depends bash | head -4
bash PreDepends: libc6 PreDepends: libtinfo6 Depends: base-files

Repository the online store

Why does it exist?

Software must come from a trusted, signed source that also delivers security updates.

How does it work?

apt update downloads the index of available packages; apt install downloads the .deb files and checks their signatures.

Where is it, really?

Index files in /var/lib/apt/lists/; downloaded packages in /var/cache/apt/archives/.

Where is it used?

Companies often run their own mirror so servers install the same, approved versions.

See this layer yourself (real output)

apt-cache policy bash | head -3
bash: Installed: 5.2.21-2ubuntu4 Candidate: 5.2.21-2ubuntu4

dpkg the unpacker

Why does it exist?

Someone must actually put each file in place and remember which package owns it, for clean upgrades and removal.

How does it work?

dpkg unpacks the .deb archive, copies files into place, runs install scripts and records everything in its database.

Where is it, really?

/usr/bin/dpkg; database in /var/lib/dpkg/. On RHEL the same job is done by rpm.

Where is it used?

“Which package owns this file?” is a daily support question.

See this layer yourself (real output)

dpkg -S /usr/bin/ls
coreutils: /usr/bin/ls

systemd starts the service

Why does it exist?

A web server must start at boot, restart if it crashes and keep logs.

How does it work?

The nginx package installs a unit file; systemd reads it and starts nginx as a background service.

Where is it, really?

Unit files in /usr/lib/systemd/system/; controlled with systemctl (Lesson 17.2).

Where is it used?

Every service on a modern Linux server: web servers, databases, Docker.

See this layer yourself (real output)

ls /usr/lib/systemd/system | grep -c service
144

Kernel the same on every distro

Why does it exist?

Whatever the distribution, programs still need CPU, memory, files and the network.

How does it work?

nginx runs as an ordinary process; the kernel gives it CPU time and memory, and delivers network connections to it.

Where is it, really?

The distribution’s build of the Linux kernel in /boot.

Where is it used?

This layer is why your skills carry across distributions.

See this layer yourself (real output)

uname -sr
Linux 6.18.44-fc-v236
Quick check When apt installs nginx on Ubuntu, which program actually unpacks and records the files?
Answer: dpkg. apt plans and downloads; dpkg installs. On Rocky Linux the pair is dnf and rpm.

One-liner corner

Ways to identify a Linux system in one line. Each was really run on Ubuntu 24.04; other distros print their own values.

Beginner

Which distro is this?

Scenario: You have just logged in to an unknown server.

grep PRETTY_NAME /etc/os-release
PRETTY_NAME="Ubuntu 24.04.5 LTS"

grep prints the line containing PRETTY_NAME: the human-readable name and version.

Beginner

Which package manager do I use here?

Scenario: You want to install a tool but do not know whether this machine uses apt or dnf.

for pm in apt dnf yum zypper pacman apk; do command -v $pm; done
/usr/bin/apt

command -v prints the path of each command that exists and nothing for those that do not. Here only apt exists, so this is the Debian family.

Intermediate

Family, ID and version for a script

Scenario: Your install script must choose apt or dnf automatically.

(. /etc/os-release && echo "id=$ID like=$ID_LIKE version=$VERSION_ID")
id=ubuntu like=debian version=24.04

/etc/os-release is written as shell variables, so . (source) loads them. The ( ) keeps those variables from leaking into your shell.

Advanced

Pick the install command automatically

Scenario: One script must install curl on both Ubuntu and Rocky servers. (The command is printed, not run.)

(. /etc/os-release; case " $ID $ID_LIKE " in *" debian "*) echo "sudo apt install -y curl";; *" rhel "*|*" fedora "*) echo "sudo dnf install -y curl";; *) echo "unknown distro: $ID";; esac)
sudo apt install -y curl

case matches the ID words; the spaces around the pattern prevent partial matches. Real automation tools (Ansible) use exactly these os-release facts.

Advanced

Build it step by step: how many packages are installed, and which are the biggest?

Scenario: Before cleaning up a server image, the team wants to know how many packages it has and which ones use the most space.

  1. Look first: dpkg lists every package it knows. Installed ones start with ii.

    dpkg -l | head -7

Puzzle answer Remember the question from the story? Open to check your guess.

The package manager is not part of the kernel; it is part of each distribution’s own set of tools. Ubuntu ships apt, Rocky Linux ships dnf, Alpine ships apk. Same kernel, different toolboxes, so apt simply does not exist on the other two. That is exactly what “distribution” means.

7 Run the code

Identify four distributions from their os-release files

The script writes shortened copies of the /etc/os-release file from four distributions (version numbers are examples), then reads each one and decides which package tool that system uses. This is exactly how install scripts and automation tools adapt to different Linux systems.

mkdir -p samples
cat > samples/ubuntu <<'EOF'
ID=ubuntu
ID_LIKE=debian
VERSION_ID="24.04"
PRETTY_NAME="Ubuntu 24.04 LTS"
EOF
cat > samples/rocky <<'EOF'
ID="rocky"
ID_LIKE="rhel centos fedora"
VERSION_ID="9.6"
PRETTY_NAME="Rocky Linux 9.6"
EOF
cat > samples/debian <<'EOF'
ID=debian
VERSION_ID="13"
PRETTY_NAME="Debian GNU/Linux 13 (trixie)"
EOF
cat > samples/alpine <<'EOF'
ID=alpine
VERSION_ID=3.22.0
PRETTY_NAME="Alpine Linux v3.22"
EOF
for f in samples/*; do
  ( . "$f"
    case " $ID $ID_LIKE " in
      *" debian "*)          tool=apt ;;
      *" rhel "*|*" fedora "*) tool=dnf ;;
      *" alpine "*)          tool=apk ;;
      *)                     tool="?" ;;
    esac
    echo "$PRETTY_NAME -> install with: $tool" )
done
Alpine Linux v3.22 -> install with: apk Debian GNU/Linux 13 (trixie) -> install with: apt Rocky Linux 9.6 -> install with: dnf Ubuntu 24.04 LTS -> install with: apt
  • cat > samples/ubuntu <<'EOF'Creates a small sample file. Real systems have more lines, but these four fields are the important ones.
  • for f in samples/*; doLoops over every file in samples (alphabetical order: alpine, debian, rocky, ubuntu).
  • ( . "$f". loads the file’s variables (ID, ID_LIKE, …) into a subshell ( ), so each file starts fresh.
  • case " $ID $ID_LIKE " inDebian has no ID_LIKE because it is the base; Ubuntu says ID_LIKE=debian; Rocky says it is like RHEL.
  • echo "$PRETTY_NAME -> install with: $tool"Prints the human name and the package tool for that family.

Every installed .deb package is listed by dpkg with status “ii”. On RHEL the equivalent is rpm -qa | wc -l.

Quick revision

Lesson 1.3 in one screen

  • Distribution = Linux kernel + GNU tools + package manager + repositories + installer + defaults + support cycle.
  • Debian family: Debian, Ubuntu, Mint, Kali · .deb · apt/dpkg.
  • Red Hat family: RHEL, Fedora, CentOS Stream, Rocky, AlmaLinux, Amazon Linux · .rpm · dnf/rpm.
  • Others: SUSE (zypper), Arch (pacman), Alpine (apk, musl, tiny containers).
  • LTS/fixed releases for servers; rolling releases for newest software.
  • Ubuntu LTS: every two years in April, 5 years standard support. RHEL: 10 years per major version.
  • CentOS Linux ended (8 in 2021, 7 in June 2024); Rocky and Alma are RHEL-compatible replacements.
  • Identify any system: cat /etc/os-release → ID, ID_LIKE, VERSION_ID.

Interview and viva questions

What is a Linux distribution?

A complete operating system built on the Linux kernel, adding system tools (usually GNU), a package manager and repositories, an installer, default settings and a support lifecycle, maintained by a community or a company.

Difference between Debian-based and RHEL-based distributions?

Debian-based (Debian, Ubuntu) use .deb packages with apt/dpkg; RHEL-based (RHEL, Rocky, AlmaLinux, Fedora) use .rpm with dnf/rpm. Some paths and names differ (auth.log vs secure, apache2 vs httpd) and RHEL enables SELinux by default while Ubuntu uses AppArmor.

What is the difference between Fedora, CentOS Stream and RHEL?

Fedora is the fast-moving community distro where new technology appears first. CentOS Stream is the development branch just ahead of the next RHEL minor release. RHEL is the stable, commercially supported product.

Why did Rocky Linux and AlmaLinux appear?

When CentOS Linux, the popular free RHEL rebuild, was ended in favour of CentOS Stream, these projects were created to continue offering free distributions compatible with RHEL.

LTS vs rolling release?

An LTS keeps the same package versions for years and only adds security and bug fixes, which suits servers. A rolling release continuously updates to the newest versions, which suits enthusiasts.

How do you find which Linux distribution and version a server runs?

cat /etc/os-release (or lsb_release -a where available). For the kernel version use uname -r.

Small tasks about identifying and grouping distributions. Expected outputs are from real runs on Ubuntu 24.04.

P1Easy

Print only the distro name

Print just the value of PRETTY_NAME, without quotes.

P2Easy

Debian family or not?

Print “Debian family” if /etc/debian_version exists, otherwise “Not Debian family”.

Input
(the machine)
Expected output

Show solution and explanation 
if [ -f /etc/debian_version ]; then
  echo "Debian family"
else
  echo "Not Debian family"
fi
Debian family

How it works: -f tests whether a regular file exists. Ubuntu and Debian have this file; RHEL-family systems do not.

P3Easy

Version from the version string

Given VERSION_ID="24.04", print the year and month of release as “Released 20<yy>-<mm>”.

Input
24.04
Expected output
Released 2024-04
Show solution and explanation 
v=24.04
echo "Released 20${v%%.*}-${v#*.}"
Released 2024-04

How it works: ${v%%.*} removes everything from the first dot (24); ${v#*.} removes everything up to the dot (04). Shell string tricks are covered in the Shell Scripting course.

P4Medium

Count servers per tool

From the inventory, count how many servers need apt and how many need dnf.

Input
web-01 ubuntu
web-02 debian
db-01 rhel
etl-01 rocky
ci-01 ubuntu
Expected output
apt: 3
dnf: 2
Show solution and explanation 
printf 'web-01 ubuntu\nweb-02 debian\ndb-01 rhel\netl-01 rocky\nci-01 ubuntu\n' > inv.txt
echo "apt: $(grep -cE ' (ubuntu|debian)$' inv.txt)"
echo "dnf: $(grep -cE ' (rhel|rocky)$' inv.txt)"
apt: 3 dnf: 2

How it works: grep -cE counts lines matching an extended regex. ( a|b ) means either word, $ the end of the line.

P5Medium

Base distro or derivative?

For each sample (ID, ID_LIKE) pair, print “base” if ID_LIKE is empty, otherwise “derivative of …”.

Input
ubuntu:debian
debian:
rocky:rhel
Expected output
ubuntu: derivative of debian
debian: base
rocky: derivative of rhel
Show solution and explanation 
for pair in ubuntu:debian debian: rocky:rhel; do
  id=${pair%%:*}; like=${pair#*:}
  if [ -z "$like" ]; then echo "$id: base"; else echo "$id: derivative of $like"; fi
done
ubuntu: derivative of debian debian: base rocky: derivative of rhel

How it works: -z is true for an empty string. The pair is split at the colon with the same shell tricks as P3.

P6Medium

Which package manager is installed?

Print the first package manager found among apt, dnf, yum, zypper, pacman, apk.

Input
(the machine)
Expected output
Package manager: apt
Show solution and explanation 
for pm in apt dnf yum zypper pacman apk; do
  if command -v "$pm" >/dev/null; then echo "Package manager: $pm"; break; fi
done
Package manager: apt

How it works: command -v succeeds if the command exists; its output is thrown away with >/dev/null. break stops at the first match.

P7Business problem

Audit: how many servers are unsupported?

Using the EOL table and inventory below, print the number of unsupported servers as of 2026-11-05.

Input
eol: centos-7 2024-06-30, ubuntu-20.04 2025-05-31, ubuntu-24.04 2029-05-31
inventory: a centos-7, b ubuntu-24.04, c ubuntu-20.04, d centos-7
Expected output
Unsupported servers: 3
Show solution and explanation 
today=2026-11-05
printf 'centos-7 2024-06-30\nubuntu-20.04 2025-05-31\nubuntu-24.04 2029-05-31\n' > eol.txt
printf 'a centos-7\nb ubuntu-24.04\nc ubuntu-20.04\nd centos-7\n' > inv.txt
n=0
while read -r s r; do
  e=$(grep "^$r " eol.txt | cut -d' ' -f2)
  [[ $e < $today ]] && n=$((n+1))
done < inv.txt
echo "Unsupported servers: $n"
Unsupported servers: 3

How it works: Same lookup as worked example 3, but counting with n=$((n+1)). && runs the count only when the date test is true.

P8Business problem

Docker base image size check

A team lists base images and their sizes in MB. Print the smallest image and its size.

Input
ubuntu:24.04 78
debian:stable-slim 75
alpine:3.22 8
rockylinux:9-minimal 92
Expected output
alpine:3.22 8
Show solution and explanation 
printf 'ubuntu:24.04 78\ndebian:stable-slim 75\nalpine:3.22 8\nrockylinux:9-minimal 92\n' > images.txt
sort -k2 -n images.txt | head -1

Real-world scenario questions (asked in company interviews)

How interviewers check your understanding of distributions in real company situations.

IT services · fresherFresher

“Which Linux have you worked on?”

You learnt on Ubuntu. The interviewer says the client project runs RHEL 9. “Can you work on it?”

The interviewer is checking: do you know what transfers and what differs?

Show a strong answer
  • Yes: the kernel, shell, core commands, permissions, processes and systemd work the same.
  • Differences I would expect: dnf/rpm instead of apt/dpkg, some package and log names (httpd, /var/log/secure), and SELinux enabled by default.
  • I would check /etc/os-release first and read the RHEL documentation for those parts.

Avoid: “Linux is Linux, no difference” or “I only know Ubuntu”.

Startup · designJunior

Choosing a distro for production

Your startup is moving its app from a laptop to cloud servers. The CTO asks you to suggest a distribution.

The interviewer is checking: do you choose by support, ecosystem and team skills?

Show a strong answer
  1. Prefer a fixed release with long support: Ubuntu LTS, or a RHEL-compatible distro (Rocky Linux / AlmaLinux) if the team or customers prefer the Red Hat family.
  2. Check that our runtime, database and tools officially support it, and that the cloud offers maintained images.
  3. Standardise on one distro and version across servers and containers to keep scripts simple.

Avoid: picking a rolling distro for production, or choosing by what looks nicest on a desktop.

Enterprise · operationsMid-level

An end-of-life server

An audit finds five servers still on CentOS 7. Your manager asks what the risk is and what you propose.

The interviewer is checking: do you understand lifecycles and safe migration?

Show a strong answer
  • Risk: CentOS 7 reached end of life on 30 June 2024, so it gets no security patches; any new vulnerability stays open.
  • Options: migrate to Rocky Linux or AlmaLinux (same family, least change), RHEL with support, or re-platform on Ubuntu LTS.
  • Plan: inventory apps, test on a copy, migrate in small waves with backups and rollback, then add EOL dates to monitoring so it does not happen again.

Avoid: “It still works, so it is fine.”

Product company · containersMid-level

Alpine image breaks the app

The team switched the Docker base image from Debian slim to Alpine to save space. A Python package with compiled parts now fails to install or crashes.

The interviewer is checking: do you know Alpine’s main difference?

Show a strong answer
  • Alpine uses the musl C library instead of glibc; some pre-built binaries (wheels) are made for glibc, so they need compiling or behave differently.
  • Options: install build tools and compile, use musl-compatible packages, or go back to a slim glibc image (Debian/Ubuntu slim). A slightly larger image that works is better than a tiny one that breaks.

Avoid: blaming Docker or Python without checking the base image.
