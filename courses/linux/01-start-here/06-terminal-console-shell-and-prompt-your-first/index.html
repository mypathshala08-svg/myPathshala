2 Definition

Terminal, console, shell and prompt

Formal definition (write this in exams)

A terminal (terminal emulator) is a program that provides a text window for entering commands and displaying output, connected to a shell through a pseudo-terminal device. A console is the system’s directly attached text terminal (physical or virtual). The shell is the command-line interpreter that reads commands, interprets them and runs programs. The prompt is the text the shell prints to show it is ready for the next command. A command line has the form command [options] [arguments].

In simple words

The terminal is the window. The shell is the program inside it that understands you. The prompt is the shell saying “your turn”. You type a command, maybe with options (how) and arguments (on what), and press Enter.

The terminal and the shell at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: ordering at a chai stall

Using a terminal is like ordering at a busy chai stall.

  • The terminal is the counter window: you speak through it, but it does not make chai.
  • The shell is the chaiwala who understands your order and gets it done.
  • The prompt is him saying “Haan, bolo?”: your turn to order.
  • A command line is your order: what you want (ls), how (-l, an option) and for which thing (/etc, an argument). Press Enter to place it.
  • Ctrl+C is shouting “cancel!” when an order takes too long.

Basic A phone call

  • The terminal is the phone handset: you speak into it and hear the reply. It does not understand anything itself.
  • The shell is the person on the other end who listens, understands your request and gets it done.
  • The prompt (riya@laptop:~$) is that person saying “Yes, go ahead”. You type only after it appears.
  • A command is your request: date means “what is the date?”. Press Enter to send it.

Intermediate Reading any command line

  • Shape of a command: command [options] [arguments]. In ls -l /etc: ls = command, -l = option (long listing), /etc = argument (which folder).
  • Short options start with one dash and can be combined: ls -l -a = ls -la. Long options use two dashes: ls --all.
  • Spaces separate words. A name with a space needs quotes: cat "my notes.txt".
  • Prompt: user@host:folder$. ~ = your home folder. $ = normal user; # = root (administrator): be careful.
  • Help: command --help (short), man command (full manual, q to quit).

Advanced What really connects your keys to the shell

  • A terminal emulator (GNOME Terminal, Windows Terminal, iTerm2) talks to the shell through a pseudo-terminal (pty) device such as /dev/pts/0; tty prints yours. A virtual console (/dev/tty1…) is the kernel’s own text screen.
  • The pty’s line discipline handles special keys: Ctrl+C sends the SIGINT signal to the foreground program, Ctrl+Z sends SIGTSTP (pause), Ctrl+D means end of input.
  • bash uses the readline library for editing (arrows, Ctrl+A/E, Ctrl+R history search) and builds the prompt from the PS1 variable (\u@\h:\w\$).
  • The program receives the words as an array, argv; each program decides what its own options mean, which is why options differ between commands.

Did you know? Ctrl+C is a real character: byte number 3 (in old teleprinter codes, “end of text”). The terminal sends that byte, and the kernel’s terminal layer, seeing it, sends the SIGINT signal to the running program instead of passing the byte on.

Exam tip: “Differentiate terminal and shell; explain the structure of a Linux command with an example” → terminal = interface window, shell = interpreter (bash, zsh); structure command [options] [arguments] with ls -l /etc labelled; mention prompt symbols $ and #.

Quick check In ls -la /tmp, which part is the option and which the argument?
Answer: -la is the option (two short options joined: long format and all files); /tmp is the argument.

4 Step by step

Reading and running one command line

Take ls -l --human-readable /etc apart, then run it the professional way.

  1. 1. Wait for the prompt

    riya@laptop:~$: user riya, computer laptop, folder ~ (home), $ = normal user.

    Behind the screen: bash printed this from its PS1 variable and is now reading your keystrokes with readline.

  2. 2. Type the command name

    ls, then press Tab twice to see every command starting with “ls”.

    Behind the screen: Tab completion searches the folders in PATH (and bash builtins) for matching names.

  3. 3. Add options

    -l (long format) and --human-readable (sizes like 4.0K). Short options can be joined: -lh.

    Behind the screen: options are just words starting with a dash; ls reads them from its argument list.

  4. 4. Add the argument

    /etc, the folder to list. Type /e and press Tab: it completes to /etc/.

    Behind the screen: Tab completion for file names reads the folder contents, so it never makes a typo.

  5. 5. Press Enter and read

    The output appears; if it is long, re-run with | less to scroll (q to quit).

    Behind the screen: the shell splits the line into words, finds /usr/bin/ls, starts it with those words, and waits.

  6. 6. Check success, reuse, get help

    echo $? → 0 means success. Press ↑ to bring the command back and edit it. Unsure of an option? ls --help or man ls.

    Behind the screen: every program returns an exit status; bash keeps the last one in $? and keeps typed lines in history.
Quick check What does echo $? print right after a successful command?
Answer: 0. Any other number means the command failed; 127 means “command not found”.
5 See it happen

Tab, Enter and Ctrl+C: what each key really does

Left: Riya’s terminal (outputs shortened). Right: the path from the keyboard to bash and the program.

From key press to program 6 steps
What you see
  1. The prompt is visible, so the shell is ready.
  2. Riya types ls -l /e and presses Tab.
  3. The shell completes the folder name to /etc/.
  4. She presses Enter; ls prints the long listing (shortened here).
  5. She runs ping, which never stops by itself, and presses Ctrl+C (shown as ^C).
  6. ping prints a summary and exits; the prompt returns. (Output shortened; times are examples.)
Behind the screen
  1. bash shows the prompt from its PS1 variable and waits.
  2. Each key travels from the keyboard to the terminal app, then through the pseudo-terminal to bash, where the readline library edits the line.
  3. On Tab, readline reads the folder /, sees only one name starting with “e” and inserts it.
  4. On Enter, bash splits the line into words, an array called argv, finds /usr/bin/ls and runs it with those words.
  5. Ctrl+C is not sent as a letter. The pseudo-terminal converts it into the SIGINT signal for the program in the foreground.
  6. ping handles SIGINT by printing statistics and exiting. bash, which was waiting, takes over again. Lesson 11.3 covers signals in depth.

Layer by layer: dissect Ctrl+C

What really happens between pressing two keys and a running program stopping? Open each layer. The commands show each step for real (a timer plays your hand on the keyboard).

Top = what you touch · bottom = the hardware. Click a layer.

You Ctrl + C

Why does it exist?

Some commands never finish by themselves (ping, tail -f) or hang. You need a way to say “stop”.

How does it work?

Hold Ctrl and press C.

Where is it, really?

Your keyboard sends the key codes for Ctrl and C.

Where is it used?

Many times a day: stopping logs, pings, stuck commands.

Terminal sends byte 3

Why does it exist?

Ctrl+C is not a letter. The terminal turns the key combination into a special control character.

How does it work?

It sends the byte 0x03 to the shell side, just as it sends letters.

Where is it, really?

The terminal app (GNOME Terminal, Windows Terminal, iTerm2).

Where is it used?

All terminal apps follow this old convention, which is why Ctrl+C means “stop” everywhere.

See this layer yourself (real output)

printf '\x03' | od -An -tx1
03

Terminal layer in the kernel turns byte 3 into a signal

Why does it exist?

The byte must reach the running program as an order, not as text.

How does it work?

The pseudo-terminal’s line discipline is set to treat byte 3 as the INTR character. Instead of delivering it as input, it asks the kernel to send signal SIGINT (number 2) to the program in the foreground.

Where is it, really?

Inside the kernel (the tty layer); settings visible with stty -a (“intr = ^C”).

Where is it used?

Also turns Ctrl+Z into SIGTSTP (pause) and Ctrl+\ into SIGQUIT.

See this layer yourself (real output)

kill -l 2
INT

The program handles SIGINT

Why does it exist?

A program may need to tidy up before stopping: save data, delete temp files, print a summary.

How does it work?

If the program set a handler (ping does), it runs: ping prints its statistics, then exits. Otherwise the default action ends the program at once.

Where is it, really?

In the program’s own code (ping from iputils). Shell scripts set handlers with trap (Lesson 11.3).

Where is it used?

Databases and servers use the same idea to shut down cleanly.

Shell (bash) takes back control

Why does it exist?

After the program ends, you need your prompt back, and to know how it ended.

How does it work?

bash was waiting for the program; it collects the exit status (128 + 2 = 130 for a program killed by SIGINT) and prints the prompt.

Where is it, really?

bash’s job control; the status is in $?.

Where is it used?

Scripts check $? to see whether a step was interrupted.

See this layer yourself (real output)

timeout --preserve-status -s INT 1 sleep 30; echo "sleep was stopped by SIGINT: exit status $?"
sleep was stopped by SIGINT: exit status 130
Quick check Who turns the Ctrl+C key press into the SIGINT signal: the terminal app, bash, or the kernel?
Answer: The kernel’s terminal (tty) layer. The terminal app sends byte 3; the kernel converts it into SIGINT for the foreground program.
6 Real-world use

The terminal in a working day

1. Watching a live log during a release

During a deployment engineers keep a terminal with tail -f on the app’s log and stop it with Ctrl+C when the release looks healthy.

Release→tail -f + Ctrl+C→Go / no-go

2. Re-running yesterday’s commands

Developers search their history for the long docker, kubectl or git commands they used before, instead of searching the internet again.

Need old command→Ctrl+R / history→Run again

3. Checking an option before a risky command

Admins open man and search inside it (/) to confirm what an option does before running it on a server.

Unsure option→man / --help→Safe command

4. Making production obvious

Teams configure prompts and terminal colours per environment, so nobody confuses a production server with a test one.

SSH to server→PS1 with host + colour→Fewer mistakes

5. Rescuing a frozen desktop

When a Linux desktop freezes, switching to a virtual console lets you log in and stop the misbehaving program without rebooting.

Frozen GUI→virtual console→Fixed

Puzzle answer Remember the question from the story? Open to check your guess.

ping receives a signal, SIGINT, not a letter. The terminal sends byte 3 when you press Ctrl+C; the kernel’s terminal layer turns that byte into SIGINT for the program in the foreground. ping has a handler for SIGINT, so instead of dying immediately it prints its statistics and then exits. Run on your PC: your terminal, your prompt

Some things only make sense in a real interactive terminal. Outputs were recorded on a real Ubuntu 24.04 cloud VM (host name vm, user riya).

1 · How Ubuntu builds your prompt

echo "$PS1"
${debian_chroot:+($debian_chroot)}\u@\h:\w\$

\u = user, \h = host, \w = working folder, \$ = $ or # for root. The debian_chroot part is empty normally. Coloured terminals have extra colour codes.

/dev/pts/0

Typical output in a terminal window or SSH session (our recording ran without a terminal, where tty prints “not a tty”). Open a second tab and run it again: you get /dev/pts/1.

  3. cat -n shows the log with line numbers.

Quick revision

Lesson 1.6 in one screen

  • Terminal = window · shell = interpreter (bash) · prompt = “ready” · console = machine’s own text screen.
  • Command shape: command [options] [arguments]. -a -l = -la; long options: --all.
  • Prompt user@host:folder$; ~ = home; $ user, # root. Built from PS1.
  • First commands: echo, date, whoami, hostname, pwd, ls, cd, uptime, clear, history, type, man, exit.
  • Help: cmd --help, man cmd (q quits, / searches).
  • Shortcuts: Tab, ↑, Ctrl+C (stop), Ctrl+L, Ctrl+A/E, Ctrl+R, Ctrl+D; copy/paste with Ctrl+Shift+C/V.
  • echo $?: 0 success; 127 command not found; other non-zero = some failure.
  • Read the prompt (user, host, folder) before any risky command.

Interview and viva questions

What is the difference between a terminal and a shell?

The terminal is the interface (a window or device) that shows text and sends your keystrokes. The shell is the program running in it that interprets commands and runs programs. You can run different shells in the same terminal.

What is a console in Linux?

The system’s directly attached text terminal. Linux provides several virtual consoles (/dev/tty1–tty6), reachable on many desktops with Ctrl+Alt+F3 and so on.

Explain the parts of a Linux command.

Command (the program to run), options (modify behaviour, start with - or --), arguments (what to act on). Example: cp -r src backup: command cp, option -r (recursive), arguments src and backup.

What do $ and # mean in the prompt?

$ means a normal user; # means the root (administrator) user.

How do you get help for a command without the internet?

command --help for a summary, man command for the full manual, man -k keyword (apropos) to search manuals, and type command to see what it is.

What happens when you press Ctrl+C?

The terminal sends the SIGINT signal to the foreground process, which normally stops it. Programs may catch SIGINT to clean up first, as ping does when printing its statistics.

P3Easy

Combine options

Show the same folder with long format and hidden files using a single combined option.

Input
h/ from P2
Expected output
-rw-r--r-- 1 riya riya    0 Nov  5 18:36 .config
-rw-r--r-- 1 riya riya    0 Nov  5 18:36 notes.txt
Show solution and explanation

How it works: -la = -l -a. tail -2 keeps the two file lines (dates in the output are from the run).

P4Medium

Count builtins

Of the names cd echo ls pwd cat type, how many are bash builtins?

Input
cd echo ls pwd cat type
Expected output
builtins: 4 of 6
Show solution and explanation 
n=0
for c in cd echo ls pwd cat type; do
  [ "$(type -t $c)" = builtin ] && n=$((n+1))
done
echo "builtins: $n of 6"
builtins: 4 of 6

How it works: type -t prints “builtin” for shell builtins; the counter is increased with $((n+1)).

P5Medium

Exit status table

Run true, false, a missing command and ls on a missing file, printing each exit status.

Input
(nothing)
Expected output
true  -> 0
false -> 1
nocmd -> 127
ls    -> 2
Show solution and explanation 
true;  echo "true  -> $?"
false; echo "false -> $?"
nocmd 2>/dev/null; echo "nocmd -> $?"
ls /missing 2>/dev/null; echo "ls    -> $?"
true -> 0 false -> 1 nocmd -> 127 ls -> 2

How it works: true always succeeds (0), false always fails (1), a missing command gives 127, and ls uses 2 for “serious trouble” such as a missing argument. 2>/dev/null hides the error text.

P6Medium

Search the help text

Using date --help, print the help line that explains the %A format.

Input
date --help
Expected output
  %A   locale's full weekday name (e.g., Sunday)
Show solution and explanation 
date --help | grep -- '%A'
%A locale's full weekday name (e.g., Sunday)

How it works: Help text is plain text, so grep can search it. -- stops grep from treating the pattern as an option.

P7Business problem

Shift log for a support desk

Record three ticket actions with fixed times in shift.log and print the log with line numbers and the total count.

Input
09:10 T-101 opened
09:45 T-101 resolved
10:20 T-102 opened
Expected output
     1	2026-11-05 09:10 T-101 opened
     2	2026-11-05 09:45 T-101 resolved
     3	2026-11-05 10:20 T-102 opened
Total actions: 3
Show solution and explanation 
for e in '09:10 T-101 opened' '09:45 T-101 resolved' '10:20 T-102 opened'; do
  echo "2026-11-05 $e" >> shift.log
done
cat -n shift.log
echo "Total actions: $(wc -l < shift.log)"
1 2026-11-05 09:10 T-101 opened 2 2026-11-05 09:45 T-101 resolved 3 2026-11-05 10:20 T-102 opened Total actions: 3

How it works: Each loop round appends one line with >>. cat -n numbers lines; wc -l < counts them.

P8Business problem

Which tickets are still open?

From the shift log of P7, print ticket IDs that were opened but not resolved.

Input
shift.log from P7
Expected output
OPEN: T-102
Show solution and explanation 
printf '2026-11-05 09:10 T-101 opened\n2026-11-05 09:45 T-101 resolved\n2026-11-05 10:20 T-102 opened\n' > shift.log
for t in $(grep opened shift.log | cut -d' ' -f3); do
  grep -q "$t resolved" shift.log || echo "OPEN: $t"
done
OPEN: T-102

How it works: For each opened ticket, grep -q checks whether a “resolved” line exists; || prints only when it does not.

Real-world scenario questions (asked in company interviews)

First-week questions interviewers use to see whether you are comfortable at a Linux prompt.

Any company · basicsFresher

“Read this prompt for me”

The interviewer shows root@db-prod-02:/var/lib/mysql# and asks what it tells you.

The interviewer is checking: can you read the prompt and see the risk?

Show a strong answer
  • User root (also shown by #), on host db-prod-02 (a production database server by its name), in folder /var/lib/mysql, where MySQL stores its data files.
  • Any delete or move here could destroy data, so I would double-check every command, prefer read-only commands, and use sudo for single commands instead of a root shell.

Avoid: reading only the folder and ignoring the user and host.

Product company · basicsFresher

Terminal vs shell vs console

You are asked to explain the three words to a non-technical project manager.

The interviewer is checking: can you separate them clearly?

Show a strong answer
  • Terminal: the window where you type, like a chat window.
  • Shell: the program on the other side that understands the commands and runs them (bash).
  • Console: the machine’s own built-in text screen, used when there is no window system or for rescue.

Avoid: saying all three are the same.

Operations · practicalFresher

A command that hangs

You ran a command on a server and it has printed nothing for five minutes. What do you do?

The interviewer is checking: do you know safe ways to regain control and investigate?

Show a strong answer
  1. Press Ctrl+C to interrupt it. If it ignores that, press Ctrl+Z to suspend it, then use jobs and kill %1 (Module 11).
  2. Find out why: maybe it was waiting for input, a network host was unreachable, or the command expected a file argument and was reading the keyboard instead.
  3. Re-run with a timeout or verbose option (-v) if available.

Avoid: closing the SSH window or rebooting the server.

Any company · habitsFresher

“How do you work fast in the terminal?”

The interviewer asks which habits make you productive at the command line.

The interviewer is checking: do you know professional shortcuts and help tools?

Show a strong answer
  • Tab completion for commands, paths and options; Up arrow and Ctrl+R to reuse history.
  • Ctrl+A/Ctrl+E to edit long lines, Ctrl+L to clear, Ctrl+C to cancel.
  • --help, man and type to check options before running anything risky, and echo $? to confirm success.

Avoid: “I copy commands from Google.”
