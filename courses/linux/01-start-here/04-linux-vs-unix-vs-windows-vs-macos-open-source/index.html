2 Definition

Open-source software and the GPL

Formal definition (write this in exams)

Open-source software is software whose source code is published under a licence that grants everyone the rights to use, study, modify and redistribute it, for any purpose. The GNU General Public License (GPL) is a copyleft open-source licence: anyone who distributes the software or a work based on it must make the corresponding source code available under the same licence terms. The Linux kernel is distributed under GPL version 2.

In simple words

Open source means the code is public and you are allowed to change and share it. The GPL adds one rule: if you give the software (or your modified version) to others, you must give them the code too, under the same freedom.

Open source and the four systems at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a sealed dabba vs a recipe you may change

Imagine two ways of getting lunch.

  • Windows and macOS are like the sealed dabba: you use them, but their makers keep the recipe (source code).
  • Linux comes with its recipe. Anyone may read it, improve it and share it. That is open source.
  • Open does not mean careless: banks, phones and supercomputers run Linux. Companies pay for support, not for the recipe.
  • The four systems (Linux, Unix, Windows, macOS) are like four houses: same kinds of rooms (files, users, programs), different builders and different house rules.

Basic An open recipe

  • Closed (proprietary) software is like a restaurant’s secret recipe: you can eat the dish (use the program) but not see or change the recipe (source code).
  • Open-source software publishes the recipe. Anyone may cook it, improve it and share it. Linux is open source.
  • “Free software” means free as in freedom. Many open-source programs are also free of cost, but companies still pay for support, certification and services.
  • Windows and macOS are mostly closed; Linux is open; classic Unix systems (AIX, Solaris, HP-UX) are commercial.

Intermediate How the four systems differ in daily use

  • Paths: Linux/macOS /home/riya with /; Windows C:\Users\Riya with \ and drive letters.
  • Case: Linux treats Logo.png and logo.png as different files. Windows and (by default) macOS do not.
  • Line endings in text files: Linux and macOS use LF (\n); Windows uses CRLF (\r\n). A script saved on Windows can fail on Linux.
  • Shells and tools: Linux uses GNU tools and bash; macOS uses BSD-style tools and zsh; Windows uses PowerShell and cmd. Many commands exist everywhere but options can differ (for example sed -i).
  • Installing software: apt/dnf on Linux, Homebrew on macOS, installers or winget on Windows.

Advanced Licences, kernels and the Unix trademark

  • The Linux kernel is licensed under GPL version 2 only. GPL is copyleft: if you distribute the kernel or a modified version, you must offer the source under the same licence. That is why phone makers publish their kernel sources.
  • Permissive licences (MIT, BSD, Apache 2.0) allow use in closed products with only attribution (Apache 2.0 adds a patent grant). AGPL extends copyleft to software offered over a network.
  • Using GPL software inside a company, without distributing it, creates no obligation to publish your code. Distribution is the trigger. Legal teams still review licences before shipping products.
  • “UNIX” is a trademark certified by The Open Group. macOS has been certified UNIX 03 since version 10.5; AIX is certified too. Linux distributions are “Unix-like”: compatible in behaviour, not certified.
  • Kernels: Linux (monolithic, Linux), macOS (XNU, hybrid), Windows (NT, hybrid). WSL 2 runs a real Linux kernel in a lightweight VM on Windows.

Did you know? CR and LF come from typewriters and teleprinters: “carriage return” moved the print head back to the left edge, “line feed” moved the paper up one line. Windows kept both characters at the end of each line; Unix decided one (LF) was enough. That 50-year-old choice is why Riya’s script fails.

Answer: No. GPL obligations start when you distribute the software (or a modified version) to others. Internal use alone does not trigger them. (AGPL is different for network services.)

4 Step by step

Moving a script from Windows to Linux without surprises

The most common cross-platform trap, fixed in six steps. You will run the same steps yourself in “Run the code”.

  1. 1. Copy the script to the server

    Riya copies backup.sh, written in Notepad on Windows, to the Ubuntu server.

    Behind the screen: the file is copied byte for byte, including Windows line endings (CR LF).

  2. 2. Run it and read the error

    ./backup.sh fails with “cannot execute: required file not found” (older bash says “/bin/bash^M: bad interpreter”).

    Behind the screen: the kernel reads the first line #!/bin/bash\r and looks for a program called /bin/bash\r, with an invisible carriage return at the end. It does not exist.

  3. 3. Look at the invisible characters

    cat -A backup.sh shows ^M$ at line ends; file backup.sh says “with CRLF line terminators”.

    Behind the screen: ^M is how cat displays the CR byte (decimal 13); $ marks the end of the line.

  4. 4. Remove the CR characters

    sed -i 's/\r$//' backup.sh (or dos2unix backup.sh if installed).

    Behind the screen: sed deletes a CR found just before each end of line, then writes a new file in place of the old one.

  5. 5. Make it executable

    chmod +x backup.sh.

    Behind the screen: Windows has no execute bit; Linux needs it before ./backup.sh may run (Lesson 9.2).

  6. 6. Prevent it next time

    Set your editor (VS Code, Notepad++) to save with LF, or set Git’s core.autocrlf for the project.

    Behind the screen: VS Code shows “CRLF” or “LF” in its status bar; one click switches it.
Quick check Which command shows ^M at the end of each line of a Windows file?
Answer: cat -A file. file also reports “CRLF line terminators” for scripts and text files.
5 See it happen

Why a Windows script fails on Linux

Left: Riya’s terminal. Right: the actual bytes of the first line of her script.

Two invisible characters 5 steps
What you see
  1. Riya runs the script she wrote in Notepad. Bash 5.2 says “cannot execute: required file not found”; older versions say “bad interpreter”.
  2. cat -A shows hidden characters: ^M before every $ (end of line).
  3. file says the text has CRLF line terminators, the Windows style.
  4. A sed command deletes the CR at the end of every line.
  5. The same script now runs normally.
Behind the screen
  1. On disk, the first line is the bytes #!/bin/bash followed by an end-of-line. When you run the script, the kernel reads this “shebang” line to find the interpreter.
  2. But there is a hidden carriage-return byte (\r) before the newline. The kernel looks for a program literally named /bin/bash\r, which does not exist.
  3. Windows ends text lines with two bytes (CR LF); Linux and macOS with one (LF). Every line of this script carries the extra CR.
  4. After the fix, each line ends with LF only, and the shebang names a real file.
  5. The kernel starts /bin/bash and passes it the script. The same problem breaks CSV imports and config files, so remember cat -A and file.

Three real-time scenarios: GNU vs BSD tools on Mac and Linux, a case-sensitive file name breaking a website, and a licence check before shipping.

Real-time scenario 1

Same command, Mac vs Linux: the sed -i surprise

Kabir’s script edits a config file in place. It works on the Ubuntu server and fails on his MacBook. A real, very common difference between GNU and BSD tools.

GNU tools vs BSD tools 5 steps
Animated example
  1. On Linux, sed -i 's/8080/9090/' app.conf edits the file in place.
  2. On macOS the same line fails, because BSD sed expects a backup-file suffix right after -i and treats the next word as that suffix.
  3. On macOS you write sed -i '' (an empty suffix). That form, in turn, does not work with GNU sed on Linux.
  4. sed -i.bak works on both and leaves a backup copy you can delete.
  5. macOS and Linux share Unix ideas, but their tools come from different projects. Test scripts where they will run.
Real-time scenario 2

It works on my laptop: the case-sensitive file name

A website looks perfect on a Windows laptop and loses its logo on the Linux server. One of the most common deployment bugs for beginners.

Case sensitivity in production 5 steps
Animated example
  1. The HTML refers to Logo.png, but the file was saved as logo.png.
  2. On Windows the file system ignores case, so the logo appears and nobody notices.
  3. On the Linux server Logo.png and logo.png are different names; the server finds no Logo.png and returns 404.
  4. ls | grep -i logo (case-insensitive search) shows the real name; the HTML shows the wrong one.
  5. Habit: lower-case names, exact matches, and testing on Linux before release.
Real-time scenario 3 · advanced

The licence check before a product ships

Companies routinely check the licences of every open-source component before releasing a product. Simplified; real reviews are done with legal teams and scanning tools.

Permissive vs copyleft in practice 5 steps
Animated example
  1. A release checklist includes a software bill of materials: every library and its licence.
  2. MIT is permissive: the code may be used in a closed product as long as the copyright notice is kept.
  3. Apache 2.0 is also permissive and adds a patent grant; keep the licence text and any NOTICE file.
  4. AGPL extends copyleft to software used over a network, so using it inside a web service needs legal review.
  5. A device that ships the Linux kernel (GPL-2.0) must offer the kernel source, including the maker’s changes. This is not legal advice; it shows why licences matter in engineering.

Layer by layer: dissect the CRLF failure

Follow Riya’s script from the moment Notepad saves it to the moment Linux refuses it. Each layer has a real command that shows exactly what that layer sees.

Top = what you touch · bottom = the hardware. Click a layer.

Editor on Windows saves the file

Why does it exist?

Text editors must mark where each line ends. Windows tradition marks it with two characters.

How does it work?

Notepad writes CR (byte 13) and LF (byte 10) after every line.

Where is it, really?

Windows apps by default; modern editors (VS Code, Notepad++) let you choose LF or CRLF in the status bar.

Where is it used?

Every script, CSV and config file written on Windows and copied to a Linux server.

File on disk just bytes

Why does it exist?

Files store bytes, not “lines”. A line ending is simply one or two more bytes.

How does it work?

The extra \r sits right before every \n. You cannot see it in most editors.

Where is it, really?

The file’s data blocks; od -c prints every byte as a character.

Where is it used?

Debugging broken CSV imports, configs and scripts.

See this layer yourself (real output)

od -c b.sh | head -2
0000000 # ! / b i n / b a s h \r \n e c h 0000020 o h i \r \n

Shell (bash) asks the kernel to run it

Why does it exist?

bash does not open scripts itself when you type ./b.sh; it asks the kernel to execute the file.

How does it work?

bash calls execve("./b.sh") and reports whatever error the kernel returns.

Where is it, really?

/usr/bin/bash; the message wording depends on the bash version.

Where is it used?

Every time you run ./script.sh.

See this layer yourself (real output)

./b.sh; echo "exit status: $?"
/home/riya/script.sh: line 2: ./b.sh: cannot execute: required file not found exit status: 127

Kernel reads the #! line

Why does it exist?

The kernel must know which program should interpret a script.

How does it work?

It reads the first line after #! up to the newline and tries to start that program. With CRLF the name is /bin/bash\r, which does not exist.

Where is it, really?

The kernel’s script loader (binfmt_script), part of execve.

Where is it used?

Every script with a shebang: bash, Python, Perl.

See this layer yourself (real output)

head -1 b.sh | od -c
0000000 # ! / b i n / b a s h \r \n 0000015

The fix sed removes the CR

Why does it exist?

Linux tools expect LF only. Removing the CRs makes the file a normal Linux text file.

How does it work?

sed -i 's/\r$//' deletes a CR at the end of each line and rewrites the file.

Where is it, really?

GNU sed (/usr/bin/sed); or dos2unix if installed; or Git’s line-ending settings.

Where is it used?

Release pipelines often check for CRLF automatically and fail the build.

See this layer yourself (real output)

sed -i 's/\r$//' b.sh && ./b.sh && file b.sh
hi b.sh: Bourne-Again shell script, ASCII text executable
Quick check What did echo $? print after the failed run, and what does that number mean?
Answer: 127: the command (here the interpreter /bin/bash\r) could not be found.
6 Real-world use

Where these differences matter at work

1. Android phones and kernel source

Because the Linux kernel is GPL, phone and TV makers publish the kernel source for their devices. Developers use it to build custom ROMs and fix drivers.

Device ships Linux→GPL v2→Kernel source published

2. Windows desktops, Linux servers

Many companies give staff Windows laptops while their servers run Linux. Developers use WSL, keep LF line endings and lower-case names to avoid surprises.

Code on Windows→WSL / LF / lowercase→Linux server

3. Mac developers

Developers on macOS use the Unix terminal daily but deploy to Linux. They install GNU tools or test in Docker containers to catch BSD/GNU differences.

Mac terminal→Docker / GNU tools→Linux deploy

4. Unix in banks and telecom

Some long-running core systems still run on commercial Unix such as AIX. Linux skills transfer to them: same shell ideas, permissions and processes.

Old Unix system→shell skills→Maintain / migrate

5. Open-source compliance

Release pipelines often generate a software bill of materials and scan licences automatically, flagging copyleft components for review.

Build→licence scanner→Approved release

One-liner corner

Commands for exactly these cross-platform problems. All were really run on Ubuntu; the sample files are created first.

Beginner

Does this file have Windows line endings?

Scenario: A script or CSV from a Windows colleague behaves strangely.

Sample files used: a CSV saved on Windows.

cat -A data.csv
name,city^M$ Riya,Kharghar^M$

cat -A shows invisible characters: ^M is the carriage return, $ the end of the line. (For scripts and plain text, file also reports “CRLF line terminators”; for CSV files it may not.)

Beginner

Find a file when you are not sure of its case

Scenario: Is it Logo.png, logo.png or LOGO.PNG?

Sample files used: three files with mixed-case names.

ls | grep -i logo
logo.png

grep -i ignores case while searching the list of names, so you see the exact spelling on disk.

Intermediate

Fix Windows line endings in place

Scenario: Convert the CSV so Linux tools see clean lines.

sed -i 's/\r$//' data.csv && cat -A data.csv
name,city$ Riya,Kharghar$

\r$ matches a carriage return at the end of a line; replacing it with nothing removes it. dos2unix does the same if installed.

Advanced

List every file in a project that still has CRLF endings

Scenario: Before a release, make sure no script or config in the repository has Windows line endings.

Sample files used: a small project with three files.

grep -rlI $'\r' proj
proj/scripts/deploy.sh proj/app.conf

$'\r' is bash’s way of writing a real carriage-return character. -r searches folders, -l prints only file names, -I skips binary files.

Advanced

Build it step by step: find and fix every Windows-style file in a project

Scenario: Before a release, make sure no file in the project has Windows line endings, and fix the ones that do.

  1. List files that contain a carriage return (-r recursive, -l names only, -I skip binaries).

    grep -rlI $'\r' proj
    proj/scripts/deploy.sh proj/app.conf

  2. How many?

    grep -rlI $'\r' proj | wc -l
    2

  3. xargs hands the list of names to sed, which fixes them all (Lesson 13.2).

    grep -rlI $'\r' proj | xargs sed -i 's/\r$//' && echo fixed
    fixed

  4. Fix and verify in one line: 0 means the project is clean.

    grep -rlI $'\r' proj | xargs sed -i 's/\r$//'; echo "Files still with CRLF: $(grep -rlI $'\r' proj | wc -l)"
    Files still with CRLF: 0

7 Run the code

Break a script the Windows way, then fix it

This script creates a file with Windows line endings, shows the error, reveals the hidden characters, fixes them and runs again. Then it proves that Linux keeps Report.txt and report.txt as two files. The output is from a real run with bash 5.2; older bash versions word the first error as “bad interpreter”.

printf '#!/bin/bash\r\necho "backup done"\r\n' > backup.sh
chmod +x backup.sh
./backup.sh
echo "exit status: $?"
cat -A backup.sh
# 2) Fix: remove the \r before each end of line
sed -i 's/\r$//' backup.sh
./backup.sh
# 3) Linux names are case-sensitive
touch Report.txt report.txt
ls

  • ./backup.shFails. The kernel looks for an interpreter called /bin/bash followed by an invisible CR.
  • echo "exit status: $?"127 means “command not found”: the interpreter could not be found.
  • cat -A backup.shShows invisible characters: ^M is the CR, $ the end of line.

Quick revision

Lesson 1.4 in one screen

  • Open source: code published with the right to use, study, modify and share. Free = freedom.
  • Copyleft (GPL): distribute it or a modified version → offer source under the same licence. Linux kernel = GPL-2.0; bash = GPL-3.0+.
  • Permissive (MIT, BSD, Apache 2.0): fine in closed products with attribution. AGPL: network use counts.
  • Kernels: Linux (monolithic) · macOS XNU (hybrid, certified UNIX) · Windows NT (hybrid) · AIX/Solaris (commercial Unix).
  • Tools: GNU on Linux, BSD-style on macOS (sed -i differs; sed -i.bak is portable).
  • Paths / vs \; Linux is case-sensitive.
  • Line endings: LF on Linux/macOS, CRLF on Windows. Detect with file or cat -A; fix with sed -i 's/\r$//'.
  • Linux licence files on Ubuntu: /usr/share/common-licenses, /usr/share/doc/<pkg>/copyright.

Interview and viva questions

Differentiate Linux and Windows.

Linux: open source (GPL), free, monolithic Linux kernel, case-sensitive file names, / paths, bash and GNU tools, software via package managers, dominant on servers and cloud. Windows: proprietary, licensed, NT kernel, case-insensitive, drive letters and \, PowerShell, installers/winget, dominant on office desktops.

Is macOS based on Linux?

No. macOS uses Apple’s XNU kernel and BSD-derived user tools, and is a certified UNIX. It feels similar to Linux because both follow Unix design and POSIX.

What is the difference between Unix and Linux?

Unix is the original family of operating systems from Bell Labs and its commercial descendants (AIX, Solaris, HP-UX); “UNIX” is a certified trademark. Linux is an independent, open-source Unix-like kernel written in 1991 that follows the same design.

What is copyleft?

A licensing approach where the freedom to use, change and share must be kept in any distributed derivative. The GPL is the best-known copyleft licence.

Can a company use GPL software without publishing its own code?

Yes, if it only uses it internally. Obligations under the GPL are triggered when the software, or a modified version, is distributed to others. (AGPL also covers offering software over a network.) This is general information, not legal advice.

Why does a script written on Windows fail on Linux?

Usually CRLF line endings: the first line becomes #!/bin/bash\r, so the kernel cannot find the interpreter. Convert to LF with sed -i 's/\r$//' or dos2unix, and add execute permission.

Portable in-place edit

Change debug=true to debug=false with a command that works on Linux and macOS, and keep a backup.

P6Medium

Lower-case every file name

A folder has Logo.PNG, Banner.JPG and team.png. Rename every file to lower case.

Input
Logo.PNG Banner.JPG team.png
Expected output
banner.jpg
logo.png
team.png
Show solution and explanation 
mkdir -p img && cd img
touch Logo.PNG Banner.JPG team.png
for f in *; do
  lower=$(echo "$f" | tr 'A-Z' 'a-z')
  [ "$f" != "$lower" ] && mv "$f" "$lower"
done

banner.jpg logo.png team.png

How it works: tr 'A-Z' 'a-z' converts letters to lower case; mv renames only when the name actually changes.

P7Business problem

Licence counts for a release note

From the dependency list, print how many libraries use each licence, most common first.

Input
a MIT
b Apache-2.0
c MIT
d GPL-3.0
e MIT
f Apache-2.0
Expected output
      3 MIT
      2 Apache-2.0
      1 GPL-3.0
Show solution and explanation 
printf 'a MIT\nb Apache-2.0\nc MIT\nd GPL-3.0\ne MIT\nf Apache-2.0\n' > deps.txt
cut -d' ' -f2 deps.txt | sort | uniq -c | sort -nr

How it works: The classic counting pipeline: take the column, sort it, count duplicates with uniq -c, sort by count. You will use it constantly (Module 6).

P8Business problem

Stop Windows files at the gate

Before deploying, print FAIL with the file names if any .sh file in deploy/ has CRLF endings, otherwise PASS.

Input
deploy/start.sh (LF), deploy/stop.sh (CRLF)
Expected output
FAIL: deploy/stop.sh
Show solution and explanation 
mkdir -p deploy
printf 'echo start\n' > deploy/start.sh
printf 'echo stop\r\n' > deploy/stop.sh
bad=$(grep -l $'\r' deploy/*.sh)
if [ -n "$bad" ]; then echo "FAIL: $bad"; else echo PASS; fi
FAIL: deploy/stop.sh

How it works: -n tests for a non-empty string. Checks like this run in CI pipelines so a broken script never reaches a server.

Real-world scenario questions (asked in company interviews)

Interview questions about operating systems, open source and cross-platform problems.

Any company · conceptsFresher

“Linux is free, so how do companies earn from it?”

The interviewer wants to see if you understand the open-source business model.

The interviewer is checking: do you understand free as in freedom and real business models?

Show a strong answer
  • The code is free to use, but companies pay for subscriptions and support (Red Hat, Canonical, SUSE), certification, long-term maintenance and consulting.
  • Cloud providers earn by renting Linux servers; hardware makers by selling devices that run Linux.
  • Companies contribute to Linux because sharing the cost of one excellent kernel is cheaper than each building their own.

Avoid: “Nobody earns from Linux” or “it is free so it has no support”.

Product company · debuggingFresher

“The script works on my laptop”

A teammate’s deploy script, written on Windows, fails on the Linux build server with “cannot execute: required file not found” (or “bad interpreter”).

The interviewer is checking: do you recognise the CRLF problem and fix it properly?

Show a strong answer
  1. Check the file: file deploy.sh or cat -A deploy.sh | head -2; ^M or “CRLF” confirms Windows line endings.
  2. Fix: sed -i 's/\r$//' deploy.sh (or dos2unix), make sure it is executable.
  3. Prevent: set the editor to LF, add a .gitattributes rule such as *.sh text eol=lf, and add a CI check.

Avoid: rewriting the script, or “just run it with bash deploy.sh” without explaining the cause.

Startup · complianceJunior

A GPL library in the product

Your company sells a desktop application. A developer added a GPL-licensed library. The product manager asks if that is a problem.

The interviewer is checking: do you know when copyleft obligations apply, and escalate correctly?

Show a strong answer
  • Because the app is distributed to customers, including a GPL library can require releasing the combined work’s source under the GPL.
  • Options: replace it with a permissively licensed alternative, use it in a way that legal confirms is acceptable, or accept GPL for that product.
  • Raise it with the legal/compliance team before release; do not decide alone.

Avoid: ignoring it because “open source is free”, or claiming any GPL use makes the whole company’s code public.

Web agency · deploymentFresher

Images missing after deployment

A site works perfectly on a Windows laptop. After deploying to the Linux server some images show as broken.

The interviewer is checking: do you think of case sensitivity?

Show a strong answer
  • Check the browser’s network tab or the server log for 404s; compare requested names with ls on the server.
  • Likely cause: names differing only in case (Logo.png vs logo.png). Windows ignores case, Linux does not.
  • Fix the references or rename files, and adopt lower-case names as a team rule.

Avoid: blaming the server or caching without checking the exact file names.
