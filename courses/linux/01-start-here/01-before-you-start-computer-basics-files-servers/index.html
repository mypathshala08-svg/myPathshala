2 Definition

Files, folders and servers: the words you must be sure of

Formal definition (write this in exams)

A server is a computer, physical or virtual, that runs continuously to provide a service (a website, a database, payments, file storage) to other computers called clients over a network. Servers are usually managed remotely through a command-line interface (CLI), a text interface in which the user types commands and the system replies with text. Data on any computer is stored as files, organised into directories (folders) that form a tree; the location of a file in that tree is its path.

In simple words

A server is a computer whose job is to serve other computers, all day and all night. Nobody sits in front of it; you talk to it by typing commands. Everything on it, including programs, settings and logs, is a file inside some folder, and every file has an address called its path.

A computer, its files and servers at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a computer is a person at a desk

A computer is a machine that follows instructions. Picture a person working at a desk:

  • The brain (CPU) does the thinking and the work.
  • The desk (RAM) holds whatever is being worked on right now. When the power goes, the desk is cleared.
  • The cupboard (disk) keeps everything safely, even when the power is off. Each thing in it is in a labelled box: a file. Boxes sit on shelves: folders.
  • A server is simply a computer whose whole job is to help other computers, all day and all night, like the kitchen behind a big restaurant serving thousands of orders.

Basic A kitchen

  • The CPU is the cook: it does the actual work, one small step at a time, very fast.
  • RAM (memory) is the kitchen counter: whatever the cook is working on right now sits here. It is fast but small, and it is wiped clean when the power goes.
  • The disk (SSD/HDD) is the store room: big, slower, and things stay there after power-off. Your files live here.
  • A file is a labelled container in the store room (notes.txt). A folder (Linux says directory) is a shelf that holds files and other shelves.
  • The operating system is the kitchen manager: it decides which order the cook works on, where things are kept and who may open which box.

Intermediate Files, folders, paths, clients and servers

  • Folders form a tree. The full address of a file is its path: on Windows C:\Users\Riya\notes.txt, on Linux /home/riya/notes.txt. Linux uses forward slashes / and has one tree that starts at /.
  • Linux names are case-sensitive: Notes.txt and notes.txt are two different files. Spaces in names are allowed but make typing harder, so people use daily_report.txt.
  • A file is just bytes. A text file holds readable characters (configs, logs, scripts, CSV). A binary file holds bytes meant for programs (images, videos, programs). On Linux the extension (.txt) is only a hint for humans.
  • A client asks for something; a server provides it. Your UPI app is a client; the bank’s computers that move the money are servers. The same machine can be both.

Advanced What a server really is, and why it runs Linux

  • “Server” describes a role, not special hardware: a computer that runs services continuously and answers requests over the network. Data-centre servers are built for it (redundant power, ECC memory, remote management) and usually run headless (no monitor).
  • Most servers today are virtual machines or containers sharing big physical machines, rented from clouds such as AWS, Azure or Google Cloud.
  • Admins reach them with SSH, an encrypted remote terminal (Lesson 15.6). One person can manage hundreds of servers because commands can be scripted and repeated exactly, which clicks cannot.
  • Why Linux: free to run on thousands of machines, stable for years without reboots, every setting is a text file, and the whole cloud, container and big-data ecosystem (Docker, Kubernetes, Hadoop, Spark) is built on it.

Did you know? “Server” is a job, not a kind of machine. The moment your laptop shares a folder or runs python3 -m http.server, it is a server for anyone who connects to it.

Exam tip: For “What is a server? Differentiate client and server” write: definition (computer providing services over a network), one example pair (browser → web server, UPI app → bank server), three properties of servers (always on, many simultaneous clients, managed remotely) and one line on why servers mostly run Linux (stable, free, scriptable).

Quick check You switch off your laptop in the middle of writing an unsaved document. Which part lost the document: the disk or RAM? Why?
Answer: RAM. Unsaved work lives only in RAM (the desk), which is cleared when the power goes. Saving copies it to the disk (the cupboard), which keeps it.

5 See it happen

What happens when you type one command

Left: what Riya sees. Right: the six layers that work together, in order. Every later module zooms into one of these layers.

One command, six layers 5 steps
What you see
  1. The terminal shows a prompt. Nothing happens until you type.
  2. Riya types cat notes.txt (cat = “show the contents”) and presses Enter.
  3. For a tiny moment nothing visible happens. A lot is happening behind.
  4. The text of the file appears in the terminal.
  5. The command has finished and the prompt returns. Total time: a few milliseconds.
Behind the screen
  1. Every key press travels from the keyboard to the terminal app, and the terminal hands the finished line to the shell.
  2. The shell reads the line and splits it into words: the first word is the command, the rest are its arguments.
  3. The shell looks for a program called cat in its list of folders (PATH), finds /usr/bin/cat and starts it. A running program is called a process.
  4. Programs never touch the disk directly. cat asks the kernel, the core of Linux, to open and read the file. The kernel finds it on the disk and copies the bytes into memory.
  5. cat writes those bytes to its output, which is connected to the terminal. Then cat exits and the shell is ready again. You will meet every one of these layers in this course.

Layer by layer: dissect cat notes.txt

The animation showed six layers working together. Now open each one: why it exists, how it works, where it really lives on a Linux machine, and where you will meet it at work. Where possible, run a command that shows that layer for real.

Top = what you touch · bottom = the hardware. Click a layer.

You keyboard and eyes

Why does it exist?

A computer only does what it is told. Someone has to decide the command: you, or a script you wrote.

How does it work?

You type a line of text and press Enter. Nothing happens until Enter.

Where is it, really?

Your fingers and the keyboard. The keyboard sends key codes to the computer over USB or Bluetooth.

Where is it used?

Every job that touches Linux: developers, testers, data engineers, DevOps, support.

Terminal the window

Why does it exist?

You need somewhere to type and read text. The terminal is that window; it does not understand commands itself.

How does it work?

It draws the characters you type and passes them to the shell through a pseudo-terminal device; it draws whatever text comes back.

Where is it, really?

An app: GNOME Terminal, Windows Terminal (for WSL), macOS Terminal, or a web terminal. The connection is a device such as /dev/pts/0.

Where is it used?

On every laptop that manages servers; through SSH the same terminal controls a machine far away.

Shell (bash) understands your command

Why does it exist?

Someone must read “cat notes.txt” and know that cat is a program and notes.txt its input.

How does it work?

bash splits the line into words, finds the program in the folders listed in PATH, starts it and waits for it to finish.

Where is it, really?

A program file, /usr/bin/bash (about 1.4 MB on Ubuntu 24.04). It is just a program, which is why you can swap it for zsh or fish.

Where is it used?

Interactive work and almost every automation script (Module 12 and the Shell Scripting course).

See this layer yourself (real output)

ps -p $$ -o comm=
bash

Program: cat does the actual job

Why does it exist?

The shell does not read files itself. Each job is done by a small, specialised program.

How does it work?

cat opens the file, reads its bytes and writes them to its output, which is connected to your terminal.

Where is it, really?

A program file from GNU coreutils: /usr/bin/cat, about 39 KB.

Where is it used?

Everywhere: viewing configs and logs, joining files, feeding data into pipelines.

See this layer yourself (real output)

type cat; ls -l /usr/bin/cat
cat is /usr/bin/cat -rwxr-xr-x 1 root root 39384 Aug 25 20:39 /usr/bin/cat

Kernel (Linux) the boss of the hardware

Why does it exist?

Programs must not touch the disk directly, or they could read each other’s files or crash the machine. One trusted program controls the hardware: the kernel.

How does it work?

cat asks the kernel “open notes.txt, read it” through system calls. The kernel checks permissions, finds the file and copies the bytes to cat.

Where is it, really?

The file /boot/vmlinuz-…, loaded into RAM at start-up. It is the “Linux” in “Linux”.

Where is it used?

Under every Linux server, Android phone, router and supercomputer (Lesson 1.2).

See this layer yourself (real output)

uname -sr
Linux 6.18.44-fc-v236

Disk where the file really is

Why does it exist?

RAM forgets everything at power-off. Files must be kept on a device that remembers.

How does it work?

The file’s bytes sit in blocks on the SSD. A record called an inode says where those blocks are; the name notes.txt points to that inode.

Where is it, really?

An SSD or hard disk (often a virtual disk in the cloud), formatted with a file system such as ext4.

Where is it used?

Every saved file, database and log. Running out of disk space is one of the most common server problems.

See this layer yourself (real output)

stat -c "%n: %s bytes, inode %i" notes.txt
notes.txt: 13 bytes, inode 795134
Quick check When you run cat notes.txt, which layer is the only one allowed to read the disk directly?
Answer: The kernel. cat and bash are ordinary programs; they must ask the kernel through system calls.

One-liner corner

Short commands you can already understand after this lesson. Each was really run in a fresh Linux folder; the output shown is the real output. You will learn every command properly in later modules.

Beginner

Who am I and where am I?

Scenario: You have just logged in to a machine and want to confirm which user you are and which folder you are in, in one go.

echo "I am $(whoami), working in $(pwd)"
I am riya, working in /home/riya/lab

$( … ) runs a command and puts its answer inside the sentence. whoami prints your user name, pwd the current folder (Lesson 2.2).

Beginner

How many things are in this folder?

Scenario: A colleague asks how many files are in the reports folder. Counting by eye is slow and error-prone.

Sample files used: a folder reports/ with 5 files.

ls reports | wc -l
5

ls lists the names, one per line when its output goes to another program; | (a pipe) hands that list to wc -l, which counts lines.

Intermediate

Create a whole project structure in one line

Scenario: First day of the internship: you want folders for logs, scripts and notes, without typing mkdir five times.

mkdir -p internship/{logs,scripts,notes} && ls internship
logs notes scripts

{logs,scripts,notes} expands into three names (brace expansion, Lesson 3.4). -p creates parent folders as needed. && runs ls only if mkdir succeeded.

Advanced

Which file is taking the most space?

Scenario: Your laptop says the disk is almost full. Find the biggest files in a folder, largest first.

Sample files used: a downloads/ folder with 4 files of different sizes.

ls -S downloads | head -2
setup.iso movie.mp4

ls -S sorts by size, largest first; head -2 keeps only the first two lines. Module 13 shows the du | sort version for whole folder trees.

Beginner

Build it step by step: how many CSV reports are there?

Scenario: Neha asks: “How many CSV reports do we have, and which ones?” Build the answer one small step at a time, checking the output after every step. This is how professionals write long commands.

  1. Start by just looking: what is in the folder?

    ls reports
    feb.csv jan.csv mar.csv notes.txt summary.pdf

  2. Count everything: | sends the list to wc -l, which counts lines. 5, but that includes non-CSV files.

    ls reports | wc -l
    5

  3. Narrow down with a wildcard: only names ending in .csv.

    ls reports/*.csv
    reports/feb.csv reports/jan.csv reports/mar.csv

  4. Combine and label it: a finished one-line answer you can paste into a chat or a script.

    echo "CSV reports: $(ls reports/*.csv | wc -l)"
    CSV reports: 3

Quick revision

Lesson 1.1 in one screen

  • CPU runs instructions, RAM holds running programs (temporary), disk stores files (permanent).
  • A file is named data; a directory (folder) holds files and directories; together they form a tree.
  • A path is a file’s address. Linux: /home/riya/notes.txt, forward slashes, one tree starting at /.
  • Linux names are case-sensitive; extensions are only hints.
  • A client asks, a server serves. Server is a role, not a machine type. Most servers are headless and many are virtual.
  • Servers are managed with a CLI over SSH: light, precise, scriptable.
  • Four ways to talk to a computer: GUI, CLI, TUI, scripts/APIs.
  • Course loop: story → animation → run in browser → run on PC → trace → test → glossary.

Interview and viva questions

Do I need to know programming before learning Linux?

No. Linux commands are not programming. You will write small shell scripts later (Module 12), but they start from zero. Basic computer use is enough.

Is Linux an operating system or just a kernel?

Strictly, Linux is the kernel, the core program. In everyday speech “Linux” means a whole operating system built on that kernel, like Ubuntu or Red Hat Enterprise Linux. Lesson 1.2 explains the difference.

What is the difference between a client and a server? Give an example.

A client requests a service; a server provides it, usually to many clients at once. Example: a web browser (client) requests a page from a web server; a UPI app (client) sends a payment to a bank’s servers.

Why do most servers run Linux?

It is free to run on any number of machines, very stable, configurable through text files, easy to automate with scripts, and the tools of the cloud, containers and big data are built for it.

What is a headless server?

A server with no monitor, keyboard or mouse. It is managed remotely over the network, usually with SSH and the command line.

Is the command line harder than a GUI?

Only for the first week. After that it is usually faster, and it can do things a GUI cannot: repeat steps exactly, work over slow links and run unattended as scripts.

User and folder in one line

(nothing)

How it works: Two command substitutions inside one echo. Each $( ) is replaced by the command’s output.

Count lines in a to-do list

P7Business problem

Canteen menu: how many items?

The college canteen menu is a text file with one item per line. Print how many items are on the menu and show the last two items added.

samosa 15

idli 30

Real-world scenario questions (asked in company interviews)

Fresher-level questions that interviewers ask to check you understand where Linux fits, before any commands.

IT services · fresherFresher

“Why do companies run servers on Linux?”

In an HR + technical round you are asked why your project should be deployed on Linux and not on Windows desktops.

The interviewer is checking: do you understand servers, cost and automation, not just “Linux is free”?

Show a strong answer
  • Servers are long-running, headless machines; Linux is stable for months without reboots and needs fewer resources because it does not need a desktop.
  • No licence cost per machine, which matters when you run tens or hundreds of servers.
  • Everything is configurable through text files and commands, so setups can be scripted and repeated exactly (automation, DevOps, cloud).
  • The tools we deploy with (Docker, Kubernetes, web servers, databases, Hadoop/Spark) are built for and tested mainly on Linux.

Avoid: saying only “because it is free” or “because it is more secure” without explaining.

Product company · fresherFresher

Client and server in a real app

The interviewer says: “Explain what happens, in terms of client and server, when you book a cab in an app.”

The interviewer is checking: can you identify clients, servers and the network in a familiar system?

Show a strong answer
  1. The phone app is the client: it sends my location and request over the internet.
  2. The company’s servers (in a data centre or cloud) receive it, find nearby drivers from a database, and send offers to drivers’ phones (also clients).
  3. When a driver accepts, the server updates the database and notifies my app.
  4. The servers run continuously and serve many thousands of clients at the same time.

Avoid: describing only the screens of the app.

Any company · first weekIntern

“SSH into the server and check the log”

Your lead asks you to check a log on a Linux server. You have never used a terminal. What do you do?

The interviewer is checking: are you honest, safe and resourceful?

Show a strong answer
  • Ask for the exact server name, my user name and how access works (password or SSH key), and which log file to check.
  • Connect with ssh user@server, confirm with whoami and pwd, and only read the log with less or tail. Never run delete or restart commands I do not understand.
  • Copy the relevant error lines and the time into my reply.

Avoid: pretending to know, or trying random commands from the internet on a company server.

Operations · scenarioFresher

GUI or CLI for 50 servers?

Your company has 50 Linux servers and needs the same setting changed on all of them. A teammate wants to log into each one with a remote desktop.

The interviewer is checking: do you see why the command line scales?

Show a strong answer
  • Clicking through 50 desktops is slow and someone will miss a step on one server.
  • Write the change once as commands, test on one server, then run the same commands on all 50 (with a loop over SSH, or a tool such as Ansible).
  • The script also documents exactly what was changed, which helps reviews and rollbacks.

Avoid: “GUI is easier, so let us just do it manually.”
