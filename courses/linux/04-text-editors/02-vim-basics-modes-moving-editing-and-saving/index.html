2 Definition

vi, vim and modes

Formal definition (write this in exams)

vi is the standard screen editor of Unix, required by POSIX; vim (Vi IMproved) is the enhanced version used on Linux. It is a modal editor: in Normal mode keys are commands (move, delete, copy), in Insert mode keys insert text, in Command-line mode (after :) you type ex commands such as :w and :q, and in Visual mode you select text. Esc returns to Normal mode.

In simple words

Normal mode = commands, Insert mode (i) = typing, Esc = back, :wq = save and quit.

vim at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a car with gears

vim is like a car gearbox: the same pedal does different things in different gears.

  • Normal mode is “neutral”: keys give orders (move, delete, copy). vim starts here.
  • Insert mode is “drive”: keys type letters. Enter it with i.
  • Esc always brings you back to neutral. When lost: Esc, Esc, then decide.

Basic The keys you will use every day

  • vim file opens; i insert, type, Esc; :wq Enter saves and quits; :q! quits without saving.
  • Move: h left, j down, k up, l right (arrows also work).
  • x deletes a character, dd a line, yy copies a line, p pastes below.
  • u undo, Ctrl+R redo.
  • /word Enter searches, n next match.

Intermediate Faster: words, counts and combinations

  • Enter Insert mode in the right place: i before the cursor, a after, I line start, A line end, o / O new line below / above.
  • Move by word w b e, line start/end 0 $, file gg G, line number :42 or 42G.
  • Counts: 3dd deletes 3 lines, 5j moves 5 down.
  • Operator + motion: d, c, y combine with motions: dw delete word, cw change word, d$ to line end, y + motion copies. r replaces one character.
  • . repeats the last change (more in 4.3).

Advanced Behind the screen: vi, vim, buffers and swap files

  • On Ubuntu, vi starts vim (often “vim.tiny” on minimal installs, with fewer features); RHEL ships vi (vim-minimal) and vim (vim-enhanced). :version shows which.
  • vim edits a buffer; :w writes it. While editing it keeps a swap file .file.swp for crash recovery; if vim or SSH dies, the next open offers to recover.
  • :wq always writes; ZZ and :x write only if changed (keep the file date when nothing changed).
  • The command-line mode is the old ex editor: :s, :g, :w, ranges. vi was built on top of ex (1976).
  • vim -u NONE starts without settings; :set nocompatible gives vim (not vi) behaviour; settings go in ~/.vimrc (Lesson 4.3).

Did you know? The keys h, j, k and l move the cursor because Bill Joy wrote vi in 1976 on a Lear Siegler ADM-3A terminal, which had no separate arrow keys: the arrows were printed on H, J, K and L. The same keyboard had Esc where Tab is today, which is why vi uses Esc so much.

Common mistake
✗j = up, k = down (as written in some notes)
✓j = down ↓, k = up ↑

Verified by a real run: from line 1, jj then x deletes on line 3; adding k deletes on line 2. Memory trick: j has a tail that hangs down.

Exam tip: “Explain the modes of vi and how to save and quit” → Normal (command) mode, Insert mode (i, a, o; Esc to leave), Command-line mode (:w save, :q quit, :wq save and quit, :q! quit without saving), Visual mode (v); mention dd, yy, p, u and /search.

Quick check You are in Insert mode and want to save and quit. Which keys?
Answer: Esc, then :wq and Enter (or Esc then ZZ).

:w :q :wq :q! ZZ saving and quitting

🟡 Changes filesno sudo

From Normal mode, : opens the command line at the bottom. :w writes, :q quits (refused if unsaved), :wq both, :q! quits and throws changes away. ZZ = save if changed and quit.

✓ Use it when
  • every session: save, quit, or both
  • escaping when something went wrong (:q!)
  • saving under another name (:w newname)
✗ Don’t use it when
  • you are in Insert mode (press Esc first, or you will type “:wq”)

Syntax: :w [name] · :q · :wq · :q! · ZZ · ZQ

OptionWhat it doesWhen to use it
:wwrite (save)save often
:w newnamesave a copy under another namekeep the original
:qquit (only if saved)leave
:wq / :x / ZZsave and quit (:x and ZZ only write if changed)normal end
:q! / ZQquit without savingabandon changes
:wq!force write (e.g. read-only file you own)rare
:e!reload the file, discard changesstart again

Undo and safety net

If something went wrong in vim…

  • Keys did strange things: Esc (twice), then u as many times as needed.
  • Want to leave without saving: Esc, :q! Enter. The file on disk is unchanged.
  • Want to start the edit again: :e! reloads the file from disk.
  • Saved by mistake: undo still works while vim is open (u, then :w); after closing, use your backup (Lesson 3.2) or git.
  • Terminal looks frozen: you may have pressed Ctrl+S (pauses output): press Ctrl+Q. Ctrl+Z suspended vim: type fg.

Error messages decoded

Messages students see in vim. The E37 screen above is real; these are produced by real runs too.

  1. printf 'a\n' > f.txt; vim -u NONE -N -i NONE -es -c 'normal x' -c 'q' f.txt; echo "vim exit status: $?"
    vim exit status: 1 exit status: 0

    What it means: E37 “No write since last change”: you tried :q with unsaved changes (here vim in batch mode exits with an error).

    Fix: :wq to save, or :q! to discard.

E212: Can’t open file for writing (typical): you saved into a folder you may not change, such as /etc. Save elsewhere with :w ~/copy.conf, and open root files with sudoedit.

E325 ATTENTION – Found a swap file (typical): vim found .app.conf.swp because the file is open elsewhere or vim crashed. Press R to recover, E to edit anyway, Q to quit; delete the old swap file afterwards if you recovered.

Why does it exist?

vim reads raw keys, not lines.

How does it work?

Esc is byte 27; “:” starts the command line.

Where is it, really?

Terminal in raw mode.

Where is it used?

All full-screen programs.

See this layer yourself (real output)

printf '\x1b:wq\r' | od -An -c
033 : w q \r

Command line the ex editor inside vim

Why does it exist?

Commands like :w :q :s :g come from ex (1976).

How does it work?

vim parses the line after : as an ex command.

Where is it, really?

vim’s ex command parser.

Where is it used?

ex scripts, sed’s syntax.

See this layer yourself (real output)

printf 'line 1\nline 2\n' > n.txt; ex -s -c '1d' -c 'wq' n.txt; cat n.txt
line 2

:w write the buffer

Why does it exist?

The disk changes only when you write.

How does it work?

vim writes the buffer (by default via a new file and rename, keeping permissions), and a backup if set.

Where is it, really?

writefile() in vim.

Where is it used?

:w, :wq, ZZ.

See this layer yourself (real output)

printf 'port=80\nhost=localhost\nuser=admin\n' > app.conf; vim -u NONE -N -i NONE -es -c '1d' -c 'wq' app.conf; cat app.conf
host=localhost user=admin

Swap file crash safety

Why does it exist?

SSH can drop while you edit.

How does it work?

While a file is open vim keeps .name.swp; it is removed on a clean exit.

Where is it, really?

Swap/recovery files.

Where is it used?

vim -r file to recover.

Script it: quick-fix.sh

The same kind of edit you would do in vim, done with vim itself in batch mode: open, change, save. Useful in scripts and Dockerfiles where nobody can type.

#!/bin/bash
f=${1:-app.conf}
printf 'port=80\nhost=localhost\nuser=admin\n' > "$f"   # demo file
cp "$f" "$f.bak"
vim -u NONE -N -i NONE -es \
  -c '%s/^port=.*/port=8080/' \
  -c 'g/^user=/d' \
  -c 'wq' "$f"
diff "$f.bak" "$f" || true
1c1 < port=80 --- > port=8080 3d2 < user=admin

%s and g are covered in Lesson 4.3; in scripts, sed (Lesson 6.4) is the more common choice.

Puzzle answer Remember the question from the story? Open to check your guess.

In Normal mode, c is “change” and waits for a motion, h moves left (so ch changed the character to the left and entered Insert mode), and the remaining letters “ange” were then typed as text. So the first two letters were commands, and c + h together switched to Insert mode. A real run with the cursor at the start of port=80 turned the line into angeport=80 (nothing to the left to change, but Insert mode started anyway). Fix: Esc, u to undo, then i before typing.

Quick check You are in Normal mode on line 1 of a 100-line file. How do you go to the last line, and back?
Answer: G, then gg.

Interview and viva questions

How do I exit vim?

Press Esc, then type :q and Enter (or :q! to discard changes, :wq to save and quit).

Why can I not type in vi?

vi starts in Normal mode where keys are commands. Press i to enter Insert mode.

What is the difference between vi and vim?

vim (Vi IMproved) is an extended vi with undo history, syntax colours, visual mode and much more; on Linux, vi usually starts vim.

How do I delete a line in vim?

dd in Normal mode; 3dd deletes three lines.

How do I copy and paste in vim?

yy copies a line, p pastes below (P above). With a selection: v, move, y, then p.

How do I go to a line number?

:42 Enter, or 42G, or open with vim +42 file.

What is a .swp file?

vim’s swap file for crash recovery; it appears while a file is open and is removed on a clean exit.

Real-world scenario questions (asked in company interviews)

Interview questions about vi and vim, from fresher to senior rounds.

Any company · basicsFresher

“How do you exit vi?”

The famous question, sometimes as a joke, often as a real test.

The interviewer is checking: do you understand modes?

Show a strong answer
  • Esc to be sure you are in Normal mode.
  • :wq save and quit, :q! quit without saving, ZZ save if changed.
  • Explain why: typed keys are commands in Normal mode.

Avoid: closing the terminal window.

OperationsJunior

Swap file warning on a production config

Opening /etc/nginx/nginx.conf shows “E325 ATTENTION Found a swap file”.

The interviewer is checking: do you know swap files?

Show a strong answer
  1. Someone may be editing it now, or vim crashed earlier: check with ps aux | grep vim and who.
  2. If nobody is editing: R to recover and compare, or delete the stale .nginx.conf.swp.
  3. Never edit the same config from two sessions.

Avoid: pressing E and overwriting a colleague’s edit.

CertificationMid-level

“Edit /etc/fstab during the exam”

RHCSA-style tasks need quick, exact edits.

The interviewer is checking: are you fluent with vim keys?

Show a strong answer
  • sudo vim /etc/fstab (exam context), G o to add a line, Esc, :wq.
  • Use :set number, /UUID to find lines, yy p to copy a similar line and edit it.
  • Validate (mount -a) before rebooting.

Avoid: a typo that stops the system from booting.
