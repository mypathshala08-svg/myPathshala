tmux and screen: terminal sessions that survive logout

Keep your terminal on the server: start work in tmux, detach, lose the connection, and attach again from anywhere. Sessions, windows, panes, the key bindings and scripting, on real screens.

The problem

Riya is restoring a 200 GB database over SSH from a café. The Wi-Fi drops after 20 minutes. With nohup (Lesson 11.4) the restore would survive, but she could not see its progress or answer its “Continue? [y/N]” question. A terminal multiplexer solves this: tmux (or the older screen) runs your shells inside a session on the server. You can detach from it, lose the connection, log in again from another computer and attach to find everything exactly as you left it, still running. tmux also gives you several windows and split panes in one terminal. This lesson shows real tmux screens step by step.

By the end of this page you will be able to:
  • explain sessions, windows and panes, and why tmux sessions survive a dropped connection
  • create, detach, list, attach and kill sessions (tmux new -s, Ctrl+b d, tmux ls, tmux attach -t)
  • work with windows and split panes, and use the most important Ctrl+b keys
  • script tmux (send-keys, capture-pane), know the screen equivalents, and pick tmux vs nohup vs systemd

2 Definition

Terminal multiplexers: tmux and screen

Formal definition (write this in exams)

A terminal multiplexer runs several terminal sessions inside one terminal and keeps them on the server independent of your connection. tmux organises them into sessions, windows and panes; you can detach from a session and attach to it later, even from another computer, while its programs keep running. GNU screen is the older tool with the same idea.

In simple words

A terminal that lives on the server; your connection is only a view onto it.

tmux at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a TV studio

The show keeps running whether you watch or not.

Basic What you will type

  • tmux new -s work: start a named session.
  • Ctrl+b then d: detach (leave it running).
  • tmux ls: list sessions.
  • tmux attach -t work (or tmux a): go back in.

Intermediate Windows, panes and the prefix

  • Every tmux key starts with the prefix Ctrl+b, released, then one key.
  • A session has windows (like tabs: c new, n/p next/previous, 0–9), and a window can be split into panes (% side by side, " one above the other, arrows to move, x close).
  • [ enters copy mode to scroll back (q to leave); ? lists all keys.
  • exit in the last shell ends the session; detaching does not.
  • Settings go in ~/.tmux.conf (mouse on, prefix Ctrl+a, history size).

Advanced Behind the screen: server, clients and sockets

  • The first tmux command starts a server process that daemonises (it is not in your SSH session, so it gets no SIGHUP).
  • Clients talk to it through a Unix socket in /tmp/tmux-UID/default (-L name chooses another socket, -S path a full path).
  • Each pane is a pseudo-terminal (/dev/pts/N) owned by the server; the shell inside thinks it has a real terminal.
  • Inside tmux, $TMUX is set (socket,pid,session); tmux refuses to nest unless you unset it.
  • If systemd-logind kills user processes at logout (KillUserProcesses=yes), the server dies too; then run it with systemd-run --user --scope tmux or enable lingering.
  • Rebooting the machine ends all sessions; plugins (tmux-resurrect) can save layouts but not running programs.

Did you know? Ubuntu Server ships with tmux and screen-style byobu preinstalled on many cloud images, precisely because so much admin work happens over SSH connections that can drop.

Exam tip: “How do you keep a process running after closing SSH, and still interact with it?” → Run it in tmux or screen, detach (Ctrl+b d), and reattach later with tmux attach.

Quick check You typed exit in the only shell of a tmux session. What happened to the session?
Answer: It ended: a session lives as long as it has at least one shell (pane). Detach with Ctrl+b d instead.

tmux new -s · Ctrl+b d · tmux ls · tmux a -t · kill-session sessions

🟡 Changes filesno sudo

tmux new -s NAME creates a session; -d creates it detached, optionally with a command. tmux ls lists sessions, tmux a -t NAME attaches (tmux a = the most recent), tmux kill-session -t NAME ends one, tmux kill-server ends all. tmux has -t NAME tests whether it exists (for scripts).

✓ Use it when
  • long installs, restores, migrations over SSH
  • anything you want to come back to
✗ Don’t use it when
  • permanent services (use systemd)
  • nesting tmux inside tmux

Syntax: tmux new -s NAME · tmux a -t NAME · tmux new -A -s NAME

tmuxthe clientnewcommand: new-session-s worksession name

tmux COMMAND OPTIONS. Short forms: new, ls, a, kill-ses.

tmux new -A -s nattach if it exists, else createone habit

Undo and safety net

Detaching is harmless; killing a session ends its programs.

  • Lost which session is which: tmux ls; rename with Ctrl+b $.
  • Accidentally typed exit in the last pane: the session is gone; start again (next time detach).
  • Screen messed up after a resize: Ctrl+b : refresh-client, or detach and attach.
  • Stuck in copy mode or a prompt: press q or Esc.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. tmux attach -t nosuch
    no sessions exit status: 1

    What it means: No session with that name.

    Fix: tmux ls.

  2. tmux ls
    no server running on /tmp/tmux-1000/default exit status: 1

    What it means: No server: no sessions at all.

    Fix: tmux new -s NAME.

  3. tmux new -d -s a
    duplicate session: a exit status: 1

    What it means: The name is taken.

    Fix: Another name, or tmux new -A -s a.

  4. tmux attach
    no sessions exit status: 1

    What it means: Nothing to attach to.

    Fix: Create a session first.

6 Real-world use

tmux at work

1. Long database work

DBAs run restores, migrations and index builds inside tmux; if the VPN drops, the work continues and they reattach.

Start in tmux→detach→reattach later

2. Incident response

On-call engineers split one window: logs on the left, top on the right, a shell below.

Alert→split panes→see everything

3. Pair work and teaching

Two people attach to the same session and see the same screen, useful for mentoring and live debugging.

Session→two clients→same view

4. Automation

Scripts start interactive tools in detached sessions, send keys and capture output (test harnesses, lab recorders like this course).

Script→send-keys→capture-pane

5. Cloud servers

Cloud images ship tmux/byobu; many teams start every SSH session with tmux new -A -s main.

ssh→tmux new -A→never lose work

Sessions

V1

Create only if missing (for scripts)

V2

Script it: workspace.sh

Create (or reuse) a tmux workspace named after the argument with three windows: shell, logs (a tail of a log file) and monitor (split into two panes), then print a summary and how to attach.

name=${1:-ops}
log=~/tm/app.log; mkdir -p ~/tm; echo "app started" > "$log"
if ! tmux has -t "$name" 2>/dev/null; then
  tmux new -d -s "$name" -n shell -x 120 -y 30
  tmux new-window -t "$name" -n logs "tail -f $log"
  tmux new-window -t "$name" -n monitor 'top'
  tmux split-window -v -t "$name:monitor" 'sleep 3600'
fi
tmux list-windows -t "$name" -F '#{window_index} #{window_name}: #{window_panes} pane(s)'
echo "attach with: tmux attach -t $name"
tmux kill-server   # cleanup for this demo
0 shell: 1 pane(s) 1 logs: 1 pane(s) 2 monitor: 2 pane(s) attach with: tmux attach -t ops

Run without a name, so it builds the ops workspace.

Quick revision

Lesson 11.6 in one screen

  • tmux server → sessions → windows → panes; your terminal is a client.
  • tmux new -s NAME, Ctrl+b d, tmux ls, tmux a -t NAME, tmux new -A -s NAME, tmux kill-session -t NAME.
  • Ctrl+b c new window, n/p/0-9 move, % and " split, arrows move, z zoom, x close, [ scroll, ? help.
  • exit in the last pane ends the session; detaching does not.
  • Scripting: new -d "cmd", send-keys … Enter, capture-pane -p, pipe-pane, has -t, display -p "#{…}".
  • screen: screen -S, Ctrl+a d, screen -ls, screen -r. Survives logout, not reboot.

Interview and viva questions

What is tmux used for?

Running terminal sessions on a server that survive disconnection, with windows and split panes.

How do I detach and reattach in tmux?

Ctrl+b then d to detach; tmux attach -t NAME (or tmux a) to reattach.

How do I list tmux sessions?

tmux ls.

What is the difference between tmux and screen?

Same idea; tmux is newer with panes, scripting and easier configuration; screen is older and often preinstalled.

How do I scroll in tmux?

Ctrl+b [ for copy mode, then arrows/PgUp; q to exit. Or set -g mouse on.

Does tmux survive a reboot?

No. Sessions live in memory; use systemd for services.

tmux vs nohup?

nohup survives logout but you cannot interact; tmux lets you reattach and type.
