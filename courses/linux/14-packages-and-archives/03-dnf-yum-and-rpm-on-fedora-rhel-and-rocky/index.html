2 Definition

rpm, dnf and yum

Formal definition (write this in exams)

rpm is the low-level package tool of the Red Hat family: it installs, removes, queries and verifies individual .rpm files and keeps the RPM database. dnf (Dandified YUM) is the high-level package manager on Fedora, RHEL 8+ and its rebuilds (Rocky, AlmaLinux): it reads repositories from /etc/yum.repos.d/, resolves dependencies, and records every change as an undoable transaction. yum is its predecessor; on current systems the yum command runs dnf.

In simple words

rpm is dpkg, dnf is apt, yum is the old name of dnf.

dnf and rpm at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: two families, same jobs

Every tool has a twin.

Basic What you will type

  • sudo dnf install nginx, sudo dnf remove nginx.
  • sudo dnf upgrade (yum update on CentOS 7).
  • dnf search editor, dnf info nginx.
  • rpm -qa | grep nginx: is it installed?

Intermediate The differences that matter

  • No separate “update” step: dnf refreshes metadata when it is older than the cache expiry (dnf makecache forces it).
  • dnf remove also removes now-unneeded dependencies (clean_requirements_on_remove); there is no purge: changed config files are saved as .rpmsave.
  • Every change is a numbered transaction: dnf history, dnf history info N, sudo dnf history undo N.
  • Groups install sets of packages: dnf group install "Development Tools".
  • Extra repositories: EPEL (community extras), CRB (CodeReady Builder, build dependencies), enabled with dnf config-manager --set-enabled crb.

Advanced Behind the screen: RPM database, versions and modules

  • The RPM database lives in /var/lib/rpm (SQLite since RHEL 9). rpm -V checks size, mode, checksum, owner of every file: S.5....T. c /etc/nginx/nginx.conf means size, MD5 and time changed, and it is a config file.
  • Version strings are [epoch:]version-release.dist.arch; the epoch (1:) forces ordering when upstream numbering went backwards.
  • dnf is written in Python on libsolv (the same solver family as openSUSE’s zypper); dnf5 (C++) replaces it in newer Fedora.
  • yum on RHEL 8/9 is a symlink to dnf; real yum (Python 2) only on CentOS 7 and older.
  • AppStream “modules” (RHEL 8) offered several versions of one package (e.g. nodejs:18, nodejs:20) via dnf module enable; RHEL 9 uses mostly normal packages again.

Did you know? dnf check-update returns exit code 100 when updates are available, 0 when there are none and 1 on error: made for scripts and monitoring checks.

Exam tip: “What is the difference between rpm and dnf?” → rpm installs and queries single package files without resolving dependencies; dnf uses repositories, resolves dependencies, and keeps an undoable transaction history.

Quick check Where would you look to see which repositories a Rocky server uses?
Answer: /etc/yum.repos.d/*.repo, or dnf repolist.
Common mistake
✗sudo rpm -ivh package.rpm for a package with dependencies
✓sudo dnf install ./package.rpm (dnf fetches the dependencies)

rpm fails with “Failed dependencies: … is needed by …”, the same problem as dpkg -i.

Common mistake
✗turning gpgcheck=0 to make an install “work”
✓import the vendor’s key (rpm --import KEY) or fix the repo’s gpgkey= line

Without signature checks a tampered package would install silently.

dnf check-update · upgrade · install · remove · history · undo dnf in daily use

🟡 Changes filesno sudo

dnf check-update lists available updates (exit 100 if any). sudo dnf upgrade installs them; --security only security fixes. dnf install/remove work like apt. Every run becomes a transaction: dnf history, dnf history info N, sudo dnf history undo N or rollback N.

✓ Use it when
  • patching Red Hat servers
  • rolling back a bad change
✗ Don’t use it when
  • dnf upgrade on production without check-update and history

Undo and safety net

dnf is the friendliest here: almost every change has an undo.

  • Bad upgrade: sudo dnf history undo N (or rollback N to go back to that point).
  • Removed something needed: sudo dnf history undo LAST, or install it again.
  • Edited config replaced: your version is saved as .rpmsave; a new default as .rpmnew.
  • Repo breaks dnf: disable it: sudo dnf config-manager --set-disabled ID or --disablerepo=ID.

6 Real-world use

dnf and rpm at work

1. Enterprise servers

Banks, telecoms and governments run RHEL or Rocky for long support (10 years); patching is dnf upgrade in windows, tracked in dnf history.

Window→dnf upgrade→history

2. Fast rollbacks

dnf history undo turns a bad patch night into a five-minute rollback.

Bad patch→history undo→back

3. Extra tools

htop, ncdu, jq on RHEL usually come from EPEL; CRB provides -devel packages for building software.

Need htop→EPEL→installed

4. Cross-distro automation

Ansible’s package module and shell scripts check os-release and call apt or dnf as needed.

os-release→detect→apt or dnf

5. Compliance audits

rpm -Va lists every changed packaged file; auditors review unexpected changes outside /etc.

rpm -Va→review→report

Translating

V1

apt → dnf translator

tr(){ case "$1" in update) echo 'dnf makecache';; upgrade) echo 'dnf upgrade';; install) echo 'dnf install';; remove|purge) echo 'dnf remove';; autoremove) echo 'dnf autoremove';; search) echo 'dnf search';; show) echo 'dnf info';; *) echo '?';; esac; }; for c in update upgrade purge show; do printf 'apt %-8s -> %s\n' $c "$(tr $c)"; done
apt update -> dnf makecache apt upgrade -> dnf upgrade apt purge -> dnf remove apt show -> dnf info

for p in '-S:-qf' '-L:-ql' '-l:-qa' '-s:-qi' '--verify:-V'; do printf 'dpkg %-9s = rpm %s\n' "${p%%:*}" "${p#*:}"; done

Script it: pkgfamily.sh

Detect the package family of the machine and print the right commands for refresh, upgrade, install, owner-of-file and history, so the same runbook works on Ubuntu and Rocky.

. /etc/os-release
case " $ID $ID_LIKE " in
  *" debian "*|*" ubuntu "*) fam=debian ;;
  *" rhel "*|*" fedora "*|*" centos "*) fam=redhat ;;
  *) fam=unknown ;;
esac
echo "machine: $PRETTY_NAME -> family: $fam"
case $fam in
  debian) printf '%s\n' 'refresh:  sudo apt update' 'upgrade:  sudo apt upgrade' 'install:  sudo apt install PKG' 'owner:    dpkg -S FILE' 'history:  less /var/log/apt/history.log' ;;
  redhat) printf '%s\n' 'refresh:  sudo dnf makecache' 'upgrade:  sudo dnf upgrade' 'install:  sudo dnf install PKG' 'owner:    rpm -qf FILE' 'history:  dnf history' ;;
  *) echo "unknown family"; exit 1 ;;
esac
machine: Ubuntu 24.04.5 LTS -> family: debian refresh: sudo apt update upgrade: sudo apt upgrade install: sudo apt install PKG owner: dpkg -S FILE history: less /var/log/apt/history.log

On our Ubuntu build machine it prints the Debian commands.

Puzzle answer Remember the question from the story? Open to check your guess.

1. htop is not in Rocky’s BaseOS/AppStream; it is in EPEL. Enable it with sudo dnf install epel-release (and usually sudo dnf config-manager --set-enabled crb), then sudo dnf install htop. 2. 1: is the epoch: it comes first in comparisons and is added when upstream version numbering would otherwise sort wrongly; rpm -q hides an epoch unless you ask (rpm -q --qf "%{EPOCH}:%{VERSION}-%{RELEASE}\n" nginx). 3. Yes: every dnf run is a numbered transaction; sudo dnf history undo 13 downgrades the 42 packages that transaction 13 upgraded (if the old versions are still available in the repositories or cache).

Reading RPM package names

The browser has no dnf or rpm; this splits real RPM names from the right, the way rpm does, because names may contain dashes.

# Split RPM names the way rpm does: name-version-release.arch
for p in openssl-libs-3.0.7-27.el9.x86_64 nginx-1.20.1-14.el9_2.1.x86_64 tmux-3.2a-5.el9.x86_64; do
  arch=${p##*.}; rest=${p%.*}
  rel=${rest##*-}; rest=${rest%-*}
  ver=${rest##*-}; name=${rest%-*}
  printf '%-13s ver=%-7s rel=%-10s arch=%s\n' "$name" "$ver" "$rel" "$arch"
done
openssl-libs ver=3.0.7 rel=27.el9 arch=x86_64 nginx ver=1.20.1 rel=14.el9_2.1 arch=x86_64 tmux ver=3.2a rel=5.el9 arch=x86_64
  • ${p##*.}Architecture: after the last dot.
  • ${rest%-*}Peel off one -part from the right.

Quick revision

Lesson 14.3 in one screen

  • rpm = dpkg (single files, queries, database); dnf = apt (repos, solver); yum = old name for dnf.
  • dnf install/remove/upgrade/search/info/provides/autoremove; check-update exits 100 if updates exist.
  • rpm -q, -qa, -qi, -ql, -qc, -qf, -qR, -V; -p for a not-installed .rpm.
  • /etc/yum.repos.d/*.repo: [id], baseurl/mirrorlist, enabled, gpgcheck, gpgkey; EPEL and CRB for extras.
  • Every dnf run is a transaction: dnf history, history info N, history undo N / rollback N.
  • Versions: [epoch:]version-release.dist.arch; split names from the right.

Interview and viva questions

What is the difference between yum and dnf?

dnf replaced yum; on RHEL 8+ the yum command runs dnf.

What is the apt update equivalent in dnf?

dnf refreshes automatically; dnf makecache forces it.

How do I find which package owns a file on RHEL?

rpm -qf /path, or dnf provides /path for packages not installed.

How do I undo a dnf install or upgrade?

dnf history to find the ID, then sudo dnf history undo ID.

What is EPEL?

Extra Packages for Enterprise Linux: a community repository of extra software for RHEL-compatible systems.

What does the epoch in an RPM version mean?

A number before the colon that overrides normal version comparison.

How do I list repositories?

dnf repolist (add all to see disabled ones).
