sort, uniq, wc, cut, paste and tr

Six small commands turn a CSV or a log into a report: cut takes a column, sort orders it, uniq counts, wc measures, paste joins and tr changes characters. This lesson explains each one, then shows how every IT role combines them.

2 Definition

sort, uniq, wc, cut, paste and tr

Formal definition (write this in exams)

cut prints selected fields (by delimiter) or character positions of each line. sort orders lines (as text, numbers, sizes or versions, by whole line or by key fields). uniq removes or counts adjacent duplicate lines. wc counts lines, words, bytes and characters. paste merges lines of files side by side. tr translates, deletes or squeezes characters read from standard input.

In simple words

Take a column, put it in order, count the repeats, measure it, glue lists, change characters.

The six tools at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a kitchen

Think of preparing vegetables for a big order.

  • cut is a knife that takes just one column of the table.
  • sort lays everything out in order; uniq -c counts how many of each kind lie next to each other.
  • wc is a ruler; paste tapes two lists side by side; tr repaints characters.

Basic The forms you will type every day

  • cut -d, -f2 file.csv: column 2 of a CSV. cut -d: -f1 /etc/passwd: user names.
  • sort names.txt, sort -n numbers.txt, sort -r, sort -u.
  • sort file | uniq -c | sort -rn: how many of each, biggest first.
  • wc -l file: number of lines.
  • tr a-z A-Z: capitals; tr -d ' ': delete spaces.

Intermediate Columns, keys and traps

  • sort -k5,5nr -t,: sort by field 5 only (,5 ends the key), numeric, reversed. Without ,5 the key runs to the end of the line.
  • Plain sort compares text: 100 comes before 20. Use -n, -h (2G, 500K) or -V (v1.10 after v1.9).
  • uniq only merges adjacent equal lines: always sort first, or use sort -u.
  • cut knows nothing about quotes: "Sharma, Riya" is split at its comma. Use a real CSV tool (csvkit, Python, or awk with care) for quoted CSV.
  • tr reads only stdin and works on single characters, not words: tr 'abc' 'xy' maps a→x, b→y, c→y.

Advanced Behind the screen: locale, memory and stability

  • sort’s order depends on the locale: in C / C.UTF-8 capitals come before small letters (byte order); in en_IN.UTF-8 it is dictionary order (alice before Bob). Scripts often set LC_ALL=C for predictable, faster results.
  • GNU sort handles files larger than memory: it sorts chunks into temporary files (in $TMPDIR) and merges them; -S 2G sets the buffer, --parallel=4 uses more cores.
  • When keys are equal sort compares the whole line as a last resort; -s (stable) keeps the input order instead.
  • wc -c counts bytes, -m counts characters: “héllo” is 7 bytes but 6 characters in UTF-8.
  • uniq -c width, cut delimiters and tr classes like [:upper:] follow POSIX, so they behave the same on every Linux.

Did you know? sort can sort files much bigger than your RAM. When the data does not fit, it sorts it in pieces, writes the sorted pieces to temporary files and then merges them, the same “external merge sort” that big-data systems like Hadoop use for terabytes.

Exam tip: “Find the top 5 most frequent values in column 3 of a comma-separated file.” → cut -d, -f3 file | sort | uniq -c | sort -rn | head -5 (skip a header with tail -n +2; explain why sort comes before uniq).

Quick check Why does sort put 100 before 20?
Answer: Without -n it compares text character by character: “1” comes before “2”. Use sort -n.

4 Step by step

Each tool explained, then used in every field

All outputs were recorded on Ubuntu 24.04 (GNU coreutils 9.4, locale C.UTF-8) with a sample employees.csv: id,name,dept,city,salary for six employees.

cut cut columns

🟢 Read-onlyno sudo

Prints parts of each line: fields separated by one delimiter character (-d + -f), or character/byte positions (-c/-b).

✓ Use it when
  • one or more columns of CSV, /etc/passwd, logs
  • fixed positions: dates, codes, IDs
  • quick extraction before sort, uniq or paste
✗ Don’t use it when
  • CSV with quoted commas (use a CSV tool or Python)
  • columns separated by a varying number of spaces (use awk or tr -s first)

Syntax: cut -d'DELIM' -f LIST [FILE] · cut -c LIST [FILE]

cutcommand-d,delimiter: comma-f2,5fields 2 and 5employees.csvfile

No space is needed after -d and -f; quote special delimiters: -d' ', -d'"'.

cut in system info / admin

  1. Situation: User names and their shells from /etc/passwd.

    cut -d: -f1,7 /etc/passwd | head -4
    root:/bin/bash daemon:/usr/sbin/nologin bin:/usr/sbin/nologin sys:/usr/sbin/nologin

    Why this way: /etc/passwd uses : between its 7 fields.

  2. Situation: The 1-minute load average (from your notes, corrected).

    cut -d' ' -f1 /proc/loadavg | sed 's/[0-9]/9/g'
cut -d' ' -f1 /proc/uptime | sed 's/[0-9]/9/g'
    9.99 999.99

    Why this way: These files are separated by spaces, so -d' ' is needed. (Digits are masked to 9 here because they change every second.)

cut in data analysis / engineering

  1. Situation: The year and month from ISO dates.

    printf '2026-11-06\n2026-10-31\n' | cut -c1-7
    2026-11 2026-10

    Why this way: Fixed-width data: -c by position is simplest.

  2. Situation: Why cut breaks quoted CSV (a real limit).

    echo '7,"Sharma, Riya",Pune' | cut -d, -f2
    "Sharma

    Why this way: cut splits at every comma, even inside quotes. Use python3 -c "import csv…", csvkit or Miller for real CSV.

cut in web servers

  1. Situation: Count requests per HTTP method from an access log.

    cut -d'"' -f2 access.log | cut -d' ' -f1 | sort | uniq -c
    31 GET

    Why this way: Field 2 between the quotes is the request line; its first word is the method.

cut in devops / cloud

  1. Situation: Email domains of a user list.

    printf 'asha@cdac.in\nravi@gmail.com\nmeena@cdac.in\n' > mails.txt
cut -d@ -f2 mails.txt | sort | uniq -c
    2 cdac.in 1 gmail.com

    Why this way: Any single character can be the delimiter.

Common mistake
✗cut -f1 /proc/uptime (“system uptime in seconds”)
✓cut -d' ' -f1 /proc/uptime

cut’s default delimiter is TAB. /proc/uptime has a space, so without -d' ' the whole line is printed (verified).

sort sort lines

🟢 Read-onlyno sudo

Sorts lines. By default compares the whole line as text using the locale. Options choose numeric, human, version or month comparison, keys (columns), reverse order and uniqueness.

✓ Use it when
  • ordering lines: names, numbers, sizes, versions, dates
  • reports by one or more columns
  • preparing input for uniq, comm and join
✗ Don’t use it when
  • data with quoted CSV commas in the key columns
  • when the original order matters (use sort -s, or awk)

Syntax: sort [-n|-h|-V|-g|-M] [-r] [-u] [-f] [-t SEP] [-k F1[,F2][n|r…]] [-o OUT] [FILE…]

OptionWhat it doesWhen to use it
-nnumeric3 20 100
-rreversebiggest first
-uuniqueremove duplicates while sorting
-fignore casenames
-t, -k5,5nby field 5, numericCSV columns
-k3,3 -k5,5nrby dept, then salary downtwo-level report
-h / -Vsizes / versionsdu output, releases
-o FILEwrite to FILE (may be the input)sort in place safely
-ccheck if sorted (exit 1 if not)validate
-sstable: keep input order for tiespredictable reports

sort in data analysis / engineering

  1. Situation: Top 3 salaries (header removed).

    tail -n +2 employees.csv | sort -t, -k5,5nr | head -3
    103,Meena,Engineering,Bengaluru,98000 101,Asha,Engineering,Pune,85000 106,Arjun,Engineering,Mumbai,72000

    Why this way: -t, sets the delimiter, -k5,5 uses only column 5, n numeric, r reverse.

  2. Situation: By department, then by salary high to low.

    tail -n +2 employees.csv | sort -t, -k3,3 -k5,5nr
    103,Meena,Engineering,Bengaluru,98000 101,Asha,Engineering,Pune,85000 106,Arjun,Engineering,Mumbai,72000 104,Kabir,HR,Pune,47000 105,Riya,Sales,Delhi,61000 102,Ravi,Sales,Mumbai,52000

    Why this way: Several -k options: the second is used only when the first is equal.

  3. Situation: Keep the header on top while sorting the rest.

    { head -n 1 employees.csv; tail -n +2 employees.csv | sort -t, -k5,5n; }
    id,name,dept,city,salary 104,Kabir,HR,Pune,47000 102,Ravi,Sales,Mumbai,52000 105,Riya,Sales,Delhi,61000 106,Arjun,Engineering,Mumbai,72000 101,Asha,Engineering,Pune,85000 103,Meena,Engineering,Bengaluru,98000

    Why this way: Braces group the two commands into one output (Lesson 5.4).

sort in system info / admin

  1. Situation: The biggest folders, in human sizes.

    mkdir -p d1 d2 d3; head -c 3M /dev/zero > d1/f; head -c 200K /dev/zero > d2/f; head -c 40K /dev/zero > d3/f
du -sh d1 d2 d3 | sort -rh
    3.1M d1 204K d2 44K d3

    Why this way: du -h prints 3.1M, 204K…; only sort -h understands those suffixes.

sort in devops / cloud

  1. Situation: The newest release tag.

    printf 'v1.10.2\nv1.2.1\nv1.10.10\nv2.1.0\nv1.9.5\n' | sort -V | tail -n 1
    v2.1.0

    Why this way: -V knows that 1.10 is after 1.9. Text sort would pick the wrong “latest”.

sort in testing / qa

  1. Situation: Check that an export is sorted before loading it.

    printf '1\n3\n2\n' > ids.txt
sort -n -c ids.txt; echo "exit $?"
    sort: ids.txt:3: disorder: 2 exit 1

    Why this way: -c reports the first line out of order and exits 1: a cheap data-quality check.

Common mistake
✗tail -n +2 employees.csv | sort -t',' -k3n | head -1 employees.csv -
✓{ head -n 1 employees.csv; tail -n +2 employees.csv | sort -t, -k5,5n; }

head with two inputs prints file-name headers and only the first line of each (a real run showed “==> employees.csv <==” and one data row). Group the two commands with braces instead.

uniq unique adjacent lines

🟢 Read-onlyno sudo

Reads lines and merges runs of identical adjacent lines. With options it counts them, or prints only repeated or only unique ones.

✓ Use it when
  • removing duplicates after sort
  • counting how often each value occurs
  • finding values that appear once or more than once
✗ Don’t use it when
  • unsorted input (it only sees neighbours)
  • keeping the first occurrence in the original order (use awk '!seen[$0]++')

Syntax: uniq [-c] [-d|-u] [-i] [-f N] [-s N] [-w N] [INPUT [OUTPUT]]

OptionWhat it doesWhen to use it
(none)one of each runafter sort
-ccount each runfrequency tables
-donly lines that repeatduplicates
-uonly lines that appear oncesingletons
-iignore case (input sorted with sort -f)mixed case
-f Nskip the first N fieldsignore an ID column
-s N / -w Nskip / compare only N charactersprefixes

First run (real output)

printf 'apple\napple\nbanana\nbanana\nbanana\ncherry\napple\napple\n' > fruits.txt
uniq fruits.txt | tr '\n' ' '; echo
sort fruits.txt | uniq -c
apple banana cherry apple 4 apple 3 banana 1 cherry

Without sort, apple appears twice (two separate runs). With sort, apple is counted 4 times: the second part of the puzzle.

uniq in data analysis / engineering

  1. Situation: Headcount per department.

    tail -n +2 employees.csv | cut -d, -f3 | sort | uniq -c | sort -rn
    3 Engineering 2 Sales 1 HR

    Why this way: The classic frequency table: cut, sort, count, rank.

  2. Situation: Keep the first of each, in the original order (no sort).

    printf 'b\na\nb\nc\na\n' | awk '!seen[$0]++'
    b a c

    Why this way: awk remembers what it has seen (Lesson 6.5). Useful when order matters.

uniq in system info / admin

  1. Situation: Duplicate user IDs are a security problem: find them.

    printf 'root:x:0\nasha:x:1001\nghost:x:0\n' > pw.txt
cut -d: -f3 pw.txt | sort -n | uniq -d
    0

    Why this way: Two accounts with UID 0 both have root power. uniq -d shows repeated values.

uniq in testing / qa

  1. Situation: Case-insensitive duplicates (from your notes, corrected).

    printf 'Apple\napple\nAPPLE\nBanana\nbanana\nCherry\n' > mixed.txt
sort mixed.txt | uniq -ci
echo ---
sort -f mixed.txt | uniq -ci
    2 APPLE 1 Banana 1 Cherry 1 apple 1 banana --- 3 APPLE 2 Banana 1 Cherry

    Why this way: In the C locale plain sort separates APPLE, Apple … from apple, so uniq -i cannot see them as neighbours. Sort with -f first.

uniq in web servers

  1. Situation: IPs that made only one request.

    cut -d' ' -f1 access.log | sort | uniq -u

    Why this way: -u keeps values that appear exactly once.

Common mistake
✗sort sample.txt | uniq -c → “3 apple” · sort structured.txt | uniq -f 1 → 2 lines · sort prefixes.txt | uniq -cw 6 → “2 apple123”
✓4 apple (two runs of 2) · 4 lines (apple red ≠ apple green) · nothing merged with -w 6 (apple1 ≠ apple4); -w 5 merges them

wc word count

🟢 Read-onlyno sudo

Prints counts of lines, words and bytes (default), or only the ones you ask for. With several files it adds a total line.

✓ Use it when
  • how big is it: lines, words, characters
  • counting results of other commands (… | wc -l)
  • checking line lengths (-L)
✗ Don’t use it when
  • counting matches in one file (grep -c is shorter)

✓ Use it when

  • joining all lines into one (-s)
  • building sums and lists: paste -sd+
✗ Don’t use it when
  • matching rows by a key (use join, Lesson 6.3)

tr translate characters

🟢 Read-onlyno sudo

Reads stdin and replaces each character of SET1 by the matching character of SET2, or deletes (-d) or squeezes (-s) characters. -c uses the complement of SET1.

✓ Use it when
  • changing case, replacing or deleting characters
  • cleaning data: Windows line endings, punctuation, repeated spaces
  • one word per line (tr ' ' '\n')
✗ Don’t use it when
  • replacing words or patterns (use sed, Lesson 6.4)
  • reading files directly: tr reads only stdin

Syntax: tr SET1 SET2 · tr -d SET · tr -s SET · tr -cd SET (input: stdin)

OptionWhat it doesWhen to use it
tr a-z A-Zto capitalsnormalise
'[:lower:]' '[:upper:]'the same, locale-aware classesportable
tr ' ' '_'spaces to underscoresfile names
tr -d '\r'delete Windows CRfiles from Windows
tr -s ' 'squeeze repeated spacesbefore cut
tr -cd '[:digit:]'keep only digitsphone numbers
tr ' ' '\n'one word per lineword counts

First run (real output)

tr in system info / admin

  1. Situation: A script edited on Windows fails with “bad interpreter”: remove the \r.

    printf '#!/bin/bash\r\necho hi\r\n' > win.sh
cat -A win.sh | head -1
tr -d '\r' < win.sh > unix.sh; cat -A unix.sh | head -1
    #!/bin/bash^M$ #!/bin/bash$

    Why this way: cat -A shows ^M (the CR). After tr the line ends with $ only.

tr in data analysis / engineering

  1. Situation: Word frequency in a sentence (case-insensitive).

    echo 'The cat and THE dog and the bird' | tr '[:upper:]' '[:lower:]' | tr ' ' '\n' | sort | uniq -c | sort -rn | head -3
    3 the 2 and 1 dog

    Why this way: Lower-case first, one word per line, then the frequency table.

tr in devops / cloud

  1. Situation: Make ps output cut-friendly (from your notes).

    ps -eo user,pid,pcpu,comm | head -3 | tr -s ' ' | cut -d' ' -f1,2,4
    USER PID COMMAND root 1 process_api root 2 kthreadd

    Why this way: ps pads columns with many spaces; tr -s squeezes them to one so cut can split.

tr in security

  1. Situation: Generate a random 12-character password.

    tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 12 | wc -c
    12

    Why this way: -dc keeps only the allowed characters from random bytes. (Only the length is shown, to keep the output stable.)

Undo and safety net

These tools only print; the risk is in where you send the output.

  • sort f > f emptied the file: use sort -o f f (safe) or write to a new file (Lesson 5.2).
  • Wrong order: check the locale (LC_ALL=C sort) and the key (-k3,3 not -k3).
  • uniq missed duplicates: sort first, and use the same options (-f) in sort and uniq.
  • cut gave strange columns: look at the separators with cat -A; tabs (^I) vs spaces; squeeze with tr -s.

Error messages decoded

Errors students see most with these tools. Each was really produced on our build machine.

  1. cut -f
    cut: option requires an argument -- 'f' Try 'cut --help' for more information. exit status: 1

    What it means: -f needs a list of fields.

    Fix: cut -d, -f2.

  2. cut -d', ' -f1 /etc/hostname
    cut: the delimiter must be a single character Try 'cut --help' for more information. exit status: 1

    What it means: The delimiter must be a single character.

    Fix: Use one character, or awk -F', '.

  3. tr a-z A-Z /etc/hostname
    tr: extra operand ‘/etc/hostname’ Try 'tr --help' for more information. exit status: 1

    What it means: tr does not take file names; it reads only stdin.

    Fix: tr a-z A-Z < /etc/hostname.

  4. printf '1\n3\n2\n' | sort -n -c
    sort: -:3: disorder: 2 exit status: 1

    What it means: Not sorted: sort -c reports the first line out of order.

    Fix: Sort it, or fix the data.

  5. sort -k0 /etc/hostname
    sort: field number is zero: invalid field specification ‘0’ exit status: 2

    What it means: Fields are numbered from 1.

    Fix: -k1.

Script it: hr-report.sh

The 5 pm report as a script: headcount, top 3, total and average, written to a dated file.

cat > employees.csv << 'EOF'
id,name,dept,city,salary
101,Asha,Engineering,Pune,85000
102,Ravi,Sales,Mumbai,52000
103,Meena,Engineering,Bengaluru,98000
104,Kabir,HR,Pune,47000
105,Riya,Sales,Delhi,61000
106,Arjun,Engineering,Mumbai,72000
EOF
f=employees.csv; out="hr_$(date -d 2026-11-06 +%F).txt"
{
  echo "== Headcount by department"; tail -n +2 "$f" | cut -d, -f3 | sort | uniq -c | sort -rn
  echo "== Top 3 salaries";          tail -n +2 "$f" | sort -t, -k5,5nr | head -3 | cut -d, -f2,5
  total=$(tail -n +2 "$f" | cut -d, -f5 | paste -sd+ | bc); n=$(tail -n +2 "$f" | wc -l)
  echo "== Total $total, average $((total / n)) for $n employees"

Quick revision

Lesson 6.2 in one screen

  • cut -d, -f2 fields; -c1-4 characters; default delimiter is TAB; no quote handling.
  • sort text by default; -n -h -V -g -M; -r -u -f -s; -t, -kN,N (give the end field).
  • Locale changes text order: LC_ALL=C for byte order. sort -o f f is safe; sort f > f is not.
  • uniq works on adjacent lines: sort | uniq -c | sort -rn; -d repeated, -u once, -i with sort -f.
  • wc -l -w -c -m -L; wc -l < f for just the number.
  • paste -d, a b side by side; -s one line; paste -sd+ | bc a sum.
  • tr reads stdin only: a-z A-Z, -d '\r', -s ' ', -cd '[:digit:]'.
  • Headers: tail -n +2; keep them: { head -1 f; tail -n +2 f | sort; }.

Interview and viva questions

How do I sort a CSV by a column?

sort -t, -k3,3 file (add n for numbers, r for reverse). Skip the header with tail -n +2.

Why does uniq not remove all duplicates?

uniq only removes adjacent duplicates. Sort first: sort file | uniq, or sort -u file.

How do I count how many times each line occurs?

sort file | uniq -c | sort -rn.

How do I extract a column from a file?

cut -d, -f2 file for delimited data, cut -c1-10 for positions, or awk for space-separated columns.

How do I convert text to upper case in Linux?

tr '[:lower:]' '[:upper:]' < file (or tr a-z A-Z).

How do I remove Windows line endings?

tr -d '\r' < in.txt > out.txt (or dos2unix).

Why does sort give a different order on another computer?

The locale (LANG/LC_ALL) differs. Use LC_ALL=C sort for a fixed byte order.

Sorting a 200 GB log on a 16 GB server

A one-off analysis needs the log sorted by user ID.

The interviewer is checking: do you know how GNU sort scales?

Show a strong answer
  • GNU sort does an external merge sort: it writes temporary files to $TMPDIR; make sure that disk has space (-T /bigdisk/tmp).
  • LC_ALL=C, -S 8G, --parallel, --compress-program=zstd speed it up.
  • Or split by key and sort in parallel, or load it into a columnar tool (DuckDB, Spark).

Avoid: buying more RAM first.

Interview and certification corner

Difference between sort -u and sort | uniq?
Same result for whole lines; -u is one process. uniq has extra options (-c -d -u).
How do you sort numerically in reverse?
sort -nr.
How do you sort by the second column of a CSV?
sort -t, -k2,2.
What does uniq -c do?
Prefixes each group of adjacent equal lines with its count.
How do you count words in a file?
wc -w file.
Convert lowercase to uppercase?
tr '[:lower:]' '[:upper:]'.
Extract the third field of a colon-separated file?
cut -d: -f3 file.
Where this appears in certification exams
  • RHCSA (EX200): Use text filters to analyse text (grep, sort, cut, wc, uniq, tr) in pipelines.
  • LFCS: Essential commands: process text streams with filters.
  • CompTIA Linux+: Text-processing commands: sort, uniq, cut, paste, tr, wc.
