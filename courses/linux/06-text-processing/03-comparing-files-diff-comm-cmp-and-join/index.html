Comparing files: diff, comm, cmp and join

“It worked yesterday, what changed?” diff shows changes between files and folders, comm compares lists, cmp checks any two files byte by byte, and join combines tables on an ID. This lesson explains each and shows how every IT role uses them.

The problem

Which users were added or removed since yesterday? 2 Definition

diff, comm, cmp and join

Formal definition (write this in exams)

diff compares two files (or folders) line by line and prints the changes needed to turn the first into the second. patch applies such a diff. comm compares two sorted files and prints three columns: lines only in file 1, only in file 2, and in both. cmp compares two files byte by byte and reports the first difference. join combines lines of two sorted files that share a common field value.

In simple words

What changed? Which lines are shared? Are they identical? Combine them on an ID.

Comparing files at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: spot the difference

Think of everyday comparisons.

  • diff is the “spot the difference” game: it circles what changed.
  • comm compares two guest lists: only on list A, only on list B, on both.
  • cmp just says whether two boxes are exactly the same, and where they first differ.
  • join puts two registers together using the roll number they share.

Basic The forms you will type every day

  • diff old.conf new.conf: what changed (exit 0 = same, 1 = different).
  • diff -u old new: the “unified” format with - and +, like git.
  • diff -rq dir1 dir2: which files differ between two folders.
  • comm -12 a b: lines in both sorted files.
  • cmp file1 file2: are they byte-for-byte identical?

Intermediate Reading diffs, sorted inputs, keys

  • Normal diff: 3a4 = after line 3 add line 4, 1c1 = change, 5d4 = delete; < is from the first file, > from the second.
  • Unified diff: @@ -1,3 +1,4 @@ = lines 1–3 of the old, 1–4 of the new; - removed, + added, space = unchanged context.
  • comm and join need input sorted the same way (same locale). They warn “not in sorted order”, and join may silently drop rows.
  • join uses field 1 and whitespace by default; -t, for CSV, -1 N -2 M other key columns, -a 1 left join, -v 1 anti-join, -e NULL -o auto to fill blanks.
  • Exit codes: diff and cmp return 0 same, 1 different, 2 trouble; perfect for scripts.

Advanced Behind the screen: the LCS algorithm and patches

  • diff finds the longest common subsequence (LCS) of lines, using Myers’ O(ND) algorithm: everything not in the common part is an insertion or deletion. --minimal, --patience and --histogram (in git) give different, sometimes clearer, results.
  • patch applies a unified diff using the context lines to find the right place even if line numbers moved (“Hunk #1 succeeded at 12 (offset 3 lines)”). patch -R undoes it.
  • cmp stops at the first different byte; to compare files on two machines, compare checksums (sha256sum) instead of copying them.
  • comm and join stream through both files once, like a database merge join: fast and with little memory, which is why they need sorted input.

Did you know? Every git diff, every GitHub pull request and every Linux kernel patch email uses the unified diff format that GNU diff introduced around 1990. The Linux kernel is still developed by emailing patches made with diff -u.

Exam tip: “How do you find what changed between two config files, and how do you check two folders?” → diff -u old new (explain - and +), diff -rq dir1 dir2; exit codes 0 same / 1 different; comm for sorted lists, cmp for binaries.

Quick check In unified diff output, what do lines starting with - and + mean?
Answer: - = only in the first (old) file, removed; + = only in the second (new) file, added. Lines starting with a space are unchanged context.

4 Step by step

Each tool explained, then used in every field

All outputs were recorded on Ubuntu 24.04 (GNU diffutils, coreutils 9.4) with small sample files: two server configs, two user lists and two CSV tables.

diff difference

🟢 Read-onlyno sudo

Prints the changes that turn FILE1 into FILE2. Exit status 0 = identical, 1 = different, 2 = trouble.

✓ Use it when
  • what changed between two versions of a file or folder
  • reviewing config changes before a restart
  • making patches for others
✗ Don’t use it when
  • binary files (use cmp or checksums)
  • huge data files where you need set logic (use comm or sort | uniq)

Syntax: diff [-u|-c|-y|-q] [-r] [-w|-b|-B|-i] FILE1 FILE2

diffcommand-uunified formatweb01.confold / referenceweb02.confnew / to check

Order matters: diff a b shows how to turn a into b. Swap them and every - becomes +.

diff in system info / admin

  1. Situation: Review a config change in the unified format before restarting a service.

    diff -u web01.conf web02.conf
    --- web01.conf 2026-11-10 22:41:37.175517756 +0530 +++ web02.conf 2026-11-10 22:41:37.175517756 +0530 @@ -1,3 +1,4 @@ -port=8080 +port=9090 level=info user=app +timeout=30

    Why this way: - lines are only in the first file, + lines only in the second. The header shows both file names and times.

  2. Situation: Are two deploy folders identical?

    mkdir -p rel1 rel2; echo v1 > rel1/app.py; echo v2 > rel2/app.py; echo x > rel1/old.cfg; echo y > rel1/same.txt; echo y > rel2/same.txt
diff -rq rel1 rel2
    Files rel1/app.py and rel2/app.py differ Only in rel1: old.cfg

    Why this way: -r walks both folders; -q reports only names: changed files and files present on one side only.

diff in software development

  1. Situation: Side by side view while reviewing.

    diff -y -W 50 web01.conf web02.conf
    port=8080 | port=9090 level=info level=info user=app user=app > timeout=30

    Why this way: | marks changed lines, > added, < removed. In a terminal, vimdiff gives the same view with colours.

diff in devops / cloud

  1. Situation: A check that fails a pipeline if the generated config differs from the approved one.

    if diff -q web01.conf web02.conf > /dev/null; then echo 'config approved'; else echo 'config DRIFT detected'; fi
    config DRIFT detected

    Why this way: diff’s exit code drives the if. Configuration-drift checks in CI work like this.

diff in testing / qa

  1. Situation: Compare actual test output with the expected output, ignoring trailing spaces.

    printf 'total: 42  \nstatus: ok\n' > got.txt; printf 'total: 42\nstatus: ok\n' > expected.txt
diff expected.txt got.txt > /dev/null; echo "strict: $?"
diff -b expected.txt got.txt > /dev/null; echo "ignoring spaces: $?"
    strict: 1 ignoring spaces: 0

    Why this way: “Golden file” tests: -b ignores changes in the amount of white space.

patch apply a diff

🟡 Changes filesno sudo

Reads a diff (best: unified) and changes the target file to match. --dry-run tests first; -R reverses; -b keeps a backup.

✓ Use it when

  • applying a change to many servers
  • undoing a change exactly (-R)
✗ Don’t use it when
  • when you can use git (git diff / git apply do the same with history)

comm common lines

🟢 Read-onlyno sudo

Reads two sorted files and prints three TAB-indented columns: lines only in file 1, only in file 2, and in both. -1 -2 -3 hide columns.

✓ Use it when
  • two lists: users, packages, IPs, IDs
  • what was added, removed, kept
  • fast set operations on big sorted files
✗ Don’t use it when
  • unsorted files (sort them first, same locale)
  • files where order or line numbers matter (use diff)

comm in system info / admin

  1. Situation: Which users were added and which removed since yesterday?

    echo 'added:';   comm -13 yesterday.txt today.txt

comm in devops / cloud

  1. Situation: Packages on server A but missing on server B (from two package lists).

    printf 'curl\ngit\nnginx\nvim\n' > srvA.txt; printf 'git\nvim\nnginx\n' > srvB.txt

    Why this way: <(sort …) sorts on the fly. Real lists: dpkg-query -W -f='${Package}\n' on each server.

comm in data analysis / engineering

  1. Situation: Customers who ordered both in October and November.

    printf 'C1\nC2\nC3\nC5\n' > oct.txt; printf 'C2\nC3\nC4\n' > nov.txt
comm -12 oct.txt nov.txt
    C2 C3

    Why this way: -12 = intersection: repeat customers.

comm in security

  1. Situation: Which listening ports are new compared with the approved baseline?

    printf '22\n443\n80\n' | sort > baseline.txt; printf '22\n80\n443\n4444\n' | sort > now.txt
comm -13 baseline.txt now.txt
    4444

    Why this way: A new port (4444) that is not in the baseline deserves a look (Lesson 16.4: ss -ltn).

Common mistake
✗comm fruits1.txt fruits2.txt (sample output with apple indented and banana at the left edge)
✓apple and date at the left edge (only in file 1), elderberry and fig after one TAB (only in file 2), banana and cherry after two TABs (both)

The indentation is the whole meaning of comm’s output. Check it with comm a b | cat -A: ^I is one TAB.

cmp compare bytes

🟢 Read-onlyno sudo

Compares two files byte by byte. Prints the first difference (byte and line number), or nothing if identical. -s prints nothing at all; -l lists every differing byte.

✓ Use it when
  • binary files: images, archives, jars, database files
  • a fast “identical or not” check in scripts
  • finding the first changed byte
✗ Don’t use it when
  • readable text changes (use diff)
  • files on different machines (compare sha256sum)

Syntax: cmp [-s] [-l] FILE1 FILE2

-ssilent; exit code onlyscripts
-levery differing byte (octal values)small binary diffs
-n Ncompare only the first N bytesheaders

cmp in system info / admin

  1. Situation: Did the backup copy of a binary come out exactly the same?

    head -c 50000 /dev/urandom > app.jar; cp app.jar backup.jar
cmp -s app.jar backup.jar && echo 'backup verified'
    backup verified

    Why this way: -s gives only the exit code. For copies on another machine compare sha256sum outputs instead.

cmp in security

  1. Situation: Is a system binary still the original? Compare checksums.

    cp /bin/ls ./ls_copy
sha256sum /bin/ls ls_copy | awk '{print substr($1,1,16), $2}'
    2726eb35864608ff /bin/ls 2726eb35864608ff ls_copy

    Why this way: Equal hashes = identical files, even on different servers. Package tools (debsums, rpm -V) check installed files this way (Lesson 19.4).

join relational join

🟢 Read-onlyno sudo

For each pair of lines whose key fields are equal, prints the key followed by the other fields of both lines. Both files must be sorted on the key. Default key: field 1; default separator: blanks.

✓ Use it when
  • combining two tables that share an ID (like SQL JOIN)
  • finding rows without a partner (anti-join)
  • large sorted exports
✗ Don’t use it when
  • unsorted files (sort on the key first)
  • complex joins with many keys or quoted CSV (use a database, Python or awk)

Syntax: join [-t SEP] [-1 F] [-2 F] [-a 1|2] [-v 1|2] [-e TXT -o auto] FILE1 FILE2

OptionWhat it doesWhen to use it
join -t, a binner join on field 1matching rows
-1 2 -2 1key = field 2 of file 1, field 1 of file 2different key columns
-a 1also unmatched rows of file 1left join
-a 1 -a 2unmatched from bothfull outer join
-v 1only unmatched rows of file 1anti-join: missing
-e NULL -o autofill missing fieldstidy outer joins

join in data analysis / engineering

  1. Situation: Left join: every employee, with pay where known.

    join -t, -a 1 -e NULL -o auto names.csv pay.csv
    101,Asha,85000 102,Ravi,52000 103,Meena,98000 104,Kabir,NULL

    Why this way: -a 1 keeps Kabir (no pay row); -e NULL -o auto fills the empty column. Without -o auto, -e has no effect (verified).

  2. Situation: Anti-join: payroll rows for unknown employees.

    join -t, -v 2 names.csv pay.csv
    105,61000

    Why this way: -v 2 prints rows of file 2 that have no partner: ID 105 is paid but not in the names file.

join in data administration

  1. Situation: Join on a column that is not the first one.

    printf 'Engineering,Floor 3\nHR,Floor 1\nSales,Floor 2\n' > floors.csv
tail -n +2 employees.csv | sort -t, -k3,3 | join -t, -1 3 -2 1 -o 1.2,0,2.2 - floors.csv
    Asha,Engineering,Floor 3 Meena,Engineering,Floor 3 Arjun,Engineering,Floor 3 Kabir,HR,Floor 1 Ravi,Sales,Floor 2 Riya,Sales,Floor 2

    Why this way: -1 3 uses field 3 of the first input (stdin, -); 0 in -o means the key. Both inputs are sorted on the key.

join in system info / admin

  1. Situation: Users with their UID and primary GID (from your notes, corrected).

    cut -d: -f1,3 /etc/passwd | sort -t: -k1,1 > u_uid.txt; cut -d: -f1,4 /etc/passwd | sort -t: -k1,1 > u_gid.txt
join -t: u_uid.txt u_gid.txt | head -3
    _apt:42:65534 backup:34:34 bin:2:2

    Why this way: These files use : so -t: is required; without it join treats the whole line as the key and joins almost nothing.

Common mistake
✗join users_uids.txt users_gids.txt · join -t, -a 1 -e '0' a.csv b.csv
✓join -t: users_uids.txt users_gids.txt · join -t, -a 1 -e 0 -o auto a.csv b.csv

Without -t: join splits on blanks, so “root:0” is one field and lines only match when UID = GID (verified: wrong rows). And -e only fills fields that -o asks for: add -o auto.

Undo and safety net

Only patch changes files; the others just print.

  • patch changed the wrong file: patch -R file < fix.patch, or restore file.orig if you used -b.
  • comm/join gave odd results: sort both inputs the same way (LC_ALL=C sort) and on the key column.
  • diff output too long: use -q first, then -u on one file; or | less.
  • diff shows every line changed: Windows line endings in one file: check with cat -A, fix with tr -d '\r'.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. diff /nope /etc/hostname
    diff: /nope: No such file or directory exit status: 2

    What it means: A file is missing. Exit 2 = trouble, not “different”.

    Fix: Check the paths.

  2. printf 'b\na\n' > x.txt; printf 'a\nb\n' > y.txt; comm x.txt y.txt
    a b comm: file 1 is not in sorted order a comm: input is not in sorted order exit status: 1

    What it means: x.txt is not sorted; the result is unreliable.

    Fix: comm <(sort x.txt) <(sort y.txt).

  3. printf '2,B\n1,A\n' > j1.csv; printf '1,x\n2,y\n' > j2.csv; join -t, j1.csv j2.csv
    join: j1.csv:2: is not sorted: 1,A 2,B,y join: input is not in sorted order exit status: 1

    What it means: j1.csv is not sorted, so join missed ID 1 (only 2,B,y is printed). This is the puzzle.

    Fix: Sort both on the key: join -t, <(sort j1.csv) <(sort j2.csv).

  4. printf 'x\n' > a.txt; printf '%s\n' '--- a' '+++ b' '@@ -1 +1 @@' '-y' '+z' > bad.patch; patch a.txt < bad.patch
    patching file a.txt Hunk #1 FAILED at 1. 1 out of 1 hunk FAILED -- saving rejects to file a.txt.rej exit status: 1

    What it means: The patch expects a line “y” that is not in a.txt: the hunk fails and is saved to a.txt.rej.

    Fix: Make sure the patch was made from the same version of the file; check with --dry-run first.

Reading a diff, and set operations

How diff matched the lines 4 steps
What you see
  1. The @@ line: old lines 1–3, new lines 1–4.
  2. A change is a - line followed by a + line.
  3. Lines with a space are the same in both.
  4. A + without a - is new.
Behind the screen
  1. diff first finds what both files share.
  2. port=… is not shared.
  3. level and user are shared, in order.
  4. timeout has no partner on the left.

Script it: drift-check.sh

A config-drift check for two servers: report changed settings, new and removed keys, and exit 1 if anything differs.

printf 'port=8080\nlevel=info\nuser=app\n' > web01.conf; printf 'port=9090\nlevel=info\nuser=app\ntimeout=30\n' > web02.conf
a=web01.conf; b=web02.conf
if diff -q "$a" "$b" > /dev/null; then echo "no drift"; exit 0; fi
echo "== changed or added in $b";   comm -13 <(sort "$a") <(sort "$b")
echo "== only in $a";               comm -23 <(sort "$a") <(sort "$b")
keys_a=$(cut -d= -f1 "$a" | sort); keys_b=$(cut -d= -f1 "$b" | sort)
echo "== new keys: $(comm -13 <(echo "$keys_a") <(echo "$keys_b") | paste -sd,)"
exit 1
== changed or added in web02.conf port=9090 timeout=30 == only in web01.conf port=8080 == new keys: timeout

The first line only creates the two sample configs. In real use, fetch the files with scp or ssh first (Lesson 16.6).

Puzzle answer Remember the question from the story? Open to check your guess.

join assumes both files are sorted on the key and walks them together. In a.csv the first line was 2; when join then saw 1 it was already past it, so the pair for 1 was never compared. GNU join warns “is not sorted” and “input is not in sorted order”. Always sort both inputs on the key first.

Quick check Which command lists IDs that are in orders.csv but not in customers.csv (both sorted on the ID)?
Answer: join -t, -v 1 orders.csv customers.csv (or comm -23 on the ID columns).

Quick revision

Lesson 6.3 in one screen

  • diff a b: 1c1 change, 3a4 add, 5d4 delete; < first file, > second. Exit 0 / 1 / 2.
  • diff -u (- old, + new, @@ hunks), -y side by side, -q brief, -r folders, -w -b -B -i ignore.
  • patch --dry-run, patch -b f < p, patch -R to undo.
  • comm needs sorted input: -12 both, -23 only A, -13 only B, -3 either; union = sort -u A B.
  • cmp -s for any files; sha256sum across machines.
  • join -t, on sorted keys; -1/-2 key fields; -a outer; -v anti; -e X -o auto.
  • Compare command outputs: diff <(cmd1) <(cmd2).
  • Every line changed? Check Windows line endings with cat -A.

Interview and viva questions

How do I compare two files in Linux?

diff file1 file2 for text (diff -u for the unified format), cmp for binary files.

How do I compare two directories?

diff -rq dir1 dir2 lists files that differ or exist on one side only.

What does the output of diff mean?

Normal format: “3a4” add, “1c1” change, “5d4” delete; < lines from the first file, > from the second. Unified: - removed, + added.

How do I find lines common to two files?

comm -12 <(sort a) <(sort b).

How do I join two CSV files on a column?

Sort both on that column, then join -t, (use -1/-2 for other columns, -a for outer joins).

How do I create and apply a patch?

diff -u old new > fix.patch; patch old < fix.patch (patch -R to undo).

Why does diff show every line as changed?

Often one file has Windows line endings (\r\n). Check with cat -A.
