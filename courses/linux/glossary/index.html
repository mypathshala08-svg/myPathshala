Often confused

The pairs that trip up most students and interview candidates.

Linux vs a distribution

Linux is the kernel. A distribution (Ubuntu, RHEL) is a full OS built around it: tools, package manager, installer, defaults.

Terminal vs shell

The terminal is the window that shows text. The shell (bash) is the program inside it that understands commands. You can change one without the other.

Absolute vs relative path

Absolute starts with / and works from anywhere. Relative is from your current folder, so the same command can mean different files in different folders.

> vs >>

> empties the file first, then writes. >> adds to the end. sort data.txt > data.txt leaves an empty file because the shell truncates it before sort reads it.

Pipe ( | ) vs redirection ( > )

A pipe sends output to another command. Redirection sends it to a file. ls > grep creates a file named grep.

Hard link vs soft link

A hard link is a second name for the same inode; survives deleting the original; same file system only. A soft link is a pointer to a path; breaks if the target moves; can cross file systems and point to folders.

rm vs freeing disk space

rm removes a name. Space comes back only when no other hard link exists and no process still has the file open (lsof +L1).

Single vs double quotes

'$HOME' prints the text $HOME. "$HOME" prints /home/riya. Both stop spaces from splitting words.

Shell variable vs environment variable

A plain X=1 exists only in this shell. export X=1 also copies it to programs you start. Children can never change the parent's variables.

source script vs ./script

source runs the file in your current shell (its cd and variables stay). ./script runs in a child process (changes vanish when it ends).

su vs sudo

su switches to another user (asks their password, gives a whole shell). sudo runs one command as root (asks your password, checks sudoers, logs it).

chmod vs chown

chmod changes what can be done (rwx). chown changes who owns the file. Only root can chown to another user.

kill vs kill -9

kill sends SIGTERM: the app can clean up and exit. kill -9 sends SIGKILL: the kernel ends it instantly, no cleanup. Use -9 only when TERM fails.

Process vs thread

A process has its own memory. Threads are parallel paths inside one process, sharing its memory. The kernel schedules both as tasks.

Zombie vs orphan

A zombie is dead but not yet collected by its parent. An orphan is alive but its parent died; PID 1 adopts it.

systemctl start vs enable

start = run it now. enable = start it automatically at boot. A service can be enabled but stopped, or running but disabled.

cron vs systemd timer

cron is simple and everywhere. A timer logs to the journal, can run missed jobs after downtime and respects dependencies.

apt vs dpkg (dnf vs rpm)

dpkg/rpm install one local package file with no dependency fetching. apt/dnf download from repositories and resolve dependencies, then call dpkg/rpm.

apt update vs apt upgrade

update only refreshes the list of available packages. upgrade actually installs newer versions. Run update first.

df vs du

df asks the file system how full it is. du adds up the files it can see. If df says full but du finds little, a deleted-but-open file or files hidden under a mount point are the usual cause.

free vs available memory

free is RAM doing nothing at all. available includes cache the kernel will give back instantly. Low "free" is normal; low "available" is a real problem.

find vs locate

find walks the folders right now: always current, slower. locate searches a database updated about daily: instant, but misses new files until updatedb runs.

grep vs sed vs awk

grep finds lines. sed changes text in lines (search and replace). awk works with columns and calculations (sums, counts, reports).

scp vs rsync

scp copies everything every time. rsync copies only differences, can resume, preserve permissions and mirror with --delete. Use rsync for backups and deployments.

dig vs ping for DNS

dig asks the DNS server directly. ping (and most programs) resolve through /etc/hosts first. If they disagree, check /etc/hosts.

Interrupt context vs process context

Interrupt context: the kernel’s short handler for a hardware event; it must not sleep. Process context: kernel code running for a process, for example inside a system call; it may wait.

ctime vs mtime

mtime changes when the file’s content changes. ctime changes when its inode changes: permissions, owner, link count, and also content. ctime is not “creation time”.

man vs --help vs info

--help: a quick summary printed by the command itself. man: the full reference page. info: GNU’s longer tutorial-style manual with links.

Container vs virtual machine

A VM runs its own full kernel on virtual hardware. A container is isolated processes sharing the host's kernel: lighter and faster to start, but the same kernel for all.

2>&1

Shell

Send errors to the same place as normal output.

Behind the screen

It means "make fd 2 a copy of whatever fd 1 is now". Order matters: cmd > all.log 2>&1 puts both in the file, but cmd 2>&1 > all.log sends errors to the screen because fd 1 still pointed there at that moment. &> all.log is the bash shortcut.

Extra permission rules for specific users or groups, beyond owner/group/others.

Behind the screen

Stored as extended attributes on the file. ls -l shows a + after the mode when ACLs exist. A mask entry limits the maximum rights any ACL entry can give.

Behind the screen

The shell replaces the first word of a command with the alias text before running it. Aliases are not used in scripts by default and are forgotten when the shell exits unless saved in ~/.bashrc.

apt vs dpkg

Packages

dpkg installs a single .deb file and does not fetch dependencies. apt fetches from repositories and handles dependencies, then uses dpkg.

Behind the screen

Same pattern on RHEL: rpm is the low-level tool, dnf (formerly yum) the high-level one. apt is the friendly command; apt-get is the older one with output that is stable for scripts.

awk

Text

A small language for column-based text: awk '{print $1}' access.log prints the first column.

Behind the screen
  1. line
  2. →
  3. split into $1 $2 $3 …
  4. →
  5. check pattern ($9==500)
  6. →
  7. run action (count++)
  8. →
  9. …
  10. →
  11. END prints count

awk splits every line (record) into fields $1, $2…$NF using the field separator (spaces by default, -F, for CSV), then runs pattern { action } rules. BEGIN runs before the first line, END after the last, which is where totals are printed.

$ awk -F, '$3>1000 {sum+=$3} END {print sum}' sales.csv

Basic vs extended regex (BRE / ERE)

Text

In basic regex (grep, sed) + ? | ( ) { } are ordinary characters unless escaped; in extended regex (grep -E, sed -E, awk) they are special.

Behind the screen

grep 'ab+' looks for a literal plus; grep -E 'ab+' means one or more b. Most "my regex doesn't work" problems are this.

$ grep -E '(ERROR|WARN)' app.log

Shell

{a,b,c} and {1..5} generate several words: mkdir -p app/{src,docs,tests}.

Behind the screen

It is pure text generation, done first, without looking at any files, so it works for names that do not exist yet (unlike *).

Building from source

Packages

Compiling a program yourself from its code: usually ./configure && make && sudo make install.

Behind the screen

configure checks your system and writes a Makefile; make compiles; make install copies files, by default under /usr/local so they do not clash with packages. The package manager does not know about these files.

Builtin vs external command

Shell

A builtin (cd, echo, export) runs inside the shell. An external command (ls, grep) is a separate program file.

Behind the screen

Builtins exist when the work must change the shell itself (current folder, variables) or for speed: no fork or exec is needed.

$ type cd ls echo

Capabilities

Security

Root's powers split into separate pieces, e.g. CAP_NET_BIND_SERVICE (use ports below 1024).

Behind the screen

A program can be given just the piece it needs instead of full root, reducing damage if it is hacked. Containers drop most capabilities by default.

cgroup (control group)

Security

A kernel feature that groups processes and limits or measures their CPU, memory and disk I/O.

Behind the screen

systemd puts every service in its own cgroup (that is how it can stop all of a service's child processes). Docker's --memory=512m is a cgroup limit; exceeding it triggers the OOM killer inside that group only. cgroup v2 is mounted at /sys/fs/cgroup.

$ systemd-cgls | head; cat /proc/self/cgroup

Chaining: ; && ||

Shell

a ; b always runs b. a && b runs b only if a succeeded. a || b runs b only if a failed.

Behind the screen

The shell simply checks the exit status of a. mkdir logs && cd logs never cds into a folder that failed to be created.

$ make && ./app || echo 'build failed'

Checksum / hash (sha256sum)

Security

A short fingerprint of a file. If even one byte changes, the fingerprint changes completely.

Behind the screen

Download sites publish the SHA-256 of an ISO; you compute it yourself and compare. A GPG signature goes further: it proves who published the checksum.

$ sha256sum ubuntu.iso; sha256sum -c SHA256SUMS

chmod

Permissions

Changes permissions: chmod +x deploy.sh, chmod 640 app.conf, chmod -R g+w shared/.

Behind the screen

Only the owner (or root) can change a file's mode. It updates the mode bits in the inode; the file's data is not touched, so it is instant even for huge files.

chown and chgrp

Permissions

Change the owner and group of a file: sudo chown www-data:www-data /var/www/site -R.

Behind the screen

Only root can give a file to another user (otherwise users could dodge disk quotas). A normal owner may change the group to one they belong to.

Command substitution $( )

Shell

Puts a command's output into another command: echo "Today is $(date +%A)".

Behind the screen

The shell runs the inner command in a subshell, captures what it prints, removes trailing newlines and pastes the text in place.

$ echo "Files: $(ls | wc -l)"

Command, option and argument

Basics

In ls -l /etc: ls is the command, -l an option (changes how it works), /etc an argument (what it works on).

Behind the screen

The shell hands the program an array of strings called argv: argv[0]="ls", argv[1]="-l", argv[2]="/etc". Options are not magic: each program reads argv and decides what -l means, which is why options differ between commands.

$ ls -l /etc

Compression (gzip, bzip2, xz, zip)

Packages

Makes files smaller. gzip is fast and common; xz squeezes most but is slowest; zip is for sharing with Windows.

Behind the screen

Text logs often shrink by 90% or more because they repeat a lot. zcat, zgrep and zless read .gz files without extracting them.

$ gzip big.log; zgrep ERROR big.log.gz

Console / virtual console

Basics

A text-only login screen provided by the machine itself, without any window app.

Behind the screen

Linux gives you several virtual consoles (/dev/tty1…tty6). On a desktop, Ctrl+Alt+F3 switches to one. Servers in a data centre are often reached through a remote console when SSH is broken.

$ who

Container

Security

An app packaged with its files, running isolated on a shared Linux kernel (Docker, Podman, Kubernetes pods).

Behind the screen
  1. docker run
  2. →
  3. image layers mounted (overlayfs)
  4. →
  5. new namespaces (pid, net, mnt…)
  6. →
  7. cgroup limits set
  8. →
  9. your process starts as PID 1 inside

A container is not a VM: it is ordinary Linux processes, isolated with namespaces, limited with cgroups, with a layered image file system (overlayfs) as its root. That is why it starts in milliseconds, and why Linux knowledge is essential for DevOps.

Context switch

Processes

When the CPU stops running one task and starts another.

Behind the screen

The kernel saves the registers of one task and loads the next. Thousands per second is normal; a huge number (seen in vmstat's cs column) can mean too many threads fighting.

$ vmstat 1 5

cron and crontab

Services

cron runs commands on a schedule. Each user's schedule is their crontab: 30 2 * * * /opt/backup.sh = every day at 02:30.

Behind the screen
  1. minute ticks
  2. →
  3. crond reads crontabs
  4. →
  5. time matches '30 2 * * *'
  6. →
  7. runs /bin/sh -c '/opt/backup.sh' with minimal env
  8. →
  9. output mailed or lost unless redirected

The cron daemon wakes every minute and checks all crontabs. Jobs run with a very small environment (short PATH, no aliases, your .bashrc not loaded), which is the number-one reason a script works by hand but fails in cron. Use full paths and log the output.

$ crontab -l; crontab -e

curl and wget

Network

Command-line tools to fetch URLs. wget is mainly for downloading files; curl for any HTTP request, including APIs.

Behind the screen

curl -I shows only headers, -v shows the whole conversation (DNS, TLS, request, response), -X POST -d sends data. Very handy to test a web service from the server itself.

$ curl -I https://myphatshala.in

Files

The folder you are "in" right now. pwd prints it; cd changes it.

Behind the screen

The kernel stores a current directory for each process. That is why cd must be a shell builtin: a separate cd program would change only its own directory and then exit, leaving the shell where it was.

cut, tr and wc

Text

cut takes columns, tr replaces or deletes characters, wc counts lines, words and bytes.

Behind the screen

wc -l counts newline characters, so a last line with no newline is not counted. tr works on single characters, not words (tr 'a-z' 'A-Z').

$ echo 'hello' | tr a-z A-Z; wc -l /etc/passwd

Processes

A background program with no terminal that provides a service. Names often end in d: sshd, crond, systemd-journald.

Behind the screen

Modern daemons are started and supervised by systemd, which restarts them if they crash and captures their output into the journal.

$ systemctl list-units --type=service --state=running

Default gateway and routes

Network

The router your machine sends traffic to when the destination is not on the local network.

Behind the screen

The kernel's routing table picks the most specific matching route for each packet; default via 192.168.1.1 catches everything else.

Files

Why disk space does not come back after rm of a huge log: a running program still has it open.

Behind the screen

rm only removes the name. The inode and its data stay until the last open descriptor is closed. Restart (or signal) the program, or truncate the file instead of deleting it.

$ sudo lsof +L1

Dependency

Packages

Another package that a package needs in order to work (a library, a runtime).

Behind the screen

Package metadata lists dependencies with version rules. The package manager installs them automatically, and apt autoremove removes ones nothing needs any more.

/dev

Files

Device files: /dev/sda (a disk), /dev/null, /dev/tty, /dev/random.

Behind the screen

These are not stored on disk. The kernel's devtmpfs and the udev service create them as hardware appears. Each has a major/minor number that tells the kernel which driver handles reads and writes.

$ ls -l /dev/null /dev/sda 2>/dev/null

/dev/null

Files

A "black hole" device: whatever you write to it disappears; reading from it gives nothing.

Behind the screen

It is a character device (c 1,3). Its driver accepts every write and throws the data away, and returns end-of-file on every read. 2>/dev/null hides error messages.

$ find / -name '*.conf' 2>/dev/null

diff

Text

Shows the differences between two files, line by line.

Behind the screen

It computes the longest common sequence of lines and prints only what must be added or removed to turn one file into the other. diff -u gives the unified format used by patches and git.

$ diff -u old.conf new.conf

Basics

A complete Linux OS: the kernel plus tools, a package manager, an installer and default settings. Ubuntu, Debian, Fedora, RHEL, Rocky, Arch.

Behind the screen

All distros share the same Linux kernel family and mostly the same GNU tools. What really differs: the package format (.deb vs .rpm), the package manager (apt vs dnf), release cycle, default configs and support period.

Services

Messages from the kernel itself: hardware, drivers, disk errors, the OOM killer.

Behind the screen

The kernel writes to a fixed-size in-memory ring buffer; old messages are overwritten. dmesg -T shows readable times; journalctl -k shows the same messages from the journal.

$ sudo dmesg -T | tail

dnf / yum and rpm

Packages

The package tools of Fedora, RHEL, Rocky and AlmaLinux.

Behind the screen

dnf reads repo files in /etc/yum.repos.d/, resolves dependencies and calls rpm. On current RHEL, the yum command is kept as a link to dnf.

$ sudo dnf install httpd; rpm -qa | head

Network

/etc

Files

Where system-wide configuration files live, as plain text: /etc/passwd, /etc/hosts, /etc/ssh/sshd_config.

Behind the screen

Programs read these text files at start-up (or on reload). That is why editing a file in /etc often needs a systemctl restart or reload before it takes effect.

Storage

The list of file systems to mount automatically at boot.

Behind the screen

Each line: device (best by UUID=), mount point, type, options, dump, fsck order. systemd turns every line into a .mount unit at boot. A typo can stop the machine booting, so test with sudo mount -a first.

$ cat /etc/fstab

Network

A local text file mapping names to IP addresses, checked before DNS.

Behind the screen

Useful to test a new server before DNS changes or to name lab machines (e.g. Hadoop nodes). A forgotten entry here explains "why does only my machine reach the old server?"

$ cat /etc/hosts

/etc/passwd

Users

The list of user accounts, one per line: riya:x:1000:1000:Riya:/home/riya:/bin/bash.

Behind the screen

Seven fields: name, password placeholder (x), UID, GID, comment, home, login shell. Everyone can read it because many programs need names; the password hashes moved to /etc/shadow.

/etc/shadow

Users

Where password hashes are stored. Readable only by root.

Behind the screen

It stores a salted one-way hash, not the password (on recent Ubuntu/Debian the hash starts with $y$ = yescrypt; older systems use $6$ = SHA-512). At login, the typed password is hashed the same way and compared. It also stores password expiry dates used by chage.

$ sudo grep riya /etc/shadow

Everything is a file

Files

Linux shows most things as files: documents, folders, disks, terminals, even running processes.

Behind the screen

The kernel gives one interface (open, read, write, close) for all of them. A program that can read a file can also read /dev/sda, a pipe, a socket or /proc/cpuinfo; the kernel routes each call to the right driver or file system.

Exit status ($?)

Shell

Every command ends with a number: 0 = success, anything else = failure. $? shows the last one.

Behind the screen

The program passes it to exit(); the kernel holds it until the parent collects it with wait(). Common values: 1 general error, 2 misuse, 126 not executable, 127 not found, 128+N killed by signal N (130 = Ctrl+C).

$ ls /nope; echo $?

Shell

Behind the screen

fail2ban

Security

A service that blocks IP addresses after too many failed logins.

Behind the screen

It watches logs (for example auth.log for SSH), counts failures per IP, and adds a firewall rule to ban the IP for a while. Internet-facing servers see automated SSH login attempts every day.

$ sudo fail2ban-client status sshd

Field and delimiter

Text

A field is one column of a line; the delimiter is the character that separates columns (space, comma, tab, colon).

Behind the screen

cut -d: -f1 /etc/passwd uses : as the delimiter and takes field 1. cut uses one exact character; awk's default treats any run of spaces as one separator, which suits command output.

$ cut -d: -f1,7 /etc/passwd

File descriptor (fd)

Files

A small number a program uses for each open file: 0 = input, 1 = output, 2 = errors, 3+ = files it opened.

Behind the screen

When a program opens a file, the kernel adds an entry to that process's descriptor table and returns its number. Every later read or write uses the number. Redirection works by changing what 0, 1 and 2 point to.

$ ls -l /proc/$$/fd

fork and exec

Processes

How every new program starts: the shell forks (copies itself) and the copy execs (turns into) the new program.

Behind the screen
  1. bash (PID 500)
  2. →
  3. fork
  4. →
  5. child bash (PID 501)
  6. →
  7. set up redirections
  8. →
  9. execve('/usr/bin/ls')
  10. →
  11. PID 501 is now ls
  12. →
  13. exits
  14. →
  15. bash wait()s
