2 Definition

A scenario guide for choosing commands

Formal definition (write this in exams)

A scenario guide maps a job to the command that does it best. Many Linux tools overlap (grep, awk and sed can all print matching lines; cp and rsync can both copy), but each is designed for one kind of job and is simplest, fastest and safest there. Choosing well means naming the job first, then picking the smallest tool designed for it.

Choosing at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a toolbox with drawers

Open the right drawer first.

Basic Four questions

  1. What is the job? Search, extract, change, compute, find files, copy, compare, stop, schedule.
  2. On what? Lines of text, columns, whole files, folders, processes, remote machines.
  3. Once or again? A one-off job or something repeated (then rsync, cron, a script).
  4. How safe? Read-only first; tools that change things get a preview (echo, -n, --dry-run).

Intermediate Rules of thumb

  • grep to select lines, cut for a fixed column, awk when a condition on a column or maths is involved, sed to replace.
  • find when you need live results or tests (size, age, -exec); locate when you only know part of a name and speed matters (index updated daily).
  • cp for one-time local copies; rsync when you copy again, over the network, or need to resume.
  • systemctl for services (they restart), pkill for programs by name, kill for a known PID.
  • diff for text, cmp for binary, comm for sorted lists, sha256sum to compare files on different machines.

Advanced Behind the screen: why the difference matters

  • grep uses highly optimised string search (Boyer–Moore-style skipping), often 10× faster than awk on large logs for pure searching.
  • locate reads a prebuilt database (/var/lib/plocate/plocate.db, rebuilt by a daily timer): instant but can be stale and only knows names.
  • rsync compares size and modification time (or checksums with -c) and sends only changed parts using a rolling checksum; cp always copies everything.
  • A service killed with kill is restarted by systemd if Restart= is set: the puzzle’s nginx that “keeps coming back”.
  • cron runs with a tiny environment and no logs by default; systemd timers log to the journal, can catch up missed runs (Persistent=true) and have dependencies.

Did you know? The grep vs awk vs sed overlap is deliberate: they were written at Bell Labs in the same decade, each for one job, and designed to be piped together. Using all three in one pipeline is normal: grep to select, sed to clean, awk to compute.

Exam tip: “When would you use awk instead of grep?” → When you need a condition on a specific column, or computation (sums, counts, formatting); grep only selects lines by pattern.

Quick check You need lines where column 3 is greater than 100. grep or awk?
Answer: awk ('$3>100'): grep cannot compare numbers in a column.
Common mistake
✗kill -9 the nginx process
✓sudo systemctl stop nginx (and disable it if it must not start at boot)

systemd sees the service die and starts it again (Restart=on-failure): it “keeps coming back”.

Common mistake
✗cp -r big/ backup/ every night
✓rsync -a --delete big/ backup/ (only changes are copied)

cp copies all 50 GB every time; rsync copies only new and changed files (real run: second rsync-style copy moved 0 files).

find vs locate · cp vs rsync · tar vs zip files: find, copy, bundle

🟡 Changes filesno sudo

find walks the disk now and can test size, age and permissions; locate only searches names in a daily index, instantly. cp copies everything every time; rsync copies only what changed (and works over SSH, resumes, has --dry-run). tar keeps Linux permissions and streams well; zip is what Windows users can open.

✓ Use it when
  • finding files
  • copying and syncing
  • archives to share
✗ Don’t use it when
  • find / every time you look for a name
  • cp -r for repeated copies

diff vs cmp vs comm vs sha256sum · which vs type vs whereis comparing and identifying

🟢 Read-onlyno sudo

diff shows changed lines of text files; cmp says whether two files are identical byte by byte (and where they first differ); comm splits two sorted lists into “only A, only B, both”; sha256sum compares files on different machines. For commands: type tells you if it is an alias, function, built-in or file; which only searches PATH; whereis also finds man pages.

✓ Use it when
  • what changed between two files
  • is this the same file?
  • where does this command come from?
✗ Don’t use it when
  • diff on binaries
  • which for aliases

Undo and safety net

Choosing the wrong tool rarely breaks things; the wrong action does.

  • Replaced in the wrong file: restore from backup or git; next time sed without -i first.
  • cp overwrote newer files: use rsync -a --update or cp -n; check with --dry-run.
  • Killed a service that came back: that is systemd working; use systemctl stop/disable.
  • Habit: name the job, choose the tool, preview, then act.

6 Real-world use

Choosing well at work

1. Backups and deployments

Nightly rsync -a --delete to a backup server copies minutes of changes instead of hours of data.

Nightly→rsync→fast backup

2. Log investigations

grep narrows gigabytes to the relevant lines first; awk then computes on the much smaller stream.

Huge log→grep then awk→answer

3. Service operations

On-call runbooks say systemctl restart/stop, never kill -9, so systemd and logs stay consistent.

Incident→systemctl→clean state

4. API checks and automation

curl -sf health endpoints in scripts; wget -c for big ISO downloads.

Check→curl / wget→result

5. Sharing with other teams

tar.gz for Linux servers, zip for colleagues on Windows, sha256sum to prove the copy is intact.

Package→tar / zip→verified

Examples are simplified and generic. They describe common patterns, not the internal systems of any particular company.

More examples and variations

Twenty more side-by-side choices. All were really run on our build machine.

Text

V1

Count matching lines: grep -c vs awk

cd ~/wc; grep -c bash users.txt; awk '/bash/{n++} END{print n}' users.txt
2 2

Same answer; grep -c is shorter.

V2

Only the matching part: grep -o

cd ~/wc; grep -oE '[0-9]{4}' users.txt | paste -sd' '
1001 1002 1003

grep -o extracts patterns, no awk needed.

V3

Delete lines: grep -v vs sed d

cd ~/wc; grep -v nologin users.txt | wc -l; sed '/nologin/d' users.txt | wc -l
3 3

Equivalent; grep -v reads more naturally.

V4

Lines 2–3: sed vs head|tail

cd ~/wc; sed -n '2,3p' users.txt | cut -d: -f1; head -3 users.txt | tail -2 | cut -d: -f1
aman zoya aman zoya

sed -n is one tool.

V5

Characters: tr vs sed

cd ~/wc; tr ':' ' ' < users.txt | head -1; sed 's/:/ /g' users.txt | head -1
riya 1001 /home/riya /bin/bash riya 1001 /home/riya /bin/bash

tr for single characters, sed for words.

V6

Upper case: tr vs ${,^^}

echo linux | tr a-z A-Z; s=linux; echo "${s^^}"

Inside scripts, parameter expansion avoids a process (Lesson 12.14).

V7

Columns with spaces: cut vs awk

echo 'a   b  c' | cut -d' ' -f2; echo 'a   b  c' | awk '{print $2}'
b

cut sees empty fields between spaces; awk treats runs as one.

Files

V8

Sizes: ls -l vs du vs stat

cd ~/wc; ls -l src/data.bin | awk '{print $5}'; du -k src/data.bin | cut -f1; stat -c %s src/data.bin
200000 196 200000

Bytes, KB on disk, bytes: choose by what you need.

V9

Unique values: sort -u vs uniq

printf 'b\na\nb\n' | sort -u | paste -sd' '; printf 'b\na\nb\n' | uniq | paste -sd' '
a b b a b

uniq without sort missed the second b.

V10

Is it text or binary? file

Before choosing diff or cmp.

V11

Full path of a file: realpath vs readlink

cd ~/wc/src; realpath a.txt | sed 's|/home/riya|~|'; ln -sf a.txt link.txt; readlink link.txt; readlink -f link.txt | sed 's|/home/riya|~|'

readlink shows the link target; -f resolves fully.

V12

Compress: gzip vs xz

cd ~/wc; seq 1 50000 > n.txt; gzip -k n.txt; xz -k n.txt; ls -l n.txt n.txt.gz n.txt.xz | awk '{print $5, $NF}'
288894 n.txt 109150 n.txt.gz 9832 n.txt.xz

xz is smaller, gzip is faster (Lesson 14.5).

V13

Archive listing: tar t vs unzip -l

cd ~/wc; tar czf s.tgz src; zip -qr s.zip src; tar tzf s.tgz | wc -l; unzip -l s.zip | tail -1 | awk '{print $2}'
5 5

Look inside before extracting.

V14

Preview a copy: cp -n vs cp -u

cd ~/wc; cp -a src/. backup/; echo new > src/a.txt; cp -nv src/* backup/ 2>&1 | wc -l; cp -uv src/* backup/ | sed "s/'//g; s|/home/riya|~|g"

-n never overwrites; -u only newer files (a poor man’s rsync).

Script it: whichtool.sh

A tiny interactive helper: given a job keyword (search, column, filter, replace, files, copy, compare, stop, schedule), print the recommended command and an example.

job=${1:-copy}
case $job in
  search)   echo "grep PATTERN FILE           e.g. grep -i error app.log" ;;
  column)   echo "cut -d: -fN FILE            e.g. cut -d: -f1 /etc/passwd" ;;
  filter)   echo "awk 'COND' FILE             e.g. awk -F: '\$3>=1000' /etc/passwd" ;;
  replace)  echo "sed 's/OLD/NEW/g' FILE      e.g. sed -i.bak 's/8080/9090/' app.conf" ;;
  files)    echo "find DIR TESTS | locate NAME e.g. find /var -size +1G" ;;
  copy)     echo "rsync -a SRC/ DST/          e.g. rsync -a --delete data/ backup01:/data/" ;;
  compare)  echo "diff (text) | cmp (binary) | comm (sorted lists)" ;;
  stop)     echo "systemctl stop SVC | pkill -x NAME | kill PID" ;;
  schedule) echo "at (once) | cron or systemd timer (repeat)" ;;
  *)        echo "unknown job: $job (try: search column filter replace files copy compare stop schedule)"; exit 1 ;;
esac
rsync -a SRC/ DST/ e.g. rsync -a --delete data/ backup01:/data/

Run without an argument, so it answers “copy”.

Puzzle answer Remember the question from the story? Open to check your guess.

(1) grep is wrong: “UID at least 1000” is a numeric condition on column 2, so awk: awk -F: '$2>=1000{print $1}'. (2) awk works but sed is the tool built for replacing text: sed -i.bak 's/^port=8080$/port=9090/' app.conf. (3) cp -r copies all 50 GB every night; rsync -a --delete src/ server:dst/ sends only the changes and can resume. (4) nginx is a systemd service with a restart policy: kill makes systemd start it again. Use sudo systemctl stop nginx (and disable if it must stay off).

Quick check One-line rule for cp vs rsync?
Answer: cp for a one-time local copy; rsync whenever you copy again or over the network.

Quick revision

Lesson 13.6 in one screen

  • Name the job first: search, extract, filter, compute, change, find files, copy, compare, stop, schedule.
  • Text: grep (lines), cut (fixed column), awk (column conditions, maths), sed (replace), tr (characters).
  • Files: find (live, tests) vs locate (index, instant); cp (once) vs rsync (again, remote); tar (Linux) vs zip (Windows); gzip (fast) vs xz (small).
  • Network: scp (one file) vs rsync (folders, resume) vs sftp (browse); curl (APIs) vs wget (downloads).
  • Processes: kill (PID) vs pkill (name) vs systemctl (services). Compare: diff (text) vs cmp (binary) vs comm (lists) vs sha256sum (remote).
  • Identify: type (aliases, built-ins) vs which (PATH) vs whereis (with man pages). Schedule: at (once) vs cron/timers (repeat).

Interview and viva questions

When should I use awk instead of grep?

When you need a condition on a specific column or computation; grep only selects lines.

What is the difference between sed and awk?

sed edits text (replace, delete lines); awk processes columns and computes.

find or locate?

find searches live with tests (size, age); locate searches a daily name index instantly.

cp or rsync?

cp for one local copy; rsync for repeated, large or remote copies (only changes, resume, dry run).

scp or rsync?

scp for a quick single file; rsync for folders and repeated syncs.

curl or wget?

curl for APIs and many protocols; wget for downloading files and sites.

kill or systemctl stop?

systemctl stop for services (otherwise systemd may restart them); kill/pkill for ordinary processes.
