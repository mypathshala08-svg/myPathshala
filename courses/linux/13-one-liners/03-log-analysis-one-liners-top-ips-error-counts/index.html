Log analysis one-liners: top IPs, error counts, status codes and response times

Answer “how bad, since when, who, where, how slow” from raw logs in minutes: learn the fields of an access log once, then filter, pick, count and rank.

The problem

10:15 a.m.: customers report that the shop’s login page is broken and the website feels slow. The on-call dashboard is down, but Riya can SSH into the web server. She has an access log with 1,320 requests, an application log and the SSH auth log. In ten minutes she must answer: how bad is it (status codes), since when (requests per minute), who (top IPs), where (failing URLs), how slow (response times) and is it an attack? Every answer is a one-liner built from grep, cut, awk, sort, uniq and a few friends. This lesson builds each one on a realistic log and shows the real output.

By the end of this page you will be able to:
  • read a web access log line by line and pick out fields with awk and cut
  • count and rank anything with sort | uniq -c | sort -rn (status codes, IPs, URLs, user agents)
  • slice logs by time, compute totals, averages and slow requests with awk, and follow live logs with tail -f
  • spot brute-force attacks in auth logs and turn the one-liners into a reusable incident report

2 Definition

Access logs and log one-liners

Formal definition (write this in exams)

A web access log records one line per request: client IP, time, request line (method, URL, protocol), status code, bytes sent, referrer, user agent and often the response time. Log analysis one-liners combine filters (grep, awk patterns), field extraction (awk, cut) and aggregation (sort, uniq -c, awk sums) to answer questions such as “which IPs”, “which URLs”, “how many errors” and “since when”.

In simple words

Filter the lines, pick the field, count or compute, sort the answer.

Log analysis at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a log line has labelled pieces

Each request is one line; each piece has a position.

Basic What you will type

  • tail -n 20 access.log: the latest requests.
  • grep -c ' 500 ' access.log: how many server errors.
  • awk '{print $1}' access.log | sort | uniq -c | sort -rn | head: top visitors.
  • tail -f access.log | grep --line-buffered ' 50[0-9] ': watch errors live.

Intermediate The patterns

  • Count and rank: sort | uniq -c | sort -rn (sort first, uniq only merges neighbours).
  • Match a field, not the line: awk '$9==500' instead of grep 500 (500 also appears in sizes and times).
  • Time windows: the time field sorts as text within one day, so $4 >= "[11/Nov/2026:10:00" works.
  • Numbers: awk '{s+=$NF; if($NF>m)m=$NF} END{print s/NR, m}' for average and maximum.
  • Rotated logs: zcat access.log.*.gz | … or zgrep.

Advanced Behind the screen: formats, locales and speed

  • This is the Apache/Nginx combined format plus $request_time at the end; your server’s log_format may differ, so check one line first.
  • awk splits on runs of blanks; a URL with a space (rare, encoded as %20) would shift fields. awk -F'"' splits at quotes instead: field 2 is the request, field 6 the user agent.
  • sort is locale-aware; LC_ALL=C sort is several times faster on big logs and sorts bytes.
  • For gigabyte logs, filter early (grep is very fast), sort late, and prefer awk associative arrays over sort | uniq for counting (one pass, no sort of every line).
  • grep --line-buffered (or stdbuf -oL) is needed after tail -f, otherwise output waits in a 4 KiB buffer.
  • Logs are evidence: copy them before experimenting, and remember they may contain personal data.

Did you know? The default web log format was defined by NCSA httpd in 1993 (the “common log format”); Apache added referrer and user agent as the “combined” format. Thirty years later most tools still read exactly that layout.

Exam tip: “How do you find the top 10 IP addresses in an access log?” → awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10.

Quick check Why is grep 500 a bad way to count server errors?
Answer: 500 can appear anywhere in the line (byte counts, times, URLs). Match the status field: awk '$9==500'.
Common mistake
✗awk '{print $1}' access.log | uniq -c
✓awk '{print $1}' access.log | sort | uniq -c | sort -rn

uniq only merges identical neighbouring lines; without sort the same IP appears many times with small counts (real run).

Common mistake
✗awk '{s+=$11} END{print s/NR}'
✓awk '{s+=$NF} END{print s/NR}' (check the field numbers on one line first)

Field 11 is the quoted referrer "-", which counts as 0. The response time is the last field, $NF.

4 Step by step

Counting, ranking, slicing and computing, then used in every field

All outputs were recorded on our Ubuntu 24.04 build machine as riya, in ~/lg: access.log (1,320 requests on 11 Nov 2026 from 08:00 to 15:59, combined format with the response time at the end, including an incident around 10:02–10:07), app.log (10 application lines) and auth.log (7 SSH lines).

awk '{print $N}' | sort | uniq -c | sort -rn · grep -c count and rank

🟢 Read-onlyno sudo

Pick the field with awk, sort so equal values are next to each other, uniq -c to count them, sort -rn to put the biggest first, head to keep the top. To count lines that match a condition, use grep -c or awk 'cond' | wc -l.

✓ Use it when
  • first look during any incident
  • daily traffic reports
✗ Don’t use it when
  • grep for numbers that can appear in many fields

substr($4,14,5) · uniq -c · $4 >= "[…" && $4 < "[…" slicing by time

🟢 Read-onlyno sudo

The time field looks like [11/Nov/2026:10:02:13. Characters 14–15 are the hour, 14–18 hour:minute. Because the log is in time order, uniq -c on the minute gives requests per minute. For a window, compare the field as text: within one day the format sorts correctly.

✓ Use it when
  • finding when an incident started and ended
  • traffic per hour
✗ Don’t use it when
  • comparing times across different days as text

awk '{s+=$NF} END{print s/NR}' · arrays a[$7]+=$NF sums, averages and maximums

🟢 Read-onlyno sudo

awk keeps numbers in variables across lines: sum with s+=$NF, count with n++, maximum with if($NF>m)m=$NF, and print in END. With associative arrays you can do it per URL or per IP in one pass. Use printf for neat columns.

✓ Use it when
  • slowness, traffic volume, capacity planning
✗ Don’t use it when
  • averages alone (one slow request hides in them)

Syntax: awk '{s+=$NF} END{printf "%.3f\n", s/NR}' access.log

Undo and safety net

Reading logs changes nothing; acting on them can.

  • Analysis looks wrong: check one line’s fields first: head -1 access.log | awk '{for(i=1;i<=NF;i++) print i, $i}'.
  • Log rotated mid-incident: include access.log.1 and zcat access.log.*.gz.
  • Blocked the wrong IP: remove the firewall rule (Lesson 19.1); check for NAT/proxy IPs before blocking.
  • Big log is slow: filter first, LC_ALL=C, count with awk arrays.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. awk '{print $9' access.log
    awk: line 2: missing } near end of file exit status: 2

    What it means: Missing closing brace in the awk program.

    Fix: awk '{print $9}'

  2. cd ~/lg; grep -c 'HTTP/2.0' access.log
    0 exit status: 1

    What it means: grep -c prints 0 and exits 1 when nothing matches.

    Fix: Not an error: status 1 means no match.

  3. tail -n 5 /var/log/auth.log
    tail: cannot open '/var/log/auth.log' for reading: No such file or directory exit status: 1

    What it means: This machine has no auth.log: it logs SSH to the journal only (on other systems auth.log exists but is readable only by root and group adm).

    Fix: journalctl -u ssh, or sudo tail /var/log/auth.log.

  4. cd ~/lg; zcat access.log > /dev/null
    gzip: access.log: not in gzip format exit status: 1

    What it means: zcat on a file that is not gzip-compressed.

    Fix: Use cat, or zcat only on .gz files.

6 Real-world use

Log one-liners at work

1. Incident triage

Before dashboards load, on-call engineers run status counts, per-minute errors and top failing URLs on the server.

Alert→one-liners→cause

2. Spotting attacks

A spike of 401s or SSH failures from one IP is brute force; the same one-liners feed block lists and fail2ban rules.

Spike→top IPs→block

3. Performance reviews

Average and p95 response time per endpoint show which API needs work.

Log→awk arrays→slow endpoints

4. Website health

Top 404 URLs reveal broken links after a redesign; marketing gets the list.

Log→$9==404→fix links

5. Daily reports

A cron job mails yesterday’s traffic, errors and top pages, built from the same one-liners (Lesson 17.4).

Script it: incident.sh

Produce an incident summary from an access log: totals, status codes, error rate, top IPs for 401/5xx, failing URLs, the busiest minute and the slowest endpoint, with an optional time window.

log=${1:-$HOME/lg/access.log}; from=${2:-00:00}; to=${3:-23:59}
[ -r "$log" ] || { echo "cannot read $log" >&2; exit 1; }
w=$(mktemp); trap 'rm -f "$w"' EXIT
awk -v f="$from" -v t="$to" '{m=substr($4,14,5)} m>=f && m<=t' "$log" > "$w"
echo "== ${log##*/}  $from-$to  ($(wc -l < "$w") requests) =="
echo "status codes:"; awk '{print $9}' "$w" | sort | uniq -c | sort -rn | head -4 | sed 's/^ */  /'
awk '{n++; if($9>=500)e++} END{printf "server error rate: %.1f%%\n", n?100*e/n:0}' "$w"
echo "top 401 sources:"; awk '$9==401{print $1}' "$w" | sort | uniq -c | sort -rn | head -2 | sed 's/^ */  /'
echo "failing URLs (5xx):"; awk '$9>=500{print $7}' "$w" | sort | uniq -c | sort -rn | head -2 | sed 's/^ */  /'
echo "busiest minute: $(awk '{print substr($4,14,5)}' "$w" | uniq -c | sort -rn | head -1 | awk '{print $2" ("$1" req)"}')"
awk '{t[$7]+=$NF;n[$7]++} END{for(u in t) print t[u]/n[u], u}' "$w" | sort -rn | head -1 | awk '{printf "slowest endpoint: %s (%.3f s avg)\n", $2, $1}'
== access.log 00:00-23:59 (1320 requests) == status codes: 948 200 123 403 120 401 71 404 server error rate: 3.1% top 401 sources: 120 203.0.113.50 failing URLs (5xx): 9 /index.html 7 / busiest minute: 10:04 (23 req) slowest endpoint: /index.html (0.332 s avg)

Run without arguments, so it reports on the whole day of the sample log (try incident.sh ~/lg/access.log 10:00 10:15 on your PC).

Puzzle answer Remember the question from the story? Open to check your guess.

1. uniq -c only merges neighbouring identical lines; the IPs were not sorted, so each run of the same IP was counted separately. Add sort before uniq -c. 2. grep 500 matches “500” anywhere: in byte counts, in times like 0.500 and in URLs. Test the status field: awk '$9==500'. 3. Field 11 is the quoted referrer "-", which awk treats as 0. The response time is the last field: $NF. Print one line’s fields first to get the numbers right.

Quick check Which command shows only new log lines as they arrive?
Answer: tail -f (with grep --line-buffered if you filter).

Quick revision

Lesson 13.3 in one screen

  • Combined format: $1 IP, $4 time, $6 method, $7 URL, $9 status, $10 bytes; here $NF = response time; -F'"' $6 = user agent.
  • Count and rank: awk '{print $N}' | sort | uniq -c | sort -rn | head.
  • Match fields, not lines: awk '$9>=500' instead of grep 500.
  • Time: substr($4,14,2) hour, substr($4,14,5) minute; windows by text comparison of $4; uniq -c per minute.
  • Numbers: s+=$NF, n++, max; per group with arrays a[$7]+=$NF; p95 with sort -n.
  • auth.log: Failed password / invalid user / Accepted; grep -oE "from [0-9.]+"; tail -f | grep --line-buffered for live.

Interview and viva questions

How do I find the top IP addresses in an access log?

awk '{print $1}' access.log | sort | uniq -c | sort -rn | head.

How do I count HTTP status codes?

awk '{print $9}' access.log | sort | uniq -c | sort -rn.

How do I see errors per minute?

awk '$9>=500 {print substr($4,14,5)}' access.log | uniq -c.

How do I find failed SSH logins?

grep 'Failed password' /var/log/auth.log (or journalctl -u ssh), then grep -oE 'from [0-9.]+' | sort | uniq -c.

How do I analyse rotated .gz logs?

zcat -f access.log* | … or zgrep.

Why does uniq -c show the same value several times?

The input was not sorted; uniq only merges adjacent lines.

How do I watch a log live and filter it?

tail -f file | grep --line-buffered pattern.

What is in the combined log format?
IP, ident, user, time, request, status, bytes, referrer, user agent.
401 vs 403?
Not authenticated vs not allowed.

How to include rotated logs?
zcat -f access.log*.
Why grep --line-buffered with tail -f?
So lines are not held in a buffer.
