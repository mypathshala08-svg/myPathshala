2 Definition

pwd, cd and ls

Formal definition (write this in exams)

Every process has a current working directory, maintained by the kernel, from which relative path names are resolved. pwd (print working directory) prints the absolute path of the shell’s current working directory. cd (change directory) is a shell builtin that changes it using the chdir() system call. ls (list) lists the entries of a directory and, with options such as -l, their attributes read from each file’s inode.

In simple words

You are always “in” one folder. pwd tells you which, cd moves you, ls shows what is there.

Moving around at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a mall with a map

Imagine walking around a big mall.

  • pwd is the “You are here” sticker on the map.
  • cd is walking to another shop (folder).
  • ls is looking through the shop window to see what is inside.
  • You are always standing in exactly one place. Everything you ask for is found from where you stand, unless you give the full address.

Basic The everyday moves

  • pwd prints the full path of the current folder: /home/riya/projects.
  • cd folder goes into a folder; cd .. goes up one level; cd or cd ~ goes home; cd / goes to the top; cd - goes back to the previous folder.
  • ls lists names; ls -l adds details; ls -a includes hidden names (starting with a dot); ls -h shows sizes like 4.0K.
  • ls folder lists another folder without going there.

Intermediate ls like a professional

  • Combine options: ls -lah (long, all, human sizes) is the most typed form on servers.
  • Sorting: -t by time (newest first), -S by size, -r reverses. ls -ltr puts the newest file last, right above your prompt, ideal for logs.
  • -d shows a folder itself, not its contents (ls -ld /etc); -R lists recursively; -1 one name per line; -F adds markers: / folder, @ link, * executable.
  • -A is like -a but hides . and ..; -i shows inode numbers (Lesson 10.1).
  • Colours (blue folders, cyan links, green executables) come from --color=auto, usually set as an alias in ~/.bashrc.

Advanced What really happens: chdir, PWD and symlinks

  • The current directory belongs to the process and is kept by the kernel. cd calls the chdir() system call, which is why cd must be a shell builtin: a separate program could only change its own directory.
  • Child processes inherit the directory; a script that does cd changes only its own copy, not your terminal’s.
  • bash also keeps the variables PWD and OLDPWD; cd - uses OLDPWD.
  • Through a symbolic link, pwd shows the logical path you typed (/srv/app/current); pwd -P shows the physical path (/srv/app/releases/2026-11-05). Deployment tools rely on this.
  • ls -l gets each detail from the file’s inode through the statx() system call; only the name comes from the directory itself.

Did you know? Your shell is not the only program with a current directory: every process has one, and you can see it. ls -l /proc/$$/cwd shows your shell’s, and ls -l /proc/<PID>/cwd shows any program’s, which helps when a server process writes files “somewhere” and nobody knows where.

Exam tip: “Explain pwd, cd and ls with examples” → one-line definition each; cd forms (cd, cd ~, cd .., cd -, cd /path); ls options -l -a -h -t -r -S -R -d; explain the 7 columns of ls -l; state that cd is a builtin because it changes the shell’s own working directory.

4 Step by step

A professional’s routine on an unfamiliar server

  1. 1. Where did I land?

    pwd right after logging in. Usually your home, /home/<you>.

    Behind the screen: the login process set the shell’s working directory to the home folder from /etc/passwd.

  2. 2. What is here, including hidden files?

    ls -la

    Behind the screen: ls reads the directory entries, then the inode of each name for the details.

  3. 3. Jump to where the work is

    cd /var/log/app (use Tab to complete each part).

    Behind the screen: bash calls chdir(); the kernel checks you have execute (x) permission on every folder in the path.

  4. 4. Find the newest file

    ls -ltr: the last line is the newest.

    Behind the screen: ls sorts by the modification time (mtime) stored in each inode.

  5. 5. Pop back and forth

    cd /etc/app to check the config, then cd - to return to the logs.

    Behind the screen: bash saved the previous folder in OLDPWD.

  6. 6. Go home when done

    cd on its own.

    Behind the screen: with no argument, cd uses the HOME variable.

5 See it happen

Moving around, and who keeps track

Left: Riya’s terminal (outputs shortened). Right: the kernel’s current directory and bash’s PWD and OLDPWD.

Who remembers where you are? 5 steps
What you see
  1. pwd prints /home/riya, where every login starts.
  2. cd /var/log/nginx. The prompt now shows the folder.
  3. ls -ltr lists the logs, oldest first, so the newest is on the last line. (Shortened.)
  4. She checks the config in /etc/nginx, then cd - brings her straight back.
  5. cd on its own: home.
Behind the screen
  1. The kernel keeps a current directory for every process. Right now bash’s is /home/riya.
  2. bash’s cd asks the kernel to change it (chdir); bash also updates its PWD and OLDPWD variables.
  3. ls runs as a child process, starts in the same directory, and reads the directory and each file’s inode.
  4. cd - is short for “cd to OLDPWD”. That is why it can toggle between two places.
  5. With no argument, cd goes to $HOME. A script’s cd changes only the script’s own process, never your terminal’s.

Which release is live? pwd vs pwd -P

A common deployment pattern uses a symbolic link named current. Folder names and dates are examples.

Logical and physical paths 5 steps
Animated example
  1. Each release goes into a dated folder; a link current points to the live one.

Layer by layer: dissect one line of ls -l

Take the line -rw-r--r-- 1 riya riya 13 Nov 5 18:41 notes.txt and open each column: what it means, why it exists, where ls really gets it from, and where you will use it. Each comes with the real stat value for the same file (recorded on our build machine).

One ls -l line, seven pieces of information. Click a column.

-rw-r--r-- type + permissions

Why does it exist?

You must know at a glance what a name is (file, folder, link) and who may read or change it.

How does it work?

The first character is the type (- file, d folder, l link). Then three groups of rwx: owner, group, others.

Where is it, really?

The mode field of the file’s inode.

Where is it used?

Every “Permission denied” you will ever fix (Module 9).

See this layer yourself (real output)

stat -c '%A  (octal %a)' notes.txt
-rw-r--r-- (octal 644)

1 hard-link count

Why does it exist?

One file can have several names; the system must know when the last name is gone.

How does it work?

Counts directory entries pointing to this inode. Folders show 2 or more (their own . and each child’s ..).

Where is it, really?

The link-count field of the inode.

Where is it used?

Understanding hard links and why a deleted file may still exist (Module 10).

See this layer yourself (real output)

stat -c '%h' notes.txt
1

riya riya owner and group

Why does it exist?

Permissions need someone to apply to: one owner user and one group.

How does it work?

The inode stores numbers (UID, GID); ls turns them into names using /etc/passwd and /etc/group.

Where is it, really?

uid and gid fields of the inode.

Where is it used?

chown, chgrp, shared team folders (Modules 8 and 9).

See this layer yourself (real output)

stat -c 'user %U (UID %u), group %G (GID %g)' notes.txt
user riya (UID 30033), group riya (GID 30033)

13 size in bytes

Why does it exist?

To know how big a file is, and to find space hogs.

How does it work?

The exact byte count: “chai at 4:30” is 12 characters plus a newline. -h turns large numbers into K, M, G.

Where is it, really?

The size field of the inode (for folders: the size of the directory listing itself, often 4096).

Where is it used?

Disk-full investigations, checking downloads.

See this layer yourself (real output)

stat -c '%s bytes' notes.txt
13 bytes

Nov 5 18:41 last modification

Why does it exist?

Finding the newest log, the file someone just changed, or a stale backup.

How does it work?

The time the content last changed (mtime). Files older than about six months show the year instead of the time.

Where is it, really?

The mtime field of the inode; stat also shows access and change times (Lesson 2.4).

Where is it used?

ls -lt, backups, “what changed last night?”.

See this layer yourself (real output)

stat -c '%y' notes.txt
2026-11-05 19:07:40.827243728 +0530

notes.txt the name

Why does it exist?

Humans need names; the system works with inode numbers.

How does it work?

The name is stored in the directory, not in the inode: a directory is a list of name → inode pairs.

Where is it, really?

A directory entry; ls -i shows the inode number next to the name.

Where is it used?

Renaming is cheap: only the directory entry changes (Lesson 10.1).

See this layer yourself (real output)

ls -i notes.txt
796576 notes.txt
Quick check In ls -l, where does the file’s name come from, and where do all the other columns come from?
Answer: The name comes from the directory entry; every other column comes from the file’s inode.
6 Real-world use

pwd, cd and ls at work

1. Support: “send me the latest log”

Support engineers run ls -ltr in a log folder to pick the newest file before reading it.

Ticket→ls -ltr→right log

2. Developers: hidden project files

Projects keep important hidden files (.git, .env, .gitignore). ls -la is the first thing to type in a new repository.

New repo→ls -la→see .env/.git

3. Deployments with a current link

Release tools deploy into dated folders and switch a current link; pwd -P and ls -l show what is really live.

Deploy→switch link→rollback ready

4. Safe scripts

Scripts write cd /opt/app || exit 1, so that if the folder is missing the script stops instead of running commands in the wrong place.

Script→cd … || exit→no accidents

5. Quick space checks

Before deeper analysis, ls -lhS in a folder shows the biggest files in a second.

Space alert→ls -lhS→big file found

Where is this process working?

Scenario: A program writes files to a mystery folder. Find its current directory without stopping it.

ls -l /proc/$$/cwd

$$ is your shell’s PID; /proc/<PID>/cwd is a link to that process’s current directory. Replace $$ with any program’s PID.

Puzzle answer Remember the question from the story? Open to check your guess.

Because the current directory belongs to each process, and a script runs as a separate child process. Its cd changes the script’s own directory (the kernel keeps one per process); your terminal’s shell is a different process and keeps its own. That is exactly why cd must be built into the shell: an external cd program could never change your shell’s directory. To change your shell’s folder from a file, run it with source file instead (Lesson 12.5).

  • The current directory is kept by the kernel per process; cd calls chdir(), so it must be a builtin.
  • bash keeps PWD and OLDPWD; a script’s cd never moves your terminal.
  • pwd logical vs pwd -P physical (through symlinks). Scripts: cd dir || exit 1.

Interview and viva questions

What is the difference between cd .. and cd -?

cd .. goes to the parent folder (one level up). cd - goes back to the previous folder you were in, wherever that was, using $OLDPWD.

What is the difference between ls -a and ls -A?

Both show hidden entries. -a also shows . and .. ; -A (almost all) leaves those two out.

Explain the output of ls -l.

File type and permissions, number of hard links, owner, group, size in bytes, last modification time, and name. Example: -rw-r--r-- 1 riya riya 13 Nov 5 18:41 notes.txt.

Why is cd a built-in command?

The working directory is a property of each process. An external program would change only its own directory and exit; the shell must call chdir() itself.

What is the difference between pwd and pwd -P?

pwd prints the logical path, including symbolic links you followed. pwd -P prints the physical path with all links resolved.

How do you list only directories?

ls -d */ (the pattern matches folders only), or ls -l | grep ^d, or find . -maxdepth 1 -type d.

Real-world scenario questions (asked in company interviews)

Interview questions about moving around and listing, as asked for support, DevOps and developer roles.

Any company · basicsFresher

“Explain ls -l output.”

The interviewer writes drwxr-x--- 2 app app 4096 Nov 5 10:02 data on the board and asks you to read it.

The interviewer is checking: can you read each column calmly?

Show a strong answer
  • d: a directory. rwx owner can read, write, enter; r-x group can read and enter; --- others nothing.
  • 2: hard-link count (a folder: itself and its own .). app app: owner and group.
  • 4096: size of the directory listing itself, not its contents. Then the last modification time and the name.

Avoid: saying 4096 is the size of everything inside the folder.

Operations · supportJunior

Find the latest log fast

A service just crashed. You are in your home folder on the server. Show the last lines of the newest log in /var/log/app.

The interviewer is checking: do you combine cd, ls and a reading tool efficiently?

Show a strong answer
  1. cd /var/log/app && ls -ltr | tail -3: the newest files are at the bottom.
  2. tail -50 "$(ls -t | head -1)", or simply the name you saw.
  3. After checking the config (cd /etc/app), return with cd -.

Avoid: opening every file with cat until one looks recent.

Platform team · conceptsMid-level

“My script runs cd, but my terminal didn’t move.”

A teammate reports a bug: ./goto-project.sh contains cd ~/project but after running it they are still in the old folder.

The interviewer is checking: do you understand processes and the working directory?

Show a strong answer
  • The script runs in a child process; the kernel keeps a separate working directory per process. Its cd changes only itself.
  • Fix: run it in the current shell with source goto-project.sh (or . goto-project.sh), or make it a function or alias in ~/.bashrc.
  • Same reason cd must be a builtin.

Avoid: “add sudo”.

DevOps · deploymentsMid-level

Which release is live?

Production runs from /srv/shop/current. A colleague asks which release is actually running.

The interviewer is checking: do you understand symbolic links and logical vs physical paths?

Show a strong answer
  • ls -l /srv/shop/current shows current -> releases/2026-11-05, or readlink -f.
  • Inside it, pwd -P prints the physical path; plain pwd prints .../current.
  • Rollback = repoint the link to the previous release, then restart or reload the service.

Avoid: copying release folders over each other.
