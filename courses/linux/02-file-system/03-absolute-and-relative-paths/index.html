2 Definition

Absolute and relative paths

Formal definition (write this in exams)

A path is a sequence of names separated by / that identifies a file in the directory tree. An absolute path begins with / and is resolved from the root directory. A relative path does not begin with / and is resolved from the current working directory of the process. The entries . and .. in every directory refer to the directory itself and to its parent; the shell expands ~ to the home directory.

In simple words

An absolute path is a full address from /; a relative path is directions from where you are now.

Paths at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: an address vs directions

There are two ways to tell a friend where you live.

  • A full address works from anywhere: that is an absolute path. On Linux it always starts with /.
  • Directions (“two doors left of the tea shop”) only work from one starting point: that is a relative path. It starts from the folder you are in.
  • .. means “one step back up”; . means “right here”; ~ means “my home”.

Basic The rules

  • Starts with / → absolute: read from the root. /etc/hostname is the same file whoever types it, from wherever.
  • Anything else → relative: read from the current folder. notes.txt means $(pwd)/notes.txt.
  • .. is the parent folder, . the current folder, ~ your home (/home/riya), ~kabir Kabir’s home.
  • Folders are separated by /. Names are case-sensitive: Data and data are different.
  • Tab completes a name; pressing Tab twice lists all choices when there are several.

Intermediate Using paths well

  • Mix them: ~/lab/../lab/data is valid; realpath cleans it up to a simple absolute path.
  • dirname and basename split a path into its folder and its last part; basename file.csv .csv also removes an extension.
  • Names with spaces need quotes: cd "My Documents" or a backslash cd My\ Documents. Tab adds the backslash for you.
  • ~+ is the current folder and ~- the previous one (same as $PWD and $OLDPWD).
  • To run a program in the current folder you must write ./run.sh: the shell only searches PATH for names without a slash.

Advanced Behind the screen: path resolution

  • ~ is expanded by the shell before the command runs; the kernel never sees it. In quotes ("~/lab") it is not expanded.
  • The kernel resolves a path one component at a time (in the Linux source this is fs/namei.c, “name to inode”): start at / for absolute paths or at the process’s current directory for relative ones, then look each name up in the directory found so far.
  • For every folder on the way you need execute (x) permission (“search”); otherwise “Permission denied”, even if the file itself is readable.
  • . and .. are real entries in every directory; /.. is / itself. Symbolic links met on the way are followed (up to 40 times, else “Too many levels of symbolic links”).
  • Limits: a single name may be 255 bytes (NAME_MAX), a whole path 4096 bytes (PATH_MAX). Repeated slashes count as one: /usr///bin = /usr/bin.

Did you know? Tab completion is not magic built into Linux; it is a feature of the shell, and it is programmable. When you type git che and press Tab, bash runs a small completion function shipped with git that knows git’s sub-commands. You can see what plain file completion would offer with compgen -f -- prefix.

Exam tip: “Differentiate between absolute and relative path names with examples” → definition of each; absolute starts with / and is independent of the current directory; relative depends on it; give the same file both ways (e.g. /home/riya/notes.txt vs notes.txt from /home/riya); mention ., .. and ~.

4 Step by step

How cat ../data/sales.csv finds the file

  1. 1. The shell reads your line

    No ~, no wildcards, so the shell passes ../data/sales.csv to cat unchanged.

    Behind the screen: tilde and wildcard expansion happen in the shell, before any program runs.

  2. 2. Where to start?

    The path does not start with /, so the kernel starts at the current directory: /home/riya/lab/reports.

    Behind the screen: cat calls openat(AT_FDCWD, "../data/sales.csv"); AT_FDCWD means “the current directory”.

  3. 3. Step “..”

    Look up .. in reports: it is the parent, /home/riya/lab.

    Behind the screen: the kernel needs x permission on reports to search it.

  4. 4. Step “data”

    Look up data in lab: a directory. Continue.

    Behind the screen: the name → inode lookup is usually answered from the dentry cache in RAM.

  5. 5. Step “sales.csv”

    Look up sales.csv in data: a regular file. Found.

    Behind the screen: now read permission on the file itself is checked.

  6. 6. Open and read

    The kernel returns a file descriptor; cat reads and prints the contents.

    Behind the screen: if any step had failed, you would see “No such file or directory” (ENOENT) or “Permission denied” (EACCES).
Quick check From /home/riya, the same command fails. At which step does it fail?
Answer: Step 3/4: .. from /home/riya is /home, and /home has no data entry, so the lookup fails with “No such file or directory”.

Walking a path, one folder at a time

Left: the directory tree and the route each path takes. Right: the kernel looking up each component in turn.

Absolute vs relative: what the kernel walks 5 steps
What you see
  1. Riya is in reports. The absolute path names the file from the very top.
  2. The route goes from / down through home, riya, lab and data. It would be the same from any folder.
  3. The relative path ../data/sales.csv is directions from where she stands.
  4. .. climbs to lab, then down to data and the file. Shorter, but tied to her position.
  5. Run from home, the same directions lead to /home, which has no data folder.
Behind the screen
  1. An absolute path makes the kernel start at the root directory, inode 2.
  2. Each component is looked up in the folder found so far; every folder needs x (search) permission.
  3. A relative path starts at the current directory the kernel keeps for this process.
  4. .. is a real entry pointing to the parent. Four lookups and the file is found.
  5. One lookup fails and the whole open fails: error ENOENT, printed as “No such file or directory”.

Real-time scenario 3 · advanced

Why ./ is needed to run a script

Every beginner hits this. The reason is how the shell decides what to run, and it is a security feature.

Names with and without a slash 5 steps
Animated example
  1. deploy.sh is right there, but typing its name gives “command not found”.
  2. A command name without any / is searched only in the PATH folders, and the current folder is not one of them.
  3. ./deploy.sh is a relative path (it has a slash), so the shell runs exactly that file.
  4. Leaving . out of PATH protects you from running a fake ls planted in a shared folder.
  5. Any path with a slash works: relative, absolute, or ask bash to read the file.

6 Real-world use

Paths at work

1. Cron jobs and services: always absolute

Schedulers start jobs in a different folder with a minimal PATH, so crontab lines and systemd units use absolute paths for programs and files.

Schedule→absolute paths→job runs at 2 a.m.

2. Code projects: relative inside the repo

Inside a project, code refers to files relatively (./src, ../config), so the project works wherever it is cloned.

git clone→relative paths→works anywhere

3. Deployment scripts

Install and deploy scripts find their own folder with dirname "$0" (or realpath) and build every other path from it.

Run from CI→script dir→right files

4. Containers and configs

Tools such as Docker Compose resolve relative paths in their files from the file’s own folder, a rule worth checking in every tool you use.

Config file→which base?→right mount

5. Everyday speed

Support engineers move around unfamiliar servers with Tab completion: fewer typos, and an instant signal when a path does not exist.

New server→Tab→fast and correct

Examples are simplified and generic. They describe common patterns, not the internal systems of any particular company.

Beginner

Build it step by step: a script’s own folder, absolute

Scenario: A script must find files next to itself, whatever folder it is started from. Grow the expression step by step. (Here the script is /home/riya/script.sh, run from ~/lab.)

  1. The path that was used to start the script.

    echo "$0"
    /home/riya/script.sh

  2. Only its folder part.

    dirname "$0"
    /home/riya

  3. Go there and print it: an absolute folder, even if $0 was relative.

    cd "$(dirname "$0")" && pwd
    /home/riya

  4. Store it once and build every path from it. The classic first line of robust scripts.

    here="$(cd "$(dirname "$0")" && pwd)"; echo "data file: $here/data/sales.csv"
    data file: /home/riya/data/sales.csv

Interview and viva questions

What is the difference between an absolute and a relative path?

An absolute path starts with / and is resolved from the root, so it means the same from any folder. A relative path does not start with / and is resolved from the current working directory.

What do . and .. mean?

. is the current directory and .. is its parent. Both are real entries in every directory.

Why do I have to type ./ to run a script?

A command name without a slash is searched only in the directories listed in PATH, and the current directory is not in PATH for safety. ./script.sh is a path, so the shell runs that exact file.

What does ~ mean?

The home directory of the current user (the value of $HOME). ~name is the home directory of user name. The shell expands it; it is not expanded inside quotes.

How do I get the absolute path of a file?

realpath file (or readlink -f file). Both remove ., .. and symbolic links.

Why does my script work in one folder and fail in another?

It uses relative paths, which depend on the current working directory. Build paths from the script’s own location (dirname "$0") or use absolute paths.

Practice problems

Tasks about paths. Expected outputs come from real runs on Ubuntu 24.04 (start folder: ~/lab).

P1Easy

Absolute or relative?

For each of /etc, notes, ../x and ./run.sh, print whether it is absolute or relative.

Input
/etc notes ../x ./run.sh
Expected output
/etc: absolute
notes: relative
../x: relative
./run.sh: relative
Show solution and explanation 
for p in /etc notes ../x ./run.sh; do
  case $p in /*) echo "$p: absolute" ;; *) echo "$p: relative" ;; esac
done
/etc: absolute notes: relative ../x: relative ./run.sh: relative

How it works: The pattern /* matches anything that starts with a slash.

P2Easy

Clean path

Print the clean absolute form of /usr/./bin/../lib.

Input
/usr/./bin/../lib
Expected output
/usr/lib
Show solution and explanation 
realpath /usr/./bin/../lib
/usr/lib

How it works: . disappears, bin/.. cancels out: /usr/lib.

P3Easy

Home in quotes

Print the path of notes.txt in your home folder from inside double quotes, correctly expanded.

Input
(none)
Expected output
/home/riya/notes.txt
Show solution and explanation 
echo "$HOME/notes.txt"
/home/riya/notes.txt

How it works: $HOME expands inside double quotes; ~ would not.

P4Medium

Relative route

Create web/css and web/img. Print the relative path from web/css to web/img/logo.png.

Input
web/css, web/img/logo.png
Expected output
../img/logo.png
Show solution and explanation 
mkdir -p web/css web/img && touch web/img/logo.png
realpath --relative-to=web/css web/img/logo.png
../img/logo.png

How it works: The route is ../img/logo.png: exactly what a stylesheet would write.

P5Medium

Folder and name

Given /srv/backups/2026-11-05/db.sql.gz, print the date folder and the file name.

Input
/srv/backups/2026-11-05/db.sql.gz
Expected output
date: 2026-11-05
file: db.sql.gz
Show solution and explanation 
f=/srv/backups/2026-11-05/db.sql.gz
echo "date: $(basename "$(dirname "$f")")"
echo "file: $(basename "$f")"
date: 2026-11-05 file: db.sql.gz

How it works: dirname, then basename of that, gives the folder’s own name.

P6Medium

Same name, two files

Create x/cfg and y/cfg with different text. From inside x, print cfg and ../y/cfg.

Input
x/cfg = "dev", y/cfg = "prod"
Expected output
dev
prod
Show solution and explanation 
mkdir x y && echo dev > x/cfg && echo prod > y/cfg
cd x
cat cfg ../y/cfg
dev prod

How it works: A relative name always depends on where you are.

P7Business problem

Check paths before a cron job

A job will use the paths /etc/hostname, /no/such/file and /usr/bin/env. Print OK or MISSING for each, so the job is not scheduled with broken paths.

Input
three absolute paths
Expected output
OK      /etc/hostname
MISSING /no/such/file
OK      /usr/bin/env
Show solution and explanation 
for p in /etc/hostname /no/such/file /usr/bin/env; do
  if [ -e "$p" ]; then echo "OK      $p"; else echo "MISSING $p"; fi
done
OK /etc/hostname MISSING /no/such/file OK /usr/bin/env

How it works: A pre-flight check like this catches typos before a job fails at 2 a.m.

P8Business problem

Portable project paths

A project keeps config/app.conf. Print the config’s absolute path from inside project/bin using only relative navigation and realpath.

Input
project/bin, project/config/app.conf
Expected output
/home/riya/lab/project/config/app.conf
port=80
Show solution and explanation 
mkdir -p project/bin project/config && echo "port=80" > project/config/app.conf
cd project/bin
realpath ../config/app.conf
cat ../config/app.conf
/home/riya/lab/project/config/app.conf port=80

How it works: Inside a repository, relative paths keep the project portable; realpath shows where they lead on this machine.

Real-world scenario questions (asked in company interviews)

Interview questions about paths, as asked for support, DevOps and developer roles.

Any company · basicsFresher

“Absolute vs relative path?”

The interviewer asks for the difference and an example of each for the same file.

The interviewer is checking: can you explain it with one clear example?

Show a strong answer
  • Absolute starts at /: /home/riya/notes.txt; same meaning from anywhere.
  • Relative starts at the current folder: from /home/riya just notes.txt; from /home/riya/docs it is ../notes.txt.
  • Mention ., .. and ~, and that ~ is expanded by the shell.

Avoid: saying relative paths are “shorter absolute paths”.

Operations · cronJunior

“My script works by hand but fails in cron.”

A backup script runs fine from the terminal but the cron job fails every night.

The interviewer is checking: do you know how cron’s environment differs?

Show a strong answer
  1. Cron starts jobs in the user’s home with a minimal PATH and no interactive startup files.
  2. So relative paths and commands found only in your custom PATH break. Use absolute paths, or cd /opt/backup || exit 1 at the start.
  3. Log output: ... >> /var/log/backup.log 2>&1, and test with env -i to simulate a bare environment (Lesson 17.4).

Avoid: “cron is broken, run it with sudo”.

Security · conceptsMid-level

“Why isn’t . in PATH?”

The interviewer asks why you must type ./tool instead of tool for a program in the current folder.

The interviewer is checking: do you see the security reason?

Show a strong answer
  • Names without a slash are searched in PATH; with . in PATH, a malicious ls placed in a shared folder like /tmp would run when you type ls there.
  • Even at the end of PATH it catches typos (sl). Explicit ./ means you always know what runs.

Avoid: “Linux is just strict”.

Kernel · internalsSenior

“What happens when you open a relative path?”

Explain what the kernel does for open("../data/x.csv").

The interviewer is checking: do you understand path resolution?

Show a strong answer
  • The syscall (openat with AT_FDCWD) starts from the process’s current directory; an absolute path would start at the process’s root directory.
  • The path is split on /; each component is looked up in the directory reached so far (dentry cache first, then the file system), checking x permission on each directory and following symbolic links (limit 40).
  • Failure modes: ENOENT, ENOTDIR, EACCES, ELOOP, ENAMETOOLONG. At the end, the final inode’s permissions are checked and a file descriptor is returned.

Avoid: not knowing that . and .. are real directory entries.
