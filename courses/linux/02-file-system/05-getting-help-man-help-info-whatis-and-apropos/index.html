2 Definition

man, --help, info, whatis, apropos and help

Formal definition (write this in exams)

Linux systems include offline documentation. man displays manual pages, organised in numbered sections, each describing one command, file format or interface. Most programs print a usage summary with the option --help. whatis shows the one-line description of a page, and apropos (man -k) searches those descriptions by keyword. The bash builtin help documents shell builtins, and info reads the longer, hyperlinked Texinfo manuals of GNU software.

In simple words

--help for a quick look, man for everything, apropos when you do not know the name, help for builtins.

Getting help at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a library on your computer

Your Linux comes with a whole library of instructions, already installed.

  • Each command has a short summary (like the back cover of a book) and a full manual (the whole book).
  • If you do not know which command you need, you search the catalogue by topic.
  • No internet is needed: it is all on the machine.

Basic The four commands to start with

  • command --help (or -h for some tools): a quick list of options, printed straight to the screen.
  • man command: the manual page. Keys: Space next page, b back, /word search, n next match, q quit.
  • whatis command: a one-line description. apropos word (same as man -k word): every command whose description mentions the word.
  • help cd: help for commands built into bash (cd, pwd, echo, export…), which have no man page of their own.

Intermediate Reading manuals like a professional

  • Manuals are split into numbered sections: 1 user commands, 5 file formats, 8 admin commands (table below). man 5 passwd explains the file /etc/passwd; man passwd shows the command.
  • A man page has standard parts: NAME, SYNOPSIS, DESCRIPTION, OPTIONS, EXIT STATUS, EXAMPLES, SEE ALSO.
  • In a SYNOPSIS, [ ] = optional, ... = may repeat, UPPERCASE or underlined = replace with your value, a|b = one or the other.
  • Combine with filters: ls --help | grep -i time, man -k compress, man -f printf (= whatis).
  • info coreutils holds long GNU manuals with chapters and links; many --help outputs end with “Full documentation … info '(coreutils) ls invocation'”.

Advanced Behind the screen: where the docs live

  • Man pages are compressed text files in roff format, e.g. /usr/share/man/man1/ls.1.gz. man finds the file, formats it with groff and shows it with a pager (less, or $MANPAGER).
  • whatis and apropos do not read every page: they search an index database built by mandb (run daily by a timer, or by hand with sudo mandb).
  • --help text is compiled into the program itself, so it always matches the installed version; man pages come with the package and can be removed (minimal Docker images often do this; Ubuntu’s unminimize restores them).
  • help exists because builtins are part of bash: their documentation is inside bash, and man bash covers them all in one huge page.
  • Section suffixes: 1p = POSIX version, 3p = Perl, ssl… man -a name shows every section in turn.

Did you know? The first Unix Programmer’s Manual was written by Ken Thompson and Dennis Ritchie in November 1971, and it already used numbered sections. The format has barely changed in over fifty years, which is why old man pages and new ones look so alike.

Exam tip: “Explain the man command and the sections of the manual” → man shows manual pages; list sections 1 (user commands), 2 (system calls), 3 (library functions), 4 (special files), 5 (file formats), 6 (games), 7 (miscellaneous), 8 (administration); example man 5 passwd vs man 1 passwd; mention whatis, apropos and --help.

4 Step by step

From “I don’t know the command” to the exact option

  1. 1. Search by topic

    apropos compress lists gzip, bzip2, xz, zip…

    Behind the screen: apropos searches the NAME lines in the mandb index, not the full pages.

  2. 2. Check one candidate

    whatis gzip: “compress or expand files”.

    Behind the screen: the same index, exact name match.

  3. 3. Quick summary

    gzip --help: the options at a glance.

    Behind the screen: the text is built into the gzip program itself.

  4. 4. Find one option fast

    gzip --help | grep -i keep → -k, --keep.

    Behind the screen: help text is just output, so any filter works on it.

  5. 5. Full details when needed

    man gzip, then type /keep and Enter, n for the next match, q to quit.

    Behind the screen: man formats ls.1.gz-style roff files and opens them in less.

  6. 6. Try it safely

    Test on a copy in a scratch folder before using it on real data.

    Behind the screen: reading is not enough; one test run removes all doubt.
Quick check In man, how do you search for the word “recursive” and jump to the next match?
Answer: Type /recursive and press Enter; press n for the next match (N for the previous).
5 See it happen

Where does the help come from?

Left: Riya asks for help on cd and ls (outputs shortened; the man page view is typical output). Right: which help system answers, and where its text is stored.

Which help system answers? 5 steps
What you see
  1. man cd finds nothing on a standard Ubuntu install. (Some systems open the bash builtins page instead.)
  2. type cd explains why: cd is built into bash.
  3. help cd prints the builtin’s documentation (in bash 4.4 and later, cd --help prints the same text).
  4. ls is a separate program, so it answers --help itself.
  5. And it has a man page in section 1.
Behind the screen
  1. A man page is a file installed by a package. bash does not install one per builtin.
  2. type tells you which route applies: builtin, alias, function or file.
  3. Builtin help is stored inside bash; help prints it.
  4. Programs print their own --help, so it always matches the installed version.
  5. man locates the compressed roff file, formats it and opens it in the pager.

Real-time scenario 2

Decoding a usage line

The first line of cp --help (real output on our build machine) looks cryptic. Every symbol has a meaning.

Reading a SYNOPSIS 5 steps
Animated example
  1. The first word is the command itself.
  2. [OPTION]...: options are optional (brackets) and you may give several (dots).
  3. Capital words are placeholders: put your real file names there.
  4. The “or:” line is a second form: many sources, then a directory.
  5. These conventions are the same in --help output and in man page SYNOPSIS sections.
Real-time scenario 3 · advanced

The command or the file? Manual sections

Riya must explain the columns of /etc/passwd in a ticket. The command’s manual will not help; the file’s manual will. Typical output on Ubuntu (shortened).

Manual sections 5 steps
Animated example
  1. whatis passwd shows two pages: the command (1) and the file (5).
  2. Plain man passwd opens section 1, the command.
  3. man 5 passwd describes each colon-separated field of the file (Lesson 8.1).
  4. Most configuration files have a section 5 page: crontab, sshd_config, fstab.
  5. Use whatis to see which sections exist, then open the one you need.

Layer by layer: dissect a usage line

Take the real first lines of cp --help: Usage: cp [OPTION]... [-T] SOURCE DEST. Open each symbol: what it means, why it exists, where the text really comes from, and where you will meet it. Each comes with a real command and its output on our build machine.

Six symbols you will see in every manual. Click one.

Usage: cp the command

Why does it exist?

Shows exactly what to type first.

How does it work?

The first word after “Usage:” is the command name. Several lines starting with “or:” are alternative forms.

Where is it, really?

Text compiled into the cp program (GNU coreutils), printed by its --help code.

Where is it used?

Every --help; man pages call this part SYNOPSIS.

See this layer yourself (real output)

cp --help | head -3
Usage: cp [OPTION]... [-T] SOURCE DEST or: cp [OPTION]... SOURCE... DIRECTORY or: cp [OPTION]... -t DIRECTORY SOURCE...

[OPTION] square brackets

Why does it exist?

Some parts are optional; the line must say which.

How does it work?

Anything in [ ] may be left out. Do not type the brackets themselves.

Where is it, really?

A convention from the first Unix manuals, later fixed by POSIX.

Where is it used?

ls [OPTION]... [FILE]...: plain ls is valid.

See this layer yourself (real output)

ls --help | head -1
Usage: ls [OPTION]... [FILE]...

... repeatable

Why does it exist?

Many commands accept any number of files or options.

How does it work?

X... = one or more X; [X]... = zero or more.

Where is it, really?

Same convention; in man pages it may be written as an ellipsis.

Where is it used?

cp a b c dir/, rm f1 f2 f3.

See this layer yourself (real output)

mkdir --help | head -1
Usage: mkdir [OPTION]... DIRECTORY...

SOURCE DEST placeholders

Why does it exist?

The line cannot know your file names.

How does it work?

Capital words (or underlined words in man) are placeholders: replace them with real values.

Where is it, really?

In man pages they are set in italics or underline by groff.

Where is it used?

cp notes.txt backup/.

See this layer yourself (real output)

mv --help | head -2
Usage: mv [OPTION]... [-T] SOURCE DEST or: mv [OPTION]... SOURCE... DIRECTORY

-T / --no-target-directory short and long options

Why does it exist?

Short options are quick to type; long ones are readable in scripts.

How does it work?

One dash + one letter (-T), or two dashes + a word (--no-target-directory). Short ones can be combined: -rv.

Where is it, really?

Parsed by the program, usually with the getopt library (man 3 getopt).

Where is it used?

Use long options in scripts for clarity.

See this layer yourself (real output)

cp --help | grep -- '-T,'
-T, --no-target-directory treat DEST as a normal file

Exit status 0 = OK

Why does it exist?

Scripts need to know whether a command succeeded.

How does it work?

Many --help texts and man pages list the meaning of each exit code.

Where is it, really?

The number the program returns to the shell, seen as $? (Lesson 5.4).

Where is it used?

if ls dir; then …, monitoring, CI jobs.

See this layer yourself (real output)

ls --help | grep -A3 '^Exit status'
Exit status: 0 if OK, 1 if minor problems (e.g., cannot access subdirectory), 2 if serious trouble (e.g., cannot access command-line argument).
Quick check In ls [OPTION]... [FILE]..., is ls with nothing after it valid? Why?
Answer: Yes: both parts are in square brackets, so both are optional. With no FILE, ls lists the current folder.

Beginner

Build it step by step: the option you need, from a long help text

Scenario: date --help prints about 100 lines. Riya needs the option that shows a date other than now.

    date --help | wc -l
    110

  2. Lines that mention STRING: the date to display.

What is the difference between whatis and apropos?

whatis shows the one-line description of an exact page name; apropos searches all descriptions for a keyword. They are the same as man -f and man -k.

Why is there no man page for cd?

cd is a bash builtin. Builtins are documented by bash itself: use help cd (or man bash).

How do you search inside a man page?

Type / followed by the word and press Enter; n goes to the next match, N to the previous.

What is the info command?

A reader for Texinfo manuals, used mainly by GNU projects. They are longer than man pages and organised in linked nodes.

Practice problems

Tasks about finding help. Expected outputs come from real runs on Ubuntu 24.04 (a minimal image, so these use --help, help and type).

P1Easy

Builtin or program?

Print the kind of pwd, grep and read.

Input
pwd grep read
Expected output
builtin
file
builtin
Show solution and explanation 
type -t pwd grep read
builtin file builtin

How it works: builtin, file, builtin.

P2Easy

The usage line

Print only the first line of mkdir --help.

Input
mkdir --help
Expected output
Usage: mkdir [OPTION]... DIRECTORY...
Show solution and explanation 
mkdir --help | head -1
Usage: mkdir [OPTION]... DIRECTORY...

How it works: DIRECTORY... = one or more folder names are required.

P3Easy

Help for a builtin

Show the short description of the builtin export.

Input
export
Expected output
export - Set export attribute for shell variables.
Show solution and explanation 
help -d export
export - Set export attribute for shell variables.

How it works: -d prints only the one-line description.

P4Medium

Find an option

Find the option of sort that sorts numbers correctly.

Input
sort --help
Expected output
  -n, --numeric-sort          compare according to string numerical value
                                numeric -n, random -R, version -V
Show solution and explanation 
sort --help | grep -- '-n,'
-n, --numeric-sort compare according to string numerical value numeric -n, random -R, version -V

How it works: -n compares as numbers, so 10 comes after 9.

P5Medium

Count the options

How many lines of ls --help start with spaces and a dash (one per option)?

Input
ls --help
Expected output
60
Show solution and explanation 
ls --help | grep -c '^ *-'
60

How it works: A rough count of the options ls offers.

P6Medium

Version check

Print the version line of grep and bash.

Input
grep, bash
Expected output
grep (GNU grep) 3.11
GNU bash, version 5.2.21(1)-release (x86_64-pc-linux-gnu)
Show solution and explanation 
grep --version | head -1
bash --version | head -1
grep (GNU grep) 3.11 GNU bash, version 5.2.21(1)-release (x86_64-pc-linux-gnu)

How it works: Always compare with the version an online answer was written for.

P7Business problem

Look it up, then use it

A report needs the date 30 days ago in YYYY-MM-DD form. Find the date option and use it.

Input
date --help
Expected output
  -d, --date=STRING          display time described by STRING, not 'now'
2026-10-06
Show solution and explanation 
date --help | grep -m1 -- '--date='
date -d '2026-11-05 -30 days' +%F
-d, --date=STRING display time described by STRING, not 'now' 2026-10-06

How it works: -d accepts expressions like “-30 days”; +%F prints YYYY-MM-DD. (A fixed start date keeps the output stable.)

P8Business problem

Onboarding check

A new laptop must have git, curl and tar. Print “ok” or “missing” for each.

Input
git curl tar
Expected output
ok      git
ok      curl
ok      tar
Show solution and explanation 
for t in git curl tar; do
  if type -P "$t" > /dev/null; then echo "ok      $t"; else echo "missing $t"; fi
done
ok git ok curl ok tar

How it works: type -P looks only for program files in PATH.

Real-world scenario questions (asked in company interviews)

Interview questions about documentation, as asked for support, admin and certification-style practical rounds.

Any company · basicsFresher

“How do you find out what a command does?”

The interviewer names a command you have never seen, for example nl.

The interviewer is checking: do you know how to help yourself?

Show a strong answer
  • whatis nl for one line, nl --help for the options, man nl for the details and examples.
  • If it is a builtin (type nl), use help.
  • Then test it on a sample file.

Avoid: “I would search on Google” as the only answer.

Operations · no internetJunior

Find a command for a task

On a server with no internet you must find how to see which process uses a port.

The interviewer is checking: can you search the local documentation by topic?

Show a strong answer
  1. apropos port or apropos socket → ss, lsof, netstat, fuser.
  2. whatis ss; then ss --help or man ss and search /listening.
  3. Result: sudo ss -ltnp (Lesson 16.4).

Avoid: giving up because there is no browser.

Certification · practicalMid-level

“The exam allows only local docs.”

In RHCSA- or LFCS-style exams you may only use the system’s documentation. How do you prepare?

The interviewer is checking: are you fluent with man sections and searching?

Show a strong answer
  • Know sections 1, 5 and 8 and use man 5 fstab, man 5 crontab, man 8 mount.
  • Use man -k with section filters, and jump to EXAMPLES with /EXAMPLES.
  • Look in /usr/share/doc/<package> for sample configs.

Avoid: only memorising options.

Platform team · internalsSenior

“Why did apropos return nothing?”

On a fresh cloud VM, apropos and man return nothing useful.

The interviewer is checking: do you understand how the man system is built?

Show a strong answer
  • Minimal images remove man pages (dpkg excludes /usr/share/man) and may skip the mandb index.
  • Fix: sudo unminimize (Ubuntu) or reinstall the man-db and manpages packages, then sudo mandb.
  • Meanwhile --help and help still work, because their text is inside the programs and bash.

Avoid: “the commands are broken”.
