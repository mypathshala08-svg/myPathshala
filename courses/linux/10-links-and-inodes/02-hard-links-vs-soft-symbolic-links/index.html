Hard links vs soft (symbolic) links

A hard link is a second name for the same inode; a symbolic link is a small file that holds a path. This lesson shows the difference on real files, the mistakes that break links, and how deploys, package tools and backups use them.

The problem

Riya runs ls -l /usr/bin/python3 and sees an arrow: python3 -> python3.12. A deployment tool switches a live website to a new version in one millisecond by changing where current points. 2 Definition

Hard links and symbolic links

Formal definition (write this in exams)

A hard link is an additional directory entry that points to an existing inode; every hard link is an equal name for the same file, and the file’s data exists until the last link is removed. A symbolic (soft) link is a separate file of type link whose content is a path to another file or directory; the system follows that path each time the link is used, so the link breaks if the path no longer exists.

In simple words

Hard link: another name for the same file. Soft link: a pointer to a name.

Links at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: name tags and notes

Two ways to reach the same box.

Basic What you will type every day

  • ln -s /opt/app/bin/run ~/bin/run: a shortcut (symbolic link). ls -l shows run -> /opt/app/bin/run.
  • ln report.txt backup.txt: a second name (hard link). ls -li shows the same inode number and link count 2.
  • readlink -f run: where does it really point?
  • rm run: removes only the link, never the target.

Intermediate The rules, from inodes

  • Hard link = a new directory entry with the same inode number. All names are equal: there is no “original”. The data is freed when the last name is removed (and nobody has it open).
  • Hard links work only inside one filesystem (inode numbers are per disk) and not for folders (that could create loops).
  • Symbolic link = its own inode of type l, whose content is a path (its size is the path length). The path is resolved every time you use the link, relative to the folder the link is in.
  • Symlinks can point to folders, to other disks and to things that do not exist (yet): a dangling link.

Advanced Behind the screen: syscalls and kernel rules

  • ln calls linkat(); ln -s calls symlinkat(); readlink calls readlink(). open() follows symlinks automatically, up to 40 in a chain (then “Too many levels of symbolic links”, ELOOP).
  • Short symlink targets are stored inside the inode (“fast symlinks”), so they use no data block.
  • Symlink permissions are always lrwxrwxrwx and ignored: access is checked on the target. chmod on a link changes the target.
  • fs.protected_symlinks and fs.protected_hardlinks (on by default) stop classic /tmp attacks: you cannot follow another user’s symlink in a sticky folder, or hard-link a file you cannot read or write.
  • Renaming a symlink over another (mv -T new current) is atomic: zero-downtime deploys rely on it.

Did you know? Every folder already uses hard links: . is a hard link to the folder itself and .. to its parent. That is why a new folder has link count 2, and only the kernel may make such links to folders.

Exam tip: “Order of arguments in ln?” → Like cp: first what exists (the target), then the new name. ln -s TARGET LINK_NAME.

Quick check A hard link and the original: which one is the “real” file?
Answer: Neither and both: they are two equal names for the same inode. There is no original once the link exists.
Common mistake
✗ln -s report.txt docs/report-link (run in ~/ln)
✓ln -s ../report.txt docs/report-link · or ln -sr report.txt docs/report-link · or an absolute path

A relative target is resolved from the link’s own folder (docs/), not from where you typed the command. -r computes the right relative path for you.

ln -s make a symbolic link

🟡 Changes filesno sudo

ln -s TARGET LINK creates LINK containing the text TARGET. The target is not checked: it may be missing. A relative target is resolved from LINK’s folder. -r makes the relative path for you; -f replaces an existing LINK; -n treats an existing folder link as a file.

✓ Use it when
  • shortcuts to files and folders
  • version switching (current → v2)
  • links to other disks
✗ Don’t use it when
  • relative targets typed from the wrong folder
  • links that must survive the target being deleted

Syntax: ln -s [-f] [-n] [-r] [-v] TARGET LINK_NAME

ln make a hard link

🟡 Changes filesno sudo

ln FILE NEW adds a directory entry NEW pointing to FILE’s inode; the link count goes up by one. Only for files, only on the same filesystem. rm of any name lowers the count; data is freed at 0.

✓ Use it when
  • a name that survives deleting the other
  • space-saving snapshots and backups
✗ Don’t use it when
  • folders (not allowed)
  • another disk (not allowed)
  • files edited by tools that replace them (sed -i, many editors)

ln in devops / cloud

  1. Situation: Snapshot backups that cost almost nothing.

    cd ~/ln; cp -al docs snap1

    803660 2 docs/notes.txt 803660 2 snap1/notes.txt 8.0K docs 4.0K snap1

    Why this way: cp -al makes a tree of hard links (rsync --link-dest does the same). du counts the shared data only once: snap1 shows 4.0K for the folder itself.

Common mistake
✗Hard-link a config, then edit the original with sed -i or vim
✓Edit in place (>>, a tool that writes into the same file), or use a symlink

sed -i and many editors write a new file and rename it over the name. The name gets a new inode; the hard link keeps the old content. Checked in the Run section.

ln -sfn · mv -T replace a link safely

🟡 Changes filesno sudo

Updating a link that points to a folder is a trap: ln -sf v2 current follows current into the folder and creates v1/v2. Add -n (or -T). For a zero-downtime switch, make a new link and rename it over the old one with mv -T: rename is atomic.

✓ Use it when
  • switching a “current” link to a new version
  • replacing a link in scripts
✗ Don’t use it when
  • ln -sf on a link that points to a folder (without -n)

Syntax: ln -sfn NEW_TARGET LINK · ln -s NEW tmp && mv -T tmp LINK

OptionWhat it doesWhen to use it
-sfnreplace the link itselfversions
-sfTsame, LINK never a folderscripts
mv -T tmp currentatomic renamelive sites
rm currentremove the linknot the folder

ln -sfn · mv -T in devops / cloud

  1. Situation: Zero-downtime release switch.

    cd ~/ln
ln -s releases/v2 current.tmp && mv -T current.tmp current
readlink current; cat current/app.txt
    releases/v2 version 2

    Why this way: At every moment current points to v1 or v2, never to nothing. Capistrano and many deploy scripts do exactly this; rollback is the same command with v1.

Common mistake
✗rm current/ · rm -r current/
✓rm current (no slash)

With a trailing slash the path means the folder behind the link. rm refuses or, with -r, deletes the folder’s contents. Without the slash only the link goes.

find -type l · -xtype l · -samefile in security

  1. Situation: Links that point outside a web root are a risk.

    cd ~/ln; find www -type l -lname '/*' -printf '%p -> %l\n'

    Why this way: A symlink to /etc/passwd inside a web folder can leak it. Web servers have options to refuse symlinks for this reason.

Undo and safety net

Links are cheap to remove and recreate; the danger is removing what is behind them.

  • Made a link in the wrong place: rm LINK (no trailing slash) and make it again.
  • Link points to the wrong target: ln -sfn RIGHT LINK.
  • Deleted the target of a symlink: restore the file at that path; the link works again automatically.
  • Deleted one hard link: the data is still there under the other names: find / -xdev -inum N.
  • ln -sf created v1/v2: rm releases/v1/v2, then use -sfn.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. ln docs docs-hard
    ln: docs: hard link not allowed for directory exit status: 1

    What it means: Hard links to folders are forbidden.

    Fix: ln -s docs docs-link.

  2. ln report.txt /mnt/tiny/r.txt
    ln: failed to create hard link '/mnt/tiny/r.txt' => 'report.txt': Invalid cross-device link exit status: 1

    What it means: Hard link across filesystems.

    Fix: Use ln -s, or copy.

  3. ln -s report.txt latest; ln -s report.txt latest
    ln: failed to create symbolic link 'latest': File exists exit status: 1

    What it means: The link name exists.

    Fix: ln -sf (or -sfn for folders).

  4. ln -s nothing.txt dead; cat dead
    cat: dead: No such file or directory exit status: 1

    What it means: Dangling link: target missing.

    Fix: readlink dead, then create the target or fix the link.

Quick check ln -s never complains about a missing target. Why is that a feature?
Answer: You can create links before the target exists (a config that will be installed later, a mount point), and links survive the target being replaced.

6 Real-world use

Links at work

1. Deployments

Releases go into their own folders; a current symlink is switched atomically, and rollback is one command.

Upload→ln -s + mv -T→live

2. Choosing versions

Debian/Ubuntu point java, editor and python at the chosen version through chains of symlinks.

Install→update-alternatives→use

3. Config on/off

nginx and Apache enable a site by linking it from sites-available into sites-enabled; systemd enables units with links.

Write→ln -s→reload

4. Backups

rsync --link-dest and Time-Machine-style tools hard-link unchanged files, so 30 snapshots cost little more than one.

Backup→hard links→restore

5. Security and clean-up

Teams search for broken links and for links pointing outside allowed folders.

Scan→find -xtype l→fix

Quick revision

Lesson 10.2 in one screen

  • Hard link: ln F N, same inode, link count +1, survives deleting the other name. Not for folders, not across disks.
  • Soft link: ln -s TARGET LINK, own inode holding a path; breaks if the path disappears; works for folders and other disks.
  • A relative target is resolved from the link’s folder: use -r or an absolute path.
  • Replace a folder link with ln -sfn; switch live with ln -s new tmp && mv -T tmp current.
  • readlink -f / realpath show the final path; find -xtype l finds broken links; -samefile finds hard links.
  • rm link removes the link only; never rm -r link/.

Interview and viva questions

What is the difference between a hard link and a soft link?

A hard link is another name for the same inode and keeps working if the other name is deleted. A soft link is a separate file holding a path and breaks if that path disappears.

How do I create a symbolic link?

ln -s TARGET LINK_NAME.

How do I update an existing symlink?

ln -sfn NEW_TARGET LINK_NAME.

Why can’t I hard link a directory?

It could create loops in the tree and confuse tools; only the kernel makes . and .. links.

How do I find broken symlinks?

find DIR -xtype l.

Does deleting a symlink delete the file?

No, rm on a link removes only the link.

Why is my symlink broken right after creating it?

A relative target is resolved from the link’s folder. Use ln -sr or an absolute path.

Interview questions about links, from fresher to senior rounds.

Any company · basicsFresher

“Hard link vs soft link?”

Asked in almost every Linux interview.

The interviewer is checking: inode-level answer?

Show a strong answer
  • Hard: same inode, survives deleting the original, no folders, same filesystem.
  • Soft: own inode holding a path, can dangle, folders and other disks OK.
  • Show with ls -li.

Avoid: saying “a soft link is a copy”.

Web hostingJunior

After a deploy the site shows the OLD version

The script ran ln -sf releases/v2 current.

The interviewer is checking: do you know -n?

Show a strong answer
  1. ls releases/v1: a stray v2 link inside it.
  2. rm releases/v1/v2; ln -sfn releases/v2 current.
  3. Better: ln -s … tmp && mv -T tmp current.

Avoid: rm -r current/ (deletes the release).

OperationsMid-level

A config change does not take effect

The service reads /etc/app.conf, a hard link to /opt/app/app.conf, edited with vim.

The interviewer is checking: sed -i / editors and hard links?

Show a strong answer
  • ls -li: the two names now have different inodes.
  • The editor saved a new file; the hard link kept the old one.
  • Use a symlink for config, or configure the editor to write in place.

Avoid: restarting the service again and again.

Backup teamSenior

30 daily snapshots of 2 TB in 2.3 TB

How?

The interviewer is checking: hard-link snapshots?

Show a strong answer
  • rsync -a --link-dest=../yesterday src/ today/: unchanged files are hard links.
  • Each snapshot looks complete; deleting old ones is safe.
  • Limit: a changed file is stored again whole; modern options use filesystem snapshots (Btrfs, ZFS, LVM).

Avoid: thinking it is compression.

Interview and certification corner

Can a hard link cross filesystems?
No; inode numbers are per filesystem.
What does the l in lrwxrwxrwx mean?
Symbolic link.
What happens to a symlink when the target is renamed?
It breaks (dangling).
How do you see where a symlink points?
ls -l or readlink (-f for the final path).
How is space freed with hard links?
When the last name is removed and no process has the file open.
How do you find all hard links of a file?
find / -xdev -samefile FILE (or -inum).
Why ln -sfn and not ln -sf?
Without -n, an existing link to a folder is followed and the new link is created inside the folder.
Where this appears in certification exams
  • RHCSA (EX200): “Create hard and soft links”.
  • LFCS: Create and manage hard and soft links.
  • CompTIA Linux+: ln, ln -s, inodes and link counts.
