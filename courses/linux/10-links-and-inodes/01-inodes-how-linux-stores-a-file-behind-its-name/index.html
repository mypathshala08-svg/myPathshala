Inodes: how Linux stores a file behind its name

Every Linux file is an inode: a numbered record with its size, owner, permissions, times and data location. The name lives in the folder. This lesson shows both on a real disk and uses them to solve full disks, missing space and odd file names.

Module 10 · Inodes and links⏱ 40 minBeginner → AdvancedA real 16-inode diskstat field by fielddebugfs inside ext4Practice lab with checkerReal Bash in your browser8 practice problems
The problem

The monitoring alert says “disk full”: the app cannot create a single new file. But df -h shows the disk is only 1% used. On another server, an admin deletes a 20 GB log and df shows no space was freed. Renaming a 50 GB video takes no time at all, yet copying it takes ten minutes. All three puzzles have one answer: Linux does not store a file under its name. Behind every name is an inode, a small numbered record that holds everything about the file except its name.

By the end of this page you will be able to:
  • explain what an inode is, what it stores (and what it does not: the name), and how a directory maps names to inode numbers
  • read every field of stat, see inode numbers with ls -i, and check inode usage with df -i
  • diagnose “No space left on device” with free space, deleted-but-open files, and why mv is instant but cp is not
  • look inside a real ext4 disk with debugfs and tune2fs, and find or delete files by inode number

2 Definition

Inode: index node

Formal definition (write this in exams)

An inode (index node) is a numbered on-disk record that describes one file system object: its type, permissions, owner, group, size, timestamps, link count and the location of its data blocks. It does not contain the file’s name. A directory is a list of entries mapping names to inode numbers, so one inode can have several names (hard links, Lesson 10.2).

In simple words

The name is a label in a folder. The inode is the file.

Inodes at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a library catalogue

A file is stored in three parts, like a book in a library.

Basic What you will see every day

  • ls -i shows the inode number in front of each name.
  • stat file shows what the inode holds: size, blocks, links, permissions, owner, times.
  • df -i shows how many inodes the disk has and how many are used.
  • Rename (mv) in the same filesystem keeps the inode: instant. cp makes a new inode and copies the data.

Intermediate What the inode stores, and what a folder is

  • An inode holds: type (file, folder, link, device…), permission bits and special bits, owner UID and group GID, size, number of blocks, link count, timestamps (atime, mtime, ctime, birth) and pointers to the data (on ext4: extents, “1 block starting at 1035”).
  • A directory is a special file whose data is a list of entries: name → inode number. Every folder contains . (its own inode) and .. (the parent’s).
  • The link count is how many names point to the inode. rm removes a name; the data is freed only when the count reaches 0 and no program still has the file open.
  • Inode numbers are unique only inside one filesystem: the pair (device, inode) identifies a file.

Advanced Behind the screen: ext4 internals

  • mkfs.ext4 creates a fixed inode table: by default one inode per 16 KB of disk, 256 bytes each. The count cannot grow later (-N or -i at mkfs time). XFS and Btrfs allocate inodes dynamically, so they rarely run out.
  • Inodes 1–10 are reserved: 2 is the root folder of every ext4 filesystem, 8 the journal, 11 lost+found.
  • Opening /srv/a/b.txt is a path walk: inode 2 → read its entries → find srv → its inode → … The kernel caches results in the dentry cache.
  • Tiny files (≈60 bytes) can live inside the inode (ext4 inline_data); a sparse file has a large size but few blocks, because holes have no blocks at all.
  • Each process’s open files point to the inode, not the name: that is why a deleted log keeps using space until the program closes it or restarts.

Did you know? Your file names are not stored with your files at all. That is why one file can have two names (10.2), why a file can exist with no name (deleted but still open), and why mv of a 50 GB file inside one disk takes milliseconds: only one line in a folder changes.

Exam tip: “What information is not stored in an inode?” → The file name (and the file’s contents). Names are stored in directory entries.

Quick check A folder has 3 subfolders. What is its link count, and why?
Answer: 5: its name in the parent, its own ., and the .. of each of the 3 subfolders.
Common mistake
✗“ctime is the creation time”
✓ctime = last inode change (chmod, chown, rename, write). Creation time is Birth (stat %w).

stat shows Access, Modify, Change and Birth. chmod changes ctime but not mtime; many scripts that “find files created today” with -ctime are wrong.

ls -i show inode numbers

🟢 Read-onlyno sudo

ls -i prints each name’s inode number in front of it. Add -l for the full listing (the 2nd column is the link count), -a to see . and .., -d for a folder itself.

✓ Use it when
  • seeing whether two names are the same file
  • checking whether a file was replaced
  • finding odd names
✗ Don’t use it when
  • comparing inode numbers from two different disks

stat show the whole inode

🟢 Read-onlyno sudo

stat prints the inode’s fields: size, blocks, IO block, device, inode number, links, mode, UID, GID and four times (Access, Modify, Change, Birth). -c FORMAT prints chosen fields; -f describes the filesystem instead.

✓ Use it when
  • reading everything Linux knows about a file
  • scripts that need size, owner or times
  • debugging time and permission problems
✗ Don’t use it when
  • expecting a creation time on every filesystem

df -i · du --inodes inode usage

🟢 Read-onlyno sudo

df -i shows each filesystem’s total, used and free inodes and IUse%. At 100%, no new file, folder or link can be created, even with gigabytes free. du --inodes counts inodes per folder to find the culprit.

✓ Use it when
  • “No space left on device” with free space
  • servers with millions of small files (mail, cache, sessions)
  • capacity planning
✗ Don’t use it when
  • reading only df -h

Undo and safety net

Inode problems are fixed by removing files or changing the filesystem; there is no “add inodes” command on ext4.

  • Inodes at 100%: find the folder with du --inodes -x /, delete old small files (sessions, cache, mail queue), then fix the program that makes them.
  • Space not freed after rm: sudo lsof +L1 lists deleted-but-open files; restart or reload that program, or empty the file with : > /proc/PID/fd/N.
  • Need more inodes permanently: back up, re-create with mkfs.ext4 -i 4096 or -N, restore; or use XFS. (Destroys data on that disk!)
  • Deleted a file by mistake: stop writing to that disk at once; tools such as extundelete may recover it from a copy of the disk. Better: backups.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. touch /mnt/tiny/f6
    touch: cannot touch '/mnt/tiny/f6': No space left on device exit status: 1

    What it means: No free inode (also printed when blocks are full).

    Fix: df -i and df -h; delete small files.

  2. find ~/ino -inum abc
    find: invalid argument `abc' to `-inum' exit status: 1

    What it means: -inum needs a number.

    Fix: Take it from ls -i or stat -c %i.

  3. debugfs -R stat /dev/vda
    /home/riya/script.sh: line 1: debugfs: command not found exit status: 127

    What it means: A real disk needs root (and a command argument).

    Fix: sudo debugfs -R 'stat <2>' /dev/sda1.

  4. stat nothing.txt
    stat: cannot statx 'nothing.txt': No such file or directory exit status: 1

    What it means: No such name in this folder.

    Fix: Check the path; names are looked up folder by folder.

Common mistake
✗“The inode is a unique number for each file” (on the whole system)
✓Unique only inside one filesystem: the pair (device, inode) identifies a file

Every disk numbers its inodes from 1, so /home/a and /mnt/usb/b can both be inode 12. find -inum should be used with -xdev, and backup tools compare device and inode together.

Quick check Two names show the same inode number with ls -i. When are they the same file?
Answer: Only when they are on the same filesystem (same Device in stat). Inode numbers repeat on every disk.

Quick check A 2 GB log was deleted but df shows no change. What do you run?
Answer: sudo lsof +L1: it lists files with link count 0 that are still open, with the program’s PID. Restart that program (or truncate via /proc/PID/fd).

Script it: inode-check.sh

An alert script for cron: warn when any real filesystem is above a threshold of inodes, and show the busiest folder.

limit=${1:-90}
df -i -x tmpfs -x devtmpfs -x squashfs -x overlay --output=ipcent,target | tail -n +2 |
while read -r pct mnt; do
  p=${pct%\%}; [ "$p" = "-" ] && continue
  if [ "$p" -ge "$limit" ]; then echo "ALERT $mnt inodes $pct"; else echo "ok    $mnt inodes $pct"; fi
done
df: options -i and --output are mutually exclusive Try 'df --help' for more information.

Run with a limit of 1% so the alert fires on our machine.

Puzzle answer Remember the question from the story? Open to check your guess.

The disk ran out of inodes, not space: every email is a file and needs one inode. Deleting one 2 GB backup freed only one inode. df -i would have shown IUse% 100%. Fix: delete or archive many old small files (find the folder with du --inodes), and for the future use a filesystem with more inodes (mkfs.ext4 -i) or XFS.

Quick check Does mv inside one filesystem change the inode number?
Answer: No. Only the folder entries change; the inode and the data stay where they are.

Quick revision

Lesson 10.1 in one screen

  • An inode is a file’s record: type, mode, owner, size, link count, times, data location. Not the name.
  • A directory is a table of name → inode number. . and .. are entries too.
  • ls -i, stat (-c %i %h %s), find -inum / -samefile.
  • “No space left” = blocks OR inodes: check df -h and df -i; find culprits with du --inodes.
  • Data is freed when links = 0 and no program has it open: lsof +L1.
  • mv (same disk) keeps the inode; cp and sed -i make a new one. ext4 inode count is fixed at mkfs.

Interview and viva questions

What is an inode in Linux?

A data structure that stores a file’s metadata (type, permissions, owner, size, times, link count, data block locations), identified by a number. It does not store the name.

How do I see a file’s inode number?

ls -i FILE or stat -c %i FILE.

How do I check inode usage?

df -i (per filesystem) and du --inodes -x DIR (per folder).

Why “No space left on device” when the disk has space?

The filesystem has run out of inodes (df -i shows 100%), usually from millions of small files.

Can I add more inodes to ext4?

Not on an existing filesystem; recreate it with mkfs.ext4 -i or -N, or use XFS.

Why is space not freed after deleting a file?

A program still has it open; find it with lsof +L1 and restart or reload it.

Where is the file name stored?

In the directory entry of its parent folder.

Interview questions about inodes, from fresher to senior rounds.

Any company · basicsFresher

“What is an inode?”

A favourite Linux interview question.

The interviewer is checking: can you say what is (and is not) inside?

Show a strong answer
  • A numbered record per file: type, permissions, owner, size, times, link count, data block pointers.
  • Not the name: names are in directories (name → inode number).
  • See it: ls -i, stat.

Avoid: saying “the inode stores the file name”.

“No space left on device” with 40% free

Customers cannot upload. df -h looks fine.

The interviewer is checking: do you check inodes?

Show a strong answer
  1. df -i: IUse% 100%.
  2. du --inodes -x / | sort -n | tail: e.g. /var/lib/php/sessions.
  3. Delete old sessions with find -mtime; fix the session clean-up job.

OperationsMid-level

Deleted 30 GB of logs, df did not change

The disk is still 100%.

The interviewer is checking: deleted-but-open files?

Show a strong answer
  • sudo lsof +L1 shows the app holding the deleted log (NLINK 0).
  • Reload the app (or : > /proc/PID/fd/N) to free the space.
  • Prevent it: logrotate with postrotate reload, or copytruncate.

Storage teamSenior

Design a disk for 200 million thumbnails

Average file 6 KB.

The interviewer is checking: inode planning?

Show a strong answer
  • ext4 default (1 inode per 16 KB) gives too few: use mkfs.ext4 -i 4096 or choose XFS (dynamic inodes).
  • Shard into folders (ab/cd/…) so directories stay small.
  • Or use object storage for billions of objects.

Interview and certification corner

What does df -i show?
Total, used and free inodes per filesystem.
Is the file name in the inode?
No, it is in the directory entry.
Why is mv fast and cp slow for large files?
mv on one filesystem only changes a folder entry; cp copies data to a new inode.
What is the link count?
The number of directory entries (names) pointing to the inode.
When is a file’s space freed?
When its link count is 0 and no process has it open.
What is the difference between mtime and ctime?
mtime: contents changed; ctime: inode changed (incl. chmod, chown).
How do you remove a file with an unprintable name?
find -inum N -delete.
