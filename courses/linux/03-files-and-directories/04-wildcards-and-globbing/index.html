2 Definition

Wildcards, globbing and brace expansion

Formal definition (write this in exams)

Globbing (pathname expansion) is the shell replacing a word that contains wildcards with the sorted list of existing file names that match it. The wildcards are * (any string, including empty), ? (any single character) and […] (one character from a set or range; [!…] or [^…] negates). Brace expansion ({a,b}, {1..9}) is a different feature that generates strings whether or not files exist.

In simple words

Wildcards find existing names; braces write names. The shell does both before the command starts.

Wildcards at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: fill in the blanks

Like a crossword clue with blanks.

  • * means “any letters here”. *.csv = every name that ends with .csv.
  • ? means “one letter here”.
  • [ ] means “one of these letters”.

Basic The patterns you will use every day

  • ls *.csv, cp *.jpg photos/, rm *.tmp.
  • data?.log matches data1.log but not data10.log (two characters).
  • [0-9] one digit, [a-z] one lowercase letter, [!0-9] anything but a digit.
  • Braces make lists: mkdir {jan,feb,mar}, touch day{1..7}.log.
  • Before a risky command, run echo with the same pattern.

Intermediate The rules that surprise people

  • No match: bash leaves the pattern as it is (*.xyz), so the command gets a literal star. Hence “cannot access ’*.xyz’”.
  • Hidden files (starting with .) are not matched by *; use .* or shopt -s dotglob. Since bash 5.2, .* no longer matches . and .. (option globskipdots).
  • Quotes switch globbing off: "*.txt" is just the text *.txt. Variables should be quoted ("$f") but patterns not.
  • Braces vs wildcards: {07..09} writes names even if the files do not exist; 0[7-9] only matches existing files.
  • Names with spaces are safe in for f in *.txt as long as you write "$f".

Advanced Behind the screen: expansion order and options

  • Bash expands in a fixed order: brace → tilde → parameter/variable → command substitution → arithmetic → word splitting → pathname (glob) → quote removal (Lesson 12.4).
  • Globbing reads the folder (opendir/getdents64), matches each name, and sorts the result by the locale’s collation order.
  • Shell options: nullglob (no match → nothing), failglob (no match → error), dotglob, nocaseglob, globstar (** = any depth), extglob (?(…) *(…) +(…) @(…) !(…)).
  • Range brackets like [a-z] depend on the locale; [[:lower:]], [[:digit:]] are exact everywhere.
  • Very large expansions can exceed the kernel’s argument limit: “Argument list too long”. Then use find … -exec or xargs (Lesson 13.2).

Did you know? In the very first versions of Unix, the shell did not expand wildcards itself: it called a separate program, /etc/glob, short for “global”. The program is long gone, but the name “glob” stayed, and it is used today in Python (glob module), Node.js, .gitignore files and Docker.

Exam tip: “Explain wildcards in Linux with examples” → * any characters, ? one character, [ ] one character from a set or range, [!…] negation; give ls *.txt, ls file?.log, ls [a-c]*; mention that the shell expands them before running the command, and that braces generate strings instead of matching files.

Quick check Which files does data?.log match among data1.log, data2.log and data10.log?
Answer: data1.log and data2.log. ? is exactly one character; data10.log has two.

* star: any text

🟢 Read-onlyno sudo

Matches any sequence of characters in a name, including nothing at all. It does not cross a / and does not match hidden files.

✓ Use it when
  • you mean “every name that starts / ends / contains …”
  • selecting files for cp, mv, rm, tar, grep
  • a quick count: ls *.csv | wc -l
✗ Don’t use it when
  • you need one exact character count (use ?)
  • the files are in many sub-folders (use ** or find)
  • you need it as plain text (quote it)

Syntax: …*… e.g. *.csv, report_*, *2026*

*2026*every name containing 2026by year, by keyword

* in software development

  1. Situation: Search for TODO in every Python file of the folder.

    grep -n TODO *.py

    Why this way: grep gets the list of .py files; with several files it prints the file name before each match (Lesson 6.1).

* in security

  1. Situation: Check permissions of every hidden config file in a home folder.

    stat -c '%A %n' .[!.]*
    -rw-r--r-- .bashrc -rw-r--r-- .profile -rw------- .ssh_config_backup

    Why this way: * skips dotfiles; .[!.]* selects names that start with one dot (and works in every shell, unlike relying on globskipdots). Files with secrets should be rw------- (600).

  2. Situation: Danger check: what would rm * delete here?

    echo rm * | wc -w
    27

    Why this way: Always count first. 25 names: everything in the folder.

? question mark: exactly one character

🟢 Read-onlyno sudo

Matches exactly one character, whatever it is. Two question marks = exactly two characters.

✗ Don’t use it when
  • the unknown part has a variable length (use *)

[ ] brackets: one character from a set

🟢 Read-onlyno sudo

Matches exactly one character that is in the set or range. With ! or ^ first, one character that is not in it.

✓ Use it when
  • one position may be one of a few characters
  • ranges of digits or letters: [0-9], [a-f]
  • excluding something: [!…]
✗ Don’t use it when
  • you need several characters in a row (brackets match ONE)
  • you want a list of whole words (use braces or extglob @(…))

Syntax: [abc] [a-z] [0-9] [!0-9] [[:digit:]]

[ ] in security

  1. Situation: Find files whose name contains a space (they break careless scripts).

    for f in *[[:space:]]*; do echo "[$f]"; done

    Why this way: [[:space:]] matches the space; brackets in the output show where names begin and end.

{ } brace expansion: write every combination

🟢 Read-onlyno sudo

Writes out every item of a comma list or sequence, combined with the text around it. It never looks at the disk, so the names may or may not exist.

✓ Use it when
  • creating many names: folders, files, backups
  • sequences with padding: {01..12}
  • two names that share a part: app.conf{,.bak}
✗ Don’t use it when
  • selecting files that already exist (use wildcards)
  • the list comes from a variable: {1..$n} does not work (use seq, Lesson 3.6)

Syntax: {a,b,c} {1..10} {01..12} {a..e} {1..20..5} pre{a,b}post

OptionWhat it doesWhen to use it
{a,b,c}a listnamed items: months, environments
{1..10}a number sequencenumbered files
{01..12}zero-padded sequencesortable names
{1..20..5}with a step: 1 6 11 16every n-th
{z..a}backwards / lettersreverse order
x{,.bak}empty item: x and x.bakbackup copies
{a,b}{1,2}combinations: a1 a2 b1 b2grids of names

shopt shell options for globbing

🟢 Read-onlyno sudo

Bash options that change how patterns behave. Switch on with shopt -s name, off with shopt -u name; they last for the current shell or script.

✓ Use it when
  • scripts: what happens when nothing matches (nullglob)
  • recursive patterns without find (globstar)
  • “everything except” (extglob)
✗ Don’t use it when
  • interactive habits you forget to switch off (they change how every pattern behaves)
  • scripts that must also run in sh (these are bash-only)

Syntax: shopt -s nullglob | failglob | dotglob | nocaseglob | globstar | extglob

failglobno match → error, command not runstrict scripts

nocaseglobignore upper/lower casemixed-case names

extglob!(p) ?(p) *(p) +(p) @(p) patternseverything except

shopt in software development

  1. Situation: Count lines of all Python files in the project, any depth.

  1. Situation: A loop over log files must do nothing when there are none.

    shopt -s nullglob

    done

    Why this way: Without nullglob the loop would run once with f="*.log" and try to open a file called *.log.

shopt in data analysis / engineering

  1. Situation: Move everything except CSV and log files into misc/.

    shopt -s extglob
mkdir misc && mv !(*.csv|*.log|misc) misc/ && ls misc
    Notes.md a.txt b.txt c.txt notes.txt

    Why this way: !(a|b) = not a and not b. extglob must be on its own line before the line that uses it.

shopt in devops / cloud

  1. Situation: Copy a folder’s content including hidden files like .env and .gitignore.

    mkdir -p app2 && touch app2/{main.py,.env,.gitignore} && mkdir -p deploy
shopt -s dotglob
cp -v app2/* deploy/
    'app2/.env' -> 'deploy/.env' 'app2/.gitignore' -> 'deploy/.gitignore' 'app2/main.py' -> 'deploy/main.py'

    Why this way: Without dotglob, .env and .gitignore would be silently left behind.

Common mistake
✗for f in $(ls *.txt); do cat $f; done
✓for f in *.txt; do cat "$f"; done

Parsing ls output breaks on names with spaces (my report.txt becomes two words). A glob gives each name as one item; quote the variable.

Undo and safety net

If a pattern selects the wrong files…

  • Before: run the same line with echo in front, or ls -d pattern; count with | wc -w.
  • During: use -i with cp, mv and rm, or -v to see each file.
  • After cp: nothing is lost; delete the extra copies.
  • After mv: move them back with the same pattern from the target folder.
  • After rm: no undo (Lesson 3.3). That is why the echo habit matters most here.

Error messages decoded

The errors students see most with patterns. Each was really produced on our build machine, with its exit status.

  1. ls *.xyz
    ls: cannot access '*.xyz': No such file or directory exit status: 2

    What it means: Nothing matched, so bash passed the text “*.xyz” unchanged, and ls looked for a file with that exact name.

    Fix: Check the pattern with ls on the folder; in scripts use nullglob or test with [ -e "$f" ].

  2. touch report_2026_01.csv
ls report_2026_0{1..3}.csv
    ls: cannot access 'report_2026_02.csv': No such file or directory ls: cannot access 'report_2026_03.csv': No such file or directory report_2026_01.csv exit status: 2

    What it means: Braces wrote all three names; only one exists.

    Fix: Use a wildcard to see what exists: ls report_2026_0[1-3].csv.

  3. touch a.txt
ls "*.txt"
    ls: cannot access '*.txt': No such file or directory exit status: 2

    What it means: The quotes switched globbing off, so ls looked for a file named *.txt.

    Fix: Do not quote patterns: ls *.txt. Quote variables instead.

  4. touch "my report.txt"
f="my report.txt"
ls $f
    ls: cannot access 'my': No such file or directory ls: cannot access 'report.txt': No such file or directory exit status: 2

    What it means: Without quotes, the variable was split at the space into “my” and “report.txt”.

    Fix: ls "$f".

  5. shopt -s failglob
echo *.xyz
    /home/riya/script.sh: line 2: no match: *.xyz exit status: 1

    What it means: With failglob, a pattern that matches nothing stops the command with an error.

    Fix: That is the point of failglob: make the pattern match, or switch it off with shopt -u failglob.

5 See it happen

Who turns the pattern into names?

Left: what Riya types and what cp receives. Right: bash’s expansion steps.

Bash’s expansion steps 5 steps
What you see
  1. Riya types cp with a pattern.
  2. Before cp starts, bash reads the folder.
  3. Three names fit; the others are ignored.
  4. cp gets an ordinary list of names. It cannot tell you used a pattern.
  5. If nothing fits, the pattern itself is passed on, which is why the error shows the star.
Behind the screen
  1. Bash expands a command line in a fixed order of steps.
  2. Pathname expansion (globbing) is step 6, after variables and splitting.
  3. Matching names are sorted alphabetically.
  4. Quotes are removed last, and the program is started.
  5. Options nullglob and failglob change what happens with no match.

Script it: archive-quarter.sh

Archive one quarter’s reports, with every safety from this lesson: nullglob, a count, and a clear message when nothing matches.

#!/bin/bash
year=${1:-2026}; q=${2:-1}
touch report_2026_{01..06}.csv                      # demo files
case $q in 1) m='0[1-3]';; 2) m='0[4-6]';; 3) m='0[7-9]';; 4) m='1[0-2]';; *) echo "quarter 1-4" >&2; exit 1;; esac
shopt -s nullglob
files=( report_${year}_$m.csv )
if [ ${#files[@]} -eq 0 ]; then echo "no reports for $year Q$q"; exit 0; fi
tar -czf "reports_${year}_Q$q.tgz" "${files[@]}"
echo "archived ${#files[@]} file(s):"; tar -tzf "reports_${year}_Q$q.tgz"
archived 3 file(s): report_2026_01.csv report_2026_02.csv report_2026_03.csv

The pattern is built from variables (report_${year}_$m.csv); globbing happens after variable expansion, so it still works. Try quarter 3: “no reports”.

Puzzle answer Remember the question from the story? Open to check your guess.

Nothing matched *.xyz. In that case bash, by default, does not remove the word: it passes the text *.xyz unchanged to ls. ls then looks for a file whose name really is “*.xyz”, does not find it, and prints the name it was given. With shopt -s nullglob the word would vanish (ls would list the whole folder); with failglob bash itself would report “no match”.

Lesson 3.4 in one screen

  • * any text · ? one character · [abc] [1-3] one from a set · [!a] not.
  • Bash expands patterns before the command starts; the command only sees names.
  • Test every pattern with echo pattern; count with | wc -w.

Interview and viva questions

What are wildcards in Linux?

Special characters in file name patterns: * (any characters), ? (one character), [ ] (one character from a set). The shell expands them into matching file names.

What is the difference between * and ?

* matches any number of characters including none; ? matches exactly one.

What is globbing?

Pathname expansion: the shell replacing a pattern with the sorted list of matching file names.

What is the difference between brace expansion and wildcards?

Brace expansion generates text whether or not files exist; wildcards match existing file names only.

Why does ls *.txt not show hidden files?

Wildcards do not match names that start with a dot unless the pattern starts with a dot or dotglob is enabled.

How do you match files in all sub-directories?

Enable globstar (shopt -s globstar) and use **/pattern, or use find -name.

Are glob patterns the same as regular expressions?

No. In globs * means any text; in regex * means “repeat the previous item”. Regex is covered in Lesson 6.6 and rename in Lesson 3.7.

Explain *, ? and [ ] with examples.
*.txt = any name ending in .txt; file?.log = one character; [a-c]* = names starting with a, b or c; [!0-9]* = not starting with a digit.
