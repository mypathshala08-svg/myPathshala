2 Definition

cp, mv and rsync

Formal definition (write this in exams)

cp (copy) copies files, and with -r or -a whole directory trees, creating new files at the destination. mv (move) moves or renames files and directories; on the same file system it only changes directory entries, so the data is not copied. rsync (remote sync) copies files locally or between computers and, on later runs, transfers only files that are new or changed; it can also delete extra files at the destination to make an exact mirror.

In simple words

cp = make a copy, mv = move or rename, rsync = copy only what changed.

Copying, moving and syncing at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: photocopier, label, smart copier

Three everyday ideas.

  • cp is a photocopier: after it, you have two of the same thing.
  • mv just changes where a thing is or what it is called. Renaming a file is “moving” it to a new name.
  • rsync looks at the copy you already have and only adds what is new or changed.

Basic The commands you will type every day

  • cp a.txt b.txt copies a file; cp a.txt backup/ copies it into a folder, keeping its name.
  • cp -r project backup/: folders need -r (recursive).
  • mv old.txt new.txt renames; mv file.txt archive/ moves. mv works on folders without any option.
  • Both cp and mv overwrite an existing target without asking. Add -i to be asked.
  • rsync -av src/ dest/ copies a folder and, next time, only the changes.

Intermediate Attributes, safety and the trailing slash

  • Plain cp gives the copy a new date and makes you the owner. -p keeps date and permissions; -a (archive) keeps everything and copies folders, links included. Use -a for backups.
  • No overwrite: -i asks, --update=none skips (older -n), -u only replaces if the source is newer, --backup=numbered keeps the old one as file.~1~.
  • rsync’s slash rule: rsync -a src/ dest/ copies the contents of src; rsync -a src dest/ creates dest/src.
  • --delete removes files from the destination that are no longer in the source: an exact mirror. Always -n (--dry-run) first.

Advanced Behind the screen: why mv is instant

  • A folder is a list of names → inode numbers. On the same file system, mv calls rename(): it moves the name to another list. The data and inode do not move at all, which is why a 5 GB mv takes milliseconds (the inode number stays the same).
  • Across file systems (laptop → USB disk), rename() is impossible, so mv copies then deletes: just as slow as cp.
  • cp creates a new inode and copies the data block by block. Modern cp can use copy_file_range() or reflinks (--reflink=auto on Btrfs/XFS) to share blocks.
  • rename() is atomic: other programs see either the old or the new name, never half. That is why programs write file.tmp and then mv file.tmp file.
  • rsync decides “changed?” by size and modification time (quick check). With -c it compares checksums. Over a network it sends only the changed parts of a file (delta transfer).

Did you know? The rsync algorithm was the subject of Andrew Tridgell’s PhD thesis at the Australian National University. Its trick: the receiver sends checksums of blocks it already has, so the sender only transmits the blocks that differ. That is why rsync can update a huge file over a slow link by sending a few kilobytes.

Exam tip: “Difference between cp and mv” → cp creates a copy and the original stays; mv moves or renames and the original name disappears; cp needs -r for directories, mv does not; on the same file system mv only changes directory entries (fast), across file systems it copies and deletes.

Quick check After cp report.txt backup/, how many report.txt files exist? After mv report.txt backup/?
Answer: cp: two (original and copy). mv: one, now inside backup/.

Answer: mv (it is the same file). cp only with -p or -a; rsync with -a (or -t).
4 Step by step

Each command explained, then used in every field

For every command: when to use it, every important option, one real run, and how it is used in different jobs. cp and mv outputs were recorded on Ubuntu 24.04; rsync outputs on Ubuntu 22.04 (rsync 3.2.7), because our build machine has no rsync.

cp copy

🟡 Changes filesno sudo

Copies files. With -r it copies folders and everything inside; with -a it also keeps dates, permissions and links. The original is never changed.

✓ Use it when
  • you need a second copy and the original must stay
  • you take a quick backup before editing a file
  • you copy a whole folder once (-a or -r)
✗ Don’t use it when
  • you copy the same big folder again and again (use rsync)
  • you only want to move or rename (mv is instant)
  • you copy to another server (rsync or scp)

Syntax: cp [OPTION]... SOURCE DEST · cp [OPTION]... SOURCE... DIRECTORY

cpcommand-avarchive + verbosedb_backup/source/home/user/backup/destination (last)

Source(s) first, destination last. If the last argument is an existing folder, the files go inside it.

OptionWhat it doesWhen to use it
(none)copy file(s); overwrites the target silentlyone-off copies
-r, -Rcopy folders recursivelyany folder
-a, --archiverecursive + keep dates, permissions, owner (if allowed), linksbackups, moving projects
-pkeep mode, owner and timestamps (files)copy a file but keep its date
-iask before overwritinginteractive work, safety
--update=none (old: -n)never overwrite an existing filescripts that must not replace files
-u, --updatecopy only when the source is newer or the target is missingquick manual refresh
-vprint each copysee what happened
--backup=numberedkeep the old target as name.~1~, ~2~ …overwrite but keep history

cp in software development

  1. Situation: Take a safety copy of a config file before editing it.

    echo "port=80" > app.conf
cp -v app.conf app.conf.bak
    'app.conf' -> 'app.conf.bak'

    Why this way: A .bak copy next to the file lets you undo your edit with cp app.conf.bak app.conf. -v confirms what was copied.

  2. Situation: Start a new project from a template folder.

    mkdir -p template/{src,tests} && touch template/README.md
cp -r template newapp && find newapp | sort
    newapp newapp/README.md newapp/src newapp/tests

    Why this way: -r copies the folder with everything inside. The new folder name is the destination.

cp in data administration

  1. Situation: Copy a dump into the backup folder, keeping its original date (so “newest backup” stays correct).

    echo 'dump' > night.sql && touch -d '2026-11-05 23:00' night.sql
cp night.sql b1.sql; cp -p night.sql b2.sql
for f in night b1 b2; do echo "$f.sql $(date -r $f.sql '+%F %H:%M')"; done
    night.sql 2026-11-05 23:00 b1.sql 2026-11-06 11:51 b2.sql 2026-11-05 23:00

    Why this way: Plain cp gives the copy the current time; -p keeps 23:00 of last night. Backup tools and clean-up scripts rely on these dates.

cp in system info / admin

  1. Situation: Copy a folder with all its permissions and dates, e.g. a home folder or website.

    mkdir -p site && echo hi > site/index.html && chmod 640 site/index.html
cp -a site site_copy && stat -c "%A %n" site/index.html site_copy/index.html
    -rw-r----- site/index.html -rw-r----- site_copy/index.html

    Why this way: -a keeps rw-r----- exactly. With plain cp -r, permissions are recalculated with your umask.

cp in data analysis / engineering

  1. Situation: Copy today’s CSV files into the input folder of a pipeline.

    touch sales_{north,south}.csv
mkdir -p input && cp -v sales_*.csv input/
    'sales_north.csv' -> 'input/sales_north.csv' 'sales_south.csv' -> 'input/sales_south.csv'

    Why this way: Several sources and a folder at the end. The wildcard is expanded by bash (Lesson 3.4).

cp in testing / qa

  1. Situation: Refresh test fixtures without destroying files a tester already changed by hand.

    mkdir -p fixtures && echo 'edited' > fixtures/users.csv
echo 'fresh' > users.csv
cp --update=none users.csv fixtures/
cat fixtures/users.csv
    edited

    Why this way: --update=none skips files that already exist. Old guides write -n; on Ubuntu 24.04 cp now warns that -n is non-portable.

cp in security

  1. Situation: Overwrite a config but keep every previous version for audit.

    echo v1 > fw.rules; echo v2 > new.rules
cp --backup=numbered new.rules fw.rules
echo v3 > new.rules; cp --backup=numbered new.rules fw.rules
ls fw.rules*
    fw.rules fw.rules.~1~ fw.rules.~2~

    Why this way: Each overwrite saves the previous file as .~1~, .~2~: you can see and restore exactly what changed.

cp in devops / cloud

  1. Situation: Copy a release into a numbered folder on the server.

    mkdir -p build && echo jar > build/app.jar
mkdir -p releases/v42 && cp -a build/. releases/v42/ && ls releases/v42
    app.jar

    Why this way: build/. means “the contents of build”, so files land directly in v42 (no extra build/ folder inside).

Common mistake
✗cp -n test_info.txt backup/ (Ubuntu 24.04 prints a warning)
✓cp --update=none test_info.txt backup/

Many notes still teach cp -n. It works, but coreutils 9.x warns: “behavior of -n is non-portable and may change in future; use --update=none instead”.

mv move

🟡 Changes filesno sudo

Moves files and folders to another place, or gives them a new name. The original name disappears. Folders need no option.

✓ Use it when
  • you rename a file or folder
  • you move something into another folder
  • you publish a finished file atomically (mv tmp final)
✗ Don’t use it when
  • you still need the original (use cp)
  • you rename 100 files by a pattern (use rename, Lesson 3.7)
  • the target name exists and you have not checked (use -i)

Syntax: mv [OPTION]... SOURCE DEST · mv [OPTION]... SOURCE... DIRECTORY

-iask before overwritingwhen the target may exist
-n, --no-clobbernever overwritescripts
-umove only if the source is newermerging folders
-vprint each movesee what happened
-b / --backupkeep the overwritten file as name~safety
-t DIRtarget folder firstwith xargs or find

mv in system info / admin

  1. Situation: Rename a log file before the application starts a new one (manual log rotation).

    echo "old lines" > app.log
mv app.log app.log.1 && touch app.log
ls app.log*
    app.log app.log.1

    Why this way: This is what logrotate does every night (Lesson 18.1). The running program keeps writing to the renamed file until it reopens.

mv in devops / cloud

  1. Situation: Deploy a new config without any moment where the file is half-written.

    printf 'port=8080\nworkers=4\n' > app.conf.tmp
mv app.conf.tmp app.conf && cat app.conf
    port=8080 workers=4

    Why this way: rename() is atomic: the app sees the old file or the new one, never a half-written one. Write to a temp name, then mv.

mv in data analysis / engineering

  1. Situation: Move processed files out of the incoming folder so they are not processed twice.

    mkdir -p incoming done && touch incoming/{a,b,c}.csv
mv incoming/*.csv done/ && ls incoming done
    done: a.csv b.csv c.csv incoming:

    Why this way: A classic pipeline pattern: incoming → processing → done (or failed). Moving is instant, even for big files.

mv in software development

  1. Situation: Rename a folder in a project.

    mkdir -p src/utils && touch src/utils/helpers.py
mv src/utils src/common && find src
    src src/common src/common/helpers.py

    Why this way: Folders need no option. (In a git project use git mv so git records it as a rename.)

mv in testing / qa

  1. Situation: Check what mv does when the target exists, safely.

    echo a > a.txt; echo b > b.txt
mv -n a.txt b.txt; cat b.txt; ls
    mv: not replacing 'b.txt' b a.txt b.txt

    Why this way: -n refuses to overwrite; both files stay. Without it, b.txt would be replaced by a.txt silently.

mv in security

  1. Situation: Quarantine a suspicious file: take it out of the web folder without deleting the evidence.

    mkdir -p www quarantine && echo "<?php ... ?>" > www/shell.php
mv -v www/shell.php quarantine/shell.php.txt && chmod 000 quarantine/shell.php.txt && stat -c "%A %n" quarantine/*
    renamed 'www/shell.php' -> 'quarantine/shell.php.txt' ---------- quarantine/shell.php.txt

    Why this way: Moving keeps the original data and inode for investigation; renaming to .txt and chmod 000 stop it from running or being served.

rsync remote sync

🟡 Changes filesno sudo

Copies files and folders like cp, but on every later run it sends only what is new or changed. It can mirror (delete extras), exclude patterns, show a preview, and work between computers.

✓ Use it when
  • you copy the same folder again and again (backups)
  • you need an exact mirror (--delete)
  • you copy to or from another server over SSH
✗ Don’t use it when
  • a one-time copy of a few files (cp is simpler)
  • rsync is not installed (sudo apt install rsync)
  • you are not sure about --delete and skipped --dry-run

Syntax: rsync [OPTION]... SRC... DEST

OptionWhat it doesWhen to use it
-aarchive: recursive, keep permissions, times, links, owneralmost always
-vlist the files it sendssee what changed
-zcompress during the transferover a network
-n, --dry-runshow what would happen, change nothingbefore --delete, always
--deletedelete files in DEST that are not in SRCexact mirrors
--exclude=PATTERNskip matching files or folderslogs, caches, node_modules
-i, --itemize-changesshow why each file is sentdebugging
--progress / -Pprogress bar (and resume partial files)big files
-e sshuse SSH to reach another computerremote copies (default today)
src/ vs srcslash = copy the contents; no slash = copy the folder itselfthe most common mistake

rsync in data administration

  1. Situation: Nightly: update the backup of the database dump folder. Nothing changed since yesterday.

    Recorded on Ubuntu 22.04 · rsync 3.2.7

    rsync -av db_backup/ backup/
    sending incremental file list sent 198 bytes received 13 bytes 422.00 bytes/sec total size is 6 speedup is 0.03

  2. Situation: Next night: schema.sql changed and a new dump appeared.

    sending incremental file list schema.sql dumps/day2.sql sent 315 bytes received 59 bytes 748.00 bytes/sec total size is 10 speedup is 0.03

    Why this way: Only the two changed files are sent. This is the whole point of rsync.

rsync in system info / admin

  1. Situation: Make the backup an exact mirror: app.log was deleted in the source. Preview first.

    Recorded on Ubuntu 22.04 · rsync 3.2.7

    rsync -av --delete --dry-run db_backup/ backup/
    sending incremental file list deleting app.log sent 197 bytes received 31 bytes 456.00 bytes/sec total size is 8 speedup is 0.04 (DRY RUN)

    Why this way: “deleting app.log … (DRY RUN)”: nothing was deleted yet. Read the list; only then run again without --dry-run.

  2. Situation: The trailing slash: copy the folder itself vs its contents.

    Recorded on Ubuntu 22.04 · rsync 3.2.7

    rsync -a db_backup backup2/; find backup2 | sort

    Why this way: No slash on the source → a db_backup folder inside backup2. Compare the next one.

  3. Situation: The same with a slash.

    Recorded on Ubuntu 22.04 · rsync 3.2.7

    rsync -a db_backup/ backup3/; find backup3 | sort
    backup3 backup3/app.log backup3/dumps backup3/dumps/day1.sql backup3/dumps/day2.sql backup3/schema.sql

    Why this way: With the slash, the contents go straight into backup3.

rsync in software development

  1. Situation: Copy a project but skip logs and generated folders.

    Recorded on Ubuntu 22.04 · rsync 3.2.7

    rsync -av --exclude='*.log' --exclude='dumps/' db_backup/ clean/
    sending incremental file list created directory clean ./ schema.sql sent 180 bytes received 66 bytes 492.00 bytes/sec total size is 4 speedup is 0.02

    Why this way: Excludes keep backups small: typical ones are node_modules/, .venv/, __pycache__/, *.log.

rsync in devops / cloud

  1. Situation: Deploy a built website to a web server over SSH.

    Typical output (cannot be recorded on our build machine)

    rsync -avz --delete public/ deploy@web01:/var/www/site/
    sending incremental file list index.html css/site.css sent 4,812 bytes received 64 bytes 3,250.67 bytes/sec total size is 182,330 speedup is 37.39

    Why this way: -z compresses, SSH encrypts, --delete removes pages you deleted locally. Only changed pages are uploaded.

rsync in networking

  1. Situation: Pull logs from a server to your laptop, resumable on a bad connection.

    Typical output (cannot be recorded on our build machine)

    rsync -avzP user@app01:/var/log/myapp/ ./app01-logs/
    receiving incremental file list app.log 52,428,800 100% 11.20MB/s 0:00:04 (xfr#1, to-chk=0/2)

    Why this way: -P = --partial --progress: if the connection drops, the next run continues the half-transferred file.

rsync in testing / qa

  1. Situation: Why was this file sent? Itemized changes.

    Recorded on Ubuntu 22.04 · rsync 3.2.7

    rsync -avi db_backup/ backup5/ | head -5
    sending incremental file list created directory backup5 cd+++++++++ ./ >f+++++++++ schema.sql cd+++++++++ dumps/

    Why this way: >f+++++++++ = a new file sent; on updates you see letters such as s (size) and t (time) that explain the reason.

Common mistake
✗rsync -av --delete src/ dest/ (first time, without checking)
✓rsync -av --delete --dry-run src/ dest/ then the same without --dry-run

If source and destination are swapped, or the source is empty (a disk not mounted), --delete makes the destination match: it deletes your backup. Always preview.

Undo and safety net

What if a copy or move went wrong?

  • Overwrote a file with cp or mv: no undo. Only a backup, git or a snapshot helps. Prevent it with -i, --update=none, or --backup=numbered; many people add alias cp="cp -i" and alias mv="mv -i" to ~/.bashrc.
  • Moved something and cannot find it: mv into an existing folder puts it inside; into a new name renames it. Look with ls -lt in the target, or find ~ -name "name" (Lesson 7.1). Next time use mv -v.
  • Copied into the wrong place: just delete the copy (Lesson 3.3); the original is untouched.
  • rsync --delete removed files: they are gone from the destination. Restore from the source or another backup. Prevent with --dry-run, or --backup --backup-dir=../deleted, which keeps deleted files.
  • Preview before running: cp/mv: put echo in front to see the expanded names; rsync: -n.

Error messages decoded

The errors students see most with cp and mv. Each was really produced on our build machine, with its exit status.

  1. mkdir -p test_data && touch test_data/a.csv

    cp: -r not specified; omitting directory 'test_data' exit status: 1

    What it means: cp copies only files unless told to go into folders.

    Fix: Add -r (or -a): cp -r test_data backup/.

  2. cp missing.txt backup/

  4. touch a.txt

    ls -l source/ and ls -l dest/: what exists where?

  2. 2. Choose the tool

Quick check What does cp -a keep that plain cp -r does not?
Answer: Timestamps, permissions, ownership (when allowed) and symbolic links as links. cp -r gives copies the current time and default permissions.
5 See it happen

What really moves when you copy, move and sync

Left: what Riya sees (times are illustrations). Right: what happens on the disk.

What really moves on the disk? 5 steps
What you see
  1. A big file has an inode number (shown by ls -i).
  2. cp reads and writes every byte, and the copy is a new file with a new inode.
  3. mv on the same disk finishes instantly and the inode number is unchanged.
  4. mv to a different disk is as slow as cp.
  5. Times are illustrations; the inode behaviour matches real runs.
Behind the screen
  1. A folder is a list of names pointing to inode numbers.
  2. cp creates a new inode and copies all data blocks.
  3. mv calls rename(): the name is removed from one list and added to another.
  4. Inodes belong to one file system, so across disks mv must copy, then delete.
  5. That is also why mv is atomic on one disk.

Under the hood: one system call for mv

The real file-related system calls of mv f d/ on our build machine. Three lines, and none of them reads or writes the data.

strace -e trace=%file,%desc mv f d/
renameat2(AT_FDCWD, "f", AT_FDCWD, "d/", RENAME_NOREPLACE) = -1 EEXIST (File exists) openat(AT_FDCWD, "d/", O_RDONLY|O_PATH|O_DIRECTORY) = 3 renameat2(AT_FDCWD, "f", 3, "f", RENAME_NOREPLACE) = 0

Recorded with strace on our Ubuntu build machine; library loading lines are hidden. You can run the same on your PC after sudo apt install strace.

First mv tries to rename f to the name d/ itself with RENAME_NOREPLACE (never overwrite); the kernel answers EEXIST because d already exists. So mv opens the folder d and renames f into it: renameat2(…, "f", 3, "f") = 0, done. No read or write of the data: the kernel only moves the name. Run the same with cp f d/ and you will see the file opened, the target created and the data copied.

Quick check Why is mv to a USB disk as slow as cp?
Answer: Inodes belong to one file system. Across file systems rename() is impossible, so mv copies the data and then deletes the original.

Interview and viva questions

What is the difference between cp and mv?

cp creates a copy and keeps the original; mv moves or renames, so the original name disappears. cp needs -r for folders; mv does not.

How do you copy a directory in Linux?

cp -r dir dest/ (or cp -a to keep timestamps, permissions and links).

How do you rename a file?

mv oldname newname. For many files at once by a pattern, use rename (Lesson 3.7).

What is the difference between rsync and cp?

rsync compares source and destination and transfers only new or changed files; it can delete extras (--delete), exclude patterns, preview (--dry-run) and copy over SSH. cp copies everything every time, locally only.

Why does rsync care about the trailing slash?

src/ means the contents of src; src means the folder itself, so it is created inside the destination.

How do you avoid overwriting files with cp?

cp -i to be asked, cp --update=none to skip existing files, or --backup=numbered to keep the old ones.

Is mv safe for big files?

On the same file system it is instant and atomic. Across file systems it copies then deletes; if interrupted, the original is still there.

Real-world scenario questions (asked in company interviews)

Interview questions about copying, moving and syncing, from fresher to senior rounds.

Any company · basicsFresher

“cp says omitting directory.”

You run cp project backup/ and nothing is copied.

The interviewer is checking: do you know cp’s recursive option?

Show a strong answer
  • cp copies only files by default; folders need -r.
  • For backups use cp -a: recursive and keeps dates and permissions.
  • Check with ls -R backup.

Avoid: saying “Linux cannot copy folders”.

Operations · backupsJunior

The backup that takes all night

A nightly cp -r of 200 GB no longer finishes before morning.

The interviewer is checking: do you know incremental copies?

Show a strong answer
  1. Replace with rsync -a --delete /data/ /backup/data/: only changes are copied.
  2. Preview the first run with --dry-run; watch with --stats.
  3. For history, rotate dated folders or use --link-dest snapshots (unchanged files become hard links).

Avoid: “buy a faster disk” as the only answer.

DevOps · deploymentsMid-level

Users saw a broken page during deploy

A deploy script writes the new index.html directly into the web folder; for a second, users get half a page.

The interviewer is checking: do you understand atomic replacement?

Show a strong answer
  • Write the new file to a temp name in the same file system, then mv tmp index.html: rename() is atomic.
  • For whole releases: upload to releases/v42/, then switch a symlink (ln -sfn, Lesson 10.2).
  • rsync already does this per file: it writes a temporary file and renames it.

Avoid: adding sleep or “deploy at night”.

Data platform · incidentSenior

rsync --delete wiped the backup

A nightly rsync -a --delete /mnt/data/ /backup/ ran while the data disk was not mounted. The backup is now empty.

The interviewer is checking: do you design safe automation?

Show a strong answer
  • An unmounted /mnt/data is an empty folder, so --delete mirrored “empty”.
  • Guards: check mountpoint -q /mnt/data or a marker file before syncing; use --max-delete=N; keep deleted files with --backup --backup-dir.
  • Keep several generations (snapshots), not one mirror; alert on unusual delete counts.

Avoid: blaming rsync instead of the missing checks.

Interview and certification corner

Difference between cp and mv?
cp makes a copy (original stays, new inode, needs -r for folders); mv moves or renames (original name gone, same inode on the same file system, works on folders directly).
How do you copy a folder and keep permissions and timestamps?
cp -a src dest/ (archive), or rsync -a src/ dest/.
Why is mv fast on the same disk but slow to a USB disk?
Same file system: rename() only changes directory entries. Different file system: mv must copy the data and then delete the original.
What does the trailing slash mean in rsync?
src/ copies the contents of src; src copies the folder itself into the destination.
How does rsync know what changed?
By default it compares size and modification time; with -c it compares checksums. Over a network it sends only changed blocks of a file (delta transfer).
How do you prevent cp from overwriting?
cp -i (ask), cp --update=none (skip; older -n), or --backup=numbered (keep the old file).
What is an atomic file replacement?
Writing to a temp file and mv-ing it over the target, so readers see the old or new file, never a partial one.
Where this appears in certification exams
  • RHCSA (EX200): “Create, delete, copy, and move files and directories”, part of the essential tools objectives.
  • LFCS: Essential Commands: copy, move and archive files; rsync for backups appears in operations tasks.
  • CompTIA Linux+: File management commands (cp, mv) and copying files between systems (rsync, scp).
