Deleting safely: rm, rm -r, rm -i, shred and why rm -rf is dangerous

One extra space in an rm -rf command deletes a project and its backup. This lesson explains rm and shred option by option, the five dangers to check for, how “deleted” files can still fill a disk, and how every IT team deletes safely.

There is no Recycle Bin in the terminal. One extra space in rm -rf /home/riya/project /backup deletes the project and the whole backup, in under a second, without a question. 2 Definition

rm, rm -r and shred

Formal definition (write this in exams)

rm (remove) deletes directory entries for files. With -r (recursive) it deletes directories and their entire contents; with -d it deletes empty directories. The data is released when no name and no open file refer to it any more; there is no recycle bin. shred overwrites a file’s contents several times with random data (and optionally zeros) and can then remove it, to make recovery harder.

In simple words

rm deletes for good, rm -r also folders, shred scribbles over the data first.

Deleting at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: no Recycle Bin

Deleting in the terminal is not like pressing Delete in Windows.

  • rm (remove) deletes at once. There is no bin and no “Undo”.
  • Folders need -r, which means “and everything inside”.
  • So the habit is: look first (ls), then delete.

Basic The commands you will type every day

  • rm file.txt deletes a file; rm a.txt b.txt several.
  • rm -r folder deletes a folder and all its content. rmdir or rm -d delete only empty folders.
  • rm -i asks “remove …?” for each file; answer y or n.
  • rm -v prints what it removed.
  • rm -f (force) never asks and does not complain about missing files. Use it only when you are sure.

Intermediate Questions, silence and strange names

  • -I asks once if you delete more than three files or delete recursively: a good everyday safety net (alias rm='rm -I').
  • rm asks before deleting a write-protected file only when you type at a keyboard; in scripts it just deletes it. -f also removes that question.
  • You need write permission on the folder, not on the file, to delete a file (Lesson 9.1).
  • A name starting with - looks like an option: use rm -- -name or rm ./-name.
  • --preserve-root (default) refuses rm -rf /; rm also refuses . and ...

Advanced Behind the screen: what “deleted” means

  • rm calls unlinkat(): it removes the name from the folder and lowers the inode’s link count (Lesson 10.1).
  • The data blocks are freed only when the link count is 0 and no process has the file open. A deleted log still held open by a program keeps using disk space (lsof +L1 finds them).
  • Freed blocks are not wiped; until they are reused, recovery tools may find the data. That is why shred overwrites first.
  • shred is unreliable on SSDs (wear levelling), on journaling or copy-on-write file systems (Btrfs, ZFS) and on files with backups or snapshots. Use full-disk encryption, blkdiscard or secure erase for real secrets.
  • rm -r walks the tree depth-first: files first, then each folder once it is empty.

Did you know? In 2017 an engineer at GitLab, tired after a long night of fixing replication, ran a recursive delete on the wrong database server and removed about 300 GB of production data. Five backup methods turned out not to be working. GitLab published the whole story openly; it is now a classic lesson: check the hostname, and test your backups.

Exam tip: “How do you delete a non-empty directory? What is the difference between rm -r, rm -rf and rmdir?” → rmdir only deletes empty directories; rm -r deletes a directory and its contents recursively; -f suppresses prompts and errors for missing files; there is no recycle bin, so use -i/-I or check with ls first.

Quick check Why does rm folder fail, while rm -r folder works?
Answer: Without -r, rm only removes files and says “Is a directory”. -r removes the folder and everything inside it.

Now the variations, by field. Pick the field you work in (or want to work in).

Same command, different jobs. Click a field.

rm in system info / admin

  1. Situation: Before deleting a folder, look at what is inside and how big it is.

    mkdir -p oldapp/logs && touch oldapp/app.jar oldapp/logs/a.log
ls -R oldapp
rm -r oldapp && echo "removed"
    oldapp: app.jar logs oldapp/logs: a.log removed

    Why this way: ls -R (or du -sh, Lesson 15.3) first, then delete. Two seconds of looking is the best safety feature.

  2. Situation: A full disk: a big log is still being written. Empty it instead of deleting it.

    printf "line\n%.0s" {1..1000} > app.log
> app.log
stat -c "%n %s bytes" app.log
    app.log 0 bytes

    Why this way: > app.log truncates to 0 bytes but keeps the file, so the program keeps writing and the space is freed at once. rm on an open file would not free the space (see Advanced).

rm in software development

  1. Situation: Clean build output and caches before a fresh build.

    mkdir -p build/obj __pycache__ && touch build/obj/a.o __pycache__/m.pyc
rm -rv build __pycache__
    removed 'build/obj/a.o' removed directory 'build/obj' removed directory 'build' removed '__pycache__/m.pyc' removed directory '__pycache__'

    Why this way: Generated folders are safe to delete: they are rebuilt. -v lists everything removed (real projects: make clean, git clean -n first).

rm in data analysis / engineering

  1. Situation: Remove yesterday’s temporary part files after the job succeeded.

    mkdir -p out && touch out/part-0000{0..3}.tmp out/_SUCCESS
[ -f out/_SUCCESS ] && rm -v out/*.tmp
ls out
    removed 'out/part-00000.tmp' removed 'out/part-00001.tmp' removed 'out/part-00002.tmp' removed 'out/part-00003.tmp' _SUCCESS

    Why this way: Delete temp files only after checking the success marker; a failed job keeps its files for debugging.

rm in data administration

  1. Situation: Delete old dumps, but be asked once because there are many.

    touch dump_{01..05}.sql
echo y | rm -I dump_*.sql; echo
ls dump_* 2>/dev/null | wc -l
    rm: remove 5 arguments? 0

    Why this way: -I asks one question (“remove 5 arguments?”) instead of five. Here the answer y comes from echo; at the keyboard you type it.

rm in devops / cloud

  1. Situation: A cleanup script deletes a release folder from a variable. Protect against an empty variable.

    release=""
rm -rf "/home/riya/lab/releases/${release:?release not set}" 2>&1; echo "exit status: $?"
    /home/riya/script.sh: line 2: release: release not set

    Why this way: ${var:?message} stops with an error if var is empty, so the path can never shrink to /home/riya/lab/releases/ (all releases).

rm in security

  1. Situation: A file with a strange name created by an attacker or a typo: -rf.

    touch -- -rf
ls
rm -- -rf
ls | wc -l
    -rf 0

    Why this way: Without --, rm -rf would read it as options. -- means “no more options”; rm ./-rf also works.

rm in testing / qa

  1. Situation: Reset the test workspace between runs, but never outside it.

    ws=/home/riya/lab/testws
mkdir -p "$ws/out" && touch "$ws/out/r.txt"
case "$ws" in /home/riya/lab/*) rm -rf "$ws" && echo "reset";; *) echo "refusing: $ws";; esac
    reset

    Why this way: A guard checks that the path is inside the expected folder before rm -rf runs.

Common mistake
✗rm -rf $dir/*
✓rm -rf -- "${dir:?}"/*

Unquoted and unchecked, an empty or space-containing $dir changes what is deleted. Quote it and use :?.

shred overwrite a file to hide its contents

🔴 Can destroy datano sudo

Overwrites the data of a file with random bytes several times, so that it is much harder to recover, and with -u deletes it afterwards.

✓ Use it when
  • a file held passwords, keys or personal data on a normal hard disk
  • you are retiring a USB stick or disk (whole device)
  • policy requires overwriting before deletion
✗ Don’t use it when
  • the disk is an SSD or the file system is copy-on-write (use encryption / secure erase)
  • copies exist elsewhere (backups, git, editor swap files)
  • a normal file you just want gone (plain rm)

Syntax: shred [OPTION]... FILE...

OptionWhat it doesWhen to use it
(none)overwrite 3 times with random data, keep the filewiping before reuse
-n Nnumber of passes (default 3)-n 1 is enough on modern disks
-za final pass of zeros, to hide the shreddingless suspicious result
-uremove the file after overwritingthe usual way to “delete securely”
-vshow progressbig files
-s SIZEshred only this many bytesdevices

First run (real output)

echo "password=Secret123" > creds.txt
shred -v -n 1 creds.txt
stat -c "%n %s bytes" creds.txt
head -c 20 creds.txt | od -An -c | head -1
shred: creds.txt: pass 1/1 (random)... creds.txt 4096 bytes q 233 020 034 0 344 w > 373 } 025 215 w q E [

After one pass the file is 4096 bytes of random data: shred rounds up to a full disk block, and the text is gone.

shred in security

  1. Situation: Remove a leaked API key file from a laptop disk (HDD) securely.

    echo "API_KEY=abc123" > key.txt
shred -u -z -n 1 key.txt
ls key.txt 2>&1
    ls: cannot access 'key.txt': No such file or directory

    Why this way: -u deletes after overwriting, -z ends with zeros. Then rotate the key anyway: assume a leaked secret is known.

shred in system info / admin

  1. Situation: Wipe a whole old USB disk before giving it away (needs root).

    Typical output (cannot be recorded on our build machine)

    sudo shred -v -n 1 -z /dev/sdb
    shred: /dev/sdb: pass 1/2 (random)...1.2GiB/14GiB 8% ... shred: /dev/sdb: pass 2/2 (000000)...14GiB/14GiB 100%

    Why this way: Triple-check the device name with lsblk (Lesson 15.1): sdb vs sda is the difference between a USB stick and your system disk.

shred in data administration

  1. Situation: Destroy a plain-text export of customer data after loading it.

    printf 'id,email\n1,a@x.in\n' > export.csv
shred -u export.csv && echo 'export destroyed'
    export destroyed

    Why this way: Exports often contain personal data; data-protection rules (such as India’s DPDP Act) expect you to dispose of it safely when it is no longer needed.

The five dangers: read every rm line for these

  1. 1 · A space in a path. rm -rf /home/riya/project /backup = two folders. Quote paths: "…".

  2. 2 · A wildcard in the wrong place. rm * .log (space!) deletes every file, then complains that “.log” does not exist. Check with echo rm * .log or ls *.log first.

  3. 3 · An empty variable. If $dir is empty, rm -rf "$dir/" becomes rm -rf /. Use "${dir:?}", which stops the script when dir is empty (see below).

  4. 4 · The wrong machine or folder. Check hostname and pwd before a big delete, especially with several terminals open (the GitLab story).

  5. 5 · -f out of habit. -f hides the warning that would have saved you. Use it in scripts with checked paths, not by default at the keyboard.

Danger 3, seen safely (real run: echo shows what rm would get)

dir=""
echo rm -rf "$dir/"
rm -rf "${dir:?dir is empty, stopping}/"
rm -rf / /home/riya/script.sh: line 3: dir: dir is empty, stopping

Undo and safety net

What if you deleted the wrong thing?

  • Stop writing to that disk: every new file may overwrite the freed blocks. On a server, stop the services writing there.
  • Restore from backup or git: this is the real undo. git checkout -- file or git restore file for tracked files; your rsync backup (Lesson 3.2) for the rest.
  • A program still has it open: the data still exists. Find it with lsof +L1 and copy it back from /proc/PID/fd/N.
  • Recovery tools: extundelete, photorec or testdisk may find data on ext4, but there is no guarantee. Snapshots (LVM, Btrfs, ZFS, cloud disks) are much better.
  • Prevent it next time: alias rm="rm -I", a trash folder (mv x ~/.trash/, or gio trash x on desktops, or the trash-cli package), and echo in front of risky commands.

Error messages decoded

The errors students see most with rm. Each was really produced on our build machine, with its exit status.

  1. mkdir reports
rm reports
    rm: cannot remove 'reports': Is a directory exit status: 1

    What it means: rm deletes only files unless told otherwise.

    Fix: Empty folder: rmdir reports or rm -d. With content: rm -r reports after ls -R reports.

  2. rm nofile.txt
    rm: cannot remove 'nofile.txt': No such file or directory exit status: 1

    What it means: There is no such file (typo, wrong folder, already deleted).

    Fix: Check with ls and Tab completion. In scripts, -f silences this.

  3. rm /etc/hostname
    rm: cannot remove '/etc/hostname': Permission denied exit status: 1

    What it means: You may not change the folder /etc.

    Fix: System files need sudo, and you should be very sure before deleting one.

  4. rm -r .
    rm: refusing to remove '.' or '..' directory: skipping '.' exit status: 1

    What it means: rm refuses to delete . or .. (the current or parent folder).

    Fix: Go up and name the folder: cd .. then rm -r foldername.

  5. rm -rf /
    rm: it is dangerous to operate recursively on '/' rm: use --no-preserve-root to override this failsafe exit status: 1

    What it means: The built-in failsafe --preserve-root refused to delete the whole system.

    Fix: Never override it. (As root, without the failsafe, this would destroy the system.)

  6. touch -- -x
rm -x
    rm: invalid option -- 'x' Try 'rm ./-x' to remove the file '-x'. Try 'rm --help' for more information. exit status: 1

    What it means: rm read “-x” as an option, not a file name.

    Fix: rm -- -x or rm ./-x.

What you see

Under the hood: rm is one system call per name

The real file-related system calls of rm notes.txt on our build machine.

strace -e trace=%file,%desc rm notes.txt
newfstatat(AT_FDCWD, "notes.txt", {st_mode=S_IFREG|0644, st_size=3, ...}, AT_SYMLINK_NOFOLLOW) = 0 unlinkat(AT_FDCWD, "notes.txt", 0) = 0

Recorded with strace on our Ubuntu build machine; library loading lines are hidden. You can run the same on your PC after sudo apt install strace.

newfstatat checks what the name is; unlinkat(AT_FDCWD, "notes.txt", 0) removes the name. That is all: no data is touched, which is why rm is instant even for huge files.

Quick check A program still writes to a log you deleted with rm. Is the disk space free?
Answer: No. The inode and data stay until the program closes the file. Truncate logs with > file instead, or restart the program.
6 Real-world use

Deleting safely at work

1. Log and temp cleanup

Servers delete old logs and temp files by age on a schedule (Lesson 7.1 and cron, Lesson 17.4), after testing the find without -delete.

Old files→find -delete→free disk

2. Guarded scripts

Production scripts quote every path, stop on empty variables (set -u, :?) and refuse paths outside an allowed folder.

Variable→check→rm -rf

3. Full disk incidents

On-call engineers truncate logs that are still open and look for deleted-but-open files with lsof +L1.

Disk 100%→truncate→space back

4. Data disposal

Security teams destroy exports and retired disks according to policy: shred for HDD files, secure erase or crypto-erase for SSDs.

Retire→wipe→compliant

5. Soft delete

Many teams move files to a trash or quarantine folder first and empty it after a few days: a cheap undo.

mv→wait→rm

Examples are simplified and generic. They describe common patterns, not the internal systems of any particular company.

Script it: cleanup.sh

A cleanup script with every safety net from this lesson: strict mode, a guarded folder, a preview, and a log of what was removed. (You will learn set -euo pipefail in Lesson 12.6.)

#!/bin/bash
set -euo pipefail
dir=${1:-/home/riya/lab/tmpwork}
mkdir -p "$dir" && touch "$dir"/{a,b}.tmp "$dir"/keep.csv     # demo files
case "$dir" in
  /home/riya/lab/*) ;;                       # allowed area only
  *) echo "refusing to clean $dir" >&2; exit 1 ;;
esac
shopt -s nullglob
files=("$dir"/*.tmp)
echo "will delete ${#files[@]} file(s)"
[ ${#files[@]} -gt 0 ] && rm -v -- "${files[@]}"
ls "$dir"
will delete 2 file(s) removed '/home/riya/lab/tmpwork/a.tmp' removed '/home/riya/lab/tmpwork/b.tmp' keep.csv

nullglob makes *.tmp expand to nothing when there are no matches, instead of the literal text “*.tmp”.

Puzzle answer Remember the question from the story? Open to check your guess.

rm did work: it removed the name. But a program (here the application writing the log) still had the file open. The kernel keeps the inode and its 20 GB of data until the last open handle is closed. lsof +L1 shows such “(deleted)” files. Restart or reload the program, or next time empty the log with > app.log (truncate) instead of deleting it.

Quick check Your script has rm -rf "$BUILD_DIR"/*. What happens if BUILD_DIR is empty, and how do you prevent it?
Answer: It becomes rm -rf /*. Use "${BUILD_DIR:?}" or set -u, and check the path is inside the expected folder.

Recorded on our build machine: 7 bytes became 4096, one full block of random data.

Quick revision

Lesson 3.3 in one screen

  • rm file deletes at once: no bin, no undo. Look first with ls.
  • Folders: rm -r dir (all inside); empty only: rmdir / rm -d.
  • -i ask each, -I ask once, -v show, -f no questions (scripts only).
  • Five dangers: a space in a path, a stray *, an empty variable, the wrong machine, -f by habit.
  • Guards: quotes, "${dir:?}", set -u, --, preview with echo.
  • rm removes names (unlink); data is freed when no name and no open file remain (lsof +L1).
  • Free a log being written: > app.log or truncate -s 0.
  • shred -u -z file overwrites then deletes; not reliable on SSD, CoW or snapshotted file systems.

Interview and viva questions

How do you delete a non-empty directory in Linux?

rm -r directory. Check it first with ls -R. rmdir only deletes empty directories.

What is the difference between rm -r and rm -rf?

-f suppresses all prompts (even for write-protected files) and errors for missing files. -rf deletes everything silently.

Is there a recycle bin for rm?

No. Use a trash folder (mv), gio trash on desktops, trash-cli, version control or backups for undo.

How do you delete a file whose name starts with a dash?

rm -- -filename or rm ./-filename.

Why is disk space not freed after deleting a file?

A process still has the file open. The space is freed when it closes the file; find such files with lsof +L1.

How do you securely delete a file?

shred -u -z file on traditional hard disks. On SSDs and copy-on-write file systems use full-disk encryption and secure erase instead.

What does --preserve-root do?

It is rm’s default safety: it refuses to recursively delete /.

Interview and certification corner

  
What is the difference between rm, rm -r, rm -f and rmdir?
rm deletes files; -r also folders and their content; -f removes prompts and missing-file errors; rmdir deletes only empty folders.
How do you make rm safer at the keyboard?
alias rm="rm -I", Tab completion, look with ls first, preview with echo, and use a trash folder for anything you might need.
What happens to a file’s data when you rm it?
The name is unlinked and the link count drops. When it reaches 0 and no process has it open, the blocks are marked free, not wiped.
How do you find files that are deleted but still use space?
lsof +L1 (or ls -l /proc/*/fd | grep deleted).
Why is rm -rf "$dir/" dangerous in scripts?
If dir is empty it becomes rm -rf /. Use "${dir:?}" and set -u.
Does shred work on SSDs?
Not reliably, because of wear levelling and over-provisioning. Use encryption and the drive’s secure erase.
How do you delete a file named -rf?
rm -- -rf or rm ./-rf.
