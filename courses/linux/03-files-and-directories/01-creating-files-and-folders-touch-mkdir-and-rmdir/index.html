2 Definition

touch, mkdir and rmdir

Formal definition (write this in exams)

mkdir (make directory) creates one or more directories; with -p it also creates missing parent directories and does not fail if the directory exists. rmdir (remove directory) deletes directories only when they are empty. touch sets the access and modification timestamps of files to the current time (or a given time), and creates any file that does not exist as an empty file. Files with content are created by redirecting the output of echo, printf or cat into a file.

In simple words

mkdir makes folders, touch makes empty files (or updates their time), rmdir removes empty folders.

Creating files and folders at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: shelves and notebooks

Think of your home folder as a school cupboard.

  • A folder (directory) is a shelf. mkdir = “make a new shelf”.
  • A file is a notebook. touch = “put a new, empty notebook here” (or, if it is already there, write today’s date on the cover).
  • rmdir takes a shelf away, but only an empty one, so no notebook is ever thrown away by mistake.

Basic The commands you will type every day

  • mkdir reports creates one folder; mkdir a b c creates three.
  • mkdir -p project/src/utils creates every missing level, and gives no error if it already exists.
  • touch file.txt creates an empty file (0 bytes). On an existing file it changes nothing inside, only the time.
  • rmdir old removes an empty folder; for a folder with files you need rm -r (Lesson 3.3).
  • Files with text: echo "Hello" > file.txt (overwrite), echo "more" >> file.txt (add at the end).

Intermediate Timestamps, braces and content

  • Each file has three times: access (atime, last read), modify (mtime, content changed) and change (ctime, details changed). touch sets atime and mtime to now; -a or -m sets only one; -d or -t sets any date; -r ref copies another file’s times.
  • touch -c (no-create) updates only files that already exist.
  • Brace expansion is done by bash, not by mkdir or touch: {a,b} = a list, {01..12} = a sequence with zero padding.
  • printf understands \n, \t, %s, %d everywhere; bash’s echo needs -e for escapes. Use printf in scripts.
  • cat > file <<'EOF' … EOF (a here-document) writes many lines at once: perfect for config files in scripts.

Advanced Behind the screen: what really happens

  • touch calls openat(…, O_CREAT) to create the file if needed, then utimensat() to set the times. A new file gets a new inode (Lesson 10.1) and a name in the folder.
  • mkdir is one system call, mkdir(). A new folder already contains two entries, . and .., so its link count starts at 2.
  • rmdir calls rmdir(), which the kernel refuses with ENOTEMPTY if anything except . and .. is inside. The safety check is in the kernel, not in the command.
  • New permissions = default (666 for files, 777 for folders) minus the umask (usually 022) → rw-r--r-- and rwxr-xr-x. mkdir -m 700 sets the mode directly (Lesson 9.3).
  • An empty file uses 0 data blocks: only its inode and the name in the folder exist.

Did you know? Brace expansion like {01..12} is done by bash, not by touch. That is why it also works with mkdir, cp and echo. Try echo report_{01..12}.csv: echo just prints what the shell built.

Exam tip: “Difference between touch and mkdir; how do you create a directory tree?” → touch creates empty files or updates timestamps, mkdir creates directories; mkdir -p a/b/c creates all missing parents and does not fail if the tree exists; rmdir removes only empty directories.

Quick check You run mkdir -p project/src twice. What happens the second time?
Answer: Nothing, and no error: -p means “make sure it exists”. Without -p, the second run fails with “File exists”.

Common mistake
✗echo -e is not needed; echo cannot use \n anyway
✓printf "line1\nline2\n" > f.txt (or echo -e "line1\nline2")

A common classroom note says “echo cannot use escape characters”. In bash, echo -e does understand \n and \t; plain echo prints them literally. printf always understands them and behaves the same in every shell, which is why scripts prefer it.

Quick check Which one overwrites an existing file: > or >>?
Answer: > empties the file first, then writes. >> adds to the end and keeps what was there.
4 Step by step

Each command explained, then used in every field

For every command: what it does, every important option and when to use it, one real run, and then how it is used in different jobs. All outputs were recorded on a real Ubuntu machine as the user riya.

mkdir make directory

🟡 Changes filesno sudo

Creates one or more folders. With -p it creates a whole path, including every missing parent, and is happy if the folder already exists.

✓ Use it when
  • you need a new folder, or a whole path of folders
  • a script must make sure a folder exists (-p)
  • you want private folders from the start (-m 700)
✗ Don’t use it when
  • the name already exists as a file
  • you only want to check if a folder exists (use [ -d dir ])

Syntax: mkdir [OPTION]... DIRECTORY...

mkdircommand-pvoptions -p -vapp/{src,tests}argument (expanded by bash)

Options start with a dash; you can combine short options (-p -v = -pv). Everything after the options are folder names.

OptionWhat it doesWhen to use it
(none)create the folder(s) namedone or a few folders in the current place
-p, --parentscreate missing parent folders; no error if it existsnested paths, scripts that may run twice
-v, --verboseprint a line for each folder createdseeing exactly what was made; logs
-m, --mode=MODEset the permissions of the new folderprivate folders: -m 700
a b cseveral folders in one commandproject folders
{x,y,z}brace expansion (bash) builds the listmany similar folders

mkdir in software development

  1. Situation: Start a new Python project with source, tests and docs folders.

    mkdir -p myapp/{src/myapp,tests,docs}
ls -R myapp
    myapp: docs src tests myapp/docs: myapp/src: myapp myapp/src/myapp: myapp/tests:

    Why this way: One command, any depth. The braces give three branches; -p makes the parent myapp and src automatically.

  2. Situation: A build script must create its output folder, whether or not it already exists.

    mkdir -p build/dist && echo "ready"
mkdir -p build/dist && echo "still ready"
    ready still ready

    Why this way: -p makes the script idempotent: safe to run again and again. Plain mkdir would fail on the second run.

mkdir in data administration

  1. Situation: Create a dated folder for tonight’s MySQL backup.

    mkdir -p backups/mysql/2026-11-06
ls backups/mysql
    2026-11-06

    Why this way: A date in the path (often $(date +%F) in the real script) keeps every night’s dump separate and easy to clean up later.

  2. Situation: Archive logs go in one folder per month of the year.

    mkdir -p archive/2026/{01..12}
ls archive/2026 | tr "\n" " "; echo
    01 02 03 04 05 06 07 08 09 10 11 12

    Why this way: {01..12} pads with zeros, so the folders sort correctly (01, 02 … 10, 11, 12).

mkdir in data analysis / engineering

  1. Situation: A data-lake style layout: raw, cleaned and curated zones, partitioned by date.

    mkdir -pv lake/{raw,clean,curated}/sales/dt=2026-11-06 | head -4
    mkdir: created directory 'lake' mkdir: created directory 'lake/raw' mkdir: created directory 'lake/raw/sales' mkdir: created directory 'lake/raw/sales/dt=2026-11-06'

    Why this way: Hive, Spark and many data lakes use key=value folder names for partitions. One mkdir -p builds the whole pattern.

mkdir in devops / cloud

  1. Situation: Prepare folders for a Docker app: config, data volume and logs.

    mkdir -p /home/riya/lab/srv/shop/{config,data,logs}
ls /home/riya/lab/srv/shop
    config data logs

    Why this way: An absolute path works from any current folder; in real servers this is often /srv/app or /opt/app (with sudo).

mkdir in security

  1. Situation: A folder for private keys that only you may open.

    mkdir -m 700 secrets
ls -ld secrets | cut -c1-10
    drwx------

    Why this way: -m 700 sets rwx------ at creation time, so there is no moment when others could read it (Lesson 9.2).

mkdir in system info / admin

  1. Situation: An admin creates folders for a service under /var/log, which needs root.

    Typical output (cannot be recorded on our build machine)

    sudo mkdir -p /var/log/myapp
    (no output: the folder is created as root)

    Why this way: System folders belong to root. Without sudo you get “Permission denied” (see Error messages below).

mkdir in testing / qa

  1. Situation: Fresh test fixtures folder for every test run.

    mkdir -p fixtures/{input,expected,actual}
ls fixtures
    actual expected input

    Why this way: Tests compare actual with expected; keeping them in fixed folders makes the comparison easy (Lesson 6.3: diff).

mkdir in system design

  1. Situation: Design a standard layout every team must follow (like the Linux FHS, Lesson 2.1).

    mkdir -p app/{bin,conf,lib,logs,run,tmp}
ls app | tr "\n" " "; echo
    bin conf lib logs run tmp

    Why this way: A fixed layout means scripts, monitoring and backups know where to look, on every server. bin = programs, conf = settings, run = PID files.

Common mistake
✗mkdir dbda/data/raw (when dbda/ does not exist yet)
✓mkdir -p dbda/data/raw

Without -p, mkdir only creates the last part and fails with “No such file or directory” if a parent is missing.

touch touch a file (update its time)

🟡 Changes filesno sudo

Creates an empty file if it does not exist. If it does exist, touch leaves the content alone and only sets its access and modification time to now (or to the time you give).

✓ Use it when
  • you need an empty file or a placeholder (marker file)
  • you want to change a file’s date for testing or a build tool
  • you want many empty files at once with braces
✗ Don’t use it when
  • you want text in the file (use echo, printf or cat)
  • you want to empty a file (touch never does that; use > file)

Syntax: touch [OPTION]... FILE...

touchcommand-d "10 days ago"option with a valueold.logfile name

An option that takes a value (-d) is followed by that value; quote it if it has spaces.

OptionWhat it doesWhen to use it
(none)create empty file(s), or update their time to nowplaceholders; “refresh” a file
-c, --no-createdo not create missing filesupdate times only where files exist
-achange only the access timerare: testing tools that read atime
-mchange only the modification timemake a build tool think a file changed
-d, --date=STRINGuse this date instead of now“10 days ago”, “2026-01-01 09:00”
-t [[CC]YY]MMDDhhmm[.ss]date in compact digitsscripts, old Unix style
-r, --reference=FILEcopy the times of another filekeep the original date after editing

First run (real output)

echo "40 lines of notes" > notes.txt
touch notes.txt new.txt
stat -c "%A %s bytes  %n" notes.txt new.txt
-rw-r--r-- 18 bytes notes.txt -rw-r--r-- 0 bytes new.txt

notes.txt keeps its 18 bytes (content untouched); new.txt is a new, empty file of 0 bytes.

Same command, different jobs. Click a field.

touch in software development

  1. Situation: Create the usual empty starter files of a project.

    touch README.md .gitignore requirements.txt
ls -A
    .gitignore README.md requirements.txt

    Why this way: Several names in one command. ls -A also shows the hidden .gitignore (Lesson 2.4).

  2. Situation: Force make to rebuild by marking a source file as changed.

    touch -m main.c && date -r main.c "+main.c modified %F %T"
    main.c modified 2026-11-06 11:51:31

    Why this way: Build tools compare modification times; touch -m makes the file look newer than its output.

touch in data analysis / engineering

  1. Situation: A Spark or Hadoop job writes an empty _SUCCESS file when it finishes; the next job waits for it.

    mkdir -p output/sales && touch output/sales/_SUCCESS
[ -f output/sales/_SUCCESS ] && echo "upstream done, start the next job"
    upstream done, start the next job

    Why this way: An empty “marker file” is a cheap signal between programs. Airflow and other schedulers check for it.

  2. Situation: Twelve empty monthly CSV files for a report.

    touch report_{01..12}.csv
ls report_* | head -3; ls report_* | wc -l
    report_01.csv report_02.csv report_03.csv 12

    Why this way: Bash expands the braces into twelve names before touch runs.

touch in testing / qa

  1. Situation: Test a “delete logs older than 7 days” script, without waiting a week.

    touch -d "10 days ago" old.log
touch new.log
for f in $(ls -t *.log); do echo "$f $(date -r $f +%F)"; done
    new.log 2026-11-06 old.log 2026-10-27

    Why this way: -d sets any date, so you can create old-looking test files in seconds. (Your dates will be relative to today.)

  2. Situation: Check that a script does not create files that should already exist.

    touch -c missing.txt
ls missing.txt 2>&1
    ls: cannot access 'missing.txt': No such file or directory

    Why this way: -c never creates: a quick way to update times only on files that really exist.

touch in data administration

  1. Situation: Create an empty log file before starting a database import, so a monitor can follow it.

    touch import_2026-11-06.log && stat -c "%A %s bytes  %n" import_2026-11-06.log
    -rw-r--r-- 0 bytes import_2026-11-06.log

    Why this way: tail -f (Lesson 3.5) needs the file to exist; touch creates it first.

touch in security

  1. Situation: After fixing a config file, keep its original timestamp (for example, for a change audit you compare later).

    touch -d "2026-01-15 10:00" app.conf
cp app.conf edited.conf && echo "port=8080" >> edited.conf
touch -r app.conf edited.conf
for f in app.conf edited.conf; do echo "$f $(date -r $f +%F_%T)"; done
    app.conf 2026-01-15_10:00:00 edited.conf 2026-01-15_10:00:00

    Why this way: -r copies the time of a reference file. Security note: because anyone can do this, a file’s timestamp alone is not proof of when it changed. Investigators also use logs and checksums.

touch in system info / admin

  1. Situation: Is this folder writable for me? Try to create a file.

    touch /etc/test.txt 2>&1; touch ~/lab/test.txt && echo "lab is writable"
    touch: cannot touch '/etc/test.txt': Permission denied lab is writable

    Why this way: A quick, harmless write test. /etc belongs to root, so it is refused; your home folder is yours.

touch in devops / cloud

  1. Situation: A deployment creates a “maintenance mode” flag; the web app shows a maintenance page while it exists.

    touch maintenance.flag && [ -e maintenance.flag ] && echo "site in maintenance"
rm maintenance.flag && echo "site live"
    site in maintenance site live

    Why this way: Many apps and load balancers check for a flag file like this (Laravel, health checks). Creating and deleting it is instant and atomic.

rmdir remove directory

🟡 Changes filesno sudo

Deletes folders, but only empty ones. If anything is inside, it refuses, so it can never delete your files.

✓ Use it when
  • a folder is empty and you want it gone
  • cleanup scripts that must never delete data
  • removing a chain of empty folders (-p)
✗ Don’t use it when
  • the folder has files you also want to delete (use rm -r, Lesson 3.3)
  • you want to delete a file (use rm)

Syntax: rmdir [OPTION]... DIRECTORY...

OptionWhat it doesWhen to use it
(none)remove the empty folder(s)clean up after moving files out
-p, --parentsalso remove the parents, if they become emptyremove a whole empty chain: a/b/c
-v, --verboseprint each folder removedsee exactly what went
--ignore-fail-on-non-emptydo not report folders that are not emptycleanup scripts over many folders

First run (real output)

mkdir -p old/empty full
touch full/data.csv
rmdir old/empty && echo "empty folder removed"
rmdir full
empty folder removed rmdir: failed to remove 'full': Directory not empty

The second rmdir fails on purpose: full contains data.csv. For non-empty folders use rm -r (Lesson 3.3), carefully.

rmdir in system info / admin

  1. Situation: Remove a whole chain of empty folders left by an uninstall.

    mkdir -p tmp/a/b/c
rmdir -pv tmp/a/b/c
    rmdir: removing directory, 'tmp/a/b/c' rmdir: removing directory, 'tmp/a/b' rmdir: removing directory, 'tmp/a' rmdir: removing directory, 'tmp'

    Why this way: -p walks up the path and removes each parent once it is empty.

rmdir in data analysis / engineering

  1. Situation: After a pipeline run, remove only the empty partition folders and keep the ones with data.

    mkdir -p out/dt=01 out/dt=02 out/dt=03
touch out/dt=02/part-0000.csv
rmdir --ignore-fail-on-non-empty out/*
ls out
    dt=02

    Why this way: rmdir is a safe filter: it deletes the empty ones and silently keeps any folder that holds data.

rmdir in security

  1. Situation: Why prefer rmdir to rm -r in cleanup scripts?

    mkdir -p logs && touch logs/app.log
rmdir logs 2>&1; ls logs
    rmdir: failed to remove 'logs': Directory not empty app.log

    Why this way: The kernel itself refuses to remove a non-empty folder with rmdir, so a typo in a path cannot wipe data. rm -r would delete everything without asking.

rmdir in devops / cloud

  1. Situation: Remove the per-release folders that are empty after a rollback.

    mkdir -p releases/v1 releases/v2 releases/v3
touch releases/v3/app.jar
rmdir -v --ignore-fail-on-non-empty releases/*
ls releases
    rmdir: removing directory, 'releases/v1' rmdir: removing directory, 'releases/v2' rmdir: removing directory, 'releases/v3' v3

    Why this way: Empty releases go, the release with an app stays. -v logs what was removed.

echo · printf · cat files with content

🟡 Changes filesno sudo

Three ways to create a file with text in it. They all print text; the > or >> redirection sends that text into a file instead of the screen (Lesson 5.2).

✓ Use it when
  • echo: one quick line
  • printf: exact format, CSV rows, scripts
  • cat with a here-document: a whole config file from a script
✗ Don’t use it when
  • the file must keep its old content and you typed > (use >>)
  • long files you will edit by hand (use nano or vim, Module 4)

Syntax: echo [TEXT] > FILE · printf FORMAT [ARGS] > FILE · cat > FILE <<'EOF' … EOF

OptionWhat it doesWhen to use it
echo "text" > fwrite one line; overwrites the filequick one-line files
echo "text" >> fadd a line at the endlogs, lists
echo -e "a\tb\n"bash echo: understand escapesquick tests (use printf in scripts)
echo -n "text"no newline at the endprompts, joining output
printf "%s,%d\n" name 42formatted text: %s text, %d number, \n newlineCSV rows, aligned reports
cat > ftype lines, finish with Ctrl+Dquick notes by hand
cat > f <<'EOF'here-document: all lines until EOFconfig files and scripts from a script

echo · printf · cat in data analysis / engineering

  1. Situation: Create a small CSV with a header row to test a pipeline.

    printf '%s,%s,%s\n' id name marks 1 Asha 91 2 Ravi 78 > marks.csv
cat marks.csv
    id,name,marks 1,Asha,91 2,Ravi,78

    Why this way: printf reuses its format for every 3 arguments, so one command writes the header and all rows.

echo · printf · cat in devops / cloud

  1. Situation: A deployment script writes a config file.

    cat > app.env <<'EOF'
APP_PORT=8080
DB_HOST=db.internal
LOG_LEVEL=info
EOF
cat app.env
    APP_PORT=8080 DB_HOST=db.internal LOG_LEVEL=info

    Why this way: Quoting 'EOF' keeps $ and backticks exactly as written. Without quotes, bash would expand variables inside.

  2. Situation: The same, but with values filled in from variables.

    PORT=9090
cat > app.env <<EOF
APP_PORT=$PORT
EOF
cat app.env
    APP_PORT=9090

    Why this way: Unquoted EOF: bash replaces $PORT before writing.

echo · printf · cat in software development

  1. Situation: Add entries to .gitignore without opening an editor.

    printf '%s\n' '__pycache__/' '*.log' '.env' >> .gitignore
cat .gitignore
    __pycache__/ *.log .env

    Why this way: >> keeps anything already in the file; printf writes one pattern per line.

echo · printf · cat in system info / admin

  1. Situation: Log a line with a timestamp from a cron job.

    echo "$(date +%F) backup finished" >> cron.log
cut -d" " -f2- cron.log
    backup finished

    Why this way: Each run appends one line; nothing is lost. (The date part is cut off here because it changes every day.)

echo · printf · cat in security

  1. Situation: Create a file that will hold a secret, with safe permissions from the start.

    (umask 077; echo "API_KEY=changeme" > token.txt)
ls -l token.txt | cut -c1-10
    -rw-------

    Why this way: Setting umask 077 in a subshell makes the new file rw-------: nobody else can read it, not even for a moment.

echo · printf · cat in testing / qa

  1. Situation: Create an input file with tricky content: a tab, an empty line and spaces at the end.

    printf 'a\tb\n\nend  \n' > tricky.txt
cat -A tricky.txt
    a^Ib$ $ end $

    Why this way: cat -A shows tabs as ^I and line ends as $: you can see exactly what is in the test file.

Common mistake
✗echo "Test executed on: $(date)" > test.txt (to add one more line)
✓echo "Test executed on: $(date)" >> test.txt

One > replaces the whole file. Double-check > vs >> before pressing Enter; with set -o noclobber bash refuses to overwrite with >.

Undo and safety net

What if you created something by mistake?

  • A folder you just made: rmdir name removes it while it is still empty. Safe.
  • Files made with a wrong brace pattern: repeat the same pattern with echo first to see the names, then remove them: echo report_{01..12}.csv → rm report_{01..12}.csv.
  • Overwritten a file with >: there is no undo in the shell. Only a backup, version control (git) or a file-system snapshot can bring the old content back. Prevent it with set -o noclobber.
  • touch changed a file’s date: only the time changed; restore it with touch -r backup_copy file or touch -d "old date" file.
  • Preview before running: put echo in front: echo mkdir -p app/{a,b} prints what would run, without running it.

5 See it happen

What touch, mkdir and rmdir really change

Left: what Riya sees. Right: what happens in the file’s record. Times are examples; sizes and behaviour match real runs.

What changes in the file’s record (inode)? 5 steps
What you see
  1. Riya’s notes: 18 bytes, last modified at 09:15.
  2. touch notes.txt sets the modification and access times to now.
  3. The content is exactly the same. Nothing was lost.
  4. On a missing name, touch creates an empty file.
  5. What really erases content is >: echo hi > notes.txt replaces it.
Behind the screen
  1. Every file has an inode: a record with size, owner, permissions and three times.
  2. touch opens the file (creating it only if missing) and calls utimensat().
  3. touch never calls write(), so the size and the data blocks are unchanged.
  4. O_CREAT tells the kernel: create the file if it is not there.
  5. The shell opens the target of > with O_TRUNC, which empties it before echo writes.

Under the hood: the system calls

This is the real list of file-related system calls that touch notes.txt made on our build machine. Look for the two lines that matter.

strace -e trace=%file,%desc touch notes.txt
openat(AT_FDCWD, "notes.txt", O_WRONLY|O_CREAT|O_NOCTTY|O_NONBLOCK, 0666) = 3 utimensat(0, NULL, NULL, 0) = 0 close(0) = 0

Recorded with strace on our Ubuntu build machine; library loading lines are hidden. You can run the same on your PC after sudo apt install strace.

openat(…"notes.txt", O_WRONLY|O_CREAT…) opens the file and creates it if it is missing. utimensat(0, NULL, …) sets both times to “now” (NULL means current time). There is no write(): touch never writes content. Compare mkdir, which is just one call, mkdir("name", 0777); the umask then turns 0777 into 0755.

Interview and viva questions

What is the difference between touch and mkdir?

touch creates empty files (or updates their timestamps); mkdir creates directories.

How do you create nested directories in one command?

mkdir -p parent/child/grandchild. It creates all missing levels and does not fail if they exist.

Why does rmdir fail on a directory that looks empty?

It probably contains hidden files (names starting with a dot). Check with ls -A. rmdir only removes truly empty directories.

How do you create a file with content without an editor?

echo "text" > file, printf "format" > file, or cat > file with a here-document (<

What are the three timestamps of a file?

atime (last access), mtime (last content modification), ctime (last change of metadata such as permissions). touch updates atime and mtime; ctime changes automatically.

How do you create 100 files at once?

With brace expansion: touch file_{001..100}.txt. Bash builds the 100 names.

Is touch dangerous?

No: it never changes content. The danger is > redirection, which empties a file before writing.

Real-world scenario questions (asked in company interviews)

Interview questions about creating files and folders, from fresher to senior rounds.

Any company · basicsFresher

“Create 50 test files quickly.”

The interviewer asks you to create file1.txt to file50.txt for a test.

The interviewer is checking: do you know brace expansion and touch?

Show a strong answer
  • touch file{1..50}.txt: bash expands the names, touch creates them.
  • Check with ls file* | wc -l → 50.
  • For sorted names use padding: {01..50}.

Avoid: a loop that runs touch 50 times, or saying it cannot be done without a script.

Operations · scriptingJunior

The script that fails on its second run

A start-up script has mkdir /home/app/logs. It works once, then fails every restart.

The interviewer is checking: do you understand idempotent scripts?

Show a strong answer
  1. The second run fails with “File exists”, and with set -e the script stops.
  2. Fix: mkdir -p /home/app/logs: same result every time, no error.
  3. Same idea for files: touch is also safe to repeat.

Avoid: adding 2>/dev/null to hide the error without fixing the logic.

Data engineeringMid-level

“How does the next job know the data is ready?”

A Spark job writes many part files. A downstream job must not read half-written output.

The interviewer is checking: do you know marker files?

Show a strong answer
  • The writer creates an empty _SUCCESS file (touch) only after all parts are written.
  • The reader (or Airflow sensor) waits for _SUCCESS before reading.
  • Writing to a temp folder and renaming it at the end (mv is atomic on one file system, Lesson 3.2) is another safe pattern.

Avoid: “wait 10 minutes and hope it is finished”.

Security · auditSenior

“Can we trust the file’s modification date?”

During an incident review, someone says a config file was not changed because its mtime is three months old.

The interviewer is checking: do you know that timestamps can be set by any owner?

Show a strong answer
  • touch -d or touch -r lets the owner set any atime/mtime, so mtime alone proves nothing.
  • ctime cannot be set with touch; it changes on every metadata change, but root can still change the clock.
  • Use audit logs (auditd), file integrity tools (AIDE), checksums and backups or version control as evidence.

Avoid: trusting ls -l dates as proof.

Interview and certification corner

What is the difference between mkdir and mkdir -p?
Plain mkdir creates only the last part of the path and fails if it exists or a parent is missing. -p creates all missing parents and does not fail if the directory already exists.
Does touch change the content of a file?
No. It creates an empty file if missing; otherwise it only updates the access and modification times.
How do you remove a directory that is not empty?
rmdir cannot. Use rm -r dir (carefully, after checking with ls -A), covered in Lesson 3.3.
What is the difference between > and >>?
> truncates (empties) the file and writes; >> appends to the end. Both create the file if it does not exist.
How do you create a file with several lines from a script?
A here-document: cat > file <<'EOF' … EOF. Quote EOF to stop variable expansion.
Why does a new folder have a link count of 2?
Its name in the parent folder, plus the . entry inside itself. Each subfolder adds one more (its .. entry).
How do you set a specific date on a file?
touch -d "2026-01-01 10:00" file, or touch -t 202601011000 file, or copy from another file with touch -r ref file.
