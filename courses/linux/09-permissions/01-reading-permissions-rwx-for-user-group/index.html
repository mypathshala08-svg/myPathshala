Reading permissions: rwx for user, group and others

Ten characters in ls -l decide who may read, change or run each file. This lesson teaches you to read them exactly, explains why folders behave differently, and shows how admins, web, DevOps, security and testers diagnose “Permission denied”.

The problem

A deploy fails with “Permission denied” on a script the developer just wrote. A password file can be read by every user on the server. A web page returns 403 although the file is clearly there. All three are answered by ten characters you have seen a hundred times in ls -l: -rw-r--r--. Today you learn to read them like a sentence: who may do what, for files and, differently, for folders.

By the end of this page you will be able to:
  • read every character of a permission string (-rwxr-x---) and the owner and group columns
  • explain what r, w and x mean for a file and what they mean for a directory (they are different)
  • work out, step by step, whether a given user can read, change or run a given file
  • see permissions with ls -l, ls -ld, stat and namei -l, and decode “Permission denied”

2 Definition

File permissions: rwx for user, group and others

Formal definition (write this in exams)

Every file and directory has an owner (a user), a group, and a mode: three sets of permission bits, read (r), write (w) and execute (x), for the owner (u), the group (g) and all others (o). When a process accesses the file, the kernel uses exactly one set (owner, else group, else others) and allows the action only if the needed bit is set.

In simple words

Decide who may read, change or run each file, and who may list, change or enter each folder.

Words you’ll meet in this lesson

Permissions at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a notice on a door

Every file has a notice with three rows.

Basic Reading a line of ls -l

  • -rw-r--r-- 1 riya riya 18 report.txt
  • 1st character: type (- file, d directory, l link).
  • Next 3: owner (riya) may read and write. Next 3: group riya may read. Last 3: everyone else may read.
  • A - in a position means “not allowed”.

Intermediate Files vs folders, and the one-class rule

  • File: r = read contents, w = change contents, x = run it as a program.
  • Folder: r = list the names, w = create, rename and delete entries (with x), x = enter it and reach things inside (“search”).
  • Deleting a file needs w on the folder, not on the file.
  • Linux picks one class: if you are the owner, only the owner bits count (even if “others” has more); else if you are in the group, the group bits; else others.
  • To open /a/b/c.txt you need x on /, /a and /a/b, plus r on c.txt.

Advanced Behind the screen: the mode word

  • The inode stores a 16-bit mode: 4 bits file type, 3 special bits (SUID, SGID, sticky: Lesson 9.4) and 9 permission bits. stat -c %a prints the permission part in octal (r=4, w=2, x=1).
  • On every open(), execve() and path lookup the kernel compares the process’s effective UID/GIDs with the inode’s owner and group (generic_permission()). root (UID 0) skips the r/w checks, and needs at least one x bit to run a file.
  • Permission is checked when a file is opened. A program that already has a file open keeps access after a chmod.
  • A + after the mode (-rw-r--r--+) means an ACL adds more rules (9.5); a . means an SELinux context.
  • x on a script is not enough: the interpreter must also read it, so a script needs r and x.

Did you know? On Ubuntu 24.04 new home folders are drwxr-x--- (750): other users cannot even look inside your home. Older Ubuntu releases used 755, so everyone could read your files by default.

Exam tip: “What does -rwxr-x--- mean?” → regular file; owner read, write, execute; group read and execute; others nothing. Octal 750.

Quick check A file is -rw-r--r-- owned by riya. Can aman (not in group riya) change it?
Answer: No. Aman falls into “others”, which has only r.
Common mistake
✗“The owner of a file can always do what others can”: -r--r--rw- lets the owner write
✓Only one class is used. If you own a file with mode 0446 you get <code>r--</code> and cannot write, even though others have rw.

Linux checks owner first and stops there. Strange modes like this are rare but appear in exam questions.

Common mistake
✗chmod 777 to “fix” Permission denied
✓Find the real block with <code>namei -l</code> and <code>id</code>, then give the smallest right (often x on one folder or g+w for a team).

777 lets every account, including a hacked web app, change the file. It hides the real cause and fails audits.

Undo and safety net

Reading permissions changes nothing; the risk is misreading them.

  • Not sure which class you are: compare id with the owner and group in ls -l.
  • Folder looks fine but access fails: namei -l the full path; check x on every folder.
  • A + at the end of the mode: an ACL adds rules: getfacl FILE (Lesson 9.5).
  • Permission denied as root: check lsattr (immutable files, 9.5), read-only mounts, or SELinux/AppArmor.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. sudo -u aman cat /home/riya/proj/.env
    cat: /home/riya/proj/.env: Permission denied exit status: 1

    What it means: aman is “others” and others have no r on .env (mode 600).

    Fix: Only if he should: give him group access (9.3) or an ACL (9.5).

  2. sudo -u aman ls /home/riya/proj/private
    ls: cannot open directory '/home/riya/proj/private': Permission denied exit status: 2

    What it means: No r (and no x) for others on the folder (700): cannot list it.

    Fix: chmod o+rx on the folder, if that is intended.

  3. sudo -u aman touch /home/riya/proj/new.txt
    touch: cannot touch '/home/riya/proj/new.txt': Permission denied exit status: 1

    What it means: No w on the folder for others: cannot create files there.

    Fix: Use a team folder with g+w (9.2, 9.4).

  4. cd ~/proj && chmod 644 bin/deploy.sh && ./bin/deploy.sh
    /home/riya/script.sh: line 6: ./bin/deploy.sh: Permission denied exit status: 126

    What it means: The file has no x: the shell will not run it (exit 126).

    Fix: chmod +x bin/deploy.sh (9.2).

Quick check Aman can ls a folder but cannot cd into it. Which bit is missing?

Under the hood: the kernel says EACCES

strace (run as aman) shows cat asking the kernel to open .env, and the kernel refusing with EACCES, the error code behind “Permission denied”.

strace -e trace=openat cat /home/riya/proj/.env
openat(AT_FDCWD, "/home/riya/proj/.env", O_RDONLY) = -1 EACCES (Permission denied) cat: /home/riya/proj/.env: Permission denied

Recorded with strace on our Ubuntu build machine as aman; library loading lines are hidden.

cat never sees the contents: the check happens inside openat(), before any data is read. The same check runs for every program, so no tool can “get around” it except by running as root or as the owner.

Script it: perm-explain.sh

Explain a mode in plain English: who may do what with a file.

f=/etc/passwd
m=$(stat -c %A "$f")
echo "$f: $m (owner $(stat -c %U "$f"), group $(stat -c %G "$f"))"
for i in 0 1 2; do
  who=$(echo owner group others | cut -d' ' -f$((i+1)))
  bits=${m:$((1+i*3)):3}
  can=""
  [ "${bits:0:1}" = r ] && can="$can read"
  [ "${bits:1:1}" = w ] && can="$can write"
  [ "${bits:2:1}" = x ] && can="$can execute"
  echo "  $who:${can:- nothing}"
done
/etc/passwd: -rw-r--r-- (owner root, group root) owner: read write group: read others: read

${m:1:3} takes three characters of the mode string (bash substring).

Puzzle answer Remember the question from the story? Open to check your guess.

On a folder, r only lets you list names; reaching anything inside needs x. With drwxr--r-- Aman (others) has r but no x, so ls shows “notes.md” (ls -l would add “cannot access” warnings for the details), but opening the file is denied before its own 644 mode is even checked.

Quick check A file shows -rwxr-x---. Write it in octal.
Answer: 750.

Quick revision

Lesson 9.1 in one screen

  • -rwxr-x---: type, then owner, group, others; r=4 w=2 x=1 → 750.
  • File: r read, w change, x run. Folder: r list, w create/delete (with x), x enter/reach.
  • One class only: owner, else group, else others.
  • Opening /a/b/f needs x on every folder and r on f. Deleting needs w+x on the folder.
  • ls -l, ls -ld, stat -c '%A %a %U %G %n', namei -l, [ -r -w -x ].
  • Common modes: 644 files, 600 secrets, 755 scripts/folders, 700 private, 750 homes/teams. Avoid 777.

Interview and viva questions

What does -rw-r--r-- mean?

A regular file; the owner can read and write, the group and others can only read (644).

What do r, w and x mean on a directory?

r lists names, w creates and deletes entries (with x), x lets you enter it and reach files inside.

How do I see a directory’s permissions?

ls -ld DIR.

How do I see permissions as numbers?

stat -c '%a %n' FILE.

Why do I get Permission denied although the file is 644?

A folder on the path is missing x for you; check with namei -l.

What is the difference between owner, group and others?

Owner is one user, group is one group of users, others is everyone else; Linux uses exactly one of them for you.

What does a + after the permissions mean?

The file has an ACL with extra rules (getfacl).

Any company · basicsFresher

“Explain -rwxr-xr--.”

Asked in almost every Linux interview.

The interviewer is checking: can you read all ten characters?

Show a strong answer

Nginx returns 403 for a new page

  2. namei -l FILE: which folder lacks x for others?
  3. Add only that x (or put the site under /var/www).

OperationsMid-level

“Permission denied” as root

root cannot change a file.

The interviewer is checking: do you know what else blocks root?

Show a strong answer
  • Immutable attribute (lsattr, Lesson 9.5).
  • Read-only mount (Lesson 15.3), NFS root_squash.
  • SELinux/AppArmor denials in the audit log.

Avoid: “root can always do everything”.

Security teamSenior

Least privilege on a shared server

Hundreds of users, many projects.

The interviewer is checking: can you design a model?

Show a strong answer
  • Private homes (700/750), one group per project, SGID team folders (9.4), umask 027 (9.3).
  • ACLs for exceptions (9.5); no world-writable files outside /tmp.
  • Regular audits with find -perm.

Avoid: one big shared folder with 777.

Interview and certification corner

What does x mean on a directory?
Permission to enter it and access entries by name.
What permission do you need to delete a file?
w and x on its directory.
How do you see permissions in octal?
stat -c %a FILE.
What is the first character in ls -l?
The file type: - file, d directory, l link, c/b device.
Why does a symlink always show lrwxrwxrwx?
Its own mode is not used; the target’s permissions apply.
Which class applies to the owner?
Only the owner bits, even if group or others have more.
What does 600 mean?
Owner read and write; nobody else anything.
