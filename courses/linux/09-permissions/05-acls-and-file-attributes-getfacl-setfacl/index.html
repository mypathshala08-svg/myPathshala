ACLs and file attributes: getfacl, setfacl and chattr

ACLs add named exceptions to the three permission classes; file attributes lock files even against root. This lesson explains getfacl, setfacl, the mask, default ACLs and chattr, and how admins, web, DevOps and security teams use them.

Module 9 · Permissions and ownership⏱ 38 minBeginner → AdvancedThe ACL mask animatedDefault ACLschattr +i and +aPractice lab with checkerReal Bash in your browser8 practice problems
The problem

Priya from internal audit needs to read the finance folder for two weeks. She is not in the finance group, and adding her would also give her everything else finance can reach. Opening the folder to “others” would let every user in. Three classes (owner, group, others) are simply not enough. ACLs (access control lists) add named entries like “user priya: read”. And when an attacker with root rewrites /etc/resolv.conf, or a script truncates an audit log, you want a lock that even root must remove first: file attributes such as immutable (+i) and append-only (+a).

By the end of this page you will be able to:
  • explain why ACLs exist and read getfacl output: user, group, mask, other and named entries
  • grant and remove access for one user or group with setfacl -m, -x, -b, recursively with -R
  • set default ACLs on folders so new files inherit them, and understand the mask
  • protect files with chattr +i (immutable) and +a (append-only), and check them with lsattr

2 Definition

ACLs (getfacl, setfacl) and file attributes (chattr, lsattr)

Formal definition (write this in exams)

A POSIX access control list (ACL) extends a file’s permissions with entries for specific named users and groups, limited by a mask. getfacl shows them; setfacl adds, changes or removes them, including default ACLs that new files in a directory inherit. File attributes are file-system flags such as immutable (i) and append-only (a), set with chattr and shown with lsattr; they apply even to root.

In simple words

Give one extra person or group exactly the access they need, and lock files against changes or deletion.

ACLs and attributes at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a guest list and a padlock

Two extras on top of chmod.

Basic The commands you will type

  • getfacl report.xlsx: show every entry.
  • setfacl -m u:priya:r report.xlsx: Priya may read.
  • setfacl -x u:priya report.xlsx: remove her entry; setfacl -b: remove all ACLs.
  • sudo chattr +i file / -i: lock / unlock. lsattr file: see it.

Intermediate Entries, the mask and default ACLs

  • An ACL has the three classic entries (user::, group::, other::) plus named user:NAME: and group:NAME: entries and a mask::.
  • The mask is the maximum for named users, named groups and the owning group. With an ACL present, the group digit of chmod is the mask, so chmod 640 sets the mask to r-- (the puzzle). #effective: shows the result.
  • Default ACLs (setfacl -d -m …, only on folders) are copied to new files and folders created inside, so access keeps working for new reports. They replace the umask for those files.
  • Order of checks: owner → named user → owning group and named groups → others, each limited by the mask (except owner and others).

Advanced Behind the screen: xattrs, tools and attributes

  • ACLs are stored as extended attributes system.posix_acl_access and system.posix_acl_default on the inode. ext4, xfs and btrfs support them by default (ext4: mount option acl is on).
  • cp keeps ACLs only with -a or --preserve=all; tar needs --acls; rsync needs -A. Backups that drop them silently open or close access after a restore.
  • NFSv4 and Windows (SMB) have their own, richer ACL models (nfs4_setfacl, icacls).
  • Attributes (chattr) are file-system flags in the inode, checked before permissions: i immutable (no write, rename, delete, link, chmod), a append-only (only >>). Setting or clearing them needs CAP_LINUX_IMMUTABLE (root). e (extents) is normal on ext4.
  • Attackers with root can run chattr -i too: attributes stop accidents and scripts, not a determined root. Malware sometimes sets +i on its own files: check lsattr when root “cannot delete” something.

Did you know? On Ubuntu, getfacl and setfacl come in the small acl package (sudo apt install acl); desktops have it, minimal servers and containers often do not. chattr and lsattr are always there (e2fsprogs).

Exam tip: “Give user tom read and write on /data/report without changing owner, group or others.” → setfacl -m u:tom:rw /data/report; check with getfacl /data/report.

Quick check ls -l shows -rw-r-----+. What does the + mean, and what do you run next?
Answer: The file has an ACL; run getfacl to see the named entries.
Common mistake
✗setfacl -m u:priya:r /srv/finance (expecting Priya to read next month’s reports too)
✓setfacl -R -m u:priya:rX /srv/finance and setfacl -d -m u:priya:rX /srv/finance

An access ACL on a folder covers only the folder itself. Existing files need -R, future files need a default ACL (-d). Your notes’ commands -m, -x u:NAME, -x g:NAME and -b are all correct; this is the step people forget.

setfacl in web servers

    Typical output on Ubuntu with the acl package (our build machine has no getfacl/setfacl; format checked against the acl manual).

    Why this way: Also: cp -a, tar --acls, rsync -aA keep ACLs.

Common mistake
✗setfacl -m u:priya:rw report.xlsx, then chmod 640 report.xlsx
✓chmod 660 (or setfacl -m m::rw report.xlsx) and check getfacl

With an ACL, the group digit of chmod sets the mask. chmod 640 made the mask r--, so priya’s rw became #effective:r--: the puzzle.

chattr · lsattr immutable and append-only

🟡 Changes filessudo needed

chattr +i makes a file immutable: no change, rename, delete or link, even for root. +a allows only appending. -i/-a remove them. lsattr lists attributes (e = extents, normal on ext4). Changing them needs root.

✓ Use it when
  • configs that must never change by accident
  • logs that may only grow
  • diagnosing “root cannot delete this”
✗ Don’t use it when
  • as a security boundary against root (root can remove it)
  • files that packages update (upgrades fail)

Syntax: sudo chattr +i|-i|+a|-a FILE… · lsattr [-d] [-R] FILE…

OptionWhat it doesWhen to use it
sudo chattr +i fimmutableprotect configs
sudo chattr -i funlockbefore editing
sudo chattr +a fappend-onlylogs
lsattr fshow flagsdiagnose
lsattr -d dirthe folder itselffolders
chattr +i dirno files added/removedfreeze a folder

chattr · lsattr in security

  1. Situation: An audit log that can only grow (no truncating, no editing).

    cd ~/at; sudo chattr +a audit.log
echo 'login riya' >> audit.log && echo appended
echo 'wiped' > audit.log; sudo truncate -s 0 audit.log
cat audit.log; sudo chattr -a audit.log
    appended /home/riya/script.sh: line 4: audit.log: Operation not permitted truncate: cannot open 'audit.log' for writing: Operation not permitted start login riya

    Why this way: >> works, > and truncate fail, even as root. Attackers often try to clear logs.

chattr · lsattr in system info / admin

  1. Situation: “root cannot delete this file”: check attributes first.

    cd ~/at; sudo rm resolv.conf; echo "exit $?"
lsattr resolv.conf
sudo chattr -i resolv.conf && sudo rm resolv.conf && echo removed
    rm: cannot remove 'resolv.conf': Operation not permitted exit 1 ----i---------e------- resolv.conf removed

    Why this way: Permissions look fine, but the i flag wins. Some malware and some admins set it; lsattr reveals it.

chattr · lsattr in devops / cloud

  1. Situation: Package upgrades fail on immutable files.

    Typical error during apt upgrade when a managed file is immutable

    echo 'dpkg: error processing … unable to make backup link of ./etc/resolv.conf: Operation not permitted'
    dpkg: error processing archive …: unable to make backup link of './etc/…' before installing new version: Operation not permitted

    Why this way: Document every +i, and remove it before upgrades or config management runs.

Undo and safety net

Both are reversible.

  • Wrong ACL entry: setfacl -x u:NAME FILE; everything: setfacl -b FILE.
  • Wrong default ACL: setfacl -k DIR (existing files keep theirs: -R -b).
  • Lost ACLs after a copy: restore from getfacl -R output with setfacl --restore.
  • Locked file: sudo chattr -i FILE (or -a).

Error messages decoded

Errors students see most. chattr errors were really produced on our build machine, with their exit status.

  1. touch f; chattr +i f
    chattr: Operation not permitted while setting flags on f exit status: 1

    What it means: Setting attributes needs root (CAP_LINUX_IMMUTABLE).

    Fix: sudo chattr +i f.

  2. touch f; sudo chattr +i f; sudo rm f; rc=$?; sudo chattr -i f; (exit $rc)
    rm: cannot remove 'f': Operation not permitted exit status: 1

    What it means: The file is immutable, so even root is refused.

    Fix: sudo chattr -i f first.

  3. getfacl /etc/hosts
    /home/riya/script.sh: line 1: getfacl: command not found exit status: 127

    What it means: The acl tools are not installed on this machine.

    Fix: sudo apt install acl.

Quick check A log must keep growing but never be edited or wiped. Which command?
Answer: sudo chattr +a FILE

6 Real-world use

ACLs and attributes at work

1. Temporary access

Auditors and contractors get named, time-limited ACL entries on exactly the folders they need.

Request→setfacl→remove later

2. Service access

A web server or backup agent gets read access to one path without opening it to everyone.

Service→setfacl→least privilege

3. Shared drives

Samba and project shares use default ACLs so new files keep the right access.

Share→setfacl -d→consistent

4. Tamper-resistant logs

Audit logs are append-only so a script or user cannot wipe them.

Log→chattr +a→evidence

5. Incident response

Responders check lsattr when malware files “cannot be deleted”.

Stuck file→lsattr→chattr -i

Puzzle answer Remember the question from the story? Open to check your guess.

With an ACL, the group digit of chmod changes the mask. chmod 640 set the mask to r--, so priya’s rwx is cut to #effective:r--; fix with chmod 660 (or setfacl -m m::rw). And root’s “Operation not permitted” comes from the immutable attribute: lsattr shows i; sudo chattr -i first.

Quick revision

Lesson 9.5 in one screen

  • ACL = named user/group entries + mask on top of u/g/o; ls -l shows +.
  • getfacl f; setfacl -m u:N:rX f, -m g:N:r, -x u:N, -b, -R.
  • Mask limits named entries and the owning group; chmod’s group digit sets it (watch #effective).
  • Default ACLs: setfacl -d -m … on folders; -k removes them.
  • Keep ACLs: cp -a, tar --acls, rsync -A; backup with getfacl -R / restore with setfacl --restore.
  • chattr +i immutable, +a append-only (root needed, applies to root); lsattr to check.

Interview and viva questions

What is an ACL in Linux?

An access control list: extra permission entries for specific users and groups beyond owner, group and others.

How do I give one user access to a file?

setfacl -m u:USER:rw FILE (install the acl package if setfacl is missing).

How do I see ACLs?

getfacl FILE; ls -l shows a + when a file has an ACL.

What is the ACL mask?

The maximum permissions for named users, named groups and the owning group.

How do I make new files inherit an ACL?

Set a default ACL on the folder: setfacl -d -m u:USER:rX DIR.

How do I make a file undeletable even by root?

sudo chattr +i FILE (remove with chattr -i).

Why can’t root delete a file?

Check lsattr for the i or a attribute, a read-only mount, or SELinux/AppArmor.

Real-world scenario questions (asked in company interviews)

Interview questions about ACLs and attributes, from fresher to senior rounds.

Any company · basicsFresher

“How do you give one user access without changing the group?”

A common question.

The interviewer is checking: do you know ACLs?

Show a strong answer
  • setfacl -m u:NAME:r FILE, check with getfacl.
  • The + in ls -l.

Avoid: chmod o+r (gives everyone access).

Help deskJunior

“My ACL stopped working”

An admin ran chmod after setfacl.

The interviewer is checking: do you know the mask?

Show a strong answer
  1. getfacl: #effective shows the mask cut rights.
  2. setfacl -m m::rw FILE or chmod with the right group digit.

Avoid: deleting and re-adding the ACL every day.

OperationsMid-level

Access lost after a migration

Files were copied with cp -r to a new server; auditors lost access.

The interviewer is checking: do you know what drops ACLs?

Show a strong answer
  • cp without -a, tar without --acls, rsync without -A drop ACLs.
  • Restore from getfacl -R backup or re-apply; copy again with rsync -aAX.

Avoid: giving everyone access to stop complaints.

Security teamSenior

Malware keeps coming back

A file in /usr/local/bin cannot be removed and reappears.

The interviewer is checking: incident handling?

Show a strong answer
  • lsattr: immutable flag; cron/systemd timers that restore it.
  • chattr -i, remove, find persistence, check other +i files: lsattr -R / 2>/dev/null | awk '$1~/i/'.
  • Rebuild if root was compromised.

Avoid: “root can always delete, it must be a disk error”.

Interview and certification corner

What package provides setfacl?
acl.
What does setfacl -x do?
Removes one ACL entry.
What does setfacl -k do?
Removes the default ACL.
What is #effective in getfacl?
Rights after applying the mask.
Can a normal user use chattr +i?
No, it needs root (CAP_LINUX_IMMUTABLE).
Where are ACLs stored?
In extended attributes (system.posix_acl_access/default).
How do you back up ACLs?
getfacl -R DIR > file; restore with setfacl --restore=file.
