Metacharacters, command-line expansion order and directory stacks (pushd, popd, dirs)

bash rewrites every command line in a fixed order before running it: braces, tilde, variables and commands, splitting, wildcards, quotes. This lesson shows each step, the metacharacters that trigger them, eval and its dangers, and the pushd/popd directory stack.

The problem

Riya types one line: cp ~/proj/{src,docs}/*.{py,md} "$BACKUP/$(date +%F)". Before cp even starts, bash rewrites that line in seven steps: braces become several words, ~ becomes her home, $BACKUP and $(date +%F) are filled in, the result is split into words, * turns into real file names, and the quotes are removed. Knowing this order explains almost every “why did the shell do that?”. This lesson also covers the metacharacters that have special meaning (; & | < > ( ) $ ` \ " ' * ? [ ] ~ { } #), eval (run a string as a new command line, and why it is dangerous), and directory stacks: pushd, popd and dirs to jump between folders and come back.

By the end of this page you will be able to:
  • name the shell metacharacters and what each one does, and protect them when you need them literally
  • list the seven expansions in their real order and predict the result of any command line
  • use brace expansion, tilde expansion, command and arithmetic substitution, and process substitution confidently
  • use eval only when needed (and safely), and move between folders with pushd, popd, dirs and cd -

2 Definition

Metacharacters, expansion, eval and directory stacks

Formal definition (write this in exams)

Metacharacters are characters with special meaning to the shell (separators, operators, quoting and expansion triggers). Expansion is the set of rewrites bash applies to every command line, in a fixed order: brace, tilde, parameter/arithmetic/command/process substitution, word splitting, pathname expansion and quote removal. eval re-parses its arguments as a new command line. The directory stack is a list of folders managed with pushd, popd and dirs.

In simple words

Special characters are instructions. The shell carries them out in order, then runs the command.

Expansion at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a sorting line

Your line passes through stations before it is delivered.

Basic What you will type

  • mkdir -p proj/{src,docs,logs}: three folders in one go.
  • cp report.txt{,.bak}: copy to report.txt.bak.
  • cd ~, cd -: home, and back to where you were.
  • pushd /var/log … popd: visit a folder and return.

Intermediate The order

  1. Brace expansion {a,b}, {1..5} (no variables inside).
  2. Tilde expansion ~, ~user, ~+, ~-.
  3. Parameter, arithmetic and command substitution, process substitution, left to right: $v, ${v}, $((…)), $(…), <(…).
  4. Word splitting of unquoted results (IFS).
  5. Pathname expansion (globbing) * ? [ ] on unquoted words.
  6. Quote removal.

Before all of it, bash splits the line into tokens at metacharacters (| & ; ( ) < > space, tab, newline) and recognises keywords; history ! and aliases come even earlier.

Advanced Behind the screen: tokens, eval and the stack

  • Operators like |, &&, > are recognised while the line is tokenised, before expansion; anything they produce later is ordinary text. That is the puzzle.
  • eval STRING joins its arguments and feeds the result through the whole parser again: expansions happen twice. If any part comes from a user or a file, that is code injection.
  • Safer: store commands in arrays (cmd=(ls -l "$dir"), run "${cmd[@]}"), use functions, or ${!name} for indirect variables.
  • The directory stack is a bash array, DIRSTACK; dirs -v numbers it, pushd +N rotates it, ~N refers to entry N.
  • $( ) runs in a subshell and strips trailing newlines; <( ) gives a /dev/fd/N path to a pipe.

Did you know? Brace expansion is not globbing: echo {x,y}.txt prints x.txt y.txt even if those files do not exist, while echo *.txt prints only names that exist. That is why mkdir -p proj/{src,docs} works for folders that do not exist yet.

Exam tip: “What is the difference between $( ) and backquotes?” → Both are command substitution; $( ) nests easily and is clearer; backquotes need escaping inside.

Quick check Why does echo {1..$n} print {1..3} when n=3?
Answer: Brace expansion is step 1 and happens before $n is filled in, so the braces are not a valid range yet; they stay as text.
Common mistake
✗cmd="ls -l | grep txt"; $cmd
✓cmd=(ls -l); "${cmd[@]}" | grep txt · or a function · eval "$cmd" only for trusted, fixed text

The pipe is recognised before expansion, so after $cmd is expanded, | is just an argument to ls. Real run: ls: cannot access '|'.

{a,b,c} · {1..10} · {a..e} · {01..10..2} brace expansion

🟢 Read-onlyno sudo

Braces generate words: a comma list {a,b,c}, a range {1..10} or {a..e}, with an optional step {0..20..5} and zero padding {01..10}. A prefix and suffix are glued to each word; braces can be nested and combined.

✓ Use it when
  • creating several folders or files at once
  • backups (file{,.bak})
  • sequences of names
✗ Don’t use it when
  • matching existing files (use globs)
  • ranges from variables

Syntax: pre{a,b}post · {1..N} · {X..Y..STEP}

mkdir -pcommandproj/prefix{src,docs}braces/xsuffix

Each brace item gets the prefix and suffix.

$(cmd) · $((expr)) · <(cmd) command, arithmetic and process substitution

🟢 Read-onlyno sudo

$(cmd) is replaced by cmd’s output (trailing newlines removed). $((expr)) by an integer result. <(cmd) by a file name (/dev/fd/…) from which cmd’s output can be read, so commands that want files can read command output.

✓ Use it when
  • values inside a command line: dates, counts, sums
  • comparing two outputs without temp files
✗ Don’t use it when
  • backticks in new scripts
  • unquoted $( ) with names containing spaces

eval · ${!name} · command arrays run a string as code

🔴 Can destroy datano sudo

eval "string" joins its arguments and runs the result as a new command line, so pipes, redirections and expansions inside it work, and everything is expanded a second time. Safer alternatives: ${!name} for “the variable whose name is in name”, arrays for commands, functions for reusable lines.

✓ Use it when
  • indirect variable names (rare)
  • running a command line read from a trusted config
✗ Don’t use it when
  • anything containing user input or file names (code injection)
  • commands that could be arrays or functions

Syntax: eval "$cmd" · echo "${!name}" · cmd=(ls -l "$d"); "${cmd[@]}"

eval · ${!name} · command arrays in security

  1. Situation: Why eval is dangerous.

    cd ~/ex; touch victim.txt
user_input='notes.txt; rm victim.txt'
eval "ls $user_input"
ls victim.txt 2>&1
    notes.txt ls: cannot access 'victim.txt': No such file or directory

    Why this way: The “file name” contained a second command, and eval ran it. Never eval anything that comes from users, files or the network.

eval · ${!name} · command arrays in software development

  1. Situation: The safe way: a command in an array.

    cd ~/ex

printf '%q ' "${cmd[@]}"; echo
    -rw-r--r-- ls -l my\ file.txt

    Why this way: Each array item is one argument, spaces included; printf %q shows a safely quoted version.

pushd · popd · dirs -v · cd - directory stack

Undo and safety net

Expansion happens before commands run; check it before running destructive commands.

  • Not sure what a line will become: put echo in front, or set -x.
  • A brace or glob created/removed too much: restore from backup; next time preview with echo.
  • Lost in folders: cd -, dirs -v, popd, or simply cd.
  • Used eval on input: remove it; use arrays, ${!name} or case to choose commands.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. popd
    /home/riya/script.sh: line 1: popd: directory stack empty exit status: 1

    What it means: The stack is empty.

    Fix: pushd first; dirs -v to check.

  2. pushd /nope
    /home/riya/script.sh: line 1: pushd: /nope: No such file or directory exit status: 1

    What it means: No such folder.

    Fix: Check the path.

  3. echo $(( 2 + ))
    /home/riya/script.sh: line 1: 2 + : syntax error: operand expected (error token is "+ ") exit status: 1

    What it means: Incomplete arithmetic.

    Fix: Complete the expression.

  4. echo a;; b
    /home/riya/script.sh: line 1: syntax error near unexpected token `;;' /home/riya/script.sh: line 1: `echo a;; b'

    What it means: ;; is only valid inside case.

    Fix: One ; separates commands.

Puzzle answer Remember the question from the story? Open to check your guess.

The pipe | is recognised when bash first splits the line into tokens, before $cmd is expanded. After expansion, |, grep and txt are just extra arguments to ls, hence “cannot access '|'”. eval "$cmd" feeds the text through the parser again, so the pipe works, but eval is dangerous with any input you do not control. Safer: cmd=(ls -l); "${cmd[@]}" | grep txt, or a function listtxt(){ ls -l | grep txt; }.

Quick check Which two expansions do NOT happen inside double quotes?
Answer: Brace expansion, tilde expansion, word splitting and globbing are all off inside double quotes; $, $( ) and $(( )) still work.

Quick revision

Lesson 12.11 in one screen

  • Metacharacters: ; & && || | < > ( ) { } $ ` \ " ' * ? [ ] ~ # ! — quote them to use them literally.
  • Order: tokens/operators → brace → tilde → $var $(( )) $( ) <( ) (left to right) → word splitting → globbing → quote removal.
  • Braces generate names (no files needed, no variables inside); globs match existing files.
  • $( ) nests and replaces backticks; $(( ) turn commands into files.
  • eval re-parses text (double expansion, injection risk); prefer arrays, functions, ${!name}.
  • pushd DIR / popd / dirs -v / pushd +N / cd -.

Interview and viva questions

What are shell metacharacters?

Characters with special meaning to the shell, such as ; & | < > ( ) $ ` \ " ' * ? [ ] ~ { } and #.

In what order does bash expand a command line?

Brace, tilde, parameter/arithmetic/command/process substitution, word splitting, pathname expansion, then quote removal.

What is brace expansion?

Generating words from {a,b,c} or {1..10}, e.g. mkdir -p dir/{a,b}.

What does eval do and why is it dangerous?

It re-parses its arguments as a command line; with untrusted input it can run arbitrary commands.

How do pushd and popd work?

pushd changes to a folder and saves the previous one on a stack; popd returns to the folder on top of the stack.

What is process substitution?

<(cmd) provides cmd’s output as a file name, so diff <(cmd1) <(cmd2) compares outputs.

Why does {1..$n} not work?

Brace expansion happens before variable expansion.
