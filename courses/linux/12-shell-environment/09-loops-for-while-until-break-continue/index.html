Loops: for, while, until, break and continue

for walks through a list, while repeats while a command succeeds, until repeats until it succeeds; break and continue change the flow; select and getopts handle menus and options. This lesson covers them all with many runnable examples.

The problem

Riya has 365 daily log files and must count the errors in each. A colleague needs every user in a CSV created on the server. A download must be retried until it succeeds, but not more than five times. A menu must keep asking until the operator chooses “exit”. All of these are loops: for walks through a list (words, files, numbers, array items), while repeats as long as a command succeeds, until repeats until it succeeds, and break / continue leave or skip early. With select you get a numbered menu for free, and getopts loops over options like -v -o file.

By the end of this page you will be able to:
  • write for loops over lists, ranges ({1..10}, seq), files (globs), command output and arrays, plus the C-style for ((i=0; i
  • write while and until loops with counters and conditions, and read files or command output line by line safely
  • control loops with break, continue, break N / continue N, and build menus with select and while true
  • parse options with getopts, and avoid the classic traps: missing ; before do, pipes that lose variables, last lines without a newline, looping over ls

2 Definition

for, while, until, break and continue

Formal definition (write this in exams)

A for loop runs its body once for each word of a list, assigning the word to a variable (bash also has an arithmetic form for ((init; test; step))). A while loop runs its body as long as a command list returns 0; an until loop runs it as long as the list returns non-zero. break exits the loop and continue starts the next iteration. select shows a numbered menu, and getopts parses command-line options one at a time.

In simple words

for = each item. while = as long as. until = until. break = stop. continue = skip.

Loops at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a conveyor belt

Three ways to keep the belt moving, two ways to interrupt it.

Basic The shapes you will type

  • for city in Pune Delhi Mumbai; do echo "$city"; done
  • for f in *.txt; do wc -l "$f"; done
  • n=1; while [ $n -le 5 ]; do echo $n; n=$((n+1)); done
  • until ping -c1 server; do sleep 5; done

Intermediate The rules

  • do is a separate word: on the next line, or after ; on the same line: for x in a b; do.
  • for x in LIST: LIST is expanded once at the start (words, {1..5}, *.log, "$@", "${arr[@]}", $(cmd)). Without in LIST, it loops over "$@".
  • while CMD runs the body while CMD returns 0; until CMD while it returns non-zero. Something in the body must change the condition.
  • break leaves the loop, continue jumps to the next round; break 2 / continue 2 act on the outer loop of two nested ones.
  • To read lines use while IFS= read -r line; do …; done < file, not for line in $(cat file) (that splits at every space).

Advanced Behind the screen: subshells and expansion

  • Every part of a pipe runs in its own subshell, so cmd | while read … changes variables in a child that disappears (unless shopt -s lastpipe in a script). Use done < file or done < <(cmd).
  • {1..N} is brace expansion: N must be a literal number, not a variable ({1..$n} does not work); use seq 1 "$n" or for ((i=1;i<=n;i++)).
  • A glob that matches nothing stays literal (*.log), so loops over globs should check [ -e "$f" ] || continue or use shopt -s nullglob.
  • read returns non-zero at end of file even if it read a last line without a newline: use while read -r l || [ -n "$l" ].
  • A loop’s exit status is that of the last body command run; redirections after done apply to the whole loop (one open, faster than >> inside).

Did you know? while true; do …; done is how many Linux services and monitoring scripts are built: an endless loop with a sleep inside, stopped by a signal or a break (Lesson 11.3).

Exam tip: “Write a script that prints the multiplication table of a number.” → for i in {1..10}; do echo "$n x $i = $((n * i))"; done.

Quick check How many times does for x in "a b" c; do echo $x; done run?
Answer: Twice: "a b" (one quoted word) and c.
Common mistake
✗for var in ${list} do (do on the same line, no ;)
✓for var in $list; do … or put do on the next line

do is a separate command word: without ; it is just another list item, and bash later fails with “syntax error near unexpected token”. Checked (class-notes for-loop syntax).

Common mistake
✗while [[ $counter -le 10 ]]; do echo $counter ((counter++)) done
✓echo "$counter"; ((counter++)) (separate commands: new line or ;)

On one line without ;, ((counter++)) becomes part of echo’s arguments: “syntax error near unexpected token (”. Checked (class-notes while-loop example).

break · continue · break N change the flow

🟢 Read-onlyno sudo

break leaves the innermost loop immediately; continue skips the rest of the body and starts the next round. With a number they act on outer loops: break 2 leaves two levels, continue 2 continues the outer loop.

✓ Use it when
  • leaving early when you found what you need
  • skipping items you do not want
✗ Don’t use it when
  • deep nesting where a function with return is clearer

Syntax: break [N] · continue [N]

Undo and safety net

Loops repeat mistakes as fast as they repeat work; test first.

  • Endless loop: press Ctrl+C; check that the condition can change.
  • Loop changed many files wrongly: restore from backup; next time put echo before the real command and check the list first.
  • Variables empty after the loop: the loop ran in a pipe: use done < file or < <(cmd).
  • Loop ran once with “*.log”: no file matched: add [ -e "$f" ] || continue or shopt -s nullglob.

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. bash -c 'for x in a b do echo $x; done'
    bash: -c: line 1: syntax error near unexpected token `done' bash: -c: line 1: `for x in a b do echo $x; done' exit status: 2

    What it means: Missing ; before do.

    Fix: for x in a b; do.

  2. bash -c 'while true; do break'
    bash: -c: line 2: syntax error: unexpected end of file exit status: 2

    What it means: Missing done.

    Fix: Every do needs a done.

  3. n=3; for i in {1..$n}; do echo $i; done
    {1..3} exit status: 0

    What it means: Brace ranges do not take variables: one round with the text {1..3}.

    Fix: seq 1 "$n" or for ((i=1;i<=n;i++)).

  4. break
    /home/riya/script.sh: line 1: break: only meaningful in a `for', `while', or `until' loop exit status: 0

    What it means: break outside a loop does nothing useful.

    Fix: Only inside for/while/until/select.

Quick check What does for i in {1..$n} print with n=3?
Answer: The text {1..3} once: brace expansion happens before variables are filled in.

Script it: bulk-check.sh

A loop-heavy tool: for every host in a file, retry a check up to 3 times (until), skip comment lines (continue), and stop everything if a STOP file appears (break). The “check” is simulated so it runs anywhere.

hosts=${1:-$HOME/lp/hosts.txt}
check(){ [ "$1" != db01 ]; }        # simulated: db01 always fails
while IFS= read -r h; do
  [[ -z $h || $h == \#* ]] && continue
  [ -e "$HOME/lp/STOP" ] && { echo "STOP file found, ending"; break; }
  tries=0
  until check "$h"; do
    tries=$((tries + 1)); [ $tries -ge 3 ] && break
  done
  if [ $tries -ge 3 ]; then echo "$h: FAILED after 3 tries"; else echo "$h: ok"; fi
done < "$hosts"
web01: ok web02: ok db01: FAILED after 3 tries

Run on the sample hosts.txt (web01, web02, db01).

Puzzle answer Remember the question from the story? Open to check your guess.

Because of the pipe, the while loop runs in a child shell: it counts to 3 there, and the child exits at the end of the pipe, so the main shell still has count=0. Fix 1: feed the loop without a pipe, while …; done < <(grep 500 app.log). Fix 2: do not loop at all, count=$(grep -c 500 app.log). (In a script, shopt -s lastpipe also works.)

Quick check How do you make a loop that asks a menu question until the user chooses Exit?
Answer: while true; do read -r -p … c; case $c in …) …;; exit) break;; esac; done (or select … with break).

Quick revision

Lesson 12.9 in one screen

  • for x in LIST; do …; done — words, {1..10}, {0..20..5}, *.log, "$@", "${arr[@]}"; C-style for ((i=0;i
  • while COND repeats while 0; until COND repeats until 0; change something each round.
  • Lines: while IFS= read -r l; do …; done < file (|| [ -n "$l" ] for a last line without \n); CSV with IFS=,.
  • cmd | while … runs in a subshell: use done < <(cmd) to keep variables.
  • break / continue (N for nested); select menus with PS3 and REPLY; getopts "vo:" with OPTARG and shift $((OPTIND-1)).
  • Never for f in $(ls) or for l in $(cat f); {1..$n} does not work.

Interview and viva questions

How do I write a for loop in bash?

for item in list; do commands; done — e.g. for f in *.txt; do echo "$f"; done.

How do I loop over numbers in bash?

for i in {1..10} for fixed ranges; for ((i=1; i<=n; i++)) or seq 1 "$n" when the end is a variable.

How do I read a file line by line in bash?

while IFS= read -r line; do …; done < file.

What is the difference between while and until?

while repeats while the condition is true; until repeats until it becomes true.

What do break and continue do?

break exits the loop; continue skips to the next iteration.

Why are my variables empty after a while loop?

The loop was at the end of a pipe and ran in a subshell; use done < <(command) instead.

How do I make a menu in bash?

select item in a b c; do …; done, or while true with read and case.

Warm-up question.

The interviewer is checking: two forms?

Show a strong answer

“Read a file line by line”

Follow-up after for loops.

The interviewer is checking: correct idiom?

Show a strong answer
