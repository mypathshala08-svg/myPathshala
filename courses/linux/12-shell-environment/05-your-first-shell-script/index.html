Your first shell script: shebang, chmod +x and running it

A shell script is your commands saved in a file, with a #! first line and execute permission. This lesson writes one from scratch, runs it four ways, returns exit codes, and decodes every first-day error.

The problem

Every morning Riya types the same five commands: check the disk, count today’s errors in the web log, list new uploads, back up the config, and print a summary for her team lead. It takes ten minutes and she sometimes forgets a step. A shell script is simply those commands saved in a file, with one special first line (#!/bin/bash) and an execute permission. After that, one word runs all five, in the same order, every time, even from cron at 6 a.m. This lesson takes you from an empty file to a script you can run by name, and explains every way it can go wrong on the first try.

By the end of this page you will be able to:
  • write a script file: the shebang line #!/bin/bash, comments, variables and several commands
  • run it in all four ways (./script, bash script, source script, by name from PATH) and know the difference
  • make it executable with chmod +x, put it in ~/bin, and return a proper exit status with exit
  • decode first-script errors: Permission denied, command not found, “required file not found” from Windows line endings, wrong shebang

2 Definition

A shell script

Formal definition (write this in exams)

A shell script is a text file containing shell commands that are executed in sequence by a shell interpreter. Its first line is usually a shebang (#! followed by the interpreter’s path) that tells the kernel which program should run the file. With execute permission, the script can be run like any other program, and it returns an exit status to its caller.

In simple words

Your commands in a file, with a first line saying “run me with bash”.

Scripts at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a recipe card

A script is a recipe card for the shell.

Basic The four steps

  • Create the file: nano hello.sh.
  • First line #!/bin/bash, then your commands, one per line. # starts a comment.
  • chmod +x hello.sh once.
  • Run it: ./hello.sh (the ./ means “in this folder”).

Intermediate The rules

  • The shebang must be the very first line, starting at column 1: #!/bin/bash or #!/usr/bin/env bash (finds bash in PATH).
  • The .sh extension is only a convention for humans; Linux ignores it. Tools in ~/bin usually have no extension.
  • A script runs in a new bash process: its cd and variables vanish when it ends; use source to run it in your shell (Lesson 11.1).
  • The script’s exit status is that of its last command, or the number given to exit (0 = success, 1–255 = failure). By default a script continues after a failing command (Lesson 12.6).

Advanced Behind the screen: execve and #!

  • ./hello.sh → the shell forks and calls execve("./hello.sh"). The kernel sees #! and turns it into execve("/bin/bash", ["/bin/bash", "./hello.sh"]).
  • Only one argument is allowed after the interpreter on Linux (#!/usr/bin/env bash -e does not work as expected; use env -S or set -e inside).
  • With a Windows file, the line is really #!/bin/bash\r: the kernel looks for a program literally called bash\r, which does not exist: “required file not found”.
  • No shebang: the kernel refuses (ENOEXEC) and bash then runs the file itself with a new bash; other callers (cron, Python’s subprocess) may fail.
  • bash reads a script a little at a time while running; editing a script while it runs can make it execute garbage.

Did you know? Many “commands” you use every day are shell scripts: run file /usr/bin/* | grep -c "shell script" on Ubuntu and you will find dozens, such as ldd, gunzip and which.

Exam tip: “Write a script that prints Hello World, and give two ways to run it.” → #!/bin/bash / echo "Hello World"; run with chmod +x hello.sh; ./hello.sh or bash hello.sh.

Quick check Why must you type ./hello.sh and not just hello.sh?
Answer: The current folder is not in PATH (for safety), so the shell would not find it. ./ gives the exact location.
Common mistake
✗“All scripts must have the .sh extension”
✓The extension is optional: Linux decides by the #! line and the x permission, not the name

Checked: a file called hello (no extension) with #!/bin/bash and chmod +x runs fine. Tools you install in ~/bin are usually extension-free.

Common mistake
✗#!/bin/sh at the top, then bash features ([[ ]], arrays, ((i++)))
✓#!/bin/bash for bash scripts; #!/bin/sh only for POSIX scripts

On Ubuntu /bin/sh is dash, not the Bourne shell and not bash (Lesson 12.1). bash-only lines fail or misbehave under dash.

✗Write the script on Windows (Notepad), copy it, run it

Undo and safety net

Scripts are just files; mistakes are fixed by editing and re-running.

  • Edited and nothing changed: check you edited the file you run: type NAME, head -3 FILE.
  • Sourced a script with exit and lost the terminal: open a new one; next time run it with ./.
  • Script half-ran and failed: fix the cause; Lesson 12.6 shows set -e so it stops at the first error.
  • Broke a script that worked: keep scripts in Git (or at least cp s.sh s.sh.bak before editing).

Error messages decoded

Errors students see most. Each was really produced on our build machine, with its exit status.

  1. ./hello.sh
    /home/riya/script.sh: line 3: ./hello.sh: Permission denied exit status: 126

    What it means: No execute permission (126).

    Fix: chmod +x hello.sh or bash hello.sh.

  2. hello.sh
    /home/riya/script.sh: line 3: hello.sh: command not found exit status: 127

    What it means: The current folder is not in PATH (127).

    Fix: ./hello.sh.

  3. bash -n broken.sh
    broken.sh: line 1: unexpected EOF while looking for matching `"' exit status: 2

    What it means: A quote is never closed (2).

    Fix: Close it; check again.

  4. bash nofile.sh
    bash: nofile.sh: No such file or directory exit status: 127

    What it means: The file name is wrong (127).

    Fix: ls; Tab-complete names.

if [ "$(id -u)" -eq 0 ]; then echo 'do not run me as root' >&2; exit 1; fi

EOF

id -u is 0 for root; errors go to stderr (>&2) and exit 1.

Puzzle answer Remember the question from the story? Open to check your guess.

The file has Windows line endings: line 1 is really #!/bin/bash\r, so the kernel looks for an interpreter called bash\r and reports it as not found. With bash report.sh, every line carries a \r, hence the $'\r' errors. Fix in one command: sed -i 's/\r$//' report.sh (or dos2unix report.sh), and save with LF line endings in the editor next time.

Quick check What do the two characters #! need to be, and where?
Answer: The very first two bytes of the file: no space, no blank line, no BOM before them.

Quick revision

Lesson 12.5 in one screen

  • A script: text file of commands; line 1 #!/bin/bash; # comments; settings at the top.
  • chmod +x then ./s.sh; bash s.sh needs no x; source runs in your shell; tools in ~/bin run by name.
  • exit N: 0 success, 1–255 failure; default = last command’s status; scripts continue after errors unless set -e.
  • 126 = not executable, 127 = not found (or bad #!), 2 = syntax; bash -n checks.
  • Windows CRLF → “required file not found”: sed -i 's/\r$//' or dos2unix.
  • .sh is optional; #!/bin/sh is dash on Ubuntu.

Interview and viva questions

How do I create and run a shell script in Linux?

Write commands in a file starting with #!/bin/bash, run chmod +x file.sh, then ./file.sh.

What is a shebang?

The #! first line that tells the kernel which interpreter runs the file, e.g. #!/bin/bash.

Why do I get Permission denied running my script?

It lacks execute permission: chmod +x script.sh, or run bash script.sh.

What is the difference between ./script.sh and bash script.sh?

./ uses the shebang and needs execute permission; bash script.sh runs it with bash regardless.

What does “required file not found” mean for a script that exists?

The interpreter in the shebang cannot be found, usually because of Windows CRLF line endings or a typo.

How do I return an error from a script?

exit 1 (any non-zero number up to 255).

Do shell scripts need the .sh extension?

No; it is only a naming convention.

CI step passes although the script failed halfway

A deploy script printed errors but CI is green.

The interviewer is checking: exit codes?

Show a strong answer

  • Add set -euo pipefail (Lesson 12.6) and explicit exit 1 checks.
  • CI reads only the exit status.

PlatformSenior

A script works on Linux but not on Mac

  • Test in CI on both.
