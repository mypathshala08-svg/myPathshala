Reading files and input line by line: while read, IFS and mapfile

One loop that never loses a line, a space or a backslash, and the two traps that make loops silently do less than you think.

The problem

Riya has to patch every server in hosts.txt, create accounts for every person in users.csv, and act on a list of file names that contain spaces. Each job is the same pattern: read a file line by line and do something with each line. It is also where shell scripts break most often: a for loop over $(cat file) splits “Sales Q3.xlsx” into two words, a backslash in a name disappears, the last line is silently skipped because the file has no final newline, and an ssh inside the loop swallows the rest of the file. This lesson teaches the one loop that gets all of this right, while IFS= read -r line, and its friends mapfile and field splitting with IFS.

By the end of this page you will be able to:
  • read a file line by line correctly with while IFS= read -r, including the last line without a newline
  • split lines into fields with IFS and read -r a b c, and read CSV-like data into variables
  • load a whole file into an array with mapfile / readarray
  • avoid the classic traps: for over $(cat), lost backslashes, trimmed spaces, subshell variables, and commands that eat stdin

2 Definition

read, IFS and mapfile

Formal definition (write this in exams)

read is a Bash built-in that reads one line from standard input and assigns it to one or more variables, splitting it into fields using the characters in IFS (the Internal Field Separator, by default space, tab and newline). In a while loop with the file redirected at done, it processes a file line by line. mapfile (also called readarray) reads all lines of its input into an indexed array.

In simple words

read takes one line per call; IFS decides where fields split; mapfile takes them all.

Reading line by line at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a queue at a counter

People come to the counter one at a time; the clerk serves exactly one, then calls “next”. read is the clerk; each line is one person.

Basic What you will type

  • while IFS= read -r line; do echo "$line"; done < file
  • while read -r name ip env; do …; done < hosts.txt (fields)
  • while IFS=, read -r a b c; do …; done < file.csv
  • mapfile -t lines < file; echo "${#lines[@]}"

Intermediate The differences that matter

  • IFS= (empty, only for this read) keeps leading and trailing spaces; -r keeps backslashes.
  • read returns non-zero at end of file even if it read a last line without a newline; || [[ -n $line ]] handles it.
  • With several variables, the last one gets the rest of the line: read -r name rest.
  • A pipe cmd | while … runs the loop in a subshell: variables set inside are lost. Use done < file or done < <(cmd).

Advanced Behind the screen: read() one byte at a time

  • On a pipe, Bash’s read builtin calls read(2) one byte at a time (it must not consume bytes after the newline, which belong to the next command); on a regular file it reads a block and seeks back. That is why huge files are slow in Bash loops: use awk for millions of lines.
  • Every command inside the loop inherits the loop’s stdin (the file). ssh, ffmpeg, read without redirection can swallow the remaining lines: give them < /dev/null (ssh -n) or read from another file descriptor (read -u 3).
  • Field splitting with IFS whitespace collapses runs of spaces and tabs and trims the ends; a non-whitespace IFS like , does not collapse, so empty fields survive (a,,c → 3 fields).
  • mapfile (Bash 4) reads all lines into an array in one call; -t strips the newlines, -s N skips N lines, -n N reads at most N.

Did you know? ShellCheck warns about almost every mistake in this lesson: SC2162 (“read without -r will mangle backslashes”), SC2013 (“to read lines rather than words, pipe/redirect to a while read loop”) and SC2031 (a variable modified in a subshell).

Exam tip: “How do you read a file line by line in Bash?” → while IFS= read -r line; do … "$line" …; done < file, with || [[ -n $line ]] to keep a last line that has no newline.

Quick check Why put < file after done and not cat file | before while?
Answer: With the redirect, the loop runs in the current shell, so variables set inside survive; a pipe runs it in a subshell.
Common mistake
✗for line in $(cat hosts.txt); do
✓while IFS= read -r line; do …; done < hosts.txt

for splits on every space and expands wildcards: one “line” becomes many words.

Common mistake
✗ssh "$host" uptime inside a while read loop
✓ssh -n "$host" uptime (or < /dev/null)

ssh reads the loop’s stdin, swallowing the remaining lines: only the first host is processed.

4 Step by step

The safe loop, fields, arrays and the traps

Every card runs on our build machine in ~/ops/data: hosts.txt (7 lines, messy, no final newline), users.csv and files.txt (names with spaces).

while IFS= read -r line || [[ -n $line ]]; do … done < file the safe loop

🟢 Read-onlyno sudo

Three details make it safe: IFS= keeps spaces at the ends, -r keeps backslashes, and || [[ -n $line ]] still processes a last line that has no newline. The file is redirected at done, so the loop runs in the current shell.

✓ Use it when
  • every “for each line” job
✗ Don’t use it when
  • for over $(cat)

Syntax: while IFS= read -r line || [[ -n $line ]]; do printf '%s\n' "$line"; done < hosts.txt

cmd | while (subshell) · < <(cmd) · ssh -n · read -u 3 the two big traps

🟢 Read-onlyno sudo

Trap 1: cmd | while … runs the loop in a subshell, so variables set inside vanish; use done < <(cmd). Trap 2: commands inside the loop share its stdin; ssh (and others) read it and swallow the rest of the file. Give them < /dev/null, use ssh -n, or read the file on fd 3.

✓ Use it when
  • loops over command output
  • remote commands in loops
✗ Don’t use it when
  • pipes when you need the variables

Syntax: while read -r h _; do ssh -n "$h" uptime; done < <(grep prod hosts.txt)

Undo and safety net

Reading never changes files; mistakes are in what the loop does with the lines. Make the body safe:

  • Wrong items processed: print first: run the loop with echo in front of the real command.
  • Only the first host done: a command ate stdin; add < /dev/null or ssh -n, rerun.
  • Counter is 0: the loop was in a pipe; switch to done < <(cmd).
  • Windows line endings (\r): strip with line=${line%$'\r'} or dos2unix first.

Script it: each-host.sh

Run a command for every host of a given environment in hosts.txt, skipping comments and blank lines, reading the list on fd 3 so the command can never steal it, and printing a summary.

#!/usr/bin/env bash
set -euo pipefail
printf '# hosts\nweb01 10.0.1.11 prod\n\ndb01 10.0.2.21 prod\ntest01 10.0.9.5 test' > hosts.txt
env_wanted=prod
cmd=(echo "would patch")          # replace with: ssh -n "$host" sudo apt-get -y upgrade
ok=0
while read -r -u 3 host ip env || [[ -n ${host:-} ]]; do
  [[ -z ${host:-} || $host == \#* ]] && continue
  [[ $env == "$env_wanted" ]] || continue
  "${cmd[@]}" "$host ($ip)"
  ((++ok))
done 3< hosts.txt
echo "done: $ok host(s) in $env_wanted"
would patch web01 (10.0.1.11) would patch db01 (10.0.2.21) done: 2 host(s) in prod

The command is an array, so it can contain spaces safely.

Puzzle answer Remember the question from the story? Open to check your guess.

1. for h in $(cat hosts.txt) splits on every space, tab and newline: 21 words, not 7 lines. 2. Plain read treats backslashes as escapes (so build\01 becomes build01), trims leading and trailing whitespace (IFS), and returns failure at a last line without a newline, so the loop body never runs for it. while IFS= read -r line || [[ -n $line ]] fixes all three. 3. cat … | while runs the loop in a subshell; count is incremented there and thrown away when the pipe ends. Redirect instead: done < hosts.txt or done < <(cmd).

Quick check Which option keeps backslashes in read?
Answer: -r (raw).

Quick revision

Lesson 2.1 in one screen

  • while IFS= read -r line || [[ -n $line ]]; do …; done < file: exact lines, last line kept.
  • for over $(cat) splits words and expands globs: never for lines.
  • read -r a b rest splits on IFS; the last variable gets the remainder; _ skips a field.
  • IFS=, / IFS=: / IFS=$'\t' for other separators; empty fields survive with non-space IFS.
  • mapfile -t arr < file (-s skip, -n limit); done < <(cmd) keeps variables, cmd | while does not.
  • Commands in the body share stdin: ssh -n, < /dev/null or read -u 3 … 3< file. Strip \r from Windows files.

Interview and viva questions

How do I read a file line by line in Bash?

while IFS= read -r line; do …; done < file (add || [[ -n $line ]] for a last line without a newline).

Why does my while read loop skip the last line?

The file does not end with a newline; read returns failure even though it filled the variable.

Why are variables lost after a while loop?

The loop was on the right of a pipe and ran in a subshell; use done < file or done < <(cmd).

What does IFS mean in Bash?

Internal Field Separator: the characters used to split words and read fields.

What is mapfile?

A Bash built-in (alias readarray) that reads lines into an array.

Why does my loop only process the first line when using ssh?

ssh reads the rest of the loop’s input; use ssh -n.

How do I read a CSV file in Bash?

For simple CSV: while IFS=, read -r a b c; for quoted fields use a real parser (next lesson).

Practice lab: process a host list

Build the lab (it creates ~/lab21/hosts.txt, messy on purpose), write ~/lab21/hosts.sh, then run the checker.

Step 1 · Build the lab (copy into your terminal)

rm -rf ~/lab21; mkdir -p ~/lab21 && cd ~/lab21
printf '# fleet\nweb01 10.0.1.11 prod\n\n  web02   10.0.1.12 prod\ndb01 10.0.2.21 prod\nbuild\\01 10.0.3.7 ci\ntest01 10.0.9.5 test' > hosts.txt

Step 2 · Your tasks

  1. hosts.sh ENV prints the names of the hosts in hosts.txt whose third field equals ENV, one per line, skipping comments and blank lines.

Show one possible solution
cat > hosts.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
want=${1:?usage: hosts.sh ENV}
n=0
while read -r host ip env || [[ -n ${host:-} ]]; do
  [[ -z ${host:-} || $host == \#* ]] && continue
