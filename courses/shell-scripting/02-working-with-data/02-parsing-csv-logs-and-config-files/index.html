Parsing CSV, logs and config files in Bash

Every format has a trap: quoted commas in CSV, spaces inside log fields, code hidden in configs. Parse the format, not just the separator.

Module 2 · Working with data⏱ 40 minIntermediateQuote-aware CSV parserRegex groups animatedWhy source is dangerousPractice lab with checkerReal Bash in your browser8 practice problems
The problem

Real data never arrives as neat space-separated columns. The sales team’s CSV has "Kumar, Ravi" with a comma inside quotes; the web server log has brackets, quotes and spaces inside fields; and the app’s config file has key = value with spaces, comments and a path containing a space. Riya’s IFS=, loop from Lesson 2.1 cuts “Kumar, Ravi” in two. This lesson parses each format properly: CSV with a real quote-aware parser, logs with [[ =~ ]] and BASH_REMATCH, config files without the dangerous source, and INI sections, and shows when to hand the job to awk, Python or jq.

By the end of this page you will be able to:
  • parse CSV with quoted fields, commas and doubled quotes correctly, in Bash and with python3 -c csv
  • pull fields out of log lines with [[ =~ ]] and BASH_REMATCH, and summarise them with awk
  • read key=value and INI config files safely into variables or associative arrays, without source
  • validate parsed values and choose the right tool for each format and size

2 Definition

Parsing data files

Formal definition (write this in exams)

Parsing means reading text in a known format and turning it into separate, meaningful values according to that format’s rules. In shell scripts the common formats are CSV (comma-separated values with quoting rules), log lines (a fixed layout of fields that may themselves contain spaces), and configuration files (key=value lines or INI files with [sections]).

In simple words

Know the format’s rules, then extract the values; never guess with a plain split.

Parsing at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: addresses on envelopes

“Kumar, Ravi” is one name even though it has a comma. Humans know because of the quotes; a parser must know the same rule.

Basic What you will type

  • csv_split "$line" (our 10-line function) or python3 -c 'import csv,sys; …'
  • [[ $line =~ $re ]] && echo "${BASH_REMATCH[1]}"
  • while IFS='=' read -r key value; do …; done < app.conf
  • awk '{print $9}' access.log | sort | uniq -c

Intermediate The differences that matter

  • CSV (RFC 4180): fields with commas, quotes or newlines are quoted; a quote inside is doubled (""). Excel files often add a BOM and CRLF.
  • Put a regex in a variable (re='…') and write [[ $s =~ $re ]] unquoted: quoting the right side makes it a plain string.
  • Config: trim spaces, skip comments and blanks, accept only known keys or ^[a-z_]+$ names, store in an associative array.
  • Validate after parsing: ports are numbers, paths exist, levels are in a list.

Advanced Behind the screen: formats and grammars

  • A format is a small grammar. Regular expressions handle “regular” formats (one log line); CSV with quotes needs a tiny state machine (inside/outside quotes), which is why a single regex or IFS split fails.
  • BASH_REMATCH[0] is the whole match, [1]… the groups; Bash uses POSIX ERE (no \d, no lazy *?, no lookahead): write [0-9] and [^"]*.
  • For big files, the cost is per line in Bash (built-ins, no fork) vs per file in awk; awk is typically 10–100× faster on large logs.
  • source/. parses the file as shell grammar: ;, $( ) and backticks all run. Even declare "$line" can be abused; a strict key=value pattern plus assigning into an array is the safe design.

Did you know? Excel saves “CSV UTF-8” with three invisible bytes at the very start (the BOM, EF BB BF). Your first column header then is not id but \ufeffid, and [[ $h == id ]] fails for no visible reason. sed '1s/^\xEF\xBB\xBF//' removes it.

Exam tip: “Why is source config.conf dangerous?” → source executes the file as shell code, so any command in it (after ;, in $( ) or backticks) runs with the script’s permissions; read key=value lines and validate them instead.

Quick check Why does [[ $s =~ "$re" ]] not work as a regex?
Answer: Quoting the right-hand side makes Bash match it as a literal string.

csv_split (regex state machine) · python3 csv CSV with quotes

🟢 Read-onlyno sudo

A quote-aware parser reads one field at a time: either a quoted field "…" (where "" means one quote) or an unquoted one up to the next comma. Our csv_split does this with one regex in a loop and prints each field on its own line, so mapfile can collect them. For big or messy files, call Python’s csv module.

✓ Use it when
  • CSV from Excel, CRMs, exports
✗ Don’t use it when

[[ $line =~ $re ]] · BASH_REMATCH log lines with a regex

🟢 Read-onlyno sudo

A regex with groups describes the whole line; [[ $line =~ $re ]] fills BASH_REMATCH with each group. Keep the regex in a variable and leave it unquoted in [[ ]]. Bash uses POSIX extended regex: [0-9] not \d, [^"]* for “anything up to a quote”.

✓ Use it when
  • log lines with a fixed layout
✗ Don’t use it when
  • splitting log lines on spaces

Syntax: re='^([0-9.]+) .* \[([^]]+)\] "([A-Z]+) ([^ ]+) [^"]*" ([0-9]{3}) ([0-9]+)'

OptionWhat it doesWhen to use it

IFS== read -r k v · trim · validate · declare -A key=value config, safely

🟢 Read-onlyno sudo

Read each line, skip comments and blanks, split at the first = (IFS== read -r k v puts everything after it in v), trim spaces, accept only keys matching ^[a-z_]+$, and store in an associative array. Nothing in the file is ever executed.

✓ Use it when
  • app configs, .env-style files
✗ Don’t use it when
  • source on files you do not fully control

Syntax: declare -A cfg; while IFS== read -r k v; do …; cfg[$k]=$v; done < app.conf

OptionWhat it doesWhen to use it
IFS== read -r k vsplit at first =v keeps later =
${k//[[:space:]]/}trim keyspaces
trim valueleading/trailingsee code
^[a-z_]+$allowed keysreject junk
cfg[$k]=$vstoreassociative
${cfg[port]:-5432}defaultmissing key

First run (real output)

cd ~/ops/data
declare -A cfg
while IFS='=' read -r k v || [[ -n $k ]]; do
  [[ $k =~ ^[[:space:]]*(#|$) ]] && continue
  k=${k//[[:space:]]/}; v=${v#"${v%%[![:space:]]*}"}; v=${v%"${v##*[![:space:]]}"}
  [[ $k =~ ^[a-z_]+$ ]] || { echo "skip bad key [$k]" >&2; continue; }
  cfg[$k]=$v
done < app.conf
for k in db_host db_port log_level backup_dir retries; do printf '%-10s = [%s]\n' "$k" "${cfg[$k]}"; done
[[ ${cfg[db_port]} =~ ^[0-9]+$ ]] && echo 'db_port is a number: ok'
db_host = [db01.internal] db_port = [5432] log_level = [INFO] backup_dir = [/srv/backups/orders data] retries = [3] db_port is a number: ok

[section] · current section · cfg[section.key] INI files with sections

🟢 Read-onlyno sudo

Keep a section variable: when a line matches ^\[(.+)\]$, update it; for key = value lines store cfg[$section.$key]. Then cfg[cache.host] and cfg[database.host] no longer clash.

✓ Use it when
  • INI files
  • php.ini, my.cnf, git config style
✗ Don’t use it when
  • one flat dictionary for sectioned data

cd ~/ops/data
declare -A ini; section=''
while IFS= read -r line || [[ -n $line ]]; do
  line=${line%%[;#]*}
  if [[ $line =~ ^[[:space:]]*\[([^]]+)\] ]]; then section=${BASH_REMATCH[1]}; continue; fi

done < site.ini

Undo and safety net

Parsing only reads; the risk is acting on wrongly parsed values. Protect the actions:

  • Columns shifted: you split quoted CSV with IFS: switch to a parser, rerun.
  • A config executed code: remove source; check what ran (logs, new files), rotate any exposed secrets.
  • Garbage values used: validate after parsing (numbers, lists, paths) and die before acting.
  • Unparsed lines ignored silently: count them and log a warning, as the regex card does.

Error messages decoded

Errors students see most (really run on our build machine).

  1. re='[0-9]+'; [[ 'abc123' =~ "$re" ]] && echo match || echo 'no match: quoted pattern is a literal string'
    no match: quoted pattern is a literal string exit status: 0

    What it means: The right side was quoted, so Bash looked for the text [0-9]+.

6 Real-world use

Parsing at work

1. Business data imports

Exports from CRMs and Excel always contain quoted commas; a quote-aware step (or Python) prevents shifted columns in the database.

export→parse→load

2. Security checks

Counting 401s per IP in access logs finds brute-force attempts; fail2ban works the same way with regexes.

access.log→regex→ban

3. Deploy configuration

Deploy scripts read per-environment key=value files and validate every value before touching servers.

app.conf→validate→deploy

4. Server configs

my.cnf, php.ini and systemd units are INI-like; scripts read a section key before changing anything.

my.cnf→section.key→check

5. Daily reports

awk summaries of access logs (status codes, top paths, bytes) are mailed every morning.

log→awk→mail

Script it: parse-config.sh

Load a key=value config into an associative array safely, with comment and blank-line handling, trimming, a key whitelist, defaults and validation, and stop with exit 2 on any bad value.

#!/usr/bin/env bash
set -euo pipefail
printf '# demo\nhost = db01\nport= 5432\nmode = fast\nrm -rf / ; oops\n' > demo.conf
declare -A cfg=([host]=localhost [port]=5432 [mode]=safe)       # defaults
allowed='^(host|port|mode)$'

while IFS='=' read -r k v || [[ -n $k ]]; do
  [[ $k =~ ^[[:space:]]*(#|$) ]] && continue
  k=${k//[[:space:]]/}
  v=${v#"${v%%[![:space:]]*}"}; v=${v%"${v##*[![:space:]]}"}
  if [[ ! $k =~ $allowed ]]; then echo "ignored unknown line: [$k]" >&2; continue; fi
  cfg[$k]=$v
done < demo.conf

[[ ${cfg[port]} =~ ^[0-9]+$ ]] || { echo "bad port: ${cfg[port]}" >&2; exit 2; }
case ${cfg[mode]} in safe|fast) ;; *) echo "bad mode: ${cfg[mode]}" >&2; exit 2 ;; esac
for k in host port mode; do echo "$k=${cfg[$k]}"; done
ignored unknown line: [rm-rf/;oops] host=db01 port=5432 mode=fast

The “rm -rf / ; oops” line is just ignored text: nothing in the file ever runs.

Puzzle answer Remember the question from the story? Open to check your guess.

1. IFS=, does not know CSV quoting, so the comma inside "Kumar, Ravi" splits the field and every later column shifts. Use a quote-aware parser (our csv_split) or python3 -c 'import csv …'. 2. In the combined log format the user agent is a quoted field that contains spaces; splitting on spaces cuts it into pieces. Match the whole line with a regex ("([^"]*)") or split on quotes in awk (-F'"', field 6). 3. source runs the config as Bash code, so ; touch HACKED executed. Read key=value lines with IFS== read -r k v, whitelist the keys and validate the values.

Quick revision

Lesson 2.2 in one screen

  • Plain IFS=, only works for CSV without quotes; quoted CSV needs a parser (csv_split, python3 csv, mlr).
  • CSV rules: quote fields with commas/quotes/newlines; "" inside quotes is one quote; strip an Excel BOM.
  • Logs: re='…' then [[ $l =~ $re ]] (unquoted); groups in BASH_REMATCH; POSIX ERE ([0-9], [^"]*).
  • Big logs: awk ($1 IP, $7 path, $9 status, $10 bytes; -F'"' for request and agent).
  • Config: IFS== read -r k v, skip comments/blanks, trim, whitelist keys, validate values; never source.
  • INI: track [section], store cfg[section.key]; git config -f or configparser also work.

Interview and viva questions

How do I parse a CSV file with quoted fields in Bash?

Use a quote-aware parser: a regex loop like csv_split, or python3 -c with the csv module, or Miller (mlr).

What is BASH_REMATCH?

An array filled by [[ string =~ regex ]]: index 0 is the whole match, 1.. the groups.

Why does my Bash regex not match \d?

Bash uses POSIX extended regex; write [0-9] or [[:digit:]].

Is it safe to source a config file?

Only if you fully trust its content: source executes it. Read key=value lines instead.

How do I parse an nginx access log?

awk for counts ($9 status, $1 IP), or a full regex with BASH_REMATCH per line.

How do I read an INI file in Bash?

Track the current [section] in a loop and store section.key; or use git config -f / crudini.

How do I remove the BOM from a CSV?

sed -i '1s/^\xEF\xBB\xBF//' file.csv.
