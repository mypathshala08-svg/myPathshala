Calling sed, awk and jq from scripts

Let sed edit, awk count and jq understand JSON, and hand them your variables as data, never as code.

Module 2 · Working with data⏱ 40 minIntermediateCode injection demojq pipeline animated40+ real callsPractice lab with checkerReal Bash in your browser8 practice problems
The problem

Some jobs are too big or too fiddly for pure Bash: changing one value in a config file in place, totalling a column over a million lines, reading a JSON answer from a cloud API. Three tools do these jobs better than any loop: sed (edit text streams and files), awk (columns, sums, reports) and jq (JSON). Calling them from a script brings one new danger: getting a shell variable into their programs safely. Riya’s script puts a city name with a slash into a sed command and breaks it; another puts a user-supplied value into an awk program and lets it run code. This lesson shows the right way for each tool: awk -v, escaped sed replacements, jq --arg.

By the end of this page you will be able to:
  • edit files in place with sed -i (with a backup), using a variable safely in the pattern and the replacement
  • pass shell variables into awk with -v and ENVIRON, and keep longer awk programs readable in a heredoc or .awk file
  • read, filter and reshape JSON with jq (.field, .[], select, map, -r, @csv, --arg, --argjson) and build JSON safely
  • choose between a Bash loop, sed, awk and jq for a job, and check results before replacing files

2 Definition

sed, awk and jq in scripts

Formal definition (write this in exams)

sed (stream editor) applies editing commands such as substitutions and deletions to each line of text, optionally rewriting a file in place. awk is a pattern-action language for field-based text: it splits lines into fields and is ideal for filtering, summing and reporting. jq is a command-line JSON processor that parses JSON and applies filters to select, transform and format it. Scripts pass values to them as data with awk -v and jq --arg; sed needs escaping.

In simple words

sed edits, awk counts, jq understands JSON; give them values as data.

sed, awk and jq from scripts at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: filling in a form

You write your name in the box on the form; you do not rewrite the form’s questions. -v and --arg are the boxes.

Basic What you will type

  • sed -i.bak 's/^feature_x = .*/feature_x = on/' app.conf
  • awk -F, -v c="$city" '$2 == c {s += $3} END {print s}' orders.csv
  • jq -r '.servers[].name' servers.json
  • jq -r --arg e "$env" '.servers[] | select(.env == $e) | .ip' servers.json

Intermediate The differences that matter

  • sed has no variables: the value becomes part of the command, so escape \, the delimiter and & in the replacement (and regex characters in the pattern), or pick a delimiter like | that the value cannot contain.
  • sed -i.bak keeps a backup; GNU sed accepts -i alone, macOS/BSD sed needs -i ''.
  • awk -v processes backslash escapes in the value; ENVIRON["NAME"] passes it raw.
  • jq: -r raw strings (no quotes), --arg always a string, --argjson a number/array/object, -n build from nothing, -e exit status from the result.

Advanced Behind the screen: three small languages

  • Each tool parses its own program string: sed’s grammar is address command, awk is a full C-like language with system() and pipes, jq is a functional language over JSON values. Shell quoting only builds that string; it does not protect it.
  • sed -i never edits in place literally: it writes a new temp file in the same folder and renames it over the original (Lesson 2.3’s atomic pattern), so the inode changes and hard links are broken.
  • awk reads input in one pass with buffered I/O and compiled patterns, which is why it beats a Bash while read loop by orders of magnitude on large files.
  • jq streams tokens and builds values; --stream handles files bigger than memory. Its @csv, @tsv, @sh and @base64 formatters escape output for the next tool.

Did you know? jq can also edit JSON: jq '.servers[1].cpu = 50' servers.json prints the whole document with one value changed. Combined with Lesson 2.3’s temp-file-and-mv pattern it becomes a safe in-place JSON editor.

Exam tip: “How do you pass a shell variable to awk?” → awk -v name="$var" '… name …' (or ENVIRON["var"] for an exported variable); never by putting "$var" inside the awk program text.

Quick check Why does sed "s/x/$dir/" fail when dir=/srv/logs?
Answer: The slashes in the value end the s command early; escape them or use another delimiter such as |.
Common mistake
✗awk "\$2 == \"$city\" {s+=\$3}" orders.csv
✓awk -v c="$city" '$2 == c {s += $3}' orders.csv

The value becomes awk code: quotes in it break the program or run commands (system()).

Common mistake
✗grep '"ip"' servers.json | cut -d'"' -f4
✓jq -r '.servers[].ip' servers.json

grep/cut depend on line breaks and key order; jq parses the real structure.

sed -i.bak 's|^key = .*|key = new|' file · diff edit a file in place

🟡 Changes filesno sudo

  • changing configs from scripts
  • deploy steps
✗ Don’t use it when
  • editing JSON or YAML with sed

awk -F, -v c="$city" '…c…' · ENVIRON · -f file.awk pass variables into awk

🟢 Read-onlyno sudo

-v name="$value" creates an awk variable before the program runs; inside, use name without $. The value is data, so quotes or system() in it do nothing. Longer programs go into a heredoc or a .awk file run with -f.

✓ Use it when
  • sums, counts, reports
✗ Don’t use it when
  • putting $var inside the awk program

Syntax: awk -F, -v c="$city" -v min="$min" 'NR > 1 && $2 == c && $3 >= min {n++; s += $3} END {print n, s}' orders.csv

Undo and safety net

Edits by tools are fast; so are mistakes. Keep the way back:

  • sed changed the wrong lines: mv app.conf.bak app.conf; next time anchor the pattern and preview with sed -n …p.
  • No backup: restore from git or backups; always use -i.bak on files that matter.
  • jq wrote empty output over the file: never redirect jq into the same file; write to a temp file and mv only if jq succeeded.
  • A value ran as code: switch to -v/--arg; check what ran.

Error messages decoded

Errors students see most (really run on our build machine).

  1. cd ~/ops/data && jq '.servers[] | .name' servers.json > servers.json; wc -c servers.json
    0 servers.json exit status: 0

    What it means: The shell empties servers.json (the > redirect) before jq reads it: the data is gone.

    Fix: jq … f > tmp && mv tmp f.

  2. cd ~/ops/data && jq '.servers[].nmae' servers.json
    null null null null exit status: 0

    What it means: A misspelled key gives null, not an error.

    Fix: Check spelling; use -e or // "default" (.nmae // "missing").

  3. awk -v city 'BEGIN{print city}'
    awk: improper assignment: -v city exit status: 2

    What it means: -v needs name=value; a bare name is an “improper assignment”.

    Fix: awk -v city="$city" …

Quick check Why must jq output never be redirected straight back into its input file?
Answer: The shell truncates the file before jq reads it; the data is lost.

6 Real-world use

sed, awk and jq at work

1. Deploy scripts

sed -i.bak sets ports, hosts and versions in config files per environment, with a diff check before restarting services.

template→sed -i→diff

2. Cloud automation

aws, az, gcloud and kubectl print JSON; jq picks instance IDs, IPs and states for the next command.

aws … --output json→jq -r→next step

3. Daily reports

awk totals sales per city or errors per service from large files in seconds.

CSV/logs→awk -v→report

4. Calling APIs

jq -n --arg builds request bodies for Slack, Jira or internal APIs; curl sends them.

variables→jq -n→curl -d

Script it: release-check.sh

Set a config value safely, verify exactly one line changed, summarise orders with awk, and build a JSON status message with jq: all values passed as data.

#!/usr/bin/env bash
set -euo pipefail
printf 'listen_port = 8080\nlog_dir = /var/log/app\n' > app.conf
printf 'id,city,amount\n1,Pune,450\n2,Delhi,800\n' > orders.csv
die() { echo "release-check: $*" >&2; exit 1; }

new_dir='/srv/logs/R&D app'                     # slashes, & and a space
esc=$(printf '%s' "$new_dir" | sed 's/[\\|&]/\\&/g')
sed -i.bak "s|^log_dir = .*|log_dir = $esc|" app.conf
n=$(diff app.conf.bak app.conf | grep -c '^>' || true)
(( n == 1 )) || die "expected 1 changed line, got $n"
grep '^log_dir' app.conf

total=$(awk -F, 'NR > 1 {s += $3} END {print s}' orders.csv)
jq -cn --arg dir "$new_dir" --argjson total "$total" '{status: "ok", log_dir: $dir, orders_total: $total}'
log_dir = /srv/logs/R&D app {"status":"ok","log_dir":"/srv/logs/R&D app","orders_total":1250}

The & and slashes reach the file exactly; the JSON is valid even with special characters.

Puzzle answer Remember the question from the story? Open to check your guess.

All three bugs pasted a value into another program’s source text. 1. sed: the slashes in /srv/logs/orders end the s/…/…/ command early (“unknown option to `s’”). Use s|…|…| and escape \, | and &. 2. awk: the quotes in the “city” closed the awk string and system("touch HACKED") became code. Pass it with awk -v c="$city". 3. JSON: grep and cut depend on the layout (one key per line); the same data on one line breaks them. Parse it with jq: jq -r '.servers[].name'.

Quick check Which jq option turns a true/false result into an exit status?
Answer: -e.

Quick revision

Lesson 2.4 in one screen

  • sed edits, awk computes over columns, jq parses JSON; Bash loops only for small data or complex logic.
  • sed: anchor (^key = .*), use | as delimiter, escape \ | & in replacements, -i.bak, preview with -n …p.
  • awk: -F, -v name="$v" (or ENVIRON["v"]); never paste $v into the program; long programs via -f or heredoc.
  • jq: .key, .[], select(), map(), group_by(), length, add; -r raw, -c compact, -e exit status.
  • jq values: --arg (string), --argjson (number/JSON), -n to build JSON; @csv @tsv @sh to hand results on.
  • Verify changes (diff, grep -c, cmp, jq empty); never jq … f > f: temp file + mv.

Interview and viva questions

How do I use a shell variable in sed?

Use double quotes and a delimiter the value cannot contain, and escape \, the delimiter and & in the value: sed "s|^key = .*|key = $v|".

How do I pass a variable to awk?

awk -v name="$var" '… name …' file.

How do I parse JSON in a shell script?

Use jq: jq -r '.field' file.json; pass variables with --arg.

How do I edit a file in place with sed and keep a backup?

sed -i.bak 's/old/new/' file (macOS: sed -i '' …).

Why is my file empty after jq … file > file?

The shell truncated it before jq read it; write to a temp file and mv.

How do I create JSON with variables in Bash?

jq -n --arg name "$v" '{name: $name}' handles all escaping.

What does jq -e do?

Sets the exit status from the last output: false or null gives 1.
