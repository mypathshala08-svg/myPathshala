Temporary files, trap and clean-up

Unique scratch space that is always removed, and results that appear all at once or not at all.

Module 2 · Working with data⏱ 35 minIntermediateEvery ending cleans upAtomic mv animatedkill -9 testedPractice lab with checkerReal Bash in your browser8 practice problems
The problem

Riya’s report job needs scratch space: a sorted copy of the orders, intermediate totals, a downloaded file. Her first version wrote to /tmp/report.tmp. Two problems appeared within a week: when two copies of the job ran at the same time, they overwrote each other’s file; and every time the job failed or someone pressed Ctrl+C, the temp files stayed behind until /tmp was full. The fix is two tools that belong together: mktemp creates a temp file or folder with a unique, unguessable name, and trap runs a clean-up function whenever the script ends: success, error, set -e exit, Ctrl+C or kill.

By the end of this page you will be able to:
  • create unique temp files and folders with mktemp (templates, -d, TMPDIR) instead of fixed names
  • clean up reliably with a trap on EXIT, and handle INT and TERM with the right exit codes
  • keep the original exit status in the clean-up function, and write results atomically with mv
  • know what trap cannot catch (kill -9) and how to sweep old leftovers

2 Definition

mktemp and trap

Formal definition (write this in exams)

mktemp creates a temporary file (or, with -d, a directory) with a unique random name and private permissions, and prints its path. trap is a Bash built-in that registers commands to run when the shell receives a signal (such as INT or TERM) or reaches a pseudo-signal such as EXIT (the shell is about to exit, for any reason) or ERR.

In simple words

mktemp gives unique scratch space; trap EXIT guarantees it is removed.

Temp files and trap at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a hotel room

mktemp is the receptionist giving you a room nobody else has; trap is the checkout rule: whenever you leave, for whatever reason, the room is cleaned.

Basic What you will type

  • tmp=$(mktemp) or work=$(mktemp -d)
  • cleanup() { rm -rf -- "$work"; }
  • trap cleanup EXIT right after creating it
  • mv -- "$work/result" final.txt at the end

Intermediate The differences that matter

  • EXIT runs on normal end, exit N and set -e failures. For INT/TERM, add traps that exit 130/143; the EXIT trap then runs too.
  • Save the status first in the handler: local rc=$?, so clean-up commands do not change the script’s exit code.
  • mktemp respects TMPDIR; templates need at least 3 trailing X’s (6 is usual).
  • Write results to a temp file on the same file system, then mv: readers see the old file or the new one, never half of one.

Advanced Behind the screen: O_EXCL, signals and rename()

  • mktemp opens with O_CREAT|O_EXCL and mode 0600 (0700 for -d): creation fails if the name exists, which defeats symlink attacks on predictable names like /tmp/report.tmp.
  • Bash runs traps between commands. While a foreground child runs, a TERM sent only to bash waits until the child finishes; Ctrl+C reaches the whole process group, so both stop.
  • SIGKILL (9) and SIGSTOP cannot be caught by any process; leftovers are then possible, which is why systemd-tmpfiles and periodic sweeps exist.
  • mv within one file system is the rename(2) system call: atomic. Across file systems it becomes copy + delete, which is not.

Did you know? On many systems /tmp is a tmpfs: it lives in RAM and is empty after every reboot. Big temp files there use memory, not disk; for multi-gigabyte scratch data set TMPDIR=/var/tmp (on disk, kept across reboots) for that job.

Exam tip: “How do you make sure a script’s temp files are removed even if it fails?” → Create them with mktemp and register trap 'rm -rf -- "$tmp"' EXIT right after; EXIT runs on success, exit, set -e failures and (with INT/TERM traps) on signals.

Quick check Why is /tmp/report.tmp a bad temp file name?
Answer: Two runs collide, and anyone can pre-create or symlink that predictable name.
Common mistake
✗tmp=/tmp/myjob.tmp; …; rm $tmp (last line)
✓tmp=$(mktemp); trap 'rm -f -- "$tmp"' EXIT

The rm is skipped on every failure and Ctrl+C, and parallel runs share one file.

Common mistake
✗trap 'rm -rf $work' EXIT (before work is set, unquoted)
✓work=$(mktemp -d); trap 'rm -rf -- "$work"' EXIT (single quotes, after mktemp)

With double quotes or an empty variable the trap command can become rm -rf with no path, or the wrong path.

trap cleanup EXIT · trap -p · trap - EXIT clean up on every exit

trap cleanup EXIT · trap -p · trap - EXIT in software development

  1. Situation: Without the trap: one failure, one leftover.

    cd ~/ops; bash -c 'set -e; w=$(mktemp -d); false; rm -rf "$w"'; echo "exit $?, leftovers: $(ls tmp | wc -l)"

    Why this way: The rm on the last line never ran.

  2. Situation: The status survives the clean-up.

    bash -c 'cleanup(){ local rc=$?; echo "cleanup sees $rc"; }; trap cleanup EXIT; exit 7'; echo "caller sees $?"
    cleanup sees 7 caller sees 7

    Why this way: local rc=$? first.

trap '…; exit 130' INT · trap '…; exit 143' TERM Ctrl+C and kill

🟢 Read-onlyno sudo

Bash runs the EXIT trap on Ctrl+C, but a kill (TERM) ends the script without it unless you trap TERM. A handler that prints a message and calls exit 130 / exit 143 makes both cases clean and gives the conventional codes.

✓ Use it when
  • long jobs someone may stop
✗ Don’t use it when
  • ignoring signals

Syntax: trap 'echo interrupted >&2; exit 130' INT; trap 'exit 143' TERM

write to temp → mv atomic results

🟡 Changes filesno sudo

Build the result in a temp file in the same folder or file system as the target, then mv it over the old one. Readers (a web server, another job) see the complete old file or the complete new one, never a half-written file, and a failed run leaves the old result untouched.

✓ Use it when
  • output files others read
  • reports, configs, web files
✗ Don’t use it when
  • writing straight into the final file

Undo and safety net

Temp-file mistakes are usually leftovers or lost results:

  • Leftovers piled up: sweep by template and age (card above), then add the trap.
  • Result half-written: the job wrote straight to the target; restore from backup and switch to temp + mv.
  • Trap deleted the wrong folder: the variable was empty or unquoted; always rm -rf -- "${work:?}".
  • Job always exits 0 now: the clean-up function changed $?; save local rc=$? first.

Error messages decoded

Errors students see most (really run on our build machine).

  1. mktemp /tmp/report.XX
    mktemp: too few X's in template ‘/tmp/report.XX’ exit status: 1

    What it means: Templates need at least 3 X’s.

    Fix: mktemp /tmp/report.XXXXXX

  2. mktemp -d /nonexistent/x.XXXXXX
    mktemp: failed to create directory via template ‘/nonexistent/x.XXXXXX’: No such file or directory exit status: 1

    What it means: The parent folder does not exist (or TMPDIR points nowhere).

    Fix: Create it, or fix TMPDIR.

  3. bash -c 'w=/tmp/demo-$$; mkdir -p "$w"; trap "rm -rf $W" EXIT; echo "trap is: $(trap -p EXIT)"'
    trap is: trap -- 'rm -rf ' EXIT exit status: 0

    What it means: Double quotes expanded the (misspelled, empty) variable when the trap was set: the trap is rm -rf with no path.

    Fix: Single quotes and the right name: trap 'rm -rf -- "$w"' EXIT

Quick check A script is stopped with kill (no -9) and has only an EXIT trap. Does it clean up?
Answer: Not reliably: add a TERM trap that calls exit 143, which then runs EXIT.

6 Real-world use

Temp files and traps at work

1. Data jobs

Extract, sort and join steps write intermediate files into one mktemp -d folder removed by a trap, even when Airflow kills the task.

extract→mktemp -d→trap

2. Publishing files

Static sites, nginx configs and price lists are written aside and mv’d into place so users never see half a file.

build→temp→mv

3. Secrets in scripts

Decrypted keys or tokens go into mktemp files (private by default) and are wiped by the EXIT trap.

decrypt→0600→trap rm

4. CI runners

Shared build machines run many jobs at once; fixed temp names cause flaky builds that mktemp fixes.

parallel→unique→stable

5. Housekeeping

systemd-tmpfiles and cron sweeps remove old leftovers by name and age after crashes and kill -9.

leftovers→find -mmin→clean

Script it: safe-job.sh

A complete pattern: a private scratch folder, a clean-up that keeps the exit status, INT/TERM handling, and an atomic publish, ready to paste into any job.

#!/usr/bin/env bash
set -euo pipefail
readonly PROG=${0##*/}
work=$(mktemp -d "${TMPDIR:-/tmp}/${PROG%.sh}.XXXXXX")
cleanup() {
  local rc=$?
  rm -rf -- "${work:?}"
  (( rc == 0 )) || echo "$PROG: failed (exit $rc), scratch removed" >&2
  exit "$rc"
}
trap cleanup EXIT
trap 'exit 130' INT
trap 'exit 143' TERM

seq 1 10 > "$work/numbers"
awk '{s += $1} END {print "sum", s}' "$work/numbers" > "$work/result"
mkdir -p out
tmp=$(mktemp out/.result.XXXXXX)
cp -- "$work/result" "$tmp"
chmod 644 "$tmp"
mv -- "$tmp" out/result.txt
cat out/result.txt
sum 55

Every line from this lesson in one place; the job prints sum 55.

Puzzle answer Remember the question from the story? Open to check your guess.

1. The rm on the last line runs only when the script reaches the last line. With set -e any failure exits earlier, Ctrl+C stops it mid-way, and kill ends it anywhere, so the file stays. trap cleanup EXIT (plus INT/TERM traps) runs on every ending. 2. A fixed name like /tmp/report.tmp is shared by every run: two runs write into the same file. mktemp gives each run its own unique, private name, so parallel runs (and other users) never collide.

Quick check In which order do you write mktemp and trap?
Answer: mktemp first, then trap immediately after, so the trap knows the path and nothing can fail in between.

Quick revision

Lesson 2.3 in one screen

  • Never fixed temp names: mktemp (file, 0600) or mktemp -d (folder, 0700); TMPDIR chooses the place.
  • Register trap 'cleanup' EXIT right after mktemp; single quotes so variables expand at run time.
  • cleanup(){ local rc=$?; rm -rf -- "${work:?}"; } keeps the exit status and refuses empty paths.
  • Add trap 'exit 130' INT and trap 'exit 143' TERM; kill -9 cannot be trapped.
  • Publish results atomically: build in a temp file on the same file system, then mv.
  • Sweep crash leftovers by template name and age (find -name job.* -mmin +60), dry run first.

Interview and viva questions

How do I create a temporary file in Bash?

tmp=$(mktemp) for a file, mktemp -d for a folder; they get unique names and private permissions.

How do I delete temp files when a script exits?

trap 'rm -rf -- "$tmp"' EXIT right after creating them.

Does trap EXIT run when the script is killed?

On Ctrl+C in Bash yes; for kill (TERM) add a TERM trap that exits; kill -9 never runs any trap.

What is the exit code after Ctrl+C?

130 (128 + signal 2).

Why use single quotes in trap?

So variables expand when the trap runs, not when it is set.

How do I write a file atomically?

Write to a temp file in the same folder, then mv it over the target.

Where should big temp files go?

Set TMPDIR to a disk-backed folder such as /var/tmp; /tmp may be RAM (tmpfs).
