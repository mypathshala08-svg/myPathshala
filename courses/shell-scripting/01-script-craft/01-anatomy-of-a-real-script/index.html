2 Definition

What makes a script “real”

Formal definition (write this in exams)

A shell script is a text file of shell commands run by an interpreter such as Bash. A production-quality (real) script additionally declares its interpreter (shebang), documents itself, runs in a safe mode that stops on errors, validates its input, reports problems on standard error with a non-zero exit code, and organises its work into functions called from one entry point.

In simple words

Commands in a file, plus checks, messages and structure.

A real script at four depths

Pick your depth. Completely new? Start at Very basic and climb one step at a time.

Very basic No jargon: a recipe card

A recipe says what it makes, what you need, what to do if an ingredient is missing, and the steps. A real script is the same, top to bottom.

Basic What you will type

  • Line 1: #!/usr/bin/env bash.
  • Line 4: set -euo pipefail.
  • Functions for each job, then main "$@" on the last line.
  • Always "$var" in double quotes.

Intermediate The differences that matter

  • -e: stop when a command fails; -u: an unset variable is an error; -o pipefail: a pipeline fails if any part fails, not just the last.
  • Errors go to stderr (>&2) so they do not mix with the script’s real output in pipes and files.
  • Exit codes: 0 success, 1 general error, 2 wrong usage (the convention of most Unix tools).
  • main "$@" at the end means Bash has read every function before anything runs.

Advanced Behind the screen: how Bash reads a script

  • The kernel reads #! on execve() and starts /usr/bin/env bash report.sh ARGS; env finds bash on the PATH (it lives in /bin, /usr/bin or /usr/local/bin depending on the system).
  • Bash reads and runs the file command by command; a function definition is just a command that stores the body. Calling main last guarantees all are defined, and protects against a half-downloaded script running its first half.
  • set -e has exceptions: commands in if, while, &&/|| lists and ! do not trigger it. Module 3 covers them.
  • ${0##*/} is the script’s name without its path, so messages say report.sh: however it was called.

Did you know? Google’s Shell Style Guide asks for exactly this shape (header, functions, main "$@" at the bottom) and says that a script over 100 lines should probably be rewritten in another language. Shell is for gluing commands together, and does that brilliantly.

Exam tip: “What does set -euo pipefail do?” → -e exits on a failing command, -u treats unset variables as errors, -o pipefail makes a pipeline’s status the last non-zero status of any command in it.

Quick check Why does main "$@" go on the last line?
Answer: So every function is defined before anything runs, and a partly downloaded script does nothing.
Common mistake
✗echo "error: file missing"; exit 0
✓echo "error: file missing" >&2; exit 1

Exit 0 tells cron, CI and other scripts that everything worked; the message also pollutes the real output.

Common mistake
✗for f in $files; do rm $f; done
✓for f in "${files[@]}"; do rm -- "$f"; done

Unquoted, a name like “my report.csv” becomes two words: rm deletes the wrong things or fails.

set -euo pipefail part 3: safe mode

🟢 Read-onlyno sudo

set -e stops at the first failing command; set -u stops on an unset variable; set -o pipefail makes a pipeline fail when any part fails. Together they stop a script from carrying on after something went wrong.

✓ Use it when
  • scripts that others run, cron, CI
✗ Don’t use it when
  • interactive shells (it would close them)

Undo and safety net

A script that went wrong usually only printed or stopped; fix and rerun. Prevent the dangerous cases:

  • Deleted the wrong files: quote every variable, and use rm -- "$f"; test with echo first.
  • Ran under sh: run bash script.sh or ./script.sh with the shebang.
  • Half-finished run: set -e stops it; make steps safe to repeat (Module 3).
  • Wrong output file overwritten: set -o noclobber makes > refuse to overwrite.

Error messages decoded

Errors students see most (really run on our build machine).

  1. cd ~/ops && printf 'echo hi\n' > bin/x.sh && ./bin/x.sh
    /home/riya/script.sh: line 49: ./bin/x.sh: Permission denied exit status: 126

    What it means: Permission denied: the file is not executable (exit 126).

    Fix: chmod +x bin/x.sh

  2. cd ~/ops && printf '#!/usr/bin/env bash\r\necho hi\r\n' > bin/w.sh && chmod +x bin/w.sh && ./bin/w.sh
    /usr/bin/env: ‘bash\r’: No such file or directory /usr/bin/env: use -[v]S to pass options in shebang lines exit status: 127

    What it means: Windows line endings: the shebang asks for “bash\r”.

    Fix: sed -i 's/\r$//' bin/w.sh (or dos2unix).

  3. cd ~/ops && bash -c 'set -u; echo "$1"'
    bash: line 1: $1: unbound variable exit status: 127

    What it means: -u: $1 is unset because no argument was given.

    Fix: Check $# first, or use ${1:-}.

  4. cd ~/ops && report.sh data/orders.csv
    /home/riya/script.sh: line 49: report.sh: command not found exit status: 127

    What it means: Not on the PATH: the shell does not look in the current folder.

    Fix: ./bin/report.sh, or put bin on PATH.

Quick check Your script prints an error but cron reports success. What is missing?
Answer: A non-zero exit (die / exit 1), and set -e / pipefail so failures stop it.

6 Real-world use

Where script anatomy matters

1. Scheduled jobs

cron and systemd timers judge a job only by its exit code; a script that exits 0 after an error fails silently for weeks.

cron→exit code→alert

2. CI/CD steps

GitHub Actions and Jenkins run steps as bash scripts, often with -e; a failing command must stop the deploy.

step→set -e→stop deploy

3. Team runbooks

On-call engineers run scripts they did not write; -h and clear errors save minutes in an outage.

-h→usage→right call

4. Data pipelines

Bash wrappers start Spark, Hive and sqoop jobs; pipefail catches a failed extract before a load step loads nothing.

extract→pipefail→load

5. Installers

Installer scripts wrap everything in main and call it last, so a half-downloaded script does nothing.

download→main last→safe

Examples are simplified and generic. They describe common patterns, not the internal systems of any particular company.

Script it: skeleton.sh

The eight-part skeleton, ready to copy: every new script in this course starts from it.

#!/usr/bin/env bash
# skeleton.sh - one line saying what the script does
# Usage: skeleton.sh [-h] NAME
set -euo pipefail

readonly PROG=${0##*/}

usage() { echo "Usage: $PROG [-h] NAME"; }
die()   { echo "$PROG: error: $*" >&2; exit 1; }

greet() {
  local name=$1
  echo "Hello, $name"
}

main() {
  [[ ${1:-} == -h ]] && { usage; exit 0; }
  [[ $# -eq 1 ]] || { usage >&2; exit 2; }
  greet "$1"
}

main "$@"
Usage: script.sh [-h] NAME

Replace greet with your work; keep the rest.

Puzzle answer Remember the question from the story? Open to check your guess.

1. A script’s exit code is the status of its last command. In cut … | sort | uniq -c that is uniq, which succeeds on empty input, so the failed cut is hidden and the script exits 0. set -o pipefail (plus -e) makes the pipeline, and the script, fail. 2. sh on Debian and Ubuntu is dash, a small POSIX shell without Bash features like [[ ]]; the shebang #!/usr/bin/env bash plus running ./script.sh (not sh script.sh) guarantees Bash.

Quick check Name the eight parts in order.
Answer: Shebang, header, safe mode, constants, usage/die, work functions, main, main "$@".

Quick revision

Lesson 1.1 in one screen

  • Eight parts: shebang, header, set -euo pipefail, readonly constants, usage/die, work functions, main, main "$@".
  • -e stops on failures, -u on unset variables, pipefail on any failing pipeline step.
  • Messages to stderr (>&2); exit 0 success, 1 error, 2 usage; 126 not executable, 127 not found.
  • Quote every variable; pass arguments on with "$@"; use ${1:-} under -u.
  • #!/usr/bin/env bash and ./script.sh; sh on Ubuntu is dash.
  • bash -n checks syntax; ${0##*/} gives the script name.

Interview and viva questions

What is the best shebang for Bash scripts?

#!/usr/bin/env bash finds bash on the PATH; #!/bin/bash is also fine on Linux.

What does set -euo pipefail mean?

Exit on errors, error on unset variables, and fail a pipeline if any command in it fails.

Why does my script exit 0 even after an error?

The exit code is that of the last command; use set -e, pipefail and explicit exit 1.

Why use a main function in Bash?

One clear entry point, local variables, and nothing runs until the whole file is read.

Why does [[ not found appear?

The script ran under sh (dash); use a bash shebang and run it with ./ or bash.

How do I print errors in a shell script?

echo "message" >&2, then exit with a non-zero code.

What does $@ mean in Bash?

All positional arguments; quoted as "$@" each stays a separate word.
