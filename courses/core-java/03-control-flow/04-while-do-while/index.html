while and do-while loops

A for loop is perfect when you know how many times to repeat. But how many months until Riya's savings reach ₹10,000? How many digits does a number have? How many tries until the right PIN? When the answer is “until something happens”, you use a while loop, or a do-while when the body must run at least once.

2 Definition

What are while and do-while?

Formal definition (write this in exams)

The while loop (while (condition) { body }) is an entry-controlled loop: the condition is evaluated before each iteration, so the body may execute zero times. The do-while loop (do { body } while (condition);) is an exit-controlled loop: the body executes first and the condition is evaluated afterwards, so the body executes at least once.

In simple words

while: “check, then do”. Like checking the queue before joining: if nobody's there, you skip it entirely. do-while: “do, then check”. Like tasting the chai and then deciding whether it needs more sugar: you always taste at least once.

Words you'll meet in this lesson

Entry-controlledCondition checked before the body (for, while). May run 0 times.
Exit-controlledCondition checked after the body (do-while). Runs at least once.
SentinelA special value that means “stop”, like entering 0 to finish a list.
Infinite loopA loop whose condition never becomes false, like while (true).
Loop invariantSomething that stays true on every iteration; useful for reasoning about correctness.
Digit extractionn % 10 gives the last digit; n / 10 removes it.

Exam tip: the do-while ends with a semicolon after the condition; forgetting it is a compile error. For a while loop, the variables in the condition must be changed inside the body, or the loop never ends.

4 Step by step

Writing a while loop that always ends

  1. Set up variables before the loop

    int savings = 0;
int months = 0;
    Unlike for, while has no init part. Everything the condition uses must already exist.

  2. Write the condition as “keep going while…”

    while (savings < 10_000) {
    javac puts the check at the top: if it's false, jump past the loop (if_icmpge). That's why a while loop can run zero times.

  3. Make progress inside the body

        savings += 1_500;
    months++;
}
    Each iteration must move the condition closer to false. Here savings grows, so eventually it reaches 10,000. If nothing changes, it's an infinite loop.

  4. Use the result after the loop

    When the loop ends, the condition is guaranteed to be false: savings >= 10_000. months holds the answer.

    At the end of the body, a goto jumps back to the check. When the check fails, execution continues after the loop.

  5. Switch to do-while when the body must run first

    do {
    digitSum += n % 10;
    n /= 10;
} while (n > 0);
    In bytecode, a do-while has its condition at the bottom: ifgt jumps back to the start if it's true. There's no check before the first iteration.
5 See it happen

Check first, or do first? Both views

Left: the code and output. Right: the order of check and body, and the bytecode shape.

while vs do-while 6 steps
What you see
  1. The while loop checks savings < 10_000 before every iteration.
  2. Each iteration adds ₹1,500 and counts a month. After 6 months: ₹9,000, still below the goal.
  3. After month 7, savings is ₹10,500, the condition is false, and the loop ends: 7 months.
  4. The do-while loop runs its body first: take the last digit, remove it.
  5. It checks n > 0 after each pass. 9 + 2 + 7 + 4 = 22.
  6. The difference shows with 0: while runs zero times, do-while runs once. The number 0 has one digit.
Behind the screen
  1. A while loop compiles to a check at the top, the body, and a goto back.
  2. Each pass updates savings and months in the stack frame.
  3. On the 8th check, 10500 ≥ 10000, so if_icmpge jumps to END.
  4. A do-while has no check at the top: execution goes straight into the body.
  5. The check is at the bottom: ifgt L jumps back while n > 0.
  6. Because the check comes last, the body always runs at least once.
6 Real-world use

“Until something happens” in real systems

Wherever software waits, retries, reads until the end, or runs until stopped, there's a while loop.

Watch it with an example: three tries to enter the OTP

A banking app gives you 3 attempts. A while loop keeps asking until the OTP is right or the attempts run out. Nobody knows in advance how many rounds it will take.

while (attempts < 3 && !ok) 6 steps
Animated example
  1. Start: attempts = 0, ok = false. The condition is checked before the first round: true, so the loop body runs.
  2. Try 1: the user types 1111. Wrong. attempts becomes 1. Back to the condition: still true.
  3. Try 2: 4812 (two digits swapped). Wrong again. attempts = 2.
  4. Try 3: 4821. Correct: ok = true, attempts = 3.
  5. Exit: the condition is now false (both parts would stop it), so the loop ends and the app logs the user in.
  6. while vs do-while: a while can run zero times. A menu that must appear at least once uses do { … } while (…), which checks at the end.

1. Reading files and streams

Reading a log or CSV file line by line: while ((line = reader.readLine()) != null). Nobody knows in advance how many lines there are (Module 13).

File→while line != null→Every line processed

2. Servers and background workers

A message consumer (for example a Kafka consumer) runs while (running) { poll(); process(); } for weeks, until it's asked to shut down.

Start service→while (running) poll→Graceful shutdown

3. Paging through an API

Many APIs return results page by page with a “next” link or cursor. Code keeps fetching while (nextCursor != null), collecting all pages.

Fetch page→while next != null→All transactions

4. Menus in terminals and kiosks

ATM-style and command-line menus use do-while: show the menu, handle the choice, repeat until the user picks Exit.

Show menu→do { … } while (choice != EXIT)→Goodbye

5. Financial projections

“How many years until this deposit doubles?” or “how many months to pay off this credit-card balance?” are while loops over months or years (see practice problem P10).

Deposit + rate→while amount < target→Years needed

Examples are simplified to show where while loops fit. Real systems add timeouts and error handling.

7 Run the code

Savings goal and digit sum

public class Main {
    public static void main(String[] args) {
        int savings = 0;
        int months = 0;
        while (savings < 10_000) {               // check first
            savings += 1_500;
            months++;
        }
        System.out.println("Goal reached in " + months + " months: Rs " + savings);

        int n = 4729, digitSum = 0;
        do {                                       // run first
            digitSum += n % 10;                    // last digit
            n /= 10;                               // remove it
        } while (n > 0);
        System.out.println("Digit sum: " + digitSum);
    }
}
Goal reached in 7 months: Rs 10500 Digit sum: 22
  • while (savings < 10_000)Keep going while the goal isn't reached. We don't need to know how many months in advance.
  • savings += 1_500;Progress: this is what eventually makes the condition false.
  • n % 10The last digit of n (4729 % 10 = 9).
  • n /= 10Removes the last digit using integer division (4729 / 10 = 472).
  • } while (n > 0);The do-while's check, at the bottom, ending with a semicolon.

9 Quiz and revision

Check yourself

Quick revision

Lesson 3.4 in one screen

  • while (cond) { … } — entry-controlled, may run 0 times.
  • do { … } while (cond); — exit-controlled, runs at least once, ends with ;.
  • Use while when the number of iterations isn't known: goals, files, sentinels, servers.
  • The body must make progress towards ending the loop, or it's infinite.
  • Digits: n % 10 = last digit, n / 10 = remove it.
  • Bytecode: while checks at the top; do-while checks at the bottom with a backward jump.

Interview and viva questions

Difference between while and do-while?

while checks the condition before each iteration and can run zero times. do-while checks after each iteration and always runs at least once. Syntax-wise, do-while ends with a semicolon.

How do you exit an infinite while (true) loop?

With break (leave the loop), return (leave the method), an exception, or by ending the program. Long-running loops usually check a flag such as running that another part of the program can set to false.

Can a for loop always replace a while loop?

Yes: while (c) { … } is the same as for (; c; ) { … }. The choice is about readability: for says “count”, while says “until”.

What is a sentinel-controlled loop?

A loop that reads values until a special stop value (the sentinel) appears, such as 0 or “exit”. The sentinel itself isn't processed as data.

What is busy waiting, and why is it bad?

A loop that repeatedly checks a condition without pausing, like while (!ready) { }. It burns 100% of a CPU core doing nothing. Use blocking calls, sleeps with backoff, or proper concurrency tools (Module 12) instead.

Practice problems

These use while or do-while because the number of steps isn't known in advance. Try each one before opening the solution.

P1Easy

Count the digits

Count how many digits a positive number has.

Input
n = 905213
Expected output
905213 has 6 digits
Show solution and explanation 
public class Main {
    public static void main(String[] args) {
        int n = 905213;
        int temp = n, count = 0;
        do {
            count++;
            temp /= 10;
        } while (temp > 0);
        System.out.println(n + " has " + count + " digits");
    }
}
905213 has 6 digits

How it works: each / 10 removes one digit, so we count how many removals it takes to reach 0. We use a copy, temp, so the original n is still available to print. do-while makes 0 correctly count as 1 digit.

P2Easy

Reverse a number

Reverse the digits of a number.

Input
n = 12345
Expected output
Reversed: 54321
Show solution and explanation 
public class Main {
    public static void main(String[] args) {
        int n = 12345;
        int reversed = 0;
        while (n > 0) {
            reversed = reversed * 10 + n % 10;
            n /= 10;
        }
        System.out.println("Reversed: " + reversed);
    }
}
Reversed: 54321

How it works: take the last digit of n and “push” it onto the end of reversed by multiplying reversed by 10 and adding the digit: 0 → 5 → 54 → 543 → 5432 → 54321.

P4Medium

Palindrome number

A palindrome reads the same forwards and backwards. Check whether a number is a palindrome.

Input
n = 12321
Expected output
12321 is a palindrome
Show solution and explanation 
public class Main {
    public static void main(String[] args) {
        int n = 12321;
        int temp = n, reversed = 0;
        while (temp > 0) {
            reversed = reversed * 10 + temp % 10;
            temp /= 10;
        }
        if (reversed == n) {
            System.out.println(n + " is a palindrome");
        } else {
            System.out.println(n + " is not a palindrome");
        }
    }
}
12321 is a palindrome

How it works: reverse a copy of the number (problem P2), then compare it with the original. Keeping the original untouched is the key detail.

P5Medium

Armstrong number

A 3-digit number is an Armstrong number if the sum of the cubes of its digits equals the number itself (e.g. 153 = 1³ + 5³ + 3³). Check a number.

Input
n = 153
Expected output
153 is an Armstrong number
Show solution and explanation 
public class Main {
    public static void main(String[] args) {
        int n = 153;
        int temp = n, sum = 0;
        while (temp > 0) {
            int d = temp % 10;
            sum += d * d * d;
            temp /= 10;
        }
        System.out.println(n + (sum == n ? " is" : " is not") + " an Armstrong number");
    }
}
153 is an Armstrong number

How it works: peel each digit, cube it with d * d * d (faster and exact compared with Math.pow, which returns a double), and add it up: 27 + 125 + 1 = 153.

P6Medium

GCD and LCM (Euclid's algorithm)

Find the greatest common divisor (GCD) and least common multiple (LCM) of two numbers.

Input
a = 48, b = 180
Expected output
GCD = 12, LCM = 720
Show solution and explanation 
public class Main {
    public static void main(String[] args) {
        int a = 48, b = 180;
        int x = a, y = b;
        while (y != 0) {
            int remainder = x % y;
            x = y;
            y = remainder;
        }
        int gcd = x;
        int lcm = a / gcd * b;
        System.out.println("GCD = " + gcd + ", LCM = " + lcm);
    }
}
GCD = 12, LCM = 720

How it works: Euclid's rule: gcd(x, y) = gcd(y, x % y), until y is 0. Steps: (48, 180) → (180, 48) → (48, 36) → (36, 12) → (12, 0). Then LCM = a × b ÷ GCD; dividing first (a / gcd * b) keeps numbers small and avoids overflow.

P7Medium

Collatz steps

Start with n. If it's even, halve it; if odd, make it 3n + 1. Count the steps until n becomes 1.

Input
n = 27
Expected output
27 reaches 1 in 111 steps
Show solution and explanation 
public class Main {
    public static void main(String[] args) {
        int start = 27;
        long n = start;
        int steps = 0;
        while (n != 1) {
            n = (n % 2 == 0) ? n / 2 : 3 * n + 1;
            steps++;
        }
        System.out.println(start + " reaches 1 in " + steps + " steps");
    }
}
27 reaches 1 in 111 steps

How it works: a perfect while-loop problem: nobody knows the number of steps in advance. Values can climb high before falling (27 goes past 9,000), so we use long to be safe from overflow.

P8Medium

Guess the number in the fewest tries

A secret number is between 1 and 100. Each guess is answered “higher” or “lower”. Always guess the middle of the remaining range, and print each guess and the number of tries.

Input
secret = 37
Expected output
Guesses: 50 25 37
Found in 3 tries
Show solution and explanation 
public class Main {
    public static void main(String[] args) {
        int secret = 37;
        int low = 1, high = 100, tries = 0;
        System.out.print("Guesses:");
        while (low <= high) {
            int guess = (low + high) / 2;
            tries++;
            System.out.print(" " + guess);
            if (guess == secret) {
                break;
            } else if (guess < secret) {
                low = guess + 1;      // answer was "higher"
            } else {
                high = guess - 1;     // answer was "lower"
            }
        }
        System.out.println();
        System.out.println("Found in " + tries + " tries");
    }
}
Guesses: 50 25 37 Found in 3 tries

How it works: this is binary search. Each guess halves the remaining range, so any number from 1 to 100 is found in at most 7 tries (27 = 128). The loop runs while the range is non-empty and stops early with break when found.

P9Business problem

ATM PIN with 3 attempts

An ATM allows 3 PIN attempts. The entered PINs for one session are given in order. Print “Access granted on attempt k”, or “Card blocked” if all 3 attempts fail.

Input
correct PIN = 4321
entered = 1111, 2580, 4321
Expected output
Attempt 1: wrong PIN
Attempt 2: wrong PIN
Access granted on attempt 3
Show solution and explanation 
public class Main {
    public static void main(String[] args) {
        final int CORRECT_PIN = 4321;
        final int MAX_ATTEMPTS = 3;
        int[] entered = {1111, 2580, 4321};   // what the customer typed

        int attempt = 0;
        boolean granted = false;
        do {
            int pin = entered[attempt];
            attempt++;
            if (pin == CORRECT_PIN) {
                granted = true;
            } else {
                System.out.println("Attempt " + attempt + ": wrong PIN");
            }
        } while (!granted && attempt < MAX_ATTEMPTS);

        if (granted) {
            System.out.println("Access granted on attempt " + attempt);
        } else {
            System.out.println("Card blocked");
        }
    }
}
Attempt 1: wrong PIN Attempt 2: wrong PIN Access granted on attempt 3

How it works:

  1. do-while fits because the customer must be asked at least once.
  2. The loop has two reasons to stop, combined with &&: success, or running out of attempts.
  3. After the loop, the granted flag tells us why it stopped. Change the last PIN to 9999 to see “Card blocked”.
  4. Real ATMs never store or compare plain PINs like this; the card and bank verify them securely. The loop logic is the same, though.
P10Business problem

When will the fixed deposit double?

A customer invests ₹50,000 in a fixed deposit at 7% per year, compounded yearly. How many years until it reaches at least ₹1,00,000, and what will it be worth then? (Compare with the “Rule of 72” estimate: 72 ÷ 7 ≈ 10.3 years.)

Input
amount = 50000, rate = 7%,
target = 100000
Expected output
Doubles after 11 years
Value then: Rs 105242.60
Show solution and explanation 
public class Main {
    public static void main(String[] args) {
        double amount = 50_000;
        double ratePercent = 7;
        double target = 100_000;
        int years = 0;
        while (amount < target) {
            amount += amount * ratePercent / 100;   // one year of interest
            years++;
        }
        System.out.println("Doubles after " + years + " years");
        System.out.printf("Value then: Rs %.2f%n", amount);
    }
}
Doubles after 11 years Value then: Rs 105242.60

How it works:

  1. Each pass adds one year's interest on the current amount: that's compounding.
  2. After 10 years the amount is about ₹98,358, just short; year 11 takes it past the target. The Rule of 72 (≈ 10.3 years) is a good mental estimate.
  3. The loop condition matches the business question exactly: “keep going while it's below the target”.
  4. Real deposit calculations follow the bank's rules (quarterly compounding, TDS) and use BigDecimal for exact money.

Real-world scenario questions (asked in company interviews)

Loops that run “until something happens” are where systems hang and burn CPU. Decide your answer first, then open the model answer.

Logistics · background job1–3 years

A waiting loop that uses 100% CPU

A job waits for a file to arrive from a partner with while (!Files.exists(path)) { }. The ops team reports one CPU core stuck at 100% for hours whenever the partner is late. What's wrong and what would you do?

The interviewer is checking: do you recognise busy waiting and know better alternatives?

Show a strong answer

This is busy waiting: the empty loop checks the file system millions of times a second without pausing.

  • Sleep between checks (e.g. Thread.sleep(30_000)), ideally with a growing delay, and a maximum wait time after which the job alerts someone.
  • Better: react to events instead of polling: Java's WatchService for file system changes, or have the partner send a message or API call when the file is ready.
  • Add monitoring so late files are visible, not just a hot CPU.

Avoid: an empty while body that waits for something external.

Fintech · API integration1–3 years

Downloading transactions never finishes

A job fetches bank transactions page by page with while (cursor != null) { page = api.fetch(cursor); … cursor = page.next(); }. One night the partner API had a bug and kept returning the same cursor. The job ran for 9 hours and filled the disk with duplicates. How would you make the loop safe?

The interviewer is checking: do you defend loops that depend on external systems?

Show a strong answer
  • Detect lack of progress: if the new cursor equals the previous one (or a page returns zero items), stop and raise an alert.
  • Add a safety limit: a maximum number of pages or a time budget, beyond which the job stops and alerts.
  • Make writes idempotent (e.g. upsert by transaction ID), so repeated pages don't create duplicates.
  • Log progress per page so you can resume from the last good cursor.

Avoid saying: “The partner's API should be correct.” Our code must protect itself.

E-commerce · message queue1–3 years

One bad order blocks all the others

An order processor runs while (!queue.isEmpty()) { Order o = queue.poll(); try { process(o); } catch (Exception e) { queue.add(o); } }. One order has corrupted data and always fails. Soon the worker spends all its time retrying it, and other orders are delayed. What's the fix?

The interviewer is checking: do you know about poison messages, retry limits and dead-letter queues?

Show a strong answer

The corrupted order is a poison message: it can never succeed, but the loop retries it forever.

  • Track a retry count per message; after a few attempts (with a delay between them), stop retrying.
  • Move it to a dead-letter queue where people can inspect and fix it, and raise an alert.
  • Separate failures that can succeed later (a timeout) from ones that can't (invalid data), and only retry the first kind.

Avoid: silently dropping the order. Someone paid for it.

Banking · kiosk softwareFresher

The menu that shows up twice

A passbook-printing kiosk shows its menu with this code: showMenu(); int choice = read(); while (choice != 4) { handle(choice); showMenu(); choice = read(); }. A reviewer says it works but suggests a do-while. Why might do-while be clearer here?

The interviewer is checking: do you know when “at least once” is the natural shape of a loop?

Show a strong answer

The menu must be shown and read at least once. With while, the “show and read” code is written twice (before the loop and at the end of it), and the two copies can drift apart when someone edits one.

  • With do-while it's written once: do { showMenu(); choice = read(); if (choice != 4) handle(choice); } while (choice != 4);
  • Add input validation and a timeout, so an abandoned kiosk returns to the home screen.

Avoid saying: “Both work, so it doesn't matter.” Duplicated code is a maintenance risk.
