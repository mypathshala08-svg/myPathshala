Operators: arithmetic, relational, logical, bitwise

Operators are the verbs of a program: add, compare, combine, flip bits. Most look familiar from maths, but a few hide surprises: x++ vs ++x, % with negative numbers, && skipping its right side, and | working on individual bits. This lesson shows the order Java evaluates things in, step by step.

1 The story

The canteen offer

The canteen runs an offer: “If your bill is over ₹70 and you're a member, get a free chai.” Riya writes the bill logic: price × quantity, plus a packing charge, plus 10% tax, then the offer check. Her first version gives free chai to everybody. Arjun Sir looks at one line and smiles.

Riya

Sir, I wrote isMember || total > 70 && isStudent and everyone who's a member gets free chai, even with a ₹20 bill!

Arjun Sir

Because && binds tighter than ||, just like * binds tighter than +. Java read it as isMember || (total > 70 && isStudent). Operators have a ranking called precedence.

Riya

So I should add brackets to say exactly what I mean.

Arjun Sir

Always, when you mix operators. Let's go through every operator family, and watch the order Java follows behind the screen.

2 Definition

What is an operator?

Formal definition (write this in exams)

An operator is a symbol that performs an operation on one, two or three operands and produces a result. Java's operators are grouped as arithmetic, unary (including increment/decrement), assignment, relational, logical, bitwise and shift, the ternary conditional operator, and instanceof. When an expression contains several operators, precedence decides which is applied first and associativity decides the order among operators of equal precedence.

In simple words

Operators are action symbols: + adds, > compares, && joins conditions. Like BODMAS in school maths, Java has rules about which action happens first. Brackets always win.

Words you'll meet in this lesson

OperandA value an operator works on. In a + b, a and b are operands.
Unary / binary / ternaryOperators with one (-x), two (a + b) or three (c ? a : b) operands.
PrecedenceWhich operator is applied first. * before +; && before ||.
AssociativityOrder among equal-precedence operators. Most go left to right; assignment goes right to left.
Short-circuit&& and || skip the right side when the left side already decides the answer.
Side effectA change an expression makes, like x++ changing x while also producing a value.

3 Types and ways to use it

The tricky operators, up close

x++ vs ++x

Postfix x++: use the old value, then add 1. Prefix ++x: add 1 first, then use the new value. Alone on a line, both just add 1.

Order matters

/ and %

Integer / drops the fraction; % gives the remainder. 17 samosas for 5 friends: 17 / 5 = 3 each, 17 % 5 = 2 left. % keeps the sign of the left side: -7 % 3 = −1.

Sign trap

&& and || short-circuit

a && b: if a is false, b is never evaluated. a || b: if a is true, b is skipped. That's why s != null && s.length() > 0 is safe.

Skips work

Bitwise & | ^ ~

Work on each bit separately. Used for flags and permissions: READ | WRITE combines; perms & WRITE tests. On booleans, & and | evaluate both sides (no short-circuit).

Bit-level

Shift operators

OperatorMeaningExample
<<Shift bits left, fill with 0 (× 2 per step)3 << 2 → 12
>>Shift right, keep the sign bit (÷ 2, rounding down)-7 >> 1 → −4
>>>Shift right, fill with 0 (unsigned shift)-7 >>> 28 → 15

String +: when either operand of + is a String, it means “join”. Evaluation is left to right, so 1 + 2 + "3" + 4 + 5 gives "3345": 1 + 2 = 3 first, then everything after the string is joined.

4 Step by step

How Java evaluates an expression

Take total = price * qty + 10 > 70 && member. Java follows the same steps for any expression.

  1. Group by precedence

    javac adds invisible brackets: total = (((price * qty) + 10) > 70) && member.

    This happens while parsing. The compiler builds a tree where higher-precedence operators sit lower, closer to the values.

  2. Evaluate operands left to right

    Java always evaluates the left operand of a binary operator before the right one.

    Unlike C, this order is guaranteed by the Java specification, so a++ + a always gives the same result on every JVM.

  3. Apply each operator

    price * qty → 60, + 10 → 70, > 70 → false.

    In bytecode this is a sequence on the operand stack: iload, iload, imul, bipush 10, iadd, then a comparison and a jump.

  4. Short-circuit if possible

    The left side of && is false, so member is never read.

    javac compiles && into a conditional jump: if the left side is false, jump straight past the right side.

  5. Assign the result

    The final value goes into total. Assignment has the lowest precedence and works right to left: a = b = 5 sets b first, then a.

    An assignment is itself an expression whose value is the assigned value. That's why if (x = 5) is a type error in Java: the result is an int, not a boolean.
5 See it happen

Six operator surprises: both views

Left: the code and what prints. Right: the order of evaluation and the bits.

Operators in action 6 steps
What you see
  1. Precedence: 3 * 5 runs first, so the answer is 35, not 115.
  2. a++ + ++a gives 12 and leaves a = 7. Two increments, two different moments.
  3. 17 / 5 = 3, 17 % 5 = 2, and -7 % 3 = −1, not 2.
  4. With &&, the null check fails first, so s.length() never runs.
  5. Bitwise OR combines flags into one number; AND tests a single flag.
  6. The ternary operator chooses between two values based on a condition.
Behind the screen
  1. javac builds an expression tree: * sits lower, so it's evaluated first.
  2. a++ hands over 5 then increments; ++a increments to 7 then hands over 7. The left side always goes first.
  3. Java defines % so that (a / b) * b + a % b == a. Division rounds towards zero, so the remainder takes the left side's sign.
  4. && is compiled as a jump: when the left side is false, the right side is skipped entirely.
  5. Flags are powers of two. | sets bits; & tests whether a bit is set.
  6. The ternary operator evaluates the condition, then only the chosen branch.
6 Real-world use

Operators in real systems

Operators look like school maths, but in production code they do some clever jobs.

Watch it with an example: checkout rules at an online store

Cart total Rs 850, the customer is a member. Watch each operator do its job, in the order Java evaluates them.

Operators deciding a discount 6 steps
Animated example
  1. Inputs: cart total is 850 and the customer is a member.
  2. GST: * and / have the same precedence, so Java goes left to right: 850 × 18 = 15,300, then ÷ 100 = 153 (integer result).
  3. Comparison: total >= 500 doesn't change anything; it produces a boolean, here true.
  4. Logical AND: big && member is true only if both are true. If big were false, Java would not even look at member (short-circuit).
  5. Ternary: condition ? a : b picks a value in one line. 850 is below 999, so delivery costs 40.
  6. Final bill: 850 + 153 − 100 + 40 = 943. Real checkouts use the same operators, just with more rules (and paise instead of rupees).

1. Spreading data across servers

Systems often decide which server or partition stores a record with the remainder operator, like userId % 4. Kafka and many databases use the same idea with hash values.

userId 1027→1027 % 4 = 3→Server 3

2. Permissions and feature flags

File permissions (like Linux's read/write/execute) and some feature-flag systems pack many yes/no options into one number, combined with | and tested with &.

READ | WRITE→perms & WRITE != 0→Allowed

3. Safe and fast checks with short-circuiting

Code puts the cheap or null-safe check first: user != null && user.isActive(), or cache.has(key) || loadFromDatabase(key), so the expensive or risky part runs only when needed.

Cheap check→&& / || skip the rest→Fewer DB calls, no NPE

4. Inside Java's own HashMap

HashMap mixes bits of a key's hash with ^ and >>>, then picks a bucket with & (n - 1), a fast replacement for % when n is a power of two (Lesson 11.6).

key.hashCode()→h ^ (h >>> 16), & (n−1)→Bucket index

5. Business rules in checkout

Offers such as “free delivery if the cart is over ₹399 or the user is a member, and the address is serviceable” are logical expressions. Getting the brackets right is the difference between a promotion and a loss.

(cart > 399 || member)→&& serviceable→Free delivery

Examples are simplified to show where operators fit. Real implementations vary.

7 Run the code

Riya's canteen bill

public class Main {
    public static void main(String[] args) {
        int price = 20, qty = 3;
        int total = price * qty + 10;          // * before +
        total += total / 10;                   // add 10% tax
        int a = 5;
        int b = a++ + ++a;                     // 5 + 7
        boolean member = total > 70 && a % 2 == 1;
        String msg = member ? "Free chai!" : "No offer";
        System.out.println(total + " " + a + " " + b + " " + msg);
    }
}
77 7 12 Free chai!
  • price * qty + 10Multiplication first: 60 + 10 = 70.
  • total += total / 10;Compound assignment: 70 + 7 = 77 (integer division).
  • a++ + ++aUses 5, then a becomes 6; then a becomes 7 and 7 is used. b = 12.
  • total > 70 && a % 2 == 1Relational and equality operators bind tighter than &&: true && true.
  • member ? … : …The ternary operator picks one of two values.

9 Quiz and revision

Check yourself

Quick revision

Lesson 2.5 in one screen

  • Arithmetic + - * / %; int / int drops decimals; % keeps the left sign.
  • x++ uses then adds; ++x adds then uses.
  • Relational/equality give booleans. = assigns, == compares.
  • && / || short-circuit; & / | always evaluate both sides.
  • Bitwise & | ^ ~ and shifts << >> >>> work bit by bit; used for flags and hashing.
  • Ternary cond ? a : b evaluates only the chosen side.
  • Precedence: postfix → unary → * / % → + − → shifts → relational → equality → & ^ | → && → || → ?: → =. Use brackets.

Interview and viva questions

What is the difference between & and && in Java?

Both can be used on booleans. && is short-circuit: it skips the right side if the left is false. & always evaluates both sides. & is also the bitwise AND for integers.

What is the output of i = i++ when i is 10?

i stays 10. i++ produces the old value 10 and increments i to 11, but then the assignment stores the produced value 10 back into i, overwriting the 11.

What is the difference between >> and >>>?

>> is an arithmetic shift that copies the sign bit, so negative numbers stay negative. >>> is a logical shift that always fills with zeros, so the result is non-negative.

Does Java support operator overloading?

Not for user-defined classes. The only built-in overload is + for String concatenation.

Why can't we write if (x = 5) in Java?

Because an assignment expression has the type of the variable (int here), and an if condition must be boolean. This rule catches a classic C bug at compile time. It only compiles if x itself is a boolean.

Real-world scenario questions (asked in company interviews)

Operator bugs hide in plain sight. Decide your answer first, then open the model answer.

E-commerce · promotionsFresher

Free delivery for everyone

The rule is: free delivery if (cart over ₹399 OR the user is a member) AND the pincode is serviceable. The code says if (cart > 399 || isMember && serviceable). Customers in non-serviceable areas are getting “free delivery” and orders are failing. Why?

The interviewer is checking: do you know that && has higher precedence than ||?

Show a strong answer

Java reads it as cart > 399 || (isMember && serviceable). Any cart over ₹399 passes, whether the pincode is serviceable or not.

  • Fix with explicit brackets: (cart > 399 || isMember) && serviceable.
  • Even better, name the parts: boolean eligible = cart > 399 || isMember; then if (eligible && serviceable).
  • Add tests for each combination of the three conditions (8 cases).

Avoid: relying on memorised precedence in business rules. Brackets document intent.

Data platform · sharding1–3 years

ArrayIndexOutOfBoundsException: Index -2

A service picks one of 8 cache servers with servers[key.hashCode() % 8]. It works for months, then crashes with an index of −2. Someone suggests Math.abs(key.hashCode()) % 8. Is that enough?

The interviewer is checking: do you know that % can be negative and about the Math.abs(Integer.MIN_VALUE) trap?

Show a strong answer

hashCode() can be negative, and Java's % keeps the sign of the left operand, so the index can be −1 to −7.

  • Math.abs is not enough: for Integer.MIN_VALUE, Math.abs returns MIN_VALUE itself (still negative), because +2,147,483,648 doesn't fit in an int. Some real strings have exactly that hash.
  • Use Math.floorMod(key.hashCode(), 8), which always returns 0–7, or (h & 0x7fffffff) % 8.
  • For real systems, consider consistent hashing, so adding a server doesn't move every key.

Avoid saying: “hashCode is always positive.”

Banking · KYC serviceFresher

Slow requests and random NullPointerExceptions

A check reads if (verifyWithBureau(pan) & customer != null & customer.isActive()). Every request makes a slow external bureau call, and some crash with NullPointerException. What would you change?

The interviewer is checking: do you understand short-circuit evaluation and ordering conditions from cheap to expensive?

Show a strong answer

Single & evaluates every operand, so the bureau call always runs, and customer.isActive() runs even when customer is null.

  • Use &&, and order conditions from cheapest and safest to most expensive: customer != null && customer.isActive() && verifyWithBureau(pan).
  • Now the null check protects the method call, and the slow external call only happens for active customers.
  • Measure the drop in bureau calls (and cost) after the change.

Avoid: treating & and && as interchangeable.

Analytics · reportingFresher

Conversion rate always shows 0%

A dashboard shows conversion rate as orders / visitors * 100, with both values as ints. It always shows 0%, even though 340 out of 9,000 visitors ordered. What's the bug, and how would you write it?

The interviewer is checking: do you combine operator order with integer division correctly?

Show a strong answer

Evaluation is left to right for / and * (same precedence). 340 / 9000 in int is 0, and 0 * 100 is 0.

  • Use double arithmetic: orders * 100.0 / visitors gives about 3.78.
  • Or reorder for integers: orders * 100 / visitors gives 3, but watch for overflow on large counts (use long).
  • Handle visitors == 0, and format the result to one or two decimals for display.

Avoid: “Multiply by 100 at the end.” Order and types both matter.
