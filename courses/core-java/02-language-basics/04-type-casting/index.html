Type casting: widening and narrowing

Sometimes a value has to move from one type of box to another: an int into a double, a double into an int. Moving to a bigger box is automatic and safe. Moving to a smaller box needs your permission, a cast, and can silently lose data. This lesson shows exactly what gets lost, bit by bit.

1 The story

The average that lost its decimals

Riya's five subject marks add up to 437. She writes double avg = total / 5; expecting 87.4. The program prints 87.0. She changed the variable to a double, so where did the .4 go?

Riya

Sir, avg is a double, so why did I get 87.0 and not 87.4?

Arjun Sir

Because Java calculated total / 5 first, and both of those are ints. int divided by int gives an int: 87. Only then was 87 widened into the double box as 87.0. The .4 was lost before the double ever saw it.

Riya

So I need to make it a double before dividing?

Arjun Sir

Exactly: (double) total / 5. That's a cast. Today you'll learn which conversions Java does for you, which ones need a cast, and what you can lose.

2 Definition

What is type casting?

Formal definition (write this in exams)

Type casting (type conversion) is converting a value from one data type to another. A widening (implicit) conversion goes from a smaller to a larger type and is done automatically by the compiler, e.g. int to double. A narrowing (explicit) conversion goes from a larger to a smaller type and requires a cast operator (type), e.g. (int) 87.4; it may lose information through truncation or overflow.

In simple words

Small box → big box: Java does it for you, nothing spills. Big box → small box: you must write the cast to say “I know, do it anyway”, and anything that doesn't fit is cut off.

Words you'll meet in this lesson

WideningConverting to a type that can hold every value of the original. Automatic.
NarrowingConverting to a type with a smaller range or no decimals. Needs a cast.
Cast operator(type) written before a value: (int) price.
TruncationCutting off the decimal part: (int) 9.99 is 9, not 10.
Numeric promotionIn arithmetic, byte, short and char are first converted to int.
ParsingConverting text to a number, e.g. Integer.parseInt("42"). Not a cast.

The widening ladder

Automatic directionbyte → short → int → long → float → double, and char → int
Needs a castAny step down the ladder, e.g. double → int, int → byte, int → char
Never allowedboolean ↔ any number. (int) true doesn't compile.
double → intDecimal part is dropped (towards zero): (int) 9.99 = 9, (int) -9.99 = -9
int → byteOnly the lowest 8 bits are kept: (byte) 300 = 44
Expression typeThe result has the widest type involved, at least int: int / int = int, int / double = double

Exam tip: “widening = implicit = safe”, “narrowing = explicit = may lose data”. One trap: long → float is widening and automatic, but can still lose precision, because float keeps only about 7 significant digits.

3 Types and ways to use it

Kinds of conversions

Widening (implicit)

int n = 42; double d = n;
Automatic, no data lost (except the long→float precision case).

Safe

Narrowing (explicit)

double d = 87.4; int n = (int) d;
You must write the cast. Decimals are cut; big values wrap.

May lose data

Promotion in expressions

byte a = 10, b = 20;
a + b is an int. Mixing int and double gives a double.

Automatic

Compound assignment

4 Step by step

How Java decides the type of an expression

  1. Look at each operand's type

    In total / 5, total is int and 5 is an int literal.

    javac works this out at compile time and chooses the bytecode instruction: idiv for ints, ddiv for doubles.

  2. Promote small types to int

    byte, short and char become int before any arithmetic.

    The JVM has no byte-addition instruction at all. Small values are loaded as ints, which is why byte + byte is an int.

  3. Widen to the biggest type present

    If either side is long, float or double, the other side is widened to match.

    For (double) total / 5, the cast happens first (it binds tighter than /), so 437.0 / 5 uses ddiv and gives 87.4.

  4. Do the operation in that type

    int ÷ int = int (fraction dropped). double ÷ int = double.

    The result's type is fixed. Assigning an int result to a double variable widens it afterwards; the lost fraction can't come back.

  5. Assign, widening automatically or casting explicitly

    Storing into a bigger type is automatic. Storing into a smaller one needs a cast, or javac reports “possible lossy conversion”.

    A narrowing cast compiles to instructions like d2i (double to int) or i2b (int to byte), which drop bits or decimals.

Pouring values between boxes 6 steps
What you see
  1. Widening: an int goes into a double automatically. 42 becomes 42.0.
  2. Narrowing: (int) 87.4 gives 87. The decimals are truncated, not rounded.
  3. (byte) 300 prints 44. A byte can't hold 300, so the value is chopped.
  4. Riya's bug: total / 5 is int division, giving 87, which is then widened to 87.0.
  5. Casting total to double before dividing gives the right answer, 87.4.
  6. a + b with two bytes is an int, so storing it in a byte needs a cast.
Behind the screen
  1. javac inserts an i2d instruction. Every int fits exactly in a double.
  2. d2i drops the fraction, rounding towards zero.
  3. i2b keeps only the lowest 8 bits of 300: 0010 1100 = 44.
  4. Both operands are ints, so javac uses idiv. The fraction is gone before the i2d widening.
  5. With the cast, 437 becomes 437.0, 5 is widened, and ddiv keeps the .4.
  6. byte values are promoted to int for arithmetic, so storing the result back needs a cast.
6 Real-world use

Where conversions bite in real systems

Conversions are everywhere data crosses a boundary: from the database, the network, a file or a calculation.

Watch it with an example: a product's average rating

Three customers rate a phone cover 5, 4 and 5 stars. Watch how integer division loses the fraction, and how one cast fixes it.

int ÷ int vs (double) cast 5 steps
Animated example
  1. Data: the ratings add up to sum = 14, and count = 3. Both are int.
  2. Bug: sum / count divides two ints, so Java does integer division and drops the fraction: 4. Storing it in a double later only makes it 4.0.
  3. Cast: (double) sum widens 14 to 14.0 before dividing. Now one side is double, so the other is widened too.
  4. Exact-ish result: 4.666666666666667. The fraction is kept.
  5. Display: round to one decimal for the screen: ★ 4.7. Shopping and food apps do exactly this for their ratings.

1. Average ratings and percentages

Ratings, attendance percentages and averages all divide one count by another. Using doubles (or casting first) avoids showing 4.0 when the real average is 4.3.

sum of stars, count→(double) sum / count→4.3 ★

2. Rounding money for display or payment

Payment gateways often need amounts in paise as whole numbers. Converting with a plain cast truncates; systems use Math.round or BigDecimal with an explicit rounding mode.

₹199.995→round, don't truncate→20000 paise

3. Reading numbers from text

Form inputs, CSV files and query parameters arrive as text. They're parsed, not cast, and invalid text must be handled (Module 9).

"42" from a form→Integer.parseInt→int 42

4. Binary data from devices and files

Bytes read from a sensor, image or network packet are Java bytes (−128 to 127). To get the unsigned value 0–255, code converts with b & 0xFF.

byte -56 from sensor→b & 0xFF→200

5. Sizes and counts from big systems

File sizes, row counts and timestamps are usually long. Casting them to int to pass into an older API works until the value passes 2.1 billion, then silently goes wrong. Math.toIntExact throws an exception instead.

3 GB file→Math.toIntExact(size)→Error instead of a wrong number

Examples are simplified to show where conversions happen. Real systems vary.

7 Run the code

Riya's marks, converted correctly

public class Main {
    public static void main(String[] args) {
        int total = 437;
        double wrongAvg = total / 5;            // int division first
        double avg = (double) total / 5;        // cast first
        int whole = (int) avg;                  // truncates
        long rounded = Math.round(avg);         // rounds
        byte squeezed = (byte) 300;             // keeps lowest 8 bits
        int parsed = Integer.parseInt("42");    // text to number

        System.out.println(wrongAvg + " vs " + avg);
        System.out.println(whole + " " + rounded + " " + squeezed + " " + parsed);
    }
}

  • (double) total / 5The cast applies to total first, so the division is done in double.
  • (int) avgNarrowing: drops .4. It never rounds up.
  • Math.round(avg)Rounds to the nearest whole number and returns a long.

9 Quiz and revision

Check yourself

Quick revision

Lesson 2.4 in one screen

  • Widening (automatic): byte → short → int → long → float → double, char → int.
  • Narrowing (needs (type)): may truncate decimals or keep only the low bits.
  • (int) 9.99 = 9, (int) -9.99 = -9. Use Math.round to round.
  • Arithmetic promotes byte/short/char to int; the result type is the widest involved.
  • int / int = int. Cast before dividing: (double) a / b.
  • +=, -=… include a hidden cast.
  • Text ↔ number is parsing/formatting, not casting. boolean never converts.

Interview and viva questions

What is the difference between implicit and explicit casting?

Implicit (widening) casting is done automatically by the compiler when converting to a type that can hold all values, like int to long. Explicit (narrowing) casting must be written with a cast operator when converting to a smaller or less precise type, like double to int, and may lose data.

Why does byte b = 10; compile if 10 is an int?

Because 10 is a compile-time constant that fits in a byte, Java allows the implicit narrowing for constants. byte b = x; where x is an int variable would not compile.

Why is long → float called widening if it can lose precision?

Because float's range is larger than long's (up to about 3.4 × 1038), so no value overflows. But float has only about 7 significant digits, so large longs are rounded. Java classifies it as widening but warns in the specification about precision loss.

What happens when you cast a very large double to int?

For double to int, Java uses saturation: values above Integer.MAX_VALUE become MAX_VALUE, values below MIN_VALUE become MIN_VALUE, and NaN becomes 0. For int to byte, the bits are chopped instead, so the result can wrap around.

Does s += 1 work when s is a short?

Yes. Compound assignment operators include an implicit cast back to the variable's type, so s += 1 compiles while s = s + 1 doesn't.

Real-world scenario questions (asked in company interviews)

Conversion bugs don't crash; they quietly produce wrong numbers. Decide your answer first, then open the model answer.

Food delivery · ratingsFresher

Every restaurant shows a whole-number rating

A restaurant listing page shows ratings like 4.0 and 3.0 but never 4.3 or 3.7. The code is double rating = totalStars / reviewCount;, where both are ints read from the database. What's wrong and how would you fix it?

The interviewer is checking: do you spot integer division and know where the cast must go?

Show a strong answer

Both operands are ints, so Java does integer division and drops the fraction before the result is widened into the double.

  • Fix: double rating = (double) totalStars / reviewCount;, casting before dividing.
  • Guard against reviewCount == 0 (no reviews yet), which would otherwise give an error or NaN.
  • Round only for display, e.g. to one decimal place, and add a unit test with an average like 4.33.

Avoid: (double) (totalStars / reviewCount). The cast is too late; the division has already dropped the fraction.

Payments · checkoutFresher

Customers are charged one paisa less

Before calling the payment gateway, the code converts a rupee amount to paise with long paise = (long) (amount * 100);. For ₹19.99, the gateway receives 1998 paise. Why?

The interviewer is checking: do you understand that floating-point results can be slightly below the expected value, and that casts truncate?

Show a strong answer

19.99 can't be stored exactly as a double. 19.99 * 100 comes out as something like 1998.9999999999998, and the cast truncates it to 1998.

  • Short-term: use Math.round(amount * 100) instead of a cast.
  • Proper fix: never hold money in double. Keep amounts in paise (long) or BigDecimal from the moment they enter the system.
  • Add tests with known problem values such as 19.99, 0.29 and 1.15.

Avoid saying: “The gateway has a bug.” The truncation happened in our code.

Cloud storage · uploads1–3 years

Large uploads show a negative size

Users uploading files larger than about 2 GB see a negative file size, and the progress bar breaks. The upload code reads long size = file.length(); and passes (int) size to an older progress-tracking method. Explain and fix.

The interviewer is checking: do you know what a narrowing cast does to values beyond the target range?

Show a strong answer

An int holds at most 2,147,483,647 bytes (about 2 GB). Casting a larger long to int keeps only the low 32 bits, which can be read as a negative number. The cast hid the problem from the compiler.

  • Change the progress method to accept a long.
  • If an int is truly required, use Math.toIntExact(size), which throws an exception instead of producing a wrong value, and handle that case.
  • Search the codebase for other (int) casts on sizes, counts and timestamps.

Avoid: adding casts just to make the compiler quiet. A cast says “I accept data loss”.

IoT · sensor data1–3 years

Negative humidity readings

A device sends humidity as one byte from 0 to 255. Readings above 127 show up in the Java dashboard as negative numbers, like −56 for a real value of 200. What's happening?

The interviewer is checking: do you know that Java's byte is signed, and how to read unsigned values?

Show a strong answer

Java's byte is signed: −128 to 127. The bit pattern for 200 (1100 1000) has the top bit set, so Java reads it as −56.

  • Convert to an unsigned int: int humidity = b & 0xFF; (or Byte.toUnsignedInt(b)). This keeps the 8 bits and treats them as 0–255.
  • Document the byte format of the device protocol, and add tests with values above 127.

Avoid: adding 256 to negative values in scattered places. Convert once, where the bytes are read.
