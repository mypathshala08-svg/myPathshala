Primitive data types (int, double, char, boolean…)

A variable's type decides how many bits of memory it gets and how those bits are read. Java has exactly eight built-in primitive types. In this lesson you'll learn their sizes and ranges, how to write their values, and why Integer.MAX_VALUE + 1 is negative and 0.1 + 0.2 isn't exactly 0.3.

1 The story

The marks sheet that broke

Riya is building a marks sheet for her class: age, roll number, percentage, grade and pass/fail. She stores everything as int. The percentage 87.5 turns into an error, and the grade 'A' won't fit either. She asks Arjun Sir which type to use for what.

Riya

Sir, can't I just use int for everything? It's easier.

Arjun Sir

An int box only holds whole numbers, and only up to about 2.1 billion. 87.5 has a decimal part, 'A' is a character, and India's population needs a bigger box. Java gives you eight sizes and shapes of box, the primitive types.

Riya

Why not one giant box for everything?

Arjun Sir

Memory and speed. A college system might store crores of marks. Using 1 byte instead of 8 for each age saves a lot. Let's look inside each box, right down to the bits.

2 Definition

What are primitive data types?

Formal definition (write this in exams)

A data type specifies the kind of values a variable can hold, the memory it needs and the operations allowed on it. Java has eight primitive data types, built into the language and not objects: four integer types (byte, short, int, long), two floating-point types (float, double), one character type (char) and one logical type (boolean). Their sizes are fixed by the language on every platform.

In simple words

Primitives are Java's basic building blocks: whole numbers in four sizes, decimal numbers in two precisions, a single character, and true/false. They hold the value directly in the box, unlike objects (next lesson), where the box holds an arrow.

3 Types and ways to use it

Four families, and how to write their values

Integers: byte, short, int, long

Whole numbers, positive or negative. Pick by range: int normally, long for big counts, IDs, timestamps in milliseconds or money in paise.

Exact

Floating point: float, double

Numbers with a decimal part, stored in binary scientific notation (IEEE 754). Very wide range, but approximate. Use double unless memory is very tight.

Approximate

Character: char

One 16-bit Unicode code unit, written in single quotes: 'A', '₹', '\n'. Internally it's a number, so 'A' + 1 is 66.

Unicode

Logical: boolean

Only true or false. The result of comparisons like marks >= 40, and the condition in every if and loop.

4 Step by step

Choosing the right type: a checklist

  1. Is it true/false?

    Use boolean: isPaid, hasDiscount, passed.

    The JVM usually stores a boolean field in a byte, and boolean arrays use one byte per element, but the language never lets you treat it as a number.

  2. Is it a single character?

    Use char: a grade, a gender code, a menu option. For words and sentences, use String (next lesson).

    'A' is stored as the number 65 in 16 bits: 0000 0000 0100 0001.

  3. Is it a whole number?

    Default to int. If it could exceed about 2.1 billion (bank balances in paise, file sizes, timestamps in milliseconds, IDs in big systems), use long.

    Arithmetic is done in at least 32 bits anyway: byte + byte produces an int. byte and short mainly save memory in large arrays.

  4. Does it have a decimal part?

    Use double for measurements: percentages, distances, temperatures.

    A double stores a sign bit, 11 exponent bits and 52 fraction bits. Most decimal fractions, like 0.1, have no exact binary form, so tiny rounding errors appear.

  5. Is it money?

    Don't use double. Store paise in a long, or use BigDecimal (Module 10).

    ₹0.10 + ₹0.20 as doubles gives 0.30000000000000004. In a bank, those tiny errors add up across millions of transactions.
5 See it happen

Inside the boxes: the bits behind each value

Left: the code and what it prints. Right: the actual bits in memory.

Primitive values, bit by bit 6 steps
What you see
  1. byte age = 100; fits easily: a byte holds −128 to 127.
  2. 'A' + 1 prints 66, because a char is stored as a number (65). Casting back gives 'B'.
  3. Integer.MAX_VALUE is 2,147,483,647, the largest int.
  4. Adding 1 gives −2,147,483,648. Java doesn't stop you: the value wraps around.
  5. 0.1 + 0.2 prints 0.30000000000000004. Decimals in double are approximate.
  6. A comparison like marks >= 40 produces a boolean: true or false.
Behind the screen
  1. 100 is stored as the 8 bits 0110 0100: 64 + 32 + 4. The leftmost bit is the sign.
  2. 'A' is the 16-bit Unicode number 65. In arithmetic, chars are promoted to int.
  3. The largest int has a 0 sign bit and 31 ones: 2³¹ − 1.
  4. Adding 1 carries into the sign bit. In two's complement that pattern is the most negative int.
  5. A double has a sign, an exponent and a 52-bit fraction. 0.1 repeats forever in binary, so it's rounded.
  6. The sizes side by side: 8, 16, 16, 32, 32, 64 and 64 bits. boolean's size is left to the JVM.
6 Real-world use

Picking types in real systems

Wrong type choices are behind some famous software bugs. Here's how real systems choose.

Watch it with an example: when the box is too small

A video app counts views in an int. A shop adds prices in double. Both hit a surprise. Watch what happens to the bits, and the fix.

int overflow and double rounding 6 steps
Animated example
  1. The limit: an int has 32 bits. The first bit is the sign, so the largest value is 2,147,483,647 (about 214 crore).
  2. Overflow: add 1 and the bits roll over to 1000…0, which means the most negative int. No error is shown; the views count silently becomes negative.
  3. Fix: use long (64 bits) for counts that can grow big: views, transaction IDs, timestamps in milliseconds.
  4. Fractions: double stores numbers in binary. 0.1 and 0.2 cannot be stored exactly, only very close values.
  5. Surprise: the tiny errors add up, and Java prints 0.30000000000000004. Fine for distances or sensor readings, risky for money.
  6. Fix for money: count whole paise in a long (or use BigDecimal, later). Integers are exact.

1. Money in banking and payments

Payment systems commonly store amounts as whole paise in a long, or use BigDecimal, so every rupee adds up exactly. Floating-point types are avoided for money.

₹1,250.50→long amountInPaise = 125050→Exact totals

2. Maps, GPS and sensors

Latitude, longitude, speed and temperature are measurements with natural tiny errors anyway, so double is the right choice. Ride-hailing and delivery apps calculate distances with doubles.

GPS 19.0473, 73.0699→double lat, lng→Distance in km

3. Timestamps and IDs

System.currentTimeMillis() returns a long: milliseconds since 1 January 1970 are far beyond int's range. Order IDs and user IDs in large systems are also usually long.

Now→long millis→Logs, sorting, expiry

4. Images, files and network data

Raw data such as image pixels, PDF files and network packets is handled as byte arrays. A photo upload is millions of bytes, so the smallest type matters.

Photo upload→byte[] data→Saved to storage

5. Indian languages and symbols

Because char is Unicode, Java handles Devanagari, Tamil, Bengali and the ₹ sign naturally. That's why Java apps serve users in many Indian languages.

'₹' = 8377→char / String (UTF-16)→Shown correctly

Examples are simplified to show type choices. Each company's design varies.

9 Quiz and revision

Check yourself

Quick revision

Lesson 2.2 in one screen

  • 8 primitives: byte 8, short 16, int 32, long 64, float 32, double 64, char 16 (Unicode), boolean (true/false).
  • Defaults: int for whole numbers, double for decimals. L for long literals, f for float.
  • Integer overflow wraps silently: MAX_VALUE + 1 = MIN_VALUE.
  • int ÷ int drops the fraction; % gives the remainder.
  • float/double are approximate: 0.1 + 0.2 ≠ 0.3. Never use them for money.
  • char is a number: 'A' = 65. boolean is never a number.
  • Primitives hold values directly (stack for locals); they are not objects.

Interview and viva questions

Why does Java have primitive types if it's object-oriented?

For speed and memory. A primitive is a plain value with no object overhead, so arithmetic is fast and arrays of numbers are compact. Wrapper classes (Integer, Double…) exist when you need an object version (Module 10).

Why is char 2 bytes in Java but 1 byte in C?

Java uses Unicode from the start, so a char holds a 16-bit UTF-16 code unit, enough for most of the world's scripts. Characters outside that range (some emoji, rare scripts) take two chars, called a surrogate pair.

What is the size of a boolean?

The language specification doesn't fix it. HotSpot typically uses one byte for boolean fields and array elements, and an int-sized slot for local variables. Only true and false are ever visible to your code.

Why is 0.1 + 0.2 not equal to 0.3?

double stores numbers in binary. 0.1 and 0.2 are repeating fractions in binary, so each is rounded to the nearest representable value. Their sum is slightly off: 0.30000000000000004. Compare doubles with a tolerance, and use BigDecimal or integer paise for money.

How do you detect integer overflow?

Use a bigger type (long), or Math.addExact, Math.multiplyExact and similar methods, which throw ArithmeticException on overflow instead of wrapping silently.

Real-world scenario questions (asked in company interviews)

Type choices look small, but they cause real money and data problems. Decide your answer first, then open the model answer.

Fintech · reconciliationFresher

The invoice total that's off by one paisa

An invoicing service stores prices as double. Finance reports that a few thousand invoices each month are off by ₹0.01 compared with the bank statement. Each line item looks correct. What's the likely cause, and how would you fix it?

The interviewer is checking: do you know that floating-point types are approximate, and the standard ways to handle money?

Show a strong answer

double stores values like 0.10 approximately in binary. When many items are added, multiplied by tax rates and rounded at different points, the tiny errors can push a total over a rounding boundary by one paisa.

  • Store amounts as whole paise in a long, or use BigDecimal with an explicit rounding mode (for example HALF_UP) and scale 2.
  • Decide and document where rounding happens (per line or per invoice), matching the finance/tax rules.
  • Store the same exact type in the database (a DECIMAL column, not FLOAT).
  • Add tests with known tricky values like 0.1 + 0.2.

Avoid: “Just round at the end with Math.round.” It hides some cases but doesn't make double exact.

E-commerce · analytics1–3 years

Negative revenue in the sales report

After a big festival sale, the daily dashboard shows negative total revenue. The code adds up order amounts in paise into an int total. On normal days the numbers are fine. What happened?

The interviewer is checking: do you recognise integer overflow, and do you know how to prevent it?

Show a strong answer

An int can hold at most 2,147,483,647, which in paise is only about ₹2.15 crore. The sale pushed the total past that, so the value wrapped around to a negative number without any error.

  • Use long for totals (up to about 9.2 × 1018 paise), or BigDecimal.
  • Use Math.addExact where overflow must never pass silently; it throws an exception instead.
  • Check the database column and any reporting code for the same limit.
  • Add a test with values near the limit, and alerting on impossible values like negative revenue.

Avoid saying: “Java would throw an error if the number was too big.” It doesn't for int and long arithmetic.

Social app · growth1–3 years

New users can't sign up

A fast-growing app suddenly fails to create new accounts. The logs show user IDs becoming negative. The database ID column is a 64-bit BIGINT, but the Java code reads IDs into an int userId. Why now, after years of working fine?

The interviewer is checking: do you understand type ranges across systems, and the need to keep Java and database types consistent?

Show a strong answer

The IDs only just crossed int's maximum of 2,147,483,647. Until then every ID fitted in an int. The next ID no longer fits; converting it to int keeps only the low 32 bits, which can produce a negative or wrong number.

  • Change the Java type to long everywhere the ID flows: entities, APIs, caches and clients.
  • Check other services and mobile apps that consume the ID, since they may have the same limit.
  • Rule of thumb: Java types should match the database column (BIGINT → long).

Avoid: “Reset the ID counter.” That risks duplicate IDs and doesn't fix the type mismatch.

IoT · cold-chain monitoringFresher

The temperature alert that never fires

A vaccine fridge monitor calculates an average temperature as a double and raises an alert with if (avgTemp == 8.0). Testers saw the reading pass through 8 degrees, but no alert came. Why?

The interviewer is checking: do you know not to compare floating-point values with ==?

Show a strong answer

A calculated double is rarely exactly 8.0. It might be 7.999999999 or 8.000000001, so the == check is almost never true.

  • For thresholds, use a range: if (avgTemp >= 8.0), which also catches values that jump past 8.
  • When equality is really needed, compare with a tolerance: Math.abs(a - b) < 0.0001.
  • Test with values just below, at and just above the limit.

Avoid: using == with float or double results of calculations.
