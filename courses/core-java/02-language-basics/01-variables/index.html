Variables: boxes in memory

Every program needs to remember things: a balance, a name, a count. Java remembers them in variables, named boxes in memory. In this lesson you'll learn how to create, fill and change those boxes, the rules for naming them, how long each box lives, and exactly where in memory Java keeps it.

1 The story

Riya's canteen wallet

The college canteen has started a prepaid wallet. Riya loads ₹500 on Monday. Every chai costs ₹20. She wants a small program that keeps track of her balance, and Arjun Sir uses it to explain the most basic idea in programming.

Riya

Sir, my balance starts at 500, then becomes 480, then 460… How does the program remember the latest number?

Arjun Sir

It stores it in a variable: a box in memory with a label on it. The label is balance. When you buy a chai, Java takes the number out, subtracts 20, and puts the new number back. The old 500 is simply gone.

Riya

And the chai price? That shouldn't change in the middle of the program.

Arjun Sir

Then we lock that box with final. Let's see how Java creates these boxes, and where it keeps them.

2 Definition

What is a variable?

Formal definition (write this in exams)

A variable is a named memory location that stores a value of a specific data type. In Java, every variable must be declared with a type before use (int balance;), may be initialised with a first value (int balance = 500;), and can be assigned new values later unless it is declared final. Based on where they are declared, Java variables are local, instance or static variables.

In simple words

A variable is a labelled box. The label is its name, the type says what kind of thing fits inside (a whole number, a decimal, text…), and the box holds one value at a time. Putting a new value in throws the old one away.

Exam tip: Java is statically typed: a variable's type is fixed at compile time and can never change. int x = 5; x = "five"; is a compile error. Also remember: local variables have no default value, so reading one before assigning it gives the error “variable might not have been initialized”.

3 Types and ways to use it

Three kinds of variables, and where each lives

Java sorts variables by where you declare them. That decides how long they live, who can see them and which part of memory holds them.

Local variable

Declared inside a method or block. Lives in that method's stack frame and disappears when the block ends. No default value.

Stack

Instance variable

Declared in the class, without static. Every object gets its own copy, stored inside the object on the heap. Gets a default value.

Heap (per object)

Static variable

Declared in the class with static. Only one copy, shared by the whole class and every object. Lives as long as the class is loaded.

Ways to write a variable

Declare, then assign

int balance;
balance = 500;
Useful when the value is decided later.

Declare and initialise

int balance = 500;
The most common and safest form.

final constant

final int CHAI_PRICE = 20;
Assigned once, never again.

var (type inference)

var city = "Kharghar";
The compiler infers String. Only for local variables with an initial value.

4 Step by step

The life of one variable

  1. Declare it

    int balance;
    javac reserves a slot for balance in main's stack frame and remembers it holds an int (4 bytes). No value is stored yet, and javac won't let you read it.

  2. Initialise it

    balance = 500;
    The number 500 is written into the slot. In bytecode this is sipush 500 then istore_1.

  3. Read and update it

    balance = balance - 20;
    The right side runs first: read 500, subtract 20, get 480. Then the result is written back into the same slot. The old value 500 is overwritten; it isn't kept anywhere.

  4. Lock a value with final

    final int CHAI_PRICE = 20;
CHAI_PRICE = 25;   // error: cannot assign a value to final variable CHAI_PRICE
    The check happens at compile time: javac refuses any second assignment. At run time a final local is just a normal slot.

  5. Watch it go out of scope

    {
    int tip = 5;
    balance = balance - tip;
}
// tip can't be used here
    A variable exists only inside the { } block where it was declared. After the closing brace the name tip is unknown to javac, and its slot can be reused.
5 See it happen

Boxes appearing, changing and disappearing: both views

Step through Riya's wallet code. Left: the code and output. Right: main's stack frame, slot by slot.

Riya's wallet in memory 6 steps
What you see
  1. int balance; declares a variable: a box named balance that can hold one whole number.
  2. balance = 500; initialises it with its first value.
  3. balance = balance - 20; reads the current value, calculates 480 and stores it back.
  4. final int CHAI_PRICE = 20; creates a constant.
  5. Inside the { } block, tip is created, used, and then goes out of scope.
  6. Trying to change CHAI_PRICE is rejected by javac: the program doesn't even compile.
Behind the screen
  1. javac gives balance slot 1 in main's stack frame: 4 bytes for an int. No value yet.
  2. 500 is stored in slot 1 (bytecode sipush 500, istore_1).
  3. The JVM loads 500, pushes 20, subtracts, and stores 480 in the same slot. The old value is gone.
  4. CHAI_PRICE gets slot 2. The lock is a compile-time rule; at run time it's a normal slot.
  5. tip takes slot 3 only while the block runs. The balance becomes 475.
  6. After the block, slot 3 is free. The attempt to reassign the final variable stops compilation.
6 Real-world use

Variables in real software

Every app you use is full of variables. Here's how the three kinds show up in real systems.

Watch it with an example: a metro card through one day

One variable, balance, holds the card's money. Watch the value in the box change while the name stays the same.

int balance changes, the box stays 6 steps
Animated example
  1. Declare: int balance = 200; reserves a 4-byte box named balance and puts 200 in it. The fare is a constant, final int FARE = 30;
  2. Morning trip: the right side is worked out first (200 − 30), then the result 170 replaces the old value. The old 200 is gone.
  3. Evening trip: same line, new value: 140. A variable remembers only its latest value.
  4. Recharge: balance += 100 is short for balance = balance + 100. Now 240.
  5. Constant: trying to change FARE fails at compile time, because it is final. Business rules like fares and tax rates are often constants.
  6. Print: the program reads the box and prints 240. Same name all day; the value moved 200 → 170 → 140 → 240.

1. Wallets and bank balances

A payment request has local variables like amount, fee and newBalance while it's being processed. The final balance is then saved to a database, because variables vanish when the program stops.

Request→local amount, fee, newBalance→Saved in DB

2. Student or customer records

Each Student object has its own instance variables: name, rollNo, marks. A college system may hold thousands of objects, each with its own copy.

new Student()→instance variables per object→Report cards

3. Constants for business rules

Rates and limits such as MAX_UPI_LIMIT or GST_RATE are written as named static final constants, so a rule change happens in one place instead of fifty.

static final GST_RATE→used in every bill→One place to update

4. Counters and statistics

A static counter can track something for the whole application, like requests served. In multi-user servers this needs care (Module 12), because many threads update the same shared variable.

Each request→static counter + 1 (thread-safe)→Dashboard

5. Configuration read into variables

Settings like database URLs and timeouts are read from configuration files or environment variables at start-up and stored in Java variables, so the same code runs in testing and production with different values.

application.properties→String dbUrl, int timeout→Same code, any environment

Examples are simplified to show where variables fit. Real systems differ in detail.

7 Run the code

Riya's wallet program

public class Main {
    static int ordersToday = 0;          // static variable

    public static void main(String[] args) {
        int balance = 500;               // local variable
        final int CHAI = 20;             // constant
        balance = balance - CHAI;
        ordersToday = ordersToday + 1;
        {
            int tip = 5;                 // exists only in this block
            balance = balance - tip;
        }
        System.out.println("Balance: " + balance);
        System.out.println("Orders today: " + ordersToday);
    }
}
Balance: 475 Orders today: 1
  • static int ordersToday = 0;A static variable: one shared copy for the whole class.
  • int balance = 500;A local variable, declared and initialised in one line.
  • final int CHAI = 20;A constant. Any later CHAI = … is a compile error.
  • balance = balance - CHAI;The right side is calculated first (500 − 20), then stored back.
  • { int tip = 5; … }tip lives only inside this block.

9 Quiz and revision

Check yourself

Quick revision

Lesson 2.1 in one screen

  • Variable = named memory location with a type. Declare → initialise → assign.
  • Names: letters, digits, _, $; no digit first; no keywords; case-sensitive. camelCase for variables, UPPER_SNAKE_CASE for constants.
  • Local (stack, no default), instance (heap, per object, default), static (class, one shared copy, default).
  • final = assign once (checked at compile time). var = inferred type for locals, still fixed.
  • Scope = the { } block where it's declared.
  • Assignment copies the value; the old value is overwritten.

Interview and viva questions

What is the difference between local, instance and static variables?

Local variables are declared inside methods, live on the stack only during that call and have no default value. Instance variables are declared in the class without static; each object has its own copy on the heap with a default value. Static variables are declared with static; one copy is shared by the whole class.

Why don't local variables get default values?

To catch mistakes. A local variable that's read before being set is almost always a bug, so javac forces you to assign it. Fields get defaults because objects are created in many ways and the JVM must zero their memory anyway.

Is var in Java the same as var in JavaScript?

No. Java's var only asks the compiler to infer the type from the initial value; the variable is still statically typed and can't change type. It works only for local variables with an initializer, not for fields or parameters.

What is a compile-time constant?

A final variable of a primitive type or String, initialised with a constant expression, such as final int CHAI = 20;. javac substitutes its value wherever it's used.

Can two variables have the same name?

Not in the same scope. A local variable can have the same name as a field, which then “shadows” the field inside that method; you reach the field with this.name or ClassName.name.

Real-world scenario questions (asked in company interviews)

Variable mistakes cause some of the most expensive bugs in production. Decide your answer first, then open the model answer.

E-commerce · production incident1–3 years

Customers seeing each other's cart

In a web service, a developer stored the current customer's cart in a static List<Item> cart field “to make it easy to access from every method”. In testing, with one user, it worked. In production, customers started seeing items added by other customers. Why?

The interviewer is checking: do you understand that a static variable is one shared copy for everyone?

Show a strong answer

A static field has exactly one copy for the whole application. A web server handles many customers at the same time on different threads, and all of them read and write that same list. So one customer's items appear in another's cart. It's also a privacy problem.

  • Per-customer data must not be static. Keep it in a local variable or an object created per request or per session, or in the database.
  • Use static only for truly shared things such as constants or carefully designed, thread-safe shared resources.
  • Add a test that simulates two users at once.

Avoid saying: “Add synchronized.” That only stops corruption; everyone would still share one cart.

Retail billing · code reviewFresher

The number 18 appears 40 times

You're reviewing a billing module where the GST rate 18 is typed directly into 40 different calculations. The government changes the rate for one product category, and the team must update the code tonight. What would you suggest, now and for the future?

The interviewer is checking: do you know why “magic numbers” are risky, and how named constants or configuration help?

Show a strong answer
  • Replace the literal with a named constant, for example static final int STANDARD_GST_RATE = 18;, so the meaning is clear and the value lives in one place.
  • Because rates differ by category and change over time, they really belong in configuration or a database table, not in code at all.
  • Search carefully: not every 18 in the code is a GST rate (it might be an age limit). That's exactly why bare numbers are dangerous.
  • Add tests for bill totals so the change can be verified quickly.

Avoid: a blind find-and-replace of “18” across the project.

Fintech · bug fixFresher

The discount that disappeared

A method calculates a final price. Inside an if block for festival offers, someone wrote int price = basePrice - discount;, and after the block the method returns price, which still holds the undiscounted value. There's no error. What's happening?

The interviewer is checking: do you understand scope and how declaring a variable a second time creates a new box?

Show a strong answer

The method already had a variable price. Writing int price = … inside the block declares a new variable rather than updating the existing one. (In Java, a local inside a nested block can't reuse the name of another local in the same method, so the outer one is most likely a field. The new local shadows it.) The discounted value lives in the inner box and disappears at the closing brace.

  • Fix: assign instead of declaring: price = basePrice - discount;
  • Prefer clear names and small methods, and turn on IDE warnings for shadowed variables.
  • Add a unit test for the festival case.

Avoid: adding print statements randomly without first checking where each variable is declared.

Any company · code reviewFresher

“What does d mean?”

Your code has variables named d, temp2, flag and x1. It works, but the reviewer leaves comments on each one asking what they mean. A friend says reviewers are being fussy. How do you respond?

The interviewer is checking: do you value readable code, and can you accept review feedback professionally?

Show a strong answer

The reviewer is right. Code is read many more times than it's written, often by someone else months later.

  • Rename to say what the value is: daysSinceLastLogin, retryCount, isPaymentVerified.
  • Booleans read best as questions: isActive, hasDiscount.
  • Use the IDE's Rename refactoring so every usage updates safely.
  • Reply to the review with thanks and push the update. Good naming often removes the need for comments.

Avoid saying: “It works, so names don't matter.”
