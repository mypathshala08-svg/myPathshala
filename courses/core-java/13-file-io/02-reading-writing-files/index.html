Reading and writing files

In Lesson 13.1 you opened streams by hand. For everyday jobs (save a list, append an order, read a CSV, move a report) Java gives you one-line helpers in java.nio.file.Files, driven by Path objects. You'll learn to create, write, append, read, copy, move and delete files and folders, understand where relative paths point, and handle the errors files bring.

2 Definition

What are Path and Files?

Formal definition (write this in exams)

java.nio.file.Path is an object that represents the location of a file or directory in the file system as a sequence of names; it may be absolute (from the root) or relative (resolved against the current working directory), and creating a Path does not access the disk. java.nio.file.Files is a utility class of static methods that operate on paths: creating, reading, writing, copying, moving and deleting files and directories and querying their attributes. Its methods open and close the required streams internally, use UTF-8 for text by default, and report failures by throwing IOException subclasses such as NoSuchFileException and FileAlreadyExistsException. The older java.io.File class serves a similar purpose.

In simple words

A Path is an address written on an envelope. Files is the postman who actually goes there to drop off, pick up, copy or remove things.

Words you'll meet in this lesson

Don't trust relative paths in servers and IDEs. “data/orders.csv” goes wherever the program was started: the project root in an IDE, some other folder on a server. For important files, build the path from a configured base folder: Path.of(config.dataDir(), "orders.csv").

4 Step by step

What happens when you call Files.writeString

  1. Resolve the path

    Files.writeString(Path.of("data", "orders.csv"), "101,dosa,80\n");
    The relative path is joined to the working directory, e.g. /home/riya/app/data/orders.csv.

  2. Open with options

    With no options it opens with CREATE + TRUNCATE_EXISTING + WRITE: create the file if missing, empty it if present. If the folder data doesn't exist, you get NoSuchFileException, so create folders first.

  3. Encode and write

    The text is encoded as UTF-8 and written through a byte stream, as in Lesson 13.1.

  4. Close

    The method closes the stream before returning, so the data is handed to the OS and the file handle is released. There is nothing for you to forget.

  5. Or append

    Files.writeString(p, "102,idli,40\n", StandardOpenOption.APPEND);
    APPEND moves the write position to the end; existing bytes are kept. (Add CREATE too if the file might not exist yet.)
5 See it happen

From Path to file and back: both views

Left: the folder and file as you'd see them in a file manager. Right: the Path and List objects on the heap, and the file as the operating system holds it.

Paths and files, both views 6 steps
What you see
  1. Path.of("data", "orders.csv") builds a path: the file's name and location. Nothing on disk changes.
  2. Files.createDirectories makes the folder (and any missing parents). No error if it already exists.
  3. Files.writeString creates the file, writes the text in UTF-8 and closes it, all in one call. An existing file would be replaced.
  4. With StandardOpenOption.APPEND, the new text goes at the end instead.
  5. Files.readAllLines reads the whole file and returns a List<String>, one element per line, without the line breaks.
  6. Files.delete removes the file. Your Path object still exists: it is only a name.
Behind the screen
  1. The Path is a small object on the heap holding a relative path. Relative paths are resolved against the program's working directory, here /home/riya/app.
  2. The OS creates the data folder. The JVM itself stores nothing about it.
  3. writeString opens a stream, encodes the text as UTF-8, writes 12 bytes and closes the stream: the stream code from Lesson 13.1, already written for you.
  4. Appending adds 12 more bytes; the file is now 24 bytes long.
  5. readAllLines reads all bytes, decodes them and splits on line breaks. Each line becomes a String in a new ArrayList. For a huge file this would fill memory, so you'd read it line by line instead (Lesson 13.3).
  6. After delete, the OS no longer has the file. The Path object is unchanged; Files.exists(p) would now return false.
6 Real-world use

Files in real systems

Even apps backed by databases read and write plenty of files: imports, exports, configs, logs and archives.

Watch it with an example: a canteen's daily sales file

Every order is appended to one CSV file per day. At closing time the owner's report reads the file and adds up the sales.

Append all day, read at night 5 steps
Animated example
  1. At 9:10 a dosa is sold. The app appends one line, time,item,amount, to today's file.
  2. Each new order adds one line at the end. Earlier lines are never rewritten, so a crash can't lose the morning's orders.
  3. By evening the file has three lines. Opening it in a spreadsheet already works: CSV is just text.
  4. At closing, the report reads all lines and takes the third field of each, the amount.
  5. It prints the day's total. One file per day keeps files small and easy to archive. (Real shops would also keep this in a database.)

1. Imports and exports

Banks import salary CSVs from companies; shops export GST and sales reports for accountants.

salary.csv→Files.readAllLines→credit 500 accounts

2. Configuration

Apps read settings (database URL, tax rates, feature flags) from files at startup.

app.properties→Files.newBufferedReader→settings

3. Archiving and cleanup

Nightly jobs move old reports into dated folders and delete temporary files older than 30 days.

reports/→Files.move→archive/2026-09/

4. Uploaded documents

KYC PDFs and invoices are saved to a storage folder under a safe generated name, never the name the user sent.

upload→Files.copy(in, dir.resolve(id))→stored

Simplified. Large companies often store such files in cloud object storage, but the read-write-move ideas are the same.

7 Run the code

Create, append, read, delete

import java.io.IOException;
import java.nio.file.*;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Path file = Path.of("data", "orders.csv");
        Files.createDirectories(file.getParent());
        Files.writeString(file, "101,dosa,80\n");
        Files.writeString(file, "102,idli,40\n", StandardOpenOption.APPEND);
        List<String> lines = Files.readAllLines(file);
        System.out.println(lines.size() + " lines: " + lines);
        System.out.println("size " + Files.size(file) + " bytes");
        Files.delete(file);
        System.out.println("exists after delete: " + Files.exists(file));
    }
}
2 lines: [101,dosa,80, 102,idli,40] size 24 bytes exists after delete: false
  • Path.of("data", "orders.csv")Builds data/orders.csv with the right separator for the OS.
  • Files.createDirectories(file.getParent())Make sure the folder exists before writing into it.
  • StandardOpenOption.APPENDAdd to the end; without it the file is replaced.
  • Files.delete(file)Throws if the file is missing; deleteIfExists returns false instead.

9 Quiz and revision

Check yourself

Quick revision

Lesson 13.2 in one screen

  • Path names a file; creating one doesn't touch the disk. Files does the work.
  • Relative paths resolve against the working directory (user.dir).
  • writeString/write create or replace; add APPEND to add at the end.
  • readString, readAllLines: whole file into memory, UTF-8 by default.
  • createDirectories before writing into a new folder.
  • copy/move refuse to overwrite unless REPLACE_EXISTING.
  • Errors: NoSuchFileException, FileAlreadyExistsException, all IOException.

Interview and viva questions

What is the difference between File and Path?

Both represent file locations. java.io.File is the original API: many methods return booleans without saying why they failed, and copy/move aren't built in. java.nio.file.Path (Java 7) works with the Files utility class, which offers rich operations, specific exceptions, symbolic-link handling and better performance. New code should use Path and Files.

How do you append to a file in Java?

Files.writeString(path, text, StandardOpenOption.CREATE, StandardOpenOption.APPEND), or new FileWriter(file, true) / new FileOutputStream(file, true).

What is the difference between an absolute and a relative path?

An absolute path starts from the file-system root and always points to the same place. A relative path is resolved against the current working directory, so the same relative path can point to different files depending on where the program was started.

When should you not use Files.readAllLines?

For large files, because it loads every line into memory at once. Read line by line with BufferedReader.readLine() or process Files.lines(path) as a stream, which reads lazily.

How do you safely overwrite a file?

Write the new content to a temporary file in the same folder, then Files.move(tmp, target, REPLACE_EXISTING, ATOMIC_MOVE). Readers then see either the old file or the new one, never a half-written file.

P4Medium

Count words in a file

Write a two-line review to review.txt, then count its lines and words.

Input
two lines of text
Expected output
2 lines, 8 words
Show solution and explanation 
import java.io.IOException;
import java.nio.file.*;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Path p = Path.of("review.txt");
        Files.writeString(p, "Great dosa and fast service\nWill come again\n");
        List<String> lines = Files.readAllLines(p);
        int words = 0;
        for (String line : lines) {
            words += line.trim().split("\\s+").length;
        }
        System.out.println(lines.size() + " lines, " + words + " words");
    }
}
2 lines, 8 words

How it works: split("\\s+") splits on any run of spaces. This is the basis of text analytics: read lines, split, count.

P5Medium

Sum numbers with Scanner

Write the numbers 120 45 300 15 to amounts.txt, then read them with new Scanner(file) and print the sum.

Input
120 45 300 15
Expected output
sum = 480
Show solution and explanation 
import java.io.*;
import java.nio.file.*;
import java.util.Scanner;

public class Main {
    public static void main(String[] args) throws IOException {
        Files.writeString(Path.of("amounts.txt"), "120 45\n300 15\n");
        int sum = 0;
        try (Scanner sc = new Scanner(new File("amounts.txt"))) {
            while (sc.hasNextInt()) {
                sum += sc.nextInt();
            }
        }
        System.out.println("sum = " + sum);
    }
}
sum = 480

How it works: a Scanner on a File reads tokens (here ints) across lines, exactly like reading from the keyboard. Close it, as it holds the file open.

P6Medium

Formatted report with PrintWriter

Write a small aligned price table to menu.txt with PrintWriter.printf, then print the file.

Input
dosa 80, thali 120, chai 15
Expected output
dosa     Rs   80
thali    Rs  120
chai     Rs   15
Show solution and explanation 
import java.io.*;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) throws IOException {
        String[] items = {"dosa", "thali", "chai"};
        int[] prices = {80, 120, 15};
        try (PrintWriter pw = new PrintWriter("menu.txt")) {
            for (int i = 0; i < items.length; i++) {
                pw.printf("%-8s Rs %4d%n", items[i], prices[i]);
            }
        }
        System.out.print(Files.readString(Path.of("menu.txt")));
    }
}
dosa Rs 80 thali Rs 120 chai Rs 15

How it works: PrintWriter gives you println and printf on a file. %-8s left-aligns in 8 columns; %4d right-aligns numbers. PrintWriter never throws IOException on write; call checkError() if you need to know.

P7Business problem

Attendance from a CSV

attendance.csv has name,status lines (P or A). Count present and absent students and list the absentees.

Input
5 students
Expected output
present 3, absent 2: [Ravi, Joseph]
Show solution and explanation 
import java.io.IOException;
import java.nio.file.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        Path p = Path.of("attendance.csv");
        Files.write(p, List.of("Asha,P", "Ravi,A", "Meena,P", "Imran,P", "Joseph,A"));
        int present = 0;
        List<String> absent = new ArrayList<>();
        for (String line : Files.readAllLines(p)) {
            String[] f = line.split(",");
            if (f[1].equals("P")) present++;
            else absent.add(f[0]);
        }
        System.out.println("present " + present + ", absent " + absent.size() + ": " + absent);
    }
}
present 3, absent 2: [Ravi, Joseph]

How it works: CSV is the most common data-exchange format in offices. Reading lines and splitting on commas is enough for simple files; real CSVs with quoted commas need a CSV library.

P8Business problem

Low-stock alert

inventory.csv has item,qty. Write a new file reorder.txt listing items with quantity below 10, then print it.

Input
rice 40, oil 6, sugar 9, salt 25
Expected output
oil (only 6 left)
sugar (only 9 left)
Show solution and explanation 
import java.io.IOException;
import java.nio.file.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        Files.write(Path.of("inventory.csv"), List.of("rice,40", "oil,6", "sugar,9", "salt,25"));
        List<String> reorder = new ArrayList<>();
        for (String line : Files.readAllLines(Path.of("inventory.csv"))) {
            String[] f = line.split(",");
            if (Integer.parseInt(f[1]) < 10) reorder.add(f[0] + " (only " + f[1] + " left)");
        }
        Files.write(Path.of("reorder.txt"), reorder);
        System.out.print(Files.readString(Path.of("reorder.txt")));
    }
}
oil (only 6 left) sugar (only 9 left)

How it works: read one file, filter, write another: the shape of most batch jobs. The output file can be emailed to the supplier or loaded by another system.

P9Business problem

Daily backup that may already exist

Copy ledger.txt to ledger-backup.txt. Copying again fails because the backup exists; catch that, then copy with REPLACE_EXISTING.

Input
ledger.txt
Expected output
backup exists: ledger-backup.txt
backup now 32 bytes, ledger 32 bytes
Show solution and explanation 
import java.io.IOException;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) throws IOException {
        Path ledger = Path.of("ledger.txt"), backup = Path.of("ledger-backup.txt");
        Files.writeString(ledger, "opening balance 50000\n");
        Files.copy(ledger, backup);
        Files.writeString(ledger, "sale 1200\n", StandardOpenOption.APPEND);
        try {
            Files.copy(ledger, backup);
        } catch (FileAlreadyExistsException e) {
            System.out.println("backup exists: " + e.getFile());
        }
        Files.copy(ledger, backup, StandardCopyOption.REPLACE_EXISTING);
        System.out.println("backup now " + Files.size(backup) + " bytes, ledger " + Files.size(ledger) + " bytes");
    }
}
backup exists: ledger-backup.txt backup now 32 bytes, ledger 32 bytes

How it works: NIO refuses to overwrite by accident: Files.copy throws FileAlreadyExistsException unless you pass REPLACE_EXISTING. Making overwrites explicit prevents losing data.

Real-world scenario questions (asked in company interviews)

File-handling bugs tend to appear only in production, where paths, permissions and sizes differ from your laptop.

Deployment · pathsFresher

Works in the IDE, NoSuchFileException on the server

A report job reads Path.of("config/tax-rates.csv"). It works in IntelliJ, but on the server it fails with NoSuchFileException although the file is deployed in /opt/app/config. Why?

The interviewer is checking: relative paths and the working directory.

Show a strong answer
  • The path is relative; on the server the process starts from a different working directory (e.g. / or the service user's home).
  • Log Path.toAbsolutePath() to confirm, then build paths from a configured base directory (environment variable or config) or load bundled files from the classpath.

Avoid: hard-coding C:\Users\me\... paths.

Batch · memoryJunior

Import job crashes on month-end files

A transaction import uses Files.readAllLines. It works daily, but the month-end file (8 GB) crashes the job with OutOfMemoryError. How would you change it?

The interviewer is checking: streaming large files.

Show a strong answer
  • Read line by line with Files.newBufferedReader or Files.lines (closed in try-with-resources), processing and discarding each line.
  • Write results in batches; keep only running totals in memory.
  • Track the last processed line so a failed run can resume.

Avoid: just raising -Xmx; next month's file will be bigger.

Reliability · crashMid

Half-written settings file after a power cut

A POS terminal saves its settings with Files.writeString(settings, json). After a power cut, the file is half-written and the terminal won't start. How do you make saving safe?

The interviewer is checking: atomic replace.

Show a strong answer
  • Write to settings.json.tmp in the same folder, then Files.move(tmp, settings, REPLACE_EXISTING, ATOMIC_MOVE). The rename is atomic, so the file is always complete.
  • Keep the previous version as a backup and validate on startup, falling back if parsing fails.

Avoid: deleting the old file before writing the new one.

Security · uploadsMid

A filename that escaped the uploads folder

An upload API saves files with uploads.resolve(userGivenName). A tester uploads a file named ../../app/config.properties and overwrites the app's config. Explain and fix.

The interviewer is checking: path traversal.

Show a strong answer
  • .. segments let the resolved path climb out of the uploads folder: a path traversal attack.
  • Never use client file names as paths. Generate an ID (e.g. a UUID) for the stored name and keep the original name as metadata.
  • If you must use it, normalize() the result and check target.startsWith(uploads); also never pass REPLACE_EXISTING for uploads.

Avoid: only stripping the text “../”; there are many encodings of the same trick.
