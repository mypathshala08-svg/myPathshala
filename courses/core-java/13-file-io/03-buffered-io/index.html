BufferedReader and BufferedWriter

Reading or writing a file one character at a time works, but it's painfully slow, because every call goes all the way to the operating system. Buffered streams collect data in memory and move it in big blocks. You'll measure the difference, learn the readLine() loop you'll use for the rest of your career, and learn why forgetting close() silently loses data.

Module 13 · File Handling and I/O⏱ 22 minIntermediate9 practice problems
1 The story

The export that took four minutes

The canteen now has a year of orders: about 2 lakh lines. Riya's export writes them straight to a FileOutputStream, a few bytes at a time. It takes minutes. Worse, one night the last few hundred orders are simply missing from the file.

Riya

Sir, why is writing a file so slow? My laptop has an SSD!

Arjun Sir

The disk isn't the slow part. Every little write is a request to the operating system, and you're making two lakh of them. Put a buffer in between: collect 8 KB in memory, then send it in one go.

Riya

And the missing orders at the end?

Arjun Sir

Those were still sitting in a buffer when your program stopped. A buffer must be flushed, and close() does that. Let's see both.

2 Definition

What is buffered I/O?

Formal definition (write this in exams)

Buffered I/O places an in-memory array (a buffer) between a program and an underlying stream, so that many small read or write operations are served from or collected in memory and transferred to the underlying stream in large blocks, reducing costly system calls. In Java, BufferedReader and BufferedWriter wrap any Reader or Writer (default buffer 8,192 characters), and BufferedInputStream and BufferedOutputStream wrap byte streams. BufferedReader.readLine() returns the next line without its terminator, or null at end of stream. Output buffers are written when full, on flush(), or on close().

In simple words

Don't run to the post office with every letter. Fill a bag, then go once. But remember to actually take the bag before you leave.

Words you'll meet in this lesson

BufferAn array in memory where data waits before moving on.
System callA request from your program to the OS (read, write). Relatively expensive.
flush()Send whatever is in the buffer now, without closing.
close()Flush, then release the file. Closing the outer stream closes the inner ones.
readLine()Next line of text without the line break; null at the end.
DecoratorAn object that wraps another of the same type to add a feature.

Exam tip: “Buffered streams improve performance by reducing the number of I/O operations. readLine() returns null at end of file. Always close() (or flush()) a buffered writer, or buffered data may be lost.” Also name the pattern: wrapping streams is the decorator design pattern.

The data that wasn't there

import java.io.*;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedWriter w = new BufferedWriter(new FileWriter("invoice.txt"));
        w.write("INV-501 Rs 2360");
        System.out.println("on disk now: " + Files.size(Path.of("invoice.txt")) + " bytes");
        w.close();
        System.out.println("after close: " + Files.size(Path.of("invoice.txt")) + " bytes");
    }
}
on disk now: 0 bytes after close: 15 bytes

Unclosed buffered writers lose data. Nothing is wrong with the code until the very end: the text sits in memory and the file stays empty. If the program crashes or exits first, it's gone. Use try-with-resources every time, and call flush() if another program must see the data before you close.

4 Step by step

Inside the readLine() loop

  1. Wrap the reader

    try (BufferedReader br = Files.newBufferedReader(Path.of("orders.txt"))) {
    A decoder reader on the file, wrapped by a BufferedReader with an empty char[8192].

  2. First readLine(): fill

        String line;
    while ((line = br.readLine()) != null) {
    The buffer is empty, so the reader asks the file for up to 8,192 characters in one call.

  3. Cut out one line

    It scans forward from pos to the next \n (or \r\n), creates a String from those characters, and moves pos past the line break.

  4. Next calls: from memory

    Following lines come straight from the array until it runs out; then one more big read refills it.

  5. End

    When the file has no more data, readLine() returns null, the loop ends, and try-with-resources closes the reader and the file.
5 See it happen

Buffers on the way out and on the way in

Left: writing with and without a buffer. Right: a BufferedReader on the heap, filling its array once and serving lines from it.

Why buffering is fast, both views 6 steps
What you see
  1. A plain FileOutputStream passes every write straight to the operating system.
  2. Each call is a system call: the program switches to the OS kernel and back. Doing that thousands of times for tiny pieces is slow.
  3. A BufferedWriter keeps an array (8,192 characters) in memory. write just copies into it: no OS call.
  4. More writes, still in memory. This is extremely fast.
  5. When the buffer is full, or when you call flush(), the whole chunk goes down in one call.
  6. close() flushes whatever is left, then closes the file. Forget it and the last part of your data never reaches the disk.
Behind the screen
  1. new BufferedReader(new FileReader("orders.txt")): two objects. The BufferedReader holds a reference to the FileReader and an empty char[8192].
  2. The first readLine() asks the FileReader for up to 8,192 characters at once. This small file fits completely.
  3. readLine() finds the first line break in the array, returns the characters before it as a new String, and moves pos forward.
  4. The second line comes from the same array: no disk access at all.
  5. Same for the third. One read from the file served three lines.
  6. At the end of the data, readLine() returns null. That's the loop condition: while ((line = br.readLine()) != null).
6 Real-world use

Buffered I/O in real systems

Practically every file and network stream in production Java code is buffered.

Watch it with an example: a bank's nightly statement file

A bank writes 2 lakh transaction lines every night. Without a buffer, each line is a separate trip to the disk; with one, lines are sent in big blocks.

2,00,000 lines, buffered vs unbuffered 5 steps
Animated example
  1. Each night the bank writes one line per transaction: date, account, amount. About 2 lakh lines, 5 MB.
  2. Written straight to a FileOutputStream with no buffer, every line is its own write call to the OS. Buffered, lines collect in an 8 KB array, so one call carries about 300 lines.
  3. The unbuffered job keeps switching into the OS kernel; the buffered one is mostly copying characters in memory.
  4. The file contents are identical. Only the number of trips differs: 2 lakh vs about 600. (Counts are approximate; the exact number depends on line lengths.)
  5. That's why production code always wraps file streams in buffers, or uses Files.newBufferedWriter, which does it for you.

Support teams scan gigabytes of logs for errors, reading line by line so memory stays tiny.

Statements, GST returns and data dumps with lakhs of lines are written through BufferedWriter.

7 Run the code

Write a menu, read it line by line

import java.io.*;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) throws IOException {
        try (BufferedWriter w = Files.newBufferedWriter(Path.of("menu.txt"))) {
            w.write("Masala Dosa,80");
            w.newLine();
            w.write("Idli Sambar,50");
            w.newLine();
            w.write("Filter Coffee,25");
            w.newLine();
        }
        try (BufferedReader r = Files.newBufferedReader(Path.of("menu.txt"))) {
            String line;
            while ((line = r.readLine()) != null) {
                String[] f = line.split(",");
                System.out.printf("%-14s Rs %3s%n", f[0], f[1]);
            }
        }
    }
}
Masala Dosa Rs 80 Idli Sambar Rs 50 Filter Coffee Rs 25
  • Files.newBufferedWriter(Path.of("menu.txt"))Buffered, UTF-8, creates or replaces the file.
  • w.newLine()Writes the line separator for the current OS.
  • (line = r.readLine()) != nullRead and test in one step; stops at end of file.
  • printf("%-14s Rs %3s%n", …)Aligned columns: name left-aligned in 14 characters, price right-aligned in 3.

9 Quiz and revision

Check yourself

Quick revision

Lesson 13.3 in one screen

  • A buffer collects data in memory so the OS is called once per block, not once per character.
  • Wrap: new BufferedReader(reader), new BufferedWriter(writer), or use Files.newBufferedReader/Writer.
  • Loop: while ((line = br.readLine()) != null); lines come without the line break.
  • newLine() writes the platform separator.
  • Buffered output is only on disk after flush() or close(); use try-with-resources.
  • Closing the outer wrapper closes the inner streams too.
  • Process big files line by line: memory stays constant.

Interview and viva questions

Why is BufferedReader faster than FileReader?

Every FileReader.read() call goes through the charset decoder and its locking for a single character. BufferedReader pulls 8,192 characters at once into its own array and serves later reads with plain array access. With raw byte streams such as FileInputStream, where each read() is a system call, the difference is even larger. BufferedReader also adds readLine().

What is the difference between flush() and close()?

flush() writes out buffered data but keeps the stream open for more writes. close() flushes and then releases the stream and its underlying resources; the stream can't be used afterwards.

BufferedReader vs Scanner?

BufferedReader reads lines of text quickly with a large buffer and does no parsing. Scanner parses tokens (ints, words) with regular expressions, which is convenient but slower, and has a smaller buffer. For large inputs, read lines with BufferedReader and parse them yourself.

What design pattern do Java I/O wrappers use?

The decorator pattern: a BufferedReader is a Reader and wraps a Reader, adding buffering without changing the interface. You can stack decorators, e.g. a BufferedReader over an InputStreamReader over a FileInputStream.

When must you call flush() explicitly?

When someone else must see the data before you close: e.g. sending a message over a socket and waiting for a reply, or writing a progress file that another program monitors. Otherwise, closing (via try-with-resources) is enough.

P1Easy

Read every line

Write three city names to cities.txt, then print each line with its number using BufferedReader.

Input
Pune, Nagpur, Nashik
Expected output
1: Pune
2: Nagpur
3: Nashik
Show solution and explanation 
import java.io.*;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) throws IOException {
        Files.writeString(Path.of("cities.txt"), "Pune\nNagpur\nNashik\n");
        try (BufferedReader br = new BufferedReader(new FileReader("cities.txt"))) {
            String line;
            int n = 1;
            while ((line = br.readLine()) != null) {
                System.out.println(n++ + ": " + line);
            }
        }
    }
}
1: Pune 2: Nagpur 3: Nashik

How it works: the assignment inside the condition reads a line and checks it for null in one go. This loop shape is worth memorising.

import java.io.*;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedWriter bw = new BufferedWriter(new FileWriter("draft.txt"));
        bw.write("hello");

P4Medium

Longest line

Find the longest line in a file of product names and print it with its length.

Input
4 product names
Expected output
Basmati Rice 5kg (16 chars)
Show solution and explanation 
import java.io.*;
import java.nio.file.*;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Files.write(Path.of("products.txt"), List.of("Tea", "Basmati Rice 5kg", "Sugar", "Sunflower Oil 1L"));
        String longest = "";
        try (BufferedReader br = Files.newBufferedReader(Path.of("products.txt"))) {
            String line;
            while ((line = br.readLine()) != null) {
                if (line.length() > longest.length()) longest = line;
            }
        }
        System.out.println(longest + " (" + longest.length() + " chars)");
    }
}
Basmati Rice 5kg (16 chars)

How it works: only the current line and the best so far are kept, so this works for files of any size.

P6Medium

Copy a text file line by line

Copy menu.txt to menu-copy.txt using a BufferedReader and BufferedWriter, converting each line to upper case.

Input
3 dishes
Expected output
[MASALA DOSA, IDLI SAMBAR, FILTER COFFEE]
Show solution and explanation 
import java.io.*;
import java.nio.file.*;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Files.write(Path.of("menu.txt"), List.of("masala dosa", "idli sambar", "filter coffee"));
        try (BufferedReader in = Files.newBufferedReader(Path.of("menu.txt"));
             BufferedWriter out = Files.newBufferedWriter(Path.of("menu-copy.txt"))) {
            String line;

    }
}
[MASALA DOSA, IDLI SAMBAR, FILTER COFFEE]

How it works: resources in one try are closed in reverse order: the writer first (flushing it), then the reader.

P7Business problem

Bank statement summary

statement.csv has date,type,amount lines with type CR or DR. Read it with BufferedReader and print total credits, total debits and the closing balance from an opening balance of 10,000.

Input
5 transactions
Expected output
credits 28000, debits 10150, closing 27850
Show solution and explanation 
import java.io.*;
import java.nio.file.*;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Files.write(Path.of("statement.csv"), List.of(
            "01-10,CR,25000", "03-10,DR,1200", "07-10,DR,8500", "15-10,CR,3000", "20-10,DR,450"));
        long cr = 0, dr = 0;
        try (BufferedReader br = Files.newBufferedReader(Path.of("statement.csv"))) {
            String line;
            while ((line = br.readLine()) != null) {
                String[] f = line.split(",");
                long amt = Long.parseLong(f[2]);
                if (f[1].equals("CR")) cr += amt; else dr += amt;
            }
        }
        System.out.println("credits " + cr + ", debits " + dr + ", closing " + (10000 + cr - dr));
    }
}
credits 28000, debits 10150, closing 27850

How it works: streaming through the statement keeps memory use constant whether it has 5 lines or 5 million.

P8Business problem

Split a big order file by city

orders.csv has id,city,amount. Write Pune orders to pune.csv and all others to others.csv, then print the line counts.

Input
6 orders
Expected output
pune.csv: 3, others.csv: 3
Show solution and explanation 
import java.io.*;
import java.nio.file.*;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Files.write(Path.of("orders.csv"), List.of("1,Pune,450", "2,Mumbai,900", "3,Pune,120", "4,Nagpur,300", "5,Pune,75", "6,Mumbai,640"));
        try (BufferedReader in = Files.newBufferedReader(Path.of("orders.csv"));
             BufferedWriter pune = Files.newBufferedWriter(Path.of("pune.csv"));
             BufferedWriter rest = Files.newBufferedWriter(Path.of("others.csv"))) {

P9Business problem

Resume-safe batch: flush every 100 lines

A job writes 250 receipt lines. To limit loss on a crash, it calls flush() every 100 lines. Count the flushes, including the final close.

Input
250 receipts
Expected output
250 receipts, 3 flushes
Show solution and explanation 
import java.io.*;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) throws IOException {
        int flushes = 0;
        try (BufferedWriter w = Files.newBufferedWriter(Path.of("receipts.txt"))) {
            for (int i = 1; i <= 250; i++) {
                w.write("RCPT-" + i);
                w.newLine();
                if (i % 100 == 0) {
                    w.flush();
                    flushes++;
                }
            }
        }
        flushes++;
        System.out.println(Files.readAllLines(Path.of("receipts.txt")).size() + " receipts, " + flushes + " flushes");
    }
}
250 receipts, 3 flushes

How it works: flushing too often removes the benefit of buffering; never flushing risks losing everything since the start. Periodic flushes (or checkpoints) are the usual compromise in batch jobs.

Real-world scenario questions (asked in company interviews)

These come up whenever a role involves batch jobs, reports or integrations.

Batch · data lossFresher

The last 300 rows are missing

An export writes 50,000 rows with a BufferedWriter. The file always ends a few hundred rows short, and the last row is cut in half. The code calls System.exit(0) right after the loop. Explain.

The interviewer is checking: buffers and flushing.

Show a strong answer
  • The writer is never closed, so the final partly-filled buffer (up to 8 KB) never reaches the file; System.exit doesn't flush it.
  • Wrap the writer in try-with-resources (or close it in finally) before exiting.

Avoid: adding flush() after every row; that removes the benefit of buffering.

Performance · I/OJunior

A 10-minute report that should take seconds

Profiling shows a report spends 95% of its time inside FileOutputStream.write, called once per character. How do you fix it with minimal code change?

The interviewer is checking: recognising unbuffered I/O.

Show a strong answer
  • Each call is a system call. Wrap the stream: new BufferedOutputStream(new FileOutputStream(f)), or use Files.newBufferedWriter for text.
  • Optionally use a larger buffer (64 KB) for very large outputs, and write whole strings rather than single characters.

Avoid: rewriting the report in multiple threads first; the bottleneck is the call pattern.

Integration · socketsJunior

The partner server never answers

A client sends a request line to a payment partner over a socket with a BufferedWriter, then waits for the reply with readLine(). It hangs forever, though the partner says it never received anything. Why?

The interviewer is checking: when explicit flush is needed.

Show a strong answer
  • The request is still in the client's buffer; it's never sent because the writer wasn't flushed. Both sides wait for each other.
  • Call writer.flush() after writing a complete request, before reading the reply.
  • Also set read timeouts so a missing reply can't hang the client forever.

Avoid: closing the writer to force sending; closing the socket stream closes the connection.

Data · line endingsMid

Files from Windows have an extra character

A Linux job reads a CSV uploaded from a Windows machine with Files.readString, splits the text on "\n", then parses the last column of each row. It fails with NumberFormatException: For input string: "450\r". Why, and how should it read the file?

The interviewer is checking: line terminators and defensive parsing.

Show a strong answer
  • Windows ends lines with \r\n. Splitting on "\n" leaves the \r at the end of every row.
  • readLine() (and lines()) treat \n, \r and \r\n all as line ends and strip them, so use those instead of splitting by hand.
  • Read with readLine (or lines()), trim() fields before parsing, and watch for a UTF-8 BOM at the start of files from Excel.

Avoid: assuming every file uses your OS's line endings.
