JDK vs JRE vs JVM

“Install Java” can mean three different things: the JDK, the JRE or the JVM. Mixing them up is why javac sometimes “is not recognized”. In this lesson you'll see exactly what is inside each one, how they nest inside each other, and which one a developer, a server and a user actually need.

1 The story

“javac is not recognized”

Riya's cousin Kabir has just joined the course. His laptop already “has Java”: a banking app and a game installed it years ago. He types his first command and gets an error. He calls Riya, and Riya calls Arjun Sir.

Riya

Sir, Kabir's laptop says java -version works, but javac “is not recognized”. If Java is installed, why is the compiler missing?

Arjun Sir

Because what's on his laptop is only a runtime: enough to run Java programs, not to build them. Think of a restaurant. The JVM is the cook who follows recipes. The JRE is the cook plus a stocked kitchen. The JDK is that kitchen plus the tools to write and test new recipes.

Riya

So the game and the banking app only needed the cook and the kitchen. Kabir needs the full JDK because he's writing new recipes!

Arjun Sir

Exactly. Let's open each box and see what's inside.

2 Definition

What are the JDK, the JRE and the JVM?

Formal definition (write this in exams)

JVM (Java Virtual Machine) is an abstract machine that loads, verifies and executes Java bytecode and manages memory at run time. JRE (Java Runtime Environment) is the JVM plus the core class libraries and supporting files needed to run Java applications. JDK (Java Development Kit) is the JRE plus development tools such as the compiler (javac), jar, javadoc and the debugger, used to develop Java applications.

In simple words

The JVM runs bytecode. The JRE is the JVM with the ready-made library classes (like String and System) that every program uses. The JDK is everything in the JRE, plus the tools a programmer needs to write, compile and package programs. JDK = JRE + tools, and JRE = JVM + libraries.

Words you'll meet in this lesson

Class libraryThousands of ready-made classes (String, Math, ArrayList, LocalDate…) that ship with Java.
Class loaderThe part of the JVM that finds .class files and loads them into memory.
Execution engineThe part of the JVM that actually runs bytecode: the interpreter, the JIT compiler and the garbage collector.
HotSpotThe most widely used JVM implementation, the one inside OpenJDK and Oracle JDK.
JAVA_HOMEA setting that tells other programs (Maven, Kafka, IDEs) which JDK folder to use.
jlinkA JDK tool (Java 9+) that builds a small custom runtime containing only the modules your app needs.

Exam tip: all three are platform dependent: you download a different JDK for Windows, macOS and Linux. Only the bytecode (.class files) is platform independent. Also remember the nesting: JVM ⊂ JRE ⊂ JDK.

3 Types and ways to use it

Inside each box, and the different versions you'll meet

The three parts of the JVM

1. Class loader subsystem

Finds .class files, loads them, links them (including the bytecode verifier's safety check) and initialises them. Three built-in loaders: bootstrap, platform and application.

Loading

2. Runtime data areas

The JVM's memory: the heap (objects), a stack per thread (method calls), the method area (class information), plus PC registers and native method stacks.

Memory

3. Execution engine

The interpreter runs bytecode, the JIT compiler turns hot code into machine code, and the garbage collector frees unused objects.

Running

What the JRE adds, and what the JDK adds

LayerAddsExamples
JRECore class libraries and config filesjava.lang (String, Math, System), java.util (ArrayList, HashMap), java.time, java.net, java.sql
JDKDevelopment tools in the bin folderjavac compiler, java launcher, jar, javadoc, jdb debugger, jshell, javap, jdeps, jlink, jcmd, jconsole

Different JDK builds and JVM implementations

OpenJDK builds

The open-source Java source code is compiled and packaged by many vendors: Eclipse Temurin, Amazon Corretto, Microsoft Build of OpenJDK, Oracle OpenJDK and others. They behave the same for your code.

Free

Oracle JDK

Oracle's own build of the JDK, with Oracle's licence terms and paid support options. Companies check the licence before using it in production.

Check licence

Other JVMs

HotSpot is the standard JVM. Eclipse OpenJ9 focuses on lower memory use. GraalVM adds an advanced JIT and can compile Java ahead of time into a native program.

Same bytecode

Is there still a separate JRE? Oracle stopped shipping a stand-alone JRE download from Java 11 onwards. Today you either install the full JDK, use a vendor's JRE package (Eclipse Temurin still offers one), or build a small custom runtime with jlink. The idea of a JRE, “JVM + libraries”, is still exactly right.

4 Step by step

Look inside a real JDK on your computer

You don't need to take our word for it. Follow these steps on any computer that has a JDK (or skip to Part 7 to use the live editor).

  1. Check what you have

    java -version
javac -version
    openjdk version "21.0.12.1" 2026-08-18 OpenJDK Runtime Environment (build 21.0.12.1+1-1-24.04.4-Ubuntu) OpenJDK 64-Bit Server VM (build 21.0.12.1+1-1-24.04.4-Ubuntu, mixed mode, sharing) javac 21.0.12.1
    Look at the three lines: the version, the Runtime Environment (the JRE part) and the 64-Bit Server VM (the JVM, HotSpot). If javac -version fails, you have a runtime but not a JDK. This sample is from an Ubuntu build; your exact version numbers will differ.

  2. Find the JDK folder

    On Windows it's usually under C:\Program Files\Eclipse Adoptium\ or C:\Program Files\Java\. On Linux, try /usr/lib/jvm/. On macOS, run /usr/libexec/java_home.

    This folder is what JAVA_HOME should point to: the JDK's top folder, not its bin subfolder.

  3. Open the bin folder: these are the JDK tools

    You'll see programs such as java, javac, jar, javadoc, jdb, jshell, javap, jlink and jcmd.

    Only java is needed to run programs. Everything else is for developing. That's the difference between the JDK and the JRE. Interesting fact: javac is itself written in Java and runs on the JVM.

  4. Look at lib and jmods: the class libraries

    The lib folder holds a file called modules, which packs all the standard library classes. The jmods folder holds the same modules in a form jlink can use.

    When your program uses String or LocalDate, the JVM's class loader reads those classes from this modules file. This is the “library” half of the JRE.

  5. List the modules

    java --list-modules
    java.base@21.0.12.1 java.compiler@21.0.12.1 java.desktop@21.0.12.1 java.net.http@21.0.12.1 java.sql@21.0.12.1 …
    The JDK is split into modules. java.base (String, Object, collections…) is needed by every program. Modules starting with jdk., such as jdk.compiler (javac), are JDK-specific tools.
5 See it happen

From “not recognized” to a running program: both views

Follow Kabir as he fixes his setup. Left: what he sees. Right: which box (JVM, JRE or JDK) is doing the work.

Kabir gets a real JDK 6 steps
What you see
  1. Kabir's laptop can run Java (java -version works) but javac is not recognized. He only has a runtime.
  2. He installs JDK 21. Its folder has bin (tools), lib (libraries) and more. He sets JAVA_HOME and PATH.
  3. javac Main.java now works, and Main.class appears.
  4. java Main runs his program. It uses System and LocalDate, classes he never wrote.
  5. The bank's production server runs a finished app with only a runtime. It has no compiler, and doesn't need one.
  6. The rule: developers install the JDK, machines that only run apps need a runtime, and the JVM inside does the actual work.
Behind the screen
  1. His old install has only the JRE (JVM + libraries). There's no tools layer, so no javac exists anywhere on his PATH.
  2. The JDK wraps the JRE and adds the developer tools. JDK = JRE + tools, JRE = JVM + libraries.
  3. javac, a JDK tool, compiles the source. It is a Java program itself, so the JVM is running it.
  4. For java Main, the class loader loads Main from his folder and String/LocalDate from the JRE's libraries. The execution engine runs main.
  5. The server has only a runtime: the JVM plus the library modules the app needs, often built with jlink.
  6. The nesting to remember: JVM ⊂ JRE ⊂ JDK.
6 Real-world use

Who installs what in a real company

In a software team, different machines need different boxes. Here's how it usually looks.

Watch it with an example: Riya's chai-bill app goes to the shop

Riya builds the app on her laptop (JDK) and the chai shop only runs it (runtime only). See which part does which job.

Build on a JDK, run on a runtime 6 steps
Animated example
  1. Write: Riya types Bill.java on her laptop. Her laptop has the full JDK (tools + runtime).
  2. Compile: javac, a tool that comes only with the JDK, turns Bill.java into Bill.class (bytecode).
  3. Ship: she copies only Bill.class to the shop's PC. The shop doesn't need the source code.
  4. Run: the shop's PC has a Java runtime (JRE). Its JVM loads the class, checks the bytecode, and runs main.
  5. Same output: both computers print the same bill, because the same bytecode runs on any JVM.
  6. But: typing javac on the shop's PC fails. A runtime can run programs but has no compiler. Developers need the JDK; users only need a runtime.

1. Developer laptops: full JDK

Every developer installs a JDK, usually the same LTS version as production. IDEs like IntelliJ IDEA and VS Code use it to compile, run tests and debug.

Write code→JDK: javac + JVM→Run and debug

2. Build (CI) servers: JDK

When code is pushed to Git, a build server (GitHub Actions, Jenkins, GitLab CI) compiles it, runs the tests and packages a .jar. It needs the compiler, so it uses a JDK.

git push→CI: JDK compiles + tests→app.jar

3. Production containers: runtime only

The finished app runs in a container (Docker) built on a small runtime image, such as a JRE image or a custom jlink runtime. Smaller images start faster and have fewer tools an attacker could misuse.

app.jar→Runtime-only image→Live service

4. Big data tools: need JAVA_HOME

Apache Kafka, Hadoop and Spark run on the JVM. Before starting them, you install a JDK or JRE and set JAVA_HOME. Their start-up scripts use it to find the right java.

JAVA_HOME→kafka-server-start.sh finds java→Broker running

5. Android phones: no JVM at all

Android apps are written in Java or Kotlin and compiled with a JDK on the developer's machine, but the phone doesn't run a JVM. Build tools convert the bytecode into Android's own DEX format, which the Android Runtime (ART) runs.

Java code→javac → bytecode→DEX→ART on phone

6. Choosing a JVM for memory or speed

Most teams use HotSpot. Some, running many small services, choose Eclipse OpenJ9 for lower memory use, or GraalVM native images for very fast start-up. The bytecode stays the same; only the JVM changes.

Same app.jar→HotSpot / OpenJ9 / GraalVM→Different speed and memory

Examples are simplified to show where each box fits. Each company's exact setup varies.

7 Run the code

Ask the JVM about itself

Java can tell you which runtime and JVM it's running on, and which class loader loaded each class. The first three lines depend on the machine; the last two are the same everywhere.

public class Main {
    public static void main(String[] args) {
        // Which runtime and JVM is running this program?
        System.out.println("Java version: " + System.getProperty("java.version"));
        System.out.println("Vendor:       " + System.getProperty("java.vendor"));
        System.out.println("JVM:          " + System.getProperty("java.vm.name"));

        // Who loaded which class?
        System.out.println("Main loaded by:   " + Main.class.getClassLoader().getName());
        System.out.println("String loaded by: " + String.class.getClassLoader());
    }
}
Java version: 21.0.12 Vendor: Eclipse Adoptium JVM: OpenJDK 64-Bit Server VM Main loaded by: app String loaded by: null

Sample output from Eclipse Temurin 21. Your version and vendor will be whatever is installed.

  • System.getProperty("java.version")Asks the runtime for a built-in setting. java.vendor is who built your JDK, java.vm.name is the JVM.
  • Main.classAn object that describes the Main class itself. Every loaded class has one.
  • getClassLoader().getName()Your own classes are loaded by the application class loader, named app.
  • String.class.getClassLoader()Prints null! Core classes like String are loaded by the bootstrap loader, which is built into the JVM and isn't a Java object, so Java shows it as null.

9 Quiz and revision

Check yourself

Quick revision

Lesson 1.3 in one screen

  • JVM: runs bytecode. Parts: class loader subsystem, runtime data areas (heap, stacks, method area…), execution engine (interpreter, JIT, GC).
  • JRE = JVM + class libraries (java.lang, java.util, java.time…). Enough to run programs.
  • JDK = JRE + tools (javac, jar, javadoc, jdb, jshell, javap, jlink). Needed to develop.
  • Nesting: JVM ⊂ JRE ⊂ JDK. All three are platform dependent; bytecode is not.
  • Class loaders: bootstrap (core, shows as null), platform, application (“app”, your classes).
  • Since Java 11, Oracle ships no separate JRE; use a JDK, a vendor JRE, or a jlink runtime.
  • Developers and CI use a JDK; production usually uses a runtime-only image.

Interview and viva questions

What is the difference between JDK, JRE and JVM?

The JVM executes bytecode. The JRE is the JVM plus the class libraries, enough to run Java programs. The JDK is the JRE plus development tools such as javac, jar and the debugger, needed to write and compile programs. JVM ⊂ JRE ⊂ JDK.

Is the JVM a real machine?

No. It's a virtual machine: a program that behaves like a computer with its own instruction set (bytecode), memory areas and execution rules. The JVM specification describes how it must behave, and products such as HotSpot and OpenJ9 are implementations of it.

Can we run a Java program with only the JVM?

Not in practice. Every program uses library classes such as String and System, which come from the class libraries. So you need at least a runtime (JVM + libraries), which is what a JRE is.

What are the main memory areas of the JVM?

The heap (all objects, shared by threads), the stack (one per thread, holding a frame per method call), the method area (class information; in HotSpot this lives in Metaspace), the PC register (current instruction of each thread) and the native method stack. Module 8 covers them in depth.

Why does String.class.getClassLoader() return null?

Because String is loaded by the bootstrap class loader, which is part of the JVM itself and written in native code, not a Java object. Java represents it as null.

Real-world scenario questions (asked in company interviews)

These come straight from day-to-day work with JDKs and runtimes. Decide your answer first, then open the model answer.

Any company · onboardingFresher

New joiner: “java works but the build fails”

On your first day, you install JDK 21 and clone the team's project. java -version prints 17, the Maven build fails with “release version 21 not supported”, and IntelliJ seems fine. Your buddy asks you to sort it out before stand-up.

The interviewer is checking: do you understand that a machine can have several Java installs, and how PATH and JAVA_HOME choose between them?

Show a strong answer

The laptop already had an older Java 17 that comes first on the PATH, so the command line and Maven pick it up. IntelliJ works because it's configured with JDK 21 separately.

  1. Find which Java is being used: where java on Windows or which -a java on Linux and macOS.
  2. Set JAVA_HOME to the JDK 21 top folder, and put %JAVA_HOME%\bin (or $JAVA_HOME/bin) first in PATH.
  3. Open a new terminal and confirm both java -version and javac -version show 21, then check mvn -v, which prints the Java it uses.
  4. Optionally remove the old runtime if nothing else needs it.

Avoid: reinstalling JDK 21 again and again. The install was fine; the PATH order was the problem.

Product company · DevOps1–3 years

The Docker image is too big

Your service's Docker image is built FROM eclipse-temurin:21-jdk, copies the source code in, and compiles it inside the image. The security team flags the image as large and full of unused tools. How would you improve it?

The interviewer is checking: do you know that production needs a runtime, not a full JDK, and how to separate building from running?

Show a strong answer

Use a multi-stage build. The first stage uses the JDK image to compile and package the jar. The second stage starts from a runtime-only image, such as eclipse-temurin:21-jre or a custom jlink runtime, and copies in just the jar.

  • The final image has no compiler, debugger or source code: it's smaller, faster to pull, and gives an attacker fewer tools.
  • jdeps can list which modules the app needs, and jlink can build a runtime with only those modules.
  • Run the container as a non-root user too.

Avoid saying: “The JDK includes the JRE, so it's fine to ship the JDK.” It works, but it isn't good practice in production.

Data engineering · Kafka setupFresher

“JAVA_HOME is not set” while starting Kafka

You're setting up Apache Kafka on a Linux VM for a data pipeline. The start script fails with an error saying it can't find Java or that JAVA_HOME is not set. Your lead asks what's wrong.

The interviewer is checking: do you know that big data tools run on the JVM, and how they find Java?

Show a strong answer

Kafka is a JVM application, so its scripts need to find a java program, through JAVA_HOME or the PATH.

  1. Check whether Java is installed: java -version. If not, install a supported JDK or JRE version for that Kafka release.
  2. Find the install folder (for example /usr/lib/jvm/java-21-openjdk-amd64) and set export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64. Point it at the top folder, not bin.
  3. Make it permanent in the service's environment file or the user's profile, so it survives a restart.
  4. Start Kafka again and check the logs.

Avoid: setting JAVA_HOME to …/bin/java. Scripts add /bin/java themselves, so the path breaks.

Fintech · cloud deployment1–3 years

The container keeps getting killed

A Java service runs in a Kubernetes container with a 1 GB memory limit. Someone set -Xmx2g “for safety”. Under load, the container is killed with an out-of-memory status, but no Java OutOfMemoryError appears in the logs. What's happening?

The interviewer is checking: do you know which part manages memory (the JVM), and how it fits inside the container's limit?

Show a strong answer

The JVM was told its heap may grow to 2 GB, but the container only allows 1 GB in total. When the JVM's memory use crosses 1 GB, the operating system kills the whole process before the JVM itself runs out, so Java never throws OutOfMemoryError.

  • Remove -Xmx2g. Modern JVMs are container-aware and size the heap from the container limit (by default, a quarter of it).
  • Or set -XX:MaxRAMPercentage (for example 70–75) so the heap leaves room for the JVM's other memory: thread stacks, Metaspace and native buffers.
  • Then monitor real memory use and raise the container limit if the app genuinely needs more.

Avoid: making the heap bigger than the container. Total JVM memory is always more than just the heap.
