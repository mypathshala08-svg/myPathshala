Lambda expressions

Java 8 changed how Java code looks. Instead of writing a whole class just to pass one small piece of behaviour (“compare by price”, “keep only items under ₹500”), you write a lambda expression: a short, anonymous function. You'll learn the syntax, what a lambda can and can't use from around it, how the JVM actually runs one, and the list methods that make lambdas useful from day one.

2 Definition

What is a lambda expression?

Formal definition (write this in exams)

A lambda expression is an anonymous function, written as a parameter list, the arrow token -> and a body (a single expression or a block), that provides the implementation of the single abstract method of a functional interface. Its parameter and return types are inferred from the target functional interface type. A lambda may use local variables of the enclosing scope only if they are final or effectively final; it does not introduce a new scope for this. At run time a lambda evaluates to an object that implements the functional interface; the JVM creates it through the invokedynamic instruction.

In simple words

A lambda is a small piece of code you can hand to a method: “here's how to compare”, “here's what to keep”. Java wraps it into an object automatically.

::

A lambda has no this of its own

public class Main {
    String name = "outer object";

    void demo() {
        Runnable lambda = () -> System.out.println("lambda sees: " + this.name);
        Runnable anon = new Runnable() {
            String name = "anonymous object";
            public void run() {
                System.out.println("anonymous sees: " + this.name);
            }
        };
        lambda.run();
        anon.run();
    }

    public static void main(String[] args) {
        new Main().demo();
    }
}
lambda sees: outer object anonymous sees: anonymous object

Captured variables must not change. A lambda stores a copy of each local variable it uses. If the variable could change afterwards, the copy would silently be wrong, so the compiler requires it to be effectively final. To count inside a lambda, use the list's size, a stream's count(), or an AtomicInteger.

4 Step by step

What happens at list.sort((a, b) -> a - b)

  1. The compiler finds the target type

    List.sort expects a Comparator<Integer>. Its one abstract method is int compare(Integer, Integer), so a and b are Integers and the body must give an int.

  2. The body becomes a hidden method

    javac moves a - b into a private static method like lambda$main$0(Integer a, Integer b) inside your class.

  3. invokedynamic makes an object

    At the lambda's position, an invokedynamic instruction asks the JVM (once) to generate a tiny class implementing Comparator, and returns an instance of it.

  4. sort calls the object

    sort calls compare(x, y) on that object whenever it needs to order two elements; the call is forwarded to lambda$main$0.

  5. Captured values travel with the object

    If the lambda uses a local variable (like budget), the generated object gets a field holding a copy of its value at the moment the lambda was created.
5 See it happen

From anonymous class to lambda: both views

Left: the code shrinking from an anonymous class to a one-liner. Right: what the compiler and JVM build so the lambda can run.

From anonymous class to lambda, both views 6 steps
What you see
  1. Before Java 8, passing behaviour meant writing an anonymous class: here a Comparator that compares two prices.
  2. Only one line, return a - b;, is the real logic. The rest (class, method name, types) is the same every time.
  3. A lambda keeps just the parameters, an arrow ->, and the body.
  4. The compiler already knows the list holds Integers, so it can infer the parameter types.
  5. When the body is a single expression, drop the braces and return: the value is returned automatically.
  6. sort calls the lambda each time it needs to compare two prices. The list ends up cheapest first.
Behind the screen
  1. javac compiles the lambda body into a hidden private static method of Main, named something like lambda$main$0. No separate .class file is written.
  2. Where the lambda appears, javac puts an invokedynamic instruction. The first time it runs, the JVM generates a small class that implements Comparator.
  3. invokedynamic returns an instance of that class (#1): the lambda is a real object on the heap.
  4. sort only knows it has a Comparator. It calls compare(450, 120), which forwards to lambda$main$0.
  5. Sorting calls compare once per comparison; the lambda object just forwards each call.
  6. A lambda that captures nothing has no state, so the JVM can hand out the same object every time that line runs. A lambda that captures a variable gets a field holding a copy of it.

7 Run the code

Sort, filter and print a menu

import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<String> dishes = new ArrayList<>(List.of("thali", "dosa", "chai", "biryani", "idli"));

        dishes.sort((a, b) -> a.compareTo(b));
        System.out.println("A-Z:        " + dishes);

        dishes.sort((a, b) -> b.length() - a.length());
        System.out.println("longest:    " + dishes);

        int maxLen = 4;
        dishes.removeIf(d -> d.length() > maxLen);
        System.out.println("short ones: " + dishes);

        dishes.forEach(d -> System.out.println("  - " + d));
    }
}
A-Z: [biryani, chai, dosa, idli, thali] longest: [biryani, thali, chai, dosa, idli] short ones: [chai, dosa, idli] - chai - dosa - idli
  • (a, b) -> a.compareTo(b)Alphabetical order: a Comparator lambda.
  • (a, b) -> b.length() - a.length()b before a: longest names first.
  • d -> d.length() > maxLenA Predicate lambda that captures maxLen.
  • d -> System.out.println(...)A Consumer lambda called for each element.

9 Quiz and revision

Check yourself

Quick revision

Lesson 14.1 in one screen

  • Lambda = anonymous function: (params) -> expression or (params) -> { statements }.
  • It implements the one abstract method of a functional interface; types are inferred.
  • One parameter: brackets optional. No parameters: (). Block body: use return.
  • Captured locals must be effectively final; the lambda keeps a copy.
  • this inside a lambda is the enclosing object.
  • Compiled to a private method + invokedynamic; at run time it's an object.
  • Useful list methods: sort, removeIf, replaceAll, forEach.

Interview and viva questions

What is a lambda expression and why was it added?

An anonymous function that implements a functional interface concisely. Added in Java 8 to make passing behaviour easy (callbacks, comparators, predicates), enabling the Stream API and a more functional style without verbose anonymous classes.

Why must captured variables be effectively final?

A lambda may run later, even on another thread, after the method has returned and its stack frame is gone. So it captures a copy of the value. If the variable could change, the copy and the variable would disagree; requiring effective finality prevents that confusion and race conditions.

Lambda vs anonymous class: what's different?

Lambdas only implement functional interfaces, have no state of their own, don't create a new this scope, and are compiled to a private method linked through invokedynamic rather than a separate class file. Anonymous classes can implement any interface or extend a class, have fields, and this refers to the anonymous object.

How does the JVM execute a lambda?

javac compiles the body into a private (often static) synthetic method and emits an invokedynamic call site. On first execution, the bootstrap method (LambdaMetafactory) generates a hidden class implementing the interface; subsequent executions reuse the linked call site. Non-capturing lambdas can reuse a single instance.

Can a lambda throw a checked exception?

Only if the functional interface's method declares it. Runnable.run() doesn't, so a Runnable lambda must catch checked exceptions itself; Callable.call() declares throws Exception, so a Callable lambda may throw.

P7Business problem

Leaderboard sort

Sort sales agents by deals closed (most first), and by name when tied. Print rank, name and deals.

Input
Ravi 12, Asha 15, Meena 12, Joseph 9
Expected output
1. Asha - 15
2. Meena - 12
3. Ravi - 12
4. Joseph - 9
Show solution and explanation 
import java.util.*;

public class Main {
    public static void main(String[] args) {
        String[] names = {"Ravi", "Asha", "Meena", "Joseph"};
        int[] deals = {12, 15, 12, 9};
        List<Integer> idx = new ArrayList<>(List.of(0, 1, 2, 3));
        idx.sort((a, b) -> deals[a] != deals[b] ? deals[b] - deals[a] : names[a].compareTo(names[b]));
        for (int r = 0; r < idx.size(); r++) {
            int i = idx.get(r);
            System.out.println((r + 1) + ". " + names[i] + " - " + deals[i]);
        }
    }
}
1. Asha - 15 2. Meena - 12 3. Ravi - 12 4. Joseph - 9

How it works: sorting a list of indexes lets you sort parallel arrays together. The lambda reads the arrays it captured.

P8Business problem

Validation rules list

A signup form has rules stored as lambdas of interface Check { boolean ok(String phone); }. Run every rule on a phone number and print which ones fail.

Input
phone "98765x210"
Expected output
FAIL 10 digits
FAIL only numbers
ok   starts 6-9
Show solution and explanation 
import java.util.*;

interface Check {
    boolean ok(String phone);
}

public class Main {
    public static void main(String[] args) {
        Map<String, Check> rules = new LinkedHashMap<>();
        rules.put("10 digits", p -> p.length() == 10);
        rules.put("only numbers", p -> p.chars().allMatch(Character::isDigit));
        rules.put("starts 6-9", p -> p.charAt(0) >= '6' && p.charAt(0) <= '9');
        String phone = "98765x210";
        rules.forEach((name, rule) -> System.out.println((rule.ok(phone) ? "ok   " : "FAIL ") + name));
    }
}
FAIL 10 digits FAIL only numbers ok starts 6-9

How it works: rules stored as data can be added or removed without changing the checking loop. Map.forEach takes a two-parameter lambda.

P9Business problem

Event handlers for a payment

Register handlers (Runnables) for SUCCESS and FAILED payment events in a map, then fire the handler for an incoming status.

Input
status SUCCESS
Expected output
Show receipt and send SMS
Show solution and explanation 
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Map<String, Runnable> handlers = new HashMap<>();
        handlers.put("SUCCESS", () -> System.out.println("Show receipt and send SMS"));
        handlers.put("FAILED", () -> System.out.println("Show retry button"));
        String status = "SUCCESS";
        handlers.getOrDefault(status, () -> System.out.println("Unknown status")).run();
    }
}
Show receipt and send SMS

How it works: this is how button clicks and payment callbacks are wired in real apps: the code to run later is passed as a lambda now.

Real-world scenario questions (asked in company interviews)

Lambdas are in almost every code review today; interviewers check that you can read them and spot their traps.

Code review · sortingFresher

Big amounts sorted in the wrong order

Transactions are sorted with (a, b) -> a.amountPaise - b.amountPaise on int fields. For very large and very negative values (refunds), the order is sometimes wrong. Why?

The interviewer is checking: integer overflow in comparators.

Show a strong answer
  • Subtracting two ints can overflow (e.g. 2,000,000,000 − (−2,000,000,000)), flipping the sign of the result.
  • Use Integer.compare(a.amountPaise, b.amountPaise) or Comparator.comparingInt(T::getAmountPaise).

Avoid: “subtraction is fine for numbers”; it's only safe for small ranges.

Code review · countingFresher

“Variable used in lambda should be final”

A colleague wants to count failed payments with int failed = 0; payments.forEach(p -> { if (p.failed()) failed++; }); and asks how to silence the compiler error. What do you suggest?

The interviewer is checking: effectively final and idiomatic alternatives.

Show a strong answer
  • Captured locals can't be modified. Don't fight it: use payments.stream().filter(Payment::failed).count(), or a plain for-each loop.
  • Tricks like an int[] or AtomicInteger work but hide intent, and an int[] is unsafe if the lambda runs on several threads.

Avoid: making failed a static field just to compile; that introduces shared mutable state.

Debugging · stack tracesJunior

A stack trace full of lambda$ frames

Production logs show NullPointerException at OrderService.lambda$process$3(OrderService.java:88). A teammate says “lambdas make debugging impossible”. How do you read this trace?

The interviewer is checking: knowing how lambdas compile.

Show a strong answer
  • lambda$process$3 is the synthetic method for the fourth lambda in process(); line 88 is inside its body.
  • Open line 88, see which value can be null (often an element or a field of the element), and handle it.
  • If a lambda grows long, extract it into a named method and use a method reference: clearer traces and easier testing.

Avoid: rewriting everything as anonymous classes; the trace would just say OrderService$4.

Design · readabilityMid

A 40-line lambda

A pull request passes a 40-line block lambda with nested ifs and try/catch into forEach. It works. Would you approve it?

The interviewer is checking: judgement about when lambdas help.

Show a strong answer
  • Lambdas are best for short, clear behaviour. A 40-line body hides a real piece of logic without a name, tests or reuse.
  • Extract it into a well-named private method (reconcile(Payment p)) and pass this::reconcile; or use a normal loop if it has side effects and early exits.

Avoid: “lambdas are modern, so longer lambdas are better”.
