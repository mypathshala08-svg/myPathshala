Generics

Before Java 5, a list could hold anything, so every read needed a cast, and a wrong element crashed the program only when someone finally read it. Generics let you write List<String>: the compiler now knows what's inside, rejects wrong elements immediately, and inserts the casts for you. You'll learn to use generic types, write your own generic classes and methods, control them with bounds and wildcards, and see what's left of them at run time.

Riya

Arjun Sir

No casts. The compiler checks everything going in, so it can safely insert the cast when things come out. Then, a surprise: once the checking is done, javac erases most of the type information. Let's see why that's fine.

2 Definition

What are generics?

Formal definition (write this in exams)

Generics (Java 5) allow classes, interfaces and methods to be declared with type parameters, such as class Box<T> or <T> T max(List<T> xs), which are replaced by actual type arguments when used (Box<String>). They provide compile-time type safety and remove the need for explicit casts. Type parameters can be restricted with bounds (T extends Number), and wildcards (?, ? extends T, ? super T) express flexible parameter types. Generics are implemented by type erasure: the compiler checks the types, then removes them, replacing type parameters with their bounds (usually Object) and inserting casts.

In simple words

A label on a container saying what it holds: List<String> is “a list of Strings”. The compiler enforces the label, so wrong items are caught while you write code, not when users run it.

Words you'll meet in this lesson

Type parameterThe placeholder in a declaration: T in class Box<T>.
Type argumentThe real type you supply: String in Box<String>.
Diamond operatorThe empty brackets in new ArrayList<>(): javac infers the type argument (Java 7+).
BoundA limit on T: T extends Comparable<T> means T must be comparable.
Wildcard? = some unknown type. List<? extends Number> = a list of some kind of Number.
Type erasureGeneric types are checked at compile time and removed from the bytecode.
Raw typeA generic type used without arguments (List): legacy, unsafe, gives warnings.
Naming conventionT type, E element, K/V key/value, R result
Type argumentsReference types only: List<Integer>, never List<int>
CheckedAt compile time; at run time List<String> and List<Integer> are the same class
Not allowednew T(), new T[10], instanceof List<String>, static fields of type T

Exam tip: generics are invariant: List<String> is not a subtype of List<Object>, even though String is a subtype of Object (incompatible types: ArrayList<String> cannot be converted to List<Object>). Use a wildcard, List<?> or List<? extends Object>, when a method must accept lists of any element type.

Your own generic class

class Box<T> {
    private T item;

    void put(T item) { this.item = item; }
    T get() { return item; }
}

public class Main {

        int n = locker.get() + 1;               // unboxed automatically
        System.out.println(n);

    }
}

Generic methods and bounded types

import java.util.List;

public class Main {
    // T must be comparable to itself, so compareTo is allowed
    static <T extends Comparable<T>> T max(List<T> xs) {
        T best = xs.get(0);
        for (T x : xs) {
            if (x.compareTo(best) > 0) best = x;
        }
        return best;
    }

    public static void main(String[] args) {
        System.out.println(max(List.of(3, 9, 4)));            // T = Integer
        System.out.println(max(List.of("kiwi", "apple")));    // T = String
    }
}
9 kiwi

Wildcards: ? extends to read, ? super to write

import java.util.ArrayList;
import java.util.List;

public class Main {
    static double sum(List<? extends Number> xs) {      // any list of numbers: read only
        double s = 0;
        for (Number n : xs) s += n.doubleValue();
        return s;
    }

    static void addDefaults(List<? super Integer> xs) {  // any list that can hold Integers: write
        xs.add(1);
        xs.add(2);
    }

    public static void main(String[] args) {
        System.out.println(sum(List.of(1, 2.5, 3L)));      // Integer, Double, Long together
        List<Number> nums = new ArrayList<>();
        addDefaults(nums);
        System.out.println(nums);
    }
}

Remember PECS: Producer Extends, Consumer Super. If a parameter produces values you read, use ? extends T. If it consumes values you add, use ? super T.

Type erasure, proved with javap

List<String> s = new ArrayList<>();
s.add("x");
String t = s.get(0);
invokeinterface  java/util/List.add:(Ljava/lang/Object;)Z     ← add(Object): no String here
invokeinterface  java/util/List.get:(I)Ljava/lang/Object;    ← get returns Object
checkcast        java/lang/String                            ← the cast javac inserted for you

Raw types defeat all of this. List raw = new ArrayList(); compiles with an unchecked warning and accepts anything; assigning it to a List<String> lets a wrong element slip through, and the ClassCastException appears far away, at the hidden cast. Never use raw types in new code.

Rule of thumb: use the diamond on the right (new HashMap<>()), the interface with full type arguments on the left, and treat every unchecked warning as a bug report.

4 Step by step

What javac does with List<String>

  1. Check every call against the type argument

    List<String> names = new ArrayList<>();
names.add(21007);   // checked: int → String? No.
    javac substitutes E = String into add(E e) and reports incompatible types: int cannot be converted to String. No class file is written.

  2. Infer the diamond

    new ArrayList<>() on the right becomes new ArrayList<String>() from the variable's type on the left.

  3. Erase the type arguments

    In the bytecode, List<String> becomes plain List, E becomes Object (or its bound, e.g. Comparable for T extends Comparable<T>).

  4. Insert casts where values come out

    String s = names.get(0) compiles to (String) names.get(0), a checkcast instruction. It can't fail, because step 1 guaranteed only Strings went in.

  5. At run time, one class for all

    new ArrayList<String>().getClass() == new ArrayList<Integer>().getClass() is true. The object on the heap has an Object[] inside, whatever the type argument was. Erasure kept Java 5 code compatible with older libraries.
5 See it happen

Checked, then erased: both views

Left: the code you write with generics. Right: what javac checks, and what remains in the class file.

Generics: checked, then erased 6 steps
What you see
  1. The variable is declared List<String>; the diamond on the right is filled in by javac.
  2. Adding a String is fine.
  3. Adding 21007 is a compile error. The bug is caught where it's written.
  4. names.get(0) is used as a String directly. No (String) cast in your code.
  5. With the bad line removed, javac produces the class file.
  6. The program runs and prints the name in capitals.
Behind the screen
  1. javac reads List<String> and substitutes E = String into every method of List for checking.
  2. add(E) is checked as add(String): "Riya" fits.
  3. An int doesn't fit add(String), and it can't be boxed to String either. javac stops with an error.
  4. get returns E, which is String, so assigning it to a String needs no cast in your code.
  5. Erasure: the class file calls add(Object) and get returning Object, plus a checkcast String javac inserted. It can't fail, because only Strings could get in.
  6. At run time the list is a plain ArrayList with an Object[] inside. ArrayList<Integer> would be exactly the same class.

7 Run the code

A generic result type for any lookup

import java.util.HashMap;
import java.util.Map;

class Result<T> {
    private final T value;
    private final String error;

    private Result(T value, String error) {
        this.value = value;
        this.error = error;
    }

    static <T> Result<T> ok(T value) { return new Result<>(value, null); }
    static <T> Result<T> fail(String error) { return new Result<>(null, error); }

    boolean isOk() { return error == null; }
    T value() { return value; }
    String error() { return error; }
}

public class Main {
    static Map<String, Integer> stock = new HashMap<>(Map.of("pen", 12, "book", 0));

    static Result<Integer> available(String item) {
        Integer n = stock.get(item);
        if (n == null) return Result.fail("No such item: " + item);
        if (n == 0) return Result.fail(item + " is out of stock");
        return Result.ok(n);
    }

    public static void main(String[] args) {
        for (String item : new String[]{"pen", "book", "lamp"}) {
            Result<Integer> r = available(item);
            System.out.println(r.isOk() ? item + ": " + r.value() + " left" : r.error());
        }
    }
}
pen: 12 left book is out of stock No such item: lamp
  • class Result<T>One class works for any result type: Result<Integer>, Result<Order>…
  • static <T> Result<T> ok(T value)A generic factory method: T is inferred from the argument.
  • Result<Integer> available(...)Callers know exactly what value() returns: an Integer, no cast.
  • Result.fail("…")T is inferred from the method's return type.

9 Quiz and revision

Check yourself

Quick revision

Lesson 11.2 in one screen

  • Generics = type parameters: class Box<T>, <T> T first(List<T>); use with type arguments: Box<String>.
  • Benefits: compile-time checks, no casts, reusable code. Diamond <> infers arguments.
  • Bounds: T extends Number, T extends Comparable<T>.
  • Wildcards: ? extends T to read (producer), ? super T to write (consumer): PECS.
  • Invariant: List<String> is not a List<Object>.
  • Erasure: types checked then removed; casts inserted; one class at run time.
  • Not allowed: primitives as arguments, new T(), generic arrays, instanceof List<String>. Avoid raw types.

Interview and viva questions

What is type erasure and why did Java choose it?

The compiler enforces generic types, then removes them from the bytecode, replacing type parameters with their bounds and adding casts. It was chosen for backward compatibility: generic code from Java 5 could run on the same JVM and interoperate with pre-generics libraries.

Explain PECS.

Producer Extends, Consumer Super. If a parameter supplies values to your method, declare it ? extends T (you can read T from it). If it receives values from your method, declare it ? super T (you can add T to it). Collections.copy(List<? super T> dest, List<? extends T> src) is the classic example.

Why can't you create new T() or new T[10]?

Because of erasure, the JVM doesn't know what T is at run time. Pass a Class<T> or a factory (Supplier<T>) instead, or use a List<T> rather than an array.

What's the difference between List<Object>, List<?> and raw List?

List<Object> holds any objects and you can add anything, but you can't pass it a List<String>. List<?> accepts a list of any type, but you can only read (as Object) and add null. A raw List turns off checking entirely, which is unsafe.

Can a generic class have static members that use T?

No. T belongs to each instance's type argument, but static members are shared by all instances (Box<String> and Box<Integer> are one class). Static generic methods declare their own type parameters instead: static <U> Box<U> of(U u).

Generic paginated results

An app shows 2 items per page. Write <T> List<T> page(List<T> all, int pageNo, int size) and print page 2 of five products.

import java.util.List;

public class Main {
    static <T> List<T> page(List<T> all, int pageNo, int size) {
        int from = (pageNo - 1) * size;
        int to = Math.min(from + size, all.size());
        return from >= all.size() ? List.of() : all.subList(from, to);
    }

    public static void main(String[] args) {
        List<String> products = List.of("P1", "P2", "P3", "P4", "P5");
        System.out.println(page(products, 2, 2));
        System.out.println(page(products, 3, 2));
    }
}
[P3, P4] [P5]

How it works: one generic method pages products, orders or users alike. subList returns a view of the range.

P7Business problem

Typed cache with a size limit

Write Cache<K, V> that keeps at most 2 entries, evicting the oldest. Store three exchange rates and print the cache.

Input
USD 83.2, EUR 90.1, GBP 105.4
Expected output
{EUR=90.1, GBP=105.4} USD=null
Show solution and explanation 
import java.util.LinkedHashMap;
import java.util.Map;

class Cache<K, V> {
    private final int max;
    private final LinkedHashMap<K, V> map = new LinkedHashMap<>();

    Cache(int max) { this.max = max; }

    void put(K key, V value) {
        map.put(key, value);
        if (map.size() > max) {
            K oldest = map.keySet().iterator().next();
            map.remove(oldest);
        }
    }

    V get(K key) { return map.get(key); }

    @Override
    public String toString() { return map.toString(); }
}

public class Main {
    public static void main(String[] args) {
        Cache<String, Double> rates = new Cache<>(2);
        rates.put("USD", 83.2);
        rates.put("EUR", 90.1);
        rates.put("GBP", 105.4);
        System.out.println(rates + " USD=" + rates.get("USD"));
    }
}
{EUR=90.1, GBP=105.4} USD=null

How it works: K and V are fixed per cache instance; LinkedHashMap keeps insertion order so the first key is the oldest.

P8Business problem

Validation result for any form

Write Validated<T> holding either a value or an error. Validate an age ("25" → 25) and a bad age ("abc").

Input
"25", "abc"
Expected output
OK 25
ERROR not a number: abc
Show solution and explanation 
class Validated<T> {
    final T value;
    final String error;

    private Validated(T value, String error) { this.value = value; this.error = error; }

    static <T> Validated<T> ok(T v) { return new Validated<>(v, null); }
    static <T> Validated<T> bad(String e) { return new Validated<>(null, e); }

    @Override
    public String toString() { return error == null ? "OK " + value : "ERROR " + error; }
}

public class Main {
    static Validated<Integer> age(String text) {
        try {
            int a = Integer.parseInt(text);
            return a > 0 && a < 120 ? Validated.ok(a) : Validated.bad("out of range");
        } catch (NumberFormatException e) {
            return Validated.bad("not a number: " + text);
        }
    }

    public static void main(String[] args) {
        System.out.println(age("25"));
        System.out.println(age("abc"));
    }
}
OK 25 ERROR not a number: abc

How it works: the generic result type works for ages, emails or dates, and callers get a typed value with no casts.

Real-world scenario questions (asked in company interviews)

Generics questions in interviews range from “why no casts?” to designing reusable APIs. Tie your answer to safety and reuse.

Legacy code · bug huntFresher

A ClassCastException far from the bug

A report crashes with ClassCastException: Integer cannot be cast to String while reading a list of names. The list is a raw ArrayList filled by three different modules. How do you find and prevent the bug?

The interviewer is checking: raw types, unchecked warnings and moving errors to compile time.

Show a strong answer
  • Change the declaration to List<String> and the methods that pass it around. javac will flag the module that adds an Integer.
  • Compile with -Xlint:unchecked and fix every warning; add it to the build so new raw types fail.
  • For data from outside (files, JSON), convert and validate at the boundary.

Avoid: adding instanceof String checks in the report. That hides the bad data instead of stopping it.

Backend · API designJunior

Ten nearly identical response classes

A service has OrderResponse, UserResponse, ProductResponse… each with status, message and a data field of a different type. How would you simplify it?

The interviewer is checking: designing a generic class.

Show a strong answer
  • One ApiResponse<T> with status, message and T data, plus factory methods ok(T) and error(String).
  • Endpoints return ApiResponse<Order>, ApiResponse<List<Product>>: type-safe, one class to test.
  • JSON libraries handle generic types with a type token (e.g. Jackson's TypeReference) because of erasure.

Avoid: Object data. Every caller would need a cast and could get it wrong.

Library · method signatureMid

A sum method that won't accept List<Integer>

A teammate wrote double total(List<Number> amounts). Calling it with a List<Integer> doesn't compile. Why, and what's the fix?

The interviewer is checking: invariance and wildcards.

Show a strong answer
  • Generics are invariant: List<Integer> isn't a List<Number>, because the method could otherwise add a Double into a list of Integers.
  • The method only reads, so make it a producer: double total(List<? extends Number> amounts).
  • If it also needed to add, use a type parameter: <T extends Number> void addAll(List<T> xs, T x).

Avoid: overloading for every number type or using a raw List.

Platform · cachingJunior

A reusable in-memory cache

You need small caches for exchange rates (String → Double) and user profiles (Long → Profile), each with a maximum size. Sketch the class.

The interviewer is checking: multiple type parameters and composition.

Show a strong answer
  • class Cache<K, V> wrapping a LinkedHashMap<K, V> (insertion or access order) with get(K), put(K, V) and eviction of the oldest entry when full.
  • Usage: Cache<String, Double> rates, Cache<Long, Profile> profiles: one tested class.
  • For production, consider a library cache with expiry and thread safety.

Avoid: a Map<Object, Object> “universal cache” that needs casts at every call site.
