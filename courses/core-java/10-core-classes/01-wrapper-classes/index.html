Wrapper classes

A form gives you "250" as text, a list refuses to hold an int, and a database says a mark is missing. Java's wrapper classes (Integer, Double, Character, Boolean and four more) turn primitive values into objects so they can do all of this. You'll learn the eight wrappers, how to convert between text, primitives and objects, and the cache that makes == lie.

Module 10 · Core Classes⏱ 20 minIntermediate8 practice problems
1 The story

A list that won't take a number

Riya is building a marks tracker for her class. She wants a growing list of marks, she reads each mark from a text box, and some students haven't taken the test yet. Three problems hit her in ten minutes.

Riya

Arjun Sir

Arjun Sir

Boxes with a toolkit: converting, comparing, limits like Integer.MAX_VALUE. And one trap with == that catches many freshers. Let's open the box.

2 Definition

What are wrapper classes?

Formal definition (write this in exams)

A wrapper class is a class in java.lang whose objects hold a single value of a primitive type. Java has eight: Byte, Short, Integer, Long, Float, Double, Character and Boolean. They let primitive values be used where objects are required (collections, generics, null), and provide constants and static utility methods for conversion and comparison. Wrapper classes are final and their objects are immutable.

In simple words

A primitive is a bare value. A wrapper puts that value inside an object, so it can go wherever Java expects an object, and gives you handy tools to work with it.

Text to number: parseXxx vs valueOf

public class Main {
    public static void main(String[] args) {
        String fromForm = "250";

        int qty = Integer.parseInt(fromForm);        // primitive int
        Integer boxed = Integer.valueOf(fromForm);   // Integer object
        double price = Double.parseDouble("99.5");
        boolean agreed = Boolean.parseBoolean("TRUE"); // case-insensitive

        System.out.println(qty + 1);
        System.out.println(boxed);
        System.out.println(price * 2);
        System.out.println(agreed);
    }
}

Comparing wrappers: equals, not ==

public class Main {
    public static void main(String[] args) {
        Integer a = Integer.valueOf(127), b = Integer.valueOf(127);
        Integer c = Integer.valueOf(128), d = Integer.valueOf(128);

        System.out.println(a == b);        // same cached object
        System.out.println(c == d);        // two different objects!
        System.out.println(c.equals(d));   // compares the values
    }
}
true false true

The Integer cache trap: Integer.valueOf keeps ready-made objects for -128 to 127 and hands out the same one every time. Outside that range it creates a new object. == compares references (is it the same object?), so it says true for 127 and false for 128. Always compare wrapper values with equals(), or unbox to int first.

Which one to pick? Use primitives (int, double) for calculations and loop counters: they're faster and can't be null. Use wrappers when you need an object: in collections and generics, when “no value” (null) is meaningful, or for the static helper methods.

4 Step by step

What happens when you call Integer.valueOf

  1. You ask for an Integer

    Integer seats = Integer.valueOf(120);
    valueOf is a static factory method of class Integer. It decides whether to reuse an object or create one.

  2. Is the value between -128 and 127?

    The JDK has an inner class Integer.IntegerCache holding an array of 256 ready-made Integer objects, created when the cache class is first initialised. For 120, valueOf returns the object at that slot. No new object is created.

  3. Outside the range: a new object

    Integer fare = Integer.valueOf(500);   // new Integer object on the heap
    For 500, valueOf creates a fresh object on the heap. Ask again for 500 and you get another fresh object. That's why == is unreliable.

  4. The variable holds a reference

    seats is a reference on the stack (like any object variable, Lesson 2.3). The value 120 lives inside the object on the heap, in a private final int value field.

  5. Getting the number back

    int n = fare.intValue();   // unboxing: copies 500 out of the object
    intValue() reads the private value field and returns a plain int. The object is unchanged: wrappers are immutable, so “changing” a wrapper variable always means pointing it to a different object.

Cached and new Integer objects: both views

Integer.valueOf: cached or new? 6 steps
What you see
  1. price is a primitive int: a bare value, no object.
  2. Integer.valueOf(120) gives back an Integer object holding 120.
  3. The same call again. On screen nothing looks different.
  4. valueOf(500): also an Integer object, holding 500.
  5. Again for 500. Two variables, both holding 500.
  6. a == b is true, c == d is false, yet c.equals(d) is true. The right side shows why.
Behind the screen
  1. A primitive lives right in the stack frame. No heap object is involved.
  2. The JDK keeps 256 ready-made Integer objects for -128 to 127. valueOf(120) returns the one for 120; a stores a reference to it.
  3. valueOf(120) returns the same cached object. Now a and b point to one object.
  4. 500 isn't cached, so valueOf creates a new Integer object on the heap.
  5. A second call creates a second object. c and d point to different objects that hold the same value.
  6. == checks whether two references point to the same object: true for a/b, false for c/d. equals() compares the stored values: 500 equals 500.
6 Real-world use

Wrapper classes in real systems

Almost every program that reads input, stores data in collections or talks to a database uses wrapper classes, often without you noticing.

Watch it with an example: a train booking form

A booking page sends everything as text. Watch the server turn the passenger count into a number, and refuse text that isn't one.

Parsing the passenger count 5 steps
Animated example
  1. The user types 2 in the form. Browsers send form fields as text, so the server receives the String "2".
  2. The server calls Integer.parseInt(text) to read the text as a number.
  3. Parsing succeeds: a primitive int 2. Now arithmetic works: 2 × ₹450 = ₹900.
  4. Another user types two. parseInt can't read it and throws NumberFormatException.
  5. The server catches the exception and shows a clear message instead of crashing. (Simplified: real sites also validate in the browser and check limits such as at most 6 passengers.)

1. Reading form and API input

Web forms, command-line arguments, query strings and JSON fields often arrive as text. Booking sites parse “number of passengers”, shops parse quantities, and every parse is wrapped in a check for bad input.

Text "2"→Integer.parseInt→int 2, or a friendly error

2. Collections of numbers

List<Integer> of order quantities, Map<String, Double> of product prices, Set<Long> of customer IDs. Collections and generics only work with objects (Module 11).

Values→Integer / Double objects→ArrayList, HashMap

3. “No value” from databases

A SQL column can be NULL (not entered). Data-access code maps it to an Integer or Double field that can be null. An int field would silently turn it into 0, a real but wrong value.

DB column NULL→Integer marks = null→shown as “Absent”

4. Validating codes and passwords

IFSC codes, PIN codes, vehicle numbers and password rules are checked character by character with Character.isDigit, isLetter and isUpperCase.

Each char→Character.isDigit(c)→valid / invalid

5. Configuration values

Settings files store everything as text: timeout=30, debug=true. Applications read them with Integer.parseInt and Boolean.parseBoolean at start-up.

config text→parseInt / parseBoolean→typed settings

Examples are simplified. Real systems add more checks, such as ranges, trimming spaces and logging rejected input.

7 Run the code

A billing counter that reads text input safely

import java.util.ArrayList;

public class Main {
    static Integer readQty(String text) {
        try {
            return Integer.valueOf(text.trim());
        } catch (NumberFormatException e) {
            return null;                       // null means "invalid"
        }
    }

    public static void main(String[] args) {
        String[] typed = {"2", " 5 ", "two", "1"};
        ArrayList<Integer> qtys = new ArrayList<>();

        for (String t : typed) {
            Integer q = readQty(t);
            if (q == null) {
                System.out.println("Skipped: '" + t + "'");
            } else {
                qtys.add(q);
            }
        }
        int total = 0;
        for (Integer q : qtys) {
            total += q.intValue();
        }
        System.out.println("Quantities: " + qtys);
        System.out.println("Total items: " + total);
    }
}
Skipped: 'two' Quantities: [2, 5, 1] Total items: 8
  • Integer.valueOf(text.trim())Removes spaces, then parses the text into an Integer object.
  • return null;Only possible because the return type is Integer, not int. Null signals “bad input”.
  • ArrayList<Integer>A list must hold objects, so we store Integer, not int.
  • q.intValue()Unboxes the object to a plain int for the arithmetic.

9 Quiz and revision

Check yourself

Quick revision

Lesson 10.1 in one screen

  • 8 wrappers in java.lang: Byte, Short, Integer, Long, Float, Double, Character, Boolean.
  • Why: collections and generics need objects; wrappers can be null; they carry utility methods and constants.
  • parseInt("85") → int; valueOf("85") → Integer. Bad text → NumberFormatException.
  • Constants: Integer.MAX_VALUE = 2147483647, MIN_VALUE = -2147483648.
  • Character.isDigit / isLetter / isUpperCase / toUpperCase for validation.
  • Integer cache: valueOf reuses objects for -128..127. Compare values with equals(), never ==.
  • Wrappers are final and immutable. new Integer(5) is deprecated; use valueOf.

Interview and viva questions

Why does Java need wrapper classes if it has primitives?

Primitives are fast but aren't objects. Many APIs need objects: collections, generics, methods that take Object, and anything where “no value” (null) must be represented. Wrappers bridge the two worlds and also provide parsing, conversion and comparison helpers.

What is the difference between parseInt() and valueOf()?

Integer.parseInt(String) returns a primitive int. Integer.valueOf(String) (or valueOf(int)) returns an Integer object, using the cache for -128 to 127. Both throw NumberFormatException for invalid text.

Explain the Integer cache.

Integer.valueOf returns pre-created objects for values from -128 to 127 (the upper limit can be raised with the JVM option -XX:AutoBoxCacheMax). Small numbers are very common, so reusing them saves memory. Side effect: == between two Integers is true for 127 but false for 128. Short, Long, Byte and Character (0 to 127) cache too; Float and Double do not.

Are wrapper classes mutable?

No. Each wrapper object holds its value in a private final field. count = count + 1 on an Integer variable creates (or fetches) a different object and points the variable at it.

Why is new Integer(5) deprecated?

A constructor always creates a new object, so it bypasses the cache and wastes memory. Since Java 9 the constructors are deprecated, and since Java 16 marked for removal. Integer.valueOf(5) (or autoboxing) is the recommended way.

public class Main {

P7Business problem

Strong password check

A password is strong if it has at least 8 characters, at least one upper-case letter, one digit and one symbol (not a letter or digit). Check "Riya@2026" and "riya2026".

Input
"Riya@2026", "riya2026"
Expected output
Riya@2026 -> true
riya2026  -> false
Show solution and explanation 
public class Main {
    static boolean strong(String pw) {
        boolean upper = false, digit = false, symbol = false;
        for (char c : pw.toCharArray()) {
            if (Character.isUpperCase(c)) upper = true;
            else if (Character.isDigit(c)) digit = true;
            else if (!Character.isLetter(c)) symbol = true;
        }
        return pw.length() >= 8 && upper && digit && symbol;
    }

    public static void main(String[] args) {
        System.out.println("Riya@2026 -> " + strong("Riya@2026"));
        System.out.println("riya2026  -> " + strong("riya2026"));
    }
}
Riya@2026 -> true riya2026 -> false

How it works: one pass over the characters sets three flags using Character helpers. All four rules must hold.

P8Business problem

Read settings from a config file

A config has maxUsers=250, debug=true and timeout=abc. Read each into the right type; use a default of 30 if the timeout is invalid.

Input
{"maxUsers=250", "debug=true", "timeout=abc"}
Expected output
maxUsers=250, debug=true, timeout=30
Show solution and explanation 
public class Main {
    static int intOr(String text, int fallback) {
        try {
            return Integer.parseInt(text);
        } catch (NumberFormatException e) {
            return fallback;
        }
    }

    public static void main(String[] args) {
        String[] lines = {"maxUsers=250", "debug=true", "timeout=abc"};
        int maxUsers = intOr(lines[0].split("=")[1], 100);
        boolean debug = Boolean.parseBoolean(lines[1].split("=")[1]);
        int timeout = intOr(lines[2].split("=")[1], 30);
        System.out.println("maxUsers=" + maxUsers + ", debug=" + debug + ", timeout=" + timeout);
    }
}
maxUsers=250, debug=true, timeout=30

How it works: each line is split at =. A helper parses with a fallback, so one bad setting doesn't stop the application from starting.

Real-world scenario questions (asked in company interviews)

Wrapper questions in interviews usually hide inside bugs: a comparison that “randomly” fails, a crash on empty input, a zero that should have been “missing”.

E-commerce · bug huntFresher

Order IDs match in testing, not in production

Code checks if (order.getUserId() == session.getUserId()), both returning Integer. It worked for all test users (IDs 1–50) but fails for real users with IDs in the thousands. Why?

The interviewer is checking: do you know about the Integer cache and reference comparison?

Show a strong answer
  • == on two Integer objects compares references, not values.
  • Values -128 to 127 come from the cache, so the same object is returned and == happens to be true. Larger IDs create separate objects, so it's false.
  • Fix: Objects.equals(a, b) (null-safe) or a.equals(b), or compare unboxed int values if neither can be null.
  • Add a test with IDs above 127, and a static-analysis rule that flags == on boxed types.

Avoid: “Java's == is buggy for big numbers.” It's working exactly as designed.

Banking · inputFresher

The transfer screen crashes

Users type amounts like 1,500 or leave the box empty, and the app shows a stack trace. The code is int amt = Integer.parseInt(box.getText());. How do you fix it?

The interviewer is checking: safe parsing and input validation.

Show a strong answer
  • parseInt throws NumberFormatException for commas, spaces and empty text.
  • Trim the text, remove allowed separators, then parse inside try/catch and show “Enter a valid amount”.
  • For money, use long paise or BigDecimal, not double, and check limits (greater than 0, below the daily limit).

Avoid: catching Exception and silently using 0. A transfer of ₹0 or a hidden error is worse than a clear message.

EdTech · data modelJunior

Absent students show 0 marks

The report card shows 0 for students who were absent, and their class average drops. The entity has private int marks;. What would you change?

The interviewer is checking: when to use a wrapper type for “no value”.

Show a strong answer
  • An int field can't represent “missing”, so a database NULL becomes 0.
  • Change it to Integer marks; null means absent. Show “AB” in the report and skip nulls when averaging.
  • Be careful when unboxing: int m = marks; on null throws NullPointerException (next lesson). Check for null first.

Avoid: using a magic value like -1 for absent. It leaks into averages and charts the moment someone forgets the rule.

Analytics · performanceJunior

A slow loop over ten million numbers

A report sums 10 million values using Long total = 0L; and total += values[i];. A teammate says changing one word makes it several times faster. Which word?

The interviewer is checking: the cost of wrapper objects in hot loops.

Show a strong answer
  • Change Long to long. Each += on a Long unboxes, adds, and boxes a new Long object, creating millions of short-lived objects for the garbage collector.
  • Use primitives for counters and sums; use wrappers only where an object is needed.
  • Prove it with a profiler or a simple timing before and after.

Avoid: “wrappers are always slow, never use them”. They're the right choice in collections and nullable fields.
