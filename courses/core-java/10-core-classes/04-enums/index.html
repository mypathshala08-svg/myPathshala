Enums

An order can be PLACED, PACKED, SHIPPED or DELIVERED, and nothing else. If you store that as a String, someone will one day write "Shiped" and the compiler won't notice. An enum is a type with a fixed list of named values, checked by the compiler, and each value is a real object that can carry data and behaviour. You'll learn to declare, compare, switch on and extend enums, and see what Java builds behind the scenes.

2 Definition

What is an enum?

Formal definition (write this in exams)

An enum (enumeration type), declared with the keyword enum, is a special class that defines a fixed set of named constants. Each constant is a public static final instance of the enum, created once when the enum class is initialised. Every enum implicitly extends java.lang.Enum, so it cannot extend another class, but it may implement interfaces and declare fields, constructors (always private) and methods. Enum objects cannot be created with new. Introduced in Java 5.

In simple words

An enum is a list of the only allowed values for something: days of the week, order statuses, coach classes. The compiler stops anything else, and each value is an object you can give data and methods to.

Words you'll meet in this lesson

Enum constantOne of the declared values, e.g. Status.SHIPPED. Written in CAPITALS by convention.
name()The constant's name as a String: "SHIPPED".
ordinal()Its position in the declaration, starting at 0.
values()A static method that returns all constants in order, as an array.
valueOf(String)Finds a constant by its exact name; unknown names throw IllegalArgumentException.
Type-safeThe compiler only accepts values of the right type, so mistakes are caught early.
Implicit parentjava.lang.Enum<E>, so an enum can't extends anything else
ConstructorAlways private (writing public is a compile error); runs once per constant
Creating objectsNot allowed: new Status() is a compile error
Comparing== is safe and preferred: there is exactly one object per constant
Free methodsname(), ordinal(), toString(), compareTo(), values(), valueOf()

Exam tip: an enum is implicitly final (unless a constant has its own body) and extends java.lang.Enum; its constructor is implicitly private; the constants must be the first thing in the enum body, followed by a semicolon if anything else comes after them. Use == to compare enum values.

1. A plain enum and its built-in methods

import java.util.Arrays;

enum Status { PLACED, PACKED, SHIPPED, DELIVERED }

public class Main {
    public static void main(String[] args) {
        Status s = Status.SHIPPED;

        System.out.println(s);                 // toString() = name
        System.out.println(s.ordinal());       // position, from 0
        System.out.println(Arrays.toString(Status.values()));
        System.out.println(Status.valueOf("PACKED"));
        System.out.println(s == Status.SHIPPED);
        System.out.println(Status.PACKED.compareTo(Status.DELIVERED));  // by ordinal
    }
}
SHIPPED 2 [PLACED, PACKED, SHIPPED, DELIVERED] PACKED true -2

valueOf is exact: Status.valueOf("Shipped") or "SHIPED" throws IllegalArgumentException: No enum constant Status.SHIPED. When reading user input, normalise it (trim().toUpperCase()) and catch the exception.

2. Switch on an enum

enum Status { PLACED, PACKED, SHIPPED, DELIVERED }

public class Main {
    static String message(Status s) {
        return switch (s) {                       // switch expression (Java 14+)
            case PLACED, PACKED -> "We're preparing your order";
            case SHIPPED -> "On the way";
            case DELIVERED -> "Delivered. Enjoy!";
        };
    }

    public static void main(String[] args) {
        for (Status s : Status.values()) {
            System.out.println(s + ": " + message(s));
        }
    }
}
PLACED: We're preparing your order PACKED: We're preparing your order SHIPPED: On the way DELIVERED: Delivered. Enjoy!

Inside a case you write SHIPPED, not Status.SHIPPED. A switch expression over an enum must cover every constant (or have default), so if someone adds RETURNED later, javac points at every switch that forgot it.

3. Fields, a constructor and methods

enum Coach {
    SL(1.0), AC3(2.5), AC2(3.6);          // each constant calls the constructor

    private final double factor;

    Coach(double factor) {                 // private by default
        this.factor = factor;
    }

    int fare(int base) {
        return (int) Math.round(base * factor);
    }
}

public class Main {
    public static void main(String[] args) {
        for (Coach c : Coach.values()) {
            System.out.println(c + " fare for ₹400 base: ₹" + c.fare(400));
        }
    }
}
SL fare for ₹400 base: ₹400 AC3 fare for ₹400 base: ₹1000 AC2 fare for ₹400 base: ₹1440

Constants can even override a method each in their own way (constant-specific bodies):

enum Op {

    abstract int apply(int a, int b);

public class Main {
    public static void main(String[] args) {

4. EnumMap and EnumSet

import java.util.EnumMap;
import java.util.EnumSet;

enum Status { PLACED, PACKED, SHIPPED, DELIVERED }

public class Main {
    public static void main(String[] args) {
        EnumMap<Status, Integer> count = new EnumMap<>(Status.class);
        count.put(Status.DELIVERED, 5);
        count.put(Status.PLACED, 2);
        System.out.println(count);                       // always in declaration order

        EnumSet<Status> active = EnumSet.range(Status.PACKED, Status.SHIPPED);
        System.out.println(active.contains(Status.SHIPPED));
    }
}
{PLACED=2, DELIVERED=5} true

Rule of thumb: if a variable can only hold one of a small, fixed set of values known while coding (statuses, roles, sizes, payment modes), make it an enum. Don't use ordinal() for business data or database storage: inserting a new constant in the middle shifts every number. Store name() instead, or a code field of your own.

4 Step by step

What javac builds from an enum

  1. You write three words

    public enum Size { SMALL, MEDIUM, LARGE }
    javac compiles this into an ordinary class file, Size.class.

  2. It becomes a final class extending Enum

    public final class Size extends java.lang.Enum<Size> {
  public static final Size SMALL;
  public static final Size MEDIUM;
  public static final Size LARGE;
  private static final Size[] $VALUES;
  public static Size[] values();
  public static Size valueOf(java.lang.String);
  private Size();
  private static Size[] $values();
  static {};
}
    Each constant is a public static final field. values() and valueOf() are generated for you. The constructor is private.

  3. The static initialiser creates the objects

    On first use of Size, the JVM runs static {}: it creates new Size("SMALL", 0), new Size("MEDIUM", 1), new Size("LARGE", 2) (javac passes the name and ordinal to Enum's constructor), stores them in the fields, and fills the $VALUES array.

  4. Every use refers to the same three objects

    Size.LARGE anywhere in the program reads the same static field, so it's the same object. That's why == is correct for enums, and why enums are a simple way to make a singleton.

  5. values() hands out a copy

    values() returns $VALUES.clone(): a new array each time, so callers can't change the real list. In a hot loop, store it once in a variable.

An enum's constants are created once 6 steps
What you see
  1. The enum is declared with two constants, each passing a fare factor. Nothing runs yet.
  2. Coach.AC3 is read for the first time.
  3. Coach.AC3 is read again into another variable.
  4. c == d prints true.
  5. c.fare(400) uses AC3's own factor: 400 × 2.5 = 1000.
  6. values() returns all constants in declaration order.
Behind the screen
  1. Declaring an enum only defines a class. No Coach objects exist until the class is first used.
  2. First use triggers the static initialiser: new Coach("SL", 0, 1.0) and new Coach("AC3", 1, 2.5) are created once and stored in static fields. c gets a reference to AC3.
  3. Reading Coach.AC3 again returns the same object. Nothing new is created; enum constructors never run again.
  4. c and d hold the same reference, so == is true. That's why == is the right way to compare enums.
  5. fare runs with this = the AC3 object and uses its factor field, 2.5.
  6. values() returns a fresh copy of the internal array, so no caller can change the real list of constants.
6 Real-world use

Enums in real systems

Wherever a value must be one of a known list, production code reaches for an enum.

An order moving through enum states 5 steps
Animated example
  1. A new order starts as Status.PLACED. Its display text comes from the constant's label field.
  2. When the restaurant accepts, the server calls status.next(), which returns the following constant: COOKING.
  3. The rider's app moves it to PICKED_UP, again with next().
  4. Finally DELIVERED. Every state and its text live in one enum.

1. Order and ticket statuses

E-commerce orders, support tickets and loan applications move through fixed states. An enum lists them, and often holds the allowed next states, so an order can't jump from PLACED to DELIVERED.

PLACED→status.next()→PACKED

2. Payment modes with their own rules

A PaymentMode enum (UPI, CARD, NETBANKING, COD) can carry a fee percentage and a limit per mode, so the rules live with the value instead of in scattered if-else chains.

mode = CARD→mode.fee(amount)→₹ fee for that mode

3. Roles and permissions

A school portal's Role enum (ADMIN, TEACHER, STUDENT) with an EnumSet<Permission> per role makes access checks fast and readable.

user.role→role.can(Permission.EDIT_MARKS)→allow / deny

4. Libraries and the JDK

The JDK itself uses enums: DayOfWeek, Month, TimeUnit, RoundingMode, Thread.State. Web frameworks use them for HTTP methods and status codes.

LocalDate.getDayOfWeek()→DayOfWeek.SUNDAY→weekend pricing

Examples are simplified. When enums are saved to a database, teams store the name (or a stable code), never the ordinal.

7 Run the code

An order tracker that can't skip a step

enum Status {
    PLACED("Order received", 0),
    PACKED("Packed at warehouse", 1),
    SHIPPED("Out for delivery", 2),
    DELIVERED("Delivered", 0);

    private final String label;
    private final int daysLeft;

    Status(String label, int daysLeft) {
        this.label = label;
        this.daysLeft = daysLeft;
    }

    Status next() {
        if (this == DELIVERED) {
            return DELIVERED;                     // last step: stay
        }
        return values()[ordinal() + 1];           // the following constant
    }

    String label() { return label; }
    int daysLeft() { return daysLeft; }
}

public class Main {
    public static void main(String[] args) {
        Status s = Status.PLACED;
        while (s != Status.DELIVERED) {
            System.out.println(s + " · " + s.label() + " · " + s.daysLeft() + " day(s)");
            s = s.next();
        }
        System.out.println(s + " · " + s.label());
    }
}
PLACED · Order received · 0 day(s) PACKED · Packed at warehouse · 1 day(s) SHIPPED · Out for delivery · 2 day(s) DELIVERED · Delivered
  • PLACED("Order received", 0)Each constant passes its own data to the constructor, once, when the enum is initialised.
  • this == DELIVEREDComparing enums with == is safe: one object per constant.
  • values()[ordinal() + 1]Uses the declaration order to find the next status. Fine inside the enum; don't store ordinals elsewhere.
  • while (s != Status.DELIVERED)Outside the enum, constants need the type name: Status.DELIVERED.

Interview and viva questions

Why use an enum instead of int or String constants?

Type safety (only declared values compile), readable names in logs and debuggers, built-in values()/valueOf(), use in switch with completeness checks, and the ability to attach data and behaviour. With public static final int constants, any int is accepted and a typo in a String constant isn't noticed.

Can an enum have a constructor? Can it be public?

Yes, it can have constructors, fields and methods. The constructor is always private (implicitly); declaring it public is a compile error, because only the enum itself may create its constants.

Can an enum extend a class or implement an interface?

It can't extend a class, because it already extends java.lang.Enum and Java has single inheritance. It can implement any number of interfaces, for example enum Mode implements FeeRule.

How do you make a singleton with an enum?

enum Config { INSTANCE; … }. The JVM guarantees one instance, creation is thread-safe (class initialisation), and serialization and reflection can't create a second copy. Joshua Bloch's Effective Java recommends it as the simplest singleton.

What's the difference between name() and toString()?

name() is final and always returns the declared name. toString() returns the name by default but can be overridden for display, e.g. “Out for delivery”. Use name() for storage and valueOf, toString() for people.

P6Business problem

Count orders by status

Given statuses of 6 orders, count how many are in each status using an EnumMap, printed in the enum's order.

import java.util.EnumMap;

enum Status { PLACED, PACKED, SHIPPED, DELIVERED }

public class Main {
    public static void main(String[] args) {
        Status[] orders = {Status.PACKED, Status.PLACED, Status.SHIPPED,

P7Business problem

Role-based permissions

Roles ADMIN, TEACHER and STUDENT each have a set of allowed actions (VIEW, EDIT_MARKS, DELETE_USER). Check whether a TEACHER may EDIT_MARKS and DELETE_USER.

Input
TEACHER: EDIT_MARKS?, DELETE_USER?
Expected output
TEACHER EDIT_MARKS: true
TEACHER DELETE_USER: false
Show solution and explanation 
import java.util.EnumSet;

enum Action { VIEW, EDIT_MARKS, DELETE_USER }

enum Role {
    ADMIN(EnumSet.allOf(Action.class)),
    TEACHER(EnumSet.of(Action.VIEW, Action.EDIT_MARKS)),
    STUDENT(EnumSet.of(Action.VIEW));

    private final EnumSet<Action> allowed;

    Role(EnumSet<Action> allowed) { this.allowed = allowed; }

    boolean can(Action a) { return allowed.contains(a); }
}

public class Main {
    public static void main(String[] args) {
        System.out.println("TEACHER EDIT_MARKS: " + Role.TEACHER.can(Action.EDIT_MARKS));
        System.out.println("TEACHER DELETE_USER: " + Role.TEACHER.can(Action.DELETE_USER));
    }
}
TEACHER EDIT_MARKS: true TEACHER DELETE_USER: false

How it works: each role carries its own EnumSet of actions; the permission rule is one method on the enum.

P8Business problem

GST slab by category

Product categories have GST rates: ESSENTIAL 5%, STANDARD 18%, LUXURY 28%. Print the final price of ₹1000 items in each category.

Expected output

enum Category {

Real-world scenario questions (asked in company interviews)

Enum questions in interviews are often about design: where should the rules live, and what happens when the list changes?

E-commerce · designFresher

Replace status Strings

An order service stores status as a String and has bugs from inconsistent spelling. How would you refactor it?

The interviewer is checking: do you know when an enum is the right tool?

Show a strong answer
  • Create enum OrderStatus { PLACED, PACKED, SHIPPED, DELIVERED, CANCELLED } and change the field type. javac now flags every wrong value.
  • Convert at the edges only: OrderStatus.valueOf(text.trim().toUpperCase()) with error handling when reading requests; name() when writing to the database.
  • Move rules into the enum, e.g. canMoveTo(OrderStatus next), so transitions are checked in one place.

Avoid: storing the ordinal in the database “to save space”. Adding a status in the middle silently corrupts old rows.

Payments · maintainabilityJunior

Fees spread across ten if-else chains

Fee logic for UPI, card, net banking and COD is copied in ten places as if (mode.equals("CARD")) …. Adding a new mode means editing all ten. What do you propose?

The interviewer is checking: putting behaviour on enum constants.

Show a strong answer
  • An enum PaymentMode with fields (fee percent, max amount) and a method fee(amount), or constant-specific bodies when the formulas differ.
  • Callers do mode.fee(amount). A new mode is one new constant; switch expressions elsewhere fail to compile until they handle it.
  • If fees change often or per merchant, keep the enum for the mode but load numbers from configuration.

Avoid: hard-coding values that the business changes weekly. Enums suit things that change with code releases.

API · backward compatibilityMid

A new constant breaks an old client

Your service adds RETURNED to OrderStatus. An older mobile app that deserialises the status with valueOf now crashes for returned orders. How do you prevent this?

The interviewer is checking: evolving enums across systems.

Show a strong answer
  • Clients should handle unknown values: catch IllegalArgumentException and map to an UNKNOWN constant (many JSON libraries have an option for this).
  • Roll out client support before the server starts sending new values; version the API if needed.
  • Document the enum as “may grow” in the API contract.

Avoid: “never add constants”. Business changes; plan for it.

Platform · singletonJunior

Exactly one configuration object

You need one shared AppConfig object for the whole application, created safely even if two threads ask for it at start-up. What's the simplest correct way in Java?

The interviewer is checking: knowledge of the enum singleton.

Show a strong answer
  • enum AppConfig { INSTANCE; private final Properties props = load(); … }.
  • The JVM creates INSTANCE once during class initialisation, which is thread-safe, and enums are protected against extra copies through reflection and serialization.
  • In larger apps, a dependency-injection container (e.g. Spring) usually manages singletons instead.

Avoid: double-checked locking without volatile. It's easy to get wrong.
