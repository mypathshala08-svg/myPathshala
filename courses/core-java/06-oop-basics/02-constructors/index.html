Constructors and constructor chaining

Creating an object and then setting five fields by hand is slow and easy to get wrong: forget one and you get null on a receipt. A constructor sets up a new object the moment it is created. You'll see when Java gives you a default constructor and when it takes it away, how overloaded constructors share work with this(...), the exact order in which initialization happens, and then practise with 10 problems.

The ID card that said “null”

Riya

Arjun Sir

Arjun Sir

2 Definition

What is a constructor?

Formal definition (write this in exams)

A constructor is a special member of a class that is invoked automatically when an object is created with new, to initialize that object. It has the same name as the class and no return type, not even void. If a class declares no constructor, the compiler supplies a default constructor with no parameters. Constructors can be overloaded, and one constructor can call another of the same class with this(...), which is called constructor chaining.

In simple words

The admission desk for new objects. new builds an empty object; the constructor fills in its details before anyone gets to use it.

Words you'll meet in this lesson

Default constructorThe no-parameter constructor javac adds when you write none.
No-arg constructorA constructor you write that takes no parameters.
Parameterized constructorTakes values: Student(String name, int roll).
OverloadingSeveral constructors with different parameter lists (Lesson 5.4).
this(...)Calls another constructor of the same class.
Initializer blockA bare { … } in the class that runs for every new object.

Constructor facts at a glance

NameExactly the class name: Student(…)
Return typeNone. void Student() compiles, but it is an ordinary method, not a constructor.
Called bynew, automatically, once per object. You can't call it like a method.
Default constructorAdded by javac only if the class has no constructor at all
this(...)Must be the first statement (Java 8 to 21); constructors can't call each other in a cycle
Inherited?No. Each class declares its own (parents are called with super(...), Lesson 7.3).

Exam tip: "Does a constructor return anything?" It has no return type and can't return a value (a bare return; is allowed). new is what produces the reference to the new object.

Overloading plus chaining: one constructor does the real work

class Pizza {
    String size;
    String crust;
    int price;

    Pizza() {                                  // no-arg
        this("Medium");
    }

    Pizza(String size) {                       // 1 parameter
        this(size, "Classic");
    }

    Pizza(String size, String crust) {         // 2 parameters: does the real work
        this.size = size;
        this.crust = crust;
        price = size.equals("Large") ? 499 : 299;
    }

    void show() {
        System.out.println(size + " | " + crust + " | Rs " + price);
    }
}

public class Main {
    public static void main(String[] args) {
        new Pizza().show();
        new Pizza("Large").show();
        new Pizza("Small", "Thin").show();
    }
}
Medium | Classic | Rs 299 Large | Classic | Rs 499 Small | Thin | Rs 299

new Pizza() → this("Medium") → this("Medium", "Classic"). Only the 2-parameter constructor contains the logic, so a price change is made in one place.

4 Step by step

What happens inside new, in order

  1. Memory and default values

    Account a = new Account("Riya");
    The JVM reserves heap memory for one Account and sets every field to its default: null, 0.0, false. This happens before any of your code runs.

  2. The matching constructor is chosen

    Account(String holder) { … }           // chosen: one String
Account(String holder, double balance) { … }
    Exactly like overloaded methods (Lesson 5.4), javac picks the constructor whose parameter list matches the arguments. In bytecode every constructor is a special method named <init>; that's the name you see in stack traces.

  3. this(...) runs first

    Account(String holder) {
    this(holder, 0.0);   // must be the first statement
    System.out.println("1-arg body");
}
    A new frame for the 2-parameter constructor is pushed on top, working on the same object. Only when it finishes does the rest of the 1-parameter body run.

  4. Field initializers and instance blocks

    String type = "SAVINGS";
{ System.out.println("instance block"); }
    javac copies these, in the order they are written, into the start of every constructor that doesn't begin with this(...) (right after the hidden call to the parent constructor). So they run once per object, before the constructor body. javap -c shows the copied putfield instructions.

  5. Bodies finish, reference handed back

    this.holder = holder;
this.balance = balance;
    The 2-parameter body runs, its frame pops, then the 1-parameter body runs and pops. Finally new gives the reference of the finished object to a. Nobody ever sees a half-built Account.
5 See it happen

Chained constructors: both views

Left: the code being run and what it prints. Right: constructor frames stacking up for one object, and that object's fields filling in.

Inside new Account("Riya") 6 steps
What you see
  1. new: before any of your code runs, an Account exists with default values.
  2. Choose: the call passes one String, so the 1-parameter constructor runs. Its first line is this(h, 0.0).
  3. Chain: this(...) calls the 2-parameter constructor for the same object. The 1-arg body waits.
  4. Initializer: type = "SAVINGS" runs now, before the 2-arg body. Nothing is printed yet.
  5. 2-arg body: it prints type=SAVINGS (already set), then stores the holder and balance.
  6. Finish: control returns to the 1-arg body, which prints its line. Only now does a get the object.
Behind the screen
  1. The JVM allocates object #1 on the heap and zeroes it: null, 0.0, null. a doesn't have it yet.
  2. The 1-parameter constructor's frame is pushed. Its hidden this points to #1.
  3. this(h, 0.0) pushes a second constructor frame on top. Both frames work on the same object #1.
  4. The initializer for type was copied by javac into the 2-arg constructor (the one that doesn't start with this(...)), so it runs here, once.
  5. The 2-arg body copies the parameters into #1's fields. Then its frame is popped.
  6. The 1-arg body finishes and its frame pops too. Only now does new hand the reference of the complete object to a.
6 Real-world use

Constructors in real systems

Good constructors make it impossible to create a broken object. That single idea prevents a large share of production bugs.

Watch it with an example: opening a bank account (KYC)

A bank won't open an account without a name and PAN. The constructor makes these details compulsory, and constructor chaining fills in sensible defaults.

new Account("Riya", "ABCDE1234F") 6 steps
Animated example
  1. Opening: new Account("Riya", "ABCDE1234F"). The constructor's parameters are exactly what the bank requires.
  2. Memory first: the JVM creates object #1 with default values: null for references, 0 for numbers.
  3. Chaining: the 2-argument constructor calls this(n, p, 1000), passing a default minimum balance. this(…) must be the first line.
  4. Main constructor: sets name, PAN and balance. All the real work is in one place.
  5. Ready: only now is the reference stored in a. Nobody can ever see a half-built account.
  6. Safety: because the class defines constructors with parameters, Java gives no default no-arg constructor. new Account() doesn't compile, so required details can't be skipped.

1. Mandatory details (KYC)

A bank's Customer class takes name, PAN and date of birth in its only constructor. There is simply no way to create a customer without them.

Onboarding form→new Customer(name, pan, dob)→Valid record

2. Sensible defaults with chaining

An Order created from the app gets status PLACED and payment mode UPI unless told otherwise. Shorter constructors pass defaults to one full constructor.

new Order(cart)→this(cart, "UPI", "PLACED")→Consistent orders

3. The JDK itself

You have already used overloaded constructors: new Scanner(System.in), new StringBuilder() and new StringBuilder(64), new String(charArray). Different arguments, different setup.

Arguments→matching constructor→Ready object

4. Frameworks and dependency injection

Frameworks such as Spring create your service objects for you and pass the parts they need (a repository, a payment client) into the constructor. This is called constructor injection.

App starts→new OrderService(repo)→Wired-up app

Examples are simplified. Real constructors usually also validate their inputs, and some libraries need a no-arg constructor to create objects from database rows or JSON.

9 Quiz and revision

Check yourself

Quick revision

Lesson 6.2 in one screen

  • Constructor: same name as the class, no return type, runs automatically inside new.
  • No constructor written → javac adds a default no-arg one. Write any constructor → it's gone.
  • Kinds: default, no-arg, parameterized. Constructors can be overloaded.
  • this(...) calls another constructor of the same class: first statement, no cycles.
  • Order: defaults → field initializers and instance blocks (in written order) → constructor body.
  • With chaining, initializers run once, in the constructor that doesn't start with this(...).
  • void ClassName() is a method, not a constructor. Constructors are not inherited.

Interview and viva questions

What is the difference between a default constructor and a no-arg constructor?

Both take no parameters. The default constructor is generated by javac only when the class declares no constructor; it just calls the parent constructor. A no-arg constructor is one you write yourself, usually to set starting values.

Why doesn't a constructor have a return type?

It doesn't produce a value; it initializes an object that new has already created. The new expression is what evaluates to the reference. If you add a return type, Java treats it as a normal method.

Why must this(...) be the first statement?

So the object is fully set up by the other constructor before the current one uses it, and so initialization runs exactly once. javac enforces it with "call to this must be first statement in constructor" (Java 8 to 21; Java 25 relaxes the rule slightly with flexible constructor bodies).

Can a constructor be private?

Yes. Then only code inside the class can create objects. It's used for utility classes that should never be instantiated, and for patterns like Singleton or factory methods (LocalDate.of(…) is a factory method rather than a public constructor).

In what order does Java initialize an object?

Memory is allocated and fields get default values; the parent constructor runs; then field initializers and instance initializer blocks run in the order written; then the rest of the constructor body. With this(...), the called constructor finishes before the caller's body continues.

P1Easy

Circle with a constructor

Write a Circle class whose constructor takes the radius. Add area() and print the area of circles with radius 7 and 2.5, rounded to 2 decimals.

Input
radius = 7, radius = 2.5
Expected output
Area 1: 153.94
Area 2: 19.63
Show solution and explanation 
class Circle {
    double radius;

    Circle(double radius) {
        this.radius = radius;
    }

    double area() {
        return Math.PI * radius * radius;
    }
}

public class Main {
    public static void main(String[] args) {
        Circle c1 = new Circle(7);
        Circle c2 = new Circle(2.5);
        System.out.printf("Area 1: %.2f%n", c1.area());

    }

Area 1: 153.94 Area 2: 19.63

How it works: the radius is required, so it is a constructor parameter: a Circle without a radius can't be created. new Circle(7) passes an int, which is widened to double automatically.

P7Medium

Rejecting bad values

A Product constructor should never store a negative price. If the price is negative, store 0 and print a warning. Create one valid and one invalid product.

class Product {

    int price;

    Product(String name, int price) {
        this.name = name;
        if (price < 0) {
            System.out.println("Warning: negative price for " + name + ", using 0");

public class Main {

P8Business problem

Hotel booking bill

A Booking takes guest name, nights and room rate. If the rate is not given, use the standard room rate of Rs 2,500. The constructor calculates the bill with 12% GST. Print two bookings.

Input
new Booking("Sharma", 3)
new Booking("Iyer", 2, 4200)
Expected output
Sharma: 3 nights x Rs 2500 + 12% GST = Rs 8400.0
Iyer: 2 nights x Rs 4200 + 12% GST = Rs 9408.0
Show solution and explanation 
class Booking {
    String guest;
    int nights;
    int rate;
    double total;

    Booking(String guest, int nights) {
        this(guest, nights, 2500);
    }

    Booking(String guest, int nights, int rate) {
        this.guest = guest;
        this.nights = nights;
        this.rate = rate;
        double base = nights * rate;
        total = base + base * 12 / 100;
    }

    void print() {
        System.out.println(guest + ": " + nights + " nights x Rs " + rate + " + 12% GST = Rs " + total);
    }
}

public class Main {
    public static void main(String[] args) {
        new Booking("Sharma", 3).print();
        new Booking("Iyer", 2, 4200).print();
    }
}
Sharma: 3 nights x Rs 2500 + 12% GST = Rs 8400.0 Iyer: 2 nights x Rs 4200 + 12% GST = Rs 9408.0

How it works:

  1. The short constructor supplies the default rate and chains to the full one, so the GST calculation exists only once.
  2. Sharma: 3 × 2500 = 7500, plus 900 GST = 8400.0. Iyer: 2 × 4200 = 8400, plus 1008 GST = 9408.0.
  3. GST rates on hotel rooms depend on the tariff and change over time; 12% is used here only as an example.
P9Business problem

Loan EMI calculated at creation

A Loan object is created with principal, annual interest rate and tenure in months. The constructor computes the monthly EMI using EMI = P × r × (1 + r)n / ((1 + r)n − 1), where r is the monthly rate. Show the EMI, total payment and total interest for a Rs 5 lakh loan at 9% for 5 years.

Input
principal = 500000, rate = 9% a year, months = 60
Expected output
EMI: Rs 10379.18
Total paid: Rs 622750.66
Total interest: Rs 122750.66
Show solution and explanation 
class Loan {
    double principal;
    double annualRate;
    int months;
    double emi;

    Loan(double principal, double annualRate, int months) {
        this.principal = principal;
        this.annualRate = annualRate;
        this.months = months;
        double r = annualRate / 12 / 100;
        double factor = Math.pow(1 + r, months);
        emi = principal * r * factor / (factor - 1);
    }
}

public class Main {
    public static void main(String[] args) {
        Loan home = new Loan(500000, 9, 60);
        double totalPaid = home.emi * home.months;
        System.out.printf("EMI: Rs %.2f%n", home.emi);
        System.out.printf("Total paid: Rs %.2f%n", totalPaid);
        System.out.printf("Total interest: Rs %.2f%n", totalPaid - home.principal);
    }
}
EMI: Rs 10379.18 Total paid: Rs 622750.66 Total interest: Rs 122750.66

How it works:

  1. The EMI depends only on values given at creation, so the constructor works it out once and stores it.
  2. The yearly rate 9% becomes a monthly rate of 0.0075; Math.pow computes (1 + r)60.
  3. This is the standard reducing-balance EMI formula used by banks; actual EMIs may differ slightly because of rounding rules and fees.
P10Business problem

Train tickets: general and Tatkal

A TrainTicket has passenger, distance in km and quota. A general ticket costs Rs 0.60 per km. Tatkal adds 30% of the base fare, with a minimum surcharge of Rs 100. A constructor without the quota means GENERAL. Print one ticket of each.

Input
new TrainTicket("Neha", 350)
new TrainTicket("Arif", 350, "TATKAL")
Expected output
Neha | 350 km | GENERAL | Rs 210.00
Arif | 350 km | TATKAL | Rs 310.00
Show solution and explanation 
class TrainTicket {
    String passenger;
    int km;
    String quota;
    double fare;

    TrainTicket(String passenger, int km) {
        this(passenger, km, "GENERAL");
    }

    TrainTicket(String passenger, int km, String quota) {
        this.passenger = passenger;
        this.km = km;
        this.quota = quota;
        fare = km * 0.60;
        if (quota.equals("TATKAL")) {
            fare += Math.max(fare * 0.30, 100);
        }
    }

    void print() {
        System.out.printf("%s | %d km | %s | Rs %.2f%n", passenger, km, quota, fare);
    }
}

public class Main {
    public static void main(String[] args) {
        new TrainTicket("Neha", 350).print();
        new TrainTicket("Arif", 350, "TATKAL").print();
    }
}
Neha | 350 km | GENERAL | Rs 210.00 Arif | 350 km | TATKAL | Rs 310.00

How it works:

  1. Most bookings are general, so the 2-parameter constructor supplies the quota and chains to the full one.
  2. Base fare 350 × 0.60 = 210. Tatkal: 30% of 210 is 63, less than the minimum, so Rs 100 is added: 310.
  3. Math.max applies the minimum in one line. The fare rules here are invented for practice, not real railway rules.

Real-world scenario questions (asked in company interviews)

Constructors decide whether a broken object can ever exist. Decide your answer first, then open the model answer.

SaaS · refactoringFresher

“I added one constructor and 40 files broke”

You add Invoice(String customerId) to the Invoice class so new code must pass a customer. Suddenly the build fails in 40 places that use new Invoice(), and a library that reads invoices from JSON starts failing too. Explain and fix.

The interviewer is checking: do you know when the default constructor disappears?

Show a strong answer
  • Before, the class had no constructor, so javac supplied a default no-arg one. Writing any constructor removes it, so every new Invoice() stops compiling.
  • Many JSON and database libraries create objects through a no-arg constructor and then fill the fields, so they break too.
  • Fix: if no-arg creation is still valid, add Invoice() back explicitly (it can chain to the other with a default). If it isn't valid, update the 40 callers so each passes a customer.

Avoid: deleting the new constructor to make the build green. Decide what a valid Invoice needs.

Banking · data qualityFresher

Accounts saved without a PAN

Audit finds 3,000 account records with an empty PAN. The Account class has only the default constructor, and each screen sets fields one by one. How would you redesign the class so this can't happen again?

The interviewer is checking: can you use constructors to enforce valid objects?

Show a strong answer
  • Give Account a constructor that takes the mandatory details (holder, PAN, branch) and remove the no-arg one, so an account can't be created without them.
  • Validate inside the constructor: if the PAN is null or not in the 10-character format, throw an exception (Module 9) instead of creating a bad object.
  • Later, make the fields private (Lesson 7.1) so nobody can blank them out after creation.
  • Clean up the 3,000 existing records separately; the code change only protects new ones.

Avoid: adding a null check on every screen. Put the rule in one place: the constructor.

E-commerce · code review1–3 years

Four constructors, one forgotten status

An Order class has four overloaded constructors, each copy-pasting the same ten lines of setup. Someone added a status = "PLACED" line to three of them, and orders created through the fourth show a blank status in the tracking page. How would you restructure it?

The interviewer is checking: do you know how to use constructor chaining to remove duplication?

Show a strong answer
  • Keep one "full" constructor that takes every value and contains all the setup.
  • Make the other three one-liners that call it with this(...), passing defaults for the missing values.
  • Values that never depend on the caller (like the starting status) can be a field initializer, which runs for every constructor path.
  • Add a unit test that creates an order through each constructor and checks the status.

Avoid: fixing just the fourth constructor. The duplication will cause the next bug.

Logistics · performance1–3 years

Creating a Shipment takes two seconds

The Shipment constructor calls a courier partner's web service to fetch the delivery estimate. Bulk uploads of 10,000 shipments take hours, and unit tests fail whenever the partner's test server is down. What's wrong with this design?

The interviewer is checking: do you know what belongs in a constructor and what doesn't?

Show a strong answer
  • A constructor should only put the object into a valid starting state: copy and check values. Slow network calls make every new slow and impossible to test without the network.
  • Create the Shipment with its own data only. Fetch estimates in a separate service method, and for bulk uploads call the partner in batches or in the background.
  • Pass collaborators (like the courier client) in from outside so tests can supply a fake one.

Avoid: "Add a cache inside the constructor." Keep constructors simple and fast.
