Classes and objects

Parallel arrays for names, roll numbers and marks get messy fast. A class lets you describe a student once, with its data and its actions together, and then create as many student objects as you need. You'll see what new really does, where objects live, why copying a reference doesn't copy the object, what null means, and then practise with 10 problems.

1 The story

Riya's three arrays

Riya is building the registration program for her college fest. She keeps String[] names, int[] rolls and int[] fees side by side, and index 7 in each array is supposed to be the same student. Then she sorts the names alphabetically for the printout, and suddenly every student has someone else's roll number.

Riya

Sir, I sorted one array and the others didn't move with it. Now Kabir has Meera's roll number.

Arjun Sir

Because nothing ties them together. Write a class called Student once: name, roll and fees in one place. Then each student is one object, and its data can never get separated.

Riya

So the class is like the blank registration form, and each filled form is an object?

Arjun Sir

Exactly. One form design, hundreds of filled copies. And the form can also have actions, like printCard(), that every copy knows how to do with its own data.

2 Definition

What are classes and objects?

Formal definition (write this in exams)

A class is a user-defined type that describes the state (fields, also called instance variables) and behaviour (methods) shared by a group of objects. An object is an instance of a class, created at run time with the new operator; it gets its own copy of the instance fields and lives on the heap. A variable of a class type is a reference variable: it holds a reference to an object, or null.

In simple words

A class is the blank form; an object is one filled-in form. The form says which boxes exist (name, roll, fees) and what you can do with it (print a card). Every filled form has its own values.

Words you'll meet in this lesson

Default values: a new object is never "empty garbage"

4 Step by step

From blueprint to working object

  1. Write the class

    class Student {
    String name;
    int marks;
    void show() { System.out.println(name + " " + marks); }
}
    Nothing runs yet. javac compiles this into Student.class. When the program first uses Student, the JVM loads that file and keeps the class description in its method area.

  2. Declare a reference variable

    Student s1;
    One slot on main's stack frame, big enough for an address. No object exists, and as a local variable it can't be used until it's assigned.

  3. Create the object with new

    s1 = new Student();
    new asks the JVM for memory on the heap for one Student (room for name and marks), sets every field to its default (null, 0), and gives back the object's reference, which is stored in s1.

  4. Use the dot operator

    s1.name = "Riya";
s1.marks = 82;
s1.show();
    The dot means "follow the reference to the object". Calling s1.show() pushes a frame for show with a hidden variable this set to the same object, so name inside the method means this object's name.

  5. Copy the reference, or clear it

    Student s3 = s1;   // two names, one object
s1 = null;          // s1 now points nowhere
    Assigning a reference copies the address, never the object. After s1 = null, calling s1.show() throws NullPointerException. The object still exists, because s3 refers to it. Once no reference is left, the garbage collector can free it.
5 See it happen

Objects and references: both views

Left: the code and what it prints. Right: reference variables on the stack and the objects they point to on the heap.

Life of a Student object 6 steps
What you see
  1. Define: the class says every Student has a name and marks. Writing it creates no student.
  2. Create: new Student() makes one object. Its fields start at default values: null and 0.
  3. Fill: the dot operator sets the object's fields. show() prints that object's data.
  4. Another object: a second new gives a completely separate student. s1 == s2 is false.
  5. Surprise: s3 = s1 copies the reference. Changing marks through s3 changes the one object both point to.
  6. Crash: after s1 = null, there is no object behind s1, so calling a method on it throws NullPointerException.
Behind the screen
  1. When the program first uses Student, the JVM loads the class description into its method area. The heap has no Student objects yet.
  2. new reserves room on the heap for one Student and sets name = null, marks = 0. The stack variable s1 stores the object's reference.
  3. s1.name = "Riya" follows the arrow and writes into object #1. The arrow itself doesn't move.
  4. The second new creates object #2 with its own fields. == compares the arrows, which point to different objects.
  5. s3 = s1 copies the arrow. The write through s3 lands in #1, the same object s1 uses.
  6. s1 = null removes s1's arrow. Following a null reference is impossible, so the JVM throws. #1 isn't garbage yet: s3 still refers to it.
6 Real-world use

Classes and objects in real systems

Almost every Java application is a set of classes describing the things the business deals with, and objects for each real customer, order or account.

Watch it with an example: one Ride class, three bookings

A ride app writes the Ride class once. Every booking is a separate object made from it, with its own values.

Blueprint → objects on the heap 5 steps
Animated example
  1. The class: Ride describes what every ride has (from, to, fare) and can do (book). Writing it creates no ride yet.
  2. new Ride(…): the first booking creates object #1 on the heap, with its own copy of every field.
  3. Second booking: object #2, same shape, different values.
  4. Third booking: object #3. One class, as many objects as there are bookings.
  5. Independent: changing r1.fare changes only object #1. College ERPs, shopping carts and bank accounts all work this way: one class, thousands of objects.

1. College ERP and student records

A Student class with roll number, name, course and fees. Each admission creates one object; results, attendance and fee receipts all work on that object.

Admission form→new Student()→Marksheet, ID card

Every product on the site is a Product object (name, price, stock); each customer's cart is a Cart object holding references to products. Millions of objects, a handful of classes.

    int roll;
    int marks;

    void printCard() {
        System.out.println(roll + " | " + name + " | " + marks + " | " + result());
    }

    String result() {
        return marks >= 40 ? "PASS" : "FAIL";
    }
}

        b.name = "Kabir";

9 Quiz and revision

Check yourself

Quick revision

Lesson 6.1 in one screen

  • Class = blueprint (fields + methods). Object = instance created with new, stored on the heap.
  • Student s = new Student();: s is a reference variable holding the object's address.
  • Fields get defaults (0, 0.0, false, '\u0000', null); local variables don't.
  • Use the dot operator: s.name, s.show(). Methods work on the object they're called on.
  • t = s copies the reference: one object, two names. == compares references.
  • Calling a method or reading a field through null → NullPointerException at run time.
  • Only one public top-level class per file; each class becomes its own .class file.

Interview and viva questions

What is the difference between a class and an object?

A class is a blueprint written in code: it declares fields and methods. An object is a concrete instance created from that class at run time with new; it occupies heap memory and has its own field values. One class can produce any number of objects.

What does the new keyword do?

It asks the JVM to allocate memory for a new object of the class on the heap, sets all its fields to default values, runs the constructor (Lesson 6.2), and returns a reference to the object, which is usually stored in a variable.

Where are objects and reference variables stored?

Objects always live on the heap. A local reference variable lives in the method's stack frame and holds only the object's address. A reference that is a field lives inside its object on the heap.

What is a NullPointerException and how do you avoid it?

It's thrown when code uses a null reference as if it pointed to an object, for example calling a method or reading a field. Avoid it by creating objects before use, checking for null where a value may be missing, and not leaving reference fields unset. Since Java 15, the message also says exactly which reference was null (helpful NullPointerException messages).

Does Student b = a; create a copy of the object?

No. It copies the reference, so a and b point to the same object and changes through either are visible through both. To get a separate object you must create one with new and copy the field values.

P5Medium

Topper from an array of students

Store four students in a Student[] array and print the name and marks of the topper. Use a helper method make(name, marks) that creates and returns a filled Student.

Input
("Riya", 82), ("Kabir", 91), ("Meera", 76), ("Aman", 88)
Expected output
Topper: Kabir (91)
Show solution and explanation 
class Student {
    String name;
    int marks;
}

public class Main {
    static Student make(String name, int marks) {
        Student s = new Student();
        s.name = name;
        s.marks = marks;
        return s;
    }

    public static void main(String[] args) {
        Student[] cls = {
            make("Riya", 82), make("Kabir", 91), make("Meera", 76), make("Aman", 88)
        };
        Student top = cls[0];
        for (Student s : cls) {
            if (s.marks > top.marks) {
                top = s;
            }
        }
        System.out.println("Topper: " + top.name + " (" + top.marks + ")");
    }
}
Topper: Kabir (91)

How it works: the array holds 4 references, each pointing to a Student object. top is just another reference that we move to whichever object is best so far; no student is copied. make returns the reference of the object it created, so the object survives after the method's frame is popped.

P6Medium

Temperature converter object

A Temperature object stores a value in Celsius. Add methods toFahrenheit() and isHot() (above 35 °C). Test it for Delhi (42.5) and Shimla (18.0).

Input
Delhi 42.5 °C, Shimla 18.0 °C
Expected output
Delhi: 42.5 C = 108.5 F, hot? true
Shimla: 18.0 C = 64.4 F, hot? false
Show solution and explanation 
class Temperature {
    String city;
    double celsius;

    double toFahrenheit() {
        return celsius * 9 / 5 + 32;
    }

    boolean isHot() {
        return celsius > 35;
    }

    void report() {
        System.out.println(city + ": " + celsius + " C = " + toFahrenheit() + " F, hot? " + isHot());
    }
}

public class Main {
    public static void main(String[] args) {
        Temperature delhi = new Temperature();
        delhi.city = "Delhi";
        delhi.celsius = 42.5;
        Temperature shimla = new Temperature();
        shimla.city = "Shimla";
        shimla.celsius = 18.0;
        delhi.report();
        shimla.report();
    }
}
Delhi: 42.5 C = 108.5 F, hot? true Shimla: 18.0 C = 64.4 F, hot? false

How it works: report() calls toFahrenheit() and isHot() without any object name in front. Inside a method, calling another method of the same class works on the same object, so delhi's report uses delhi's temperature.

P7Medium

Safe withdrawal

Write a Wallet class with balance and a method pay(amount) that returns true and deducts the amount only if the balance is enough. Try paying 300, then 900, from a wallet with Rs 1000.

Input
balance = 1000; pay(300); pay(900)
Expected output
Pay 300: true, balance 700
Pay 900: false, balance 700
Show solution and explanation 
class Wallet {
    int balance;

    boolean pay(int amount) {
        if (amount > balance) {
            return false;
        }
        balance -= amount;
        return true;
    }
}

public class Main {
    public static void main(String[] args) {
        Wallet w = new Wallet();
        w.balance = 1000;
        System.out.println("Pay 300: " + w.pay(300) + ", balance " + w.balance);
        System.out.println("Pay 900: " + w.pay(900) + ", balance " + w.balance);
    }
}
Pay 300: true, balance 700 Pay 900: false, balance 700

How it works: the rule "never go below zero" lives inside the class, next to the data it protects, so every caller gets the same check. In Lesson 7.1 you'll make balance private so nobody can skip the method and change it directly.

P8Business problem

Restaurant bill with GST

A restaurant order has three items. Create a MenuItem class (name, price, quantity) with a method amount(). Print each line, the subtotal, 5% GST and the grand total.

Input
("Masala Dosa", 120, 2), ("Filter Coffee", 40, 3), ("Gulab Jamun", 60, 1)
Expected output
Masala Dosa x2 = Rs 240
Filter Coffee x3 = Rs 120
Gulab Jamun x1 = Rs 60
Subtotal: Rs 420
GST 5%: Rs 21.0
Total: Rs 441.0
Show solution and explanation 
class MenuItem {
    String name;
    int price;
    int qty;

    int amount() {
        return price * qty;
    }
}

public class Main {
    static MenuItem item(String name, int price, int qty) {
        MenuItem m = new MenuItem();
        m.name = name;
        m.price = price;
        m.qty = qty;
        return m;
    }

    public static void main(String[] args) {
        MenuItem[] order = {
            item("Masala Dosa", 120, 2),
            item("Filter Coffee", 40, 3),
            item("Gulab Jamun", 60, 1)
        };
        int subtotal = 0;
        for (MenuItem m : order) {
            System.out.println(m.name + " x" + m.qty + " = Rs " + m.amount());
            subtotal += m.amount();
        }
        double gst = subtotal * 0.05;
        System.out.println("Subtotal: Rs " + subtotal);
        System.out.println("GST 5%: Rs " + gst);
        System.out.println("Total: Rs " + (subtotal + gst));
    }
}
Masala Dosa x2 = Rs 240 Filter Coffee x3 = Rs 120 Gulab Jamun x1 = Rs 60 Subtotal: Rs 420 GST 5%: Rs 21.0 Total: Rs 441.0

How it works:

  1. Each line of the bill is one object, so name, price and quantity can't get mixed up between items.
  2. The line amount is calculated by the object itself (amount()); main only adds the results.
  3. GST is applied once on the subtotal. Real billing systems round money carefully (and often use BigDecimal); here the values are exact.
P9Business problem

Low-stock alert for a kirana store

A store tracks products with name, stock and reorder level. Print every product whose stock is at or below its reorder level, and how many units to order to bring it back to twice the reorder level.

Input
("Atta 5kg", 12, 10), ("Toor Dal 1kg", 4, 8), ("Sugar 1kg", 25, 15), ("Mustard Oil 1L", 6, 6)
Expected output
Reorder Toor Dal 1kg: 12 units
Reorder Mustard Oil 1L: 6 units
2 of 4 products need reordering
Show solution and explanation 
class Product {
    String name;
    int stock;
    int reorderLevel;

    boolean needsReorder() {
        return stock <= reorderLevel;
    }

    int unitsToOrder() {
        return 2 * reorderLevel - stock;
    }
}

public class Main {
    static Product p(String name, int stock, int level) {
        Product x = new Product();
        x.name = name;
        x.stock = stock;
        x.reorderLevel = level;
        return x;
    }

    public static void main(String[] args) {
        Product[] shelf = {
            p("Atta 5kg", 12, 10), p("Toor Dal 1kg", 4, 8),
            p("Sugar 1kg", 25, 15), p("Mustard Oil 1L", 6, 6)
        };
        int count = 0;
        for (Product item : shelf) {
            if (item.needsReorder()) {
                System.out.println("Reorder " + item.name + ": " + item.unitsToOrder() + " units");
                count++;
            }
        }
        System.out.println(count + " of " + shelf.length + " products need reordering");
    }
}
Reorder Toor Dal 1kg: 12 units Reorder Mustard Oil 1L: 6 units 2 of 4 products need reordering

How it works:

  1. Every product carries its own reorder level, so different items can have different rules.
  2. The decision (needsReorder) and the calculation (unitsToOrder) are methods of Product, so the loop in main reads like plain English.
  3. Toor Dal: 2 × 8 − 4 = 12 units. Mustard Oil is exactly at its level (6 ≤ 6), so it is included.
P10Business problem

Monthly salary slip

Create an Employee class with name, basic pay and HRA. Add methods for gross pay, PF (12% of basic) and net pay (gross − PF). Print slips for two employees.

Input
("Sneha", basic 30000, HRA 12000), ("Rahul", basic 45000, HRA 18000)
Expected output
Sneha: gross Rs 42000, PF Rs 3600, net Rs 38400
Rahul: gross Rs 63000, PF Rs 5400, net Rs 57600
Show solution and explanation 
class Employee {
    String name;
    int basic;
    int hra;

    int gross() {
        return basic + hra;
    }

    int pf() {
        return basic * 12 / 100;
    }

    int net() {
        return gross() - pf();
    }

    void printSlip() {
        System.out.println(name + ": gross Rs " + gross() + ", PF Rs " + pf() + ", net Rs " + net());
    }
}

public class Main {
    public static void main(String[] args) {
        Employee e1 = new Employee();
        e1.name = "Sneha";
        e1.basic = 30000;
        e1.hra = 12000;

        Employee e2 = new Employee();
        e2.name = "Rahul";
        e2.basic = 45000;
        e2.hra = 18000;

        e1.printSlip();
        e2.printSlip();
    }
}
Sneha: gross Rs 42000, PF Rs 3600, net Rs 38400 Rahul: gross Rs 63000, PF Rs 5400, net Rs 57600

How it works:

  1. Only the inputs (basic, HRA) are stored as fields. Gross, PF and net are calculated by methods, so they can never be out of date.
  2. net() reuses gross() and pf(); change the PF rule in one place and every slip follows.
  3. Sneha: 42000 − 3600 = 38400. Real payroll has many more components (tax, professional tax, allowances); this keeps the structure.

Real-world scenario questions (asked in company interviews)

Objects and references are where many real production bugs start. Decide your answer first, then open the model answer.

E-commerce · cartsFresher

“Two customers, one cart”

For a "buy again" feature, a developer writes Cart newCart = oldOrder.cart; and then adds today's items to newCart. Customers complain that their past order history now shows items they never bought in that order. What went wrong?

The interviewer is checking: do you know that assigning a reference doesn't copy the object?

Show a strong answer
  • newCart = oldOrder.cart copies the reference, so both variables point to the same Cart object. Adding to newCart changed the old order's cart.
  • Fix: create a new object (new Cart()) and copy the items into it, so the old order stays untouched.
  • Past orders should ideally never change at all: store them as read-only snapshots.

Avoid: saying "Java copied the cart wrongly". Java never copies objects on assignment.

Banking · KYCFresher

The statement job that crashes on one customer

A nightly job prints customer.nominee.name on each account statement. It runs fine for months, then crashes with a NullPointerException on a newly opened account. Why, and how would you fix it?

The interviewer is checking: do you know default null fields and defensive handling of optional data?

Show a strong answer
  • The new customer has no nominee yet, so the reference field nominee still has its default value, null. Reading .name through null throws.
  • Fix: check before use, if (customer.nominee != null), and print "Not registered" otherwise.
  • Also decide which fields are mandatory and make sure they are always set when the object is created (constructors, Lesson 6.2).
  • One bad record shouldn't stop the whole batch: log it and continue with the next account.

Avoid: wrapping everything in a catch that hides the error. Handle the missing value on purpose.

Fintech · onboarding1–3 years

Duplicate PAN check that never finds duplicates

Sign-up code builds a Customer object from the form and checks if (newCustomer == existingCustomer) against each stored customer to block duplicate PAN numbers. Duplicates are never caught, even when every field matches. Explain.

The interviewer is checking: do you understand reference equality versus comparing data?

Show a strong answer
  • == on references asks "same object?". The form creates a brand-new object, so it is never the same object as one already stored, whatever its fields.
  • Compare the identifying data instead: newCustomer.pan.equals(existing.pan) (String comparison from Lesson 4.4).
  • In a real system, put a unique constraint on PAN in the database too, so two parallel sign-ups can't both succeed.

Avoid: comparing every field by hand everywhere. Later you'll define equals() once in the class (Lesson 10.3).

Logistics · code review1–3 years

Parallel arrays that went out of sync

A shipment tracker keeps String[] awb, String[] city and int[] weight, linked by index. A teammate sorted weight for a "heaviest first" report, and now parcels show the wrong cities. You're asked to review the design. What do you propose?

The interviewer is checking: can you see why related data belongs in one object?

Show a strong answer
  • Sorting one array moved its values but not the matching entries in the others. Nothing in the code ties index 5 of each array together.
  • Create a Shipment class with awb, city and weight fields, and keep one Shipment[] (or a list).
  • Sorting the shipments now moves whole objects, so the data can't separate. Adding a new field means changing one class, not every array.

Avoid: "Sort all three arrays the same way." It works until someone forgets one.
