The final keyword

Some values should never change once set: a GST rate, an account number, the rules of a payment flow. The final keyword lets the compiler guarantee that. You'll see final variables and fields (including blank finals), effectively final variables, final parameters, final methods and classes, the difference between a final reference and an immutable object, and then practise with 10 problems.

Module 7 · OOP Pillars⏱ 21 minIntermediate10 practice problems
1 The story

The GST rate that changed overnight

Riya's billing app has static double GST_RATE = 0.18;. A teammate, testing a luxury-goods feature, writes GST_RATE = 0.28; inside one method. From then on, every bill the app prints charges 28% GST, including for tea and notebooks.

Riya

Sir, it was meant to be a constant. How did one line in a test method change it for everyone?

Arjun Sir

Because nothing told Java it was a constant. Add final: static final double GST_RATE = 0.18;. Then that line won't even compile.

Riya

Is final only for constants?

Arjun Sir

No. On a variable it means "assign once"; on a method, "no overriding"; on a class, "no subclasses". One word, three kinds of lock, all checked by the compiler.

2 Definition

What does final mean?

Formal definition (write this in exams)

final is a non-access modifier. A final variable (local, parameter, instance or static field) can be assigned exactly once; a final field with no initializer is a blank final and must be definitely assigned in every constructor (or a static initializer, for static fields). A final method cannot be overridden by subclasses. A final class cannot be extended. For a reference variable, final fixes the reference, not the state of the object it refers to.

In simple words

final variable: write once. final method: children can't change it. final class: no children at all. A final reference is a label glued to one box; you can still change what's inside the box.

Words you'll meet in this lesson

Constantstatic final field, named in CAPITALS: GST_RATE.
Blank finalA final field declared without a value; each constructor must set it once.
Effectively finalA local variable never reassigned, even without the keyword (Java 8).
final parameterA parameter the method body can't reassign.
final methodA method subclasses can't override.
final classA class nobody can extend, like String.

final at a glance

Local variableAssign once: final int x = 5; x = 6; → cannot assign a value to final variable x
Instance fieldSet at declaration, in an initializer block, or in every constructor. Missing → variable rate might not have been initialized
Static fieldSet at declaration or in a static block. Together, static final = a class constant.
Parameterfinal double amount: final parameter amount may not be assigned
MethodCan't be overridden: overridden method is final. Still inherited and callable.
ClassCan't be extended: cannot inherit from final String. All its methods are effectively final.

Exam tip: final, finally and finalize are a favourite trick question. final is this keyword; finally is a block that always runs after try/catch (Lesson 9.2); finalize() was an Object method for cleanup before garbage collection, deprecated since Java 9.

All three, plus a blank final

final class Invoice {                          // final class: can't be extended
    static final double GST_RATE = 0.18;       // constant
    private final String number;               // blank final: set in the constructor
    private final double amount;

    Invoice(String number, double amount) {
        this.number = number;                  // assigned exactly once
        this.amount = amount;
    }

    final double total() {                     // final method (already implied by final class)
        return amount + amount * GST_RATE;
    }

    String line() {
        return number + ": Rs " + total();
    }
}

public class Main {
    public static void main(String[] args) {
        final Invoice inv = new Invoice("INV-1042", 2000);
        System.out.println(inv.line());
        final int[] qty = {2, 3};
        qty[0] = 5;                            // allowed: the array object can change
        System.out.println(qty[0] + qty[1]);
    }
}

4 Step by step

How javac enforces final

  1. A final local is assigned once

    final double rate;
if (isSenior) rate = 7.5; else rate = 7.0;   // OK: exactly one assignment on each path
    javac does definite assignment analysis: on every path through the code, a final variable must be assigned once before use and never twice ("might already have been assigned").

  2. A blank final field is set in every constructor

    private final String accountNo;
Account(String no) { accountNo = no; }
Account() { this("SB-NEW"); }                 // delegates, so still assigned once
    If any constructor can finish without assigning it, javac reports "variable accountNo might not have been initialized". With no constructor at all: "not initialized in the default constructor".

  3. Effectively final for lambdas and inner classes

    int limit = 5000;                        // never reassigned → effectively final
Runnable r = () -> System.out.println(limit);
    A lambda captures a copy of the local's value. Java requires the local to be final or effectively final so the copy can never disagree with the original. Add limit++ anywhere and javac reports "must be final or effectively final".

  4. final methods lock the steps

    final String process() {
    return validate() + " → " + charge() + " → receipt";
}
    Subclasses still inherit and call process(), but can't replace it, so a step like validation can't be skipped. This is how template methods are protected (Lesson 7.6).

  5. final classes close the hierarchy

    class SafeString extends String { }      // ✗ cannot inherit from final String
    String is final so that nobody can create a subclass that breaks its immutability, which the string pool, hashing and security checks all rely on.
5 See it happen

What final locks, and what it doesn't: both views

Left: the code and what javac or the console says. Right: the variable, its fixed reference, and the object it points to.

final in six lines 6 steps
What you see
  1. final local: the value is fixed after the first assignment. The second line doesn't compile.
  2. Blank final field: accountNo has no value at declaration; the constructor sets it once, and it's read-only afterwards.
  3. Forgotten assignment: a constructor that leaves a blank final unset is a compile error.
  4. final reference: marks can't point elsewhere, but the array object it points to is still mutable.
  5. Reassign the reference: this is exactly what final forbids.
  6. final class: String is final, so no class can extend it.
Behind the screen
  1. For a final local, javac checks there is exactly one assignment. A final primitive initialised with a constant expression is a compile-time constant, which javac may inline wherever it's used.
  2. The blank final field lives in object #1 on the heap. The constructor gives it its only value.
  3. javac traces every path through each constructor. If one path can finish without setting the field, compilation fails.
  4. final on marks fixes the arrow from the stack to array #2. The elements inside #2 are ordinary, changeable slots.
  5. Assigning a new array would mean a new arrow. That's the one thing a final reference forbids.
  6. The class file of String is marked final; javac refuses any extends String, and the JVM would refuse to load such a class.
6 Real-world use

final in real systems

Experienced Java developers use final widely, because code that can't change by accident is easier to trust.

Watch it with an example: a payroll run that can't be tampered with

A payroll module fixes the PF rate, the holiday list reference and the run steps with final. Watch what final blocks, and what it doesn't.

final in a payroll run 6 steps
Animated example
  1. Constant: static final double PF = 0.12. Every payslip uses 12%: Rs 30,000 − 3,600 = Rs 26,400.
  2. Locked value: a test that writes PF = 0.10 doesn't compile, so a stray line can't change everyone's PF.
  3. final reference: holidays is final, yet add("Diwali") works: the list object itself is ordinary and changeable.
  4. What final blocks: pointing holidays at a different list is a compile error.
  5. Protecting contents: the getter hands out List.copyOf(holidays); trying to add to that copy throws UnsupportedOperationException.
  6. final method: run() is final in Payroll, so a FastPayroll subclass can't override it to skip PF or audit steps.

1. Business constants

Limits and fixed rates (maximum OTP attempts, a free-delivery threshold) are static final, so no code path can quietly change them. Values that change by environment go in configuration instead.

OTP check→tries < MAX_OTP_TRIES→same rule everywhere

2. Dependencies set in the constructor

Service classes keep their collaborators in private final fields assigned in the constructor. The service can never end up half-wired or switched to another object mid-request.

new OrderService(repo, sms)→final fields→fixed for life

3. Immutable value classes

The JDK's String, wrapper classes and java.time types are final classes with final fields. That's what makes them safe as map keys and safe to share between threads.

map.put(key, …)→String can't change→key stays findable

4. Protected workflows

Base classes in payment and security code mark workflow methods final, so subclasses can customise steps but can't skip audits or validations.

Gateway subclass→can't override process()→audit always runs

Examples are simplified. Some teams mark every local variable and parameter final as a style rule; others rely on "effectively final" and keep final for fields, methods and classes.

7 Run the code

A bank account that can't be tampered with

class Account {
    static final double MIN_BALANCE = 1000;     // constant for all accounts
    private final String accountNo;             // blank final
    private double balance;

    Account(String accountNo, double opening) {
        this.accountNo = accountNo;
        this.balance = opening;
    }

    final boolean withdraw(final double amount) {   // final method, final parameter
        if (balance - amount < MIN_BALANCE) {
            return false;
        }
        balance -= amount;
        return true;
    }

    String summary() {
        return accountNo + " Rs " + balance;
    }
}

class SalaryAccount extends Account {
    SalaryAccount(String no, double opening) { super(no, opening); }
    // cannot override withdraw(): it is final
}

public class Main {
    public static void main(String[] args) {
        final Account acc = new SalaryAccount("SAL-2201", 5000);
        System.out.println(acc.withdraw(3500) + " " + acc.summary());
        System.out.println(acc.withdraw(1000) + " " + acc.summary());
        System.out.println("Minimum: " + Account.MIN_BALANCE);
    }
}
true SAL-2201 Rs 1500.0 false SAL-2201 Rs 1500.0 Minimum: 1000.0
  • static final double MIN_BALANCEOne constant shared by every account; can't be reassigned anywhere.
  • private final String accountNoBlank final: set once by the constructor, never changed afterwards.
  • final boolean withdraw(final double amount)Subclasses can't override the rule; the method can't reassign its parameter.
  • final Account accThe variable always refers to this account; the account's balance can still change.

9 Quiz and revision

Check yourself

Quick revision

Lesson 7.8 in one screen

  • final variable: assigned exactly once (local, parameter, instance or static field).
  • Blank final field: no initializer; every constructor must set it once.
  • static final = constant, named in CAPITALS.
  • Effectively final: never reassigned; required for locals used in lambdas and inner classes.
  • final method: can't be overridden (still inherited). final class: can't be extended (String, Integer, Math).
  • A final reference can't point elsewhere, but the object it points to can still change.
  • abstract + final is illegal; final ≠ finally ≠ finalize().

Interview and viva questions

What is the difference between final, finally and finalize?

final is a modifier for variables, methods and classes. finally is a block after try/catch that always runs, used for cleanup. finalize() was a method on Object that the garbage collector might call before reclaiming an object; it's unreliable and has been deprecated since Java 9.

Does making a reference final make the object immutable?

No. final only stops the variable from being reassigned. An immutable object needs a design: private final fields, no setters, a final class, and defensive copies of mutable parts (Lesson 7.1). A final reference to an immutable object gives you both guarantees.

Why is the String class final?

String's immutability is relied on by the string pool, by hash-based collections (a key's hash must never change), by class loading and by security checks such as file paths and URLs. If String could be subclassed, a subclass could add mutable state or override methods and break all of those guarantees.

Can a final method be overloaded? Can a constructor be final?

Overloading is allowed: a method with the same name but different parameters is a different method. Constructors can't be final (or abstract or static); they're never inherited, so there's nothing to override and the modifier would be meaningless. javac rejects it.

Why must local variables used in a lambda be effectively final?

A lambda captures a copy of the local variable's value, and it may run later, even on another thread, after the method has returned. If the original could still change, the copy and the original could disagree. Requiring the variable to be final or effectively final avoids that confusion.

P1Easy

Constants for a fee calculator

Store the convenience fee percentage (2%) and the maximum fee (Rs 50) as static final constants and compute the fee for orders of Rs 800 and Rs 4,000.

Input
orders Rs 800 and Rs 4000
Expected output
Fee on 800: 16.0
Fee on 4000: 50.0
Show solution and explanation 
public class Main {
    static final double FEE_PERCENT = 2.0;
    static final double MAX_FEE = 50;

    static double fee(double order) {
        return Math.min(order * FEE_PERCENT / 100, MAX_FEE);
    }

    public static void main(String[] args) {
        System.out.println("Fee on 800: " + fee(800));
        System.out.println("Fee on 4000: " + fee(4000));
    }
}
Fee on 800: 16.0 Fee on 4000: 50.0

How it works: 2% of 800 = 16; 2% of 4000 = 80, capped at 50. Constants are written in CAPITALS by convention. Any line like MAX_FEE = 100; would fail to compile.

Use a local variable threshold (never reassigned) inside a lambda that checks whether an order amount is large. Test it with Rs 1,200 and Rs 12,000.

P7Medium

An immutable Money class

Write a final class Money with a private final long paise field, a plus method that returns a new Money, and a toString that shows rupees. Add Rs 199.50 and Rs 50.75.

Input
Rs 199.50 + Rs 50.75
Expected output
Rs 199.50 + Rs 50.75 = Rs 250.25
Show solution and explanation 
final class Money {
    private final long paise;

    Money(long paise) {
        this.paise = paise;
    }

    Money plus(Money other) {
        return new Money(paise + other.paise);
    }

    @Override
    public String toString() {
        return String.format("Rs %d.%02d", paise / 100, paise % 100);
    }
}

public class Main {
    public static void main(String[] args) {
        Money a = new Money(19950);
        Money b = new Money(5075);
        Money total = a.plus(b);
        System.out.println(a + " + " + b + " = " + total);
    }
}
Rs 199.50 + Rs 50.75 = Rs 250.25

How it works: final class (no subclass can add setters), private final field (no reassignment), and plus returns a new object, so a and b never change. Storing paise as a long avoids floating-point rounding with money.

P8Business problem

Bank account with a final account number and minimum balance

Every account has a final account number, a constant minimum balance of Rs 2,000 for all accounts, and a final withdraw rule. Withdraw Rs 6,000 and then Rs 3,000 from an account opened with Rs 10,000.

Input
open Rs 10,000; withdraw 6000, then 3000
Expected output
Withdraw 6000: true -> SB-55021: Rs 4000.0
Withdraw 3000: false -> SB-55021: Rs 4000.0
Show solution and explanation 
class BankAccount {
    static final double MIN_BALANCE = 2000;
    private final String accountNo;
    private double balance;

    BankAccount(String accountNo, double opening) {
        this.accountNo = accountNo;
        this.balance = opening;
    }

    final boolean withdraw(double amount) {
        if (amount <= 0 || balance - amount < MIN_BALANCE) return false;
        balance -= amount;
        return true;
    }

    String statement() {
        return accountNo + ": Rs " + balance;
    }
}

public class Main {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount("SB-55021", 10000);
        System.out.println("Withdraw 6000: " + acc.withdraw(6000) + " -> " + acc.statement());
        System.out.println("Withdraw 3000: " + acc.withdraw(3000) + " -> " + acc.statement());
    }
}
Withdraw 6000: true -> SB-55021: Rs 4000.0 Withdraw 3000: false -> SB-55021: Rs 4000.0

How it works:

  1. The account number is a blank final; the minimum is a shared constant; the withdraw rule can't be overridden by any account subclass.
  2. 10,000 − 6,000 = 4,000 is fine; 4,000 − 3,000 = 1,000 is below 2,000, so it's refused.
  3. The balance itself is deliberately not final: it must change.
P9Business problem

Payroll run with final configuration

A payroll run uses fixed settings for the month: PF rate 12% of basic, professional tax Rs 200. Put them in a final configuration object with final fields, and compute net pay for three employees.

Input
basics: Anil 30000, Sara 45000, Kiran 80000
Expected output
Anil   net Rs 26,200.00
Sara   net Rs 39,400.00
Kiran  net Rs 70,200.00
Show solution and explanation 
final class PayrollConfig {
    final double pfRate;
    final int professionalTax;

    PayrollConfig(double pfRate, int professionalTax) {
        this.pfRate = pfRate;
        this.professionalTax = professionalTax;
    }
}

public class Main {
    static double net(double basic, PayrollConfig cfg) {
        return basic - basic * cfg.pfRate - cfg.professionalTax;
    }

    public static void main(String[] args) {
        final PayrollConfig cfg = new PayrollConfig(0.12, 200);
        String[] names = {"Anil", "Sara", "Kiran"};
        double[] basics = {30000, 45000, 80000};
        for (int i = 0; i < names.length; i++) {
            System.out.printf("%-6s net Rs %,.2f%n", names[i], net(basics[i], cfg));
        }
    }
}

How it works:

  1. Because the class is final and its fields are final, nothing during the run can change the rates halfway through.
  2. Anil: 30,000 − 3,600 − 200 = 26,200. Sara: 45,000 − 5,400 − 200 = 39,400. Kiran: 80,000 − 9,600 − 200 = 70,200.
  3. Next month's settings would be a new PayrollConfig object. (Rates here are simplified for teaching.)
P10Business problem

Delivery slots that can't be swapped out

A delivery hub keeps private final List<String> slots. Expose the slots safely so a caller can read them but cannot clear them, and show that trying to clear the returned list fails while the hub's slots stay intact.

Input
slots "9-11", "11-1", "4-6"
Expected output

import java.util.ArrayList;
import java.util.List;

class DeliveryHub {
    private final List<String> slots = new ArrayList<>();

    DeliveryHub() {
        slots.add("9-11");
        slots.add("11-1");
        slots.add("4-6");
    }

    List<String> getSlots() {
        return List.copyOf(slots);
    }
}

public class Main {
    public static void main(String[] args) {

        List<String> view = hub.getSlots();
        try {
            view.clear();
        } catch (UnsupportedOperationException e) {

Clear refused: the list is unmodifiable Hub slots: [9-11, 11-1, 4-6]

How it works:

  1. final on the field guarantees the hub always uses the same list object.
  2. But final alone would still let callers clear() it through a getter that returns the field. List.copyOf (Java 10+) returns an unmodifiable copy, so clear() throws UnsupportedOperationException.
  3. Together: a fixed reference to data that only the hub can change.

Real-world scenario questions (asked in company interviews)

final turns "please don't change this" into a rule the compiler checks. Decide your answer first, then open the model answer.

Billing · constantsFresher

The tax rate that changed in production

A billing service has public static double GST_RATE = 0.18;. A new report feature sets GST_RATE = 0.12 to calculate a scenario, and for the next hour all invoices use 12%. What's the fix, and what else would you check?

The interviewer is checking: do you know how to make true constants?

Show a strong answer
  • Declare it public static final double GST_RATE = 0.18;. The report's assignment then fails to compile; the report should use a local variable for its scenario.
  • Search for other public static non-final fields: each one is shared mutable state that any code can change.
  • Since GST rates differ by product category and change by notification, consider loading rates from configuration or a rate table, keeping each loaded value immutable.

Avoid: making it private but adding a public setter. That just moves the problem.

Fintech · security1–3 years

A subclass that skipped the audit

A PaymentProcessor base class has process() that validates, charges and writes an audit record. A team building a new wallet subclass overrode process() for speed and skipped the audit. How do you prevent this?

The interviewer is checking: do you know when to make methods final?

Show a strong answer
  • Make process() final so it can't be overridden, and expose the varying part as an abstract or protected step such as charge() (template method, Lesson 7.6).
  • Make helper steps that must never change (audit()) private or final.
  • Add a test that checks an audit record exists for every processor type.

Avoid: a comment saying "please call super.process()". Comments aren't enforced.

E-commerce · code review1–3 years

"It's final, so it's safe"

A developer says the Cart class is safe because it has private final List<Item> items and a getter. A bug report shows that a discount module emptied a customer's cart by calling getItems().clear(). Explain to the developer what went wrong.

The interviewer is checking: do you understand final reference vs immutable object?

Show a strong answer
  • final means items always refers to the same list, but that list is still a normal, changeable ArrayList, and the getter hands it out.
  • Return List.copyOf(items) or Collections.unmodifiableList(items); changes then go only through Cart's methods (addItem, removeItem) which validate.
  • final is still useful here: it guarantees the cart never swaps to a different list, so the protection above can't be bypassed by reassignment.

Avoid: treating final as a synonym for immutable.

SaaS · concurrency3+ years

Configuration shared across threads

A multi-tenant service builds a TenantConfig object at start-up and shares it across hundreds of request threads. A teammate proposes adding setters so admins can change limits at run time. What design would you suggest, and where does final help?

The interviewer is checking: do you know that final fields help safe publication of immutable objects?

Show a strong answer
  • Keep TenantConfig immutable: a final class with private final fields and no setters. Java's memory model guarantees that other threads see final fields correctly initialised once the constructor finishes, without locks.
  • To change limits, build a new TenantConfig and swap a single shared reference atomically (for example AtomicReference, Module 12).
  • Each request reads the reference once, so it sees one consistent configuration.

Avoid: setters on a shared object, which give threads half-updated, inconsistent views.
