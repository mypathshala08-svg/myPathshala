Parameters and return values

A method is useful only if you can hand it data and get an answer back. Parameters are the inputs, the return value is the output, and Java checks both strictly at compile time. You'll see how arguments are matched by position, how guard clauses return early, how to return several values in an array, and the three compile errors every beginner meets, and then practise with 12 problems.

1 The story

The discount that charged too much

Riya is adding a festival discount to the college bookshop's billing program. She writes discount(price, percent) and tests it: 10% off Rs 500 gives Rs 450. Then her friend calls it as discount(10, 500), and a Rs 500 book now costs minus Rs 40.

Riya

Sir, Java is so strict about types. Why didn't it stop him from swapping the numbers?

Arjun Sir

Because both are numbers, and 10 and 500 both fit. Java matches arguments to parameters by position and checks only that the types fit. It doesn't know which number you meant as the price.

Riya

So I should check bad inputs inside the method too?

Arjun Sir

Yes. Put a guard clause at the top: if the percent is outside 0 to 100, return early. Today you'll learn exactly how values go in and come out of a method, and what javac checks on both sides.

2 Definition

What are parameters and return values?

Formal definition (write this in exams)

A parameter (formal parameter) is a variable declared in a method's header that receives a value when the method is called. An argument (actual parameter) is the value supplied in the call. Arguments are evaluated left to right and assigned to parameters by position; their number must match and each must be assignable to the parameter's type. A method's return type declares the type of the single value it sends back with a return statement, or void if it returns nothing.

In simple words

Parameters are the empty slots in an order form. Arguments are what you write in the slots when you place an order. The return value is the parcel that comes back. The slots are filled in order, so writing the quantity in the price box gives a wrong order.

Words you'll meet in this lesson

ParameterThe variable in the header: price in discount(double price, …).
ArgumentThe value in the call: 500 in discount(500, 10).
Parameter listAll parameters in order, with types, separated by commas.
Return valueThe one value a method sends back to its caller.
Early returnLeaving a method before its last line, from inside an if or loop.
Guard clauseAn early check at the top that rejects bad input and returns.

The rules javac checks

CountSame number of arguments as parameters (for now; varargs in Lesson 5.6 relax this)
Order and typeMatched by position. Each argument must fit its parameter's type: int → double is fine (widening), double → int is not
NamesDon't matter. The caller's variable names have nothing to do with the parameter names
Return typeEvery return must give a value that fits the declared type
Every pathA non-void method must return on every possible path, or it's a compile error
One valueOnly one value comes back; to return several, return an array or an object

Exam tip: know the three compile errors by their exact words: missing return statement (some path doesn't return), unreachable statement (code after a return), and incompatible types (wrong type returned or passed, e.g. possible lossy conversion from double to int).

Guard clauses: handle the bad cases first

public class Main {
    static double discount(double price, int percent) {
        if (percent <= 0) {
            return price;              // guard: nothing to discount
        }
        return price - price * percent / 100;
    }

    public static void main(String[] args) {
        double a = discount(500, 10);
        double b = discount(800, 0);
        System.out.println(a + " " + b);
    }
}

4 Step by step

From call to returned value

  1. The caller evaluates the arguments

    double a = discount(400 + 100, 10);
    Each argument expression is calculated first, left to right: 400 + 100 becomes 500. Only the resulting values are passed.

  2. Values are copied into the parameters, by position

    static double discount(double price, int percent)
    A new frame is pushed. The 1st value goes to the 1st parameter, the 2nd to the 2nd. The int 500 is widened to 500.0 to fit double price. javac already checked at compile time that every argument fits.

  3. Guard clauses reject bad input

    if (percent <= 0) {
    return price;
}
    A return ends the method immediately, wherever it appears. The lines below it don't run for this call.

  4. The main path computes and returns

    return price - price * percent / 100;
    The expression is evaluated, converted to the return type if needed (only widening is automatic), and handed to the caller. The method's frame is popped.

  5. The caller uses the value

    double a = discount(500, 10);   // a = 450.0
    In the caller, the call expression is replaced by the returned value. It can be stored, printed, or passed straight into another call. If you ignore it, it is simply thrown away.
5 See it happen

Values in, value out: both views

Left: the line running and its effect. Right: arguments landing in parameter slots, and the returned value going back to main.

Two calls to discount 6 steps
What you see
  1. Call: discount(500, 10). The arguments are worked out first; main waits for an answer.
  2. Parameters filled: first argument → first parameter, second → second. The int 500 becomes 500.0.
  3. Guard, then formula: the percent is positive, so the guard doesn't fire, and the method computes 450.0.
  4. Returned: a gets 450.0. The method's work is finished.
  5. Early return: with a percent of 0 the guard fires and returns the price unchanged. The formula line never runs.
  6. Output: the real output of the program is 450.0 800.0.
Behind the screen
  1. The call has two argument values. If an argument were an expression like 400 + 100, it would be calculated first.
  2. A new frame is pushed. Values are copied into parameter slots strictly by position; the int 500 is widened for the double slot.
  3. Inside the method, price and percent behave like normal local variables of this frame.
  4. return sends exactly one value back and the frame is popped. main stores it in a.
  5. The second call gets its own fresh frame. The guard clause returns the price at once.
  6. Both values now live in main's frame, and the method's frames are long gone.
6 Real-world use

Parameters and returns in real systems

In real code, a method's header is a contract: what it needs, and what it promises to give back. Teams read headers far more often than bodies.

Watch it with an example: an EMI calculator

emi(60000, 12): the arguments are copied into the parameters, the method works with its own copies, and one value travels back with return.

Arguments in, return value out 5 steps
Animated example
  1. The call: emi(60000, 12) passes two arguments. Their order matters: the first goes to the first parameter.
  2. Copying: a new frame is created. Parameters principal and months receive copies of 60000 and 12.
  3. Guard clause: the method first rejects bad input (months must be positive), then computes 60000 / 12 = 5000.
  4. return: sends exactly one value back to the place it was called from. The method ends immediately.
  5. Result: the frame is popped and monthly = 5000. EMI, tax and insurance-premium calculators are all methods like this. (Real EMI formulas include interest; this is a no-cost EMI.)

1. Guard clauses in payment and banking code

Transfer and withdrawal methods start with checks: amount positive, account active, balance sufficient, daily limit not crossed. Each failed check returns or rejects immediately, so the money-moving line runs only when everything is valid.

Transfer request→if (amount <= 0) return …→Safe debit

2. Calculators: EMI, tax, premium

Loan EMI, income tax and insurance premium calculators are methods with several parameters and one returned number. The same method serves the website, the mobile app and the bank officer's screen.

Amount, rate, tenure→emi(p, rate, months)→Monthly EMI

3. Returning several results together

A report method may need to give back a count, a total and a maximum. Beginners return an array; production code returns an object or a record with named fields (Modules 6 and 14), so callers can't mix up the positions.

Day's orders→return new int[]{count, total, max}→Dashboard

4. The compiler as a safety net

Because parameter and return types are checked at compile time, a whole class of bugs never reaches production: passing text where a number is needed, or forgetting to return a value on some path.

Wrong type→javac error→Fixed before release

Examples are simplified. Real financial code uses BigDecimal for money and named result objects instead of arrays.

7 Run the code

A weekly sales summary

public class Main {
    static int[] minMax(int[] values) {
        int min = values[0];
        int max = values[0];
        for (int v : values) {
            if (v < min) min = v;
            if (v > max) max = v;
        }
        return new int[]{min, max};
    }

    static double average(int[] values) {
        if (values.length == 0) {
            return 0;
        }
        int sum = 0;
        for (int v : values) {
            sum += v;
        }
        return (double) sum / values.length;
    }

    public static void main(String[] args) {
        int[] sales = {4200, 3900, 5100, 4700, 3600};
        int[] range = minMax(sales);
        System.out.println("Lowest day: Rs " + range[0]);
        System.out.println("Best day: Rs " + range[1]);
        System.out.println("Average: Rs " + average(sales));
        System.out.println("No sales yet: Rs " + average(new int[0]));
    }
}
Lowest day: Rs 3600 Best day: Rs 5100 Average: Rs 4300.0 No sales yet: Rs 0.0
  • static int[] minMax(int[] values)Takes an array, returns a new two-element array: index 0 = min, index 1 = max.
  • if (values.length == 0) return 0;A guard clause: avoids dividing by zero. The int 0 widens to 0.0 for the double return type.
  • (double) sum / values.lengthCast first so the average keeps its decimals (Lesson 2.4).
  • average(new int[0])An argument can be any expression of the right type, even a brand-new empty array.

9 Quiz and revision

Check yourself

Quick revision

Lesson 5.2 in one screen

  • Parameters are in the header; arguments are the values in the call.
  • Arguments are evaluated left to right and matched by position; names don't matter.
  • Count and types must fit: widening (int → double) is automatic, narrowing is a compile error.
  • A non-void method must return a value of its type on every path.
  • return ends the method at once; guard clauses use this to reject bad input early.
  • Only one value comes back; return an array (or object) for several.
  • Errors to recognise: missing return statement, unreachable statement, incompatible types.

Interview and viva questions

What is the difference between a parameter and an argument?

A parameter is the variable declared in the method header; it exists in the method's frame while the call runs. An argument is the actual value passed in a particular call. In square(5), 5 is the argument and n in square(int n) is the parameter.

Can a Java method return more than one value?

Not directly; a method has exactly one return value. To return several, return an array, a collection, or an object (a class or a record) whose fields hold the values. Objects are preferred because the fields have names.

What is a guard clause and why is it preferred over nested if-else?

A guard clause is an early check that handles an invalid or special case and returns immediately. It keeps the main logic at the left margin instead of buried in nested blocks, makes each rule easy to see, and ensures the main calculation only runs on valid input.

Why does javac report "missing return statement" when my if and else-if both return?

javac checks every possible path. If neither condition is true, execution reaches the end of the method without a return. Adding a final else or a last return covers that path. javac does not reason about which values are actually possible at run time.

Can a void method contain a return statement?

Yes, but only return; without a value, used to leave the method early. return 1; in a void method is a compile error: incompatible types: unexpected return value.

Power without Math.pow

public class Main {

        long result = 1;
        for (int i = 1; i <= exp; i++) {

Return a reversed copy

Write reversed(int[] a) that returns a new array with the elements in reverse order, leaving the original unchanged.

import java.util.Arrays;

public class Main {
    static int[] reversed(int[] a) {
        int[] result = new int[a.length];
        for (int i = 0; i < a.length; i++) {
            result[i] = a[a.length - 1 - i];
        }
        return result;
    }

    public static void main(String[] args) {
        int[] a = {10, 20, 30, 40};
        int[] r = reversed(a);
        System.out.println("Original: " + Arrays.toString(a));
        System.out.println("Reversed: " + Arrays.toString(r));
    }
}
Original: [10, 20, 30, 40] Reversed: [40, 30, 20, 10]

How it works: the method creates a new array on the heap and returns its reference. The local variable result disappears when the method returns, but the array lives on because r in main now refers to it.

P8Medium

Minimum and maximum in one call

A method can return only one value, but that value can be an array. Write minMax(int[] a) that returns {min, max}.

P9Medium

Greatest common divisor

Write gcd(int a, int b) using Euclid's method: replace (a, b) with (b, a % b) until b is 0. Use it to simplify a fraction.

Input
fraction 84 / 126
Expected output
gcd = 42
84/126 = 2/3
Show solution and explanation 
public class Main {
    static int gcd(int a, int b) {
        while (b != 0) {
            int r = a % b;
            a = b;
            b = r;
        }
        return a;
    }

    public static void main(String[] args) {
        int num = 84, den = 126;
        int g = gcd(num, den);
        System.out.println("gcd = " + g);
        System.out.println(num + "/" + den + " = " + (num / g) + "/" + (den / g));
    }
}
gcd = 42 84/126 = 2/3

How it works: inside the method, a and b are changed freely; they are copies, so num and den in main keep their values. 84, 126 → 126, 84 → 84, 42 → 42, 0, so the gcd is 42.

P10Business problem

Loan EMI calculator

Write emi(double principal, double annualRatePercent, int months) using EMI = P × r × (1 + r)n / ((1 + r)n − 1), where r is the monthly rate. Guard: if the rate is 0, the EMI is simply P / n. Print the EMI rounded to 2 decimals.

Input
Rs 5,00,000 at 9% for 60 months
Rs 60,000 at 0% for 12 months
Expected output
EMI: Rs 10379.18
EMI: Rs 5000.00
Show solution and explanation 
public class Main {
    static double emi(double principal, double annualRatePercent, int months) {
        if (annualRatePercent == 0) {
            return principal / months;
        }
        double r = annualRatePercent / 12 / 100;
        double factor = Math.pow(1 + r, months);
        return principal * r * factor / (factor - 1);
    }

    public static void main(String[] args) {
        System.out.printf("EMI: Rs %.2f%n", emi(500000, 9, 60));
        System.out.printf("EMI: Rs %.2f%n", emi(60000, 0, 12));
    }
}
EMI: Rs 10379.18 EMI: Rs 5000.00

How it works:

  1. The guard clause handles the zero-interest offer separately; without it the formula would divide 0 by 0.
  2. (1 + r)n is computed once and stored in factor, then used twice.
  3. Three parameters of different meanings: passing months where the rate is expected would compile (int widens to double) but give nonsense, so read headers carefully.

GST breakup for an invoice line

public class Main {
    static int fare(int baseFare, int age) {
        if (age < 5) {
            return 0;
        }
        if (age >= 60) {
            return baseFare * 60 / 100;
        }
        return baseFare;
    }

    public static void main(String[] args) {
        int[] ages = {4, 34, 31, 63};
        int total = 0;
        for (int age : ages) {
            int f = fare(850, age);
            System.out.println("Age " + age + ": Rs " + f);
            total += f;
        }
        System.out.println("Family total: Rs " + total);
    }
}
Age 4: Rs 0 Age 34: Rs 850 Age 31: Rs 850 Age 63: Rs 510 Family total: Rs 2210

How it works:

  1. Each special case returns immediately, so the code reads as a list of rules, without nested if-else.
  2. 40% off means paying 60%: 850 × 60 / 100 = 510. Multiplying before dividing keeps the int arithmetic exact here.
  3. The order of arguments matters: swapping them as fare(34, 850) still compiles (both are int), but the method then treats 850 as the age and returns Rs 20.

Real-world scenario questions (asked in company interviews)

Most method bugs in real systems are about inputs that weren't checked and results that were misread. Decide your answer first, then open the model answer.

E-commerce · pricingFresher

A product sold at a negative price

A method applyDiscount(double price, int percent) is called from a new campaign screen, which keeps both values as int, as applyDiscount(percent, price). The code compiles and a Rs 1,200 jacket is shown at a negative price. Why didn't Java catch this, and how do you prevent it?

The interviewer is checking: do you know that arguments are matched by position, and that type-checking can't catch every mix-up?

Show a strong answer
  • Arguments are matched by position. The int percent widens to fit the double price parameter, and the int price fits the int percent parameter, so javac had nothing to complain about.
  • Add guard clauses: reject a percent outside 0–100 and a price that is not positive, with a clear error.
  • Make mix-ups harder: clear parameter names, fewer parameters, or a small object (e.g. a Discount type) instead of bare numbers.
  • Add a unit test with realistic values for the new screen.

Avoid: saying "the compiler should have caught it". Validation is the method's job.

Banking · transfers1–3 years

Deeply nested transfer code

A transfer method has five levels of nested if-else checking the amount, account status, KYC, balance and daily limit, with the actual debit buried in the middle. A bug slipped in where a blocked account could still transfer. How would you restructure it?

The interviewer is checking: can you use guard clauses and early returns to make validation obvious?

Show a strong answer
  • Rewrite each check as a guard clause at the top: if the condition fails, return a clear failure result (or reject) immediately.
  • After all guards, the debit and credit run at the left margin, only on the "everything is valid" path.
  • Each rule becomes one readable block that can be tested on its own, including the blocked-account case that was missed.
  • Keep the order intentional: cheap checks (amount > 0) first, costly ones (database lookups) later.

Avoid: adding a sixth nested level to fix the bug. The structure is what hid it.

Analytics · reportsFresher

The dashboard that swapped min and max

A helper returns int[]{min, max}. A teammate assumed index 0 was the maximum, so the dashboard showed "Best day: Rs 3,600" for months. How would you make this kind of bug less likely?

The interviewer is checking: do you see the weakness of returning unnamed values in an array?

Show a strong answer
  • Positions in an array carry no meaning; every caller must remember the order, and nothing checks it.
  • Return a small object or record with named fields, e.g. Range(int min, int max), so the caller writes range.max().
  • Or split into two clearly named methods, min(values) and max(values), if performance isn't an issue.
  • At minimum, document the order in the method comment and add a test.

Avoid: blaming the teammate. The method's design made the mistake easy.

Logistics · rate card1–3 years

"Just return 0 when something is wrong"

A method double shippingCharge(int pincode, double weightKg) returns 0 whenever the pincode is unknown or the weight is invalid. Finance later finds hundreds of orders shipped free by mistake. What would you change?

The interviewer is checking: do you understand that a return value must not hide errors?

Show a strong answer
  • 0 is a valid-looking charge, so callers can't tell "free delivery" from "something went wrong". The error was silently turned into a business decision.
  • For invalid input, fail clearly: throw an exception (Module 9) so the order can't be placed with a wrong charge.
  • For a legitimately "unknown" result, use a value the caller is forced to check, such as Optional (Lesson 14.4), rather than a magic number.
  • Log the bad pincodes so the rate card can be fixed.

Avoid: special return values like 0 or −1 for errors in money calculations.
