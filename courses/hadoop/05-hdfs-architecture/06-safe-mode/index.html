Safe mode

Every time a NameNode starts, it spends a little while in safe mode: it can list files but won't change anything until DataNodes have reported where the blocks are. This lesson shows real restarts with all, none and some DataNodes running, explains the threshold and extension behind the countdown, and teaches you to read a stuck safe mode as a symptom rather than an obstacle to force away.

1 The story

“Name node is in safe mode”

Kabir restarts the NameNode and, without waiting, uploads a file. HDFS refuses: put: Cannot create file … Name node is in safe mode. He tries again a minute later and it works. Riya does a nastier experiment: she stops all four DataNodes and restarts the NameNode. Now hdfs dfs -ls lists every file with its size, but hdfs dfs -cat fails with Zero blocklocations … Name node is in safe mode. “It knows the files but can't find them?”

Arjun Sir

Remember: after a restart the NameNode knows every file from its fsimage and edits, but not where the blocks are. That map comes only from DataNode block reports. Until enough blocks have been reported, the NameNode protects you: it allows reading the namespace, but no changes, and it won't start re-replicating blocks just because their DataNodes haven't reported yet.

Kabir

So it's waiting for the roll call.

Arjun Sir

Exactly. When 99.9% of blocks have at least one reported replica, it waits 30 more seconds for the stragglers, then leaves safe mode by itself. With no DataNodes at all, the threshold can never be reached, so it waits for ever, unless an admin forces it out, which you should do only when you understand why it's stuck.

2 Definition

Safe mode

Formal definition (write this in exams)

Safe mode is a read-only state of the NameNode in which the namespace can be read but not modified (no create, delete, rename or append) and no blocks are replicated or deleted. The NameNode enters it automatically at start-up, after loading the fsimage and edit log, while it collects block reports from DataNodes. It leaves automatically when (1) the fraction of blocks that have at least dfs.namenode.replication.min (1) reported replicas reaches dfs.namenode.safemode.threshold-pct (0.999), and (2) the number of live DataNodes reaches dfs.namenode.safemode.min.datanodes (0), followed by an extension period of dfs.namenode.safemode.extension (30,000 ms). Administrators can control it with hdfs dfsadmin -safemode get | enter | leave | wait; manual safe mode (entered with enter) must be left manually.

In simple words

Right after starting, HDFS is in a careful read-only mode until DataNodes have reported almost all blocks. Then it waits 30 seconds more and opens for writing. Admins can also switch it on and off.

Words you'll meet in this lesson

Safe mode settings (Hadoop 3.5.0 defaults)

threshold-pct0.999: the NameNode computes the needed count as the whole number part of total × 0.999
extension30,000 ms
min.datanodes0 (“The minimum number of live datanodes is not required”)
replication.min1 replica counts a block as safe
Allowed in safe models, stat, cat/get of blocks already reported, getconf, fsck, saveNamespace
Refusedput, mkdir, rm, mv, setrep, append; no replication or deletion of blocks

Safe mode at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner The morning roll call

  • The school opens, but the principal doesn't start classes until almost every teacher has signed in.
  • Students can look at the timetable (read the namespace) but no room changes are allowed (no writes).
  • When 99.9% have signed in, she waits a little for latecomers, then rings the bell.

Intermediate Why it exists

  • Without it, a restarting NameNode would see “no replicas” for every block and immediately order lakhs of copies, then delete them again as reports arrived.
  • It stops clients from writing while the NameNode can't yet choose good DataNodes or confirm space.
  • The 30 s extension avoids leaving the moment the threshold is touched, while a few DataNodes are still reporting.
  • Scripts that start HDFS and then write data should run hdfs dfsadmin -safemode wait first.

Advanced Stuck in safe mode: what it tells you

  • Stuck means too many blocks have no reported replica: DataNodes down, disks lost, or a wrong dfs.datanode.data.dir.
  • The threshold uses a whole-number count: with 9 blocks, int(9 × 0.999) = 8, so one missing block is tolerated (we saw exactly this). With 10 lakh blocks, only 1,000 may be missing.
  • -safemode leave lets the cluster work, but files with missing blocks stay unreadable; first bring DataNodes back or accept the loss.
  • Low disk space on the NameNode's metadata disks (dfs.namenode.resource.du.reserved) also puts it into safe mode.

Exam tip: “What is safe mode in Hadoop?”: a read-only state of the NameNode at start-up while it receives block reports; no modifications or replication; exits automatically when 99.9% of blocks have the minimum replicas, after a 30 s extension. Commands: hdfs dfsadmin -safemode get|enter|leave|wait.

The four safemode commands

-safemode get

Prints “Safe mode is ON” or “OFF”.

Check

-safemode wait

Waits until it is OFF. Put it in start-up scripts before any writes.

Scripts

-safemode enter

Freeze changes manually (stays until you leave).

Admin

-safemode leave

Force it off. Only after you know why it's on.

Careful

The NameNode explains itself. The web UI's Overview, or the Safemode field in /jmx, says how many blocks have been reported, how many are needed, and how many seconds are left. Read it before forcing anything.

  6. A missing block: what safe mode does and doesn't catch

    docker compose exec namenode hdfs dfs -D dfs.replication=1 -put /tmp/canteen_orders.csv data/scratch_r1.csv
# its only replica is on lab5-datanode-1: stop it, restart the NameNode
docker stop lab5-datanode-1
docker restart lab5-namenode-1
docker compose logs namenode | grep -A1 "Safe mode ON"
docker compose exec namenode hdfs fsck / | grep -E "MISSING|Missing blocks|Status"
    STATE* Safe mode ON, in safe mode extension. The reported blocks 8 has reached the threshold 0.9990 of total blocks 9. … /user/hadoop/data/scratch_r1.csv: MISSING 1 blocks of total size 4692009 B. Status: CORRUPT Missing blocks: 1
    The threshold is a whole number: int(9 × 0.999) = 8, so 8 of 9 blocks was “enough” and the NameNode left safe mode with a block missing. fsck reports it. Starting datanode-1 again made the file HEALTHY. On a big cluster the threshold is tighter (1,000 missing blocks out of 10 lakh), but safe mode is not a data-integrity check: fsck is.

Don't make hdfs dfsadmin -safemode leave a habit. If the NameNode is waiting, it is usually waiting for DataNodes that hold real data. Forcing it out turns “not reported yet” into “missing”, and can start unnecessary re-replication.

5 See it happen

A NameNode restart with no DataNodes, then four

Step 4 and step 5 from the real lab, frame by frame.

Safe mode from start to finish 6 steps
What you see
  1. Right after the restart the NameNode is still loading the fsimage and edits; its RPC port isn't open yet.
  2. Now it answers: safe mode is ON. Listing works, because the namespace is loaded.
  3. Reading fails (no block locations yet) and writing is refused.
  4. The DataNodes start, register and send block reports: 8 of 8 blocks reported.
  5. Threshold reached; the 30 s extension counts down.
  6. Safe mode turns off by itself. Reads and writes work again.
Behind the screen
  1. The NameNode rebuilds its namespace from disk. The block map starts empty.
  2. It enters safe mode: the namespace is complete, so metadata reads work.
  3. With 0 of 8 blocks located, it can't serve data and won't allow changes. (8 × 0.999 = 7.99, so 7 blocks would be enough.)
  4. DataNodes register and send their block reports: every block now has known replicas.
  5. The threshold is met; the NameNode waits the 30 s extension for any late reports.
  6. Safe mode ends automatically. Replication monitoring and writes resume.
6 Real-world use

Safe mode at work

1. Start-up scripts that wait

Automation that restarts a cluster and then loads data runs hdfs dfsadmin -safemode wait before the first write, instead of failing with SafeModeException or sleeping for a guessed time.

Start HDFS→safemode wait→Run jobs

2. Diagnosing a stuck restart

When a large cluster stays in safe mode, admins compare reported vs total blocks in the NameNode UI and look for DataNodes that haven't registered (often a failed disk mount or a whole rack still powering up) before deciding anything.

Stuck→Which nodes missing?→Fix, don't force

3. Freezing the namespace for maintenance

Before upgrades or metadata backups, admins enter safe mode so nothing changes, run saveNamespace, copy the metadata, and only then proceed.

safemode enter→saveNamespace + backup→Upgrade

4. When the NameNode's own disk fills

If the disk holding the edit log runs low, the NameNode enters safe mode to avoid corrupting its metadata. Free space on that disk, then leave safe mode.

Metadata disk full→Safe mode→Free space, leave

Simplified; organisations differ in tools and policies.

7 Run the code

Will the NameNode leave safe mode?

This function applies the safe mode rules: the needed count is the whole-number part of total blocks × threshold, plus the minimum number of live DataNodes. Run it on the real cases from Part 4.

def safe_mode(total_blocks, reported, live_dns, threshold=0.999, min_dns=0):
    needed = int(total_blocks * threshold)
    blocks_ok = reported >= needed
    dns_ok = live_dns >= min_dns
    if blocks_ok and dns_ok:
        return f"reported {reported}/{total_blocks} (needed {needed}): leaves after 30 s extension"
    return f"reported {reported}/{total_blocks} (needed {needed}): STAYS in safe mode"

print(safe_mode(8, 8, 4))       # restart, all DataNodes up
print(safe_mode(8, 0, 0))       # restart, no DataNodes
print(safe_mode(9, 8, 3))       # replication-1 file on a stopped DataNode
print(safe_mode(10_00_000, 998_000, 400))
reported 8/8 (needed 7): leaves after 30 s extension reported 0/8 (needed 7): STAYS in safe mode reported 8/9 (needed 8): leaves after 30 s extension reported 998000/1000000 (needed 999000): STAYS in safe mode
  • needed = int(total_blocks * threshold)int() keeps only the whole-number part: int(9 × 0.999) = int(8.991) = 8. That is why 8 of 9 was enough in our lab.
  • dns_ok = live_dns >= min_dnsdfs.namenode.safemode.min.datanodes is 0 by default, so this never blocks unless an admin sets it.

Run it on your PC: follow a NameNode restart

This script restarts the lab NameNode, then every few seconds asks for the safe mode state and reads the NameNode's own explanation from /jmx. Save it as safemode_watch.py in the hdfs-lab folder and run it while the DataNodes are up.

Safe mode from restart to OFF

# safemode_watch.py: restart the NameNode and follow safe mode until it ends.
# Run in the hdfs-lab folder while the cluster is up.
import json
import re
import subprocess
import time

URL = "http://namenode:9870/jmx?qry=Hadoop:service=NameNode,name=NameNodeInfo"

def nn(*cmd):
    return subprocess.run(["docker", "compose", "exec", "-T", "namenode", *cmd],
                          capture_output=True, text=True).stdout.strip()

def explanation():
    try:
        return json.loads(nn("curl", "-s", URL))["beans"][0]["Safemode"] or "(off)"
    except (ValueError, KeyError, IndexError):
        return "(NameNode not answering yet)"

subprocess.run(["docker", "restart", "lab5-namenode-1"], capture_output=True)
start = time.time()
while time.time() - start < 120:
    state = nn("hdfs", "dfsadmin", "-safemode", "get").splitlines()
    state = state[-1] if state else "(no answer)"
    why = explanation()
    blocks = re.search(r"reported blocks (\d+).*?total blocks (\d+)", why)
    left = re.search(r"in (\d+) seconds", why)
    detail = (f"reported {blocks.group(1)}/{blocks.group(2)} blocks" if blocks else why[:40]) + \
             (f", off in {left.group(1)} s" if left else "")
    print(f"t={time.time() - start:3.0f}s  {state:24} {detail}")
    if "OFF" in state:
        break
    time.sleep(5)

# In the hdfs-lab folder:
#   python3 safemode_watch.py

Interview and viva questions

What is safe mode in HDFS?

A read-only state of the NameNode. At start-up it loads the namespace and then waits for DataNodes to report their blocks. Until enough blocks are reported, it allows reading metadata but no modifications and no replication, so it doesn't act on incomplete information.

How do I leave safe mode?

Normally you just wait: it ends automatically when 99.9% of blocks are reported plus 30 seconds. Use hdfs dfsadmin -safemode wait in scripts. hdfs dfsadmin -safemode leave forces it off, which is appropriate only after you know why it is stuck (or after a manual enter).

Why is my NameNode stuck in safe mode?

Usually because DataNodes holding a significant share of blocks have not registered: they are down, their disks are not mounted, or dfs.datanode.data.dir points to the wrong folder. It can also be caused by low disk space on the NameNode's metadata directories.

Can I read files in safe mode?

You can read metadata (ls, stat). File data can be read for blocks whose replicas have already been reported; blocks with no reported replica cannot be read yet.

What do threshold-pct and extension mean?

dfs.namenode.safemode.threshold-pct (0.999) is the fraction of blocks that must have at least dfs.namenode.replication.min reported replicas. dfs.namenode.safemode.extension (30,000 ms) is how long the NameNode stays in safe mode after reaching that threshold, to let late reports arrive.

Does leaving safe mode guarantee no data is missing?

No. The threshold allows a small fraction of blocks (0.1%, rounded) to be unreported. Run hdfs fsck / after restarts to find missing or corrupt blocks.

P5Medium

Blocks per DataNode needed

Show solution and explanation 
import random
random.seed(1)
nodes = 300
blocks = [random.sample(range(nodes), 3) for _ in range(60_000)]   # 1/10 sample
order = random.sample(range(nodes), nodes)
reported = set()

files = {"orders.csv": ["b1", "b2"], "scratch_r1.csv": ["b9"], "users.csv": ["b5"]}
reported = {"b1": ["dn2"], "b2": ["dn3", "dn4"], "b5": ["dn2", "dn4"], "b9": []}
for f, blocks in files.items():
    missing = [b for b in blocks if not reported.get(b)]
    print(f, "MISSING " + ", ".join(missing) if missing else "ok")

Real-world scenario questions (asked in company interviews)

Safe mode questions check both knowledge and judgement: do you force it, or do you find out why?

HDFS · basicsFresher

“My job fails with ‘Name node is in safe mode’ right after starting HDFS”

A student's script runs start-dfs.sh and immediately hdfs dfs -put.

The interviewer is checking: what safe mode is and the right fix.

Show a strong answer
  • At start-up the NameNode stays read-only until DataNodes report 99.9% of blocks, plus 30 s.
  • Add hdfs dfsadmin -safemode wait after starting HDFS, before any write.
  • Don't add -safemode leave to the script: it would hide real problems.
Operations · incidentExperienced

Production NameNode stuck in safe mode at 96%

After a data-centre power cut, the NameNode reports 96% of blocks after 30 minutes. Users want you to force it out.

The interviewer is checking: calm, systematic recovery.

Show a strong answer
  • 4% unreported blocks means many DataNodes or disks are missing. Compare expected vs registered DataNodes (dfsadmin -report, UI).
  • Check those hosts: powered on? DataNode running? Disks mounted? Logs for clusterID or volume errors.
  • As nodes return, the count rises and safe mode ends by itself. Force it off only if the missing nodes are confirmed lost, then run fsck and restore data from backups/DR.
  • Communicate: the cluster is readable for reported data meanwhile.
HDFS · internalsExperienced

Why doesn't the NameNode just start re-replicating straight away?

A design question about the purpose of safe mode.

The interviewer is checking: understanding of the block map.

Show a strong answer
  • Right after start-up the block map is empty: every block looks like it has 0 replicas.
  • Acting on that would trigger copies of the whole cluster, followed by mass deletion when reports arrive.
  • Safe mode waits until the map is nearly complete, so replication decisions are based on real data.
Admin · maintenanceFresher

When would you put HDFS into safe mode on purpose?

An interviewer asks for real uses of -safemode enter.

The interviewer is checking: practical admin experience.

Show a strong answer
  • Before hdfs dfsadmin -saveNamespace (required), e.g. to create a clean checkpoint before maintenance.
  • To freeze the namespace while taking a metadata backup or before an upgrade.
  • Remember to run -safemode leave afterwards: manual safe mode never ends by itself.
