Who's who: Hadoop glossary

Every Hadoop term used in this course in one or two plain sentences, grouped by topic and searchable. Start with Often confused: the pairs of terms that trip up most students and interview candidates. 274 terms so far; the list grows with each module.

Often confused

Hadoop vs Spark

Not either/or. Hadoop is storage (HDFS) + resources (YARN) + an engine (MapReduce). Spark is an engine that usually runs on YARN and reads HDFS. In our lab five cached Spark passes took 35 s; five MapReduce jobs took 199 s.

Data lake vs lakehouse

A data lake is files in cheap storage. A lakehouse adds a table format (Iceberg, Delta, Hudi) on top, giving transactions, updates, snapshots and time travel.

Authentication vs authorization

Authentication proves who you are (Kerberos tickets). Authorization decides what you may do (HDFS permissions, ACLs, Ranger policies). Without authentication, authorization can be bypassed by claiming another name, as our unsecured lab showed.

Backup vs disaster recovery

A backup is a copy you can restore from, maybe slowly. DR is a ready second site with recent data and a rehearsed plan to switch over within the RTO.

Capacity vs maximum-capacity vs user limit

capacity is what a queue is guaranteed; maximum-capacity is how far it may grow when others are idle; user-limit-factor caps one user inside the queue. In our lab maximum-capacity 100% did nothing until user-limit-factor was raised.

Container memory vs Java heap

The container (mapreduce.map.memory.mb) is what YARN reserves on the node; the heap (-Xmx) is what Java may use for objects, about 80% of it. Too small a heap gives "Java heap space"; heap + overhead above the container gets the container killed.

Row format vs columnar format

Row formats (CSV, SequenceFile, Avro) keep each record together: good for writing and reading whole records. Columnar (Parquet, ORC) keep each column together: good for analytics that read a few columns of many rows.

Compressed file vs compressed container

A .gz file is one stream: not splittable, one map. A container (SequenceFile BLOCK, Avro, Parquet, ORC) compresses inside blocks, so the file stays splittable whatever the codec.

Combiner vs reducer

A reducer runs once per key on all values, after the shuffle. A combiner runs on one map task's output, zero or more times, before the shuffle; it only works for operations like sum, count, max and min.

Reduce-side vs map-side join

Reduce-side: both inputs are shuffled; works for any sizes (24.4 MB shuffled, 24.8 s in our lab). Map-side: the small side is copied to every map task; no shuffle (18.9 s), but the small side must fit in memory.

Partitioner vs grouping comparator

The partitioner decides which reducer gets a key. The grouping comparator decides which keys, already on that reducer, share one reduce() call.

Killed vs failed task attempt

Failed: the attempt crashed (exception, exit code 137) and counts toward the retry limit. Killed: the framework stopped it on purpose, usually the losing copy in speculative execution. Our job showed both and still succeeded.

Map output vs job output

Map output is temporary, sorted, on the worker's local disk, served to reducers and deleted after the job. Job output (part-r files) is written to HDFS with replication.

Snapshot vs Trash

Trash catches a normal -rm for a while, but -skipTrash or expiry bypasses it. A snapshot keeps the old state even after a -skipTrash delete, until you delete the snapshot.

HA vs Federation

HA gives one namespace two NameNodes (active + standby) for availability. Federation splits the namespace across several active NameNodes for scale. They can be combined.

Replication vs erasure coding

Replication keeps 3 full copies (200% overhead), fast to read and repair. Erasure coding keeps data + parity (e.g. 50% overhead), cheaper for cold data but costlier CPU and network on repair.

Block vs input split

A block is how HDFS physically stores bytes (128 MB pieces). An input split is the logical piece one map task reads; it normally matches a block, but a record that crosses a block boundary is read whole by one split.

NameNode vs ResourceManager

Both are masters, of different things. The NameNode manages storage (files and blocks). The ResourceManager manages compute (memory and CPU for jobs).

DataNode vs NodeManager

Both run on a worker. The DataNode stores blocks; the NodeManager runs task containers. Running both on one machine is what makes data locality possible.

Secondary NameNode vs Standby NameNode

The Secondary only merges the edit log into the fsimage. It cannot replace a failed NameNode. The Standby (HA) is a hot spare that takes over automatically.

ResourceManager vs ApplicationMaster

The ResourceManager serves the whole cluster and hands out containers. An ApplicationMaster serves one job and decides which of its tasks run in those containers.

Replication vs backup

Replication keeps live copies to survive hardware failure; deletes and bad writes reach every copy. A backup or snapshot is a separate point-in-time copy you can restore.

Node-local vs rack-local

Node-local: the task runs on a machine holding its block. Rack-local: on another machine in the same rack, so data crosses only the rack switch.

Dead vs stale DataNode

A dead node has been silent past the timeout (≈10.5 min) and its replicas are re-created elsewhere. A stale node has missed heartbeats for a shorter time (30 s by default) and can be avoided for reads and writes without being declared dead.

Standalone vs pseudo-distributed

Standalone runs a job inside one Java process on local files; no daemons. Pseudo-distributed runs every daemon (NameNode, DataNode, ResourceManager…) as a separate process on one machine, with real HDFS and YARN.

core-default.xml vs core-site.xml

core-default.xml holds Hadoop's built-in defaults inside the jars; never edit it. core-site.xml in etc/hadoop is where you override the values you need.

Decommission vs stopping a DataNode

Decommissioning copies every block away first, then marks the node Decommissioned: no moment with fewer replicas. Stopping it is treated as a failure: HDFS waits until the node is declared dead (≈10.5 min) before re-replicating.

hdfs dfs -mv vs -cp

-mv only renames in the NameNode, so it is instant for any size. -cp reads and rewrites every byte through the client (5.6 s vs 1.9 s for 403 MB in our lab).

docker compose stop vs down

stop pauses the containers and keeps their disks, so HDFS data survives. down deletes the containers, and without volumes the data goes with them.

HDFS

Active NameNodeIn HA, the one NameNode that serves clients and writes the edit log; the other waits as standby. Lesson →

BalancerTool that moves blocks from full DataNodes to emptier ones (hdfs balancer). Lesson →
blk_ and .meta filesA replica on a DataNode disk: blk_N holds the bytes, blk_N_genstamp.meta the checksums (4 B per 512 B). Lesson →
BlockThe unit HDFS stores: a file is cut into blocks of 128 MB by default (the last one can be smaller). Lesson →
Block groupIn erasure coding, the set of data + parity blocks that together hold one striped piece of a file. Lesson →
Block mapNameNode's in-memory map from each block to the DataNodes holding it; rebuilt from block reports, never saved. Lesson →

ChecksumA small value computed from data to detect corruption. HDFS uses CRC32C per 512 bytes. Lesson →
Cluster IDID shared by all NameNodes of a federated cluster; DataNodes only join NameNodes with the same cluster ID. Lesson →
CompactionRewriting many small files into a few large ones (e.g. 128 MB–1 GB), typically per partition. Lesson →
Corrupt replicaA replica whose checksum does not match; the reader reports it (reportBadBlocks) and the NameNode replaces it. Lesson →
DataNodeHDFS worker that stores block replicas on its local disks and serves reads and writes. Lesson →

FileSystem APIorg.apache.hadoop.fs.FileSystem: the Java API (create, open, listStatus, rename, delete…) used by all Hadoop clients. Lesson →

Data formats

Apache AvroLanguage-neutral binary row format; each data file carries its JSON schema; compact, splittable, compressible. Lesson →
Columnar formatStores a table column by column (Parquet, ORC) so readers fetch only needed columns and compress better. Lesson →
Compression codecA CompressionCodec: Default (deflate), Gzip, BZip2, Lz4, Snappy, ZStandard; chosen by file extension. Lesson →
Dictionary encodingStoring each distinct value once plus small codes per row (ORC DICTIONARY_V2[8] for 8 items). Lesson →
hadoop checknativeShows which native libraries (hadoop, zlib, zstd, bzip2, openssl, ISA-L) Hadoop can load. Lesson →
Map output compressionmapreduce.map.output.compress + codec: compresses the shuffle (lab: 60 MB → 13 KB with ZSTD). Lesson →
ORCOptimized Row Columnar: stripes with light-weight indexes every 10,000 rows; Hive's native format. Lesson →
ParquetColumnar format: row groups → column chunks → pages, footer with schema and min/max statistics. Default in Spark. Lesson →
Predicate pushdownSkipping row groups or stripes whose min/max cannot match a filter; works best on sorted data (1 of 10 vs 10 of 10). Lesson →
Projection (column pruning)Reading only the needed columns: 192,526 bytes instead of 4,431,110 for Parquet in our lab. Lesson →
Row group / stripeThe horizontal slice of a Parquet (row group) or ORC (stripe) file; the unit that statistics let readers skip. Lesson →
Schema evolutionChanging a schema without breaking old data: new fields need defaults (our lab: missing default → AvroTypeException). Lesson →
SequenceFileHadoop's binary file of Writable key-value pairs; header names the classes and codec; NONE, RECORD or BLOCK compression. Lesson →
Splittable codecA codec readers can start mid-file (SplittableCompressionCodec); only bzip2 among the built-ins. A .gz file is one map. Lesson →
Sync markerA 16-byte marker repeated inside SequenceFile and Avro files so a split can start in the middle of the file. Lesson →
Writer vs reader schemaAvro resolves the schema stored in the file against the one the program expects, field by field. Lesson →

Ecosystem

Spot / preemptible workersCheaper cloud machines that can be taken back; fine for task-only workers because tasks rerun. Lesson →
SQL-on-HadoopEngines that run SQL over files in HDFS or object storage: Hive, Spark SQL, Trino, Impala, Drill. Lesson →
