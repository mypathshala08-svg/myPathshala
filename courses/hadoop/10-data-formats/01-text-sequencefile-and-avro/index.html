Text, SequenceFile and Avro

CSV is easy to read and says nothing about its own columns. Hadoop's SequenceFile and Apache Avro store the same records as compact binary, stay splittable when compressed, and (in Avro's case) carry a schema that can change safely over time. This lesson converts real data into all of them and measures what each choice costs.

1 The story

The day someone added a column

The canteen's 5 lakh orders live in HDFS as student_orders.csv. On Monday the billing team added a payment column at the end of each new line. On Tuesday Kabir's monthly report crashed: his job expected five fields and found six. Riya's Python script didn't crash, but it read "cash" as the amount. Nothing in a CSV file says what its columns are called or what type they have. Arjun Sir pulls up a different version of the same data.

Arjun Sir

A file format is a contract between whoever writes the data and everyone who will ever read it. CSV's contract is “some text with commas”. That is easy to read with your eyes, and that is all it promises.

Riya

So binary formats are smaller, and they also remember the column names?

Arjun Sir

Some of them. A SequenceFile stores binary keys and values and writes their Java classes in its header. An Avro file stores a full schema, field names and types, in its header, so a reader in Java, Python or anything else knows exactly what each record contains. And Avro has rules for changing that schema without breaking old files.

Kabir

Today we convert the same orders into all of these, compare the sizes, read them back with one job, and then add Monday's payment column the safe way.

2 Definition

Row-oriented file formats in Hadoop

Formal definition (write this in exams)

A file format defines how records are encoded into bytes in a file. In Hadoop it is read by an InputFormat and written by an OutputFormat. Text files (TextInputFormat) store one record per line as characters with no schema. A SequenceFile is Hadoop's flat binary file of key-value pairs: a header names the key and value classes (Writables) and the compression codec, records may be stored uncompressed, record-compressed or block-compressed, and periodic sync markers let a reader start in the middle of the file, making it splittable. Apache Avro is a language-neutral data serialization system: an Avro data file (object container file) stores its schema as JSON in the header, followed by blocks of compactly encoded binary records separated by sync markers, each block optionally compressed. Avro supports schema evolution: data written with one schema (the writer's schema) can be read with a different but compatible schema (the reader's schema). All three are row-oriented: the fields of one record are stored together.

In simple words

Text is human-readable but has no types. SequenceFile is Hadoop's own compact key-value box. Avro is a compact box that carries its own label (the schema), works in any language, and lets the label change over time without breaking old boxes.

File formats at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Three ways to keep a register

  • Text is a notebook where each order is written as one line. Anyone can read it, but nothing says which number is the amount and which is the roll number.
  • SequenceFile is a register with two columns, key and value, printed in Hadoop's own shorthand. Compact, but you need Hadoop (or Java) to read it.
  • Avro is a register with the column headings printed on the first page, in a shorthand every language understands. When a new column is added, old pages still make sense.

Intermediate What the bytes look like

  • Text: numbers as characters (“45” is 2 bytes, “1000001” is 7), commas, a newline. Our CSV: about 39 bytes per order.
  • SequenceFile NONE: every record stores its record length and key length (4 + 4 bytes), the key as an 8-byte LongWritable, then the value as Text, plus a 20-byte sync entry about every 100 KB. That's why it was bigger than the CSV: 24.0 MB vs 19.4 MB.
  • SequenceFile RECORD: each value compressed on its own. A 30-byte value can't shrink, and each one pays the deflate overhead: 27.9 MB, the worst of all. BLOCK compresses many records together: 4.7 MB.
  • Avro: no field names or separators per record (the schema says what comes next), numbers as variable-length zig-zag integers, strings as length + bytes. Without compression already 16.6 MB, smaller than the CSV.

Advanced Splitting, compression and evolution

  • Both binary formats put a 16-byte sync marker between blocks. A map task given bytes 128 MB–256 MB scans forward to the next marker and starts there, like LineRecordReader does with newlines (Lesson 8.2). So they stay splittable even when compressed, unlike a gzip'd CSV (Lesson 10.3).
  • Avro schema resolution matches fields by name: a field in the reader's schema but not in the file needs a default; a field in the file but not the reader's schema is skipped; renames use aliases; types can be promoted (int → long, float → double).
  • Compatibility is directional: backward = new readers can read old data (add fields with defaults); forward = old readers can read new data (remove only fields that had defaults). Kafka's Schema Registry enforces exactly these rules.
  • SequenceFile's types are Java class names, so other languages struggle with it. It is best for Hadoop-internal data: intermediate job output, or packing small files (Lesson 7.5).

Exam tip: For “Compare Text, SequenceFile and Avro”, use four headings: schema (none / Java classes in header / JSON schema in header), size (largest / compact with BLOCK compression / compact), splittable when compressed (no with gzip / yes / yes), languages (any / mainly Java / any). Add one line on Avro schema evolution: new fields need defaults.

Choosing

Exchanging data or expecting schema changes: Avro. Hadoop-only intermediate data: SequenceFile. Analytics on a few columns: Parquet or ORC (next lesson).

rule of thumb

Row formats are fast to write one record at a time, which is why streaming pipelines (Kafka → HDFS) usually land data as Avro. Analytical tables are then rewritten into columnar formats, which are faster to read when a query needs only a few columns. Lesson 10.2 measures that difference.

4 Step by step

Converting the orders and reading them back

We use the Module 8 lab cluster and Module 9's student_orders.csv. Hadoop ships the Avro core library but not avro-mapred (the Avro InputFormat and OutputFormat), so get_jars.sh downloads it from Maven Central, and formats_env.sh passes it to the job with -libjars.

  1. Write SequenceFiles three ways

    hadoop jar mr10.jar ToSequenceFile -libjars $LIBJARS -D seq.compress=NONE   $D /out/f_seq_none
hadoop jar mr10.jar ToSequenceFile -libjars $LIBJARS -D seq.compress=RECORD $D /out/f_seq_record
hadoop jar mr10.jar ToSequenceFile -libjars $LIBJARS -D seq.compress=BLOCK  $D /out/f_seq_block
    text 19418699 seq_none 24034722 seq_record 27878984 seq_block 4683378
    A map-only job turns each line into (order_id as LongWritable, rest of the line as Text). Uncompressed it grows by about 9 bytes per order (lengths, the 8-byte key). Compressing each tiny value separately makes it even bigger; compressing blocks of records shrinks it to a quarter of the CSV.

  2. Look at the first bytes

    hdfs dfs -cat /out/f_seq_block/part-m-00000 | head -c 150
    SEQ.!org.apache.hadoop.io.LongWritable.org.apache.hadoop.io.Text..*org.apache.hadoop.io.compress.DefaultCodec....P...........8`......P...........8`...
    The header: magic bytes SEQ, a version byte, the key class, the value class, the compression flags and codec, then a 16-byte sync marker. Any reader learns the types from the file itself.

  3. Write Avro three ways

    hadoop jar mr10.jar ToAvro -libjars $LIBJARS -D avro.codec=null    $D /out/f_avro_null
hadoop jar mr10.jar ToAvro -libjars $LIBJARS -D avro.codec=deflate $D /out/f_avro_deflate
hadoop jar mr10.jar ToAvro -libjars $LIBJARS -D avro.codec=snappy  $D /out/f_avro_snappy
    avro_null 16558165 avro_deflate 4793471 avro_snappy 7791915
    Even with no codec, Avro is smaller than the CSV: no commas, no field names per record, and numbers stored as variable-length integers. Deflate compresses better; snappy is faster but larger (Lesson 10.3).

  4. Read the binary files as text

    hdfs dfs -text /out/f_seq_block/part-m-00000 | head -2
hdfs dfs -text /out/f_avro_deflate/part-m-00000.avro | head -2
java -jar lib/avro-tools-1.11.5.jar getmeta orders.avro

    -text (unlike -cat) recognises SequenceFiles and Avro files and decodes them. The Avro file's metadata holds the whole schema and the codec name.

  5. Add Monday's column the safe way

    {"name":"payment","type":"string","default":"cash"}
    {"order_id":432369,"student":"S0454","time":"2026-09-20 12:05","item":"chai","amount":15,"payment":"cash"} {"order_id":432370,"student":"S1436","time":"2026-09-18 18:50","item":"chai","amount":15,"payment":"cash"} -- and a new field WITHOUT a default: AvroTypeException: Found in.myphatshala.Order, expecting in.myphatshala.Order, missing required field payment
    The old file was written without payment. Reading it with the new schema, Avro fills the default. Without a default there is no value to fill, so Avro refuses instead of guessing, a loud failure rather than Riya's silent one.

  6. Read all three with the same job

    hadoop jar mr10.jar ItemCountAny -libjars $LIBJARS -D in.format=text $D /out/r_text

hadoop jar mr10.jar ItemCountAny -libjars $LIBJARS -D in.format=avro /out/f_avro_deflate /out/r_avro
    text 25221 ms HDFS bytes read 19427239 map input records 500000 chai=149669 seq_block 25073 ms HDFS bytes read 4683705 map input records 500000 chai=149669 avro_deflate 25813 ms HDFS bytes read 4818410 map input records 500000 chai=149669
    Same answer, a quarter of the bytes read from HDFS. The times are equal here because 19 MB is tiny and job start-up dominates; on terabytes, reading 4× fewer bytes is the difference that matters, paid for with CPU to decompress.

Don't use RECORD compression for small records: our SequenceFile grew from 24.0 MB to 27.9 MB. Use BLOCK compression (or Avro with a codec), which compresses many records together.

Inside the files 6 steps
What you see
  1. The CSV: 19.4 MB, one readable line per order.
  2. The uncompressed SequenceFile is larger than the CSV: 24.0 MB.
  3. Compressing record by record makes it worse (27.9 MB); compressing blocks gives 4.7 MB.
  4. Avro without a codec is already smaller than the CSV; deflate brings it to 4.8 MB.
  5. An old file read with a new schema: the default fills the gap; with no default, Avro refuses.
  6. One job reads all three formats and gets the same answer from a quarter of the bytes.
Behind the screen
  1. CSV stores everything as characters with commas in between; types are a guess.
  2. A SequenceFile record adds a record length, a key length and an 8-byte key; a sync marker follows about every 100 KB.
  3. RECORD compression deflates each tiny value alone; BLOCK compression deflates many records together.
  4. Avro writes the schema once in the header, then bare values: small numbers become single bytes.
  5. When reading, Avro matches the file's fields to yours by name and fills defaults for new ones.
  6. The binary formats let the same job read about a quarter of the bytes.
6 Real-world use

Row formats at work

1. Event streams with a schema registry

Payment, order and click events are published to Kafka as Avro, with schemas stored in a schema registry that rejects incompatible changes. Connectors then land them in HDFS or a data lake as Avro files.

App events→Kafka + Avro schema→HDFS landing zone

2. Packing small files

Images, PDFs or tiny logs are packed into SequenceFiles with the file name as key and the bytes as value, so the NameNode tracks one file instead of thousands (Lesson 7.5).

Small files→(name, bytes) records→One splittable file

3. Data between chained jobs

When one MapReduce job feeds another, the middle data is written as block-compressed SequenceFiles: binary Writables need no parsing, and Hive, Pig and Mahout used them this way.

Job 1→SequenceFile (BLOCK)→Job 2

4. Raw zone, then curated tables

Data lakes keep the raw, append-only zone in Avro (fast writes, full records, schema history), then nightly jobs rewrite it into Parquet or ORC tables for analysts (Lesson 10.2).

Raw (Avro)→nightly rewrite→Curated (Parquet/ORC)

Simplified; organisations differ in tools and policies.

7 Run the code

Encode one order three ways

This model builds the bytes of one order as a CSV line, as an uncompressed SequenceFile record, and as an Avro record (zig-zag variable-length integers, strings as length + bytes). The layouts follow the real formats; the file headers are left out.

import struct

order = (1, "S1413", "2026-09-14 15:30", "dosa", 45)

def zigzag_varint(n):                       # Avro's int/long encoding
    n = (n << 1) ^ (n >> 63)                # zig-zag: 0,-1,1,-2 -> 0,1,2,3
    out = b""
    while n > 0x7F:
        out += bytes([(n & 0x7F) | 0x80])   # 7 bits per byte, high bit = "more follows"
        n >>= 7
    return out + bytes([n])

csv = (",".join(map(str, order)) + "\n").encode()

value = ",".join(map(str, order[1:])).encode()               # Text value
seq = struct.pack(">ii", 8 + 1 + len(value), 8) + struct.pack(">q", order[0]) + bytes([len(value)]) + value

avro = zigzag_varint(order[0])
for s in order[1:4]:
    avro += zigzag_varint(len(s)) + s.encode()
avro += zigzag_varint(order[4])

for name, b in [("CSV", csv), ("SequenceFile", seq), ("Avro", avro)]:
    print(f"{name:13} {len(b):3} bytes  {b[:24]!r}")
CSV 33 bytes b'1,S1413,2026-09-14 15:30' SequenceFile 47 bytes b"\x00\x00\x00'\x00\x00\x00\x08\x00\x00\x00\x00\x00\x00\x00\x01\x1eS1413,2" Avro 30 bytes b'\x02\nS1413 2026-09-14 15:30'
  • n = (n << 1) ^ (n >> 63) # zig-zag: 0,-1,1,-2 -> 0,1,2,3Zig-zag maps small negative numbers to small positive ones, so -1 also fits in one byte.
  • seq = struct.pack(">ii", 8 + 1 + len(value), 8) + struct.pack(">q", order[0]) + bytes([len(value)]) + valueRecord length, key length, an 8-byte LongWritable key, then the Text value with its length. About 9 bytes more than the CSV line per order.
  • avro += zigzag_varint(order[4])No field names and no separators: the schema in the file header says what comes next.

CSV to SequenceFile

// ToSequenceFile.java: map-only job. CSV orders -> SequenceFile of (order_id, "student,time,item,amount").
//   -D seq.compress=NONE|RECORD|BLOCK   (codec: -D seq.codec=default|snappy|zstd|gzip)
import java.io.IOException;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.SequenceFile.CompressionType;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.io.compress.*;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;
import org.apache.hadoop.mapreduce.lib.output.SequenceFileOutputFormat;
import org.apache.hadoop.util.GenericOptionsParser;

public class ToSequenceFile {
  public static class M extends Mapper<LongWritable, Text, LongWritable, Text> {
    private final LongWritable id = new LongWritable();
    private final Text rest = new Text();
    @Override
    protected void map(LongWritable k, Text line, Context ctx) throws IOException, InterruptedException {
      String s = line.toString();
      int comma = s.indexOf(',');
      id.set(Long.parseLong(s.substring(0, comma)));
      rest.set(s.substring(comma + 1));
      ctx.write(id, rest);
    }
  }

  static Class<? extends CompressionCodec> codec(String name) {
    switch (name) {
      case "snappy": return SnappyCodec.class;
      case "zstd": return ZStandardCodec.class;
      case "gzip": return GzipCodec.class;
      default: return DefaultCodec.class;           // zlib/deflate
    }
  }

  public static void main(String[] args) throws Exception {
    Configuration conf = new Configuration();
    String[] rest = new GenericOptionsParser(conf, args).getRemainingArgs();
    CompressionType type = CompressionType.valueOf(conf.get("seq.compress", "NONE"));
    Job job = Job.getInstance(conf, "to sequencefile " + type);
    job.setJarByClass(ToSequenceFile.class);
    job.setMapperClass(M.class);
    job.setNumReduceTasks(0);
    job.setOutputKeyClass(LongWritable.class);
    job.setOutputValueClass(Text.class);
    job.setOutputFormatClass(SequenceFileOutputFormat.class);
    if (type != CompressionType.NONE) {
      FileOutputFormat.setCompressOutput(job, true);
      FileOutputFormat.setOutputCompressorClass(job, codec(conf.get("seq.codec", "default")));
      SequenceFileOutputFormat.setOutputCompressionType(job, type);
    }
    FileInputFormat.addInputPath(job, new Path(rest[0]));
    FileOutputFormat.setOutputPath(job, new Path(rest[1]));
    System.exit(job.waitForCompletion(true) ? 0 : 1);
  }
}

CSV to Avro, then a new schema

// ToAvro.java: map-only job. CSV orders -> Avro data files with an explicit schema.
//   -D avro.codec=null|deflate|snappy|zstandard
import java.io.IOException;
import org.apache.avro.Schema;
import org.apache.avro.generic.GenericData;
import org.apache.avro.generic.GenericRecord;
import org.apache.avro.mapred.AvroKey;
import org.apache.avro.mapreduce.AvroJob;
import org.apache.avro.mapreduce.AvroKeyOutputFormat;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.NullWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;
import org.apache.hadoop.util.GenericOptionsParser;

public class ToAvro {
  static final String SCHEMA = "{\"type\":\"record\",\"name\":\"Order\",\"namespace\":\"in.myphatshala\",\"fields\":["
      + "{\"name\":\"order_id\",\"type\":\"long\"},"
      + "{\"name\":\"student\",\"type\":\"string\"},"
      + "{\"name\":\"time\",\"type\":\"string\"},"
      + "{\"name\":\"item\",\"type\":\"string\"},"
      + "{\"name\":\"amount\",\"type\":\"int\"}]}";

  public static class M extends Mapper<LongWritable, Text, AvroKey<GenericRecord>, NullWritable> {
    private Schema schema;
    private GenericRecord rec;
    private final AvroKey<GenericRecord> out = new AvroKey<>();
    @Override
    protected void setup(Context ctx) { schema = new Schema.Parser().parse(SCHEMA); rec = new GenericData.Record(schema); }
    @Override
    protected void map(LongWritable k, Text line, Context ctx) throws IOException, InterruptedException {
      String[] f = line.toString().split(",");
      rec.put("order_id", Long.parseLong(f[0]));
      rec.put("student", f[1]);
      rec.put("time", f[2]);
      rec.put("item", f[3]);
      rec.put("amount", Integer.parseInt(f[4]));
      out.datum(rec);
      ctx.write(out, NullWritable.get());
    }
  }

  public static void main(String[] args) throws Exception {
    Configuration conf = new Configuration();
    String[] rest = new GenericOptionsParser(conf, args).getRemainingArgs();
    Job job = Job.getInstance(conf, "to avro " + conf.get("avro.codec", "deflate"));
    job.setJarByClass(ToAvro.class);
    job.setMapperClass(M.class);
    job.setNumReduceTasks(0);
    AvroJob.setOutputKeySchema(job, new Schema.Parser().parse(SCHEMA));
    job.setOutputFormatClass(AvroKeyOutputFormat.class);
    String codec = conf.get("avro.codec", "deflate");
    if (!codec.equals("null")) { FileOutputFormat.setCompressOutput(job, true); job.getConfiguration().set("avro.output.codec", codec); }
    FileInputFormat.addInputPath(job, new Path(rest[0]));
    FileOutputFormat.setOutputPath(job, new Path(rest[1]));
    System.exit(job.waitForCompletion(true) ? 0 : 1);
  }
}

One job that reads any format

// ItemCountAny.java: orders per item, reading any of our formats.  -D in.format=text|seq|avro|parquet|orc
// For parquet and orc only the "item" column is requested (column projection); -D proj=false reads all columns.
import java.io.IOException;
import org.apache.avro.Schema;
import org.apache.avro.generic.GenericRecord;

public class ItemCountAny {
  static final LongWritable ONE = new LongWritable(1);

  public static class TextM extends Mapper<LongWritable, Text, Text, LongWritable> {
    private final Text item = new Text();
    @Override protected void map(LongWritable k, Text v, Context c) throws IOException, InterruptedException {
      item.set(v.toString().split(",")[3]); c.write(item, ONE);
    }
  }
  public static class SeqM extends Mapper<LongWritable, Text, Text, LongWritable> {   // value = student,time,item,amount
    private final Text item = new Text();
    @Override protected void map(LongWritable k, Text v, Context c) throws IOException, InterruptedException {
      item.set(v.toString().split(",")[2]); c.write(item, ONE);
    }
  }
  public static class AvroM extends Mapper<AvroKey<GenericRecord>, NullWritable, Text, LongWritable> {
    private final Text item = new Text();
    @Override protected void map(AvroKey<GenericRecord> k, NullWritable v, Context c) throws IOException, InterruptedException {
      item.set(k.datum().get("item").toString()); c.write(item, ONE);
    }
  }
  public static class ParquetM extends Mapper<Void, Group, Text, LongWritable> {
    private final Text item = new Text();
    @Override protected void map(Void k, Group g, Context c) throws IOException, InterruptedException {
      item.set(g.getString("item", 0)); c.write(item, ONE);
    }
  }
  public static class OrcM extends Mapper<NullWritable, OrcStruct, Text, LongWritable> {
    @Override protected void map(NullWritable k, OrcStruct row, Context c) throws IOException, InterruptedException {
      c.write((Text) row.getFieldValue("item"), ONE);
    }
  }

  public static void main(String[] args) throws Exception {
    Configuration conf = new Configuration();
    String[] rest = new GenericOptionsParser(conf, args).getRemainingArgs();
    String fmt = conf.get("in.format", "text");
    Job job = Job.getInstance(conf, "item count from " + fmt);
    job.setJarByClass(ItemCountAny.class);
    switch (fmt) {
      case "seq": job.setInputFormatClass(SequenceFileInputFormat.class); job.setMapperClass(SeqM.class); break;
      case "avro":
        job.setInputFormatClass(AvroKeyInputFormat.class);
        AvroJob.setInputKeySchema(job, new Schema.Parser().parse(ToAvro.SCHEMA));
        job.setMapperClass(AvroM.class); break;
      case "parquet":
        job.setInputFormatClass(ExampleInputFormat.class);
        if (conf.getBoolean("proj", true))
          job.getConfiguration().set("parquet.read.schema", "message order { required binary item (UTF8); }");   // projection
        job.setMapperClass(ParquetM.class); break;
      case "orc":
        job.setInputFormatClass(OrcInputFormat.class);
        if (conf.getBoolean("proj", true))
          OrcConf.INCLUDE_COLUMNS.setString(job.getConfiguration(), "3");                                       // only column 3: item
        job.setMapperClass(OrcM.class); break;
      default: job.setMapperClass(TextM.class);
    }
    job.setCombinerClass(LongSumReducer.class);
    job.setReducerClass(LongSumReducer.class);
    job.setOutputKeyClass(Text.class);
    job.setOutputValueClass(LongWritable.class);
    FileInputFormat.addInputPath(job, new Path(rest[0]));
    FileOutputFormat.setOutputPath(job, new Path(rest[1]));
    System.exit(job.waitForCompletion(true) ? 0 : 1);
  }
}

Quick revision

Lesson 10.1 in one screen

  • Text/CSV: readable, no schema, splittable only uncompressed (or bzip2). Ours: 19.4 MB.
  • SequenceFile: binary key-value Writables, class names + codec in the header, sync markers (~every 100 KB). NONE 24.0 MB, RECORD 27.9 MB, BLOCK 4.7 MB.
  • Avro: JSON schema in the header, compact binary (zig-zag varints), sync markers between blocks, many languages. null 16.6 MB, snappy 7.8 MB, deflate 4.8 MB.
  • Schema evolution: fields matched by name; new fields need a default; renames use aliases; int → long promotion allowed.
  • Without a default: “AvroTypeException: … missing required field payment”.
  • hdfs dfs -text decodes SequenceFile and Avro; avro-tools getmeta / tojson inspect Avro.
  • Hadoop ships avro core, not avro-mapred: add it with -libjars and HADOOP_CLASSPATH.

Interview and viva questions

What is a SequenceFile in Hadoop?

A flat binary file of key-value pairs, where the keys and values are Writables. Its header names the key and value classes and the compression codec. Records can be stored uncompressed, record-compressed or block-compressed, and sync markers written every 100 KB or so let readers start in the middle, so the file stays splittable even when compressed. It is commonly used for intermediate MapReduce data and for packing many small files into one.

What is Apache Avro and why is it used with Hadoop?

Avro is a language-neutral data serialization system. An Avro data file stores its schema as JSON in the header, followed by compact binary records in blocks separated by sync markers, optionally compressed with deflate, snappy, zstandard or others. It is splittable, readable from many languages, and supports schema evolution, which is why it is popular for data ingestion, Kafka messages and the raw zone of data lakes.

What is schema evolution in Avro?

Reading data written with one schema (the writer's schema, stored in the file) using a different, compatible schema (the reader's schema). Avro matches fields by name: fields only in the reader's schema are filled from their default values, fields only in the writer's schema are ignored, aliases handle renames and some types can be promoted (int to long, float to double). Adding a field without a default breaks backward compatibility.

What is the difference between SequenceFile and Avro?

Both are binary, row-oriented, compressible and splittable. A SequenceFile stores Java Writable key-value pairs and records only the class names, so it is mainly used inside Hadoop. Avro stores a full language-neutral schema with named, typed fields, can be read from many languages and supports schema evolution, so it suits data exchanged between systems and teams.

Which compression type should I use for SequenceFiles?

BLOCK compression, which compresses many records together. RECORD compression compresses each value separately, which barely helps (or even hurts) for small values: in our lab a 5 lakh order SequenceFile was 24.0 MB uncompressed, 27.9 MB with RECORD and 4.7 MB with BLOCK compression.

P8Advanced

A tiny container file

Write records into blocks of 3 with a sync marker before each block, then read only the block that starts after byte 20.

Input
7 records
Expected output
b'\xff\xfer1,r2,r3;\xff\xfer4,r5,r6;\xff\xfer7;'
split from byte 20 starts at 22 -> b'r7'
Show solution and explanation 
SYNC = b"\xff\xfe"
recs = [f"r{i}".encode() for i in range(1, 8)]
f = b""
for i in range(0, len(recs), 3):
    f += SYNC + b",".join(recs[i:i + 3]) + b";"
start = f.find(SYNC, 20)
print(f)
print("split from byte 20 starts at", start, "->", f[start + 2:].split(b";")[0])

How it works: The reader skips the partial block and starts at the next marker; the reader of the previous split finishes that block. This is how Avro and SequenceFile splits work.

A producer added a field and consumers started failing

After a release, Spark jobs reading old Avro files fail with “missing required field”.

The interviewer is checking: reader vs writer schema and defaults.

Show a strong answer
  • The new reader schema has a field that old files lack and it has no default, so resolution fails.
  • Fix: add a default (or make it a union with null, default null) and redeploy; old and new files then both read.
  • Prevent it: a schema registry with BACKWARD compatibility checks in CI before producers can publish.

“We compressed our SequenceFiles and they got bigger”

A team switched on compression for an intermediate dataset of short records.

The interviewer is checking: RECORD vs BLOCK compression.

Show a strong answer
  • They probably used RECORD compression: each small value is compressed alone, with no repetition to exploit and per-value overhead.
  • Switch to BLOCK compression (mapreduce.output.fileoutputformat.compress.type=BLOCK), which compresses many records together.
  • Our measurement: 24.0 MB uncompressed, 27.9 MB RECORD, 4.7 MB BLOCK.

Choose formats for a new data lake

Events arrive from Kafka; analysts run SQL over a few columns of billions of rows.

The interviewer is checking: row vs columnar by workload.

Show a strong answer
  • Raw/landing zone: Avro, which is fast to append, keeps whole records and schema history, and matches the Kafka schemas.
  • Curated tables: Parquet or ORC, since columnar storage reads only the needed columns and compresses better.
  • A scheduled job converts and compacts raw Avro into partitioned columnar tables.
