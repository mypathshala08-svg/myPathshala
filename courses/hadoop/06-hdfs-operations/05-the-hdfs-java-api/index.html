The HDFS Java API

The shell is great for people; programs need an API. This lesson writes and runs two Java programs against the lab cluster with the Hadoop FileSystem API: one that writes, reads, inspects, renames and deletes a file, and one that counts items in a big file. Then the same file is read over plain HTTP with WebHDFS. Every output is real.

1 The story

When the shell is not enough

The canteen app's backend, written in Java, must save every order batch into HDFS and read daily totals back. Riya's first version calls hdfs dfs -put from Java with Runtime.exec(). It works, but each call starts a new JVM: 1.8 seconds per batch, and errors arrive as text she has to parse. Arjun shows her that every hdfs dfs command is itself a small Java program built on one class, FileSystem, and her backend can use that class directly.

Arjun Sir

Everything you did with the shell, you can do from code: fs.create() is -put, fs.open() is -cat, fs.rename() is -mv. The JVM starts once, connections are reused, and errors are real Java exceptions.

Riya

Is it different from writing a normal file?

Arjun Sir

Almost the same streams you know from Java. The difference is what happens underneath: a create asks the NameNode, the bytes go through the write pipeline from Lesson 6.1, and open reads from the nearest DataNode as in Lesson 6.2. Spark and Hive use this same class, which is why they can read HDFS and S3 with the same code.

2 Definition

The Hadoop FileSystem API

Formal definition (write this in exams)

The Hadoop FileSystem API (org.apache.hadoop.fs) is the Java interface through which all Hadoop clients access storage. FileSystem.get(Configuration) returns an implementation chosen by the URI scheme of fs.defaultFS or of a Path; for hdfs:// it is DistributedFileSystem, which uses a DFSClient to call the NameNode over RPC and to stream data to and from DataNodes. Files are created with create() (returning an FSDataOutputStream that supports hflush() and hsync()) and read with open() (returning a seekable FSDataInputStream). Metadata is returned as FileStatus and block placement as BlockLocation; namespace operations include mkdirs, listStatus, rename and delete.

In simple words

A Java library that lets your program open, write, list, rename and delete HDFS files, the way the shell does, but inside your own application.

Words you'll meet in this lesson

ConfigurationLoads core-site.xml and hdfs-site.xml from the classpath; fs.defaultFS says where HDFS is.
FileSystemThe abstract class; get one with FileSystem.get(conf).
PathA file or folder name, absolute or relative, optionally a full URI.
FSDataOutputStreamWhat create() returns; hflush() makes data visible to readers.
FSDataInputStreamWhat open() returns; supports seek(offset).
FileStatusLength, replication, block size, owner, permission, times.
BlockLocationOffset, length and hosts of one block.
WebHDFSThe same operations over HTTP/JSON, for non-Java programs.

API facts worth remembering

FileSystem.get(conf)Returns a cached, shared instance per scheme, authority and user; closing it closes it for the whole JVM
rename()Returns false on many failures instead of throwing: always check it
delete(path, true)Recursive and permanent: the API does not use the trash
create(path, true)true = overwrite an existing file
VisibilityOther readers see written data after hflush() or close()
Classpathhadoop classpath prints the jars to compile and run with

The API at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Like Java file handling you already know

  • Path is like java.io.File, open()/create() give streams.
  • You wrap them in a BufferedReader or write bytes, as usual.
  • Always close streams (try-with-resources).

Intermediate Everyday use

  • Upload: fs.copyFromLocalFile(src, dst), or create() and write.
  • Check before reading: fs.exists(p), fs.getFileStatus(p).getLen().
  • Walk a tree: fs.listFiles(dir, true) (recursive iterator, includes block locations).
  • Publish results: write into a temporary folder, then one fs.rename().

Advanced What library and framework authors care about

  • getFileBlockLocations is how MapReduce and Spark place tasks near data.
  • hflush() vs hsync(): visible to readers vs also forced to disk on DataNodes.
  • Seek + read lets a reader start in the middle of a file: that is how input splits work.
  • Use FileSystem.newInstance() if your code must close its own instance without affecting others.
  • On a secure cluster, the same code needs a Kerberos login (UserGroupInformation).

Exam tip: “Write a Java program to read a file from HDFS.” Steps: create a Configuration; FileSystem fs = FileSystem.get(conf); FSDataInputStream in = fs.open(new Path(...)); read lines with a BufferedReader (or IOUtils.copyBytes(in, System.out, 4096, false)); close the stream. Mention that open() gets block locations from the NameNode and reads from DataNodes.

Six API calls, and who answers each

The calls from HdfsBasics, in order.

From Java call to NameNode and DataNodes 6 steps
What you see
  1. FileSystem.get reads the configuration and connects.
  2. create returns an output stream.
  3. Writing and closing stores the file.
  4. open returns an input stream.
  5. Reading prints the three lines.
  6. Rename and delete both return true.
Behind the screen
  1. The configuration's fs.defaultFS picks DistributedFileSystem, which wraps a DFSClient.
  2. create is one RPC to the NameNode: the file exists, still empty and open for writing.
  3. write + close: addBlock, the DataNode pipeline (Lesson 6.1), then complete.
  4. open asks the NameNode where the blocks are (Lesson 6.2).
  5. Reading streams bytes directly from a DataNode.
  6. rename and delete touch only the NameNode.
6 Real-world use

The API at work

1. Ingestion services

Services that collect events (from Kafka, logs or apps) keep an HDFS file open, write records and call hflush() regularly so readers see recent data, then roll to a new file every hour.

Events→create + write + hflush→Hourly files

2. Moving to the cloud

Teams migrating from on-premise Hadoop to cloud object stores often change only paths and configuration: Spark and Hive jobs keep working because they talk to the FileSystem abstraction.

hdfs:// paths→FileSystem API→s3a:// paths

3. Non-Java tools

Dashboards and Python scripts read result files through WebHDFS or HttpFS (a gateway that also hides the DataNodes), with no Hadoop installation on the client.

Python app→HTTP/JSON→HDFS

4. Housekeeping tools

Admins write small Java tools that walk the namespace once with listFiles(dir, true) to find small files, old data or wrong replication, far faster than thousands of shell calls.

listFiles→Filter in Java→Report or fix

Simplified; organisations differ in tools and policies.

7 Run the code

The FileSystem API, modelled in Python

The Java API can't run in your browser, so this Python class copies its shape: create, open, get_file_status, get_file_block_locations, rename and delete, with a NameNode namespace and 128 MB blocks placed on DataNodes. Run it, then try the tasks.

BLOCK = 128 * 1024 * 1024

class FileSystem:
    def __init__(self, datanodes):
        self.ns = {}                       # path -> (length, replication, blocks)
        self.dns = datanodes
        self.next_dn = 0

    def create(self, path, data_len, replication=3):
        blocks = []
        for off in range(0, data_len, BLOCK):
            hosts = [self.dns[(self.next_dn + i) % len(self.dns)] for i in range(replication)]
            self.next_dn += 1
            blocks.append((off, min(BLOCK, data_len - off), hosts))
        self.ns[path] = (data_len, replication, blocks)

    def get_file_status(self, path):
        length, rep, blocks = self.ns[path]
        return {"path": path, "len": length, "replication": rep, "blocksize": BLOCK}

    def get_file_block_locations(self, path):
        return self.ns[path][2]

    def rename(self, src, dst):            # returns False instead of raising, like Java
        if src not in self.ns or dst in self.ns:
            return False
        self.ns[dst] = self.ns.pop(src)
        return True

    def delete(self, path):
        return self.ns.pop(path, None) is not None

fs = FileSystem(["datanode-1", "datanode-2", "datanode-3"])
fs.create("/user/hadoop/data/orders_x30.csv", 140_760_270)
print(fs.get_file_status("/user/hadoop/data/orders_x30.csv"))
for off, length, hosts in fs.get_file_block_locations("/user/hadoop/data/orders_x30.csv"):
    print(f"  block at offset {off:,} length {length:,} on {', '.join(hosts)}")

Run it on your PC: Java against HDFS

Save these files in the hdfs-lab folder. The namenode container already has Java and the Hadoop jars, so we copy the files in, compile there with javac -cp $(hadoop classpath), package a jar and run it with hadoop jar. The exact commands are at the end of the first file.

Write, read, inspect, rename, delete

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.nio.charset.StandardCharsets;

import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.BlockLocation;
import org.apache.hadoop.fs.FSDataInputStream;
import org.apache.hadoop.fs.FSDataOutputStream;
import org.apache.hadoop.fs.FileStatus;
import org.apache.hadoop.fs.FileSystem;
import org.apache.hadoop.fs.Path;

public class HdfsBasics {
    public static void main(String[] args) throws Exception {
        Configuration conf = new Configuration();          // reads core-site.xml, hdfs-site.xml
        try (FileSystem fs = FileSystem.get(conf)) {
            System.out.println("Connected to: " + fs.getUri());

            Path dir = new Path("/user/hadoop/api_demo");
            fs.mkdirs(dir);

            // write a small file
            Path file = new Path(dir, "orders.csv");
            try (FSDataOutputStream out = fs.create(file, true)) {   // true = overwrite
                out.write("order_id,item,amount\n".getBytes(StandardCharsets.UTF_8));
                out.write("3001,samosa,18\n3002,chai,15\n".getBytes(StandardCharsets.UTF_8));
            }

            // read it back
            try (FSDataInputStream in = fs.open(file);
                 BufferedReader r = new BufferedReader(new InputStreamReader(in, StandardCharsets.UTF_8))) {
                String line;
                while ((line = r.readLine()) != null) {
                    System.out.println("  read: " + line);
                }
            }

            // metadata, as the NameNode stores it
            FileStatus st = fs.getFileStatus(file);
            System.out.printf("%s  %d bytes  replication %d  block size %d MB  owner %s%n",
                    st.getPath().getName(), st.getLen(), st.getReplication(),
                    st.getBlockSize() / (1024 * 1024), st.getOwner());

            // where are the blocks of a big file?
            Path big = new Path("/user/hadoop/data/orders_x30.csv");
            FileStatus bs = fs.getFileStatus(big);
            for (BlockLocation b : fs.getFileBlockLocations(bs, 0, bs.getLen())) {
                System.out.printf("  block at offset %,d length %,d on %s%n",
                        b.getOffset(), b.getLength(), String.join(", ", b.getHosts()));
            }

            // list, rename, delete
            for (FileStatus s : fs.listStatus(dir)) {
                System.out.println("  ls: " + s.getPath());
            }
            Path renamed = new Path(dir, "orders_old.csv");
            System.out.println("rename: " + fs.rename(file, renamed));
            System.out.println("exists after rename: " + fs.exists(file));
            System.out.println("delete: " + fs.delete(dir, true));             // true = recursive
        }
    }
}

Count orders per item, streaming one file

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.nio.charset.StandardCharsets;
import java.util.Map;
import java.util.TreeMap;

import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.FSDataInputStream;
import org.apache.hadoop.fs.FileSystem;
import org.apache.hadoop.fs.Path;

/** Count orders per item by streaming one HDFS file through a single client. */
public class ItemCount {
    public static void main(String[] args) throws Exception {
        Path path = new Path(args[0]);
        Map<String, Integer> counts = new TreeMap<>();
        long start = System.currentTimeMillis();
        try (FileSystem fs = FileSystem.get(new Configuration());
             FSDataInputStream in = fs.open(path);
             BufferedReader r = new BufferedReader(new InputStreamReader(in, StandardCharsets.UTF_8))) {
            r.readLine();                                         // skip the header
            String line;
            while ((line = r.readLine()) != null) {
                String item = line.split(",")[1];
                counts.merge(item, 1, Integer::sum);
            }
        }
        counts.forEach((item, n) -> System.out.printf("%-9s %,d%n", item, n));
        System.out.println("took " + (System.currentTimeMillis() - start) + " ms in one JVM");
    }
}

Expected output

Example 3AdvancedParallelism · blocks

How many parallel readers for a 1-hour target?

Problem statement

A 4 TB file has 128 MB blocks. If each reader handles whole blocks at 68 MB/s, how many parallel readers are needed to finish within one hour, and how many blocks does each read?

Input
4 TB · 128 MB blocks · 68 MB/s · 1 hour
Expected output
32,768 blocks, 18 readers, about 1821 blocks each

Approach

  1. Blocks = size ÷ 128 MB.
  2. One reader reads 68 × 3600 MB per hour.
  3. Readers = ceil(size ÷ per-reader capacity); blocks each = blocks ÷ readers.

  • Lab: 300,000 orders in 1.3 s; 403 MB in 5.9 s (≈68 MB/s) through one client.
  • WebHDFS: REST on port 9870, OPEN redirects (307) to a DataNode on 9864.
  • Run with javac -cp $(hadoop classpath) and hadoop jar app.jar Class.

Interview and viva questions

How do you read a file from HDFS in Java?

Create a Configuration, get a FileSystem with FileSystem.get(conf), call fs.open(new Path("/path")) to get an FSDataInputStream, wrap it in a BufferedReader (or copy it with IOUtils.copyBytes), and close the stream. The client gets block locations from the NameNode and reads the bytes directly from DataNodes.

How do you write a file to HDFS in Java?

Call fs.create(path, overwrite) to get an FSDataOutputStream, write bytes, and close it. Closing completes the file on the NameNode. Use hflush() to make written data visible to readers before closing, and hsync() to also force it to disk on the DataNodes.

What is the difference between FileSystem.get() and FileSystem.newInstance()?

get() returns a cached instance shared across the JVM for the same scheme, authority and user; closing it affects every user of that instance. newInstance() always returns a new instance that you own and may close.

What is WebHDFS?

A REST API for HDFS served by the NameNode (port 9870 in Hadoop 3) and DataNodes (port 9864). Metadata operations are answered by the NameNode; for reading and writing data it redirects the client to a DataNode. It lets any language use HDFS over HTTP.

How does Spark know where HDFS blocks are?

Through the same FileSystem API: getFileBlockLocations (or listFiles with locations) returns the hosts of each block, and the scheduler prefers to run a task on one of those hosts.

Can the same Java code access S3?

Yes, if the S3A connector is on the classpath and configured: FileSystem.get(URI.create("s3a://bucket/"), conf) returns an S3AFileSystem with the same methods. Some semantics differ (for example rename is a copy on object stores, not an atomic metadata change).

P8Advanced

Locality-aware task plan

Given block locations (like getFileBlockLocations returns) and 3 worker nodes, assign each block to a worker that holds a replica, keeping the load as even as possible. Print the plan and how many blocks are local.

Input
6 blocks · hosts per block
Expected output
{'dn-1': [(0, 'local'), (4, 'local')], 'dn-2': [(1, 'local'), (3, 'local')], 'dn-3': [(2, 'local'), (5, 'local')]}
local: 6 of 6
Show solution and explanation 
locs = {0: ["dn-1", "dn-2", "dn-3"], 1: ["dn-1", "dn-2", "dn-3"], 2: ["dn-1", "dn-3", "dn-4"],
        3: ["dn-2", "dn-4", "dn-5"], 4: ["dn-1", "dn-5", "dn-2"], 5: ["dn-4", "dn-5", "dn-3"]}
workers = {"dn-1": [], "dn-2": [], "dn-3": []}
for b, hosts in locs.items():
    local = [w for w in workers if w in hosts]
    pick = min(local or workers, key=lambda w: len(workers[w]))
    workers[pick].append((b, "local" if pick in hosts else "remote"))
print(workers)
print("local:", sum(t == "local" for v in workers.values() for _, t in v), "of", len(locs))
{'dn-1': [(0, 'local'), (4, 'local')], 'dn-2': [(1, 'local'), (3, 'local')], 'dn-3': [(2, 'local'), (5, 'local')]} local: 6 of 6

How it works: Every block finds a worker with a local replica here, two blocks each. This is the core idea of MapReduce scheduling (Module 8): move the computation to the data.

Real-world scenario questions (asked in company interviews)

API questions check whether you can go beyond the shell and understand what client code really does.

HDFS · JavaFresher

“Write code to copy a local file to HDFS”

A whiteboard coding question.

The interviewer is checking: Configuration, FileSystem, Path, closing resources.

Show a strong answer
  • Configuration conf = new Configuration(); FileSystem fs = FileSystem.get(conf);
  • fs.copyFromLocalFile(new Path("orders.csv"), new Path("/user/hadoop/raw/"));, or fs.create() plus IOUtils.copyBytes() from a local input stream.
  • Close streams with try-with-resources; mention that the bytes go through the DataNode write pipeline.
Production · bugExperienced

A web service fails with “java.io.IOException: Filesystem closed”

It happens randomly, after some requests finish.

The interviewer is checking: the FileSystem cache.

Show a strong answer
  • Some code calls fs.close() on an instance from FileSystem.get(), which is cached and shared by all threads.
  • Fix: never close the shared instance (close only streams), or use FileSystem.newInstance() where code must own and close its instance.
DesignExperienced

A Python dashboard must read results from HDFS

No Hadoop installation on the dashboard servers, and a firewall in between.

The interviewer is checking: WebHDFS vs HttpFS.

Show a strong answer
  • WebHDFS works over HTTP, but OPEN redirects to DataNodes on port 9864, so every DataNode must be reachable.
  • Through a firewall, use HttpFS: a gateway that streams the data itself, so only one host and port are opened.
  • Keep results small (aggregated by Hive or Spark) so the dashboard never pulls raw data.
PerformanceFresher

“My Java program takes 17 hours to scan 4 TB. Why?”

A single program reads a big file from start to end.

The interviewer is checking: single client vs parallel processing.

Show a strong answer
  • One client reads one stream: in our lab about 68 MB/s, so 4 TB ≈ 17 hours.
  • HDFS can serve many readers at once. Split the work by blocks (getFileBlockLocations) and run readers on the nodes that hold them: that is MapReduce or Spark.
