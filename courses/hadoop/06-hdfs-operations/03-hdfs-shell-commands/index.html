HDFS shell commands

You will use hdfs dfs every day. This lesson runs the important commands on a real cluster and shows their exact output, then explains what each one does behind the screen: which commands only change the NameNode's metadata and finish instantly, which ones read and write data through DataNodes, and which defaults (like trash being off) catch people out.

1 The story

Linux commands, with a twist

Riya's first day on the data team. Her task: put two days of canteen orders into HDFS, check them, merge them into one local file for the accounts team, and clean up. She guesses hdfs dfs -ls, -mkdir, -cat, -rm, and they all work like Linux. Then two surprises. Copying a 403 MB file takes 5.6 seconds, but moving it takes 1.9 seconds, the same as deleting it. And when she deletes a file by mistake, it's simply gone: no trash.

Arjun Sir

hdfs dfs deliberately looks like Linux, so you'll feel at home in a day. But think about where each command works. mv only changes a name in the NameNode's memory, so moving a 403 MB file, or a 4 TB folder, takes the same time: most of those 1.9 seconds were just Java starting up. cp has to read every byte and write it again through a pipeline.

Riya

And the trash?

Arjun Sir

HDFS has a trash, but fs.trash.interval is 0 by default, so it's off unless the admins switch it on. On our lab it's off. With it on, -rm moves files to .Trash and you can get them back. Today: the commands you'll use every day, with real outputs, and which ones to be careful with.

2 Definition

The HDFS shell

Formal definition (write this in exams)

The HDFS shell is the command-line client for Hadoop file systems, invoked as hdfs dfs <command> (equivalent to hadoop fs for HDFS paths). Its commands mirror POSIX tools: listing and inspecting (-ls, -du, -df, -count, -stat, -test, -find, -checksum), reading (-cat, -head, -tail, -text), transferring between local and HDFS (-put/-copyFromLocal, -get/-copyToLocal, -getmerge, -moveFromLocal), changing the namespace (-mkdir, -mv, -cp, -rm, -appendToFile, -touchz) and managing attributes (-chmod, -chown, -chgrp, -setrep). Paths may be absolute (/user/…), relative to the user's home /user/<name>, or full URIs (hdfs://namenode/…, file:///…). Generic options such as -D property=value come before the command.

In simple words

hdfs dfs -something is Linux file handling for HDFS: list, copy in, copy out, read, move, delete, change permissions. Commands that only rename or list are instant; commands that move data take time.

The shell at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Like a phone's file manager

  • Folders, files, copy, move, delete: the same ideas.
  • Upload (-put) is like sending a photo to the cloud; download (-get) brings it back.
  • Renaming is instant; copying a big video takes time. HDFS behaves the same way.

Intermediate Everyday patterns

  • Load data: -mkdir -p, then -put (or -put -f to replace).
  • Check: -ls, -du -s -h, -count, -head / -tail.
  • Publish results: jobs write to a temporary folder, then one -mv makes them visible atomically.
  • Export: -getmerge a result folder into one local file for business users.
  • Script checks: hdfs dfs -test -e path && ….

Advanced Things to know before you script

  • Each call starts a JVM. For thousands of small operations use the Java API, WebHDFS, or one job, not a loop of shell calls.
  • -cp copies through the client (it reads and writes every byte); for big copies use distcp, which runs as a parallel job.
  • -rm -r on a big folder is fast for you but creates lots of block deletions for DataNodes, done in the background.
  • Trash is per user and client-side policy plus server setting; never rely on it for important data.
  • Globs (*, ?) are expanded by HDFS: quote them so your local shell doesn't expand them first.

Exam tip: For “List any ten HDFS shell commands with syntax”, group them: list (-ls, -du, -count), read (-cat, -tail), transfer (-put, -get, -getmerge), change (-mkdir, -mv, -cp, -rm), attributes (-chmod, -chown, -setrep). Give the syntax hdfs dfs -command [options] path and one example each.

5 See it happen

Which daemons does each command wake up?

Six commands from Part 4, and the daemons each one involves.

Metadata commands vs data commands 6 steps
What you see
  1. -ls: a listing with permissions, replication, owner, size and time.
  2. -put: uploads two files; silence means success.
  3. -cat: prints the file contents.
  4. -mv of a 403 MB file: under 2 seconds, mostly Java start-up.
  5. -cp of the same file: 5.6 seconds, three times longer.
  6. -rm with trash off: deleted immediately.
Behind the screen
  1. -ls talks only to the NameNode.
  2. -put uses the full write pipeline (Lesson 6.1).
  3. -cat uses the read path (Lesson 6.2).
  4. -mv changes one entry in the namespace: no DataNode is involved.
  5. -cp is a read plus a write of the whole file through the client.
  6. -rm removes the entry at once; DataNodes delete the block files later, when the NameNode tells them in heartbeat replies.
6 Real-world use

The shell at work

1. Atomic publishing with mv

Pipelines write today's results into out/_tmp_2026-10-21 and only then -mv it to out/2026-10-21. Readers never see half-written data, because a rename is instant and all-or-nothing.

Write to tmp→-mv→Visible at once

2. Shell checks in schedulers

Airflow or cron jobs start the next step only if hdfs dfs -test -e input/_SUCCESS returns 0, and alert if -du -s shows an unusually small input.

-test→Exit code→Run or alert

3. Handing results to business users

A job writes part-00000 … part-00099; an analyst runs -getmerge to get one CSV for a spreadsheet (and removes repeated headers first, as we saw).

part files→getmerge→One CSV

4. Trash as a safety net

Most production clusters set fs.trash.interval to a day or more. Support teams regularly restore files from .Trash after accidental deletes, something impossible with the default of 0.

Wrong -rm→.Trash→-mv back

Simplified; organisations differ in tools and policies.

7 Run the code

A tiny HDFS shell in Python

This program keeps a namespace in a dictionary (path → size and replication) and implements ls, mv, du and rm, counting which ones would touch DataNodes. Run it, then try the tasks.

ns = {"/user/hadoop/raw/mon.csv": (47, 3), "/user/hadoop/raw/tue.csv": (34, 3)}
datanode_bytes = 0

def ls(folder):
    for path, (size, rep) in sorted(ns.items()):
        if path.startswith(folder + "/"):
            print(f"-rw-r--r--  {rep} hadoop {size:>6} {path}")

def mv(src, dst):                 # metadata only: no bytes move
    ns[dst] = ns.pop(src)

def cp(src, dst):                 # reads and writes every byte
    global datanode_bytes
    size, rep = ns[src]
    datanode_bytes += size + size * rep
    ns[dst] = (size, rep)

def du(folder):
    files = [v for p, v in ns.items() if p.startswith(folder + "/")]
    print(sum(s for s, r in files), sum(s * r for s, r in files), folder)

cp("/user/hadoop/raw/mon.csv", "/user/hadoop/mon_backup.csv")
mv("/user/hadoop/mon_backup.csv", "/user/hadoop/archive_mon.csv")
ls("/user/hadoop/raw")
du("/user/hadoop")
print("bytes through DataNodes:", datanode_bytes)
-rw-r--r-- 3 hadoop 47 /user/hadoop/raw/mon.csv -rw-r--r-- 3 hadoop 34 /user/hadoop/raw/tue.csv 128 384 /user/hadoop bytes through DataNodes: 188
  • def mv(src, dst): # metadata only: no bytes moveA rename only changes the key in the namespace. That is why -mv of 403 MB took 1.863 s, mostly Java start-up.
  • datanode_bytes += size + size * repcp reads the file once and writes it again with 3 replicas: 47 + 141 bytes here.
  • print(sum(s for s, r in files), sum(s * r for s, r in files), folder)The two du columns: data size and raw space with replicas. Real output: 81 243 for the shell_lab folder before the copy.

Interview and viva questions

What is the difference between hadoop fs and hdfs dfs?

They run the same FsShell. hadoop fs works with any file system Hadoop supports (HDFS, local, S3, ADLS…), and hdfs dfs is the conventional name when working with HDFS. hadoop dfs is an old deprecated form.

How do I copy a file from local disk to HDFS?

hdfs dfs -put localfile /hdfs/path/ (or -copyFromLocal). Use -f to overwrite an existing file. To move instead of copy, -moveFromLocal deletes the local file after upload.

Why is hdfs dfs -mv so fast?

A move or rename within HDFS only changes the path in the NameNode namespace; no block data is copied. Its time is dominated by the client JVM start-up, so it is the same for a tiny or a huge file.

How do I recover a deleted file?

Only if trash was enabled (fs.trash.interval > 0) and the file was not deleted with -skipTrash: move it back from /user/<name>/.Trash/Current/<original path>. Otherwise restore from a snapshot or backup if one exists.

What do the columns of hdfs dfs -du mean?

First: the size of the data. Second: the disk space consumed including all replicas. Then the path. With -s you get one total line for the folder, and -h prints human-readable units.

How do I change the replication factor of existing files?

hdfs dfs -setrep N path (folders apply to all files inside). The NameNode updates the metadata immediately and schedules extra copies or deletions; -w waits until the actual replica count matches.

P3Easy

Octal permissions

Convert chmod 640 into the rwx string that -ls shows.

Input
640
Expected output
-rw-r-----
Show solution and explanation 
def rwx(mode):
    return "".join(("r" if d & 4 else "-") + ("w" if d & 2 else "-") + ("x" if d & 1 else "-") for d in map(int, mode))
print("-" + rwx("640"))
-rw-r-----

How it works: -rw-r-----, exactly what the real -ls showed after hdfs dfs -chmod 640 day1.csv.

P8Advanced

Mini FsShell

Implement mkdir -p, put (fail if the file exists unless -f), and rm with optional trash on a dictionary namespace. Print the messages like the real shell.

Input
commands list
Expected output
put: `/user/hadoop/lab/raw/a.csv': File exists
Moved: '/user/hadoop/lab/raw/a.csv' to trash at: /user/hadoop/.Trash/Current/user/hadoop/lab/raw/a.csv
['/user/hadoop/.Trash/Current/user/hadoop/lab/raw/a.csv']
Show solution and explanation 
ns, trash_on = {"/user/hadoop": "dir"}, True

def mkdir_p(p):
    parts = p.strip("/").split("/")
    for i in range(1, len(parts) + 1):
        ns.setdefault("/" + "/".join(parts[:i]), "dir")

def put(p, size, force=False):
    if p in ns and not force:
        print(f"put: `{p}': File exists"); return
    ns[p] = size

def rm(p):
    if trash_on:
        t = "/user/hadoop/.Trash/Current" + p
        ns[t] = ns.pop(p); print(f"Moved: '{p}' to trash at: {t}")
    else:
        del ns[p]; print("Deleted", p)

mkdir_p("/user/hadoop/lab/raw"); put("/user/hadoop/lab/raw/a.csv", 47)
put("/user/hadoop/lab/raw/a.csv", 50); put("/user/hadoop/lab/raw/a.csv", 50, force=True)
rm("/user/hadoop/lab/raw/a.csv")
print(sorted(p for p in ns if ns[p] != "dir"))
put: `/user/hadoop/lab/raw/a.csv': File exists Moved: '/user/hadoop/lab/raw/a.csv' to trash at: /user/hadoop/.Trash/Current/user/hadoop/lab/raw/a.csv ['/user/hadoop/.Trash/Current/user/hadoop/lab/raw/a.csv']

How it works: The second put prints File exists, the -f put overwrites, and rm moves the file to .Trash/Current with its full path, which is all that is left as a file.

Real-world scenario questions (asked in company interviews)

Shell questions check practical habits: safe deletes, fast scripts and knowing what each command really costs.

HDFS · basicsFresher

“Name ten HDFS commands you use”

The most common first question on HDFS.

The interviewer is checking: real usage, not a memorised list.

Show a strong answer
  • Group them: list/size (-ls, -du -s -h, -count), transfer (-put, -get, -getmerge), read (-cat, -tail), change (-mkdir -p, -mv, -cp, -rm -r), attributes (-chmod, -setrep).
  • Add one detail that shows experience: du's second column includes replicas; mv is metadata-only; trash is off by default.
Operations · safetyExperienced

Someone ran hdfs dfs -rm -r on a production folder

A colleague deleted yesterday's processed data by mistake and asks you to bring it back.

The interviewer is checking: trash, snapshots and prevention.

Show a strong answer
  • Check .Trash/Current of the user who ran it; if it is there, -mv it back.
  • If trash was off or -skipTrash was used, restore from a snapshot (.snapshot) or reprocess from raw data.
  • Prevent: enable fs.trash.interval, snapshot important folders, restrict write permissions on production paths.
Scripting · performanceExperienced

A housekeeping script takes 40 minutes

It loops over 1,300 paths, calling hdfs dfs -test and -rm for each.

The interviewer is checking: JVM start-up cost.

Show a strong answer
  • Each call starts a JVM (about 1.8 s): 1,300 × 2 calls ≈ 40 minutes, almost all start-up.
  • List once (-ls -R or -find), decide in the script, then pass many paths or a glob to one -rm.
  • For complex logic, use the Java API or Python with WebHDFS in a single process.
Pipelines · correctnessFresher

Reports sometimes read half-written output

A dashboard reads a folder while the nightly job is still writing to it.

The interviewer is checking: atomic rename.

Show a strong answer
  • Write to a temporary folder first, then publish with one -mv; a rename is atomic in the NameNode.
  • Also have readers wait for a _SUCCESS marker (-test -e).
