Word count end to end

Every MapReduce program has the same parts: a mapper, a reducer, a driver, a jar and one command. This lesson takes word count from an empty Java file to a sorted result in HDFS on a real cluster, follows what YARN does at each step, reads the errors you will meet first, and then kills a running task to watch Hadoop recover.

2 Definition

A MapReduce job, end to end

Formal definition (write this in exams)

A MapReduce application consists of a Mapper class, a Reducer class and a driver (a main method) that configures a Job: its input and output paths, the classes to use, and the output key and value types. It is compiled against the Hadoop libraries, packaged as a jar and launched with hadoop jar. On submission the client checks the output specification (the output directory must not exist), computes the input splits, copies the jar, configuration and split information to a staging directory in HDFS and submits an application to the YARN ResourceManager. YARN starts the job's MRAppMaster in a container; it requests containers for the map and reduce tasks, monitors them, reruns failed attempts (up to mapreduce.map.maxattempts = 4 by default), and commits the output. Job counters and task history are kept by the JobHistory Server after the job ends.

In simple words

You write three small pieces of Java, pack them into a jar and hand the jar to Hadoop with one command. Hadoop uploads it, YARN starts a manager for your job, the manager runs your map and reduce tasks on the workers (again if one fails), and the answer appears as files in HDFS.

The whole job at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner A recipe, a parcel and a kitchen

  • The Java file is a recipe: what to do with one line (map) and with one word's pile of ones (reduce).
  • The jar is the recipe sealed in a parcel so it can be sent to every kitchen (worker).
  • hadoop jar hands the parcel to the canteen manager (YARN), who appoints a supervisor for this order (the ApplicationMaster).
  • If one cook faints, the supervisor gives that cook's part to another cook. The final dish is the same.

Intermediate What each command does

  • javac -cp $(hadoop classpath) compiles against Hadoop's jars; jar cf wc.jar … packs the .class files, including the nested $TokenizerMapper and $IntSumReducer.
  • hadoop jar wc.jar WordCount in out runs main. GenericOptionsParser removes options like -D mapreduce.job.reduces=2 so rest holds only the two paths.
  • job.waitForCompletion(true) submits and then prints progress and counters until the job ends; the exit code tells scripts whether it worked.
  • Output: part-r-00000 (one per reducer) and _SUCCESS. Read it with hdfs dfs -cat, or sort it: | sort -k2,2nr | head.

Advanced What happens inside YARN

  • The client writes the jar, job.xml, job.split and job.splitmetainfo to the staging directory, then asks the ResourceManager for an application.
  • The RM starts the MRAppMaster in a container on some NodeManager. The AM reads the splits and requests one container per map (with the split's hosts as preferred locations) and the reducers.
  • Each task runs in a YarnChild JVM that downloads the jar from HDFS (localization). Tasks report progress to the AM over the umbilical protocol; a dead JVM ends its container with a non-zero exit code and the AM schedules a new attempt, preferably on another node.
  • When all reducers have committed, the FileOutputCommitter moves their output into place and writes _SUCCESS; the AM hands the history file to the JobHistory Server and exits.

Exam tip: For “Explain the execution flow of a MapReduce job on YARN”, list in order: client submits (output check, splits, staging) → ResourceManager allocates a container for the MRAppMaster → AM requests task containers → NodeManagers launch map tasks → shuffle → reduce tasks → output commit and _SUCCESS → history to the JobHistory Server. Add one line on failure: attempts are retried up to 4 times.

4 Step by step

From an empty file to a result in HDFS

Run on the Module 8 lab cluster (Lesson 8.1) with wordcount_lab.sh and kill_task.sh from “Run it on your PC”.

  1. Write the mapper and reducer

    // Mapper<input key, input value, output key, output value>
public void map(LongWritable offset, Text line, Context context) … {
  StringTokenizer it = new StringTokenizer(line.toString().toLowerCase(), " \t.,!?;:\"'()");
  while (it.hasMoreTokens()) { word.set(it.nextToken()); context.write(word, ONE); }
}
// Reducer<Text, IntWritable, Text, IntWritable>
public void reduce(Text word, Iterable<IntWritable> ones, Context context) … {
  int sum = 0;
  for (IntWritable one : ones) sum += one.get();
  result.set(sum); context.write(word, result);
}
    The four generic types must line up: the mapper's output types (Text, IntWritable) are the reducer's input types. word and result are reused objects: Hadoop serializes them on every write, so reuse is safe and saves millions of allocations.

  2. Write the driver

    String[] rest = new GenericOptionsParser(conf, args).getRemainingArgs();
Job job = Job.getInstance(conf, "word count");
job.setJarByClass(WordCount.class);
job.setMapperClass(TokenizerMapper.class);
job.setReducerClass(IntSumReducer.class);
job.setOutputKeyClass(Text.class);
job.setOutputValueClass(IntWritable.class);
FileInputFormat.addInputPath(job, new Path(rest[0]));
FileOutputFormat.setOutputPath(job, new Path(rest[1]));
System.exit(job.waitForCompletion(true) ? 0 : 1);
    setJarByClass tells Hadoop which jar to ship to the workers. Input format defaults to TextInputFormat (key = byte offset, value = line), output to TextOutputFormat (key TAB value).

  3. Compile and package

    javac -cp $(hadoop classpath) -d wc_classes WordCount.java
jar cf wc.jar -C wc_classes .
jar tf wc.jar | grep class
    WordCount$IntSumReducer.class WordCount$TokenizerMapper.class WordCount.class
    Nested classes compile to separate files with a $ in the name. They must be static: Hadoop creates them by reflection with no outer object.

  4. Submit and watch

    hadoop jar wc.jar WordCount /user/hadoop/data/feedback.txt /out/wc

  5. Read the result

    hdfs dfs -cat /out/wc/part-r-00000 | head -5

    The file is sorted by word (the shuffle sorts keys), not by count; sorting by count is a second step. “was” appears once in every line: 200,000. Good words (tasty, crispy…) appear about twice as often as bad ones (cold, stale…).

  6. Make it fail, twice, before it starts

    Both are caught by the client before anything is sent to YARN: the output check and the split calculation happen at submission. Cheap, early failures are a feature.

  7. Kill a running map task

    docker exec lab8-worker2-1 kill -9 <pid of the map task's YarnChild JVM>
bash attempts.sh job_1792601400460_0033
    Task Id : attempt_1792601400460_0033_m_000000_0, Status : FAILED Container exited with a non-zero exit code 137. Job job_1792601400460_0033 completed successfully Failed map tasks=1 Launched map tasks=5 attempt_…_m_000000_0 FAILED worker2 7.9 s attempt_…_m_000000_1 SUCCEEDED worker3 21.7 s attempt_…_m_000000_2 KILLED worker2 4.4 s Speculation: attempt_…_m_000000_1 succeeded first! chai 668620 was 4000000
    The AM saw the container die (137 = 128 + signal 9) and launched attempt _1 on worker3. It also started a speculative _2, which lost the race and was killed. The answer is exactly 20 × the small one (chai 20 × 33431 = 668620): a failed attempt's partial output is thrown away, never mixed in.

Don't “fix” FileAlreadyExistsException by deleting output folders automatically inside the driver unless you are sure. In production, a rerun silently replacing yesterday's results is worse than a job that refuses to start. Use dated output paths like /out/wc/dt=2026-10-21.

5 See it happen

The job's life, including a crash

Six steps of the 20× run: submit, ApplicationMaster, maps, a killed task, the retry and the reduce.

Word count on YARN 6 steps
What you see
  1. The client finds 3 splits in the 102 MB file and submits the application.
  2. YARN starts the job; it is too big for uber mode, so tasks get their own containers.
  3. Three map tasks start reading their blocks.
  4. We kill map 0's JVM: its attempt is reported FAILED with exit code 137.
  5. Progress continues as if nothing happened, and the reducer starts merging.
  6. Success: one failed attempt in the counters, and counts exactly 20× the small file.
Behind the screen
  1. The client uploads the jar, job.xml and split list to a staging folder in HDFS and submits the application.
  2. The ResourceManager launches the MRAppMaster, which requests one container per map and for the reducer.
  3. NodeManagers start three map tasks, each next to its block.
  4. We kill map 0. Its container exits with code 137 (SIGKILL) and the AM records a failed attempt.
  5. The AM reruns map 0 from the start on worker3. The reducer only uses output from successful attempts.
  6. The reducer's file is committed, _SUCCESS is written, and the job's history is archived.

6 Real-world use

Word count's real cousins

1. Feedback and review analysis

E-commerce and food apps count words and phrases in millions of reviews to find recurring complaints (“late”, “cold”) per city or restaurant, before any fancy model is trained.

Reviews→count (word, city)→Complaint trends

2. Log-level and error-code counts

The same job with “error code” instead of “word”: count exceptions per service per hour across thousands of servers' logs.

App logs→(code, 1)→Alerts and reports

3. Cluster smoke tests

After an upgrade or a new node, admins run the bundled wordcount example: if it succeeds, HDFS, YARN, the shuffle service and the history server all work together.

New cluster→examples wordcount→Go / no-go

4. Search and NLP preprocessing

Term frequencies over large text collections (news archives, court judgments, documents in Indian languages) are the first step of search ranking (TF-IDF) and of building vocabularies for language models.

Documents→(term, 1) per doc→TF-IDF, vocabulary

Simplified; organisations differ in tools and policies.

7 Run the code

Word count, exactly like the Java version

The tokenizer below uses the same delimiters as WordCount.java (space, tab and .,!?;:"'(), after lowercasing), so for the same lines it gives the same counts as the real job.

DELIMS = " \t.,!?;:\"'()"

def tokens(line):                         # like java.util.StringTokenizer(line.toLowerCase(), DELIMS)
    word, out = "", []
    for ch in line.lower():
        if ch in DELIMS:
            if word: out.append(word)
            word = ""
        else:
            word += ch
    if word: out.append(word)
    return out

lines = ["the idli was fresh", "Why is the chai was cold?", "loved the vada pav was tasty!", "the chai was hot"]
pairs = [(w, 1) for line in lines for w in tokens(line)]       # map
print(len(pairs), "pairs, e.g.", pairs[:5])

counts = {}
for w, one in pairs:                                           # shuffle + reduce
    counts[w] = counts.get(w, 0) + one
for w in sorted(counts):
    print(w, counts[w])
20 pairs, e.g. [('the', 1), ('idli', 1), ('was', 1), ('fresh', 1), ('why', 1)] chai 2 cold 1 fresh 1 hot 1 idli 1 is 1 loved 1 pav 1 tasty 1 the 4 vada 1 was 4 why 1
  • for ch in line.lower():toLowerCase() first, so “Why” and “why” are one key.
  • if ch in DELIMS:Punctuation splits words just like spaces: “cold?” becomes “cold”.
  • pairs = [(w, 1) for line in lines for w in tokens(line)] # mapOne pair per word: our 2 lakh lines produced 1,033,238 pairs.

Compile, package, run, read, fail

// WordCount.java: the classic first MapReduce program (new org.apache.hadoop.mapreduce API).
import java.io.IOException;
import java.util.StringTokenizer;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IntWritable;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;
import org.apache.hadoop.util.GenericOptionsParser;

public class WordCount {

  public static class TokenizerMapper extends Mapper<LongWritable, Text, Text, IntWritable> {
    private static final IntWritable ONE = new IntWritable(1);
    private final Text word = new Text();

    @Override
    public void map(LongWritable offset, Text line, Context context) throws IOException, InterruptedException {
      StringTokenizer it = new StringTokenizer(line.toString().toLowerCase(), " \t.,!?;:\"'()");
      while (it.hasMoreTokens()) {
        word.set(it.nextToken());
        context.write(word, ONE);                 // ("chai", 1)
      }
    }
  }

  public static class IntSumReducer extends Reducer<Text, IntWritable, Text, IntWritable> {
    private final IntWritable result = new IntWritable();

    @Override
    public void reduce(Text word, Iterable<IntWritable> ones, Context context) throws IOException, InterruptedException {
      int sum = 0;
      for (IntWritable one : ones) sum += one.get();
      result.set(sum);
      context.write(word, result);                // ("chai", 41873)
    }
  }

  public static void main(String[] args) throws Exception {
    Configuration conf = new Configuration();
    String[] rest = new GenericOptionsParser(conf, args).getRemainingArgs();
    if (rest.length != 2) { System.err.println("Usage: wordcount <in> <out>"); System.exit(2); }
    Job job = Job.getInstance(conf, "word count");
    job.setJarByClass(WordCount.class);
    job.setMapperClass(TokenizerMapper.class);
    job.setReducerClass(IntSumReducer.class);
    job.setOutputKeyClass(Text.class);
    job.setOutputValueClass(IntWritable.class);
    FileInputFormat.addInputPath(job, new Path(rest[0]));
    FileOutputFormat.setOutputPath(job, new Path(rest[1]));
    System.exit(job.waitForCompletion(true) ? 0 : 1);
  }
}

9 Quiz and revision

Check yourself

Quick revision

Lesson 8.6 in one screen

  • A job = Mapper + Reducer + driver; nested classes must be static; mapper output types = reducer input types.
  • Build: javac -cp $(hadoop classpath) → jar cf wc.jar; run: hadoop jar wc.jar WordCount in out; -D key=value via GenericOptionsParser/ToolRunner.
  • Submission: output check → splits → staging dir in HDFS → RM → MRAppMaster container → task containers (YarnChild JVMs).
  • Lab: 2 lakh lines → 1,033,238 pairs → 31 words; top: was 200000, the 166921.
  • Errors before start: FileAlreadyExistsException (output exists), InvalidInputException (input missing).
  • Failure: kill -9 → exit code 137 → attempt FAILED → rerun elsewhere (max 4 attempts); same counts.
  • New API org.apache.hadoop.mapreduce (Context, Iterable) vs old mapred (OutputCollector, Reporter, JobConf).
  • UIs: ResourceManager :8088 while running, JobHistory :19888 after; yarn logs -applicationId for task logs.

Interview and viva questions

How do you run a MapReduce program in Hadoop?

Compile the Java classes against the Hadoop libraries (javac -cp $(hadoop classpath)), package them into a jar (jar cf app.jar ...), make sure the input is in HDFS and the output folder does not exist, then run hadoop jar app.jar MainClass <input> <output>. Progress and counters are printed in the terminal; the result is in the output folder as part-r-NNNNN files.

What happens when you submit a MapReduce job to YARN?

The client checks the output path, computes input splits and uploads the jar, job.xml and split files to a staging directory in HDFS, then submits an application to the ResourceManager. The RM launches the MRAppMaster in a container; the AM requests containers for map and reduce tasks, NodeManagers launch them, the AM tracks progress and failures, and on success commits the output and passes the job history to the JobHistory Server.

What is the difference between the mapred and mapreduce APIs?

org.apache.hadoop.mapred is the original (old) API with Mapper and Reducer interfaces, OutputCollector, Reporter and JobConf. org.apache.hadoop.mapreduce is the newer API with abstract Mapper and Reducer classes, a Context object, Iterable values, setup/cleanup methods and the Job class. Both still work; new code should use org.apache.hadoop.mapreduce and never mix classes from the two.

What happens if a map task fails in Hadoop?

The MRAppMaster notices the failed attempt (an exception, a non-zero container exit code, or no progress for mapreduce.task.timeout) and schedules a new attempt, preferably on another node. A task may be attempted mapreduce.map.maxattempts times (4 by default) before the job fails. Output of failed attempts is discarded, so results are not affected.

Why does my job fail with “Output directory already exists”?

FileOutputFormat refuses to write into an existing directory so a job never overwrites earlier results by accident. Delete the folder with hdfs dfs -rm -r, or better, write each run to a new path such as a dated folder.

P5Medium

Join the two-word item

“vada pav” is split into “vada” and “pav”. Write a tokenizer that keeps known two-word phrases together.

Input
one line
Expected output
['loved', 'the', 'vada pav', 'was', 'tasty']
Show solution and explanation 
PHRASES = {"vada pav"}
def tokens(line):
    w = line.lower().split()
    out, i = [], 0
    while i < len(w):
        if i + 1 < len(w) and w[i] + " " + w[i + 1] in PHRASES:
            out.append(w[i] + " " + w[i + 1]); i += 2
        else:
            out.append(w[i]); i += 1
    return out
print(tokens("loved the vada pav was tasty"))
['loved', 'the', 'vada pav', 'was', 'tasty']

How it works: Mapper logic decides what a “word” is; Hadoop just counts whatever keys you emit.

Real-world scenario questions (asked in company interviews)

Interviewers love asking you to walk through a job end to end, and what happens when it breaks.

Concepts · flowFresher

“What happens after you type hadoop jar?”

A favourite follow-up after word count.

The interviewer is checking: the YARN execution flow.

Show a strong answer
  • The driver configures a Job; the client checks the output path, computes splits and uploads jar, job.xml and splits to the HDFS staging directory.
  • The ResourceManager starts the MRAppMaster in a container; the AM requests containers for maps (near their data) and reducers.
  • NodeManagers launch task JVMs; maps run, shuffle, reducers write part files; the committer writes _SUCCESS; history goes to the JobHistory Server.
Debugging · errorsFresher

Job fails with ClassNotFoundException: WordCount$TokenizerMapper

It ran fine in local mode but fails on the cluster.

The interviewer is checking: how code reaches the tasks.

Show a strong answer
  • The tasks run on other machines and only see what is in the job jar: check that setJarByClass is called and the jar contains the $ classes (jar tf).
  • Third-party libraries must be shipped too: -libjars (with ToolRunner), a fat jar, or the distributed cache.
  • Make sure nested Mapper/Reducer classes are public static.
Operations · failuresExperienced

Map tasks keep failing with exit code 137 on a big input

Nobody is running kill -9. The job eventually fails after 4 attempts.

The interviewer is checking: container memory limits.

Show a strong answer
  • 137 means SIGKILL; YARN kills containers that exceed their memory (“running beyond physical memory limits” in the diagnostics), or the OS OOM killer does.
  • Check yarn logs and the attempt diagnostics; raise mapreduce.map.memory.mb and keep mapreduce.map.java.opts (-Xmx) at about 80% of it.
  • Also look for a mapper that holds too much in memory (big HashMaps) and fix the code.
Design · pipelinesExperienced

“Top 10 words by count” with MapReduce

Word count output is sorted by word, not count.

The interviewer is checking: chaining jobs.

Show a strong answer
  • Job 1: word count. Job 2: each map keeps a local top 10 (counts are already final per word) and one reducer merges them.
  • Or swap key and value in job 2 and sort counts in descending order with a custom comparator and one reducer.
  • For small outputs like our 31 lines, hdfs dfs -cat | sort -k2,2nr | head is enough.
