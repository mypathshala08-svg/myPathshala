Hadoop Streaming with Python

Hadoop Streaming lets any program that reads lines and prints lines be a mapper or a reducer. This lesson writes a Python mapper and reducer for revenue per menu category, tests them with an ordinary Linux pipe, runs them on the cluster with the same result as the Java job, and then breaks the mapper to show where a Python error really ends up.

1 The story

Riya writes MapReduce without Java

The canteen committee wants revenue per menu category: drinks, snacks, breakfast, meals. Kabir knows Python well but has never written a line of Java. Riya has the Java version from Lesson 9.4 working, but Kabir asks: “Can't I just write two small Python scripts and let Hadoop run them on the cluster?” He can. Hadoop ships a tool for exactly this, and it works with any program that reads lines and prints lines.

Kabir

So Hadoop runs my Python script instead of a Java Mapper?

Arjun Sir

Alongside it. Each map task is still a Java process, but it starts your script as a child process, writes every input line to the script's standard input, and reads whatever the script prints. A line like meal⇥45 becomes the key meal and the value 45. That is Hadoop Streaming.

Riya

And the reducer gets all values of a key in a list, like in Java?

Arjun Sir

No, that's the one surprise. The reducer script gets plain lines, sorted by key, one after another. Your script has to notice when the key changes. Today we write both scripts, test them with an ordinary Linux pipe, run them on the cluster, and then break one on purpose to learn where Python errors hide.

2 Definition

Hadoop Streaming

Formal definition (write this in exams)

Hadoop Streaming is a utility shipped with Hadoop (hadoop-streaming-*.jar, run with mapred streaming or hadoop jar) that lets any executable or script that reads standard input and writes standard output act as the mapper, combiner or reducer of a MapReduce job. Each map task launches the mapper program as a subprocess and pipes its input records to it as lines of text; each output line is split at the first tab character into a key and a value (the whole line is the key if there is no tab). After the shuffle and sort, each reduce task pipes the key-value lines of its partition, sorted by key, to the reducer program, which must detect the boundaries between keys itself. The program and any files it needs are shipped to the worker nodes with the -files option; its interpreter must already be installed on every NodeManager.

In simple words

Write the map and the reduce as two small scripts that read lines and print key⇥value lines. Hadoop runs them on every node, sorts between them, and does everything else exactly as for a Java job.

Words you'll meet in this lesson

Streaming at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Two scripts and a pipe

  • The mapper reads order lines and prints one line per order: category⇥amount.
  • Hadoop collects those lines from all maps, sorts them by category and hands each reducer its share.
  • The reducer reads the sorted lines, keeps a running total, and prints the total whenever the category changes, and once more at the end.
  • On your laptop, head -1000 orders.csv | python3 mapper.py | sort | python3 reducer.py does the same thing; sort plays the shuffle.

Intermediate What Hadoop does with your script

  • Each task JVM (YarnChild) starts your command as a child process in the task's working folder, where -files placed your scripts and menu.csv.
  • Map input: with the default TextInputFormat, only the line (the value) is written to stdin, not the byte offset.
  • Your output lines are split at the first tab into key and value, partitioned with the HashPartitioner and sorted, just like Java map output (Lesson 8.4).
  • The reducer's stdin is key⇥value lines, grouped only in the sense that equal keys are next to each other. There is no Iterable of values.
  • If your process exits with a non-zero code, the attempt fails and is retried, up to 4 times, like any task (Lesson 8.6).

Advanced Options, limits and alternatives

  • -numReduceTasks 0 gives a map-only job (filtering, format conversion); -combiner takes a script too.
  • -D stream.num.map.output.key.fields=2 makes the first two tab-separated fields the key, so you can sort on a composite key; with KeyFieldBasedPartitioner you can partition on part of it (a Streaming-style secondary sort, Lesson 9.7).
  • Everything travels as text and every record crosses two pipes, so Streaming usually uses more CPU than the same job in Java. For the heavy work, Java (or Spark) wins.
  • Libraries such as mrjob and Pydoop wrap Streaming for Python. Today most Python work on Hadoop data uses PySpark instead, but Streaming is still the quickest way to run an existing script, or a shell command like grep, across a cluster.

Exam tip: For “What is Hadoop Streaming?”, say: a utility that lets any program reading stdin and writing stdout act as mapper or reducer; lines are split into key and value at the first tab; the reducer receives lines sorted by key and must detect key changes itself; files are shipped with -files. Then write the one-line command: mapred streaming -files m.py,r.py -input in -output out -mapper "python3 m.py" -reducer "python3 r.py".

Revenue per category in Python, on the cluster

Run inside the namenode container of the Module 8 lab, with student_orders.csv (Lesson 9.1) in HDFS. The full script is streaming_lab.sh in “Run it on your PC”.

  1. The mapper: one order in, one line out

    menu = {}
with open("menu.csv") as f:                 # shipped with -files
    for line in f:
        item, category, price, counter = line.strip().split(",")
        menu[item] = category

for line in sys.stdin:

  2. The reducer: watch for the key to change

    current, orders, total = None, 0, 0
for line in sys.stdin:
    category, amount = line.rstrip("\n").split("\t")
    if category != current:
        if current is not None:
            print(f"{current}\t{orders}\t{total}")
        current, orders, total = category, 0, 0
    orders += 1
    total += int(amount)
if current is not None:
    print(f"{current}\t{orders}\t{total}")

  3. Test with a Linux pipe first

  4. Run it on the cluster

    Streaming output files are called part-00000 (the older API's naming). Every number equals the Java counters job of Lesson 9.4: BREAKFAST 90,110 and ₹24,76,620, and so on.

  6. Break the mapper and find the error

    # a typo: itme instead of item
mapred streaming -files broken_mapper.py,revenue_reducer.py,menu.csv … -mapper "python3 broken_mapper.py" …
yarn logs -applicationId <app id> -log_files stderr
    Error: java.lang.RuntimeException: PipeMapRed.waitOutputThreads(): subprocess failed with code 1 Job job_1792643020992_0046 failed with state FAILED due to: Task failed task_1792643020992_0046_m_000002 -- the Python error is in the task's stderr: NameError: name 'itme' is not defined Traceback (most recent call last):
    The job log only says that the subprocess exited with code 1. Python's traceback went to the task's stderr, which YARN keeps in the container logs. Retrying cannot fix a typo: the failed attempts are retried (up to 4 by default) and fail the same way, so the job gives up.

Python (and every library your script imports) must be installed on every NodeManager, in the same version. A script that works on the edge node can fail on a worker with ModuleNotFoundError. Ship pure-Python helpers with -files or -archives, or use a container image that has them.

5 See it happen

Lines through the pipes

Six steps of one Streaming job: ship the files, map through a Python process, sort, reduce through another Python process, and what a failure looks like.

Streaming job 6 steps
What you see
  1. The command ships two scripts and the menu, and the client finds 3 splits.
  2. Three map tasks start; each launches its own Python mapper.
  3. Maps are done: 5 lakh category lines were printed by the scripts.
  4. The reducer script saw 4 categories; the job succeeds.
  5. Four output lines, identical to the Java job's totals.
  6. With a typo, the job only reports a failed subprocess; the Python error is in the task log.
Behind the screen
  1. The NodeManager localizes the -files into each container's working folder.
  2. The Java map task writes every input line to Python's stdin and reads its stdout.
  3. Each output line is split at the first tab into key and value, then partitioned and sorted.
  4. The reduce task pipes sorted key⇥value lines to the reducer script, which prints one line per key.
  5. The reducer's printed lines become the job output in HDFS.
  6. If the script crashes, only its exit code reaches the job; its error text is in the container's stderr.

Streaming at work

Simulate a Streaming job: mapper, sort, reducer

The mapper and reducer below are the lab scripts turned into functions that take and return lines. sorted() plays the shuffle, exactly as sort does in the local pipe test.

menu = {"chai": "drink", "coffee": "drink", "samosa": "snack", "vada pav": "snack",
        "poha": "breakfast", "idli": "breakfast", "dosa": "meal", "thali": "meal"}
orders = ["1,S1413,2026-09-14 15:30,dosa,45", "2,S0973,2026-09-26 20:11,samosa,18",
          "3,S0007,2026-09-01 13:37,samosa,18", "4,S0001,2026-09-02 08:10,chai,15",
          "5,S0002,2026-09-02 13:05,thali,80", "6,S0001,2026-09-03 08:20,poha,25"]

def mapper(lines):                      # stdin lines in, "key\tvalue" lines out
    out = []
    for line in lines:
        oid, student, time, item, amount = line.split(",")
        out.append(f"{menu.get(item, 'unknown')}\t{amount}")
    return out

def reducer(lines):                     # SORTED lines in; no list of values per key
    out, current, orders, total = [], None, 0, 0
    for line in lines:
        key, value = line.split("\t")
        if key != current:
            if current is not None:
                out.append(f"{current}\t{orders}\t{total}")
            current, orders, total = key, 0, 0
        orders += 1
        total += int(value)
    if current is not None:
        out.append(f"{current}\t{orders}\t{total}")
    return out

mapped = mapper(orders)
print("map output :", mapped)
shuffled = sorted(mapped)               # the shuffle and sort
print("sorted     :", shuffled)
for line in reducer(shuffled):
    print("reduce     :", line)
map output : ['meal\t45', 'snack\t18', 'snack\t18', 'drink\t15', 'meal\t80', 'breakfast\t25'] sorted : ['breakfast\t25', 'drink\t15', 'meal\t45', 'meal\t80', 'snack\t18', 'snack\t18'] reduce : breakfast 1 25 reduce : drink 1 15 reduce : meal 2 125 reduce : snack 2 36
  • out.append(f"{menu.get(item, 'unknown')}\t{amount}")Everything is text. The tab separates the key (category) from the value (amount), exactly what Hadoop splits on.
  • if key != current:The reducer only ever sees one line at a time, so it must notice where one key ends and the next begins.
  • if current is not None:After the loop the last key is still open: forget this and the last category silently disappears.

Interview and viva questions

What is Hadoop Streaming?

A utility that comes with Hadoop which lets you write the mapper and reducer of a MapReduce job in any language. Each task runs your program as a subprocess, writes input records to its standard input as lines, and reads its standard output as key and value lines separated by a tab. The shuffle, sort, scheduling and fault tolerance are the same as for Java jobs.

How do you run a Python MapReduce job on Hadoop?

Write a mapper and a reducer script that read sys.stdin and print key TAB value lines, test them with cat file | python3 mapper.py | sort | python3 reducer.py, then run mapred streaming -files mapper.py,reducer.py -input <hdfs input> -output <hdfs output> -mapper "python3 mapper.py" -reducer "python3 reducer.py". Python must be installed on every NodeManager.

How is a Streaming reducer different from a Java reducer?

A Java reducer is called once per key with an Iterable of all its values. A Streaming reducer is one process that reads all the lines of its partition, sorted by key, so the script must remember the current key, accumulate values, and output a result whenever the key changes and once more at the end of input.

How do I debug a failed Hadoop Streaming job?

The job output usually only shows “PipeMapRed.waitOutputThreads(): subprocess failed with code 1”. Read the failed task's stderr with yarn logs -applicationId <id> -log_files stderr (or the JobHistory UI) to see the real error, such as a Python traceback. Test the scripts first with a local Unix pipe, and never print debug text to stdout.

Is Hadoop Streaming slower than Java MapReduce?

Usually somewhat, because every record is converted to text and passed through pipes to and from a separate process, and the scripting language itself may be slower. For many jobs the difference is small compared with the I/O; for CPU-heavy jobs Java or Spark is faster.

P4Medium

Reducer with a minimum and maximum

Extend the key-change reducer to also print the smallest and largest amount per key.

Input
sorted lines
Expected output
drink 3 15 20
meal 2 45 80
Show solution and explanation 
lines = sorted(["drink\t15", "drink\t20", "meal\t45", "meal\t80", "drink\t15"])
current, vals = None, []
for line in lines + [None]:                     # None marks the end of input
    key, value = line.split("\t") if line else (None, None)
    if key != current and current is not None:
        print(current, len(vals), min(vals), max(vals))
        vals = []
    current = key
    if value is not None:
        vals.append(int(value))
drink 3 15 20 meal 2 45 80

How it works: A sentinel at the end replaces the separate “print the last key” step. Both patterns are fine; forgetting both is the bug.

P8Advanced

Secondary sort with two key fields

With stream.num.map.output.key.fields=2 and a partitioner on field 1 only, each reducer sees one student's orders sorted by time. Simulate it: partition on the student, sort on (student, time), and print each student's first order.

Input
5 lines, 2 reducers
Expected output
reducer 0: S2 first order 2026-09-02 09:00 poha
reducer 1: S1 first order 2026-09-02 08:10 chai
Show solution and explanation 
lines = ["S2\t2026-09-03 08:05\tchai", "S1\t2026-09-02 13:05\tthali", "S1\t2026-09-02 08:10\tchai",
         "S2\t2026-09-02 09:00\tpoha", "S1\t2026-09-03 08:40\tpoha"]
parts = {0: [], 1: []}
for l in lines:
    parts[int(l.split("\t")[0][1:]) % 2].append(l)          # partition on field 1 only
for p in parts:
    current = None
    for l in sorted(parts[p]):                              # sort on fields 1 and 2
        s, t, item = l.split("\t")
        if s != current:
            print(f"reducer {p}: {s} first order {t} {item}")
            current = s
reducer 0: S2 first order 2026-09-02 09:00 poha reducer 1: S1 first order 2026-09-02 08:10 chai

How it works: Each student lands in one reducer, already in time order, so the first line per student is the first order: Lesson 9.7's secondary sort without Java comparators.

Real-world scenario questions (asked in company interviews)

Streaming comes up when interviewers check whether you know MapReduce beyond Java, and in debugging questions.

Concepts · basicsFresher

“Can you write MapReduce in Python?”

A common follow-up after the word count question.

The interviewer is checking: knowing Streaming and how its reducer differs.

Show a strong answer
  • Yes, with Hadoop Streaming: the mapper and reducer are scripts reading stdin and printing key⇥value lines.
  • The reducer gets lines sorted by key, not a list per key, so it tracks the current key and emits on change (and at the end).
  • Run with mapred streaming -files … -mapper "python3 m.py" -reducer "python3 r.py"; Python must be on every node. Today PySpark is usually preferred.
Debugging · logsExperienced

“subprocess failed with code 1” and nothing else

A Streaming job that worked yesterday fails on every map attempt.

The interviewer is checking: where to look and likely causes.

Show a strong answer
  • Read the failed attempt's stderr: yarn logs -applicationId … -log_files stderr, or the JobHistory UI. That shows the Python traceback.
  • Typical causes: a malformed input line (unpacking error), a missing module or different Python on some nodes, a file not shipped with -files.
  • Reproduce locally with the failing split's data through the same pipe; make the script skip and count bad lines instead of crashing.
Design · trade-offsExperienced

Streaming, Java or PySpark for a new job?

A team of Python developers must aggregate 5 TB of logs nightly on an existing Hadoop cluster.

The interviewer is checking: balanced reasoning, not a reflex.

Show a strong answer
  • Streaming: fastest to start with existing scripts; text pipes add CPU; limited control (no custom comparators without Java).
  • Java MapReduce: best per-record efficiency and control, but a skills gap for this team.
  • PySpark on YARN: Python skills, in-memory stages, SQL/DataFrames; usually the right default for new work if Spark is available.
Correctness · reducerFresher

“The last category is missing from the output”

A Streaming job prints totals for drink, meal and breakfast, but never snack.

The interviewer is checking: the key-change reducer pattern.

Show a strong answer
  • The reducer prints a key only when the next key arrives; the final key has no successor.
  • Fix: after the loop, print the current key's result if current is not None (or use a sentinel).
  • Test with a local pipe whose last sorted key is known, and with empty input.
