Custom Writable types

Every key and value in MapReduce is turned into bytes, sorted, copied and turned back into objects. Writable is how you control those bytes. This lesson builds a composite key and a value type, measures three encodings of the same record on a real cluster, and shows the one mistake that compiles fine and fails on every task.

1 The story

The “efficient” version that was bigger

Kabir wants, for every student and every day, three numbers: how many orders, how much money, and the biggest single order. His first version glues everything into strings: the key is "S0001\t2026-09-01", the value "1,20,20". Riya says strings are wasteful and writes proper Java types instead: a key class with two fields and a value class with an int, a long and an int. They run both on 5 lakh orders. Riya's version moves 40% more bytes through the shuffle.

Riya

Sir, I used real types instead of strings. How can mine be bigger?

Arjun Sir

Look at what your write() does. writeUTF("2026-09-10") writes a 2-byte length and 10 characters: 12 bytes for a date. Then writeInt is always 4 bytes and writeLong always 8, even when the number is 1 or 45. Kabir's text "1,45,45" is only 7 characters.

Kabir

So Writable is just “you decide the bytes”. Decide badly and you pay in the shuffle.

Arjun Sir

Exactly. Today we write a composite key and a value type, see what Hadoop needs from them (and what happens when you forget the empty constructor), then shrink the same record to 8 bytes with variable-length numbers: 4.3 times smaller than the first try.

2 Definition

Writable and WritableComparable

Formal definition (write this in exams)

Writable (org.apache.hadoop.io.Writable) is Hadoop's serialization interface. A type implements write(DataOutput out), which writes its fields as bytes, and readFields(DataInput in), which reads them back in the same order into an existing object. MapReduce uses Writables for all keys and values that are transferred between tasks or stored in SequenceFiles. Keys must implement WritableComparable, which adds compareTo(): it defines the order in which keys are sorted during the shuffle. The default partitioner uses the key's hashCode() to choose a reducer, so equal keys must have equal hash codes. Because the framework creates instances by reflection and reuses them for many records, a Writable must have a public no-argument constructor and readFields() must overwrite every field. A RawComparator can compare keys directly in their serialized form, avoiding deserialization during sorting.

In simple words

A Writable is a class that knows how to turn itself into bytes and back. You choose which bytes. A key also needs to know how to compare itself, because the shuffle sorts by it.

Writables at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Packing a parcel

  • Sending a parcel by courier: you decide how to pack it. Every map output record is packed (write), sent through the shuffle, and unpacked (readFields) on the other side.
  • The receiver unpacks in the same order you packed: first the student, then the day. Change the order on one side only and you get nonsense.
  • A big box for a small thing still costs postage. A 4-byte int for the number 1 is a big box.

Intermediate What Hadoop needs from your class

  • Value types implement Writable: write() and readFields().
  • Key types implement WritableComparable: also compareTo() (sort order), and override hashCode() and equals() (partitioning).
  • A public no-argument constructor. Without it the map task cannot even start its output collector: our job failed on every attempt.
  • toString() decides how the type looks in TextOutputFormat output: our key prints S0001<TAB>2026-09-01.
  • Objects are reused: readFields() must set every field, and never store the object itself (Lesson 8.5).

Advanced Making records small and sorting fast

  • Shuffle cost is per byte: map output is buffered, spilled, compressed, copied and merged. Smaller records mean fewer spills (Lesson 8.4).
  • Encode the information, not the text: an ID like S1413 is the number 1413; a date in one month is a day-of-year number; small counts fit in a VInt.
  • Fixed sizes (writeInt) are simpler and slightly faster to decode; VInts are smaller for small numbers. Our compact job used a little more CPU (8,600 ms vs 8,360) for 4.3× fewer bytes.
  • Sorting calls compareTo() millions of times. The default WritableComparator deserializes both keys first; a RawComparator that compares the bytes directly (as Text and IntWritable do) is faster. Register it with WritableComparator.define() or job.setSortComparatorClass().

Exam tip: For “Why does Hadoop use Writable instead of Java Serializable?”, give three points: compact (no class names or metadata per object, only the fields), fast (objects are reused, no new object per record), and comparable in serialized form (RawComparator for sorting). Mention that keys must be WritableComparable.

4 Step by step

A composite key, a value type, and three sizes

Run on the Module 8 lab cluster with writable_lab.sh and student_orders.csv (5 lakh orders, 2,000 students, September 2026). Files are in “Run it on your PC”.

  1. The key: (student, day)

    public static class StudentDayKey implements WritableComparable<StudentDayKey> {
  private String student = "", day = "";
  public StudentDayKey() { }                       // Hadoop needs this
  public void write(DataOutput out) throws IOException { out.writeUTF(student); out.writeUTF(day); }
  public void readFields(DataInput in) throws IOException { student = in.readUTF(); day = in.readUTF(); }
  public int compareTo(StudentDayKey o) {
    int c = student.compareTo(o.student);
    return c != 0 ? c : day.compareTo(o.day);       // sort by student, then day
  }
  public int hashCode() { return student.hashCode() * 31 + day.hashCode(); }
  public String toString() { return student + "\t" + day; }
}
    compareTo makes the output come out sorted by student and then by day. hashCode decides the reducer. Both must agree with equals: equal keys, equal hash.

  2. The value: orders, total, max

    public static class SpendWritable implements Writable {
  private int orders; private long total; private int max;
  public SpendWritable() { }
  public void write(DataOutput out) throws IOException { out.writeInt(orders); out.writeLong(total); out.writeInt(max); }
  public void readFields(DataInput in) throws IOException { orders = in.readInt(); total = in.readLong(); max = in.readInt(); }
}
    The reducer adds orders and totals and keeps the maximum, which is also safe as a combiner (Lesson 9.1). Combine output records: 151,475 instead of 500,000.

    It compiles fine; it fails only on the cluster. The map output collector creates key objects by reflection (ReflectionUtils.newInstance), which needs new StudentDayKey().

write() and readFields() must handle the same fields in the same order and with the same methods. If write uses writeVInt and readFields uses readInt, nothing fails at compile time; the reducer silently reads wrong numbers or crashes with an EOFException.

5 See it happen

One record, packed and unpacked

Six steps: one record from map() to reduce(), first in the naive Writable, then in the compact one.

write() and readFields() 6 steps
What you see
  1. The mapper fills its reusable key and value and calls ctx.write.
  2. The framework calls key.write(): two writeUTF calls, 19 bytes.
  3. Then value.write(): 16 bytes of fixed-size numbers. 35 in total.
  4. On the reduce side, readFields() refills the same objects for each record.
  5. The compact version writes the same information in 8 bytes.
  6. Over 5 lakh records: 17.5 MB, 12.5 MB, 4.1 MB of map output.
Behind the screen
  1. Before writing, the key and value are just Java objects in the map task.
  2. writeUTF writes a 2-byte length and then each character: 19 bytes for the key.
  3. Fixed-size numbers are mostly zero bytes: 16 bytes for 1, 45 and 45.
  4. The reducer reads the bytes back into reused objects, in exactly the same order.
  5. Variable-length encoding stores 1413, 253, 1, 45, 45 in 8 bytes.
  6. Per record: 35, 25 or about 8 bytes. Multiply by every record of the job.
6 Real-world use

Custom types at work

1. Composite keys for daily aggregates

Telecom and payments jobs aggregate per (customer, day) or (merchant, hour). A composite WritableComparable keeps the key typed and sorts output by customer and then by time.

Transactions→key = (customer, day)→Daily totals

2. Statistics values for combiners

A value type holding sum, count, min and max lets one job compute several statistics with a correct combiner, instead of one job per statistic.

(1, amount, amount)→combine: add, max→avg, max per key

3. Intermediate data between chained jobs

When one job feeds another, output is often written as a SequenceFile of the same Writables, so the next job reads binary records without parsing text.

Job 1→SequenceFile of Writables→Job 2

4. Inside the ecosystem

Hive, HBase and Mahout define their own Writables (HBase's ImmutableBytesWritable, Hive's row Writables). Knowing the interface helps when reading their code or their errors.

Your job→Writable interface→Hive, HBase types

Simplified; organisations differ in tools and policies.

7 Run the code

Count the bytes of one record, three ways

Python's struct module can write the same bytes as Java's DataOutput. This code serializes one map output record the way each of our three jobs did, and also implements Hadoop's VInt encoding (WritableUtils.writeVLong).

import struct

def write_utf(s):                      # DataOutput.writeUTF: 2-byte length + UTF-8 bytes
    b = s.encode()
    return struct.pack(">H", len(b)) + b

def write_vint(i):                     # WritableUtils.writeVInt / writeVLong (for i >= 0)
    if -112 <= i <= 127:
        return bytes([i & 0xFF])
    data = i.to_bytes((i.bit_length() + 7) // 8, "big")
    return bytes([(-112 - len(data)) & 0xFF]) + data

def text(s):                           # Text: VInt length + UTF-8 bytes
    b = s.encode()
    return write_vint(len(b)) + b

student, day, amount = "S1413", "2026-09-10", 45
naive = write_utf(student) + write_utf(day) + struct.pack(">iqi", 1, amount, amount)
as_text = text(student + "\t" + day) + text(f"1,{amount},{amount}")
compact = write_vint(1413) + write_vint(253) + write_vint(1) + write_vint(amount) + write_vint(amount)

for name, b in [("Writable (UTF)", naive), ("Text", as_text), ("Writable (VInt)", compact)]:
    print(f"{name:16} {len(b):2} bytes  {b.hex(' ')}")

  • return struct.pack(">H", len(b)) + bwriteUTF always spends 2 bytes on the length: "2026-09-10" costs 12 bytes.
  • naive = write_utf(student) + write_utf(day) + struct.pack(">iqi", 1, amount, amount)">iqi" = int, long, int, big-endian: 4 + 8 + 4 = 16 bytes, mostly zeros.
  • return bytes([(-112 - len(data)) & 0xFF]) + dataOne marker byte saying how many bytes follow, then only those bytes: 1413 → 8e 05 85.

Composite key and value with writeUTF and fixed-size numbers

// StudentDay.java: a composite WritableComparable key (student, day) and a custom Writable value.
// Job: for every student and day, the number of orders, total spend and the biggest order.
import java.io.DataInput;
import java.io.DataOutput;
import java.io.IOException;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.io.Writable;
import org.apache.hadoop.io.WritableComparable;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;
import org.apache.hadoop.util.GenericOptionsParser;

public class StudentDay {

  /** Key: (student, day). Sorted by student, then day. */
  public static class StudentDayKey implements WritableComparable<StudentDayKey> {
    private String student = "";
    private String day = "";
    public StudentDayKey() { }                                   // Hadoop needs a no-argument constructor
    public void set(String s, String d) { student = s; day = d; }
    @Override public void write(DataOutput out) throws IOException { out.writeUTF(student); out.writeUTF(day); }
    @Override public void readFields(DataInput in) throws IOException { student = in.readUTF(); day = in.readUTF(); }
    @Override public int compareTo(StudentDayKey o) {
      int c = student.compareTo(o.student);
      return c != 0 ? c : day.compareTo(o.day);
    }
    @Override public int hashCode() { return student.hashCode() * 31 + day.hashCode(); }   // used by HashPartitioner
    @Override public boolean equals(Object o) {
      return o instanceof StudentDayKey && compareTo((StudentDayKey) o) == 0;
    }
    @Override public String toString() { return student + "\t" + day; }
  }

  /** Value: orders, total and max amount. Small and fixed size: 3 numbers. */
  public static class SpendWritable implements Writable {
    private int orders; private long total; private int max;
    public SpendWritable() { }
    public void set(int o, long t, int m) { orders = o; total = t; max = m; }
    @Override public void write(DataOutput out) throws IOException { out.writeInt(orders); out.writeLong(total); out.writeInt(max); }
    @Override public void readFields(DataInput in) throws IOException { orders = in.readInt(); total = in.readLong(); max = in.readInt(); }
    @Override public String toString() { return orders + "\t" + total + "\t" + max; }
  }

  public static class M extends Mapper<LongWritable, Text, StudentDayKey, SpendWritable> {
    private final StudentDayKey key = new StudentDayKey();
    private final SpendWritable val = new SpendWritable();
    @Override
    protected void map(LongWritable k, Text line, Context ctx) throws IOException, InterruptedException {
      String[] f = line.toString().split(",");        // order_id,student_id,time,item,amount
      int amount = Integer.parseInt(f[4]);
      key.set(f[1], f[2].substring(0, 10));          // "2026-09-20 08:36" -> "2026-09-20"
      val.set(1, amount, amount);
      ctx.write(key, val);
    }
  }

  public static class R extends Reducer<StudentDayKey, SpendWritable, StudentDayKey, SpendWritable> {
    private final SpendWritable out = new SpendWritable();
    @Override
    protected void reduce(StudentDayKey k, Iterable<SpendWritable> vals, Context ctx) throws IOException, InterruptedException {
      int orders = 0, max = 0; long total = 0;
      for (SpendWritable v : vals) { orders += v.orders; total += v.total; max = Math.max(max, v.max); }
      out.set(orders, total, max);
      ctx.write(k, out);
    }
  }

  public static void main(String[] args) throws Exception {
    Configuration conf = new Configuration();
    String[] rest = new GenericOptionsParser(conf, args).getRemainingArgs();
    Job job = Job.getInstance(conf, "student day");
    job.setJarByClass(StudentDay.class);
    job.setMapperClass(M.class);
    job.setCombinerClass(R.class);                    // orders, total and max are all safe to combine
    job.setReducerClass(R.class);
    job.setOutputKeyClass(StudentDayKey.class);
    job.setOutputValueClass(SpendWritable.class);
    FileInputFormat.addInputPath(job, new Path(rest[0]));
    FileOutputFormat.setOutputPath(job, new Path(rest[1]));
    System.exit(job.waitForCompletion(true) ? 0 : 1);
  }
}

// StudentDayText.java: the same job as StudentDay, but key and value travel as Text strings.
import java.io.IOException;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.LongWritable;

import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;
import org.apache.hadoop.util.GenericOptionsParser;

public class StudentDayText {
  public static class M extends Mapper<LongWritable, Text, Text, Text> {
    private final Text key = new Text(), val = new Text();
    @Override
    protected void map(LongWritable k, Text line, Context ctx) throws IOException, InterruptedException {
      String[] f = line.toString().split(",");
      key.set(f[1] + "\t" + f[2].substring(0, 10));
      val.set("1," + f[4] + "," + f[4]);
      ctx.write(key, val);
    }
  }

    job.setJarByClass(StudentDayText.class);

    job.setCombinerClass(R.class);
    job.setReducerClass(R.class);
    job.setOutputKeyClass(Text.class);
    job.setOutputValueClass(Text.class);
    FileInputFormat.addInputPath(job, new Path(rest[0]));
    FileOutputFormat.setOutputPath(job, new Path(rest[1]));
    System.exit(job.waitForCompletion(true) ? 0 : 1);

}

Compact encoding with VInt and VLong

// StudentDayCompact.java: the same job as StudentDay, with compact variable-length encodings:
// student "S0001" stored as the number 1, the day as a day-of-year number, every number as a VInt/VLong.
import java.io.DataInput;
import java.io.DataOutput;
import java.io.IOException;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.io.Writable;
import org.apache.hadoop.io.WritableComparable;
import org.apache.hadoop.io.WritableUtils;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;
import org.apache.hadoop.util.GenericOptionsParser;

public class StudentDayCompact {

  /** Key: (student, day). Sorted by student, then day. */
  public static class StudentDayKey implements WritableComparable<StudentDayKey> {
    private int student;                                         // "S0001" -> 1
    private int day;                                             // day of the year, 2026-09-01 -> 244
    public StudentDayKey() { }
    public void set(String s, String d) { student = Integer.parseInt(s.substring(1)); day = java.time.LocalDate.parse(d).getDayOfYear(); }
    @Override public void write(DataOutput out) throws IOException { WritableUtils.writeVInt(out, student); WritableUtils.writeVInt(out, day); }
    @Override public void readFields(DataInput in) throws IOException { student = WritableUtils.readVInt(in); day = WritableUtils.readVInt(in); }
    @Override public int compareTo(StudentDayKey o) {
      int c = Integer.compare(student, o.student);
      return c != 0 ? c : Integer.compare(day, o.day);
    }
    @Override public int hashCode() { return student * 31 + day; }
    @Override public boolean equals(Object o) {
      return o instanceof StudentDayKey && compareTo((StudentDayKey) o) == 0;
    }
    @Override public String toString() { return String.format("S%04d\t%s", student, java.time.LocalDate.ofYearDay(2026, day)); }
  }

  /** Value: orders, total and max amount, each written in as few bytes as the number needs. */
  public static class SpendWritable implements Writable {
    private int orders; private long total; private int max;
    public SpendWritable() { }
    public void set(int o, long t, int m) { orders = o; total = t; max = m; }
    @Override public void write(DataOutput out) throws IOException { WritableUtils.writeVInt(out, orders); WritableUtils.writeVLong(out, total); WritableUtils.writeVInt(out, max); }
    @Override public void readFields(DataInput in) throws IOException { orders = WritableUtils.readVInt(in); total = WritableUtils.readVLong(in); max = WritableUtils.readVInt(in); }
    @Override public String toString() { return orders + "\t" + total + "\t" + max; }
  }

  public static class M extends Mapper<LongWritable, Text, StudentDayKey, SpendWritable> {
    private final StudentDayKey key = new StudentDayKey();
    private final SpendWritable val = new SpendWritable();
    @Override
    protected void map(LongWritable k, Text line, Context ctx) throws IOException, InterruptedException {
      String[] f = line.toString().split(",");        // order_id,student_id,time,item,amount
      int amount = Integer.parseInt(f[4]);
      key.set(f[1], f[2].substring(0, 10));          // "2026-09-20 08:36" -> "2026-09-20"
      val.set(1, amount, amount);
      ctx.write(key, val);
    }
  }

  public static class R extends Reducer<StudentDayKey, SpendWritable, StudentDayKey, SpendWritable> {
    private final SpendWritable out = new SpendWritable();
    @Override
    protected void reduce(StudentDayKey k, Iterable<SpendWritable> vals, Context ctx) throws IOException, InterruptedException {
      int orders = 0, max = 0; long total = 0;
      for (SpendWritable v : vals) { orders += v.orders; total += v.total; max = Math.max(max, v.max); }
      out.set(orders, total, max);
      ctx.write(k, out);
    }
  }

  public static void main(String[] args) throws Exception {
    Configuration conf = new Configuration();
    String[] rest = new GenericOptionsParser(conf, args).getRemainingArgs();
    Job job = Job.getInstance(conf, "student day compact");
    job.setJarByClass(StudentDayCompact.class);
    job.setMapperClass(M.class);
    job.setCombinerClass(R.class);                    // orders, total and max are all safe to combine
    job.setReducerClass(R.class);
    job.setOutputKeyClass(StudentDayKey.class);
    job.setOutputValueClass(SpendWritable.class);
    FileInputFormat.addInputPath(job, new Path(rest[0]));
    FileOutputFormat.setOutputPath(job, new Path(rest[1]));
    System.exit(job.waitForCompletion(true) ? 0 : 1);
  }
}
Map output records=500000 Map output bytes=4068724 Map output materialized bytes=1601326 Combine output records=151475 Reduce output records=59946

About 8 bytes per record. toString() prints the student and date back in their usual form.

9 Quiz and revision

Check yourself

Quick revision

Lesson 9.3 in one screen

  • Writable: write(DataOutput) + readFields(DataInput), same fields, same order.
  • Keys: WritableComparable (compareTo = sort order) and a consistent hashCode/equals (partitioning).
  • Public no-arg constructor required (reflection); readFields must overwrite every field (objects are reused).
  • Sizes: writeUTF 2 + bytes; int 4; long 8; VInt 1–5, VLong 1–9; Text = VInt length + bytes; NullWritable 0.
  • Lab: 35 B (writeUTF + fixed numbers) vs 25 B (Text) vs ≈8 B (VInt) per record; 17.5 / 12.5 / 4.1 MB for 5 lakh records; same 59,946 rows.
  • toString() controls how the type appears in TextOutputFormat output.
  • Faster sorting: a RawComparator compares serialized bytes. Avro/Parquet for data files shared with other tools.

Interview and viva questions

What is a Writable in Hadoop?

Writable is Hadoop's serialization interface. A class implements write(DataOutput) to write its fields as bytes and readFields(DataInput) to read them back. Hadoop uses Writables for all MapReduce keys and values and in SequenceFiles. Common built-in Writables are Text, IntWritable, LongWritable, DoubleWritable and NullWritable.

What is the difference between Writable and WritableComparable?

Writable only serializes and deserializes. WritableComparable also implements Comparable, so objects can be sorted. MapReduce sorts map output by key, so every key type must be WritableComparable; value types only need Writable.

Why does Hadoop not use Java serialization?

Java serialization writes class information and object metadata with every object and creates a new object when reading, which is slow and large for billions of small records. Writables write only the field values, can be reused for every record, and many can be compared directly in serialized form with a RawComparator.

How do you create a custom key in MapReduce?

Write a class that implements WritableComparable<YourKey>, with a public no-argument constructor, write() and readFields() handling the same fields in the same order, compareTo() defining the sort order, and hashCode() and equals() based on the same fields so the partitioner sends equal keys to the same reducer. Override toString() for readable text output.

Why does my custom Writable job fail with NoSuchMethodException <init>()?

Hadoop creates key and value objects by reflection with the no-argument constructor. If your class only has a constructor with parameters, Java does not generate the default one, and tasks fail at runtime with NoSuchMethodException: YourClass.<init>(). Add a public no-argument constructor (and make nested classes static).

def vint(i):
    if i <= 127:

Real-world scenario questions (asked in company interviews)

Writable questions test whether you understand what really travels between map and reduce.

Concepts · basicsFresher

“Why does Hadoop have its own IntWritable instead of using Integer?”

A common opener in Hadoop interviews.

The interviewer is checking: serialization basics.

Show a strong answer
  • Keys and values are sent between JVMs and written to disk, so they must be serialized.
  • Writable writes only the field bytes (4 for an int), with no class metadata, and objects are reused for every record.
  • Keys are WritableComparable so they can be sorted, often byte by byte with a RawComparator.
Debugging · runtimeFresher

The job runs in your IDE tests but fails on the cluster with NoSuchMethodException

The message ends with MyKey.<init>().

The interviewer is checking: reflection and constructors.

Show a strong answer
  • Hadoop instantiates keys and values by reflection with a no-argument constructor.
  • Adding a constructor with parameters removed Java's default one; add a public no-arg constructor.
  • For nested classes, make them static, or reflection cannot create them either.
Performance · shuffleExperienced

A job with a custom Writable shuffles more data than the old Text version

The team expected the opposite.

The interviewer is checking: encoding choices.

Show a strong answer
  • Compare Map output bytes / Map output records for both versions to get bytes per record.
  • Look at write(): writeUTF adds 2 bytes per string, writeInt/writeLong use 4/8 bytes even for tiny numbers.
  • Encode IDs and dates as numbers, use VInt/VLong, drop fields the reducer doesn't need; in our lab 35 → 8 bytes per record.
Correctness · keysExperienced

Output has duplicate keys across part files

The same (customer, day) appears in part-r-00001 and part-r-00003 with different totals.

The interviewer is checking: hashCode and equals contracts.

Show a strong answer
  • The key's hashCode() is not based on its fields (or is inconsistent with equals/compareTo), so equal keys go to different reducers.
  • Implement hashCode() from the same fields compareTo() uses; avoid Object.hashCode() and anything JVM-specific.
  • Rerun the job: each key then appears exactly once.
