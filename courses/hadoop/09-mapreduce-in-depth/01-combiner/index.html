Combiner

A combiner runs a mini-reduce on each map task's output before the shuffle, so the network carries totals instead of lakhs of ones. It can make a job much faster, but Hadoop may run it zero, one or many times, and some logic breaks when that happens. This lesson measures both sides on a real cluster.

1 The story

Two crore ones on the network

Kabir runs word count on the 102 MB feedback file and opens the counters. “Reduce shuffle bytes = 225,867,818.” The map tasks emitted 2 crore 6 lakh pairs, and nearly all of them were (“was”, 1), (“the”, 1), (“chai”, 1): the same few words, each with a 1, copied one by one to a single reducer. Riya adds one line to the driver and runs it again. Same answer, 29 seconds instead of 53, and the shuffle shrinks to 1,083 bytes.

Riya

One line, and the shuffle went from 226 MB to one kilobyte? What did it do?

Arjun Sir

job.setCombinerClass(IntSumReducer.class). It runs your reducer's logic on each map task's output before the shuffle. Instead of sending “chai, 1” a lakh times, every map sends “chai, its total”. The reducer then adds three totals instead of lakhs of ones.

Kabir

Then let's use it everywhere. My average-spend job could use the same trick.

Arjun Sir

Try it. Your averages will come out wrong for all 2,000 students, and Hadoop won't say a word. Today we see why a combiner may run zero, one or several times, which kinds of logic survive that, and how to fix the average with a (sum, count) pair.

2 Definition

Combiner

Formal definition (write this in exams)

A combiner is an optional, user-supplied function in a MapReduce job that performs local aggregation of the intermediate key-value pairs produced by a map task, before they are transferred to the reducers. It is set with job.setCombinerClass() and is implemented as a Reducer whose input and output key and value types are both equal to the map output types. The framework applies it to sorted map output when spilling the sort buffer and may apply it again when merging spill files (when there are at least mapreduce.map.combine.minspills = 3 spills), and on the reduce side during merges; it may therefore be executed zero, one or many times on any subset of a key's values. Consequently the combining operation must be commutative and associative and must not change the final result, regardless of how often it runs. Its purpose is to reduce the volume of data written to local disk and transferred in the shuffle.

In simple words

A combiner is a mini-reducer that each map task runs on its own output, so it sends “chai: 1,33,000” instead of 1,33,000 lines of “chai: 1”. Hadoop decides when, and how many times, to run it, so it is only safe for logic like adding, counting, max and min.

The combiner at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Tally sheets at counting tables

  • Without a combiner, every counting table sends a slip for each single vote to the central desk: lakhs of slips saying “Party X: 1”.
  • With a combiner, each table first writes one tally sheet: “Party X: 4,312”. The central desk adds a handful of sheets.
  • Adding is safe to do in pieces: the total is the same however the votes were grouped. That is the whole rule.

Intermediate Where it runs and what the counters say

  • The combiner runs inside the map task, on sorted map output, each time the sort buffer spills (Lesson 8.4).
  • With 3 or more spills it runs again while those spills are merged. That is why Combine input records (20,665,132) was larger than Map output records (20,664,760): 372 records produced by earlier combines were combined a second time.
  • The arithmetic: 12 spills × 31 words = 372 records, merged and combined into 3 maps × 31 words = 93 records. Combine output 372 + 93 = 465. The reducer received exactly 93.
  • Its input and output types must both equal the map output types, because its output is fed to the reducer as if the map had written it, and may even be fed to the combiner again.

Advanced What is safe to combine

  • Safe: sum, count, max, min, logical AND/OR, set union. Applying them to partial results gives the same final answer.
  • Not safe as-is: average, median, percentiles, “count distinct” by counting, “top-N” on partial counts. An average of partial averages ignores how many values each one stood for.
  • The fix: make the map emit a partial aggregate that can be merged again: (sum, count) for average, (min, max), a set of IDs for distinct. Divide or finish only in the reducer.
  • Hadoop gives no guarantee that the combiner runs at all, so the reducer must produce the right answer whether or not it ran. Never put side effects (writing files, external calls) in a combiner.

Exam tip: For “What is a combiner? When can't you use one?”, write: local mini-reducer on map output, set with setCombinerClass, reduces shuffle data; may run 0, 1 or many times, so the function must be commutative and associative with input type = output type = map output type. Example that works: word count (sum). Example that fails: average (use sum and count instead).

Three ways to cut map output

Combiner

One line in the driver. Hadoop runs it on spills and merges. Saves shuffle bytes and disk, but every pair is still created and serialized first.

setCombinerClass

In-mapper combining

Keep a HashMap of totals in the mapper and write them in cleanup() (Lesson 8.3). Fewer objects and no repeated sorting; you must watch memory if there are many keys.

fastest

Filter early

Don't emit what the reducer will throw away: skip bad rows and unused columns in the mapper.

always

When none helps

If almost every key is unique (order IDs, timestamps), there is nothing to combine; the combiner only costs CPU.

check the counters

Read the ratio Combine output records ÷ Combine input records. Word count: 465 ÷ 20,665,132, a huge win. If the ratio is close to 1, the combiner is wasted work: remove it.

4 Step by step

A combiner that helps, and one that lies

Module 9 runs on the Module 8 lab cluster (Lesson 8.1) with a new, bigger dataset made by make_student_orders.py: 5 lakh orders by 2,000 students over September 2026, with the time of each order and 8 items including coffee and thali. Twenty “regulars” (S0001 to S0020) order far more than everyone else, which will matter for partitioning and skew.

  1. Turn the combiner on

    job.setMapperClass(TokenizerMapper.class);
if (conf.getBoolean("wc.combiner", true)) job.setCombinerClass(IntSumReducer.class);
job.setReducerClass(IntSumReducer.class);
    The reducer itself works as the combiner because its input (Text, IntWritable) and output (Text, IntWritable) are both the map output types, and summing is safe to do in pieces.

  2. Run word count without and with it

    hadoop jar mr9.jar WordCountCombiner -D wc.combiner=false /user/hadoop/data/feedback_x20.txt /out/wc_nocomb
hadoop jar mr9.jar WordCountCombiner -D wc.combiner=true  /user/hadoop/data/feedback_x20.txt /out/wc_comb
    == wc_nocomb 52918 ms Map output records=20664760 Combine input records=0 Reduce shuffle bytes=225867818 Reduce input records=20664760 Spilled Records=61994280 == wc_comb 29249 ms Map output records=20664760 Combine input records=20665132 Combine output records=465 Reduce shuffle bytes=1083 Reduce input records=93 Spilled Records=558
    The maps did exactly the same work (20,664,760 pairs each time). What changed is everything after: 93 records instead of 2 crore reached the reducer, and the job was 45% faster.

  3. Check the answer didn't change

    diff <(hdfs dfs -cat /out/wc_nocomb/part-r-00000) <(hdfs dfs -cat /out/wc_comb/part-r-00000) && echo "identical output"
    identical output
    Always compare a run with and without the combiner once. A correct combiner never changes the output.

  4. Notice the combiner ran twice

    Combine input records  20,665,132 = 20,664,760 map pairs + 372
spill combines   : 20,664,760 pairs → 372 records (12 spills × 31 words)
merge combine    :        372       →  93 records (3 maps × 31 words)
Combine output   : 372 + 93 = 465
    Each 102 MB map filled its sort buffer several times. The combiner ran on every spill, and because each map had at least 3 spills, it ran again while merging them. Your combiner must give the same result however many times it runs.

  5. Now the dangerous one: average spend per student

    hadoop jar mr9.jar AvgSpend -D avg.combiner=none  /user/hadoop/data/student_orders.csv /out/avg_none
hadoop jar mr9.jar AvgSpend -D avg.combiner=wrong /user/hadoop/data/student_orders.csv /out/avg_wrong
    S0001 none: 25.90 (3899 orders) | wrong: 26.05 (3 orders) S0007 none: 25.64 (3934 orders) | wrong: 25.50 (3 orders) S1413 none: 25.13 (184 orders) | wrong: 25.30 (3 orders) -- students whose answer differs from the no-combiner run wrong: 2000 of 2000
    The wrong combiner averaged each map's values and passed the average on as if it were a single order. The reducer then averaged three averages, one per map. No error, no warning: every one of the 2,000 answers is slightly wrong.

  6. Fix it with a (sum, count) pair

    // map emits "amount,1"; the combiner adds sums and counts, never divides
for (Text v : vals) { String[] p = v.toString().split(",");
  sum += Double.parseDouble(p[0]); n += Long.parseLong(p[1]); }
ctx.write(s, new Text(sum + "," + n));
    == avg_right 23559 ms Combine input records=500000 Combine output records=6000 Reduce shuffle bytes=107140 S1413 none: 25.13 (184 orders) | right: 25.13 (184 orders) right: 0 of 2000
    6,000 records (2,000 students × 3 maps) instead of 5 lakh, 61 times fewer shuffle bytes, and every answer correct. The division happens once, in the reducer.

Hadoop never checks whether your combiner is mathematically safe. A wrong combiner produces plausible numbers, not errors. Test with and without it on a sample, and compare the outputs.

5 See it happen

Inside one map task with a combiner

Six steps: spills get combined, merged spills get combined again, then the same idea applied to an average, wrongly and rightly.

Combine, merge, combine again 6 steps
What you see
  1. Without a combiner: 2 crore pairs and 226 MB cross to the reducer.
  2. With a combiner the map emits exactly the same 2 crore pairs.
  3. But the combiner shrinks them: 20,665,132 in, 465 out.
  4. The reducer gets 93 records. Same answer, 45% faster.
  5. The averaging reducer as a combiner: every student's average is a little wrong.
  6. A (sum, count) combiner: small shuffle and every answer right.
Behind the screen
  1. Without a combiner every (word, 1) pair is written to disk and sent to the reducer.
  2. With a combiner, each time the sort buffer spills, its sorted contents are combined before being written.
  3. With 3 or more spills, merging them runs the combiner a second time.
  4. Only one line per word per map leaves the map task.
  5. Wrong: partial averages are passed on as if each were one order, so the counts are lost. (Per-map numbers illustrative.)
  6. Right: partial (sum, count) pairs can be merged any number of times; the reducer divides once. (Illustrative numbers.)
6 Real-world use

Combiners at work

1. Counting events in logs

Page views, errors or clicks per URL per hour: billions of (key, 1) pairs collapse to a few lakh partial totals per map before the shuffle.

(url, 1) × billions→combiner: sum→(url, partial total)

2. Metrics with partial aggregates

Average transaction value per merchant, average latency per API: the map emits (sum, count, min, max) so a combiner can merge them safely; the reducer finishes the averages.

Transactions→(sum, count) combiner→Averages per merchant

3. Inside SQL engines

Hive's hive.map.aggr and Spark's reduceByKey do the same thing automatically: a partial aggregation on the map side, then the final one after the shuffle. A GROUP BY with SUM or COUNT gets it for free.

GROUP BY item→partial aggregate→final aggregate

4. Approximate distinct counts

“Unique users per day” can't be added from partial counts. Teams combine HyperLogLog sketches instead: small structures that can be merged any number of times and give a close estimate.

(day, user)→merge sketches→≈ unique users

Simplified; organisations differ in tools and policies.

7 Run the code

Simulate a combiner running on spills

One map task's output is cut into spills, as the sort buffer would. The combiner runs on each spill, then once more on the merged spills. Compare the final answer with no combiner, a sum combiner and an averaging combiner.

pairs = [("chai", 15), ("chai", 15), ("dosa", 45), ("chai", 15), ("thali", 80),
         ("dosa", 45), ("chai", 15), ("thali", 80), ("chai", 20), ("dosa", 40)]
spills = [pairs[0:4], pairs[4:7], pairs[7:10]]        # the sort buffer filled 3 times

def combine(records, fn):                             # group by key, apply fn to each group
    groups = {}
    for k, v in records:
        groups.setdefault(k, []).append(v)
    return [(k, fn(vs)) for k, vs in sorted(groups.items())]

total = lambda vs: sum(vs)
avg = lambda vs: sum(vs) / len(vs)

for name, fn in [("sum", total), ("average", avg)]:
    after_spills = [r for s in spills for r in combine(s, fn)]   # combiner on every spill
    merged = combine(after_spills, fn)                           # and again on the merge
    print(f"{name:8} combiner ->", merged)
print("true sums      ->", combine(pairs, total))
print("true averages  ->", [(k, round(v, 2)) for k, v in combine(pairs, avg)])
sum combiner -> [('chai', 80), ('dosa', 130), ('thali', 160)] average combiner -> [('chai', 16.666666666666668), ('dosa', 43.333333333333336), ('thali', 80.0)] true sums -> [('chai', 80), ('dosa', 130), ('thali', 160)] true averages -> [('chai', 16.0), ('dosa', 43.33), ('thali', 80.0)]

Word count with an optional combiner

// WordCountCombiner.java: word count with an optional combiner.  -D wc.combiner=true|false
import java.io.IOException;
import java.util.StringTokenizer;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IntWritable;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;
import org.apache.hadoop.util.GenericOptionsParser;

public class WordCountCombiner {
  public static class TokenizerMapper extends Mapper<LongWritable, Text, Text, IntWritable> {
    private static final IntWritable ONE = new IntWritable(1);
    private final Text word = new Text();
    @Override
    public void map(LongWritable k, Text line, Context ctx) throws IOException, InterruptedException {
      StringTokenizer it = new StringTokenizer(line.toString().toLowerCase(), " \t.,!?;:\"'()");
      while (it.hasMoreTokens()) { word.set(it.nextToken()); ctx.write(word, ONE); }
    }
  }

  // Used as the reducer AND (optionally) as the combiner: summing is safe to do in pieces.
  public static class IntSumReducer extends Reducer<Text, IntWritable, Text, IntWritable> {
    private final IntWritable result = new IntWritable();
    @Override
    public void reduce(Text word, Iterable<IntWritable> counts, Context ctx) throws IOException, InterruptedException {
      int sum = 0;
      for (IntWritable c : counts) sum += c.get();
      result.set(sum);
      ctx.write(word, result);
    }
  }

  public static void main(String[] args) throws Exception {
    Configuration conf = new Configuration();
    String[] rest = new GenericOptionsParser(conf, args).getRemainingArgs();
    Job job = Job.getInstance(conf, "word count combiner=" + conf.getBoolean("wc.combiner", true));
    job.setJarByClass(WordCountCombiner.class);
    job.setMapperClass(TokenizerMapper.class);
    if (conf.getBoolean("wc.combiner", true)) job.setCombinerClass(IntSumReducer.class);
    job.setReducerClass(IntSumReducer.class);
    job.setOutputKeyClass(Text.class);
    job.setOutputValueClass(IntWritable.class);
    FileInputFormat.addInputPath(job, new Path(rest[0]));
    FileOutputFormat.setOutputPath(job, new Path(rest[1]));
    System.exit(job.waitForCompletion(true) ? 0 : 1);
  }
}

Average spend: no, wrong and right combiner

// AvgSpend.java: average amount per order for each student.
// -D avg.combiner=wrong   uses the averaging reducer as a combiner (gives WRONG answers)
// -D avg.combiner=right   map emits (sum,count) pairs and the combiner adds them (correct)
// -D avg.combiner=none    no combiner (correct, more data shuffled)
import java.io.IOException;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;
import org.apache.hadoop.util.GenericOptionsParser;

public class AvgSpend {
  // value travels as text "sum,count" so the same reducer can read map output and combiner output
  public static class M extends Mapper<LongWritable, Text, Text, Text> {
    private final Text student = new Text(), val = new Text();
    @Override
    protected void map(LongWritable k, Text line, Context ctx) throws IOException, InterruptedException {
      String[] f = line.toString().split(",");          // order_id,student_id,time,item,amount
      student.set(f[1]);
      val.set(f[4] + ",1");
      ctx.write(student, val);
    }
  }

  // WRONG as a combiner: it averages its input and claims the result is 1 order, so averages get averaged
  public static class AvgReducer extends Reducer<Text, Text, Text, Text> {
    @Override
    protected void reduce(Text s, Iterable<Text> vals, Context ctx) throws IOException, InterruptedException {
      double sum = 0; long n = 0;
      for (Text v : vals) { String[] p = v.toString().split(","); sum += Double.parseDouble(p[0]); n += 1; }   // ignores the counts
      ctx.write(s, new Text((sum / n) + ",1"));                  // a partial AVERAGE, pretending to be 1 order
    }
  }

  // RIGHT as a combiner: adds sums and counts, never divides
  public static class SumCountCombiner extends Reducer<Text, Text, Text, Text> {
    @Override
    protected void reduce(Text s, Iterable<Text> vals, Context ctx) throws IOException, InterruptedException {
      double sum = 0; long n = 0;
      for (Text v : vals) { String[] p = v.toString().split(","); sum += Double.parseDouble(p[0]); n += Long.parseLong(p[1]); }
      ctx.write(s, new Text(sum + "," + n));
    }
  }

  // Final reducer for the correct versions: divide once at the end
  public static class FinalAvg extends Reducer<Text, Text, Text, Text> {
    @Override
    protected void reduce(Text s, Iterable<Text> vals, Context ctx) throws IOException, InterruptedException {
      double sum = 0; long n = 0;
      for (Text v : vals) { String[] p = v.toString().split(","); sum += Double.parseDouble(p[0]); n += Long.parseLong(p[1]); }
      ctx.write(s, new Text(String.format("%.2f (%d orders)", sum / n, n)));
    }
  }

  public static void main(String[] args) throws Exception {
    Configuration conf = new Configuration();
    String[] rest = new GenericOptionsParser(conf, args).getRemainingArgs();
    String mode = conf.get("avg.combiner", "none");
    Job job = Job.getInstance(conf, "avg spend combiner=" + mode);
    job.setJarByClass(AvgSpend.class);
    job.setMapperClass(M.class);
    if (mode.equals("wrong")) job.setCombinerClass(AvgReducer.class);
    if (mode.equals("right")) job.setCombinerClass(SumCountCombiner.class);
    job.setReducerClass(FinalAvg.class);
    job.setOutputKeyClass(Text.class);
    job.setOutputValueClass(Text.class);
    FileInputFormat.addInputPath(job, new Path(rest[0]));
    FileOutputFormat.setOutputPath(job, new Path(rest[1]));
    System.exit(job.waitForCompletion(true) ? 0 : 1);
  }
}

9 Quiz and revision

Check yourself

Quick revision

Lesson 9.1 in one screen

  • Combiner = mini-reducer on one map task's output, before the shuffle; job.setCombinerClass(...).
  • Runs on each spill and again on merges (≥ 3 spills, mapreduce.map.combine.minspills); may run 0, 1 or many times.
  • Must be commutative and associative; input type = output type = map output type.
  • Lab word count: 225,867,818 → 1,083 shuffle bytes, 52.9 s → 29.2 s, identical output; Combine input 20,665,132 > Map output (ran twice).
  • Safe: sum, count (as sum of 1s), max, min. Unsafe as-is: average, median, distinct count.
  • Average: emit (sum, count), divide only in the reducer. Wrong combiner → 2,000 of 2,000 averages wrong, silently.
  • Alternative: in-mapper combining (HashMap + cleanup()). Useless when keys are nearly unique.

Interview and viva questions

What is a combiner in MapReduce?

A combiner is an optional local reducer that runs on the output of each map task before the shuffle. It aggregates values for the same key on the map side, so far less data is written to disk and sent over the network to the reducers. It is set with job.setCombinerClass() and often reuses the reducer class when the reduce function is commutative and associative.

Is the combiner guaranteed to run?

No. Hadoop may run the combiner zero, one or several times for a map task: on each spill of the sort buffer, again while merging spill files (when there are at least 3 spills), and sometimes during reduce-side merges. The job must produce correct results whether or not it runs.

Can every reducer be used as a combiner?

No. Only when the reduce function is commutative and associative and its input and output types are the same as the map output types. Sums, counts expressed as sums, max and min work. Averages, medians and distinct counts do not; for an average, emit (sum, count) pairs and divide only in the reducer.

What is the difference between a combiner and a reducer?

A reducer receives all values of a key from every map task and produces the final output, which is written to HDFS. A combiner sees only part of the values (one map task's, often one spill's), its output goes into the shuffle rather than HDFS, and it may run any number of times, so it can only do work that is safe to repeat on partial data.

What is in-mapper combining?

Aggregating inside the mapper itself, for example in a HashMap of key → running total, and writing the totals once in cleanup(). It avoids creating and sorting every intermediate pair, so it is usually faster than a combiner, but it uses mapper memory and you must flush the map if it grows too large.

P8Advanced

In-mapper combining

Instead of a combiner, aggregate inside the mapper with a dictionary and emit totals at the end (cleanup). Flush when the dictionary exceeds 3 keys, to bound memory. How many records are emitted?

Input
10 words, flush above 3 keys
Expected output
7 records emitted for 10 words: [('chai', 2), ('was', 2), ('hot', 1), ('cold', 1), ('chai', 2), ('was', 1), ('late', 1)]
Show solution and explanation 
words = "chai was hot chai was cold chai was late chai".split()
buf, emitted = {}, []
for w in words:
    buf[w] = buf.get(w, 0) + 1
    if len(buf) > 3:                     # memory guard: flush partial totals
        emitted += buf.items(); buf = {}
emitted += buf.items()                   # cleanup()
print(len(emitted), "records emitted for", len(words), "words:", emitted)
7 records emitted for 10 words: [('chai', 2), ('was', 2), ('hot', 1), ('cold', 1), ('chai', 2), ('was', 1), ('late', 1)]

How it works: 7 records for 10 words: one flush happened, so chai and was are emitted twice. Without the memory limit it would be 5 (one per word). The reducer still sums correctly because partial totals for the same word are simply added.

Real-world scenario questions (asked in company interviews)

Combiners are a favourite interview topic because one wrong answer reveals whether a candidate understands what “local aggregation” really means.

Concepts · basicsFresher

“What is a combiner and why is it used?”

Asked right after word count.

The interviewer is checking: where it runs and what it saves.

Show a strong answer
  • A local mini-reducer that runs on each map task's output, set with setCombinerClass.
  • It reduces the data written to local disk and sent in the shuffle, e.g. (chai, 1) × lakhs → (chai, total).
  • In our lab word count: 225 MB of shuffle became 1 KB and the job ran 45% faster.
Correctness · designFresher

“Can I use my average reducer as a combiner?”

The classic trick question.

The interviewer is checking: associativity and partial aggregates.

Show a strong answer
  • No: an average of partial averages is wrong unless every part has the same count, and Hadoop may run the combiner any number of times.
  • Emit (sum, count) from the map, let the combiner add both, and divide once in the reducer.
  • The combiner's input and output types must both match the map output types, which (sum, count) does.
Debugging · productionExperienced

Results changed slightly after a “performance fix”

A colleague added a combiner to a metrics job; dashboards now differ from last month by 0.5–2%. No job failed.

The interviewer is checking: silent correctness bugs.

Show a strong answer
  • Suspect a non-associative combiner (average, ratio, percentile, distinct count).
  • Rerun the same input with and without the combiner and diff the outputs; check Combine input/output counters.
  • Fix with partial aggregates (sum, count; min, max; sets or sketches) and add a regression test comparing both modes on a sample.
Performance · tuningExperienced

“We added a combiner but the job didn't get faster”

Counters show Combine input 50 crore, Combine output 49 crore.

The interviewer is checking: reading counters.

Show a strong answer
  • The ratio is about 0.98: keys are almost unique per map task, so there is nothing to combine; the combiner only adds CPU.
  • Remove it, or change the key design (coarser keys) if aggregation is the goal.
  • Look elsewhere: compress map output, filter earlier, or use in-mapper combining for hot keys.
