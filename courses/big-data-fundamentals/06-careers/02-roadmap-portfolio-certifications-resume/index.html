Data engineering roadmap, portfolio, certifications and resume

Long lists of tools and badges rarely get anyone hired. Projects with numbers do. In this lesson you build a roadmap from your own skills and hours, choose the certification that matches the jobs you want, design a portfolio project reviewers trust, and rewrite resume bullets from vague duties into results, with a program that scores them.

Kabir

2 Definition

Roadmap, portfolio, certifications and resume

Formal definition (write this in exams)

A career roadmap for data engineering is an ordered plan of skills, projects and credentials leading to employment and growth in roles that design, build and operate data pipelines and platforms. Core competencies include SQL, programming (usually Python), data modelling, distributed processing, orchestration, streaming, cloud data services and data quality. Employability is demonstrated through a portfolio of documented projects, a resume with measurable achievements, and optionally vendor certifications that validate platform knowledge.

In simple words

Learn the skills in a sensible order, prove them with projects people can see, write a resume that shows results with numbers, and add a certification only where it helps with the jobs you want.

Your data engineering career plan at three levels

Pick your level. New to this? Start at Beginner and climb.

Beginner Getting started (0–3 months)

  • SQL deeply: joins, GROUP BY, window functions, CTEs, query plans. It is in nearly every data engineering interview.
  • Python for data: files, JSON, CSV, functions, error handling, pandas basics, writing small scripts.
  • Linux, Git and the command line: navigating servers, shell scripts, branches, pull requests.
  • Data modelling: normalisation for transaction systems, star schemas (facts and dimensions) for analytics.
  • First small project on GitHub with a clear README.

Intermediate Becoming job-ready (3–8 months)

  • Distributed processing: Spark (PySpark DataFrames, partitions, joins, shuffles) and file formats (Parquet).
  • Orchestration: Airflow DAGs, scheduling, retries, backfills; dbt for SQL transformations and tests.
  • Streaming basics: Kafka topics, partitions, consumer groups; when to use streaming.
  • One cloud well: its object storage, managed Spark, warehouse and IAM. Optionally one associate-level certification.
  • Lakehouse: Delta Lake or Iceberg tables, medallion layers, data quality checks.
  • An end-to-end portfolio project; a resume with quantified bullets; active applications.

Advanced Growing after you are hired

  • Depth: Spark tuning, cost optimisation, data modelling at scale, streaming with exactly-once semantics.
  • Engineering practice: testing, CI/CD for data, infrastructure as code (Terraform), observability, code review.
  • Ownership: data contracts, governance, on-call, design documents and estimating cost and capacity.
  • Paths: senior/staff data engineer, analytics engineer, platform or streaming engineer, ML/data platform engineer, data architect, engineering manager.

Exam tip: Describe a learning path for a data engineer (foundations → processing → orchestration → streaming → cloud → lakehouse → projects), explain why projects and quantified results matter more than tool lists, and name one certification each for AWS, Azure, Google Cloud and Databricks.

4 Step by step

From job posts to interviews

  1. Study 20 job posts

    Collect 20 data engineer postings for roles you want (product companies, service companies, start-ups) and count the skills that repeat.

    In India, SQL, Python, Spark, a cloud, Airflow and data modelling appear in most posts. The posts tell you what to learn and which certification matters.

  2. Make a time-boxed plan

    hours_needed, hours_per_week = 367, 12
weeks = -(-hours_needed // hours_per_week)
print(weeks, "weeks, about", round(weeks / 4.3, 1), "months")
    31 weeks, about 7.2 months
    Honest hours per week turn a vague goal into a date. Skip what you already know well; spend most time on gaps.

  3. Build one end-to-end project

    Ingest real data (for example from data.gov.in or a public API), land it raw, clean it with Spark or dbt, run quality checks, orchestrate with Airflow, and serve a small dashboard.

    One complete, documented project beats five half-finished notebooks. Interviewers ask about decisions, so write them down in the README.

  4. Write quantified resume bullets

    bullet = "Reduced a nightly PySpark job from 3 h to 25 min"
print("has a number:", any(ch.isdigit() for ch in bullet))
print("starts with action:", bullet.split()[0] in ("Built", "Reduced", "Designed"))
    has a number: True starts with action: True
    Use action + tool + scale + result. Keep the resume to one page as a fresher, with projects above a skills list.

  5. Apply with referrals and polish your profiles

    Update LinkedIn and GitHub, ask former classmates and colleagues for referrals, apply on job portals and company career pages, and track every application in a sheet.

    Referrals and direct messages to hiring managers often get faster replies than portal applications alone.

  6. Prepare for interviews

    Practise SQL and Python problems, Spark and data-modelling questions, a system design for a pipeline, and STAR stories about your projects. The next lesson has a full question bank.

    Most data engineering rounds are SQL, coding, a project deep-dive, design and a behavioural round.

What the recruiter sees, and what she is checking 6 steps
What you see
  1. A recruiter opens Kabir’s resume, one of 180 for the role.
  2. Her eyes go first to the projects section.
  3. Then to the internship result with a number.
  4. A short skills line that matches the job.
  5. Education and one certification.
  6. About 30 seconds later, Kabir is shortlisted.
Behind the screen
  1. Applications are often searched or filtered by keywords from the job description, by an applicant tracking system or simply by a person using search. Matching words get the resume opened.
  2. The first question is whether there is real evidence. A named project with scale and a link is concrete.
  3. Numbers show impact and understanding. A runtime cut from 3 hours to 25 minutes signals real Spark skill.
  4. A short, relevant skills list is believable when each tool also appears in a project or bullet. Long lists of tools invite doubt.
  5. Degree and a relevant certification satisfy basic requirements; they rarely decide alone.
  6. He is shortlisted, and the interviewer’s first questions will come straight from his bullets. Only write what you can explain in depth.

Real-time scenario 3 · advanced

A portfolio repository a senior engineer would trust

Hiring managers often open a candidate’s main project for two minutes. Watch what turns a folder of notebooks into evidence of professional skill.

Portfolio quality 5 steps
Animated example
  1. The README states the problem (for example a UPI-style payments analytics pipeline), shows an architecture diagram, and gives exact run instructions and the outcome.
  2. A docker-compose file starts Kafka, Spark, Airflow and MinIO (an S3-compatible store) locally, so a reviewer can run everything with one command.
  3. Code is organised by layer (bronze, silver, gold), with configuration separate from code and no passwords or keys committed.
  4. Unit tests and data quality checks run automatically in CI on every push, showing engineering discipline most fresher projects lack.
  5. Results include a dashboard screenshot, data volumes, run times, rough cloud cost and an honest list of limitations and next steps. These become the best interview conversations.

Portfolio project ideas with Indian data

1. Payments analytics lakehouse

Simulate UPI-style transactions into Kafka, process them with Spark Structured Streaming into Delta tables, flag suspicious patterns and build daily settlement reports.

Kafka→Spark → Delta→Fraud + reports

2. Railway or metro performance

Use public timetable or delay data, model it as a star schema, load with Airflow daily and show punctuality by route and station.

Open data→Airflow + dbt→Punctuality dashboard

3. Air quality across cities

Collect air-quality readings from public sources (for example data.gov.in), clean and partition by city and date, and alert when levels cross thresholds.

API ingest→Partitioned Parquet→Alerts + trends

4. E-commerce clickstream

Generate sale-day clickstream, compute live funnels (view → cart → buy) and hourly product rankings, with batch reprocessing for corrections.

Events→Streaming + batch→Live funnel

Run it on your PC: roadmap planner and resume-bullet scorer

This program plans a 10-skill data engineering roadmap from your self-ratings and weekly hours, then scores resume bullets for an action verb, a named tool, a number and an impact. Edit the levels, hours and bullets to your own and run it again. Save it as career_planner.py.

Your weeks, and your bullets

"""Plan a data engineering learning roadmap from your current skills,
then score resume bullets the way a busy reviewer would."""
import re

# 1) skills: (hours needed from zero, your level 0-3)
skills = {
    "SQL (joins, windows, CTEs)": (60, 2),
    "Python for data": (60, 2),
    "Linux, Git, shell": (25, 1),
    "Data modelling (star schema)": (30, 0),
    "Spark / PySpark": (70, 0),
    "Airflow orchestration": (30, 0),
    "Kafka basics": (30, 0),
    "One cloud (storage, Spark, warehouse)": (50, 0),
    "Lakehouse: Delta / Iceberg, dbt": (40, 0),
    "Portfolio project end to end": (60, 0),
}
HOURS_PER_WEEK = 12
week, plan = 1, []
for skill, (hours, level) in skills.items():
    need = round(hours * (3 - level) / 3)
    if need == 0:
        continue
    weeks = -(-need // HOURS_PER_WEEK)          # ceiling division
    plan.append((week, week + weeks - 1, skill, need))
    week += weeks
print(f"Roadmap at {HOURS_PER_WEEK} hours a week:")
for start, end, skill, need in plan:
    print(f"  weeks {start:2}-{end:2}: {skill:38} ({need} h)")
print(f"Total: {sum(p[3] for p in plan)} hours, about {week - 1} weeks ({(week - 1) / 4.3:.1f} months)")

# 2) resume bullets: action verb + tool + number + impact
VERBS = ("built", "designed", "reduced", "migrated", "automated", "optimised", "optimized", "created", "led", "improved")
TOOLS = ("spark", "pyspark", "airflow", "kafka", "sql", "python", "dbt", "delta", "parquet", "aws", "azure", "gcp", "bigquery", "s3")
def score(bullet):
    b = bullet.lower()
    checks = {
        "action verb": b.split()[0] in VERBS,
        "tool named": any(t in re.findall(r"[a-z0-9]+", b) for t in TOOLS),
        "number": bool(re.search(r"\d", b)),
        "impact": any(w in b for w in ("reduc", "faster", "saving", "cut", "improv", "%", "from")),
    }
    return sum(checks.values()), [k for k, ok in checks.items() if not ok]

bullets = [
    "Worked on data pipelines using various tools.",
    "Responsible for Spark jobs.",
    "Built an Airflow DAG that loads 2 lakh orders a day into Delta tables.",
    "Reduced a nightly PySpark job from 3 h to 25 min by fixing skewed joins and partitioning by date.",
]
print("\nResume bullet scores (out of 4):")
for b in bullets:
    s, missing = score(b)
    print(f"  {s}/4  {b}")
    if missing:
        print(f"        missing: {', '.join(missing)}")

# In a terminal:  python career_planner.py
Roadmap at 12 hours a week: weeks 1- 2: SQL (joins, windows, CTEs) (20 h) weeks 3- 4: Python for data (20 h) weeks 5- 6: Linux, Git, shell (17 h) weeks 7- 9: Data modelling (star schema) (30 h) weeks 10-15: Spark / PySpark (70 h) weeks 16-18: Airflow orchestration (30 h) weeks 19-21: Kafka basics (30 h) weeks 22-26: One cloud (storage, Spark, warehouse) (50 h) weeks 27-30: Lakehouse: Delta / Iceberg, dbt (40 h) weeks 31-35: Portfolio project end to end (60 h) Total: 367 hours, about 35 weeks (8.1 months) Resume bullet scores (out of 4): 0/4 Worked on data pipelines using various tools. missing: action verb, tool named, number, impact 1/4 Responsible for Spark jobs. missing: action verb, number, impact 3/4 Built an Airflow DAG that loads 2 lakh orders a day into Delta tables. missing: impact 4/4 Reduced a nightly PySpark job from 3 h to 25 min by fixing skewed joins and partitioning by date.

Interview and viva questions

How do I become a data engineer as a fresher in India?

Learn SQL and Python thoroughly, then data modelling, Spark, an orchestrator such as Airflow, the basics of Kafka and one cloud platform. Build two or three end-to-end projects on GitHub with clear documentation, write a one-page resume with quantified bullets, apply through referrals, job portals and company career pages, and practise SQL, coding and pipeline design questions.

Which certification is best for data engineers?

The best one matches the jobs you target: AWS Certified Data Engineer – Associate for AWS roles, Microsoft Certified: Fabric Data Engineer Associate (DP-700) for Azure and Fabric, Google Cloud Professional Data Engineer for GCP, and Databricks Certified Data Engineer Associate for Spark and lakehouse roles. Certifications help most when combined with projects on the same platform.

What projects should a data engineer have in a portfolio?

End-to-end projects that ingest real or realistic data, store it in layers (bronze, silver, gold), transform it with Spark or dbt, run data quality checks, are orchestrated by Airflow, and serve results in a dashboard or table. Include a README with problem, architecture diagram, run instructions, results and limitations; add tests and CI if possible. Examples: payments streaming with Kafka and Spark, public transport punctuality, air quality monitoring, e-commerce clickstream funnels.

How long does it take to become a data engineer?

With prior programming knowledge, a focused learner studying 10–15 hours a week can usually become job-ready in about 6–9 months; full-time study can shorten that. The time depends on your starting skills, so plan from an honest self-assessment and measure progress with finished projects.

How should a data engineer write a resume?

Keep it to one page for freshers, with a header including GitHub and LinkedIn links, projects near the top, and bullets written as action plus tool plus scale plus result. List only tools you can discuss in depth, add relevant certifications, avoid duties and generic adjectives, and tailor keywords to each job description truthfully.

Real-world scenario questions (asked in company interviews)

Career questions students and early-career engineers ask. Decide your answer first, then open the model answer.

Career planningFresher

“I have 6 months. What should I learn?”

A final-year student wants a data engineering job in six months and asks for a plan.

The interviewer is checking: can you prioritise ruthlessly?

Show a strong answer
  1. Weeks 1–6: SQL (windows, CTEs), Python, Git and Linux, data modelling.
  2. Weeks 7–14: PySpark and Parquet, then Airflow and dbt.
  3. Weeks 15–18: one cloud’s storage, Spark and warehouse; Kafka basics.
  4. Weeks 19–24: one end-to-end project, resume, applications and interview practice (SQL daily).

Skip Hadoop administration, multiple clouds and five certifications; depth in the core beats breadth.

Avoid: trying to learn every tool on a “roadmap” poster.

ResumeFresher

Fix this resume

A resume lists 30 tools, has no projects and says “responsible for data pipelines” for an internship.

The interviewer is checking: can you turn duties into evidence?

Show a strong answer
  • Cut skills to tools the candidate can discuss in depth.
  • Add 2–3 projects with tools, scale, results and GitHub links, above the skills section.
  • Rewrite each bullet as action + tool + scale + result, for example “Automated a daily sales load with Airflow, cutting manual work by 2 hours a day”.
  • Keep it to one page and check each line is true and explainable.

Avoid: adding more tools or decorative design.

Certifications1–3 years

Which certification first?

An analyst moving into data engineering has budget for one certification and works at a company on Azure.

The interviewer is checking: can you link a certification to real goals?

Show a strong answer

Start with the platform you use or the jobs you target. On Azure/Microsoft Fabric that is the Fabric Data Engineer Associate (DP-700); on AWS the AWS Certified Data Engineer – Associate; on Google Cloud the Professional Data Engineer; for Spark/lakehouse roles the Databricks Data Engineer Associate. Take it after building something on that platform, and pair it with a project so the badge has evidence behind it.

Avoid: choosing the most popular badge without checking job posts.

Interview · behaviouralFresher

“Tell me about your project.”

The first question in most data engineering interviews.

The interviewer is checking: can you explain your project clearly and honestly in 2 minutes?

Show a strong answer

Use a clear structure: problem (what and why), architecture (sources → ingestion → storage → processing → serving, with tools), scale (rows, size, frequency), one hard problem you solved and how (STAR), result with numbers, and what you would improve. Be ready for “why this tool and not X?” and “what happens if this fails?”.

Avoid: reading the tool list or claiming work you didn’t do.
