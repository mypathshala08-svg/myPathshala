2 Definition

Big Data Fundamentals in one page

Formal definition (write this in exams)

Big Data Fundamentals covers the characteristics of data sets too large, fast or varied for a single traditional system (volume, velocity, variety, veracity, value); the storage formats and databases suited to them; the distributed-systems principles of scaling out, partitioning, replication and consistency; the ecosystem of processing and streaming tools (Hadoop, Spark, Kafka, lakehouse table formats, orchestration, cloud services); the practices of data quality, governance, security and privacy; and the roles and skills of data professionals, applied in an end-to-end pipeline.

In simple words

Big data is data too big, fast or messy for one computer. We spread it across many machines, store it in efficient formats, process it with tools like Spark and Kafka, keep it correct, safe and lawful, and turn it into useful answers.

2-mark questions with model answers

Define big data.

Data sets whose volume, velocity or variety exceed the capacity of traditional single-machine systems to store and process them in acceptable time, requiring distributed storage and processing.

What is veracity?

The quality and trustworthiness of data: accuracy, completeness and consistency. Example: duplicate or fake transactions reduce veracity.

Differentiate structured and semi-structured data.

Structured data has a fixed schema of rows and columns (a bank table); semi-structured data has tags or keys but a flexible schema (JSON, XML).

What is a NameNode?

The HDFS master that stores the file system metadata (file names, block locations) and coordinates DataNodes, which store the actual blocks.

What is schema-on-read?

The schema is applied when data is read rather than when it is written, as in data lakes; allows storing raw data first.

What is a partition key?

The column whose value decides which partition or shard a row belongs to, for example customer_id or date.

What is eventual consistency?

If no new updates occur, all replicas eventually converge to the same value; reads may briefly return stale data.

What is a DAG in Spark or Airflow?

A directed acyclic graph of steps with dependencies and no cycles; Spark uses it for stages of computation, Airflow for task order.

What is a Kafka offset?

The sequential position of a message within a partition, used by consumers to track what they have read.

What is the lakehouse?

An architecture combining low-cost lake storage with warehouse features (ACID transactions, schemas, fast SQL) using table formats such as Delta Lake, Iceberg or Hudi.

What is egress in cloud billing?

Charges for data transferred out of a cloud region or out of the cloud, often a hidden cost.

Who is a data fiduciary under the DPDP Act?

The person or organisation that determines the purpose and means of processing personal data.

5-mark questions with answer outlines

Explain the 5 Vs of big data with examples.

Define each V in one line with an Indian example: volume (UPI billions a month), velocity (live cricket concurrency), variety (text, images, logs), veracity (fake reviews, duplicates), value (fraud detection, recommendations). Add a small diagram of the five Vs.

Why is one computer not enough for big data?

Disk read speed limits (hours to scan TBs), memory limits, CPU limits, single point of failure, cost of very large machines. Solution: split data and work across many machines (parallelism) with replication. Include a calculation, e.g. 10 TB at 200 MB/s ≈ 14 hours vs 100 machines ≈ 8 minutes.

Compare CSV, JSON, Avro, Parquet and ORC.

Table with: row/columnar, schema, compression, splittable, best use. CSV/JSON human-readable but large; Avro row-based with schema, good for streaming and Kafka; Parquet/ORC columnar, compressed, best for analytics.

Explain replication strategies.

Leader-follower (writes to leader, followers copy; sync vs async), multi-leader, leaderless with quorums (R + W > N). Benefits: availability, durability, read scaling; issues: lag, conflicts, failover. Diagram.

Explain Spark architecture.

Driver, cluster manager, executors; jobs, stages, tasks; lazy evaluation and DAG; narrow vs wide transformations and shuffles; in-memory processing. Diagram with driver and executors.

Explain Kafka architecture.

Producers, brokers, topics, partitions, offsets, replication, consumer groups; ordering per partition; retention; use cases like UPI events or order tracking. Diagram.

Explain cloud service models for big data with AWS/Azure/GCP examples.

IaaS, managed PaaS, serverless, SaaS; examples: S3/ADLS/GCS, EMR/Databricks/Dataproc, Redshift/Synapse/BigQuery; benefits and concerns (cost, lock-in, residency).

Explain the DPDP Act, 2023 from a data engineer’s point of view.

Fiduciary and principal; consent and notice; purpose limitation; rights (access, correction, erasure); security safeguards; breach notification within 72 hours to the Board; penalties up to ₹250 crore; engineering impacts: PII tagging, masking, deletion workflows, audit logs.

Interview and viva questions

What are the most important topics in Big Data for exams?

The 5 Vs and the need for distributed systems; data types and file formats; HDFS, YARN and MapReduce; Spark architecture; NoSQL types and the CAP theorem; partitioning and replication; Kafka and stream processing; data lakes, warehouses and lakehouses; cloud services for big data; and data quality, governance and privacy. Practise diagrams for HDFS, Spark, Kafka and pipelines.

How do I write a 10-mark answer in a Big Data exam?

Use five parts: a precise definition, a labelled diagram, explanation in numbered points, a real example (preferably with numbers, such as UPI or IRCTC figures) and a comparison table or advantages and limitations. Underline key terms and keep each point short.

How should I revise Big Data Fundamentals in one week?

Day 1: course map and cheat sheets. Days 2–4: two modules a day, redrawing diagrams and taking each lesson’s quiz. Day 5: question banks and estimation practice. Day 6: a timed 50-mark practice paper. Day 7: weak areas and the final test.

Is Hadoop still important to learn?

Its ideas are: distributed storage with replication, moving computation to data, resource management and table metadata. Many exams still test HDFS, YARN and MapReduce, and many companies still run or migrate Hadoop clusters, but new projects mostly use Spark, cloud object storage and lakehouse formats.

What should I study after Big Data Fundamentals?

Go deeper in the Big Data Engineering track: SQL and data modelling, PySpark in practice, Kafka and stream processing, a cloud data platform, lakehouse formats and orchestration with Airflow. Extend your capstone at each step and follow the roadmap in Lesson 6.2.

Real-world scenario questions (asked in company interviews)

Exam, viva and next-step questions. Decide your answer first, then open the model answer.

Exam strategyFresher

Ten minutes left, two questions to go

In the exam you have 10 minutes left and one 5-mark and one 10-mark question unanswered.

The interviewer is checking: can you maximise marks under time pressure?

Show a strong answer

Attempt both in outline form: for each, a one-line definition, a quick labelled diagram and 3–4 bullet points with an example. Partial structured answers earn marks; a blank page earns none. Spend roughly 4 minutes on the 5-mark and 6 on the 10-mark question.

Avoid: perfecting one answer and leaving the other blank.

Concept checkFresher

“Is Hadoop dead?”

A viva examiner or interviewer asks whether Hadoop is still relevant.

The interviewer is checking: can you give a nuanced, current answer?

Show a strong answer

Hadoop MapReduce is rarely chosen for new projects; Spark and cloud services have replaced it. But Hadoop’s ideas live on everywhere: distributed storage with replication (HDFS → object storage), resource management (YARN → Kubernetes and cloud schedulers), Hive’s metastore and table concepts (→ catalogs and lakehouse formats). Many enterprises still run Hadoop clusters and are migrating them to cloud lakehouses.

Avoid: a simple yes or no.

Integration1–3 years

“Which single idea from this course matters most?”

A reflective viva or interview question.

The interviewer is checking: can you connect concepts?

Show a strong answer

A strong answer picks one idea and links it across the course, for example partitioning: it decides how data is spread across machines (Module 3), how Parquet folders are laid out and queries prune data (Modules 2 and 4), how Kafka scales and orders events (Module 4), how cloud scan costs fall (Module 4.6), how pipelines stay idempotent by overwriting a partition (capstone), and where skew comes from (interviews).

Avoid: listing tools without connecting them.
