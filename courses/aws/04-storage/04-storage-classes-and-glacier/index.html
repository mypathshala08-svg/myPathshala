1 The story

First-class fare for luggage nobody opens

🤔 A logistics start-up’s S3 bill grew every month — 2 TB of GPS logs, all in S3 Standard, mostly never read after the first week. The finance head asked: “Why are we paying first-class fare for luggage nobody opens?”

2 Definition

Storage classes, lifecycle and Glacier

Formal definition (write this in exams)

S3 storage classes trade storage price against access speed, retrieval fees, minimum storage duration and redundancy — Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant Retrieval, Glacier Flexible Retrieval and Glacier Deep Archive. Lifecycle configurations automatically transition objects between classes and expire them based on age, filtered by prefix, tags or size; archived Glacier objects are read after a restore creates a temporary copy.

In simple words

Keep data in an expensive, fast class while it is used, let a lifecycle rule move it to cheaper, slower classes as it ages, and delete it when nobody needs it.

Say it in an interview

30-second answer you can speak:

  • “I pick classes by access frequency and latency: Standard for hot, Intelligent-Tiering for unknown, IA for monthly, Glacier IR for instant archives, Flexible/Deep Archive for long retention — minding 30/90/180-day minimums and the 128 KB minimum.”
  • “Lifecycle rules by prefix and tag do transitions and expirations, plus housekeeping for noncurrent versions and incomplete multipart uploads; Storage Class Analysis and Storage Lens guide the thresholds.”

3 The big picture

The ladder of classes and rules per prefix

New to computers? Start here. Storage classes are like where you keep things at home: daily-use items on the table (Standard), occasional things in a cupboard (Standard-IA — quick to reach, small effort each time), old files in the loft (Glacier — cheap space, you need a ladder and time), and documents you must keep but will almost never see in a bank locker far away (Deep Archive). A lifecycle rule is a helper who moves things to the cupboard after a month and to the loft after three.

Jargon buster:

  • Storage class — a price/speed tier for objects
  • Retrieval fee — charge per GB when reading cheaper classes
  • Minimum duration — you pay at least this many days
  • Lifecycle rule — automatic move/delete by age
  • Transition — moving to another class
  • Restore — making a Glacier object readable again (temporary copy)

Type 2 · S3 Intelligent-Tiering

Definition (say it in an interview): Intelligent-Tiering automatically moves each object between Frequent, Infrequent (after 30 days without access) and Archive Instant (after 90 days) tiers, and back on access, with no retrieval fees — for a small monthly monitoring fee per object (objects under 128 KB are not monitored and stay in Frequent). Optional Archive Access and Deep Archive Access tiers need restores.

In plain words (no jargon): A class that moves objects to cheaper tiers by itself.

Analogy: A smart cupboard that moves things you stopped using to the back shelf — and to the front again when you touch them.

How it works internally, step by step

  1. Frequent. Like Standard.
  2. Infrequent. After 30 days.
  3. Archive Instant. After 90 days.
  4. Optional archive. Restore needed.
  5. Fee. Per object monitored.

Words used above, in simple terms: tier = price level inside the class · monitoring fee = small charge per object · auto-tiering = moves by access

In plain words (no jargon): Cheap infrequent storage in only one data centre.

Type 6 · S3 Glacier Flexible Retrieval

Definition (say it in an interview): Glacier Flexible Retrieval (formerly S3 Glacier) is low-cost archive storage where objects must be restored before reading: Expedited (1–5 minutes), Standard (3–5 hours) or Bulk (5–12 hours, free retrieval), with a 90-day minimum. A restore creates a temporary readable copy for the days you choose.

In plain words (no jargon): Very cheap archive that needs a wait before reading.

Animated

What a lifecycle rule does to one file over a year

Watch a log file move to cheaper classes as it gets older, come back for an audit, and finally expire — automatically.

A year in the life of a log 6 steps
Watch what happens
  1. Step 1 · Day 0 — Standard — new logs are read often (debugging), so they start in S3 Standard: fastest access, highest storage price, no retrieval fee.
  2. Step 2 · Day 30 — Standard-IA — the lifecycle rule transitions logs/ objects to Standard-IA: same speed, about half the storage price, but a per-GB retrieval fee and 30-day minimum.
  3. Step 3 · Day 90 — Glacier Flexible Retrieval — archived: a small fraction of the price; reading now needs a restore that takes minutes to hours.
  4. Step 4 · An audit request — you call restore-object (Expedited minutes, Standard 3–5 hours, Bulk 5–12 hours) — the object stays archived meanwhile.
  5. Step 5 · Temporary copy — when the restore completes, a temporary copy is readable for the days you asked for; the archived original stays in Glacier.
  6. Step 6 · Day 365 — expire — the rule deletes the object. You paid premium price only for the first month. All of it happened with zero manual work.

8 Deep dive

Lifecycle constraints, restores, cost comparison

Lifecycle rules: what is allowed

  • Transitions go “down” the ladder (Standard → IA → Glacier IR → Flexible → Deep Archive), never back up.
  • Standard-IA / One Zone-IA transitions only after ≥ 30 days from creation.
  • By default, objects smaller than 128 KB are not transitioned (you can override with an object-size filter).
  • Rules run asynchronously (once a day); an object may move a day or two after the threshold.
  • Expiration on a versioned bucket adds a delete marker; use NoncurrentVersionExpiration for old versions.

Restore from Glacier Flexible Retrieval

aws s3api restore-object --bucket $B --key logs/2025/access-01.log \
  --restore-request '{"Days":7,"GlacierJobParameters":{"Tier":"Standard"}}'
aws s3api head-object --bucket $B --key logs/2025/access-01.log --query Restore
# "ongoing-request=\"true\""                       ← still restoring
# "ongoing-request=\"false\", expiry-date=\"…\""   ← ready: GET works until expiry

9 Under the hood

How transitions and restores run

How transitions and restores actually run.

1 · Lifecycle evaluation

S3 evaluates lifecycle rules once a day (UTC) and queues eligible objects; actions can lag by a day or more for large buckets. Billing changes when the transition actually happens. Transitions are billed per request (per 1,000 objects).

2 · Archive overhead

For each object in Glacier Flexible/Deep Archive, S3 stores 8 KB of metadata in Standard and 32 KB in the archive class (billed). That is why archiving tiny files is inefficient — zip/tar them first.

3 · Restore mechanics

restore-object starts a job; the object stays in its archive class and a temporary copy appears (billed at Standard-IA or similar rates) for the Days you set. Restore completion can trigger an S3 Event Notification (s3:ObjectRestore:Completed) → Lambda/SNS.

4 · Intelligent-Tiering internals

Access tracking is per object; any GET/PUT moves it back to Frequent. Optional archive tiers are configured per bucket (configuration with Days ≥ 90/180) and then behave like Glacier (restore needed).

14 Hands-on

Do it yourself, step by step

These labs run on your own AWS account — we cannot run them for you. Every step shows the UI way (console clicks) and the CLI way (commands for AWS CloudShell or your terminal), plus what you should see. Work as an IAM/Identity Center user, never root; use the Mumbai Region (ap-south-1); stay inside Free Tier/credits; and always do the Clean up step at the end. Three small objects — practically free. Note: Glacier objects have a 90-day minimum charge (tiny here).

  1. 0 · Get ready: signed in, budget, Region, CloudShell

    UI way — AWS Management Console

    1. Sign in as your admin user (not root) — Lesson 1.2 shows how to create it.
    2. Billing and Cost Management → Budgets → check a monthly cost budget with e-mail alerts exists (e.g. $5).
    3. Top-right Region menu → Asia Pacific (Mumbai).
    4. Click the CloudShell icon (>_) in the top bar — the AWS CLI is already signed in there.

    CLI way — the same thing with commands

    aws sts get-caller-identity --query Arn --output text   # must NOT end in :root
aws configure set region ap-south-1
aws configure list | grep region

    You should see: an ARN ending in :user/… or :assumed-role/… and region ap-south-1.

    CloudShell is free, runs in your browser and is already signed in as the user you logged in with.

  2. 1 · Upload into different classes and check

    UI way — AWS Management Console

    1. Create bucket logs-ACCOUNTID → Upload app.log → Properties → Storage class Standard-IA → Upload → in the object list the Storage class column shows Standard-IA.

    CLI way — the same thing with commands

    ACCT=$(aws sts get-caller-identity --query Account --output text); B=logs-$ACCT; aws s3 mb s3://$B
head -c 200000 /dev/urandom | base64 > app.log    # ~270 KB (above the 128 KB minimum)
aws s3 cp app.log s3://$B/logs/2026/app.log --storage-class STANDARD_IA
aws s3 cp app.log s3://$B/notes/app.log --storage-class INTELLIGENT_TIERING
aws s3 cp app.log s3://$B/archive/old.log --storage-class GLACIER
aws s3api list-objects-v2 --bucket $B --query 'Contents[].[Key,StorageClass]' --output table

    You should see: a table with STANDARD_IA, INTELLIGENT_TIERING and GLACIER for the three keys.

    You can choose the class at upload; lifecycle rules change it later.

  3. 2 · The lab-exam lifecycle rule by prefix

    UI way — AWS Management Console

    1. Management → Create lifecycle rule → name logs-ia-30-expire-365 → Limit the scope prefix logs/ → transition current versions to Standard-IA after 30 days and Glacier Flexible after 90 → expire current versions after 365 days → Create rule. Add a second rule for submissions/ and a housekeeping rule.

    CLI way — the same thing with commands

    # save lifecycle.json from above, then:
aws s3api put-bucket-lifecycle-configuration --bucket $B --lifecycle-configuration file://lifecycle.json
aws s3api get-bucket-lifecycle-configuration --bucket $B --query 'Rules[].[ID,Filter.Prefix,Status]' --output table
aws s3api head-object --bucket $B --key logs/2026/app.log --query Expiration

    You should see: three rules listed and an Expiration value like expiry-date="…", rule-id="logs-ia-30-expire-365" — S3 already knows when this object will be deleted.

    Transitions happen in the background once objects are old enough; you will not see them change today.

  4. 3 · Read a Glacier object: denied, restore, then read

    UI way — AWS Management Console

    1. Open archive/old.log → Download is refused → Initiate restore → 7 days, Standard → wait (3–5 hours) → download works.

    CLI way — the same thing with commands

    aws s3 cp s3://$B/archive/old.log - 2>&1 | tail -1
aws s3api restore-object --bucket $B --key archive/old.log --restore-request '{"Days":7,"GlacierJobParameters":{"Tier":"Standard"}}'
aws s3api head-object --bucket $B --key archive/old.log --query '[StorageClass,Restore]'

    You should see: An error occurred (InvalidObjectState) when calling the GetObject operation: The operation is not valid for the object's storage class, then ["GLACIER", "ongoing-request=\"true\""]. A few hours later the Restore value shows ongoing-request="false" with an expiry date and the download works.

    Expedited (1–5 minutes) costs more; Bulk is cheapest. Plan restores for audits ahead of time.

Clean up and cost check

aws s3 rb s3://$B --force (early-deletion fees on these tiny objects are negligible).
