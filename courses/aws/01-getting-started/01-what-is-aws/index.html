2 Definition

What is AWS?

Formal definition (write this in exams)

Amazon Web Services (AWS) is Amazon’s public cloud platform: a global infrastructure of Regions, Availability Zones and edge locations on which more than 200 on-demand services — compute, storage, databases, networking, security, analytics, AI and management — are provided through authenticated APIs and billed on a pay-as-you-go basis.

In simple words

AWS is Amazon renting you computers, storage, databases and many other ready-made services over the internet, and charging only for what you use.

Say it in an interview

30-second answer you can speak:

  • “AWS is Amazon’s cloud: 200+ managed services running on Regions and Availability Zones worldwide, all controlled through APIs and billed per use.”
  • “For example, a startup can run its site on EC2, keep images in S3, orders in RDS, and pay per second instead of buying servers.”

Words you’ll meet

RegionGeographic area with AZs.

3 The big picture

AWS in four layers

New to computers? Start here. Imagine you want to start a tiffin business. Instead of buying a big kitchen, you rent a kitchen by the hour — and pay only for the hours you cook. AWS rents computers, storage and software the same way, over the internet.

Jargon buster:

  • Server — a computer that runs all day to serve websites or apps
  • Cloud — computers in someone else’s building that you use over the internet
  • Service — one ready-made product, e.g. storage or a database
  • Region — a city/area where AWS has its buildings
  • API — the “order window” through which programs ask AWS to do things

Amazon Web Services (AWS) started selling infrastructure to other companies in 2006 with S3 (storage) and EC2 (servers). Today it is the largest cloud provider by revenue. Think of it in four layers:

Definition (say it in an interview): Compute services run your code: EC2 virtual servers you manage, containers on ECS/EKS (optionally serverless with Fargate), and event-driven functions on Lambda; plus simpler options such as Elastic Beanstalk and Lightsail.

  5. Pay. Per second / per request.

Words used above, in simple terms: instance = a virtual server on EC2 · container = packaged app with its libraries · function = code run per event

Words used above, in simple terms: relational = tables with relationships, SQL · NoSQL = non-tabular models, e.g. key-value · Multi-AZ = standby copy in another AZ

5 How it works, step by step

What happens when you click “Launch”

One console click followed through AWS.

Animated

What happens when you click “Launch” — inside AWS

Follow one click from Riya’s browser to a running server and a line on the bill.

Inside AWS 6 steps
Watch what happens
  1. Step 1 · The click — the console turns Riya’s form into an API request — the same call the CLI or SDK would make.
  2. Step 2 · A signed request — an HTTPS request “RunInstances” goes to ec2.ap-south-1.amazonaws.com, signed with SigV4 so AWS can verify who sent it.
  3. Step 3 · IAM decides — AWS checks Riya’s policies for ec2:RunInstances. With no Allow (or any explicit Deny) the answer is AccessDenied and nothing happens.
  4. Step 4 · The control plane acts — EC2 finds a physical host with free capacity in an Availability Zone, attaches a disk and network card, and replies with an instance ID.
  5. Step 5 · Running — and recorded — the instance boots; CloudTrail writes who called RunInstances, when, from which IP and whether it succeeded.
  6. Step 6 · The meter runs — billing counts every second the instance runs (plus its disk). Stop it and compute charges stop; terminate it and the disk is deleted by default.

Control plane vs data plane

The control plane is the set of APIs that create, change and delete resources (RunInstances, CreateBucket). The data plane is the resource doing its job (your instance serving pages, S3 returning an object). AWS designs data planes to keep working even if a control plane has problems — your running server keeps serving while you briefly cannot launch new ones.

Ways to pay

  • On-Demand: per second/hour, no commitment.
  • Savings Plans / Reserved Instances: 1- or 3-year commitment for a large discount.
  • Spot: spare capacity at a big discount, can be interrupted.
  • Free Tier: credits and always-free limits for learning (Lesson 1.2).
9 Under the hood

Endpoints, request signing, ARNs, limits and consistency

What really happens between your keyboard and AWS. You do not need this to pass CLF-C02, but it is what separates someone who uses AWS from someone who can debug it.

1 · Every action is an HTTPS request to a service endpoint

Each service has endpoints per Region, such as https://ec2.ap-south-1.amazonaws.com or https://s3.ap-south-1.amazonaws.com. A few services are global and have one endpoint for the whole account.

ScopeExamplesWhat it means for you
GlobalIAM, Route 53, CloudFront, Organizationscreate once, used in every Region; IAM changes apply everywhere
RegionalS3 buckets, VPC, Lambda, DynamoDB, RDSresources live in one Region; pick it deliberately
Zonal (inside a Region)EC2 instances, EBS volumes, subnetslive in one Availability Zone; spread across AZs for availability

Run any CLI command with --debug to see the exact endpoint, headers and response.

2 · How AWS knows it is really you: Signature Version 4 (SigV4)

Your secret access key is never sent over the network. The CLI/SDK uses it to sign each request; AWS repeats the same calculation and compares signatures.

  1. Canonical request — method, path, query, sorted headers and a SHA-256 hash of the body are written in a fixed format.
  2. String to sign — AWS4-HMAC-SHA256, the timestamp, the scope (20261112/ap-south-1/ec2/aws4_request) and the hash of the canonical request.
  3. Signing key — derived in a chain: HMAC(“AWS4”+secret, date) → HMAC(·, region) → HMAC(·, service) → HMAC(·, “aws4_request”). A key for one day, Region and service cannot sign for another.
  4. Signature — HMAC-SHA256(signing key, string to sign), added to the Authorization header.
  5. AWS verifies — recomputes it, checks the timestamp is recent (a few minutes), then hands the request to IAM for authorisation.
Authorization: AWS4-HMAC-SHA256 Credential=AKIAEXAMPLE/20261112/ap-south-1/ec2/aws4_request,
  SignedHeaders=host;x-amz-date, Signature=5d672d79c15b13162d9279b0855cfba6789a8edb4c82c400e06b5924a6f2b5d7

This is why a wrong system clock causes SignatureDoesNotMatch or “Signature expired” errors, and why temporary credentials carry an extra session token.

4 · Limits, throttling and retries

Every API has a request rate limit and every account has service quotas (for example, how many vCPUs of On-Demand instances you may run). Exceed a rate and AWS answers ThrottlingException or RequestLimitExceeded; the SDKs and CLI retry automatically with exponential backoff and jitter (wait 1×, 2×, 4×… plus randomness). You can tune it with AWS_RETRY_MODE=standard|adaptive and AWS_MAX_ATTEMPTS.

5 · “I just created it — why can’t I see it?” Eventual consistency

AWS is a distributed system. Some changes take a moment to reach every server: a new IAM policy can take a few seconds to apply, and an EC2 Describe call right after RunInstances may briefly not return the new instance. Scripts should wait (aws ec2 wait instance-running) or retry rather than fail. Amazon S3 is an exception: since December 2020 it gives strong read-after-write consistency for all objects.

10 By role

How developers, data, ML, DevOps and security people use it

Cloud is not one job. The same AWS account is used very differently by each role — here is what each one actually touches in a normal week.

Software developer (backend)

Builds APIs and services; wants fast, repeatable environments.

Uses: EC2 or containers (ECS/Fargate), Lambda, RDS/DynamoDB, SQS, CloudWatch Logs, SDKs (boto3, AWS SDK for Java/JS), CodeBuild/GitHub Actions.

A real task: Ship an order API: code in Git → CI builds a container → deployed to ECS → logs and errors visible in CloudWatch.

Skill to build: IAM roles for apps (no keys in code), SDK retries/pagination, reading CloudWatch logs.

App / mobile developer

Builds web and mobile front ends; wants sign-in, storage and APIs without running servers.

Uses: Amplify, Cognito (user sign-up/login), API Gateway + Lambda, S3 + CloudFront, DynamoDB, SNS push.

A real task: TiffinGo app: users sign in with Cognito, upload a profile photo to S3 with a pre-signed URL, get push notifications.

Skill to build: Pre-signed URLs, CORS, Cognito tokens, CDN caching.

Data analyst

Answers business questions with SQL and dashboards; does not want to manage clusters.

Uses: Athena (SQL on S3), QuickSight dashboards, Redshift (warehouse), Glue Data Catalog, S3 exports.

A real task: “Which locality orders most after 9 pm?” — query a month of order logs in S3 with Athena, chart it in QuickSight.

Skill to build: SQL on files, partitions, cost per query (Athena bills by data scanned).

Data engineer

Builds pipelines that move and clean data reliably.

Uses: S3 data lake, Glue (ETL, crawlers), EMR (Spark), Kinesis (streams), Step Functions/MWAA (orchestration), Lake Formation (permissions), Redshift.

A real task: Nightly: raw orders land in s3://lake/raw/ → Glue job cleans to Parquet in curated/ → partitions registered → analysts query.

Skill to build: Partitioning, file formats (Parquet), idempotent jobs, IAM for data access.

ML / AI engineer

Trains, deploys and monitors models; increasingly builds generative-AI features.

Uses: SageMaker (notebooks, training, endpoints), Bedrock (foundation models via API, knowledge bases), S3 for datasets, GPU instances, CloudWatch for model metrics.

A real task: Demand forecast trained on SageMaker; a support chatbot answering from TiffinGo’s FAQ using a Bedrock knowledge base.

Skill to build: GPU cost control, data security, model endpoints and monitoring.

DevOps / cloud engineer

Owns accounts, networks, deployments, reliability and cost.

Uses: Organizations, IAM Identity Center, VPC, CloudFormation/CDK/Terraform, CloudWatch alarms, Systems Manager, Budgets.

A real task: Create dev and prod environments from the same template; alarms page on-call; monthly cost review.

Skill to build: Infrastructure as code, networking, incident response, FinOps.

Security engineer

Makes sure everything above is safe and auditable.

Uses: IAM Access Analyzer, CloudTrail, GuardDuty, Security Hub, KMS, Config rules, WAF.

A real task: Detect a public bucket within minutes and auto-remediate; prove to auditors who accessed customer data.

Skill to build: Least privilege, logging, detection and response.

How organisations use AWS (illustrative cases)

An ed-tech start-up in Pune (500 → 50,000 students)

Problem: Exam-result day crashed its single server every year.

14 Hands-on

Do it yourself, step by step

These labs run on your own AWS account — we cannot run them for you. Every step shows the UI way (console clicks) and the CLI way (commands for AWS CloudShell or your terminal), plus what you should see. Work as an IAM/Identity Center user, never root; use the Mumbai Region (ap-south-1); stay inside Free Tier/credits; and always do the Clean up step at the end. This first lab creates nothing — it only reads public information and your own account data, so it is free.

  1. 0 · Get ready: signed in, budget, Region, CloudShell

    UI way — AWS Management Console

    1. Sign in as your admin user (not root) — Lesson 1.2 shows how to create it.
    2. Billing and Cost Management → Budgets → check a monthly cost budget with e-mail alerts exists (e.g. $5).
    3. Top-right Region menu → Asia Pacific (Mumbai).
    4. Click the CloudShell icon (>_) in the top bar — the AWS CLI is already signed in there.

    CLI way — the same thing with commands

    aws sts get-caller-identity --query Arn --output text   # must NOT end in :root
aws configure set region ap-south-1
aws configure list | grep region

    You should see: an ARN ending in :user/… or :assumed-role/… and region ap-south-1.

    CloudShell is free, runs in your browser and is already signed in as the user you logged in with.

  2. 1 · Count AWS services and see what Mumbai offers

    UI way — AWS Management Console

    1. Console top-left ≡ Services → All services: scroll the families from this lesson.
    2. Top-right Region menu: count the Regions listed (enabled and “not enabled”).
    3. Search box → type Athena, Lambda, CloudTrail — open each to see where it lives.

    CLI way — the same thing with commands

    # public, read-only list that AWS publishes in Systems Manager Parameter Store
aws ssm get-parameters-by-path --path /aws/service/global-infrastructure/services --query 'length(Parameters)'
aws ssm get-parameters-by-path --path /aws/service/global-infrastructure/regions/ap-south-1/services --query 'length(Parameters)'
aws ssm get-parameters-by-path --path /aws/service/global-infrastructure/regions --query 'length(Parameters)'
# is Bedrock offered in Mumbai?
aws ssm get-parameters-by-path --path /aws/service/global-infrastructure/regions/ap-south-1/services \
  --query "Parameters[?Value=='bedrock'].Value" --output text

    You should see: three numbers — total service identifiers (a few hundred, including sub-services), services offered in Mumbai (fewer), and Regions — then bedrock if it is available in Mumbai.

    Not every service is in every Region: always check before you design.

  3. 2 · One action, three ways — and all are API calls in CloudTrail

    UI way — AWS Management Console

    1. Open S3 in the console — the bucket list loads (this is a ListBuckets API call).
    2. Wait ~5 minutes, then CloudTrail → Event history → Lookup attribute Event name = ListBuckets.
    3. Open an event: see userAgent, sourceIPAddress, userIdentity.

    CLI way — the same thing with commands

    aws s3api list-buckets --query 'length(Buckets)'                       # 2) the CLI
python3 -c "import boto3; print(len(boto3.client('s3').list_buckets()['Buckets']))"   # 3) the Python SDK
sleep 300   # CloudTrail delivers events within about 5 minutes
aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=ListBuckets --max-results 5 \
  --query 'Events[].CloudTrailEvent' --output json \
  | python3 -c "import sys,json; [print(e['eventTime'], e['userIdentity']['arn'].split('/')[-1], e['userAgent'][:45]) for e in map(json.loads, json.load(sys.stdin))]"

    You should see: the same bucket count twice, then up to five ListBuckets events with your user name and user agents like aws-cli/2…, Boto3/… and the console — one API, three clients.

    This is why AWS can be fully automated and audited: there is no “click” that is not an API call.

  4. 3 · Pay-as-you-go in practice: your plan and Free Tier usage

    UI way — AWS Management Console

    1. Billing and Cost Management → Free Tier: see your account plan, remaining credits (newer accounts) and usage per service.
    2. Bills: this month’s charges by service — likely zero or a few cents.

    CLI way — the same thing with commands

    aws freetier get-account-plan-state --region us-east-1 \
  --query '{plan:accountPlanType,status:accountPlanStatus,credits:accountPlanRemainingCredits.amount,expires:accountPlanExpirationDate}'
aws freetier get-free-tier-usage --region us-east-1 \
  --query 'freeTierUsages[].[service,description,actualUsageAmount,limit,unit]' --output table

    You should see: your plan type (e.g. FREE or PAID), remaining credits, and a table of Free Tier usage against limits. Older accounts may get an error on the first command — the second still works.

    Billing data lives in us-east-1 (N. Virginia) whatever Region you work in.

Clean up and cost check

Nothing was created. Run aws sts get-caller-identity once more to confirm you are not root, and keep your budget alert switched on for the rest of the course.

Common mistakes, why they happen, how to fix them

Mistake or symptomWhy it happensHow to fix or avoid

Working as the root user.It is the first login you get.Create an admin user with MFA (Lesson 1.2); lock root away.
Assuming every service is in every Region.Global marketing.Check the Region table or the SSM list.
